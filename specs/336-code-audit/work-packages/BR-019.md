# [#336] S1: весь контроллер `/api/properties/**` доступен анонимно (нет ни `SiteAuthInterceptor`, ни о… (BR-019)

Задача: устранение дефекта **BR-019** (S1) из полного аудита кода (#336).

## Что не так

** весь контроллер `/api/properties/**` доступен анонимно (нет ни `SiteAuthInterceptor`, ни ограничения в `SecurityConfig` — там `/api/**` + `anyRequest` = `permitAll`). `GET /api/properties/getproperty` и `GET /api/properties/digest` отдают произвольные значения `tbl_public_settings` (включая секрет `yandexSmartCaptchaServerKey`), а `POST /api/properties/setproperty` пишет любое значение в прод-БД.

## Доказательство

**
  ```
  @PostMapping("/setproperty")
  @ResponseBody
  fun setProperty(
      @RequestParam key: String,
      @RequestParam stringValue: String,
  ```
  (`PublicSettingsWebController.kt:50–54`) и
  ```
  "SELECT key, value, description FROM tbl_public_settings ORDER BY key",
  ```
  (`:148`; сам `digest` — `:140–142`). Секрет в таблице: `deploy/karaoke-db/07_public_settings.sql:18` (`'yandexSmartCaptchaServerKey', '', '... серверный ключ (секретный, для валидации на бэкенде)'`), потребитель — `services/CaptchaConfigService.kt:55` → `YandexCaptchaValidationService.kt:31`. Ограничение доступа: `config/SecurityConfig.kt:25–38` (`permitAll`), `config/WebMvcConfig.kt:29–38` (перехватчик только для `/api/public/account/**`, `/api/public/auth/me|logout`, `/api/siteusers/**`); прод-nginx `deploy/web-server-deploy/deploy/80to8897:50–51` проксирует весь `/api/` на `karaoke-web:8897` без auth.

## Путь достижимости

** аноним → `GET https://sm-karaoke.ru/api/properties/digest` (или `?key=yandexSmartCaptchaServerKey` в `getproperty`) → значения всех настроек, включая серверный ключ капчи; аноним → `POST /api/properties/setproperty` с любыми `key/stringValue` → `UPDATE/INSERT tbl_public_settings` → изменение поведения сайта (kill-switch `newsAutoPublishKillSwitch`, ключи капчи и т.п.). Подмена серверного ключа капчи на «свою» пару ломает/обходит проверку капчи при регистрации.

## Предлагаемая поправка

** закрыть весь `/api/properties/**` административной аутентификацией (перехватчик/`SecurityConfig` matcher), вынести запись в admin-only путь; из `digest`/`getproperty` исключить секретные ключи (whitelist публичных ключей).
