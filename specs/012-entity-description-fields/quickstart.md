# Quickstart: проверка фичи «Доп. поля Author/Album/Song + новый UI Закромов»

В проекте нет CI-тестов для этого слоя — проверка выполняется вручную, в
браузере, на LOCAL-окружении. Все шаги — после реализации задач из `tasks.md`.

## Предпосылки

- Локальный docker-стек поднят (`db`, `karaoke-app`, `karaoke-web`, `webvue3`,
  `karaoke-public`) — см. `deploy/do.sh`.
- Миграция `deploy/karaoke-db/31_entity_description_fields.sql` применена на
  LOCAL Postgres.
- `karaoke-app`/`karaoke-web` пересобраны и перезапущены; `webvue3`/
  `karaoke-public` пересобраны (`npm run build` или через `do.sh`).

## Сценарий 1 — редактирование в админке (US1)

1. Открыть webvue3 → «Авторы», выбрать любого автора, кликом по значению
   открыть редактирование, заполнить «Описание», «Короткое описание»,
   «Предупреждение», сохранить.
2. Перезагрузить страницу авторов — убедиться, что значения сохранились
   (видны при повторном открытии редактирования).
3. Повторить для «Альбомы» (выбрать альбом того же автора) и для песни этого
   автора (страница «Песни» → редактирование песни).

**Ожидаемо**: все 3×3 = 9 полей сохраняются и переживают перезагрузку страницы
админки.

## Сценарий 2 — Закрома: предупреждение/короткое описание/тултип (US2)

1. У автора из Сценария 1 заполнить `warning`, `shortDescription`,
   `description` (если ещё не заполнены).
2. Открыть публичный сайт → страница Закромов этого автора (`/zakroma/<author>`
   или соответствующий маршрут `karaoke-public`).
3. Проверить: имя автора — предупреждение красным текстом НАД именем; короткое
   описание — серым текстом через пробел ПОСЛЕ имени; наведение курсора на имя
   показывает тултип с описанием.
4. То же самое для альбома с заполненными полями — плюс под названием альбома
   виден тип (Студийный/Сингл/…), взятый из сущности Album.

**Ожидаемо**: визуальные правила применяются независимо (пустое поле → элемент
не рендерится).

## Сценарий 3 — карточка песни (US3)

1. Открыть страницу песни с заполненными `description`/`shortDescription`/
   `warning` (страница `/song/<id>` или аналог в `karaoke-public`).
2. В информационном блоке (рядом с тональностью/темпом) проверить те же 3
   визуальных правила.

## Сценарий 4 — порядок альбомов по sortOrder (US4)

1. В webvue3 → «Авторы» → модалка «Альбомы автора» (drag-and-drop) задать
   произвольный порядок трём+ альбомам одного автора.
2. Открыть Закрома этого автора в сквозном режиме — альбомы должны идти
   строго в заданном порядке (не по году/алфавиту).

## Сценарий 5 — переключатель сквозной/групповой (US5)

1. Взять автора минимум с 3 разными типами альбомов (например, студийные +
   синглы + концертники).
2. В шапке Закромов переключить на «сгруппированный» режим.
3. Проверить: альбомы разбиты на блоки с заголовками "Студийные альбомы",
   "Синглы", "Концертные альбомы" (в этом порядке); заголовки отсутствующих у
   автора типов (Сборники/Бутлеги) не показаны.
4. Переключить обратно на «сквозной» — заголовки исчезают, порядок = Сценарий 4.
5. Перезагрузить страницу — убедиться, что выбранный режим сохранился
   (`localStorage`, research.md §5).

## Сценарий 6 — быстрые фильтры по типу (US6)

1. На том же авторе — в шапке проверить, что кнопки фильтра показаны только
   для типов с count>0, и на каждой — верное число (например, «Синглы (13)»).
2. Выключить кнопку «Синглы» — все альбомы-синглы должны скрыться со
   страницы, независимо от текущего режима (сквозной/групповой).
3. Переключить режим при выключенном фильтре — синглы должны остаться
   скрытыми.
4. Взять автора без бутлегов — убедиться, что кнопка «Бутлеги» вообще не
   отображается.

## Готово, когда

- Все 6 сценариев проходят визуально без ошибок в консоли браузера.
- `git diff` не содержит изменений вне заявленных в `plan.md` файлов (Принцип V
  — admin/public не смешаны).
- Recordhash-миграция применена на LOCAL (и, по согласованию с пользователем,
  на PROD — см. конституцию, «Категорически запрещено агенту: деплоить на
  сервер без явного согласия»).
