# Phase 1 Data Model: Доступность плеера в таблице «Песни» при статусе ≥4

Фича не добавляет новых сущностей, полей или переходов состояния — она только
меняет UI-условие чтения уже существующего поля.

## Song (существующая сущность, без изменений схемы)

| Поле | Тип | Значения, релевантные фиче |
|------|-----|------------------------------|
| `idStatus` | int | `0`=NONE, `1`=TEXT_CREATE, `2`=TEXT_CHECK, `3`=TEXT_WORDS_VERIFIED, `4`=MARKERS_CREATED, `5`=MARKERS_VERIFIED, `6`=READY |

### Правило доступности плеера (изменяется этой фичей)

| Компонент | Поле-источник | Было | Стало |
|---|---|---|---|
| `SongsTable.vue` → `#cell(player)` иконка | `data.item.idStatus` | активна при `>= 6` | активна при `>= 4` |
| `SongsTable.vue` → `#cell(player)` disabled title | `data.item.idStatus` | «Плеер недоступен (статус < 6)» | «Плеер недоступен (статус < 4)» |

### Без изменений (для контраста, см. spec.md Assumptions)

| Компонент | Поле-источник | Порог |
|---|---|---|
| `SongsTable.vue` → `#cell(playerDemo)` иконка + title | `data.item.idStatus` | `>= 6` (не меняется) |
| `SongEdit.vue` → кнопка «Открыть плеер» (▶) | — | без статусного гейта (не меняется) |

Никакого изменения в БД, DTO, sync-реестре или backend API не требуется —
`idStatus` уже загружается в таблицу вместе с остальными полями песни.
