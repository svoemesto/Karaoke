## Что делает

Пакет закрывает 15 записей аудита #336 в модуле `karaoke-public` — публичном
SPA сайта. Записи разных классов, но одного свойства: **публичная страница
врала пользователю** — показывала «ссылка мертва» при сбое сервера, «автор не
найден» вместо объяснения, пустое предупреждение правообладателя, «успешную»
отмену подписки, которая не выполнилась.

Темы пакета: `author-id-find`, `request-token-timeout`, `postmessage-origin`,
`return-timeout`, `cancel-ignores-status`, `route-state`.

## Зачем

- **Публичный периметр.** Пользователь читал «ссылка истекла» при временном
  сбое сервера, «не удалось отключить автопродление» — тишина при неудачной
  отмене, пустую страницу — при битой ссылке на автора.
- **Правообладатель.** Предупреждение автора (в т.ч. правовое «удалено по
  требованию правообладателя») не показывалось на публичной странице **никогда**:
  при переходе на NDJSON-стрим авторские поля потерялись.
- **Безопасность.** Плеер плейлиста принимал `postMessage` от любого окна —
  единственным барьером была строковая константа из бандла.
- **Ресурсы.** Таймер ожидания токена жил 8 секунд после ухода со страницы и
  продолжал очередь (до 500 HTTP-запросов); интервал опроса заданий создавался
  на уже размонтированном компоненте и его было нечем снять.
- **Гонка.** Стрим автора A, завершившийся после старта стрима автора B,
  показывал песни A на странице B и гасил прогресс-бар B.

## Как работает

Правки идут по той же двухуровневой схеме, что и пакет `PKG-S3-27`:

1. **Правило живёт в чистом модуле** `karaoke-public/src/utils/*.js` —
   без зависимостей, тестируется `node --test` без `node_modules` и без
   браузера: `authorIndex.js`, `messageOrigin.js`, `tokenTimers.js`,
   `streamGeneration.js`, `shareClaim.js`, `zakromaRoute.js`, `stemJobs.js`.
2. **Точка применения** — в `.vue`/`.js` компонентов; для неё есть
   **контрактный тест по тексту исходника**
   (`karaoke-public/src/utils/__tests__/sourceContract.js`) — он компилируется
   и на старом коде, но **падает** на нём (AssertionError, а не «модуль не
   найден»).

Общие принципы:

1. **Ответ разбирается по кодам.** Доменный код ошибки — это разные состояния
   с разными текстами и разными действиями, а не «всё остальное → 404».
2. **«Повторить» повторяет операцию.** Ровно ту, что упала, с теми же
   параметрами — без навигации.
3. **Состояние — из маршрута.** Один URL обязан вести себя одинаково при
   прямом заходе, F5 и переходе изнутри SPA.
4. **Ресурс снимается при уходе.** Таймеры, промисы и листенеры — на инстансе
   компонента, с явным снятием в `beforeUnmount`.
5. **Поколение запроса.** Коммитить ответ вправе только последний запрос.
6. **Флаг — из поля, которое реально есть в DTO.** Несуществующее поле в
   шаблоне — это вечный `false`, а не «мелочь».

## Известные ловушки

1. **Один маршрут — один компонент, несколько `path`.** `ZakromaView` стоит на
   маршрутах `/zakroma`, `/zakroma/{id}`, `/zakroma/{id}/albums` и
   `/zakroma/special-bucket`, и vue-router **переиспользует инстанс**
   (`data()` не вызывается заново). Поэтому состояние страницы нельзя
   выводить из клика — только из `$route` (иначе F5 по прямой ссылке даёт
   другую страницу, чем клик по той же ссылке).
2. **`params.authorId` — строка, и не всегда id.** Для маршрута
   `/zakroma/special-bucket` его нет вовсе, а для `/zakroma/{id}` это число.
   Проверка «числовой ли id» обязательна, иначе `/zakroma//albums` (нет такого
   маршрута) даёт пустую страницу.
3. **NDJSON-контракт расширяется только необязательными полями.** `meta`
   теперь несёт авторские поля; старый фронт их просто не читает, новый фронт
   обязан терпеть их отсутствие (старый бэкенд). Новые поля в NDJSON-сообщения
   — только nullable.
4. **Флаг SKIP автора нельзя отдавать всем.** `authorSkip` уходит только тем,
   у кого `canWorkWithSkipped` — иначе это раскрытие скрытого автора
   обычному посетителю (в REST-версии `ZakromaPublicDto` флаг отдавался всем —
   здесь сознательно строже).
5. **Lease share-сессии живёт 90 секунд.** Продлевает его heartbeat **плеера**,
   а не лендинга. Лендинг обязан либо продлевать lease, либо повторно claim'ить
   перед переходом в плеер — иначе пользователь получает «Ошибка: HTTP 404».
6. **`window.parent` в плеере плейлиста — единственный легитимный отправитель.**
   Проверка origin обязательна: `X-Frame-Options`/`frame-ancestors` на
   публичном nginx **не выставлены** (см. `karaoke-public/nginx_karaoke-public.conf`),
   фрейминг сайта第三方 не запрещён. Усиление заголовков на уровне nginx —
   **за владельцем** (может сломать встраивание плеера в другие сервисы).
7. **В `karaoke-public` `setTimeout`/`setInterval` без хэндла — ловушка.**
   Ручка таймера обязана жить на инстансе компонента (не на уровне модуля) и
   сниматься в `beforeUnmount`; колбэк после `await` обязан проверять флаг
   размонтирования.
8. **`SongPublicDto` не содержит `tags`.** Поля `tags` в DTO нет — есть
   вычисленный `contentRemoved` (сервер считает его из `tags` **точным**
   сравнением токена). Читать `song.tags` во фронте — читать вечный `undefined`.
9. **REST-версия `ZakromaPublicDto` и NDJSON-стрим — два разных источника
   авторских полей.** Любое новое поле блока автора обязано появиться в обоих
   (`ZakromaPublicDto` и NDJSON `meta`), иначе страницы разойдутся.
10. **Каталог тайлов авторов — тысячи записей.** Линейный `find` по нему в
    шаблоне означает O(строк × каталог) на каждый рендер (в плейлисте — до
    500 строк). Резолв — в `computed`, по `Map`, один раз на строку.
11. **Контрактные тесты читают текст исходника.** Новый фикс без контрактного
    теста остаётся непроверенным на «до/после»: поведенческий тест чистой
    функции проверяет только модуль, а не факт его применения в компоненте.
12. **Регресс-тесты публичного SPA двух уровней.** Поведенческие проверяют
    чистые функции; контрактные читают исходник
    (`karaoke-public/src/utils/__tests__/sourceContract.js`) и падают на старом
    коде. Новый фикс без контрактного теста останется непроверенным на
    «до/после».
