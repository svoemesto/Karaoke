# Quickstart: Мини-редактор — редизайн (валидация)

**Branch**: `233-mini-editor-redesign` | **Date**: 2026-08-15

> Этот документ — **руководство по ручной проверке** редизайна мини-редактора в admin SPA. Используется после реализации, чтобы убедиться, что фича работает end-to-end. В CI автотестов нет (см. Constitution § «Рабочий процесс» → «Тесты»).

## Предусловия

1. **Окружение**:
   - Admin-машина (`hostname != dev-pc` ИЛИ `dev-pc` под `dev`).
   - Локальный `webvue3` собран и запущен (`cd webvue3 && npm run dev`, см. `DEVELOPMENT.md`).
   - `karaoke-app` запущен (для отдачи API мини-редактора, см. `deploy/do.sh`).
   - В LOCAL-БД (`Connection.local()`) есть как минимум **3 тестовые песни**:
     - **A**: 1 голос, с маркерами (например, простая запись с 1 дорожкой вокала).
     - **B**: 2 голоса, с маркерами (например, дуэт).
     - **C**: 5 голосов (например, хор или квинтет), с маркерами.

2. **Доступы**:
   - Открыть `http://localhost:8897/admin/songs/<id>` (или URL, по которому стартует `webvue3` dev-сервер).
   - Войти как админ (`webvue3` permitAll — вход не требуется, см. Constitution V).
   - Должна быть хотя бы одна песня, для которой **открывается мини-редактор** (кнопка «Редактировать» / «Открыть в редакторе» в карточке песни).

3. **Сборка**:
   - `cd webvue3 && npm run build` — должна пройти без warnings.
   - `cd webvue3 && ./node_modules/.bin/eslint src/components/SongEditor/SongKaraokeEditorView.vue` — должно вернуть 0 errors и **0 new** warnings сверх baseline (`./tools/check-eslint-baseline.sh`).

## Сценарий проверки

### Шаг 1: открыть мини-редактор для песни A (1 голос)

**Действие**: в карточке песни A нажать «Редактировать» / «Открыть в мини-редакторе».

**Ожидаемый результат**:

1. ✅ Открывается окно мини-редактора.
2. ✅ В верхней части **нет** дубля заголовка с названием, исполнителем и бейджем «Песня» (блок `.ske-header` скрыт через `v-if="false"`).
3. ✅ В шапке страницы/модалки (`Машина Времени · редактирование песни`) название и исполнитель видны (это существующая шапка, не трогаем).
4. ✅ Видна **карточка «плеер + голоса + волна»** — единый блок с общим фоном/обводкой, внутри:
   - **Верхняя строка** (Pass 2, через `.ske-pv-header` flex space-between): слева — кнопки голосов («Голос 1», «+ Голос»), справа — кнопка «▶ Прослушать в плеере».
   - Вейвформа.
   - Бегущая строка под вейвформой.
   - Транспорт (⏮ ▶ ⏭ + слайдеры скорость/масштаб/гем/громкость **+ панель «Показать клавиатуру / Очистить маркеры / Типограф»** в конце строки).
5. ✅ Под карточкой — **двухколоночный лэйаут**:
   - Левая колонка: «Текст песни» + слайдер шрифта + `<textarea>`.
   - Правая колонка: 3 кнопки в ряд («Показать клавиатуру / Очистить маркеры / Типограф») **над** preview-блоком «Разметка» + слайдер шрифта + тёмный preview.
6. ✅ Блок «Новая строка / Куплет / Припев / Бридж / Приговор / Группа 4 / Комментарий…» **не виден** (скрыт за `showKeyboard`).
7. ✅ Между `.ske-transport` и `.ske-texts` **нет** панели «Показать клавиатуру / Очистить маркеры / Типограф» (она переехала в правую колонку).

**Что проверять руками**:
- Прокрутить окно — заголовок нигде не «всплывает».
- В DevTools (F12) проверить DOM: `.ske-header` присутствует, но имеет `display: none` (или комментарий-`v-if`).
- Сделать скриншот — сравнить с эталоном из спеки (если есть Figma/мокап).

### Шаг 5: панель маркер-действий в карточке плеера (Pass 2)

**Действие**: в карточке плеера нажать «Очистить маркеры» → «Типограф» (кнопки в `.ske-transport`, **справа от ползунка «Громкость»**).

**Ожидаемый результат**:

1. ✅ «Очистить маркеры» — маркеры текущего голоса очищаются.

5. ✅ Панель расположена **внутри карточки плеера**, **после ползунка «Громкость»**, в правой части строки `.ske-transport` (рядом с другими элементами транспорта).
6. ✅ В правой колонке (preview) панели нет — там только preview-блок «Разметка».

### Шаг 6: drawer при `<1024px`

**Действие**: открыть мини-редактор для **любой** песни. Ресайз окна браузера так, чтобы ширина стала < 1024px (например, 900px или открыть DevTools → toggle device toolbar → iPad portrait 768×1024).

**Ожидаемый результат**:

1. ✅ Правая колонка (preview + панель маркер-действий) **скрывается** (translateX(100%) или display: none).
2. ✅ Появляется кнопка-«бургер» (`.ske-drawer-toggle`) — где именно (над текстом / рядом с голосами / в углу) — по результату визуальной примерки, но она видна.
3. ✅ Клик на «бургер» — правая колонка выезжает (drawer), появляется затемнение (`.ske-drawer-backdrop`).
4. ✅ Клик на затемнение — drawer закрывается.
5. ✅ Внутри drawer'а кнопки «Очистить маркеры / Типограф / Показать клавиатуру» работают как раньше.
6. ✅ Клик на «Прослушать в плеере», переключение голосов, ввод текста — продолжают работать (они в основной части страницы, не в drawer'е).
7. ✅ Ресайз обратно к `>= 1024px` — drawer исчезает, правая колонка возвращается на место (даже если `rightDrawerOpen === true`, CSS media-query скрывает его).

## Что делать, если что-то сломалось

| Симптом | Вероятная причина | Что проверить |
|---------|-------------------|---------------|
| Дубль заголовка всё ещё виден | `v-if="false"` не добавлен на `.ske-header` | DevTools → проверить, рендерится ли `.ske-header` |
| Голоса не в карточке плеера | Не добавлена обёртка `.ske-player-voice-wave-card` | DevTools → проверить DOM |
| Спецтеги видны без toggle | `ske-spectag-toolbar` не перемещён в `.ske-keyboard` | DevTools → найти `ske-spectag-toolbar` |
| Панель «Показать клавиатуру» под плеером | `ske-kb-toolbar` не перемещён в правую колонку | DevTools → найти `ske-kb-toolbar` |
| >4 голосов переносятся на 2-ю строку | `flex-wrap: nowrap` не применён | CSS → `.ske-voice-tabs` |
| Drawer не открывается при `<1024px` | Нет `.ske-drawer-toggle` или `rightDrawerOpen` не работает | DevTools → проверить data и CSS |
| Регрессия 232/163 | Затронут `<script>` без необходимости | Git diff → проверить, что менялся только `<template>` + `<style>` + минимально `<script>` (только `rightDrawerOpen`) |
