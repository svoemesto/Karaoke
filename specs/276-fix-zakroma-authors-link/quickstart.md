# Quickstart: ручная валидация фикса 276-fix-zakroma-authors-link

**Дата**: 2026-08-30
**Спека**: [spec.md](spec.md)

## Предусловия

1. **Окружение**: `dev-pc` (или любая другая машина) с поднятым `karaoke-public` (dev-server на `http://localhost:5173`) или собранным и развёрнутым билдом (`deploy/do.sh build_start_public`).
2. **Backend**: `karaoke-web` доступен на `http://localhost:8897` (или прод). БД содержит хотя бы 2-х авторов с песнями.
3. **Browser DevTools**: открыть Network tab для отслеживания HTTP-запросов (стрим песен автора виден как chunked-NDJSON ответ).
4. **Известные ID авторов** для теста:
   - Открыть `http://localhost:5173/zakroma` → DevTools → посмотреть ID у любого тайла (например, `<a href="/zakroma/123">`). Использовать реальные ID из локальной БД.

## Опциональный пре-чек (для подтверждения бага ДО фикса)

```bash
# На ветке master (без фикса) выполнить:

# - Открыть /zakroma/123
# - Кликнуть «← К списку авторов»
# - Наблюдать: URL → /zakroma, на экране — список песен (баг).
```

## Сценарии валидации

### Q1 — Базовый сценарий US1 (P1)

**Цель**: подтвердить, что клик на «← К списку авторов» с `/zakroma/N` действительно возвращает на сетку тайлов.

**Шаги**:
1. Открыть `http://localhost:5173/`.
2. Кликнуть «Закрома» → попадаем на `/zakroma` (сетка тайлов).
3. Кликнуть на любой тайл автора → попадаем на `/zakroma/<id>` (страница песен автора).
4. Дождаться загрузки стрима (виден прогресс-бар).
5. Кликнуть на ссылку «← К списку авторов» в левой части шапки.

**Ожидаемый результат**:
- URL в адресной строке: `http://localhost:5173/zakroma`.
- На экране: сетка тайлов всех авторов (НЕ список песен).
- В шапке слева: ссылка «← К списку авторов» отсутствует (т.к. автор не выбран → `zakromaHeaderBack === null`).
- DevTools → Network: предыдущий стрим прерван (статус `canceled` или `aborted`), новых запросов нет (authorTiles уже в кэше Vuex).

**Если упало**:
- Если на экране всё ещё список песен — watcher не сработал. Проверить, что `'$route.path'` действительно watcher'ит в `ZakromaView.vue`.
- Если ссылка в шапке осталась — `authorChosen` не сброшен. Проверить вызов `backToAuthors()` в watcher'е.

### Q2 — Спец-корзина (US1 Scenario 2)

**Цель**: подтвердить, что фикс покрывает также возврат с `/zakroma/special-bucket`.

**Шаги**:
1. Открыть `/zakroma`.
2. Кликнуть на спец-плашку «Отдельные песни разных авторов» в конце сетки тайлов → попадаем на `/zakroma/special-bucket`.
3. Дождаться загрузки таблицы.
4. Кликнуть «← К списку авторов» в шапке.

**Ожидаемый результат**:
- URL: `/zakroma`.
- На экране: сетка тайлов (со спец-плашкой в конце).
- В шапке слева: ссылки нет.

### Q3 — Обратное направление (US1 Scenario 3)

**Цель**: убедиться, что фикс не сломал противоположный flow (из тайлов — на конкретного автора).

**Шаги**:
1. Выполнить Q1 (дойти до `/zakroma` с сеткой).
2. Кликнуть на тайл другого автора → попадаем на `/zakroma/<другой_id>`.

**Ожидаемый результат**:
- URL: `/zakroma/<другой_id>`.
- На экране: список песен нового автора.
- В шапке слева: ссылка «← К списку авторов» снова появилась.
- Стрим запустился (виден прогресс-бар).

**Если упало**:
- Если клик по тайлу НЕ переключает на список песен (остаёмся на сетке) — watcher пересбрасывает state при переходе `/zakroma` → `/zakroma/<id>`. Проверить условие `newPath === '/zakroma' && oldPath !== '/zakroma'`.

### Q4 — Системная «Назад» в браузере (US2)

**Цель**: подтвердить, что `router.replace` работает корректно — не плодит дубликаты в истории.

**Шаги**:
1. Открыть `http://localhost:5173/` (новая вкладка, чистая история).
2. Перейти: `/` → клик «Закрома» → `/zakroma` → клик на тайл автора → `/zakroma/<id>`.
3. Кликнуть «← К списку авторов» в шапке → URL → `/zakroma` (через `replace`).
4. Нажать системную кнопку «Назад» браузера ОДИН раз.
5. Проверить URL после «Назад».
6. Нажать «Назад» ещё раз.
7. Нажать «Назад» ещё раз.

**Ожидаемый результат** (history stack):
- Шаг 4: URL → `/` (НЕ `/zakroma/<id>`, потому что `/zakroma/<id>` был заменён на `/zakroma` через replace).
- Шаг 6: URL → `/zakroma` (предыдущий entry в истории).
- Шаг 7: URL → `/`.

**Если упало**:
- Если после шага 4 попадаем на `/zakroma/<id>` — `<RouterLink>` использует `push` вместо `replace`. Проверить, что в `AppHeader.vue` на `<RouterLink>` стоит атрибут `replace`.

### Q5 — Сброс локального состояния (US3)

**Цель**: убедиться, что после возврата на сетку локальные фильтры сбрасываются, а пользовательские настройки (theme, albumDisplayMode) сохраняются.

**Шаги**:
1. Открыть `/zakroma/<id>`.
2. В поле быстрого фильтра «Быстрый фильтр по названию песни...» ввести произвольную подстроку (например, `love`). Убедиться, что таблица отфильтровалась.
3. В шапке таблицы (если есть) включить режим «По типам альбомов» (grouped). Убедиться, что layout переключился.
4. Кликнуть «← К списку авторов».
5. Перейти на другого автора через тайл → `/zakroma/<другой_id>`.
6. Проверить: поле фильтра пустое, режим отображения — сохранённый «По типам альбомов».

**Ожидаемый результат**:
- Шаг 4: URL `/zakroma`, сетка тайлов.
- Шаг 6: поле фильтра пустое (сброшено), режим «По типам альбомов» сохранён (из localStorage).

### Q6 — Edge case: отмена активного стрима

**Цель**: убедиться, что при клике на «← К списку авторов» в момент загрузки стрима прогресс-бар исчезает, нет «зависших» состояний.

**Шаги**:
1. Открыть `/zakroma/<id>` для автора с МНОГО песен (например, > 50 — чтобы стрим шёл ощутимо).
2. НЕ дожидаясь конца прогресс-бара, кликнуть «← К списку авторов».

**Ожидаемый результат**:
- URL → `/zakroma`.
- Сетка тайлов отображается сразу, без артефактов прогресс-бара.
- DevTools → Network: предыдущий chunked-запрос имеет статус `canceled`.
- `state.zakroma.isStreaming === false` (можно проверить через Vue DevTools → Vuex → modules → zakroma).

### Q7 — Edge case: несуществующий ID автора

**Цель**: убедиться, что watcher не ломает обработку ошибки «Автор не найден».

**Шаги**:
1. Открыть `/zakroma/999999` (несуществующий ID).
2. Дождаться уведомления `Автор с ID=999999 не найден`.
3. Проверить: на экране сетка тайлов (`authorChosen === false` выставлен в `mounted()` fallback), в шапке нет back-link (т.к. `authorChosen === false`).

**Ожидаемый результат**:
- Всё работает, как до фикса. Watcher не должен срабатывать, потому что path остаётся `/zakroma/999999` (не переходит на `/zakroma`).

## Опциональный регресс-тест: проверка `trackUi`

В DevTools → Network → ищем запросы на `/api/public/events` (или аналогичный endpoint для трекинга):

- При клике «← К списку авторов» → должен появиться POST с `event_type=ui, link_type=navigate, link_name=zakroma`.
- При нажатии системной «Назад» → аналогично, с `link_name=<предыдущий_route>`.

Это sanity-check что трекинг не сломан фиксом.

## Когда валидация считается пройденной

Все 7 сценариев (Q1-Q7) дали ожидаемый результат. Если хотя бы один упал — фикс неполный, нужно вернуться к `research.md` и пересмотреть решение R-1 (watcher) или контракт в `contracts/zakroma-view-state.md` (AppHeader.replace).

## Что НЕ покрывает этот quickstart

- **Автоматизированные тесты**: их нет (см. AGENTS.md — все unit/integration тесты `@Disabled`). Проверка — только ручная.
- **Cross-browser**: тестировать в актуальных Chrome/Firefox/Safari. Edge-cases IE/старых браузеров не покрываем (проект современный, см. `livedocs/architecture-notes.md`).
- **Accessibility (screen readers, keyboard navigation)**: edge case в `spec.md:87` упомянут, но не формализован в quickstart. Если требуется — отдельная спека.
- **Performance при большом числе авторов (1000+ тайлов)**: спека не покрывает (scope — фикс навигации, не производительность рендера тайлов).
