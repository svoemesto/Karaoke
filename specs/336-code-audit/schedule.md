## Темп и точки отчёта

- 3 аудитора параллельно; лид ревьюит каждую пачку до запуска следующей.
- Промежуточный отчёт после волны 1: `bug-report-w1.md` — только S1/S2 публичного периметра, чтобы ранние находки не ждали конца.
- Финальный отчёт — после волны 7; тесты идут в отдельный раздел.
- Ориентир: 6–9 порций в день при трёх параллельных аудиторах и ревью лида; 78 порций ≈ 10–14 рабочих дней. Ориентир не обязательство: качество ревью важнее темпа.

## Если бюджет кончается

Режем в обратном порядке риска:

1. тесты (волна 7) — оставить только те, что маскируют production-дефекты;
2. build/CSS/шаблоны/доки внутри волн 4–6;
3. tools/deploy/config/CI;
4. никогда не режем волны 1–3 (публичный периметр, деньги, данные, сохранение).

Снижение глубины допустимо только для низкорисковых модулей: S1/S2 ищем, S3 — по остатку. Остаток фиксируется в `status.md` разделом «Не покрыто» с причиной.
