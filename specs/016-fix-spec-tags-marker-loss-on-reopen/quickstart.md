# Quickstart: Спецтеги — сохранение маркеров после «Точные маркеры → Apply → Save → reopen»

**Input**: spec.md, research.md, data-model.md, contracts/README.md
**Phase**: 1 (design)

## 0. Назначение

Этот документ — **runnable-проверка фикса** вручную в браузере (по образцу `quickstart.md` спеки 010). Юнит-тестов на Vue-стороне SubsEdit.vue проект не пишет (см. спек 010 `tasks.md` T024 — «ручная проверка в браузере»), и эта спецификация формализует ЧТО именно проверяется после фикса.

## 1. Предусловия

- Локальная копия репозитория Karaoke, ветка `016-fix-spec-tags-marker-loss-on-reopen`.
- Запущены локальные контейнеры через `deploy/do.sh` (admin-контейнер, web-контейнер, public, postgres, minio, alignment-ml).
- В БД есть хотя бы одна **размеченная** песня (id_status >= 3), у которой в `sourceText` есть распознаваемый спецтег (например `~Припев~` или `~group:1~`).
- В БД есть хотя бы одна **размеченная** песня БЕЗ спецтегов (регрессионный набор).
- В `karaoke.properties` (на прод-машине это `/sm-karaoke/system/Karaoke.properties`, на local — то, что проброшено в `karaoke-app`) выставлен `alignmentServiceUrl` и доступен alignment-ml.
- `useFinetunedModel` — по умолчанию из `alignmentUseFinetunedModel` (любое значение, для теста подходит оба).

## 2. Подготовка тестовых песен

Если в текущей локальной БД нет размеченной песни со спецтегом, можно:

1. Открыть любую размеченную песню в `SubsEdit.vue` (`/Songs` → открыть строку).
2. В поле текста (textarea «editor») **вставить** `~Припев~` на отдельной строке перед одним из куплетов.
3. **Сохранить** (кнопка Save в `SubsEdit.vue`).
4. Закрыть редактор.
5. Открыть снова — убедиться, что спецтег-маркер (`GROUP|1` от `~Припев~`) появился **в добавок** к существующим (если есть) или сам по себе (если на той позиции не было соответствующего маркера). Это baseline сценария D спеки 010.

**Важно**: до фикса этот сценарий приводит к потере маркеров на reopen. После фикса — нет.

## 3. Сценарии проверки

### Сценарий A — БАГ-РЕПРО (без фикса должен падать, с фиксом — проходить)

**Цель**: воспроизвести ровно тот сценарий, который описал пользователь.

**Шаги**:

1. Открыть в `SubsEdit.vue` песню со спецтегом (например, `~Припев~`) и с расставленными маркерами в БД.
2. Запомнить (сфотографировать на F12 → Vue Devtools, или просто посчитать на глаз):
   - Число syllables-маркеров.
   - Число endofline-маркеров.
   - Число group/comment/newline-маркеров.
3. Нажать «Точные маркеры» (кнопка с иконкой `icon_auto_markers.svg` в панели).
4. В модалке дождаться завершения (статус «Готово», кнопка «Применить маркеры к голосу» активна).
5. Нажать «Применить маркеры к голосу». Модалка закроется, на вейвформе появятся новые маркеры.
6. Снова посчитать: syllables/endofline/group/comment/newline — все должны быть в примерно том же количестве, что в шаге 2 (могут быть незначительные отличия из-за пересчёта forced-alignment).
7. Нажать Save (иконка дискеты в панели).
8. Закрыть редактор (закрыть вкладку или перейти на другую страницу админки).
9. Снова открыть ту же песню в `SubsEdit.vue`.

**Ожидаемое поведение (с фиксом)**:

- На reopen в `sourceMarkers` присутствуют ВСЕ маркеры, что были после Apply в шаге 6.
- `syncMarkersFromSpecTags()` отрабатывает аддитивно: для каждого spec tag-маркера, который УЖЕ есть в `loadedMarkers`, **ничего не вставляется** (FR-006 спеки 010). Дубликатов быть не должно.
- Если `sourceText` содержит спецтег, для которого в `loadedMarkers` **нет** маркера (например, пользователь только что добавил `~comment:трек барабанов~` в текст), этот маркер **должен** появиться (FR-007 спеки 010, аддитивная вставка).
- Число маркеров с одинаковой парой `(markertype, label)` в `sourceMarkers` после reopen **не больше**, чем в `loadedMarkers` (т.е. дубликатов не появилось).

**Проверка в Vue Devtools** (F12 → Vue → `SubsEdit.vue` → `data` → `sourceMarkers`):

- `sourceMarkers.length` после reopen ≈ `sourceMarkers.length` после Apply (с точностью до ±1 за счёт `createBeatMarkers`).
- Все маркеры с `markertype === 'syllables'` имеют непустой `label`.
- Все маркеры с `markertype === 'setting'` и `label.startsWith('GROUP|')` имеют валидный номер группы (0..4).
- Все маркеры с `markertype === 'setting'` и `label.startsWith('COMMENT|')` имеют непустой текст после `|`.

**Ожидаемое поведение (без фикса, текущий код)**:

- На reopen в `sourceMarkers` присутствуют ТОЛЬКО spec tag-маркеры, автоподставленные `syncMarkersFromSpecTags()` (визуально 2-3 маркера вместо 20-30 после Apply). **Это и есть баг.**

### Сценарий B — Регрессия на песне БЕЗ спецтегов (должна проходить и ДО, и ПОСЛЕ фикса)

**Цель**: убедиться, что фикс не сломал поведение для песен без спецтегов.

**Шаги**:

1. Открыть в `SubsEdit.vue` размеченную песню БЕЗ единого спецтега в `sourceText`.
2. Посчитать: syllables, endofline, group, comment, beat.
3. Нажать «Точные маркеры» → «Применить».
4. Сохранить.
5. Закрыть редактор.
6. Открыть снова.

**Ожидаемое поведение**:

- Число и состав маркеров после reopen совпадают с тем, что было после Apply.
- НЕ появляется никаких spec tag-маркеров (т.к. в `sourceText` нет распознанных тегов).
- Поведение **идентично** тому, что было до этого фикса (регрессия недопустима, FR-007 спеки 015).

### Сценарий C — Спецтег, для которого НЕТ соответствующего маркера в БД (US1/Acceptance #3 из спеки)

**Цель**: убедиться, что `syncMarkersFromSpecTags()` корректно аддитивно добавляет недостающий маркер.

**Шаги**:

1. Открыть размеченную песню.
2. В textarea «editor» вставить `~comment:трек барабанов~` на отдельной строке.
3. Нажать Save.
4. Закрыть редактор.
5. Открыть снова.

**Ожидаемое поведение**:

- На reopen в `sourceMarkers` присутствует маркер `{markertype: 'setting', label: 'COMMENT|трек барабанов'}` (аддитивно добавлен `syncMarkersFromSpecTags`).
- Дубликатов `COMMENT|трек барабанов` нет.
- Остальные маркеры на месте.

### Сценарий D — Спецтег на той же позиции, что уже есть соответствующий маркер (FR-006 спеки 010)

**Цель**: убедиться, что `syncMarkersFromSpecTags()` НЕ дублирует маркер, если соответствующий уже есть.

**Шаги**:

1. Открыть размеченную песню, у которой в БД есть маркер `GROUP|1` на позиции 30.0s.
2. В textarea «editor» вставить `~Припев~` (= `~group:1~`) на отдельной строке так, чтобы spec tag-анкор пришёлся в то же окно (между двумя syllables-маркерами, в которое попадает 30.0s).
3. Нажать Save.
4. Закрыть редактор.
5. Открыть снова.

**Ожидаемое поведение**:

- На reopen в `sourceMarkers` есть **ровно ОДИН** маркер `GROUP|1` (а не два). Дубликат НЕ создаётся.

### Сценарий E — Переключение голоса в `SubsEdit.vue` (US1 в части «switch voice»)

**Цель**: убедиться, что фикс корректно работает при переключении между голосами в редакторе.

**Шаги**:

1. Открыть песню минимум с двумя голосами, у КАЖДОГО из которых в `sourceText` есть спецтег и расставлены маркеры.
2. Переключиться на голос №2 (select «Голос» в панели).
3. Посчитать маркеры голоса №2 (syllables, endofline, group, comment, beat).
4. Переключиться обратно на голос №1.
5. Посчитать маркеры голоса №1.

**Ожидаемое поведение**:

- Число маркеров голоса №1 (после возврата) совпадает с числом ДО переключения на №2.
- Число маркеров голоса №2 совпадает с тем, что в БД.
- Дубликатов не появляется.
- `syncMarkersFromSpecTags` отрабатывает корректно на обоих голосах (т.е. spec tag-маркеры добавляются, если их не было, и не дублируются, если были).

### Сценарий F — Правка текста (ручное редактирование уже размеченной песни) (US3 спеки 010)

**Цель**: убедиться, что ручная правка текста по-прежнему аддитивно добавляет маркеры (FR-007 спеки 010).

**Шаги**:

1. Открыть размеченную песню.
2. В textarea «editor» вставить `~newline~` на отдельной строке (например, между двумя куплетами, где ещё нет `NEWLINE`-маркера).
3. Подождать ~100мс (watcher `sourceText` асинхронный).

**Ожидаемое поведение**:

- В `sourceMarkers` появляется новый маркер `{markertype: 'newline', label: ''}` в позиции между двумя syllables-маркерами.
- Остальные маркеры не изменились.
- Дубликатов `newline`-маркера на той же позиции нет (если уже был — новый не вставится).

### Сценарий G — «Точные маркеры + Apply» БЕЗ последующего Save

**Цель**: убедиться, что немедленный Apply работает корректно (тест на шум).

**Шаги**:

1. Открыть размеченную песню со спецтегом.
2. Нажать «Точные маркеры» → «Применить».
3. **НЕ нажимать Save**, а сразу нажать Reload страницы (F5).

**Ожидаемое поведение**:

- После F5 и повторного открытия маркеры — то, что было ДО Apply (т.е. предыдущее сохранённое состояние в БД). Ничего не «утекло» в БД, ничего не «потерялось» при Apply, если Save не нажат.

## 4. Что фиксировать в `architecture-notes.md` (если сценарий A падает)

Если на шагах сценария A обнаружено расхождение, **до** дебага — собрать следующее (для отчёта о баге):

- Содержимое `sourceMarkers` ДО Apply (Vue Devtools → скриншот).
- Содержимое `sourceMarkers` ПОСЛЕ Apply.
- Содержимое `sourceMarkers` на reopen (Vue Devtools).
- Значение `loadedMarkers.length` на reopen (Vue Devtools).
- Содержимое `autoMarkersDebug.markers` после Apply (Vue Devtools → компонент SubsEdit → data).
- Скриншот waveform с маркерами на reopen.

Это ускорит локализацию первопричины (если фикс не покрывает какой-то сценарий).

## 5. Связь с quickstart спеки 010

Этот quickstart **расширяет** quickstart спеки 010 (который покрывает Сценарии A-E по базовой функциональности спецтегов) сценариями reopen-потока. Все сценарии спеки 010 (особенно «Сценарий D» — ручное добавление тега в размеченную песню и «Сценарий E» — удаление тега без удаления маркера) **должны** проходить как ДО, так и ПОСЛЕ этого фикса — это требование FR-007 спеки 015 (регрессия недопустима).
