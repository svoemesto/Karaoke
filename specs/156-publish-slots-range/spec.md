# Feature Specification: Расширение диапазона свободных слотов публикации

**Feature Branch**: `156-publish-slots-range`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "Админка, SongEdit. Когда поле "Дата публикации" пусто и получает фокус то отображается список свободных слотов для публикации (с 11 до 17). Надо расширить диапазан с 10 до 22. Проверить, чтобы даты в списке были только в будущем. Если посленяя публикация в слоте 10:00 была месяц назад, а сейчас 12:00, то свободный слот на 10:00 должен быть на завтрашнюю дату."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Расширенный диапазон часовых слотов (Priority: P1)

Администратор открывает карточку песни с пустым полем «Дата публикации», ставит в него фокус и видит подсказку со списком свободных слотов на каждый час с 10:00 до 22:00 включительно, а не только с 11:00 до 17:00, как раньше.

**Why this priority**: Текущий диапазон (11–17) искусственно ограничивает время публикаций серединой дня. Более широкий диапазон (10–22) даёт администратору больше вариантов равномерно распределить публикации в течение дня без ручного подбора времени.

**Independent Test**: Открыть карточку любой песни с пустым полем «Дата публикации», поставить в него фокус и убедиться, что список подсказок содержит по одному варианту на каждый час с 10:00 по 22:00 включительно (13 вариантов), включая часы, для которых раньше вариантов не было (10:00, 18:00–22:00).

**Acceptance Scenarios**:

1. **Given** поле «Дата публикации» пустое, **When** пользователь ставит в него фокус, **Then** список подсказок содержит один вариант даты для каждого часа с 10:00 до 22:00 включительно.
2. **Given** в системе никогда не было ни одной песни, запланированной на час 20:00, **When** пользователь открывает список подсказок, **Then** в списке всё равно присутствует свободный слот на 20:00 (на ближайшую подходящую дату), а не отсутствует вовсе.

---

### User Story 2 - Предлагаются только будущие даты (Priority: P1)

Администратор видит в списке подсказок только даты и время, которые ещё не наступили, независимо от того, когда в последний раз использовался этот часовой слот.

**Why this priority**: Предложение слота в прошлом бесполезно и вводит в заблуждение — администратор может случайно запланировать публикацию на прошедшую дату, что фактически означает немедленную/просроченную публикацию либо ошибку данных.

**Independent Test**: Для часового слота, последняя занятая дата которого была месяц назад, открыть список подсказок в момент, когда текущее время уже позже часа этого слота, и убедиться, что предложенная дата — ближайшая будущая (не месячной давности + 1 день, и не сегодняшняя, если час уже прошёл).

**Acceptance Scenarios**:

1. **Given** последняя запланированная публикация в слоте 10:00 была месяц назад, **When** текущее время — сегодня, 12:00, **Then** свободный слот для 10:00 в списке подсказок — это 10:00 завтрашнего дня (а не 10:00 следующего дня после той месячной давности даты).
2. **Given** последняя запланированная публикация в слоте 15:00 была вчера, **When** текущее время — сегодня, 10:00 (то есть 15:00 сегодня ещё не наступило), **Then** свободный слот для 15:00 в списке подсказок — это сегодняшняя дата.
3. **Given** последняя запланированная публикация в слоте 15:00 была сегодня, **When** текущее время — сегодня, 20:00, **Then** свободный слот для 15:00 в списке подсказок — это завтрашняя дата.
4. **Given** для часового слота ещё никогда не было ни одной запланированной публикации, **When** текущее время ещё не достигло этого часа сегодня, **Then** свободный слот предлагается на сегодня; **When** текущее время уже позже этого часа сегодня, **Then** слот предлагается на завтра.

---

### Edge Cases

- Что если текущее время совпадает секунда-в-секунду с часом слота (например, ровно 10:00:00)? Слот считается уже наступившим (не в будущем) и должен быть сдвинут на завтра.
- Что если для часового слота существует несколько будущих запланированных публикаций подряд (например, на ближайшие 5 дней вперёд)? Предложенный свободный слот должен быть на первый день после самой поздней уже занятой даты для этого часа (а не на первую свободную дату, пропущенную между занятыми).
- Что если у песни, которую сейчас редактируют, уже проставлены дата и время публикации, совпадающие с одним из предлагаемых слотов? Слот всё равно показывается в списке подсказок как обычно (список не исключает слот, занятый самой редактируемой песней).
- Что если сервер и администратор находятся в разных часовых поясах? Расчёт «текущего времени» и всех предложенных дат выполняется по времени сервера (существующее поведение сохраняется, не меняется в рамках этой фичи).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА предлагать по одному свободному слоту публикации на каждый целый час в диапазоне с 10:00 до 22:00 включительно (13 часовых слотов: 10:00, 11:00, …, 22:00) вместо текущего диапазона 11:00–17:00.
- **FR-002**: Для каждого часового слота система ДОЛЖНА вычислять предлагаемую дату как первый день после самой поздней даты, уже занятой публикацией в этот час, среди всех песен независимо от площадки публикации (сохраняется текущий принцип «один слот на час на календарный день», без разделения по площадкам).
- **FR-003**: Если для часового слота ещё не было ни одной запланированной публикации в системе, слот ВСЁ РАВНО ДОЛЖЕН быть предложен: на сегодняшнюю дату, если этот час сегодня ещё не наступил, иначе — на завтрашнюю дату.
- **FR-004**: Система ДОЛЖНА гарантировать, что предложенная дата и время каждого слота строго позже текущего момента времени на сервере. Если вычисленный по правилу FR-002 кандидат (день после последней занятой даты) оказывается в прошлом или совпадает с уже наступившим сегодня часом, система ДОЛЖНА сдвигать предложенную дату вперёд (на сегодня, если час ещё не наступил, иначе на ближайший будущий день), пока не будет найдена ближайшая дата, строго позже текущего момента.
- **FR-005**: Список свободных слотов ДОЛЖЕН отображаться пользователю как подсказки при получении полем «Дата публикации» фокуса, когда оно пусто (существующее поведение точки вызова не меняется).
- **FR-006**: Порядок и формат отображения предложенных слотов (одна строка вида «дата время» на слот) ДОЛЖЕН остаться таким же, как в текущей реализации, — меняется только состав часов и корректность выбора даты.

### Key Entities

- **Часовой слот публикации**: фиксированный час дня (10:00, 11:00, …, 22:00), для которого система хранит и предлагает одну свободную дату публикации.
- **Свободный слот**: пара «часовой слот + дата», предлагаемая администратору как следующая доступная дата для публикации в этот час, гарантированно находящаяся в будущем относительно текущего момента на сервере.
- **Запланированная публикация песни**: существующая запись песни с заполненными датой и временем публикации, используемая для определения того, какие даты в каждом часовом слоте уже заняты.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Список подсказок при фокусе на пустом поле «Дата публикации» всегда содержит ровно 13 вариантов — по одному на каждый час с 10:00 до 22:00 включительно.
- **SC-002**: 100% предложенных в списке дат и времени строго позже текущего момента времени на сервере (ни одна дата в списке никогда не оказывается в прошлом или равна текущему моменту).
- **SC-003**: Для часовых слотов, которые ранее (до расширения диапазона) никогда не использовались, администратор всё равно видит предложенный вариант в списке, а не пустое место.
- **SC-004**: Администратор может выбрать любой из 13 предложенных вариантов и сохранить песню без дополнительной ручной проверки/коррекции даты на предмет «не в прошлом».

## Assumptions

- Диапазон «с 10 до 22» из описания пользователя понимается как включающий обе границы (10:00 и 22:00), по аналогии с текущим диапазоном «с 11 до 17», который на практике реализован как 7 включительных часов (11:00…17:00).
- Определение «свободности» слота остаётся глобальным по всей системе (по всем песням и площадкам публикации), без разделения по площадкам (VK/Telegram/др.) — в описании пользователя не запрошено изменение этого принципа, меняется только диапазон часов и гарантия «только будущее».
- «Текущий момент» для проверки «только будущее» — время сервера приложения (та же система отсчёта времени, что уже используется в текущей реализации), без учёта часового пояса конкретного администратора.
- Список свободных слотов используется только как подсказки (datalist) — поле «Дата публикации» остаётся редактируемым вручную, пользователь не ограничен строго этими 13 вариантами.
