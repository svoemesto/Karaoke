# Contract: формат журнала автоматизации allow-list

> Phase 1 output. Контракт формата записей (FR-012) и уведомлений (FR-013).

## 1. Носители

| Носитель | Путь | Что пишется |
|---|---|---|
| Файл журнала | `ALLOWLIST_LOG_FILE` (по умолчанию `/var/log/admin-ip-allowlist.log`) | Те же строки, что и в stderr |
| journald | stdout/stderr сервиса | Те же строки (unit: `StandardOutput=journal`, `StandardError=journal`) |
| Уведомление | Telegram Bot API | Краткий итог (см. §4) |

Файл журнала и файл состояния лежат **вне репозитория**; в git не попадают.

**Журнал пишется в stderr, stdout остаётся машинным каналом.** Это требование
вытекает из устройства скрипта: функции вроде `detect_address` возвращают значение
через stdout, и строка журнала, попавшая в тот же поток, делала значение непригодным
(на живой машине адрес всегда получался «невалидным»). Под systemd и stdout, и stderr
идут в journald (`StandardOutput=journal`, `StandardError=journal`), поэтому в журнале
ничего не теряется.

## 2. Формат записи

Одна строка на событие, формат `event:key=value` (конвенция структурированного логирования,
ADR `local-0005`). Ключи — стабильные, значения — без пробелов и кавычек (пробелы заменяются
`_`).

| Событие | Обязательные ключи | Смысл |
|---|---|---|
| `probe` | `target`, `ok`, `duration_ms`, `detail` | Результат одной пробы: `pg:5433`, `minio:9000`, `https` |
| `decision` | `reason`, `action` | Причина срабатывания (`https_down`, `allow_list`, `all_ok`) и решение |
| `address` | `ip`, `sources`, `agree` | Определённый адрес, число ответивших источников, согласие источников |
| `skip` | `reason` | Правка не выполнялась: `already_allowed`, `rate_limit`, `invalid_ip`, `sources_disagree`, `no_sources`, `prod_down`, `config_mismatch` |
| `edit` | `ip`, `blocks`, `backup` | Подготовлена правка: адрес, число затронутых блоков, путь бэкапа |
| `syntax` | `ok`, `cmd` | Результат проверки синтаксиса (команда — без секретов) |
| `reload` | `ok` | Результат перезагрузки nginx |
| `control` | `pg_ok`, `minio_ok`, `https_ok` | Результат контрольной проверки (FR-009) |
| `rollback` | `ok`, `reason` | Откат выполнен или не понадобился; причина сбоя |
| `notify` | `channel`, `ok` | Отправлено ли уведомление владельцу. При неудаче дополнительно: `reason` (`proxy_unreachable` / `transport_error` / `api_error`), `http_code`, `curl_rc`, `proxy` (`set` / `none`) |
| `pr` | `url`, `ok` | Создан ли PR, ожидающий одобрения (FR-014) |

## 3. Обязательные поля записи о правке

FR-012 требует в каждой записи о попытке/правке: **метку времени, адрес, причину срабатывания,
результат проверки синтаксиса, результат контрольной проверки, выполненное действие, признак
отката**. Реализация обязана обеспечить их наличие — либо одной сводной строкой `edit:...`,
либо связанной цепочкой строк `decision` → `address` → `syntax` → `reload` → `control` →
`rollback`, где сводка собирается из них.

Метка времени — ISO-8601 UTC (`2026-10-30T14:05:12Z`) в начале строки либо в ключе `ts`.

## 4. Уведомление владельцу (FR-013)

Текст — краткий, без содержимого конфигурации и без секретов (FR-016):

| Событие | Содержание |
|---|---|
| Успешная правка | адрес, время, результат проверки синтаксиса, результат контроля, ссылка на PR |
| Откат | адрес, причина сбоя, что восстановлено |
| Недоступны все источники адреса | факт, что адрес определить не удалось, прод не тронут |
| Расхождение источников | какие ответы разошлись (адреса — не секрет), прод не тронут |
| Превышение частоты | когда была последняя правка, когда следующая будет возможна |
| Прод недоступен по ssh | факт, прод не тронут |
| Прод недоступен целиком (HTTPS не отвечает) | причина не в allow-list, адрес не добавлялся, прод не тронут (FR-002, US1-сценарий 3) |
| Адрес невалиден или IPv6 | что именно не прошло валидацию, правка не выполнялась (FR-004, edge case IPv6) |

Если `ALLOWLIST_TELEGRAM_BOT_TOKEN` не задан — уведомление не отправляется, в журнал пишется
`notify:channel=none ok=false reason=token_absent`. Отсутствие токена не является ошибкой
выполнения (код возврата не меняется).

**Недоставленное уведомление** (прокси недоступен, Telegram недоступен, не-2xx) —
тоже не ошибка выполнения: в журнал пишется `notify:channel=telegram ok=false` с
`reason` (`proxy_unreachable` / `transport_error` / `api_error`), `http_code`, `curl_rc` и
`proxy` (`set` / `none`); код возврата цикла не меняется. Значение прокси в журнал не
попадает — только факт его наличия.

## 5. Ограничения содержимого

- Токены, пароли, значения `Authorization` в журнал **не попадают** (FR-016).
- Содержимое `nginx.conf` в журнал **не попадает** — только факты (адрес, число блоков, путь
  бэкапа, результаты проверок).
- Секреты в argv не допускаются (guard `tools/check-secret-in-argv.sh`, BR-551/552/605):
  токен Telegram передаётся через `curl -K` с конфиг-файлом `600`.
