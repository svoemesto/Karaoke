# agent-command-guard — защита команд AI-агента

Плагин хоста **DeepSeek Harness (DSH)**: перехватывает вызов инструмента `bash`
**до выполнения**, сверяет текст команды с политикой запретов и оставляет след
в append-only журнале.

Контекст и решение: карта [KARAOKE-339](https://tracker.sm-karaoke.ru/svoemesto/projects/KARAOKE/issues/339)
(`[wayfinder:map] Жёсткие ограничения AI-агента`), прототип — тикет KARAOKE-342,
финальный перечень правил — KARAOKE-343.

## Зачем

Правило «контейнеры — только через `deploy/do.sh`», «коммит — только через
feature-ветку + PR», «force-push запрещён» написано в `AGENTS.md` — но
инструкция не мешает агенту её нарушить: guard'ы репозитория смотрят только в
`git diff HEAD` и ловят **намерение закоммитить**, а не **исполнение**.

Этот плагин закрывает разрыв «правило написано — обход возможен» для команд,
меняющих состояние среды, и делает нарушения **видимыми**.

## Что он делает

| Шаг | Что происходит |
|---|---|
| Перехват | Событие `tools/pre-execute` хоста DSH: до диспетчеризации вызова, текст команды виден целиком |
| Сопоставление | Команда разбирается по сегментам (`&&`, `\|\|`, `;`, `\|`, перевод строки); правила — из политики; часть правил — состояниезависимая (ветка читается из `.git/HEAD` рабочего каталога) |
| Решение | `deny` — запретить вызов; `ask` — спросить владельца через approval-канал DSH (тот же, что у эскалаций песочницы; при его отсутствии — запрет) |
| След | Запись в журнал: время, команда (секреты замаскированы), сработавшее правило, сегмент, вердикт |

## Чего он НЕ делает

- **Не делает нарушение невозможным.** Текстовое правило обходится: `d''ocker`,
  `$(echo docker)`, запуск из скрипта-файла, `podman`, `systemctl`, `kill <pid>`,
  `docker exec`. Корректная цель — «остановить, спросить и оставить след».
- **Не определяет согласие владельца.** Запуск санкционированной команды
  `deploy/do.sh` без одобрения по тексту не виден: это состояние, а не текст.
  Источник согласия — отдельное решение (KARAOKE-343/346).
- **Не покрывает всё.** Только инструмент `bash`; `terminal`, persistent-bash,
  PTC, CUA и внутренние действия MCP-серверов через `tools/pre-execute` не
  проходят.

## Файлы

| Файл | Назначение |
|---|---|
| `index.js` | Плагин: перехват, сопоставление, журнал |
| `cordis.patch.yml` | Строка профиля: id, режим по умолчанию, журналирование всех вызовов |
| `policy/deny-commands.json` | Политика по умолчанию (копируется в `~/.dsh/policies/`) |
| `test-guard.mjs` | Офлайн-проверка матчера на реальных командах агента |
| `locale/`, `icon.svg` | Метаданные и иконка для Plugin Manager |

## Установка

```bash
# 1. Политика запретов и независимый сборщик следа:
bash tools/install-agent-command-guard.sh

# 2. Плагин в профиль DSH — через инструмент plugin_manager (шаг требует
#    одобрения: код хоста исполняется вне песочницы рабочего каталога):
#    plugin_manager install_bundle target=<путь к tools/dsh-agent-command-guard>
#
#    После изменения кода плагина: remove_bundle + install_bundle —
#    правка файла в установленном бандле на лету не подхватывается.
#    Файл политики, наоборот, применяется сразу (перечитывается по mtime).
```

## Пути и права

| Что | Где | Права |
|---|---|---|
| Журнал плагина | `~/.dsh/ledger/agent-commands.ndjson` | 0600 (каталог 0700) |
| Политика | `~/.dsh/policies/deny-commands.json` | 0600 (каталог 0700) |
| Независимый ledger | `~/.dsh/ledger/ledger.ndjson` | 0600 |

Переопределение путей — переменные окружения `DSH_GUARD_POLICY`,
`DSH_GUARD_JOURNAL` или конфиг строки профиля. Пути по умолчанию не содержат
пути конкретной машины.

## Проверка матчера

```bash
# Собрать выборку реальных команд из журналов сессий DSH:
bash tools/dsh-agent-command-guard/extract-commands.sh /tmp/commands.jsonl 200
# Прогнать матчер:
node tools/dsh-agent-command-guard/test-guard.mjs \
  tools/dsh-agent-command-guard/policy/deny-commands.json /tmp/commands.jsonl
```

Ожидание на реальных данных: обязательные срабатывания ловятся все, ложных
срабатываний на легитимных командах нет, обходные варианты (см. выше) —
проходят, и это зафиксированное ограничение, а не дефект.
