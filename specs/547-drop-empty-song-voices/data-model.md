# Phase 1 — Data Model: голоса песни и их нормализация

**Спека**: [spec.md](spec.md) | **Research**: [research.md](research.md)
**Дата**: 2026-10-20

Модель данных не меняется (FR-013): голоса уже хранятся в двух JSON-колонках
`tbl_songs`. Меняется только **правило записи** этих колонок при сохранении песни.

## 1. Сущность «Голос» (voice)

Голос — элемент песни, адресуемый индексом с нуля. Полное состояние голоса
распределено по двум спискам одинаковой длины:

| Аспект | Хранилище | JSON-тип | Пример |
|---|---|---|---|
| Текст голоса | `tbl_songs.source_text` | массив строк | `["Эн- эр- гия...", ""]` |
| Маркеры голоса | `tbl_songs.source_markers` | массив массивов объектов `SourceMarker` | `[[{...621 шт...}], []]` |

`SourceMarker` — существующая модель (`model/SourceMarker.kt`): `time`, `label`,
`note`, `chord`, `stringLad`, `lockLad`, `tag`, `color`, `position`, `markertype`.

**Легаси-форма маркеров**: `source_markers` может быть плоским массивом объектов
(один голос). Читается как один голос — нормализация в этом случае ничего не удаляет.

**Списки разной длины**: допустимая историческая аномалия. Отсутствующий текст =
пустой текст; отсутствующие маркеры = пустой список маркеров.

## 2. Предикат «голос пуст»

```
empty(voice) := textOf(voice).isBlank() && markersOf(voice).isEmpty()
```

- `isBlank()` — пустая строка или только пробельные символы (пробелы, табы,
  переводы строк) — FR Assumptions спеки.
- Любой маркер (включая служебные `SETTING`, `COMMENT`, `ENDOFLINE`) делает голос
  непустым.

## 3. Результат нормализации

```
data class VoiceNormalization(
    val texts: List<String>,              // тексты оставшихся голосов
    val markers: List<List<SourceMarker>>,// маркеры оставшихся голосов
    val removedIndices: List<Int>,        // какие исходные индексы удалены, по возрастанию
    val changed: Boolean,                 // true, если что-то удалено
) {
    fun mapVoice(index: Int): Int?        // старый индекс -> новый, null если голос удалён
    val count: Int                        // texts.size == markers.size
}
```

Правила построения:

1. Рассматриваются индексы `0 .. max(texts.size, markers.size) - 1`.
2. Индекс `0` сохраняется **всегда** (FR-004), даже если голос пуст.
3. Индекс `i > 0` удаляется, если `empty(i)` (FR-001).
4. Оставшиеся голоса сохраняют взаимный порядок; нумерация — 0..N-1 без дыр (FR-003).
5. `texts` и `markers` результата **всегда одинаковой длины**: отсутствующий текст
   дополняется `""`, отсутствующие маркеры — `emptyList()`.
6. Если ничего не удалено — `changed = false`, списки возвращаются как есть
   (никаких «нормализующих» дополнений — FR-005, FR-009).

**Инварианты**:

| ID | Инвариант | FR |
|---|---|---|
| I1 | `count >= 1` для любой песни, у которой вообще есть данные голосов | FR-004 |
| I2 | `texts.size == markers.size` после `changed = true` | FR-003, FR-007 |
| I3 | Подпоследовательность оставшихся голосов побайтово равна исходной | FR-006 |
| I4 | Повторная нормализация нормализованного результата не меняет его | FR-009 |
| I5 | `changed = false` ⇒ данные голосов не переписываются | FR-005, FR-009 |
| I6 | При нечитаемых данных возвращается `null`, ничего не удаляется | FR-012 |

## 4. Пример: песня 15696 («Энергия (акустика, live)», АлисА)

До сохранения (замер по локальной БД 2026-10-20):

```
source_text    = ["Эн- эр- гия...\n..." , ""]
source_markers = [ [<621 маркер>] , [] ]
```

Нормализация на сохранении:

| Индекс | Текст | Маркеров | Пуст? | Решение |
|---|---|---|---|---|
| 0 | непустой | 621 | нет | сохранить |
| 1 | `""` | 0 | да | **удалить** |

После сохранения:

```
source_text    = ["Эн- эр- гия...\n..."]
source_markers = [ [<621 маркер>] ]
countVoices    = 1
removedIndices = [1]
mapVoice(1)    = null        // сохранённый голос удалён -> ответ эндпоинта voice = -1
result_text / formatted_text_* — пересчитаны без «пустого» голоса
```

## 5. Пример: пустой голос в середине

```
до:    [A(10 маркеров), пусто, B(7 маркеров)]
после: [A, B]         removedIndices = [1]
       mapVoice(0) = 0, mapVoice(1) = null, mapVoice(2) = 1
```

## 6. Границы и защита

| Ситуация | Поведение | Основание |
|---|---|---|
| В `fields` нет `SOURCE_MARKERS`/`SOURCE_TEXT` (песня загружена с `withoutMarkersAndText = true`) | нормализация не выполняется; поля не создаются | research R3 |
| `source_markers` не разбирается как JSON | WARN в лог, нормализация пропускается, сохранение идёт обычным путём | FR-012 |
| `source_text` не разбирается, маркеры разбираются | текст считается отсутствующим (все голоса «без текста»); удаление — только по пустым маркерам; перезапись `source_text` не выполняется | FR-012, research R3 |
| Один голос, пустой | ничего не меняется | FR-005, I5 |
| Все голоса кроме первого пусты | остаётся один (первый) | FR-001 |
| Первый голос пуст, остальные нет | первый остаётся, остальные сохраняются | FR-004 |
| Аномалия «текст без маркеров» (песни 2278, 3182, 3197, 19905, 22041) | голос не пуст (текст есть) — сохраняется | спека, Edge Cases |

## 7. Сущности, которые НЕ меняются

- `SongAssignment` (`tbl_song_assignments.voice`) и `SongAssignmentDraft`
  (`edited_markers`/`edited_texts` по голосам) — нормализация их не трогает (FR-015).
- `SongDTO`/`SongPublicDTO` — форма не меняется; меняется только значение
  `countVoices` (становится равен реальному числу голосов) — FR-007.
- Схема БД, `recordhash`, sync-механика — без изменений.

## 8. Проверяемость модели

| Что проверяется | Как |
|---|---|
| Предикат пустоты, сдвиг, mapping, идемпотентность, fail-safe | юнит-тесты `VoiceNormalizationTest` (12+ кейсов) |
| Парсинг реальных данных (15696 и песни с 2+ голосами) | SQL-проверка до/после + сохранение через API (quickstart) |
| `texts.size == markers.size` после сохранения | SQL: `jsonb_array_length` обеих колонок (quickstart) |
