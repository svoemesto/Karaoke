# Quickstart: Закрома автора — отрисовка списка песен без N×3 фоновых запросов

**Branch**: `239-zakroma-author-songs-batch-render` | **Date**: 2026-08-25

Этот документ — руководство по ручной проверке фичи на `dev-pc` или проде после выкатки. Автоматических тестов нет (см. AGENTS.md, раздел «Тесты»), проверка делается вручную.

## Prerequisites

1. **Машина с hostname `dev-pc`** под пользователем `dev` (см. Constitution § Ограничения доступа агента, п.1 — исключение).
2. Karaoke запущен локально (`deploy/do.sh build_start_public` или эквивалент).
3. БД содержит автора «Машина Времени» с ≥ 2000 песен (для регрессии — все `id_status` от 0 до 6).
4. Тестовые пользователи:
   - **Аноним**: инкогнито-окно (без логина).
   - **Зарегистрированный**: пользователь без премиума (например, свежий аккаунт).
   - **Премиум**: пользователь с активной подпиской `scope='SITE', status='PAID'`.

## Сценарий A: основной репорт (P1)

**Цель**: подтвердить, что страница «Машина Времени» НЕ вешает сайт.

### Шаги

1. Открыть инкогнито-окно (аноним), зайти на `/zakroma`.
2. Кликнуть по плашке «Машина Времени».
3. Дождаться полной загрузки списка (~2500 песен).
4. Прокрутить до конца списка.
5. Открыть **второе** окно (обычное) и зайти на `/` (главная).
6. **Refresh** страницу `/zakroma?author=Машина Времени`.

### Ожидаемый результат

- ✅ В DevTools → Network видно **только 1 запрос** для анонима (стрим `/api/public/zakroma/stream`).
- ✅ Все 2500 строк списка отрисованы с **иконками плеера финального цвета** (золотой для `id_status >= 6`, серый для `id_status < 6`). **Никаких спиннеров** «Проверка доступности плеера…».
- ✅ Иконки избранного/плейлистов **скрыты** для анонима (или показаны как «гостевые» серая ★ / серая ▶| — по решению дизайна).
- ✅ Главная страница во втором окне отвечает за **≤ 1 сек** (не зависает).
- ✅ После refresh — `/zakroma` загружается нормально, **не «site down»**.

## Сценарий B: зарегистрированный пользователь

**Цель**: подтвердить корректную работу избранного/плейлистов без per-row запросов.

### Шаги

1. Залогиниться как зарегистрированный (без премиума).
2. Добавить 5 песен в «Избранное» через существующую иконку.
3. Создать плейлист «Тест» и добавить туда 3 песни.
4. Открыть `/zakroma`, выбрать «Машина Времени».
5. Кликнуть по иконке ★ на любой НЕ добавленной в избранное песне → должна мгновенно загореться.
6. Открыть вторую вкладку того же домена, залогиниться тем же юзером → иконка ★ уже горит (через `BroadcastChannel`).

### Ожидаемый результат

- ✅ В DevTools → Network видно **≤ 4 запроса** на загрузку страницы: стрим + `/favorites/ids` + `/song-subscriptions/ids` + (если есть не-избранные плейлисты) `/playlists/membership`.
- ✅ Клик по ★ → мгновенный optimistic update (цвет меняется ДО ответа сервера).
- ✅ BroadcastChannel синхронизирует иконку между вкладками.

## Сценарий C: премиум-пользователь (P2)

**Цель**: подтвердить логику «зелёный vs золотой» для премиума.

### Шаги

1. Залогиниться как премиум.
2. Открыть `/zakroma`, выбрать «Машина Времени».
3. Найти песню со статусом «в эфире» (`is_in_air=true`) → должна быть **зелёная** иконка.
4. Найти обычную готовую песню (`is_in_air=false`, `flag_free=false`, без подписки) → **золотая** иконка.
5. Найти песню с `id_status < 6` → **серая disabled** иконка.
6. Refresh страницы.

### Ожидаемый результат

- ✅ Премиум-песни, «в эфире», `flag_free=true` или с активной подпиской → **зелёная** иконка плеера сразу после рендера.
- ✅ Остальные готовые песни → **золотая** иконка, кликабельна (демо-фрагмент).
- ✅ Неготовые песни → **серая disabled**, клик не открывает плеер.
- ✅ После refresh — те же цвета, без мигания через серый/спиннер.

## Сценарий D: регрессия — страница одиночной песни

**Цель**: убедиться, что страница `/song/{id}` НЕ сломана (backward-compat).

### Шаги

1. Залогиниться как зарегистрированный.
2. Открыть `/song/{id}` (любая готовая песня).
3. Нажать кнопку «Открыть плеер».
4. Убедиться, что плеер открывается и работает.

### Ожидаемый результат

- ✅ Страница `/song/{id}` загружается штатно.
- ✅ Плеер открывается в iframe, токен `kp_token_*` генерируется через `/api/public/player/{id}/access` (как было).
- ✅ Никаких изменений в `PlayerView.vue`.

## Сценарий E: счётчики на бэке

**Цель**: убедиться, что per-row readiness вызовы устранены.

### Шаги

1. Открыть `/zakroma` зарегистрированным юзером, выбрать «Машина Времени».
2. Подождать полной загрузки + прокрутки.
3. Проверить логи `karaoke-web` за последние 5 минут:

```bash
docker logs karaoke-web 2>&1 | grep "POST /api/public/player/readiness" | wc -l
docker logs karaoke-web 2>&1 | grep "GET /api/public/account/playlists/membership" | wc -l
```

### Ожидаемый результат

- ✅ `readiness` вызовов для пользователя со страницы `/zakroma` = **0** (только `/song/{id}` может делать такие вызовы).
- ✅ `playlists/membership` вызовов = **1** (а не 60+ как раньше при chunked-load).

## Сценарий F: отказоустойчивость

**Цель**: убедиться, что падение membership-fetch не вешает UI.

### Шаги

1. Залогиниться как зарегистрированный.
2. Открыть DevTools → Network → «Offline» (или заблокировать `/favorites/ids` через Request Blocking).
3. Открыть `/zakroma`, выбрать «Машина Времени».
4. Дождаться загрузки (иконки в «off»/нейтральном состоянии).
5. Включить сеть обратно.
6. Logout → Login тем же юзером.

### Ожидаемый результат

- ✅ При offline загрузке — иконки показывают «off» (outline), **не блокируют** отрисовку списка.
- ✅ После возврата сети без refresh — иконки остаются «off» (нет retry, см. Clarification Q3).
- ✅ После logout/login — membership подгружается заново, иконки обновляются.

## Метрики для подтверждения SC-*

| SC | Как проверить | Целевое значение |
|----|---------------|------------------|
| **SC-001** | Сценарий A шаг 5-6 | Главная отвечает ≤ 1 сек, refresh не даёт «site down» |
| **SC-002** | Сценарий B шаг 4 | ≤ 4 запроса на загрузку `/zakroma` |
| **SC-003** | Сценарий A шаг 4 | 0 спиннеров, все иконки финального цвета |
| **SC-004** | Сценарий A шаг 3 | ≤ 5 сек до полного списка 2500 песен |
| **SC-005** | Сценарий E шаг 3 | 0 readiness вызовов со страниц списка |
| **SC-006** | Сценарий C | 3 типа юзеров × 3 типа песен = правильные цвета |
| **SC-007** | Сценарий A шаг 4 + DevTools Performance | 60 FPS при прокрутке 2500 строк |

## Что НЕ нужно проверять вручную (вне scope)

- `/api/public/player/readiness` endpoint всё ещё работает (нужен для страниц одиночной песни — отдельная регрессия, см. спеку 100).
- Миграция `tbl_subscriptions` индексов (если добавлялась) — проверить только EXPLAIN ANALYZE запроса, чтобы убедиться, что индекс используется.
- BroadcastChannel fallback для старых браузеров — нет автоматического покрытия; допустимо ручное тестирование в IE11 (если поддерживается) или тихая деградация.
