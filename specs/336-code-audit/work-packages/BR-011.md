# [#336] S1: `POST /changerecords` — публичный endpoint, который исполняет присланный клиентом SQL. Ни… (BR-011)

Задача: устранение дефекта **BR-011** (S1) из полного аудита кода (#336).

## Что не так

`POST /changerecords` — публичный endpoint, который исполняет присланный клиентом SQL. Ни `SecurityConfig`, ни `SiteAuthInterceptor` его не защищают (`SecurityConfig.kt:26–34` — `anyRequest().permitAll()`, `WebMvcConfig.kt:28–35` — только `/api/public/account/**`, `/api/public/auth/{me,logout}`, `/api/siteusers/**`). Единственная проверка — расшифровать фиксированную константу `Crypto.WORDS_TO_CHECK`. Шифр AES/CBC без MAC, а при отсутствии env `CRYPTO_AES_KEY`/`CRYPTO_AES_IV` `Crypto` берёт захардкоженные в репозитории ключ и IV (`Crypto.kt:36–37`, `45–58`, `60–73`); в deploy-конфигах `CRYPTO_AES_*` не задаётся (`grep` по `deploy/` — 0 совпадений, в `docker-compose-web.yml` переменных нет). Таблицы и SET-текст тоже приходят из запроса: `UPDATE $tableName SET $setTextDecrypted WHERE id = $idRecord`.

## Доказательство

«`val word = data["word"] as String` / `if (Crypto.decrypt(word) != Crypto.WORDS_TO_CHECK) return "Не удалось расшифровать кодовое слово"` / `val dataCreate = data["dataCreate"] as List<Map<String, Any>>`» (`karaoke-web/.../controllers/MainController.kt:310–313`, SHA `1977838a`).

## Путь достижимости

`POST https://sm-karaoke.ru/changerecords` → host-nginx `location /changerecords` без `allow/deny` (`deploy/prod-single-host/80to8897:74–88`, `proxy_pass http://127.0.0.1:8897/changerecords`) → `MainController.doChangeRecords` → `Crypto.decrypt` (фиксированное слово) → `connection.prepareStatement(decrypted).executeUpdate()` для каждого элемента `dataCreate`/`dataDelete` → `UPDATE $tableName SET $setTextDecrypted WHERE id = $idRecord` для `dataUpdate` (`MainController.kt:354`). Ограничения на набор таблиц/операций нет: достаточно знать ключ (при дефолте — он в репозитории) и зашифровать `Crypto.WORDS_TO_CHECK` + произвольный SQL.

## Предлагаемая поправка

убрать маршрут с публичного периметра (nginx `allow` только для admin-IP, как у `stream`-портов 5433/9000), авторизацию перевести на общий internal-secret (как в `InternalStemJobController`), ключ сменить и удалить legacy-fallback, операции ограничить белым списком таблиц.
