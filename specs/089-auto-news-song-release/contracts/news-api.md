# Contract: News API — изменения

Эта фича не добавляет новых публичных HTTP-эндпоинтов. Изменения — точечные добавления к
существующим внутренним контрактам (`karaoke-app` ↔ `webvue3`, `karaoke-web` ↔ публичный сайт).

## `POST /api/news/list` (существующий, `NewsController`, `karaoke-app`)

**Без изменений сигнатуры.** Ответ (`NewsDto`) получает одно новое поле:

```json
{
  "id": 123,
  "title": "Новая песня: Автор — Название",
  "body": "...",
  "category": "air",
  "link": "/song?id=456",
  "publishAt": "2026-07-29 12:00:00",
  "createdAt": "2026-07-29 12:00:01",
  "published": true,
  "source": "auto"
}
```

`source` — `"auto"` | `"manual"`. Обратная совместимость: старые клиенты, не знающие про это поле,
продолжают работать без изменений (поле дополнительное, не заменяет существующие).

Чтобы увидеть авто-новости (физически существующие только на PROD), администратор вызывает этот же
эндпоинт с `target=remote` — параметр уже существует и не меняется этой фичей.

## `POST /changerecords` (существующий, `MainController`, `karaoke-web`, PROD-only)

**Без изменений внешнего контракта** (запрос/ответ те же: `dataCreate`/`dataUpdate`/`dataDelete` →
строка статуса). Внутреннее изменение: после применения операций к `WORKING_DATABASE` обработчик
дополнительно вызывает `SongReleaseAnnouncementService.checkAndAnnounce(WORKING_DATABASE)` —
побочный эффект, не отражённый в ответе (по аналогии с тем, что ответ уже сегодня не детализирует,
какие именно записи затронуты, только счётчики).

Если `SongReleaseAnnouncementService` бросит исключение, оно **не должно** ронять уже применённую
синхронизацию (обернуть в `try/catch`, залогировать, вернуть обычный `result` как и раньше) — сбой
детекции анонсов не является причиной откатывать/проваливать реальную синхронизацию данных.

## Новый внутренний контракт: `SongReleaseAnnouncementService`

Не HTTP-эндпоинт — Kotlin-объект/класс, вызываемый напрямую из `MainController.doChangeRecords`.

```kotlin
object SongReleaseAnnouncementService {
    /**
     * Находит песни, которые стали публично доступны, но ещё не были анонсированы,
     * и создаёт по каждой новость. Идемпотентно, безопасно вызывать многократно.
     * @param database подключение к БД, на которой выполняется проверка (WORKING_DATABASE на PROD).
     * @return список id песен, для которых была создана новость (для логирования/тестов).
     */
    fun checkAndAnnounce(database: KaraokeConnection): List<Long>
}
```
