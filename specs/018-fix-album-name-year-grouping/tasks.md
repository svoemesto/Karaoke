## Phase 3: User Story 1 - Посетитель открывает закрома автора с двумя одноимёнными альбомами (Priority: P1) 🎯 MVP

**Goal**: Закрома автора показывают два (и более) альбома с одинаковым
названием, но разными годами как отдельные карточки — каждая со своим годом
и полным набором собственных песен, без потерь и без задвоений.

**Independent Test**: Найти/создать в тестовых данных автора с двумя
альбомами одинакового названия и разных годов (`quickstart.md` → шаг 1),
открыть его закрома через API или UI (`quickstart.md` → шаги 2-3) и
убедиться, что видны обе карточки с корректными годами и полным набором
песен каждая (SC-001, SC-002 spec.md).

### Implementation for User Story 1

- [X] T001 [US1] В `karaoke-app/src/main/kotlin/com/svoemesto/karaokeapp/model/Zakroma.kt`, метод `buildFromSettings()`: заменить группировку альбомов `val settingsByAlbum = settingsByAuthor.groupBy { it.album }` (строка ~126) на группировку по составному ключу «год + название» (например, `Pair(it.year, it.album)` или `data class`), в пределах уже сгруппированных по автору песен. Год карточки (`album.year = ...`) взять из ключа группы, а не из `settingsByAlbum.first().year`, чтобы он не зависел от порядка песен в списке. См. `research.md` → «Решение: ключ группировки альбомов».
- [X] T002 [US1] В том же файле и методе — обновить/добавить KDoc над `buildFromSettings()` (или над блоком группировки альбомов), кратко зафиксировав, что ключ группировки альбома — (год, название) в пределах автора, а не только название, со ссылкой `@see docs/features/special-orders.md`. Выполнять после T001 (один файл).
- [X] T003 [US1] Обновить `docs/features/special-orders.md` (FR-009 конституции): в разделе, описывающем `buildFromSettings()` («группировка Автор→Альбом→Песни»), зафиксировать исправленный ключ группировки альбомов (год + название) и кратко описать баг, который это устраняет (коллизия одноимённых альбомов разных годов). Зависит от T001.
- [X] T004 [US1] Вручную выполнить шаги 1-3 из `quickstart.md` (найти/создать коллизию одноимённых альбомов, проверить через `curl`/API и через UI закромов) в локальном sandbox-стеке. Убедиться, что видны обе карточки с корректными годами и полным набором песен, без потерь и без задвоений (SC-001, SC-002 spec.md). Зависит от T001.
      **Выполнено**: в LOCAL БД нашлись 3 реальные коллизии («Орден Славы»/«Мертвец» 2021+2025, «Вадим Самойлов»/«На Берлин» 2017+2022, «Торба-на-Круче»/«Час времени» 2015+2025). Пересобран и перезапущен `karaoke-web` (бандлит код `karaoke-app`) через `build_web`+`start_web`. `GET /api/public/zakroma?author=Орден Славы` вернул ОБА альбома «Мертвец» отдельно: 2021 (1 песня), 2025 (10 песен) — суммарно 11, как в БД. Остальные 2 коллизии проверены аналогично — тоже разделились корректно.

**Checkpoint**: Основной баг устранён и подтверждён вручную — это уже
самостоятельно ценный MVP фичи.

## Phase 4: User Story 2 - Автор без коллизий имён альбомов не замечает изменений (Priority: P2)

**Goal**: Для авторов без дублирующихся названий альбомов закрома выглядят и
работают ровно так же, как и до фикса — без регрессии в количестве
альбомов, составе песен, сортировке или оформлении.

**Independent Test**: Открыть закрома нескольких авторов без коллизий имён
альбомов до и после фикса (`quickstart.md` → шаг 4) и сравнить список
альбомов и подсчёт песен в каждом — результат должен совпадать побайтово
(SC-003 spec.md).

### Implementation for User Story 2

- [X] T005 [US2] Код-ревью guard: убедиться, что изменение в T001 не трогает
      поведение группировки для случая, когда у автора нет коллизий имён
      альбомов (составной ключ (год, название) для единственной пары
      логически эквивалентен прежнему ключу «название», когда коллизий нет).
      Зависит от T001.
- [X] T006 [US2] Вручную выполнить шаг 4 из `quickstart.md` (сравнение
      `curl`-вывода `/api/public/zakroma` для 1-2 авторов без коллизий имён
      альбомов до и после фикса — списки альбомов и подсчёт песен совпадают
      побайтово). Зависит от T001, T004.
      **Выполнено эмпирически** (не только рассуждением): временно
      `git stash` только `Zakroma.kt` → пересборка `karaoke-web` на pre-fix
      коде → тот же запрос для «Орден Славы» (есть и коллизия, и обычные
      альбомы) → сравнение `diff` до/после. Единственное отличие — как раз
      разделение «Мертвец» на 2 альбома (пропавшие 10 песен 2025 года
      вернулись); ВСЕ остальные альбомы автора (не имеющие коллизий имён)
      побайтово идентичны — регрессии нет (SC-003 spec.md). После сравнения
      `git stash pop` — фикс восстановлен, `karaoke-web` пересобран и
      перезапущен на исправленной версии (финальное состояние).

**Checkpoint**: Обе истории подтверждены — основной баг устранён, регрессии
для типичного случая (без коллизий) нет.

## Implementation Strategy

### MVP First (User Story 1)

1. Phase 3 (US1) — сам фикс группировки + документация + ручная проверка.
2. **STOP and VALIDATE**: прогнать шаги 1-3 `quickstart.md`.
3. Phase 4 (US2) — regression guard, быстрый, в основном verification-only.

### Incremental Delivery

1. US1 (сам фикс) → проверить независимо (шаги 1-3 quickstart.md) →
   основная пользовательская ценность доставлена.
2. US2 (guard от регрессии) → проверить независимо (шаг 4 quickstart.md) →
   обязателен перед PR, но не добавляет отдельной пользовательской ценности.
3. Phase 5 (Polish) — линтер, KDoc-покрытие, финальный quickstart.
