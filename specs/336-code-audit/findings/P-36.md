## Сверки

1. **Возвраты ЮKassa (`refund.succeeded`) не обрабатываются.** `PublicPaymentController.webhook` ищет подписку по `object.id`; у события возврата это id возврата, а не платежа → `unknown_subscription`, 200. `STATUS_REFUNDED` объявлен (`Subscription.kt:139`), но нигде не присваивается (`grep -rn STATUS_REFUNDED` — только объявление). После возврата денег подписка остаётся `PAID`, доступ сохраняется. Домен фиксирует возвраты как открытый TODO (`knowledge/domains/monetization/domain.md:286`) — отложенная фича или дефект? Если фича отложена — запись не нужна; если возвраты уже делаются в кабинете ЮKassa — это S2 (деньги).
2. **`POST /api/public/share/debug` без аутентификации** (`PublicShareController.kt:263–270`): для валидного секрета отдаёт `linkId`/`ownerId` и тексты ошибок SQL (`SongShareLinkService.debugTryClaim`, `:694–747`), при этом не проходит через rate-limit `tryClaim` (10/мин на IP), т.е. работает неограниченным оракулом существования ссылки. Практический перебор невозможен (секрет — 32 байта `SecureRandom`, base64url), поэтому в находки не вынесено: подтвердить, нужен ли публичный диагностический эндпоинт в проде.
3. **Неверный код ошибки для `ttlSeconds`:** `PublicShareController.kt:61–63` при недопустимом TTL возвращает `400` с `errorCode = "share.tokenMissing"` (семантически — «секрет не передан»); фронт `ShareView` различает ошибки по `errorCode`. Косметика контракта или намеренный маппинг?

Риск портативности, не рантайма.
5. **Демо-обрезка при непарсируемом MP3:** `Mp3Trimmer.trimToRange` при ошибке разбора возвращает исходные байты целиком (`Mp3Trimmer.kt:87–88`, «лучше отдать длиннее задуманного»).
