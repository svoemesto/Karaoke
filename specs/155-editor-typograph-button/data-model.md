# Data Model: Кнопка «Типограф» в онлайн-редакторе

Фича не добавляет и не меняет персистентные сущности/таблицы БД — только манипулирует уже
существующим in-memory состоянием онлайн-редактора (переиспользует существующие поля, ничего
нового не заводит).

## Затрагиваемое состояние (существующее, без изменений формы)

### `voices[i]` (существующая структура, оба фронтенда)

| Поле | Тип | Затронуто фичей | Примечание |
|---|---|---|---|
| `sourceText` | `string` | Да — заменяется результатом `POST /api/replacesymbolsinsong` | Только для `voices[currentVoiceIdx]`; остальные голоса не трогаются (см. `research.md` §4) |
| `markers` | `array` | Косвенно — пересинхронизируется через `onTextInput()`-путь после замены текста | Формат маркера не меняется; элементы могут добавляться/удаляться, как при любом обычном редактировании текста |
| `syllables` | `array` | Косвенно — пересчитывается через `splitSyllables(sourceText)` как часть `onTextInput()`-пути | Производное от `sourceText`, не хранится отдельно от него смыслово |

### Компонентное состояние (UI, не персистится отдельно от `voices[]`)

| Поле | Тип | Назначение |
|---|---|---|
| `currentVoiceIdx` | `number` | Индекс голоса, к которому применяется замена (существующее поле) |
| `saveState` / `saving` | `string`/`boolean` | Существующий индикатор состояния сохранения — переиспользуется для отображения ошибки, если запрос замены завершился неудачно (см. `research.md` §5) |

## Новые сущности

Нет. Ни новых полей, ни новых DTO/таблиц/миграций фича не вводит — она вызывает уже существующий
backend-эндпоинт (см. [contracts/replacesymbolsinsong.md](./contracts/replacesymbolsinsong.md)) и
переиспользует существующий путь пересинхронизации маркеров (`onTextInput()`).

## Валидационные правила

Нет новых правил валидации на уровне данных: тело запроса — произвольная строка `txt` (в т.ч.
пустая, см. Edge Cases в `spec.md`), backend уже обрабатывает пустой/любой текст без изменений в
рамках этой фичи.
