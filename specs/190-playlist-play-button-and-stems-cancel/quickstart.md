# Quickstart: 190-playlist-play-button-and-stems-cancel

**Branch**: `190-playlist-play-button-and-stems-cancel` | **Date**: 2026-08-14
**Spec**: [spec.md](spec.md) | **Research**: [research.md](research.md) | **Data model**: [data-model.md](data-model.md) | **Contract**: [contracts/api-public-playlist-detail.md](contracts/api-public-playlist-detail.md)

Это **ручной** сценарий проверки фичи — автотесты в CI отключены (`@Disabled` в `karaoke-app/src/test`, см. Constitution §Тесты). Проверка делается пользователем после деплоя на dev-pc.

## Prerequisites

1. Доступ к dev-машине (admin — `dev-pc` hostname, OS-пользователь `dev`), см. [AGENTS.md §Ограничения](../../AGENTS.md).
2. Локальный стенд собран и поднят (`bash deploy/do.sh build_start_public` + `karaoke-app`/`karaoke-web` запущены).
3. Зарегистрированный пользователь с непустым «Избранным» (≥5 песен, чтобы покрыть сценарии SC-002 со spam-click).
4. Браузер с DevTools (для SC-002 — DOM-снимок; SC-003 — Network panel).

## Сценарии проверки

### US1 + US2: визуальный smoke

**Шаги**:
1. Открыть `http://localhost:8897/account/playlists/{FAVORITES_ID}` (URL плейлиста «Избранное»).
2. **Ожидание**: список песен отображается. У каждой строки:
   - слева: drag-handle `⠿`, badge (`♪` если песня доступна, `🔒` если заблокирована).
   - **NEW**: превью альбома 48×48 px.
   - **NEW**: превью автора 48×48 px (справа от альбома).
   - название песни, подзаголовок «Автор — Альбом».
   - **NEW**: кнопка ▶.
   - существующие кнопки 🔊/🔇 и ✕.
3. Кликнуть ▶ на 3-й песне (не на первой).
4. **Ожидание**: плеер стартует именно с 3-й песни, preroll играет, очередь начинается с 3-й.

### US1: muted / locked поведение

**Шаги**:
1. На той же странице нажать 🔇 (mute) на любой песне → её badge станет `🔇`.
2. Навести курсор на кнопку ▶ этой песни.
3. **Ожидание**: 
   - кнопка ▶ **видна**, но **серая** (стиль `disabled`).
   - при hover нативный tooltip: «Эта песня пропускается — сначала включите её».
4. Клик по disabled ▶ — **ничего не происходит**.
5. Снять mute (🔊) → ▶ становится активной.

### US1: ▶ на уже играющей песне (toggle pause)

**Шаги**:
1. Запустить любую песню ▶.
2. Кликнуть ▶ на той же строке.
3. **Ожидание**: плеер ставится на паузу; глобальная кнопка ⏯ плеера показывает `▶`.
4. Повторный клик ▶ на той же строке — плеер продолжает с того же места.

### US3: фикс задвоения вейвформ

**Шаги**:
1. На странице плейлиста нажать ▶ на песне A.
2. **Не дожидаясь** загрузки (визуально — пока спиннер «Загрузка...»), нажать ▶ на песне B.
3. Повторить 5+ раз быстро (spam-click по разным песням).
4. **Ожидание**:
   - В плеере **ровно две** вейвформы (одна «Музыка», одна «Голос»). Никаких наложений/4/6 вейвформ.
   - Прогресс-бар показывает прогресс **только** последней запрошенной песни.
5. Проверка DevTools → Network:
   - Запросы стемов предыдущих песен (`audioAccompanimentUrl`, `audioVocalsUrl`) — статус **canceled** (красный), а не 200.
6. Проверка DOM (в консоли DevTools):
   ```js
   document.querySelectorAll('#kp-ws-acc canvas, #kp-ws-voc canvas').length
   // → должно быть ровно 2
   ```

### US2: превью + fallback на ошибку

**Шаги**:
1. Открыть плейлист.
2. **Ожидание**: у всех строк видны две картинки (или плейсхолдеры).
3. Найти песню, у которой точно нет обложки (например, инструментальная без альбома). Сравнить с песней, у которой есть.
4. **Ожидание**: строки выровнены по высоте; плейсхолдер не «ломает» сетку.
5. Симулировать ошибку загрузки (например, через DevTools → Network → Block request URL для `albumPictureUrl` конкретной строки, обновить страницу).
6. **Ожидание**: на этой строке показывается CSS-плейсхолдер (иконка ♪ для альбома, 👤 для автора), а не битое изображение.

### Бэкенд: проверка контракта

**Шаги**:
1. `curl -H "Authorization: Bearer $TOKEN" http://localhost:8897/api/public/account/playlists/{FAVORITES_ID}`.
2. **Ожидание**: каждый элемент `items[]` содержит `albumPictureUrl` и `authorPictureUrl` (или пустую строку).
3. `curl -I http://localhost:8897/minio/karaoke/<encoded-album-preview-path>`.
4. **Ожидание**: `200 OK` + `Content-Type: image/png` + `Cache-Control: public, max-age=86400` (если песня с альбомом существует).
5. `curl -I http://localhost:8897/minio/karaoke/<несуществующий-путь>`.
6. **Ожидание**: `404 Not Found` (фронт обработает через `@error`).

### Регрессия: одиночная песня вне плейлиста (FR-012)

**Шаги**:
1. Открыть любую песню напрямую: `http://localhost:8897/player/{songId}` (без `?pl=1`).
2. **Ожидание**: плеер ведёт себя **идентично** версии до фичи — те же вейвформы, тот же прогресс, тот же preroll.
3. Перезагрузить страницу, открыть ту же песню, нажать ⏭ (без плейлиста — неактивно).
4. **Ожидание**: поведение плеера без изменений (нет postMessage handlers, нет queue).

### Регрессия: drag-drop / mute во время воспроизведения

**Шаги**:
1. Запустить воспроизведение песни X (▶ в строке X).
2. Перетащить песню Y на 1-ю позицию (drag-drop).
3. **Ожидание**: очередь в плеере обновилась (`pushQueue` отработал); песня X доиграла до конца, затем пошёл следующий трек (Y теперь первый).
4. Не прерывая, нажать 🔇 на текущей играющей.
5. **Ожидание**: песня доигрывает до конца (mute не прерывает); при auto-next следующая не-muted песня.
