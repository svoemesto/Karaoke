# Отчёт по issue #323 — полное переименование артефактов песни

## Что сделано

Переименование песни в админке (`POST /api/song/update`, параметр `fileName`) теперь
переименовывает **все** её артефакты, а не только часть.

| Файл | Изменение |
|---|---|
| `model/SongArtifactRenamer.kt` | новый объект: переименование локальных артефактов (исходник, `[key].json`, стемы, вложения, симлинки) |
| `model/Song.kt` | новый `renameAllArtifacts(oldFileName)` + `moveStorageObject` (перенос объектов картинок в обоих хранилищах) |
| `controllers/SongUpdateMapper.kt` | вызов `renameAllArtifacts` после существующего каскада |
| `KaraokeFileType.kt` | `PUBLICATION_PICTURE_NAME_SUFFIXES` — общий список суффиксов картинок |
| `services/cleanup/ArtifactCleanupClass.kt` | реестр уборки использует общий список вместо своей копии |
| `test/.../RenameAllArtifactsTest.kt` | новый тест-класс, 7 тестов |
| `docs/features/complete-song-rename.md` | per-feature документ (FR-009) |
| `specs/323-complete-song-rename/spec.md` | спека с FR-001…FR-005 и SC-001…SC-003 |

## Факты с диска (до правки)

Найдено при ремонте группы «Чёрный Обелиск» (#322). После переименования песни 30287
через штатный эндпоинт:

- переименовались: `<файл>-accompaniment.mp3`, `<файл>-vocals.mp3` в `hdemucs_mmi` и те же
  объекты в локальном и прод-MinIO;
- **не переименовались**: `<файл>.flac`, `<файл> [key].json`,
  `hdemucs_mmi/<файл>-{accompaniment,vocals}.flac`;
- проверка здоровья сразу после переименования показала 12 нарушений, в том числе
  `AUDIO_SONG/LOCAL_FILESYSTEM`, `AUDIO_ACCOMPANIMENT/LOCAL_FILESYSTEM`,
  `AUDIO_VOCAL/LOCAL_FILESYSTEM` — то есть песня выглядела сломанной, хотя файлы лежали рядом
  под старым именем;
- у песни 22072 дополнительно остались `done_files/*.txt` и симлинк
  `symlink_sponsr/<файл>-accompaniment.flac`, который после ручного переименования цели
  стал бы висячим.

## Что осталось за владельцем

- Перезапуск/пересборка `karaoke-app` не требуется для приёмки: правка проявится после
  ближайшего деплоя образа. Проверка сценария в UI — на стороне владельца.
- Ретроактивных переименований не требуется: накопленные имена вычищены в #322.

## Открытые вопросы и факты, найденные при реализации

- `Song` нельзя сконструировать в юнит-тесте (нужны БД и хранилища) — поэтому файловая логика
  вынесена в `SongArtifactRenamer`. Это же ограничение отмечено в тестах specs/544.
- Проверка здоровья на холодном кеше хранилища отвечает «нет» на первый запрос: сразу после
  переноса объектов первый прогон даёт фантомные `REMOTE_STORAGE`-нарушения, повторный — чистый.
- `/api/song/update` молча игнорирует неизвестные параметры (верный ключ — `fileName`), и его
  операция может идти дольше двух минут; обрыв клиента по таймауту её не отменяет.
