# Data Model: состояния и цвета песен

## 1. Производная сущность «Состояние песни»

Состояние песни не хранится как отдельная пользовательская сущность и не требует отдельной записи в БД. Оно вычисляется из текущего снимка песни.

| Атрибут | Тип/форма | Назначение |
|---|---|---|
| `idStatus` | целое число | Определяет готовность; значения меньше 6 всегда дают `IN_WORK`. |
| `free` | логический признак | Помечает песню как постоянно бесплатную. |
| `date` + `time` | пара строк расписания | Формирует момент эфира; неполная или некорректная пара считается отсутствующим действительным моментом. |
| `now` | текущий момент в часовом поясе эфира | Нужен для различения `TODAY`, текущего бесплатного окна и `DONE`. В production используется московское время, в тестах передаётся явно. |
| `state` | одно из пяти значений | Производная категория песни. |
| `color` | строка цвета или пустая строка | Визуальное представление `state`. |

## 2. Канонические значения

| Состояние | Цвет | Условие |
|---|---|---|
| `IN_WORK` | `""` | `idStatus < 6`, независимо от остальных атрибутов. |
| `ON_AIR` | `#33FF33` | `idStatus >= 6` и `free=true`, либо готовая песня находится в действующем бесплатном окне после эфира. |
| `EXCLUSIVE` | `#99CCFF` | `idStatus >= 6`, `free=false`, действительная пара даты/времени отсутствует. |
| `TODAY` | `#FFFF00` | `idStatus >= 6`, `free=false`, дата эфира сегодня, момент эфира ещё не наступил. |
| `DONE` | `#CCFFCC` | `idStatus >= 6`, `free=false`, действительная дата и время есть, но песня не является `ON_AIR` или `TODAY`. |

## 3. Порядок разрешения конфликтов

1. Проверить готовность: `idStatus < 6` → `IN_WORK`.
2. Проверить постоянную бесплатность: `free=true` → `ON_AIR`.
3. Проверить наличие действительного момента эфира. Если его нет → `EXCLUSIVE`.
4. Если дата эфира сегодня и момент ещё не наступил → `TODAY`.
5. Если эфир уже наступил и бесплатное окно ещё действует → `ON_AIR`.
6. Во всех остальных случаях при наличии действительного расписания → `DONE`.

Порядок делает категории взаимоисключающими и покрывает все входные состояния.

## 4. Переходы

Состояние пересчитывается при следующем обновлении данных песни и может измениться без изменения записи в БД при переходе времени через момент эфира или конец бесплатного окна:

- `IN_WORK` → `TODAY`, `ON_AIR`, `DONE` или `EXCLUSIVE` после достижения `idStatus >= 6` и в зависимости от расписания/free.
- `TODAY` → `ON_AIR` в момент эфира, если бесплатное окно активно.
- `TODAY` → `DONE` после эфира, если бесплатное окно не применяется или уже завершилось.
- `ON_AIR` → `DONE` после окончания бесплатного окна для песни без `free=true`.
- `EXCLUSIVE` → `TODAY`, `ON_AIR` или `DONE` после заполнения корректной даты и времени.
- Любое готовое состояние → `ON_AIR` при включении `free=true`.
- Любое состояние готовой песни → `IN_WORK` при снижении `idStatus < 6`.

## 5. Передача в представления

`SongDTO.color` и `SongDTOdigest.color` остаются существующими полями представления. Они должны содержать канонический цвет состояния, включая пустую строку для `IN_WORK`. Вложенные песни `PublicationDTO` используют тот же цвет; отдельное поле `songState` не вводится.

## 6. Не в скоупе

- Состояния фоновых процессов и отдельных каналов публикации.
- Изменение критериев готовности `idStatus`.
- Изменение доступа онлайн-плеера и длительности бесплатного окна.
- Изменение схемы БД, recordhash-триггеров, `SyncRegistry` и sync-флагов.
