Без severity; к разбору лидом/владельцем.

1. **Роутер вне порции — имя порции вводит в заблуждение.** Порция названа «webvue3: views + router», но `webvue3/src/router/index.js` (167 строк) по ведомости относится к **P-65** (32 файла, 3 723 строки, статус `PENDING`). Guard'ов в роутере нет вообще: `grep -n "beforeEach\|requiresAuth\|meta\|redirect" webvue3/src/router/index.js` — пусто, т.е. админ-маршруты (`/stats`, `/subscriptions`, `/sync` …) открываются любому, кто знает URL. Проверка «роутер/guard (auth, redirect)» в границах P-67 невыполнима по составу порции — лиду стоит отдельно убедиться, что P-65 закрывает роутер.
2. **Доступ к API админки.** Все эндпоинты, которые вызывает `StatsView` (`/api/stats/*`, `/api/webevents`), отдаются без аутентификации: `SecurityConfig.kt` (`karaoke-app`, P-08) — `requestMatchers("/api/private/**").authenticated(); anyRequest().permitAll()`, CSRF выключен. Уже зафиксировано как **BR-114** (`admin-api-no-auth:karaokeapp`, SEC, S3) — новой записи не создаю. Отмечу только практическое следствие для этой порции: `GET /api/stats/summary?target=remote` и `GET /api/stats/monetization?target=remote` отдают аналитику **продовой** БД (`target=remote` — это `Connection.remote()`) без учётных данных и без CSRF-защиты; в связке с отсутствием guard'а в роутере это делает дашборд StatsView доступным любому, кто дотянется до :7906.
3. **Режим графика «Динамика» и период в кешируемых endpoint'ах.** `onChangeTimeSeriesMode` (`:878–880`) → `loadStatsTimeSeries({ mode })` → `GET /api/stats/timeseries?target=…&days=…&mode=type`; бэкенд кладёт ответ в `StatsCache` под ключом `StatsCacheKey(endpoint, emptyMap())` (`StatsController.kt:78`, `StatsCacheKey.kt:16–19`) — `mode`, `days` и `target` в ключ не входят. Поэтому переключение режима графика и период не меняют картинку до истечения 60-секундного backend-кеша. Это **BR-195** (`cache-key-no-params:stats`, DATA, S2) — фронтовая часть корректна, новой записи не создаю; фиксирую здесь, что из фронтовых переключателей затронуты 6 кешируемых endpoint'ов (`summary` — `:149`, `monetization` — `:164`, `timeseries` — `:187`, `channels` — `:212`, `countries` — `:226`, `referrers` — `:240`), а `by-type` (`:202`), `by-detail` (`:255`), `by-song` (`:93`), `webevents` (`:124`), `top-users` (`:264`), `top-listened` (`:109`) кешем не покрыты (см. сценарии A и B в P-67-01).
4. **Внешняя ссылка из данных БД.** Колонка «Источник» рендерит `evt.referer` как кликабельную ссылку (`:273–281`), а `referer` — это `document.referrer` публичного сайта, то есть значение задаёт внешний посетитель. XSS исключён (рендерится только при `^https?://`, `rel="noopener noreferrer"`, Vue экранирует атрибуты), но это открытая ссылка на произвольный домен в админке (в т.ч. в `title`-подсказках). Вопрос владельцу: показывать ли внешние домены вообще/с подсветкой, или рендерить как текст.
