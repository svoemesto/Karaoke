# Верификация BR-509 — дефект не воспроизводится (уже исправлен)

- **Задача**: KARAOKE-398 «CI: шаг «No direct commits to master» выполняется в shallow-клоне и не видит историю (BR-509)»
- **BR-код**: BR-509
- **Карточка-источник**: `specs/336-code-audit/findings/P-78.md`, находка P-78-03 (класс BUILD, severity S2).
- **Реестр**: `specs/336-code-audit/registry.csv` — BR-509, статус `исправлено`, review `lead-verified`,
  work_package `409`.
- **Итог**: **(Б) дефект в текущем коде отсутствует** — правка не выдумывалась, код не менялся.

## Что проверял

Утверждения находки P-78-03:

1. Шаг «No direct commits to master» выполнялся в shallow-клоне (`checkout` без `fetch-depth`).
2. Из-за этого `git log --first-parent origin/master` отдавал пустой вывод.
3. Счётчик `DIRECT_COMMITS` всегда оставался 0, и guard «final safety net» никогда не срабатывал —
   прямой коммит в master проходил незамеченным.
4. Дефект был в **обеих** копиях CI-конфигурации (`.github/workflows/` и `.forgejo/workflows/`).

## Как проверял (команды)

Обе копии CI-конфигурации — шаг `checkout` перед шагом guard'а:

```bash
for F in .github/workflows/lint.yml .forgejo/workflows/lint.yml; do
  N=$(grep -n "No direct commits to master" "$F" | tail -1 | cut -d: -f1)
  awk -v s=$((N-40)) -v e=$N 'NR>=s && NR<=e' "$F"
done
```

Штатные проверки CI-конфигурации (указаны в самой задаче):

```bash
bash tools/check-ci-workflow-sync.sh
bash tools/check-ci-checks-manifest.sh
```

## Вывод

**Не воспроизводится.** В обеих копиях CI-конфигурации шаг `checkout` перед guard'ом идёт с
`fetch-depth: 0` — полная история, `origin/master` доступен, `git log --first-parent origin/master`
возвращает непустой вывод, счётчик `DIRECT_COMMITS` вычисляется корректно.

`.github/workflows/lint.yml` (шаг guard'а — строка 1058):

```yaml
        name: direct commits to master
          - name: Checkout (полная история обязательна для git log по origin/master)
              fetch-depth: 0
          - name: No direct commits to master (Pass 353, final safety net)
```

`.forgejo/workflows/lint.yml` (шаг guard'а — строка 1097) — идентично:

```yaml
        name: direct commits to master
          - name: Checkout (полная история обязательна для git log по origin/master)
              fetch-depth: 0
          - name: No direct commits to master (Pass 353, final safety net)
```

Штатные проверки CI-конфигурации зелёные:

```
OK: наборы гейтовых команд и if:-условия совпадают (52 гейт(ов) в каждой копии).
OK: манифест и обе копии workflow согласованы (37 записей, 37 job-id, мёртвых зон нет).
```

Рядом с шагом стоит комментарий-объяснение, фиксирующий именно эту причину:

> Полная история обязательна для шага «No direct commits to master» ниже: при shallow clone
> (fetch-depth по умолчанию = 1) remote-tracking ref origin/master недоступен → `git log` отдаёт
> пустоту → счётчик DIRECT_COMMITS всегда 0 → guard «final safety net» никогда не падал
> (BR-509, P-78-03). fetch-depth: 0 — actions/checkout тянет ВСЕ ветки
> (+refs/heads/*:refs/remotes/origin/*), поэтому origin/master существует и в сборке pull_request.
