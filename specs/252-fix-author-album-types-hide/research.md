## Решения

### D1 — Корень overlap'а

- **Decision**: оба блока `.km-filter-bar` и `.km-album-controls-bar` имеют идентичное `top: 53px` (`ZakromaView.vue:740` и `ZakromaView.vue:780`). С `z-index: 90` фильтр-бара и `z-index: 89` блока альбомов, плюс DOM-порядок (фильтр идёт ПЕРЕД блоком альбомов), CSS-stacking рисует фильтр поверх блока альбомов. Когда высота блока альбомов **больше** высоты фильтра (а это так при наличии 2-3 кнопок типов + тумблера), нижняя часть блока альбомов **выглядывает** из-под фильтра — это и есть баг «блок с типами альбомов не весь скрывается».
- **Rationale**: проверено исходниками `karaoke-public/src/views/ZakromaView.vue:738-785` (оба блока позиционированы `sticky; top: 53px`), `AppHeader.vue:138-142` (header height = `padding 0.5rem × 2 + логотип 36px + border 1px` = 53px). Стандартное CSS-поведение: одинаковый `top` + поздний DOM + меньший `z-index` ⇒ объект A (фильтр) перекрывает объект B (типы альбомов); нижняя часть B проступает.
- **Alternatives considered**:
  - **(α) Поменять `z-index` блока альбомов на 91 (выше фильтра).** Тогда фильтр окажется «под» блоком альбомов — некорректное стэкинг-отношение, плюс визуально фильтр уезжает за экран «раньше», чем блок альбомов. Отвергнуто.
  - **(β) Спрятать блок альбомов при скролле (FR — «hide-on-scroll»).** Меняет UX-контракт спеки 012 (`specs/012-entity-description-fields` FR-025/027 — sticky filter by album type сохраняется при скролле). Не входит в скоуп этого багфикса. Отвергнуто.
  - **(γ) Сдвинуть `top` блока альбомов на высоту фильтра (FR-002).** Минимальная правка, сохраняет UX 012. **Принято как основной вариант реализации** (см. D2).

### D2 — Стратегия фикса: FR-002 vs FR-004

- **Decision**: комбинированный подход — **доминирующий FR-004 (общий sticky-контейнер)**, c резервом FR-002 (смещение `top`) на случай если FR-004 окажется несовместим с `flex-wrap` 2-строчного блока типов.
- **Rationale**:
  - **FR-004** (обёртка `<div class="km-author-header-sticky">`) даёт **одну** sticky-область: либо вся обёртка уехала за viewport, либо прилипла к шапке одним блоком. Никаких overlap'ов между подблоками по построению. Проще поддерживать (один `top`, один `z-index`).
  - **FR-002** (`.km-album-controls-bar { top: calc(53px + <filter-bar-height>) }`) — оставляет два независимых sticky-блока, при изменении высоты фильтра (например, при добавлении бейджей в будущем) смещение придётся пересчитывать. Менее устойчиво к будущим изменениям.
  - На spec-уровне оставлены оба FR как альтернативы (FR-002 / FR-004), чтобы план/таск мог выбрать; **по дефолту идём FR-004**.
- **Alternatives considered**:
  - **Снять `position: sticky` с `.km-album-controls-bar` совсем (сделать обычный in-flow элемент, едет с контентом).** Радикально просто, но ломает контракт спек 012 (FR-025/027 — sticky filter by album type). Отвергнуто.
  - **CSS-переменная для высоты header'а (`--km-header-height: 53px`) и передача `top: var(--km-header-height)` повсюду.** Хорошо в долгосрочной перспективе, но это изменение в AppHeader.vue выходит за скоуп бага; **может быть сделано отдельной фичей** в духе рефакторинга. В этой спеке не делается.

### D3 — База для расчёта offset'а фильтра

- **Decision**: для FR-002 (запасной вариант) использовать **высоту `.km-filter-bar` как CSS-переменную `--km-filter-bar-height`**, заданную на компоненте (например, через inline-style на корне `.km-filter-bar`), или явно зафиксировать «`top: calc(53px + 50px) = 103px`» для `.km-album-controls-bar` (комментарий: высота фильтра ≈ 1 строка × ~36px + padding 0.5rem × 2 ≈ 50px). Для **FR-004** (принятый) высота не нужна — контейнер сам уезжает.
- **Rationale**: магические числа опасны; если фильтр расширится (например, добавят кнопку «Сбросить всё»), зафиксированный `top: 103px` сломается. Переменная `--km-filter-bar-height` устойчива. Но в рамках текущего бага и текущей структуры (фильтр = одна строка) `top: calc(53px + 50px) = 103px` достаточно.
- **Alternatives considered**:
  - **JS-измерение `getBoundingClientRect()` фильтр-бара в `mounted()` и запись в CSS-переменную.** Точно, но добавляет runtime-логику в Vue (нарушает простоту «CSS-only fix»). Отвергнуто как overkill.

### D4 — Совместимость z-index с другими sticky-блоками

- **Decision**: при реализации **FR-004** — одна sticky-область `km-author-header-sticky` с `top: 53px; z-index: 90` (тот же, что был у фильтра). AppHeader остаётся на `z-index: 100` сверху, `.km-stream-progress` (спек 181) остаётся на `z-index: 50` под обёрткой. Никакие значения не меняются.
- **Rationale**:
  - Текущее стэкинг-отношение (AppHeader z=100 → filter-bar z=90 → album-controls-bar z=89 → stream-progress z=50) корректно *по вертикали* — фильтр выше альбомов выше стрима. При FR-004 фильтр и блок альбомов объединяются в обёртку z=90; вертикальный порядок в DOM сохраняется (фильтр сверху, блок альбомов снизу внутри обёртки) — пользователь видит то же, что и сейчас, **но без overlap'а**.
  - Никакие сторонние стили не задеты (z-index'ы те же по семантике).
- **Alternatives considered**: перераспределение z-индексов (например, переименовать в «слои»). Не требуется для данной фичи.

### D5 — Mobile: `flex-wrap` 2-строчного блока типов альбомов

- **Decision**: при FR-004 (общий sticky-контейнер) 2-строчный блок типов альбомов на мобильном автоматически занимает больше вертикального места в обёртке; вся обёртка прилипает одной полосой — никаких «обрезанных строк». Специального media-query не нужно.
- **Rationale**: обёртка sticky уезжает/прилипает целиком независимо от внутренней высоты. FR-007 удовлетворяется автоматически.
- **Alternatives considered**: media-query `@media (max-width: 480px)` для дополнительного `top: calc(53px + var(--filter-h) + 10px)` или для отдельного sticky-стека. Не нужно при FR-004.

## Best Practices для sticky-стэков CSS

- **Источник**: MDN Web Docs, раздел «Sticky positioning» + опыт Vue 3 + Bootstrap 5 community (справочно).
- **Правила, которые соблюдаем**:
  1. Каждый sticky-блок должен иметь **уникальный** `top` (или быть в общем sticky-контейнере) — иначе stacking создаёт overlap по вертикали.
  2. `position: sticky` работает **только** если у родителя нет `overflow: hidden/auto/scroll` (проверено: родитель `.km-page { min-height: 100vh }` — ок; в этой спеке не трогаем).
  3. При смене `flex-wrap` внутреннего блока sticky-контейнер автоматически масштабируется (CSS нативно).
  4. `<header :class="['km-header', 'km-header-sticky']">` — `z-index: 100` (AppHeader.vue:141). Не трогаем.
