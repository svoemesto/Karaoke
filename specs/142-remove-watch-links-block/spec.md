# Feature Specification: Удалить блок «Ссылки на просмотр» со страницы песни

**Feature Branch**: `142-remove-watch-links-block`
**Created**: 2026-08-04
**Status**: Draft
**Input**: User description: "На проде со страницы песни убрать блок 'Ссылки на просмотр'"

## Контекст

На публичной странице песни (`karaoke-public`, маршрут `/song?id=...`, оба дизайна
`classic` и `modern` используют общий шаблон `SongView.vue`) под онлайн-плеером
выводится блок `.km-links-card` с заголовком «Ссылки на просмотр».

Блок показывается для песен в эфире (`v-if="currentSong.onAir"`) и содержит пять
групп внешних ссылок на сторонние платформы (Sponsr, Dzen, VK, Telegram, Max) в
четырёх версиях — `Все / Karaoke / Lyrics / TABS / Chords`.

Решение — убрать блок целиком со страницы песни. Поля источника данных
(`currentSong.linkSponsrPlay`, `currentSong.linkDzenKaraoke`, `currentSong.linkVkLyrics`,
… и т.п.) и сам компонент `PlatformLink.vue` сохраняем: они используются в
других публичных представлениях (`SearchView.vue`, `ZakromaView.vue`).

## Что меняется

**Файл**: `karaoke-public/src/views/SongView.vue`

1. Удалить целиком DOM-блок `.km-links-card` со всем содержимым (строки ~201–333
   текущего файла: 5 групп × 5 `PlatformLink`-ссылок, ~15–17 `<PlatformLink>`).
2. Удалить связанные CSS-правила (если они не используются в `SongView.vue`
   вне `.km-links-card`): `.km-links-card`, `.km-links-title`, `.km-links-grid`,
   `.km-link-group`, `.km-link-label`, `.km-link-icons`, и медиа-правило
   `.km-links-grid { gap: 0.5rem }` в адаптивной секции.
3. Удалить неиспользуемые после правки импорт и регистрацию `PlatformLink` в
   секции `<script>` файла `SongView.vue` (компонент перестаёт быть нужен в
   этой view — только здесь он сейчас используется; `SearchView.vue` и
   `ZakromaView.vue` импортируют его сами).

**Не меняется:**
- API-эндпоинты (`/api/public/song`) — поля ссылок остаются в JSON.
- Компонент `karaoke-public/src/components/PlatformLink.vue` — нужен другим view.
- Модель/SQL/`SyncRegistry` — никаких изменений данных.
- `webvue3` (админка) — там блока «Ссылки на просмотр» нет.

## Что НЕ меняется (намеренно)

- Никаких визуальных заглушек «Ссылки на просмотр убраны» / «Coming soon» /
  поясняющих текстов на месте блока. Страница просто становится короче.
- Никаких чисток полей `link*` в БД и в DTO (`SettingsDTO`).
- Не делаем флаг «показывать ссылки»: фича = «убрать навсегда с публичной
  страницы песни», а не «включаемое отображение».

## User Stories

### Story 1 — Пользователь на публичной странице песни (P1)

Гость/зарегистрированный пользователь открывает страницу
`https://sm-karaoke.ru/song?id=<id>` для песни, которая в эфире. Сейчас он видит
под плеером карточку «Ссылки на просмотр» с иконками Sponsr, VK, Telegram, Dzen,
Max. После изменения этой карточки на странице нет.

**Why P1**: прямое следование запросу пользователя, основной сценарий.

**Independent test**: открыть страницу любой эфирной песни в браузере, выполнить
визуальную проверку — блока нет; в DevTools не должно быть элемента
`.km-links-card`.

**Acceptance scenarios**:
1. **Given** страница песни со статусом `onAir=true`, **When** пользователь
   открывает `/song?id=<id>` (или `/song/<slug>` если включён), **Then** на
   странице отсутствует DOM-элемент `.km-links-card` и текст «Ссылки на
   просмотр».
2. **Given** страница песни со статусом `onAir=false` (демо/премиум), **When**
   пользователь открывает страницу, **Then** визуально страница не меняется по
   сравнению с текущим состоянием — блок и так не отображался.
3. **Given** дизайн переключён на `modern` или `classic` (через
   `localStorage`), **When** пользователь открывает страницу, **Then** блок
   отсутствует в обоих дизайнах.

### Story 2 — Разработчик/админ сайта (P2)

Источники данных (`Song.linkSponsrPlay`, `Song.linkDzen*`, `Song.linkVk*`,
`Song.linkMax*`, `Song.linkTg*`) и сам компонент `PlatformLink.vue` остаются в
коде без изменений — другие публичные view (`/search`, `/zakroma`) продолжают
ими пользоваться. После правки `SongView.vue` больше не импортирует
`PlatformLink`.

**Why P2**: важно для гигиены кода, но не блокирует выкатку.

**Independent test**: `grep -rn "PlatformLink" karaoke-public/src/views/` —
должно остаться упоминание в `SearchView.vue` и `ZakromaView.vue`, но НЕ в
`SongView.vue`.

**Acceptance scenarios**:
1. **Given** код после изменения, **When** запускается `npm run build` в
   `karaoke-public`, **Then** сборка проходит без ошибок и предупреждений про
   неиспользуемые импорты (если линтер включён для unused-imports).
2. **Given** `SongView.vue` после изменения, **When** посмотреть секцию
   `<script>`, **Then** `import PlatformLink from '../components/PlatformLink.vue'`
   и соответствующая запись в `components`/`setup` отсутствуют.

## Edge Cases

- **Песня удалена / SKIP-тег**: блок всё равно скрывался через
  `currentSong.onAir`. После удаления этой логики эти ветки остаются
  работоспособными. На странице просто не будет никакого «ссылочного» блока — это
  соответствует запрошенному поведению.
- **Нет эфира, но есть ссылка**: блок уже не показывался при
  `onAir=false`. Никакой регрессии.
- **A/B-тест**: модель D (эфир-N-дней) подразумевает переход части эфирных песен
  в платный доступ. Когда/если это будет реализовано, поле `.km-links-card`
  уже не нужно — новая логика прав доступа не должна его воскрешать.

## Requirements

### Functional Requirements

- **FR-001**: Страница `/song?id=<id>` (для песен в эфире) не должна
  отображать блок с заголовком «Ссылки на просмотр» и сетку внешних ссылок на
  платформы.
- **FR-002**: Изменение должно пройти через стандартный цикл сборки и деплоя
  `karaoke-public`, чтобы попасть на прод (`188.119.64.111`). Конкретный
  триггер деплоя — `bash do.sh build_start_public` из `deploy/` (по
  инструкции пользователя).
- **FR-003**: Источники данных — поля `link{Sponsr,Dzen,Vk,Tg,Max}{,Karaoke,Lyrics,Tabs,Chords}`
  в `Song`/`SettingsDTO` — сохраняются без изменений; сам API `/api/public/song`
  продолжает возвращать их в JSON.
- **FR-004**: Компонент `PlatformLink.vue` сохраняется и продолжает
  использоваться в `SearchView.vue` и `ZakromaView.vue` без изменений.
- **FR-005**: Локально (`classic` и `modern` дизайны в `karaoke-public`) поведение
  совпадает с продом — блок отсутствует в обоих дизайнах.
- **FR-006**: При правке удаляется неиспользуемый импорт `PlatformLink` из
  `SongView.vue` (если других использований в файле нет) и CSS-правила
  `.km-links-*` (если они не используются за пределами удаляемого блока).

### Не-функциональные требования

- **NFR-001**: Никаких визуальных заглушек на месте удалённого блока.
  Страница должна выглядеть так, будто блока никогда не было (естественные
  отступы, без пустых обёрток и placeholder-надписей).
- **NFR-002**: Никаких изменений в backend (`karaoke-app`, `karaoke-web`),
  БД и `webvue3`.

## Success Criteria

- **SC-001**: На проде (`https://sm-karaoke.ru/song?id=<id>` эфирной песни) при
  просмотре HTML-исходника страницы нет ни одного DOM-элемента с классом
  `km-links-card`/`km-links-title`/`km-link-group`.
- **SC-002**: `grep -rn '\.km-links-card\|\.km-links-title\|\.km-links-grid\|km-links\|km-link-' karaoke-public/src/` после правки возвращает только те места, где эти классы ещё могут осмысленно
  использоваться (их не должно остаться — удаляем вместе с блоком).
- **SC-003**: `grep -rn "PlatformLink" karaoke-public/src/views/SongView.vue` —
  пусто (импорт + регистрация убраны).
- **SC-004**: `npm run build` в `karaoke-public` проходит без новых ошибок и
  предупреждений; дизайн-кнопка «Переключить classic/modern» продолжает
  работать.
- **SC-005**: Другие публичные страницы со ссылками (`/search`, `/zakroma`)
  визуально и функционально не изменились.

## Assumptions

- Под «на проде» пользователь имеет в виду стандартный путь: правим в исходниках
  → собираем фронт → деплоим через `deploy/do.sh build_start_public`. Никакого
  hot-fix на сервере в обход репо не предполагается (см. AGENTS.md, раздел
  «Деплой»).
- Активный сейчас дизайн страницы песни — `modern` (новый шаблон),
  переключатель дизайна остаётся без изменений. Удаление работает в обоих.
- Поля `link*` в БД не очищаем — теоретически пригодятся, если потребуется
  вернуть блок или показывать ссылки в других местах (например, в карточке
  песни в результатах поиска — `SearchView.vue`).
- Решение по `PlatformLink.vue` как компоненту переиспользования не меняем —
  это решение было принято ранее, отдельным PR (см. блок в `SearchView.vue`).

## Out of Scope

- Изменения backend (Kotlin) кода.
- Чистка SQL/DDL и миграций.
- Чистка полей `link*` в `SettingsDTO` и БД.
- Изменение логики доступа к песне (`onAir`, премиум-плеер, демо-плеер).
- Редизайн страницы песни и соседних блоков.
- Включаемый/отключаемый флаг «показывать ссылки» через админку или конфиг.
- A/B-тест «с ссылками vs без» — решение пользователя окончательное (блок
  убирается).
