# Quickstart: проверка Album + Settings→Song

В проекте нет CI-тестов, покрывающих этот путь (см. constitution.md, «Тесты: в CI нет») —
проверка ручная, на LOCAL-окружении администратора. Ниже — минимальный сквозной сценарий.

## Предпосылки

- Локальный docker-стек поднят (`db`/`storage`/`karaoke-web`/`karaoke-app`/`webvue3`).
- Применена миграция `deploy/karaoke-db/28_rename_settings_to_songs.sql` на LOCAL БД, **и
  выполнен Сценарий 0 ниже**, прежде чем собирать/перезапускать код с новым `TABLE_NAME`.
- Применены миграции `29_albums.sql` и `30_song_coauthors.sql` на LOCAL БД.
- Собраны и перезапущены `karaoke-app` (см. ограничение конституции — пересборку/рестарт
  `karaoke-app` выполняет только пользователь), `karaoke-web`, `webvue3` (через
  `deploy/do.sh build_web && deploy/do.sh start_web`, `build_start_webvue3`, — см. DEVELOPMENT.md).

## Сценарий 0 — Переименование таблицы (research.md §5.1 runbook)

1. До миграции: `SELECT count(*) FROM tbl_settings;` — записать число N.
2. Применить `28_rename_settings_to_songs.sql`.
3. После миграции: `SELECT count(*) FROM tbl_songs;` = N; `SELECT to_regclass('tbl_settings');` = `NULL` (старое имя больше не существует); `SELECT to_regclass('tbl_settings_sync');` = `NULL`, `SELECT count(*) FROM tbl_songs_sync;` — данные на месте.
4. Только теперь — пересобрать/перезапустить `karaoke-app`/`karaoke-web` с обновлённым `Song.TABLE_NAME = "tbl_songs"` (не раньше, иначе `relation "tbl_songs" does not exist`).
5. Проверить, что список песен в `webvue3` открывается без ошибок — это подтверждает, что код и схема синхронизированы по имени таблицы.

## Сценарий 1 — Бэкфилл существующих альбомов (US1, сценарий 2)

1. Перед запуском backfill-скрипта: `SELECT count(*) FROM tbl_songs WHERE song_album <> '' AND album_id IS NULL;` — должно быть > 0 (есть что бэкфиллить).
2. Запустить одноразовый backfill (см. `research.md` §6 за алгоритмом; конкретная команда
   запуска фиксируется в `tasks.md`/реализации).
3. Проверить: `SELECT count(*) FROM tbl_songs WHERE song_album <> '' AND album_id IS NULL;` = 0.
4. Проверить идемпотентность: повторный запуск backfill не создаёт дублей —
   `SELECT author_id, year, name, count(*) FROM tbl_albums GROUP BY 1,2,3 HAVING count(*) > 1;` = 0 строк.
5. Синглы без альбома остались нетронутыми: `SELECT count(*) FROM tbl_songs WHERE song_album = '' AND album_id IS NOT NULL;` = 0.

## Сценарий 2 — Управление альбомами в админке (US1, сценарий 1)

1. Открыть `webvue3` → новый раздел «Альбомы» (по аналогии с «Авторы»).
2. Найти автора с двумя+ альбомами одного года (после бэкфилла такие есть в реальных данных).
3. Изменить `sortOrder` так, чтобы порядок отличался от алфавитного.
4. Открыть `karaoke-public` → страницу дискографии/Закрома этого автора → убедиться, что
   альбомы этого года показаны в заданном (не алфавитном) порядке.

## Сценарий 3 — Соавторы песни (US2)

1. В `webvue3` открыть редактор произвольной песни.
2. Добавить двух соавторов (не совпадающих с главным автором).
3. Сохранить, перезагрузить страницу — убедиться, что оба соавтора отображаются.
4. Проверить на публичном сайте: страница/URL песни по-прежнему определяется только главным
   автором (адрес не изменился, песня не появилась на дискографии соавтора).
5. Удалить одного соавтора — убедиться, что остался только второй.
6. Попытаться добавить в соавторы автора, совпадающего с главным — убедиться, что запрос
   отклонён с понятной ошибкой (см. `contracts/api.md`).

## Сценарий 4 — Синхронизация LOCAL↔SERVER новых сущностей (Principle III)

1. В `webvue3` → «Синхронизация» — убедиться, что в списке сущностей появились «Альбомы» и
   соавторская связь, с полным набором чекбоксов push/pull × insert/update/delete/move.
2. Создать альбом на LOCAL, включить `push insert` для «Альбомы», выполнить синхронизацию —
   убедиться, что запись появилась на SERVER (`SELECT * FROM tbl_albums` на удалённой БД).
3. Аналогично для одной строки `tbl_song_authors`.

## Сценарий 5 — Переименование не сломало существующие сценарии (US3, SC-005)

1. Открыть список песен в `webvue3` — данные и колонки отображаются как раньше.
2. Отредактировать текст/маркеры произвольной песни, сохранить — без ошибок.
3. Запустить «Синхронизацию в 1 клик» — сущность бывших `Settings` (теперь `Song`, физическая
   таблица `tbl_songs`, `sync key` остаётся `"settings"`, см. research.md §5) синхронизируется как раньше.
4. Открыть публичный плеер для любой песни — воспроизведение работает как раньше.
5. `grep -rn "\bSettings\b" karaoke-app karaoke-web webvue3/src karaoke-public/src` — не должно
   находить упоминаний сущности песни (кроме намеренно сохранённого `PublicSettingsController`/
   `tbl_public_settings`/`PublicSettings*`, см. FR-014).
6. `grep -rn "tbl_settings\b" karaoke-app karaoke-web deploy/karaoke-db` — не должно находить
   упоминаний физического имени таблицы (кроме старых, уже применённых миграций `01`…`27_*`,
   которые не переписываются задним числом, и `tbl_public_settings`, см. FR-014).
