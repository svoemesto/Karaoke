# Quickstart: 287 — Прекращение извлечения текста после первого успеха + ручная попытка по ссылке

> **Дата**: 2026-08-31 | **Спека**: [spec.md](spec.md) | **Research**: [research.md](research.md) | **Data Model**: [data-model.md](data-model.md) | **Contracts**: [contracts/](.)

Это руководство по проверке фичи end-to-end в dev-окружении. Используется разработчиком / агентом после реализации для валидации, что всё работает.

## Prerequisites

1. **Локальное окружение Karaoke** на admin-машине (`dev-pc`/`dev` или `nsa-i9`/`nsa`):
   - PostgreSQL (локальная БД karaoke).
   - `karaoke-app` собран и запущен (или готов к сборке).
   - `karaoke-web` собран и запущен.
   - `webvue3` (админка) собран и доступен на `http://localhost:8897`.

2. **Тестовая песня**:
   - Создать песню без `source_text` (пустое поле текста).
   - Желательно с известным автором/названием, по которому FOURGET/Yandex находит несколько рабочих ссылок (например, «Кино — Группа крови», «Nautilus Pompilius — Мальчик зима»).

3. **Доступ к админке**:
   - Открыть `http://localhost:8897`.
   - Перейти в таблицу песен, найти тестовую песню.
   - Открыть карточку песни → `SubsEdit` (редактор субтитров).

4. **Доступ к БД** (для проверки SQL-сценариев):
   ```bash
   psql -h localhost -U karaoke -d karaoke
   ```

## Сценарий 1: Алгоритм останавливается после первого успеха (US1)

**Цель**: убедиться, что после автоматического поиска в БД ровно 1 запись с непустым `text`, остальные — с пустым.

### Шаги

1. В `SubsEdit` нажать кнопку с иконкой «Найти в Интернете текст песни» (`SubsEdit.vue:976`).

2. В модалке «Поиск текста песни в интернете» подтвердить поиск (кнопка «Найти в Интернете тексты для этой песни?»).

3. **ВАЖНО для теста**: убедиться, что движок по умолчанию — `FOURGET` (или `SEARXNG`), т.к. он часто возвращает 5-10+ ссылок. Яндекс обычно возвращает меньше.

4. Дождаться завершения поиска (секунды — десятки секунд).

5. **Проверка через UI**:
   - В левой колонке должно быть видно N ссылок.
   - Ровно **одна** ссылка должна быть визуально «белой» (с текстом).
   - Все остальные ссылки должны быть «серыми» (приглушённый фон).
   - Клик на «белую» ссылку — в правой колонке должен быть непустой текст.
   - Клик на «серую» ссылку — правая колонка должна быть пустой.

6. **Проверка через БД**:
   ```sql
   SELECT id, song_id, url, text IS NULL OR text = '' AS is_empty, html IS NULL OR html = '' AS html_empty
   FROM tbl_search_results
   WHERE song_id = <ID_ТЕСТОВОЙ_ПЕСНИ>
   ORDER BY id;
   ```
   **Ожидается**: N строк, из них ровно 1 с `is_empty = false` (непустой `text`) и `html_empty = false` (непустой `html`), остальные N-1 строк с `is_empty = true` И `html_empty = true` (HTTP-запрос НЕ делался).

7. **Проверка через логи `karaoke-app`**:
   - Должна быть строка `«Успех! Текст найден на: <url>»` от LLM-парсера (для SearXNG/FOURGET) или `«Обработка ссылки в домене ... вернула текст длиной N символов»` (для Yandex).
   - После этой строки НЕ должно быть HTTP-запросов `GET` к доменам остальных URL (можно проверить через `tcpdump` или `mitmproxy`, если настроено).

### Ожидаемый результат

- 1 запись с `text`, остальные с пустым `text` И `html`.
- В UI модалки: 1 «белая» ссылка + N-1 «серых».
- В логах: ровно 1 успешный парсинг + 0 HTTP-запросов для остальных URL.

## Сценарий 2: Ручная попытка «Получить текст по ссылке» (US3)

**Цель**: убедиться, что кнопка «Получить текст по ссылке» работает для отдельной «серой» ссылки.

### Шаги

1. Продолжение Сценария 1 (модалка открыта, поиск завершён).

2. **Кликнуть на «серую» ссылку** в левом списке.

3. **В правой колонке**: убедиться, что:
   - `<textarea>` пуста.
   - Кнопка «Открыть на сайте» доступна.
   - Кнопка «Получить текст по ссылке» доступна (НЕ `disabled`).

4. **Нажать «Получить текст по ссылке»**:
   - Кнопка должна показать текст «Получаю текст...» и стать `disabled`.
   - Через несколько секунд (HTTP-запрос + парсинг) — обновиться.

5. **Сценарий 2A — успех** (если на выбранной «серой» ссылке действительно есть текст):
   - Правая колонка заполнится текстом.
   - Ссылка в левом списке станет «белой» (визуально).
   - Кнопка «Получить текст по ссылке» станет `disabled` или скроется.

6. **Сценарий 2B — ошибка** (если ссылка не отвечает / парсер пустой):
   - Увидеть уведомление (toast / alert) с описанием ошибки.
   - Правая колонка останется пустой.
   - Ссылка останется «серой».
   - Кнопка «Получить текст по ссылке» снова доступна для повторной попытки.

7. **Проверка через БД**:
   ```sql
   SELECT id, song_id, url, text IS NULL OR text = '' AS is_empty, html IS NULL OR html = '' AS html_empty, last_update
   FROM tbl_search_results
   WHERE song_id = <ID_ТЕСТОВОЙ_ПЕСНИ>
   ORDER BY id;
   ```
   **Ожидается**: выбранная запись теперь имеет `is_empty = false` (если успех) или `is_empty = true` + `html_empty = false` (если HTTP успешен, но парсер пустой). `last_update` обновлён.

8. **Проверка идемпотентности (FR-022)**:
   - Ещё раз нажать на ту же ссылку (если она успешная).
   - Кнопка «Получить текст по ссылке» должна быть `disabled` или скрыта.
   - Если вручную вызвать endpoint ещё раз — он НЕ должен делать HTTP-запрос (проверяется по логам backend).

### Ожидаемый результат

- Только выбранная ссылка обновилась (другие «серые» остались без изменений).
- В логах: 1 новый HTTP-запрос ТОЛЬКО для выбранной ссылки.
- В БД: обновлена ровно 1 запись.

## Сценарий 3: Регрессия Pass 020/278/281 (SC-007)

**Цель**: убедиться, что `key`/`bpm` не теряются и `source_text` подставляется как раньше.

### Шаги

1. **Pass 020 (автоподстановка текста)**:
   - Найти песню БЕЗ `source_text`.
   - Запустить поиск через любой движок (FOURGET/SEARXNG).
   - После завершения проверить: `tbl_songs.source_text` заполнен, `tbl_songs.id_status = 1`.

2. **Pass 278 (key/bpm при импорте)**:
   - Запустить «Добавить файлы из папки» с папкой из 3+ файлов.
   - Убедиться, что для файлов, где `KEY_BPM_FROM_FILE` успевает отработать до завершения поиска текста, в `tbl_songs` заполнены и `source_text`, и `song_tone`/`song_bpm` (без необходимости ручного перезапуска).

3. **Pass 281 (key/bpm при «Найти тексты для всех песен»)**:
   - Выбрать в админке несколько песен с уже заполненными `song_tone`/`song_bpm`.
   - Нажать «Найти тексты для всех песен», выбрать любой движок.
   - После завершения проверить: `song_tone`/`song_bpm` остались на прежних значениях, `source_text` обновился (если нашлось).

### Ожидаемый результат

- Все три регрессионных сценария Pass 020/278/281 проходят без изменений.

## Сценарий 4: Разные движки дают одинаковое поведение (US4 / SC-008)

**Цель**: убедиться, что для всех 4 движков результат идентичен.

### Шаги

1. Для одной и той же тестовой песни без текста запустить поиск 4 раза (с `forceResearch=true` между запусками, чтобы очистить предыдущие результаты):
   - `YANDEX_SYNC`
   - `YANDEX_ASYNC`
   - `SEARXNG`
   - `FOURGET`

2. После каждого запуска проверить:
   - В UI: 1 «белая» ссылка + N-1 «серых».
   - В БД: 1 запись с непустым `text`.
   - В логах: ровно 1 успешный парсинг.

### Ожидаемый результат

- Для всех 4 движков поведение идентично.

## Сценарий 5: «Серых» ссылок больше нет в БД → ручной режим не работает

**Цель**: убедиться, что после удаления «серых» ссылок (например, через «Удалить результаты поиска» + повторный поиск без успеха) ручной режим всё равно работает.

### Шаги

1. Запустить поиск с движком, который гарантированно НЕ найдёт текст (например, поиск по бессмысленному названию).
2. После завершения в модалке будет N «серых» ссылок.
3. Кликнуть на любую «серую» → нажать «Получить текст по ссылке» → должен быть HTTP-запрос + парсинг (но с пустым результатом, потому что название бессмысленное).

### Ожидаемый результат

- Ручной режим работает даже для «безнадёжных» ссылок.

## Сценарий 6: Очистка состояния модалки

**Цель**: убедиться, что после «Удалить результаты поиска» + «Искать заново» модалка переходит в чистое состояние.

### Шаги

1. В модалке нажать «Удалить результаты поиска».
2. Подтвердить.
3. Модалка должна показать «Поиск не запущен» (или аналог).
4. Нажать «Искать заново», выбрать движок, подтвердить.
5. Поиск стартует заново.

### Ожидаемый результат

- Старые записи в `tbl_search_results` удалены.
- Новый поиск стартует с чистого листа.
