# Постоянный туннель к прод-хосту (WireGuard) — спека 733

Комплект конфигурации и скриптов постоянного туннеля между админской машиной
(`nsa-i9`) и прод-хостом (`188.127.240.124`). Туннелем владеет приложение
`karaoke-app` (FR-027); хост админской машины пользуется тем же туннелем по
тому же постоянному внутреннему адресу (FR-031).

## Что где лежит

| Файл | Назначение |
|---|---|
| `wg0-admin.conf.template` | справочный конфиг админского пира (те же значения использует приложение) |
| `wg0-prod.conf.template` | шаблон конфига пира «prod» (ставится на прод-хосте владельцем) |
| `install-admin-tunnel.sh` | подготовка админской стороны: каталог `700`, ключ `600`, печать публичного ключа |
| `install-prod-tunnel.sh` | печать точных команд для установки пира на проде (само ничего на проде не делает) |
| `host-route.sh` | маршрут хоста `10.77.0.0/24` через контейнер (доступ оператора к БД по тому же адресу) |
| `karaoke-tunnel-host-route.service` | systemd-юнит этого маршрута (установку делает владелец) |
| `selftest.sh` | изолированная проверка механики туннеля на сетевых namespace'ах (без прода) |

## Адресация

| Роль | Адрес | Комментарий |
|---|---|---|
| админская сторона (в контейнере `karaoke-app`) | `10.77.0.1/24` | прод видит этот адрес как источник; в allow-list прода — **ровно одна** строка `allow 10.77.0.1;` |
| прод-сторона | `10.77.0.2/24` | постоянный внутренний адрес прод-каналов (БД `5433`, MinIO `9000`, HTTPS `443`) — его используют и приложение, и оператор с хоста |
| UDP-порт пира «prod» | `51820` | единственный порт, который остаётся открытым наружу; аутентификация — криптографическая |

Подсеть `10.77.0.0/24` не пересекается с `tun0` (`172.28.3.0/24`), Docker-сетями
(`172.18.0.0/16`, `172.21.0.0/16`, `172.23.0.0/16`), VPN-маршрутами (`10.128.0.0/16`)
и LAN `10.0.1.0/24` — проверено guard'ом и фактом (стенд).

## Порядок (фазы)

1. **Подготовка (без прода).** `install-admin-tunnel.sh --apply` → публичный ключ
   админского пира → передать владельцу. Проверка механики: `selftest.sh`.
2. **Пи�� на проде (по согласию владельца).** `install-prod-tunnel.sh --print-commands`
   → команды установки `wg0` на `188.127.240.124`.
3. **Allow-list прода.** Заменить публичный адрес админской машины на `10.77.0.1`
   во всех трёх местах (stream `5433`/`9000` и HTTP-локации `/changerecords`,
   `/api/properties/setproperty`). Порядок: **сначала allow-list, потом переключение
   каналов** — иначе доступ пропадёт.
4. **Переключение каналов.** `DB_REMOTE_HOST=10.77.0.2`, `STORAGE_REMOTE_ENDPOINT=http://10.77.0.2:9000`,
   `PROD_TUNNEL_ENABLED=true`; перезапуск `karaoke-app` по Pass 380 (очередь → стоп →
   дренаж → старт → старт очереди).
5. **Закрытие публичных портов** (FR-018) — после успешной проверки Фазы 4.

## Чего скрипты НЕ делают

- Не ходят на прод и не меняют конфигурацию прод-хоста (это делает владелец —
  по отдельному согласию; Hard Gate «Прод deploy»).
- Не перезапускают и не пересобирают контейнеры (Pass 380 — отдельная процедура).
- Не хранят и не печатают приватные ключи: наружу выходит только **публичный** ключ.
- Не меняют маршрут по умолчанию админской машины и не трогают `tun0`/`xray`.
