# Data Model: Флаг «песня доступна» для авто-новостей + очистка ленты и таблицы учёта

## Song (`tbl_songs`) — изменения

Схема колонок не меняется. Единственное изменение — новый ключ внутри уже
существующего текстового JSON-поля `player_readiness_flags`.

| Поле (Kotlin) | Хранение | Тип | Default | Участвует в sync |
|---|---|---|---|---|
| `newsAvailableAnnounced` | ключ `newsAvailableAnnounced` внутри `player_readiness_flags` (text/JSON) | Boolean | `false` (ключ отсутствует ⇒ читается как `false`) | Да — как часть уже синхронизируемого поля `player_readiness_flags`, без изменений recordhash-формулы |

**Инвариант (одноразовый, необратимый флаг)**: после установки в `true`
значение никогда автоматически не возвращается в `false`, даже если условие
готовности позже временно не выполняется (см. Edge Cases spec.md).

**Условие установки в `true`** (проверяется в `Song.saveToDb()`, до
вычисления diff — чтобы изменение попало в тот же цикл сохранения/синхронизации):

```
idStatus == 6L &&
stemAccompanimentReady && stemVocalReady &&
pictureAlbumReady && pictureAuthorReady &&
sourceMarkersList.isNotEmpty() &&
!newsAvailableAnnounced
```

(то же условие, что уже вычисляет `Song.isContentReady` — без проверки
`onAir`, см. Assumptions spec.md).

**Переходы состояния**:

```
[flag=false] --(условие выполнено при save())--> [flag=true] --(навсегда)--> [flag=true]
```

Нет пути назад в `false`.

## News (`tbl_news`) — без изменений схемы, новое значение поля

Схема не меняется. Новое **значение** уже существующего поля `category`
используется впервые автоматически:

| Поле | Значение для «доступна» | Значение для «в эфире» (без изменений) |
|---|---|---|
| `category` | `"premium"` (уже существовало как ручная опция) | `"air"` (как сегодня) |
| `source` | `"auto"` | `"auto"` |
| `song_id` | заполнен | заполнен |
| `link` | `/song?id={id}` | `/song?id={id}` |
| `publish_at` | момент создания (сразу опубликована) | момент создания (сразу опубликована) |

Обе категории остаются `source="auto"` и, как и раньше, полностью исключены
из `NewsSyncTarget`/`News.listHashes()` (см. существующий комментарий
`News.source` — авто-новости физически существуют только там, где были
созданы, и не участвуют в LOCAL↔SERVER hash-diff).

## Удаляемая сущность: `tbl_song_news_announced` / `SongNewsAnnounced`

Таблица и соответствующий Kotlin-объект `SongNewsAnnounced` удаляются целиком.
Их роль распределяется между двумя новыми, более простыми механизмами:

- Для «доступна» — персистентный флаг на самой песне (см. выше) + before/after
  сравнение при применении синхронизации (не отдельная бухгалтерия).
- Для «в эфире» — узкое скользящее окно (~10 минут) плановой проверки +
  точечный existence-check по `tbl_news` (`song_id` + `category='air'`) только
  для кандидатов внутри окна.

## Сводная схема жизненного цикла авто-новостей одной песни

```
                     save() при idStatus==6 и всех флагах готовности
Song (не готова) ─────────────────────────────────────────────────▶ Song.newsAvailableAnnounced=true (локально)
                                                                              │
                                                                    следующая синхронизация
                                                                              ▼
                                                     SERVER: было false/нет → пришло true
                                                                              │
                                                                              ▼
                                                        News(category="premium", source="auto")
                                                        "песня появилась в коллекции"


Song.dateTimePublish (эфир) наступает внутри окна проверки (~10 мин)
                                                                              │
                                                        плановая проверка на PROD (~5 мин)
                                                                              │
                                                    нет существующей News(song_id, category="air")?
                                                                              │
                                                                              ▼
                                                        News(category="air", source="auto")
                                                        "песня вышла в эфир"
```

Оба события независимы (FR-013 spec.md) — наличие одного не блокирует другое
и не влияет на его условие срабатывания.
