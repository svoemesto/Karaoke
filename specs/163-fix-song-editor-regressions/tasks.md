# Tasks: Исправление регрессий редакторов текста песни после внедрения спецтегов

**Input**: Design documents from `/specs/163-fix-song-editor-regressions/`
**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md),
[data-model.md](./data-model.md), [contracts/sync-idempotency-invariant.md](./contracts/sync-idempotency-invariant.md),
[quickstart.md](./quickstart.md)

**Tests**: Проект не использует автоматизированный test-раннер для `webvue3` (по конституции — CI
без JS-автотестов, см. AGENTS.md/Constitution). Верификация — ручная браузерная проверка
(quickstart.md) + разовые Node/REPL-проверки инварианта идемпотентности, не постоянный test-suite.

**Organization**: Задачи сгруппированы по user story (US1 = P1, US2 = P2) из spec.md — каждая
история независимо реализуема и проверяема.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно выполнять параллельно (разные файлы/активности, нет зависимости)
- **[Story]**: US1 или US2
- Указаны точные пути к файлам

## Path Conventions

Все правки — внутри `webvue3/src/` (admin SPA). Backend (`karaoke-app`) не затрагивается —
подтверждено диагностикой Phase 0 (research.md §1).

сохранения никогда не маскируется под успех и блокирует закрытие редактора явным предупреждением.

дождаться «Сохранено ✓», переоткрыть редактор — текст и маркеры соответствуют последнему
сохранённому состоянию (spec.md «Independent Test» US1).

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Phase 1: Setup
2. Phase 3: User Story 1 (T003-T010)
3. **STOP and VALIDATE**: T009 — ручная приёмка US1 независимо от US2
4. При необходимости — задеплоить/показать пользователю исправление потери данных как отдельный PR

### Incremental Delivery

1. Setup → готово
2. US1 (сохранение) → проверить независимо → это уже самостоятельно ценный фикс (устраняет
   потерю данных, P1)
3. US2 (торможение/визуальный артефакт) → проверить независимо
4. Polish (T016-T020) → финальная сквозная проверка перед PR

### Parallel Team Strategy

При двух исполнителях: один берёт US1 (T003-T010), второй — US2 (T011-T015) сразу после Setup;
Polish — совместно после того как обе истории готовы.
