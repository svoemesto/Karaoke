# Data Model: 268-song-edit-date-datalist

Данная фича **не вводит новых сущностей**, **не меняет схемы БД** и **не меняет
формат хранения** существующих полей. Этот документ фиксирует текущие
инварианты, чтобы ревьюер мог проверить, что фикс их не нарушает.

## Затронутые поля (без изменений)

### `song.date: string` — `tbl_songs.publish_date` + `publish_time`

| Аспект | Значение |
|---|---|
| Тип в БД (`tbl_songs`) | `publish_date text` (`DD.MM.YY`), `publish_time text` (`HH:mm`) — два отдельных столбца |
| Тип в JS (`SongDto`) | `date: string`, `time: string` — тоже два отдельных поля |
| Формат в UI | В шаблоне хранится как `song.date` (формат `dd.MM.yy HH:mm`) **визуально**, но в `data` это пустая строка или значение, введённое пользователем |
| Использование | Поле «Дата» в `SongEdit.vue` (`v-model="song.date"`, `<input list="list_free_time_slots">`) |
| Связь с публикацией | Используется для автопубликации в Telegram/VK/др. (specs/113, 121, 122) |
| Длина | Строка формата `dd.MM.yy HH:mm` — 14 символов, может быть пустой |

**Инвариант**: фикс не меняет ни формат, ни валидацию, ни парсинг этого поля.
Всё, что делает фикс — добавляет два HTML-атрибута на `<input>`, которые
влияют только на UX-подсказки браузера, не на данные.

### `song.time: string` — отдельное поле в UI

| Аспект | Значение |
|---|---|
| Тип в JS | `string`, формат `HH:mm` |
| Источник значений | Статический массив `data.hours = ['11:00', '12:00', '13:00', '14:00', '15:00', '16:00']` в `SongEdit.vue` |
| Использование | Поле «Время» в `SongEdit.vue` (`v-model="song.time"`, `<input list="list_hours">`) |
| Сохранение | Сохраняется в `tbl_songs.publish_time` при сохранении формы |

**Инвариант**: фикс не меняет ни массив `hours`, ни поведение `<datalist id="list_hours">`,
ни валидацию времени. Добавляются только два HTML-атрибута на `<input>`.

## Неизменные источники данных (потоки, формирующие datalist)

### `freeTimeSlots: string[]` — Vuex-геттер `getFreeTimeSlots`

| Аспект | Значение |
|---|---|
| Источник | Backend: `Utils.kt::getFreeTimeSlots()` (см. спеку 156) |
| Транспорт | HTTP `POST /api/getfreetimeslots` → JSON `List<String>` |
| Формат элементов | `dd.MM.yy HH:mm` (например, `"30.08.26 14:00"`) |
| Длина | До 13 элементов (диапазон 10:00–22:00) |
| Гарантия | Все элементы — строго в будущем (относительно серверного `LocalDateTime.now()`) |
| Использование | `<datalist id="list_free_time_slots">` в `SongEdit.vue` (строки 41-43) |
| Потребитель в Vuex | `actions.getFreeTimeSlots()` в `store.js:2759-2767`; вызывается при загрузке песен (строки 1237, 1270, 1569, 1800, 1826 в `store.js`) |

**Инвариант**: фикс не меняет API, store, формат ответа, логику формирования.
Только клиентский UX двух `<input>`.

### `hours: string[]` — статический массив в `data()`

| Аспект | Значение |
|---|---|
| Источник | Inline `data()` в `SongEdit.vue:2595` |
| Формат | `['11:00', '12:00', '13:00', '14:00', '15:00', '16:00']` |
| Использование | `<datalist id="list_hours">` в `SongEdit.vue` (строки 38-40) |

**Инвариант**: фикс не меняет массив, только клиентский UX `<input>`.

## Что НЕ меняется в схеме/данных (резюме)

- `tbl_songs.publish_date`, `tbl_songs.publish_time` — без изменений.
- `SongDto.date`, `SongDto.time` — без изменений.
- API `/api/getfreetimeslots` — без изменений (см. [`contracts/getfreetimeslots.md`](./contracts/getfreetimeslots.md)).
- Vuex-стор (`store.js`) — без изменений.
- SyncRegistry (Local↔Server) — без изменений (publish_date/time уже синхронизируются как часть `tbl_songs`).
- recordhash-триггеры — без изменений.
