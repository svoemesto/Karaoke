# Feature Specification: Доп. поля Author/Album/Song (Описание/Короткое описание/Предупреждение) + новый UI Закромов

**Feature Branch**: `012-entity-description-fields`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "В сущности "Автор", "Альбом" и "Песня" нужно добавть дополнительные поля. Поле "Описание" (по умолчанию пустое) — форматированный текст с интересными фактами. Поле "Короткое описание" (по умолчанию пустое) — например "Remastered 2018" или "Live". Поле "Предупреждение" (по умолчанию пустое) — короткий текст-предупреждение, например "УЧАСТНИК ГРУППЫ ПРИЗНАН ИНОАГЕНТОМ". Поля добавляются во все DTO для веб, редактируются в админке. На проде в закромах информация об альбоме (картинка, название и т.п.) должна браться из сущности "Альбом", а не из таблицы песен. Тип альбома отображается под названием. Короткое описание — серым через пробел после названия. Предупреждение — красным над названием. Описание — в тултипе на ховере. Аналогично для автора в его блоке вверху закромов. Для песни — в карточке песни, в блоке информации. Порядок альбомов — по полю сортировки альбома. В шапке закромов — переключатель сквозного/группированного по типу отображения альбомов (со заголовками-разделителями по группам: студийные, синглы, концертные, сборники, бутлеги) и кнопки быстрого фильтра по типу альбома со счётчиком, скрывающиеся при отсутствии альбомов такого типа."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Редактор заполняет описательные поля сущностей (Priority: P1)

Редактор (администратор) открывает в админке карточку автора, альбома или песни и
заполняет поля «Описание», «Короткое описание» и «Предупреждение» (например,
указывает статус иноагента для исполнителя или помечает переиздание альбома как
"Remastered 2018"). После сохранения значения остаются видны при повторном
открытии карточки редактирования.

**Why this priority**: Без возможности заполнить поля в админке вся остальная
функциональность (отображение на публичном сайте) не имеет смысла — это
фундамент фичи.

**Independent Test**: Открыть в админке карточку любого автора/альбома/песни,
заполнить все три новых поля, сохранить, перезагрузить страницу админки и
убедиться, что значения сохранились.

**Acceptance Scenarios**:

1. **Given** карточка альбома в админке с пустыми новыми полями, **When**
   редактор вводит текст в «Короткое описание» и сохраняет, **Then** значение
   сохраняется и отображается при следующем открытии карточки этого альбома.
2. **Given** карточка автора в админке, **When** редактор вводит текст
   предупреждения («ИСПОЛНИТЕЛЬ ПРИЗНАН ИНОАГЕНТОМ») и сохраняет, **Then**
   значение сохраняется независимо от заполненности остальных двух полей.
3. **Given** карточка песни в админке с уже заполненным описанием, **When**
   редактор очищает поле и сохраняет, **Then** поле возвращается к пустому
   значению по умолчанию и на публичном сайте перестаёт отображаться.

### User Story 2 - Посетитель видит предупреждения, короткие описания и описания автора/альбома на странице «Закрома» (Priority: P1)

Посетитель публичного сайта открывает страницу «Закрома» конкретного автора.
Если у автора или у какого-либо из его альбомов заполнено предупреждение, оно
показывается красным текстом над именем/названием. Если заполнено короткое
описание — оно показывается серым текстом через пробел после имени/названия.
Если заполнено полное описание — оно доступно в тултипе при наведении на
имя/название. Тип альбома (Студийный, Сингл, Концертный, Сборник, Бутлег)
отображается под названием альбома и берётся из сущности «Альбом», а не из
эвристики по таблице песен.

**Why this priority**: Это основная пользовательская ценность запроса —
предупреждения об иноагентах — юридически значимая информация, которая должна
быть видна посетителю сразу, без дополнительных действий.

**Independent Test**: Присвоить одному альбому предупреждение, короткое
описание и описание; открыть страницу Закромов соответствующего автора без
авторизации и убедиться, что все три элемента показаны в нужном месте и с
нужным визуальным оформлением.

**Acceptance Scenarios**:

1. **Given** у альбома заполнено предупреждение, **When** посетитель открывает
   страницу Закромов автора, **Then** предупреждение отображается красным
   текстом над названием альбома.
2. **Given** у альбома заполнено короткое описание "Remastered 2018", **When**
   страница отображается, **Then** текст "Remastered 2018" показан серым
   цветом через пробел сразу после названия альбома, на той же строке.
3. **Given** у альбома заполнено описание, **When** посетитель наводит курсор
   на название альбома, **Then** появляется тултип с текстом описания.
4. **Given** у автора заполнены предупреждение/короткое описание/описание,
   **When** страница отображается, **Then** те же три визуальных правила
   применяются к блоку автора в верхней части страницы Закромов.
5. **Given** альбом связан с сущностью Album определённого типа (например,
   "live"), **When** страница отображается, **Then** под названием альбома
   показана русская подпись типа, соответствующая типу связанной сущности
   Album ("Концертный альбом"), а не выведенная из данных песен.
6. **Given** ни одно из трёх полей у альбома/автора не заполнено, **When**
   страница отображается, **Then** ни красный текст, ни серый текст, ни
   иконка/область тултипа не показываются — блок выглядит как раньше.

### User Story 3 - Посетитель видит описательные поля песни в карточке песни (Priority: P2)

На странице отдельной песни, в блоке информации (там же, где тональность и
темп), посетитель видит предупреждение (красным), короткое описание (серым,
рядом с названием) и описание (в тултипе) — если эти поля заполнены у песни.

**Why this priority**: Расширяет ту же ценность (предупреждения, контекст) на
уровень отдельной песни; логически зависит от модели данных из US1, но
независима от UI Закромов (US2, US4-US6).

**Independent Test**: Заполнить у песни все три поля, открыть страницу этой
песни и убедиться, что они видны в блоке информации рядом с тональностью/темпом.

**Acceptance Scenarios**:

1. **Given** у песни заполнено предупреждение, **When** посетитель открывает
   страницу песни, **Then** предупреждение отображается красным текстом в
   блоке информации.
2. **Given** у песни заполнены короткое описание и описание, **When** страница
   отображается, **Then** короткое описание видно серым текстом рядом с
   названием, а полное описание доступно по наведению.
3. **Given** ни одно поле песни не заполнено, **When** страница отображается,
   **Then** блок информации выглядит как раньше, без новых пустых элементов.

---

### User Story 4 - Альбомы автора на Закромах идут в порядке поля сортировки альбома (Priority: P2)

Посетитель видит альбомы автора на странице Закромов в том порядке, который
задан полем сортировки сущности Album (а не по случайной эвристике из данных
песен).

**Why this priority**: Обеспечивает предсказуемый и управляемый порядок
показа — важно для восприятия дискографии автора, но не блокирует показ
предупреждений (US2 уже даёт основную ценность даже при текущем порядке).

**Independent Test**: Задать альбомам автора в админке произвольный порядок
сортировки, отличный от порядка по году/названию, открыть страницу Закромов и
убедиться, что альбомы идут именно в заданном порядке.

**Acceptance Scenarios**:

1. **Given** у автора несколько альбомов с явно заданным порядком сортировки,
   **When** страница Закромов отображается в «сквозном» режиме, **Then**
   альбомы идут строго в порядке значения поля сортировки.
2. **Given** альбом ещё не связан с сущностью Album (переходный период),
   **When** страница отображается, **Then** такой альбом использует прежнее
   поведение (сортировка по году/названию) как запасной вариант.

---

### User Story 5 - Переключение между сквозным и групповым отображением альбомов (Priority: P3)

В шапке страницы Закромов посетитель переключает режим отображения альбомов:
«сквозной» (все альбомы одним списком в порядке сортировки) или
«сгруппированный по типу» (альбомы разбиты на визуально разделённые группы —
сначала студийные, затем синглы, концертные, сборники, бутлеги — с заголовком
у каждой группы).

**Why this priority**: Улучшает навигацию по большой дискографии, но не влияет
на базовую видимость предупреждений/описаний (US2/US3) и не блокирует их.

**Independent Test**: Открыть страницу Закромов автора с альбомами минимум трёх
разных типов, переключить режим на «сгруппированный» и убедиться, что альбомы
разбиты на подписанные группы в заданном порядке; переключить обратно на
«сквозной» и убедиться, что группировка исчезает, а порядок соответствует US4.

**Acceptance Scenarios**:

1. **Given** у автора есть студийные, концертные альбомы и синглы, **When**
   посетитель включает групповой режим, **Then** альбомы показаны тремя
   блоками с заголовками "Студийные альбомы", "Синглы", "Концертные альбомы" в
   этом порядке (сборники и бутлеги отсутствуют — их заголовки не показаны).
2. **Given** групповой режим включён, **When** посетитель переключает обратно
   на сквозной режим, **Then** заголовки групп исчезают и альбомы показаны
   единым списком по порядку сортировки.

---

### User Story 6 - Быстрые фильтры по типу альбома (Priority: P3)

В шапке страницы Закромов, рядом с переключателем режима, посетитель видит
кнопки быстрого фильтра — по одной на каждый тип альбома, который есть у этого
автора (например, "Студийные (10)", "Синглы (13)"). Клик по кнопке
скрывает/показывает альбомы этого типа. Кнопка типа, альбомов которого у
автора нет, не отображается вовсе.

**Why this priority**: Дополнительное удобство навигации поверх US5; наименее
критичная часть запроса, полностью независима по ценности от предупреждений.

**Independent Test**: Открыть страницу Закромов автора без бутлегов, убедиться,
что кнопка "Бутлеги" не показана вовсе; выключить кнопку "Синглы" и убедиться,
что все синглы скрываются со страницы (в обоих режимах отображения — и
сквозном, и групповом).

**Acceptance Scenarios**:

1. **Given** у автора 10 студийных альбомов и 13 синглов и 0 бутлегов, **When**
   страница Закромов отображается, **Then** кнопки "Студийные (10)" и "Синглы
   (13)" видны, а кнопка для бутлегов не отображается.
2. **Given** кнопка "Синглы" включена (по умолчанию), **When** посетитель
   выключает её, **Then** все альбомы типа "Сингл" скрываются со страницы
   (независимо от текущего режима отображения — сквозного или группового), а
   счётчик на кнопке продолжает показывать полное число синглов автора.
3. **Given** посетитель выключил один из типов, **When** он переключает режим
   сквозной/групповой, **Then** выключенный тип остаётся скрытым в обоих
   режимах.

---

### Edge Cases

- Все три новых поля пустые (значение по умолчанию) у сущности — ни один из
  визуальных элементов (красный текст, серый текст, тултип) не рендерится, вид
  блока не меняется по сравнению с текущим состоянием.
- Заполнено только предупреждение (без короткого описания и описания, или
  наоборот) — каждый элемент отображается независимо от заполненности других.
- Песня или альбом ещё не связаны с сущностью Album (переходный период после
  внедрения сущности Album) — тип альбома по умолчанию "Студийный альбом",
  сортировка — по прежней эвристике (год/название), поля описания недоступны
  до установления связи.
- У автора все альбомы одного типа — среди кнопок быстрого фильтра видна ровно
  одна (для этого типа), остальные четыре не отображаются.
- Групповой режим включён, но у автора нет альбомов одной из категорий (например,
  бутлегов) — соответствующий заголовок-разделитель для этой категории не
  показывается.
- Текст описания очень длинный — тултип должен оставаться читаемым (не
  обрезаться до нечитаемого вида и не выходить за пределы экрана).
- Предупреждение или короткое описание содержат очень длинный текст — не
  должны ломать вёрстку строки с именем/названием (перенос на новую строку
  допустим).

## Requirements *(mandatory)*

### Functional Requirements

**Модель данных**

- **FR-001**: Система MUST хранить для сущности «Автор» три новых текстовых
  поля: «Описание», «Короткое описание», «Предупреждение», каждое пустое по
  умолчанию.
- **FR-002**: Система MUST хранить те же три поля для сущности «Альбом»,
  каждое пустое по умолчанию.
- **FR-003**: Система MUST хранить те же три поля для сущности «Песня», каждое
  пустое по умолчанию.

**Передача данных (DTO)**

- **FR-004**: Все представления сущности «Автор», передаваемые в админку и на
  публичный сайт (за исключением плиточного представления авторов, не
  участвующего в данной фиче), MUST включать три новых поля.
- **FR-005**: Все представления сущности «Альбом», передаваемые в админку и на
  публичный сайт (закрома), MUST включать три новых поля.
- **FR-006**: Все представления сущности «Песня», передаваемые в админку и на
  публичный сайт (страница песни), MUST включать три новых поля.

**Редактирование в админке**

- **FR-007**: Администратор MUST иметь возможность просматривать и изменять
  значения всех трёх новых полей для любого автора через интерфейс админки.
- **FR-008**: Администратор MUST иметь возможность просматривать и изменять
  значения всех трёх новых полей для любого альбома через интерфейс админки.
- **FR-009**: Администратор MUST иметь возможность просматривать и изменять
  значения всех трёх новых полей для любой песни через интерфейс админки.
- **FR-010**: Поле «Описание» MUST поддерживать ввод многострочного текста с
  сохранением абзацев/переносов строк, пригодного для «интересных фактов» об
  авторе/альбоме/песне. Разметка/выделение текста (жирный, курсив и т.п.) — вне
  объёма: намеренно не поддерживается, чтобы не рендерить произвольный HTML от
  ручного ввода на публичном сайте без риска инъекции (см. Assumptions).

**Отображение на Закромах — Автор**

- **FR-011**: Если у автора заполнено «Предупреждение», система MUST
  отображать его красным текстом над именем автора в верхнем блоке страницы
  Закромов.
- **FR-012**: Если у автора заполнено «Короткое описание», система MUST
  отображать его серым текстом через пробел сразу после имени автора.
- **FR-013**: Если у автора заполнено «Описание», система MUST делать его
  доступным для просмотра во всплывающей подсказке (тултипе) при наведении на
  имя автора, с сохранением переносов строк и абзацев исходного текста.

**Отображение на Закромах — Альбом**

- **FR-014**: Если у альбома заполнено «Предупреждение», система MUST
  отображать его красным текстом над названием альбома.
- **FR-015**: Если у альбома заполнено «Короткое описание», система MUST
  отображать его серым текстом через пробел сразу после названия альбома.
- **FR-016**: Если у альбома заполнено «Описание», система MUST делать его
  доступным во всплывающей подсказке при наведении на название альбома, с
  сохранением переносов строк и абзацев исходного текста.
- **FR-017**: Система MUST отображать под названием альбома тип альбома
  (Студийный альбом / Сингл / Концертный альбом / Сборник / Бутлег), причём
  источником типа, названия и остальных отображаемых атрибутов альбома MUST
  быть связанная сущность «Альбом», а не производные данные из таблицы песен
  (за исключением переходного случая из Edge Cases, пока связь не установлена).
- **FR-018**: Русские подписи типа альбома MUST быть едиными между админкой и
  публичным сайтом (единый источник правды на стороне сервера).

**Отображение в карточке песни**

- **FR-019**: Если у песни заполнено «Предупреждение», система MUST отображать
  его красным текстом в информационном блоке карточки песни (там же, где
  тональность и темп).
- **FR-020**: Если у песни заполнено «Короткое описание», система MUST
  отображать его серым текстом рядом с названием песни в том же
  информационном блоке.
- **FR-021**: Если у песни заполнено «Описание», система MUST делать его
  доступным во всплывающей подсказке в том же информационном блоке.

**Сортировка, группировка и фильтрация альбомов на Закромах**

- **FR-022**: Система MUST отображать альбомы автора на странице Закромов в
  порядке значения поля сортировки альбома (по умолчанию — «сквозной» режим),
  с запасным вариантом сортировки для ещё не связанных с сущностью Album
  альбомов.
- **FR-023**: В шапке страницы Закромов система MUST предоставлять
  переключатель между «сквозным» отображением альбомов и отображением,
  сгруппированным по типу альбома.
- **FR-024**: В сгруппированном режиме система MUST показывать альбомы
  разбитыми на визуально отделённые группы в фиксированном порядке: студийные,
  синглы, концертные, сборники, бутлеги; группа, для которой у автора нет ни
  одного альбома, MUST не отображаться (включая заголовок).
- **FR-025**: В шапке страницы Закромов система MUST предоставлять кнопки
  быстрого фильтра по типу альбома — по одной на каждый тип, альбомы которого
  есть у текущего автора; каждая кнопка MUST показывать число альбомов этого
  типа у автора (например, «Студийные (10)»).
- **FR-026**: Кнопка быстрого фильтра для типа альбома, которого у автора нет
  ни одного экземпляра, MUST не отображаться вовсе.
- **FR-027**: Переключение (включение/выключение) кнопки быстрого фильтра
  MUST немедленно показывать либо скрывать все альбомы соответствующего типа,
  независимо от того, какой режим отображения (сквозной или групповой) выбран
  в данный момент.

### Key Entities *(include if feature involves data)*

- **Author (Автор)**: исполнитель/группа. Новые атрибуты: описание
  (многострочный текст с фактами, без разметки/выделения), короткое описание,
  предупреждение (все — пустые по умолчанию). Уже существующие атрибуты (имя,
  привязанные картинки и т.п.) не меняются.
- **Album (Альбом)**: альбом конкретного автора; уже существующая сущность с
  названием, годом, типом (Студийный/Сингл/Концертный/Сборник/Бутлег) и полем
  сортировки. Новые атрибуты: описание, короткое описание, предупреждение
  (пустые по умолчанию). Становится единственным источником правды для
  отображения альбома на странице Закромов (вместо производных данных из
  песен).
- **Song (Песня)**: отдельная песня, может быть привязана к альбому. Новые
  атрибуты: описание, короткое описание, предупреждение (пустые по умолчанию).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% авторов/альбомов/песен с заполненным полем «Предупреждение»
  показывают его красным текстом на соответствующей публичной странице без
  дополнительных действий редактора после сохранения в админке.
- **SC-002**: Редактор способен заполнить все три новых поля для одной
  карточки (автора, альбома или песни) за одно открытие формы редактирования,
  без необходимости отдельных экранов на каждое поле.
- **SC-003**: Посетитель может скрыть или показать любую из присутствующих
  категорий альбомов автора одним действием (кликом), без перезагрузки
  страницы, и изменение видно мгновенно (менее 1 секунды).
- **SC-004**: Переключение между сквозным и групповым отображением альбомов
  происходит без перезагрузки страницы и отражается мгновенно (менее 1
  секунды).
- **SC-005**: На странице Закромов автора с альбомами нескольких типов, но без
  альбомов определённого типа (например, без бутлегов), ни заголовок группы,
  ни кнопка быстрого фильтра для этого типа не появляются ни при каком
  сочетании режима отображения — проверяется на 100% таких случаев.
- **SC-006**: Порядок отображения альбомов автора в сквозном режиме совпадает
  с заданным в админке порядком сортировки альбомов в 100% случаев (для
  альбомов, связанных с сущностью Album).

## Assumptions

- Поле «Описание» требует поддержки читаемого многострочного текста (абзацы,
  переносы строк), БЕЗ выделения/разметки (жирный, курсив и т.п. — намеренно
  не поддерживаются, см. FR-010); конкретный способ ввода этого текста в
  админке (простой многострочный ввод против полноценного визуального
  редактора) — реализационная деталь, решается на этапе технического
  планирования, а не в этой спецификации.
- Способ показа многострочного описания в тултипе (сохранение переносов строк
  при наведении) — тоже реализационная деталь технического планирования.
- Русские подписи типов альбомов для группировки/фильтров: "Студийные альбомы"
  / "Синглы" / "Концертные альбомы" / "Сборники" / "Бутлеги" — заголовки групп;
  "Студийные" / "Синглы" / "Концертные" / "Сборники" / "Бутлеги" — подписи на
  кнопках быстрого фильтра (короче, с добавлением счётчика в скобках).
  Используется единый источник правды на стороне сервера (уже существующие
  русские названия типов альбомов), фронтенд не хранит собственный дублирующий
  список.
- Порядок групп при группировке жёстко фиксирован: студийные → синглы →
  концертные → сборники → бутлеги — не настраивается пользователем.
  Состояние переключателя режима отображения и включённости фильтров по типу
  сохраняется в браузере посетителя между визитами (аналогично уже
  существующему переключателю темы оформления), не хранится на сервере и не
  требует авторизации.
- Изображение альбома по-прежнему определяется отдельным механизмом подбора
  картинки (не входит в объём этой фичи) — эта фича добавляет только описание/
  короткое описание/предупреждение и обязывает брать название/тип/порядок
  сортировки альбома из сущности «Альбом».
- Плиточное представление авторов (списки/грид авторов на других страницах
  сайта, не Закрома) и построчное представление песен внутри таблицы альбома
  на странице Закромов не получают новые поля — запрос пользователя
  ограничивается блоком автора/альбома на Закромах и информационным блоком
  отдельной страницы песни.
- Для альбомов и песен, ещё не связанных с сущностью Album (переходный период
  после функциональности 011-album-song-rename), сохраняется существующее
  запасное поведение отображения (сортировка и тип по умолчанию), пока связь
  не будет установлена — эта фича не требует принудительной миграции всех
  исторических данных.
