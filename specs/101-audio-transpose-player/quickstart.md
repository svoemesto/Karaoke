# Quickstart: Валидация фичи транспонирования в плеере админки

**Feature**: 101-audio-transpose-player
**Date**: 2026-07-31
**Related**: [spec.md](./spec.md), [data-model.md](./data-model.md), [contracts/player-transpose-ui-contract.md](./contracts/player-transpose-ui-contract.md)

Руководство для ручной end-to-end валидации фичи. CI-тестов в проекте нет (см. AGENTS.md «Тесты»), интеграционные `@Disabled` — для проверки не подходят. Валидация выполняется пользователем вручную в браузере.

## Предпосылки

- Локально запущенный бэкенд `karaoke-app` (admin-машина) + `webvue3` dev-сервер (`cd webvue3 && npm run dev`) ИЛИ собранная `webvue3`-сборка через `deploy/do.sh`.
- В БД есть хотя бы 2 песни с заполненным полем `key` (напр. `Am`, `Dm`) и 1 песня с **пустым** `key`.
- Современный десктоп-браузер с Web Audio API (Chrome/Firefox/Edge/Safari актуальных версий).
- Доступ к DevTools браузера (Network, localStorage).

## Подготовка

1. Открыть плеер песни с `key = Am` в админке (через таблицу «Песни» → иконка плеера).
2. Открыть DevTools → Network (для SC-002), Application → localStorage (для проверки per-song ключа).

## Сценарии валидации

### SC-001 — Транспонирование применяется ≤1 с, без остановки воспроизведения

1. Нажать ▶ — воспроизведение началось.
2. Открыть меню (≡) → «Тональность» → выбрать пункт `(+3) Cm`.
3. **Ожидается**: аудио продолжает играть без паузы/щёлчка; тональность повысилась на 3 полутона (слышно на слух — вокал выше). С момента клика до изменения тональности ≤ 1 с.
4. Выбрать `(0) Am`.
5. **Ожидается**: тональность вернулась к исходной, без остановки.

### SC-002 — Без сетевых запросов к серверу

1. В DevTools → Network включить фильтр по `Fetch/XHR`.
2. Запустить воспроизведение, сменить тональность `+3` → `-2` → `0` несколько раз.
3. **Ожидается**: после первоначальной загрузки плеера (`/api/song/{id}/playerdata`, `fileminus.mp3`, `filevoice.mp3`) **нет новых** HTTP-запросов при смене тональности.

### SC-002a — Все стемы транспонируются синхронно (FR-005)

1. Песня с `key = Am`, запустить воспроизведение (acc + voc слышны).
2. Открыть меню громкости (если есть) или использовать микс-контролы — отдельно приглушить vocals (voc = 0), слышать только acc.
3. Выбрать `(+3) Cm`.
4. **Ожидается**: accompaniment транспонирован на +3 полутона (слышно на слух).
5. Вернуть voc в микс (voc = 1), приглушить acc (acc = 0).
6. **Ожидается**: vocals также транспонированы на +3 полутона — оба стема в одной новой тональности, смесь согласована.
7. (В первой реализации bass/drums не воспроизводятся плеером — проверка их транспонирования откладывается до добавления воспроизведения; архитектура map-based гарантирует применение сдвига ко всем будущим стемам автоматически.)

### SC-003 — Синхронность с караоке-разметкой (≤100 мс)

1. Песня с `key = Am`, запустить воспроизведение.
2. Выбрать `(+3) Cm`.
3. **Ожидается**: текст/маркеры караоке идут синхронно с аудио — визуально расхождение не заметно (текст подсвечивается в такт). Темп не изменился (песня не ускорилась/не замедлилась).
4. Проверить на нескольких перемотках (seek): клик по таймлайну в разные точки.
5. **Ожидается**: после каждой перемотки аудио продолжает в `(+3) Cm`, синхронность сохраняется.

### SC-004 — Бейдж тональности (синий, под бейджем скорости)

1. `key = Am`, скорость 1x (бейджа скорости нет).
2. Выбрать `(+3)`.
3. **Ожидается**: в правом верхнем углу экрана плеера — синий бейдж `+3 Cm` (постоянный, не мелькает).
4. Выбрать в меню скорости `0.75x`.
5. **Ожидается**: видны **оба** бейджа — оранжевый `0.75x` сверху, синий `+3 Cm` под ним; не перекрываются.
6. Выбрать `(0) Am` (тональность базовая).
7. **Ожидается**: синий бейдж исчез; оранжевый `0.75x` остался.
8. Вернуть скорость `1x` и тональность `(0)`.
9. **Ожидается**: оба бейджа исчезли.

### SC-005 — Per-song персистентность (FR-011, FR-012)

1. Песня A (`key = Am`) — выбрать `(+3) Cm`. Убедиться в DevTools → localStorage, что появился ключ `kp_transpose_<id-A>` со значением `3`.
2. Открыть плеер песни B (`key = Dm`) — в той же вкладке/новой.
3. **Ожидается**: песня B стартует в **базовой** тональности `(0) Dm` (бейджа нет), **не** наследует `+3` от A. В localStorage появился `kp_transpose_<id-B>` со значением `0` (или отсутствует).
4. Выбрать для песни B `(-2) Fm`.
5. Перейти обратно к песне A (перезагрузить страницу плеера A).
6. **Ожидается**: песня A восстановила `(+3) Cm` — бейдж виден сразу после загрузки. `kp_transpose_<id-A>` = `3`.
7. Перейти к песне B.
8. **Ожидается**: песня B восстановила `(-2) Fm`.
9. Открыть впервые песню C (никогда не транспонировалась).
10. **Ожидается**: базовая тональность `(0)`, бейджа нет, `kp_transpose_<id-C>` отсутствует.

### SC-006 — Robustness: пустой `key`, нестандартный `key`, все типы песен

1. Песня с **пустым** `key`.
2. Открыть меню → «Тональность».
3. **Ожидается**: подменю доступно, пункты подписаны только сдвигом (`(0)`, `(+1)`, `(+3)`, `(-2)`, ...), без результирующей тональности.
4. Выбрать `(+3)`.
5. **Ожидается**: аудио транспонировано от исходного; бейдж `+3` (без тональности); плеер не упал.
6. (Опционально) Песня с нестандартным `key` (напр. `Amm` опечатка, или `C` мажор): подменю открывается, пункты подписаны по принципу «наследовать суффикс»; аудио-сдвиг работает; плеер не падает.
7. Песня типа `instrumental` (без вокала/разметки) и песня типа `poetry`: транспонирование аудио работает так же; бейдж/меню идентичны.

### FR-018 — Деградация без поддержки

(Только если есть доступ к браузеру без Web Audio AudioWorklet — напр. очень старый браузер, или эмуляция через DevTools.)

1. Открыть плеер в неподдерживающем браузере.
2. Открыть меню → «Тональность».
3. **Ожидается**: подменю видно, но все пункты заблокированы (серые, не кликабельны), показана подсказка «Браузер не поддерживает». Песня воспроизводится в базовой тональности.
