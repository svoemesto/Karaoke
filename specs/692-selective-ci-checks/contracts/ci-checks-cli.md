# Contract: CLI `tools/ci-checks.py`

**Feature**: 692-selective-ci-checks | **Дата**: 2026-11-01

`tools/ci-checks.py` — **единственная** реализация правила применимости (FR-006, FR-007, R-48).
Её используют четыре потребителя:

| Потребитель | Режим | Что делает |
|---|---|---|
| джоб `changes` (CI) | `--emit-outputs` | считает применимые проверки → outputs джоба |
| джоб `ci-summary` (CI) | `--summary` | сверяет «должно было выполниться» с фактическими результатами |
| локальный пред-PR прогон (R-47) | `--local [--all]` | исполняет команды применимых проверок |
| гейт согласованности | (внутри) | проверяет, что манифест и workflow не разошлись |

---

## 1. Синтаксис

```
python3 tools/ci-checks.py [--manifest PATH] [--workflow PATH] [--base REF] [--json] MODE
```

| Опция | По умолчанию | Смысл |
|---|---|---|
| `--manifest PATH` | `config/ci/checks.yml` | файл манифеста |
| `--workflow PATH` | `.forgejo/workflows/lint.yml` | источник `run:`-команд (локальный прогон) |
| `--base REF` | `origin/master` (fallback `master`) | база диффа |
| `--json` | выкл. | машинно-читаемый вывод вместо текстового |
| `--list` | выкл. | в режиме `--local`: напечатать список применимых проверок и выйти **без** исполнения команд |

Режимы (взаимоисключающие, ровно один):

| Режим | Назначение |
|---|---|
| `--emit-outputs` | печатает outputs джоба `changes` |
| `--summary` | печатает агрегированный сигнал прогона |
| `--local` | исполняет команды применимых проверок |
| `--local --all` | то же, но полный набор (страховка) |
| `--self-test` | внутренние фикстуры реализации |

## 2. Коды возврата

Единый контракт guard'ов проекта (`knowledge/system/infra/ci-tools.md` § «Контракт кодов возврата»):

| Код | Смысл |
|---|---|
| `0` | успех (правило применено, все применимые проверки зелёные) |
| `1` | нарушение (есть красная применимая проверка / расхождение / фикстура упала) |
| `2` | проверка не выполнена (данных нет: манифест нечитаем, неизвестна версия, нет git-истории, нет PyYAML) |

«Нет данных» ≠ «нет нарушений» (FR-014).

## 3. Режим `--emit-outputs`

**Вход**: манифест + git-дифф (база `--base`, merge-base).

**Выход** (stdout, формат GitHub Actions outputs — строки `key=value`):

```
all=false
actions_pinned_guard=true
root_junk_guard=false
backend_build=true
...
```

- `all` — `true`, если применяется полный набор (push в master, расписание, ручной полный прогон,
  путь вне объединения зон при `unknown_paths: all`, невозможность посчитать дифф);
- по одному ключу на проверку; **имя ключа = `id` с заменой `-` на `_`** — в выражениях
  `${{ needs.changes.outputs.<ключ> }}` дефис недопустим (оператор вычитания);
- значение — `true`/`false` (строки).

**Правила**:
- `mode: always` → всегда `true`;
- применимость группы распространяется на всех её членов;
- неизвестная версия манифеста / нечитаемый манифест → **выхода нет**, код `2` → джоб `changes`
  падает → агрегат `ci-summary` падает (fail-closed, FR-014).

## 4. Режим `--summary`

**Вход** (через окружение):

| Переменная | Содержимое | Источник в workflow |
|---|---|---|
| `CI_CHEKS_OUTPUTS` | JSON `{"all": "true", "backend_build": "true", …}` | `${{ toJSON(needs.changes.outputs) }}` |
| `CI_CHEKS_RESULTS` | JSON `{"changes": {"result": "success", …}, "backend-build": {"result": "success"}, …}` | `${{ toJSON(needs) }}` |

**Алгоритм** (правила S-1…S-6 в [../data-model.md](../data-model.md)):

1. `changes` не `success` → падение (код `1`);
2. для каждой проверки манифеста: применимость = `CI_CHEKS_OUTPUTS[<id с `_`>]`; результат =
   `CI_CHEKS_RESULTS[<id>].result`;
3. применимая и результат ≠ `success` → падение;
4. применимая и результата нет → падение (fail-closed);
5. неприменимая → ожидаем `skipped`, на решение не влияет, но попадает в перечень пропусков (FR-017);
6. иначе → успех.

**Выход** (текст): перечень применимых проверок с результатами; перечень неприменимых — с
указанием зон, по которым они не применились (след пропуска, FR-017); итоговая строка `SUMMARY:
green|red`.

**Выход** (`--json`):

```json
{
  "result": "success",
  "applicable": [{"id": "backend-build", "result": "success"}],
  "inapplicable": [{"id": "backend-test", "zones": ["karaoke-app/src/test/**"], "reason": "no zone matched"}],
  "missing": []
}
```

## 5. Режим `--local`

**Два источника (важно для FR-007 — «зеркалирование CI»)**:

| Что | Откуда берётся | Чем |
|---|---|---|
| список **применимых** проверок | манифест `config/ci/checks.yml` | та же реализация правила — `tools/ci-checks.py` |
| список **команд** каждой проверки | workflow `.forgejo/workflows/lint.yml` | `jobs.<id>.steps[*].run` — по `id` джоба |

Отбор — из манифеста (как в CI), исполнение — из workflow (как в CI). Ни один из двух списков не
перечисляется вручную: манифест не хранит команды, workflow не хранит зоны.

**Вход**: манифест + изменённые пути + workflow (для извлечения команд).

1. Изменённые пути = дифф против базы (`git diff <base>...HEAD --name-only`) **плюс** рабочее
   дерево: staged (`git diff --cached --name-only`), unstaged (`git diff --name-only`),
   untracked (`git ls-files --others --exclude-standard`). Пути объединяются (union).
2. По манифесту вычисляются применимые проверки (та же логика, что в `--emit-outputs`).
3. Для каждой применимой проверки извлекаются её `run:`-команды из workflow **по `id`**
   (`jobs.<id>.steps[*].run`) и исполняются по порядку:
   - `working-directory` шага уважается (по умолчанию — корень репозитория);
   - матрица (`strategy.matrix`) разворачивается: для каждой комбинации значений подставляется
     `${{ matrix.<key> }}` (в проекте одна ось — `spa: [webvue3, karaoke-public]`);
   - команды, не начинающиеся с `bash tools/`, `python3 tools/`, `python tools/`, `./tools/`,
     не исполняются — это команды окружения (checkout, `npm ci`, `apt-get`), а не проверки
     (та же фильтрация, что в нынешнем R-47);
   - неподставляемые `${{ … }}` выражения → команда пропускается с предупреждением.
4. `--all` — полный набор проверок независимо от применимости (страховка, прежнее поведение R-47).

**Выход**: для каждой проверки — `APPLICABLE` / `SKIPPED (зона не затронута)`; для выполненных —
команда, код возврата; итог — `LOCAL: green|red` и ненулевой код возврата при красной проверке.

**Инвариант**: на одном и том же изменении список применимых проверок локально и в CI совпадает
полностью (SC-007) — обе величины считает одна реализация.

## 6. Режим `--self-test`

Внутренние фикстуры реализации (без сети и без CI):

| # | Фикстура | Ожидание |
|---|---|---|
| T-1 | глоб `karaoke-app/**` против `karaoke-app/src/main/a.kt` | совпал |
| T-2 | глоб `karaoke-app/**` против `other/a.kt` | не совпал |
| T-3 | глоб `**/Dockerfile*` против `deploy/x/Dockerfile.prod` | совпал |
| T-4 | глоб `*` против `a/b/c` (слеш) | не совпал |
| T-5 | зона без пересечения с изменениями | проверка неприменима |
| T-6 | группа `ssoT`: применим один член → применимы оба | FR-009 |
| T-7 | `mode: always` | применима всегда |
| T-8 | путь вне объединения зон при `unknown_paths: all` | применимо всё |
| T-9 | неизвестная версия манифеста | код `2`, не `0` |
| T-10 | `--summary` с применимой проверкой без результата | код `1` (fail-closed) |

Код возврата `--self-test`: `0` — все фикстуры прошли, `1` — упала хотя бы одна.

## 7. Примеры вызова

```bash
# CI, джоб changes
python3 tools/ci-checks.py --manifest config/ci/checks.yml --emit-outputs

# CI, джоб ci-summary
CI_CHEKS_OUTPUTS='{"all":"false","backend_build":"true"}' \
CI_CHEKS_RESULTS='{"changes":{"result":"success"},"backend-build":{"result":"success"}}' \
python3 tools/ci-checks.py --manifest config/ci/checks.yml --summary

# локальный пред-PR прогон (применимые проверки)
python3 tools/ci-checks.py --manifest config/ci/checks.yml --local

# полный набор (страховка)
python3 tools/ci-checks.py --manifest config/ci/checks.yml --local --all

# фикстуры реализации
python3 tools/ci-checks.py --self-test
```
