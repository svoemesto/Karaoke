# Contract: server-to-server канал приватных объектов StemJob (`X-Internal-Secret`)

**Версия**: 1.0 · **Дата**: 2026-10-24 · **Ветка**: `561-impl-stem-bucket`
**Спека**: [../556-close-stem-bucket-anonymous/spec.md](../../556-close-stem-bucket-anonymous/spec.md)

Контракт между двумя сторонами:

- **Отправитель** — `karaoke-app` (admin-машина) — единственный компонент с учётными
  данными доступа к хранилищу;
- **Получатель** — `karaoke-web` (прод) — хранит принятые объекты в приватном каталоге и
  отдаёт их владельцу задания через публичный авторизованный сценарий сайта.

Направление канала — **admin → prod**: прод-`karaoke-web` не имеет прямого доступа к
admin-машине (firewall, см. research Ф6). Все существующие каналы (`/raw`, `/ack`,
`/changerecords`) идут в этом же направлении.

## Транспорт

| Свойство | Значение |
|---|---|
| Базовый URL | `Karaoke.stemJobsWebInternalUrl` на стороне `karaoke-app` (пусто = канал выключен) |
| Заголовок авторизации | `X-Internal-Secret: <значение>` |
| Сравнение | точное, регистрозависимое, по всему значению |
| Тело | `application/octet-stream`, сырые байты объекта |

## Эндпоинты

### `PUT /api/internal/stemjobs/{id}/files/{fileName}`

Принимает **приватный объект** задания `{id}` (стем или исходный файл) и складывает его в
приватный каталог результатов `karaoke-web`.

| Параметр | Тип | Описание |
|---|---|---|
| `id` | Long | Идентификатор задания (`tbl_stem_jobs.id`) |
| `fileName` | строка | Имя файла вида `<stem>.<ext>`: `vocals.mp3`, `accompaniment.mp3`, `drums.mp3`, `bass.mp3`, `other.mp3`, `original.<ext>` |

Тело — байты объекта, без дополнительной обёртки.

### `POST /api/internal/stemjobs/{id}/purge`

Просит удалить все локальные копии задания `{id}` (приватный каталог результатов и сырой
файл загрузки). Тело пустое.

## Правила приёма (получатель — `karaoke-web`)

1. Если секрет **не настроен** (пустое значение) → **403**, тело не читается.
2. Если заголовок отсутствует → **403**.
3. Если заголовок присутствует, но не совпадает с настроенным секретом → **403**.
4. Если секрет совпал → тело запроса разбирается и сохраняется.
5. `fileName` проверяется по **фиксированному allow-list**: имя стема из набора
   `accompaniment | vocals | drums | bass | other | original` и расширение из
   `mp3 | wav | flac | ogg | m4a | aac | wma | opus | aiff`. Имя, содержащее `/`, `..`,
   абсолютный путь или иной символ, → **400**. Содержимое файла не интерпретируется.
6. Проверки идентификатора задания по БД на этом пути **нет** (канал доверенный: доступ
   есть только у приложения со знанием секрета); «фантомные» каталоги удаляются уборкой по TTL.

## Правила отправки (отправитель — `karaoke-app`)

1. Заголовок `X-Internal-Secret` добавляется к каждому запросу.
2. Ответ **403** — отказ по правам, повтор не выполняется (конфигурационная ошибка, а не
   сетевая).
3. Сетевые ошибки (таймаут, сбой соединения) — повтор: до 3 попыток с короткой паузой.
4. Источник байтов — объект приватного бакета `stemjobs`, прочитанный клиентом с
   учётными данными (`StorageApiClient`); наружу отдаётся ровно то, что лежит в бакете.
5. Значение секрета в журналы не пишется.

## Ответы (получатель)

| Код | Когда | Тело |
|---|---|---|
| 200 | объект принят / копии удалены | пусто (формат прежнего `ack`-эндпоинта не меняется) |
| 400 | недопустимое имя файла | короткий текст без деталей |
| 403 | нет/неверный секрет либо секрет не настроен | пусто (без деталей) |
| 404 | нет (на этом пути не используется) | — |
| 5xx | внутренняя ошибка | без содержимого объекта и без деталей инфраструктуры |

## Журналирование

Категория `infra.stemjobs.security`:

| Сообщение | Уровень | Когда |
|---|---|---|
| `stemjobs:security:denied` | WARN | отказ во внутреннем канале: `reason=` (`missing_secret` / `invalid_secret` / `secret_not_configured`), `source=`, `jobId=`, `file=` (имя файла, не содержимое) |
| `stemjobs:security:rejected` | WARN | недопустимое имя файла (400): `source=`, `jobId=`, `file=` |
| `stemjobs:security:stored` | INFO | объект принят: `jobId=`, `file=`, `bytes=` |
| `stemjobs:security:purged` | INFO | копии удалены: `jobId=`, `files=` |

Содержимое объекта в журнал **не** попадает (FR-007).

## Обе стороны должны использовать одно значение

Значение задаётся один раз и вводится в двух местах:

- `karaoke-web` — переменная окружения `STEMJOBS_INTERNAL_SECRET`
  (`application.yml` → `stemjobs.internal-secret`);
- `karaoke-app` — свойство `stemJobsInternalSecret` в `Karaoke.properties`.

Значение не коммитится и не попадает в репозиторий, сборку и журналы (Constitution VIII).

## Что НЕ входит в контракт

- Публичный API сайта: `GET /api/public/account/stemjobs/{id}/download` — формат запроса и
  ответа прежний (FR-011); изменён только источник байтов (файл из приватного каталога
  результатов вместо анонимного чтения `/minio/karaoke/...`).
- Доступ к публичным объектам бакета `karaoke` — без изменений (FR-002).
