# Приёмка отчёта аудита

> Карта #337 / задача #336. Решение владельца 2026-10-23: «продолжай без остановки».
> Приёмка — по фактам с диска, не по ответу субагента.

## Обязательные критерии

1. **Покрытие 100%.** Все 1 032 файла из `coverage-ledger.csv` отчитаны; 78 порций `DONE`; `comm -3` между ведомостью и разделами «Покрытие» пуст. Сумма LOC порций = 259 827.
2. **Каждая запись доказана.** Есть `path:line`, цитата совпадает с файлом на SHA, указан путь достижимости, автор подтверждён `git blame`, severity и класс по рубрике.
3. **Ревью лида.** У каждой записи `Проверено лидом: да`; доля возвратов и переписанных записей зафиксирована в `status.md`.
4. **S1 закрыты доказательно.** Каждый S1 либо воспроизведён (команда/замер), либо помечен `эмпирика: требует согласия` с описанием, что именно нужно проверить.
5. **Сверки собраны.** Все `NEEDS-VERDICT` — в отдельном разделе: вопрос, две трактовки, доказательство, почему важно. Без severity до вердикта.
6. **Дубли исключены.** `registry.csv` не содержит двух `BR` с одним `root_cause_key`; зеркала перечислены внутри записи.
7. **Отчёт собран.** `bug-report.md` соответствует структуре (`protocol.md` § 9): шапка, сводка, записи S1→S3, сверки, тесты, приложение о покрытии.
8. **Вложение.** `bug-report.md` приложен к #336; md5 файла в репозитории = md5 вложения; в комментарии к #336 — PR, md5, число записей.
9. **Никаких правок кода.** Аудит read-only: в PR только `specs/336-code-audit/**`.

## Выборочная проверка владельца

- Все S1 — обязательно.
- 10% записей S2/S3 (но не меньше 10) — случайная выборка по `registry.csv`.
- Калибровка severity: владелец подтверждает или понижает/повышает; изменения фиксируются в `registry.csv` и отчёте.

## Что считается провалом приёмки

- хотя бы один файл ведомости без отчёта;
- запись без цитаты или с цитатой, не совпадающей с файлом;
- S1 без доказательства или без пометки о согласии;
- два `BR` с одним корневым механизмом;
- отчёт в репозитории расходится с вложением;
- в PR есть изменения кода.
