## Что делает

Закрывает 40 записей аудита #336 в `karaoke-app` (и одной в `karaoke-web`).
Общий корень у них один: **непроверенный вход доходил до артефакта или до
ответа** — и ломал не одну запись, а всё целиком (генерацию `.mlt`, страницу
админки, публичный API).

Порции по карточкам аудита:

- **P-12** (BR-228…BR-230) — `llm` + `mlt`: размер скачиваемой страницы
  (BR-228), единый фильтр URL для обоих движков поиска (BR-229), пакетная
  загрузка UUID узлов MLT вместо N+1 (BR-230).
- **P-10** (BR-231…BR-236) — `controllers/MainController`: разбор числовых

  логом и различимыми кодами (BR-236).

## Зачем

Три группы последствий:

1. **Ломалась вся генерация, а не один элемент.** Одно поле `stringLad`
   вида `undefined|undefined` (его пишет редактор маркеров) роняло
   `NumberFormatException` и `.mlt` не создавался для песни целиком
   (BR-239). Один короткий список в админском свойстве `countersColors` —
   `IndexOutOfBoundsException` в `template()` (BR-243). Отсутствие TEXT-элемента
   в строке давало nameless-узел `< />` внутри `xmldata` титра — не-well-formed
   XML (BR-241).
2. **Клиент получал 500 там, где данные просто кривые.** Пустое поле «New
   prior» → `NumberFormatException` → 500 на КАЖДОЕ из N строк, приоритеты в БД
   не менялись, экран показывал пустые значения (BR-231). Неразобранные маркеры
   → 200 с текстом `Error`, клиент считал, что сохранилось (BR-236). Сбой БД при
   загрузке альбомов → 200 с `[]`, и результат ещё кэшировался на TTL (BR-240).
3. **Тихое расхождение и лишняя работа.** Telegram-пост публиковался с
   VK-заголовком без ссылки на песню (BR-233). Каждое изменение поля в админке
   скачивало всю страницу `/processes` целиком, а «New prior» — N раз подряд
   (BR-232). Генерация `.mlt` делала ~9 000 запросов к БД на песню только за
   UUID (BR-230).

Сквозной инвариант — в SSoT:
[boundary-validation](../../knowledge/domains/monitoring/components/boundary-validation.md).

## Как работает

- **Проверка на границе, до артефакта.** `parseOptionalInt(raw, reason)`:
  пусто → `null` («не менять»), нечисло → 400 с machine-readable причиной.
  Статус процесса — по белому списку `KaraokeProcessStatuses`.
- **Различение отказа по типу.** 404 (`song_not_found`) — песни нет;
  400 (`bad_source_markers`) — маркеры не разобрались; 503
  (`albums.unavailable`) — БД недоступна. Наружу — `ResponseStatusException`,
  не 500 и не «200 + Error».
- **Пакетная загрузка вместо N+1.** `UuidCache` читает `tbl_uuids` одним
  `SELECT` и раздаёт UUID из памяти; `INSERT` — только для действительно новых
  `id`.
- **Разделение по типу запроса.** XHR → 200 `{ok:true}`; обычный запрос → 302
  на `/processes`.
- **Ссылки внутри `.mlt` — на существующие узлы.** Типы без `producer()`
  (`LINETRACK`, `CHORDPICTURELINETRACK`, `SCROLLERTRACK`) в `main_bin`
  ссылаются на `tractor_*`.
- **Валидный узел вместо nameless.** Отсутствие TEXT-элемента в строке даёт
  валидный пустой `kdenlivetitle`, а не `MltNode()` с пустым именем.
- **Fallback вместо исключения на конфигурации.** Короткий список цветов →
  последний цвет + WARN; пустые голоса → запасной шрифт + WARN.
- **Единый фильтр URL.** `filterUselessLyricsUrls` применяется и к SearXNG, и
  к fourget (дедупликация + отсев homepage/логинов/sitemap/tracking).
- **Ограничение тела страницы.** `Jsoup.maxBodySize(2 МБ)` — обрезка до 8 000
  символов делалась ПОСЛЕ построения DOM, то есть пик памяти был безграничен.

## Инварианты

1. **Вход проверяется ДО использования** — HTTP-параметр, страница из
   интернета, значение из админского свойства, значение из БД.
2. **Отказ ≠ штатный результат** (см. также
   [error-semantics](../../knowledge/domains/monitoring/components/error-semantics.md)):
   «нет данных» и «БД недоступна» — разные состояния и разные коды ответа.
3. **Пустое числовое поле — «не менять», а не ошибка**; нечисловое — 400 с
   причиной, а не 500.
4. **Сравнение строк — по значению.** `!==` для строк запрещён: `replace(...)`
   возвращает новый объект, и такое сравнение истинно всегда.
5. **Ссылка в артефакте ведёт на существующий узел.**
6. **Узел артефакта всегда имеет имя** (well-formed XML).
7. **В цикле генерации нет обращения к БД на каждый узел** — данные берутся
   пакетно из кеша.
8. **Нет N+1 к БД в цикле** (см. также
   [error-semantics](../../knowledge/domains/monitoring/components/error-semantics.md)).
9. **Исключение логируется со стеком** через SLF4J-категорию `infra.*`
   (зарегистрированы в
   [log-categories](../../knowledge/domains/monitoring/components/log-categories.md));
   `println`/`printStackTrace` в затронутом коде — не осталось.
10. **Один фильтр на оба движка поиска** — поведение не должно зависеть от
    того, какой движок выбран в свойстве.

## Известные ловушки

1. **`cds !== ""` — сравнение по ссылке, истинно ВСЕГДА.** `String.replace`
   возвращает новый объект, поэтому условие «описание аккордов пустое» было
   ложным всегда, а fallback «Key/BPM» на заставке не срабатывал НИКОГДА.
   Сравнивайте строки по значению (`isNotBlank`, `isEmpty`, `==`).
2. **`String.split("|") + toInt()` без проверки формата.** `split` без
   limit может вернуть больше двух частей, а `toInt()` на не-числе бросает
   исключение ВНУТРИ генерации `.mlt` — падает весь проект песни. Разбирайте
   маршрут регулярным выражением и возвращайте `null`, а не бросайте.
3. **`MltNode()` — это узел с ПУСТЫМ именем.** Его `toString()` даёт `< />`,
   и такой не-well-formed XML уезжает в `xmldata` титра. Для «пустого» узла
   используйте валидный `kdenlivetitle` (`emptyKdenliveTitle()`).
4. **Ссылка на несуществующий `<producer>`.** Не каждый `ProducerType`
   переопределяет `producer()` — у `LINETRACK`/`CHORDPICTURELINETRACK`/
   `SCROLLERTRACK` такого узла в `.mlt` нет, и ссылка `producer_linetrack_*`
   была битой (182 штуки на 12 свежих проектах). Список типов без `producer()`
   — в `PRODUCER_TYPES_WITHOUT_PRODUCER`; при добавлении нового типа проверка
   `PkgS325Batch1SourceContractsTest` падает, если тип в список не попал.
5. **Списки из админских свойств — не типизированные.** `countersColors` и
   `voices` приходят из `POST /api/properties/setproperty` строкой без
   валидации. Индексация `list[i]` без проверки размера = падение генерации.
   Берите `getOrNull` и fallback.
6. **Редирект в XHR — это скачивание всей страницы.** `return
   "redirect:/processes"` в обработчике, который зовёт AJAX, приводит к тому,
   что каждый клик скачивает и рендерит всю страницу (а «применить ко всем» —
   N раз подряд). Для XHR отвечайте коротким JSON.
7. **`@RequestParam(required = false)` с non-null Kotlin-типом = NPE при
   отсутствии параметра.** Тип должен быть nullable, а «не передано» —
   означать «не менять».
8. **Пустое значение из UI — не то же, что невалидное.** Пустое (поле не
   заполнено) → «не менять»; нечисловое (опечатка) → 400. Если считать оба
   случая ошибкой, обычная кнопка «применить ко всем» с пустым полем будет
   бить по каждой строке.
9. **Точечный `SELECT` на каждый узел в цикле — это N+1.** Даже если данные
   «никогда не меняются», 9 000 запросов на песню съедают время рендера.
   `tbl_uuids` читается одним `SELECT` (`UuidCache`).
10. **`emptyList()` из упавшего `SELECT` — это «сбой», а не «пусто».** Такой
    результат ещё и кэшируется на TTL, и публичный API потом отдаёт «у автора
    нет альбомов» ещё минуту после восстановления БД. Пробрасывайте
    `AlbumTilesUnavailableException` → 503.
11. **Обрезка текста ПОСЛЕ разбора HTML не ограничивает память.** `Jsoup`
    строит полный DOM до того, как вы обрежете текст. Лимит тела — на
    уровне HTTP-клиента (`maxBodySize`).
12. **Два движка поиска — один фильтр.** Если фильтр применён только к
    fourget, SearXNG-путь отдаёт в LLM homepage/логины/sitemap/дубликаты, а
    каждая лишняя ссылка стоит до 120 с вызова LM Studio.
13. **Пустое `voices`/`countersColors` в свойствах ломает рендер, а не
    админку.** Свойство можно испортить через админ-API без валидации; падать
    будет потом генерация `.mlt` — с большим отрывом по времени и без
    указания, какой параметр виноват. Поэтому в `MkoCounter` есть WARN с
    именем свойства.
14. **Проверка `isValidVoiceIndex` должна быть ДО любых операций со
    списками.** Иначе `voice` из URL пишет/читает чужой диапазон.
15. **`String.toBoolean()` — не разбор, а тихое «нет».** Любая строка, кроме
    «true», становится `false`: опечатка в значении молча выключала фичу.
    Разбирайте boolean явно (`true/false/1/0/yes/no/on/off`), иначе — 400.
16. **`toLong()`/`toInt()` на вводе из UI = 500.** Значение свойства приходит
    строкой; `toLongOrNull()` → 400 с причиной, иначе один символ в поле
    роняет обработчик.
17. **Незарегистрированный ключ свойства — это 404, а не тихий no-op.**
    Иначе админ правит настройку, видит «установлено», а ничего не меняется
    (а типизированные геттеры отдают нулевое значение языка вместо дефолта).
18. **`conn.isValid(3)` — это запрос к серверу, а не локальная проверка.**
    В pgjdbc он уходит на сервер пустым query'ем. В горячем пути (`getConnection`)
    это лишний round-trip на каждое обращение к БД — на удалённой БД десятки
    тысяч лишних запросов за прогон.
19. **Флаг «задача идёт» = `AtomicBoolean.compareAndSet`, а не `if (f) return;
    f = true`.** Пара check-then-set на `@Volatile`-флаге неатомарна: два
    одновременных запроса запускают две тяжёлые задачи и пишут в одни и те же
    строки.
20. **Флаг снимается в `finally`, а не последним оператором тела.** Если сбой
    случился раньше (например, в `SNS.send`, который сериализует payload вне
    `try`), флаг остаётся поднятым навсегда: кнопка до перезапуска приложения
    отвечает «уже выполняется».
21. **`waitFor()` без таймаута вешает поток Tomcat навсегда.** Внешний процесс
    должен иметь таймаут и `destroyForcibly()`; вывод — с лимитом (иначе
    непрерывный вывод съедает память).
22. **Скрипт для хоста — не склейка.** Значение пользователя (автор/альбом с
    апострофом) в одинарных кавычках без экранирования апострофа даёт
    незакрытую кавычку: watcher исполняет искажённую команду. Передавайте
    значения позиционными параметрами и экранируйте `'` как `'\''`; права на
    скрипт — `700`, не `777`.
23. **Один битый CSV-строка не должна ронять массовое обновление.**
    `csvRecord.get(3)` на короткой строке и `bpm.toLong()` на нечисле бросали
    наружу и прерывали цикл на середине — часть песен уже сохранена, остальные
    не обработаны, сводка не сформирована.
24. **Текст песни — это текст, а не HTML.** `element.html()` кладёт в
    `sourceText` чужую разметку (`<div>`, `<span>`, `<script>`), которая
    потом уезжает в маркеры строк и в кадр видео как литеральные символы.
25. **`find` вместо `findAll` — молчаливая потеря данных.** Разбиение текста на
    слова через `regex.find(text)` давало ТОЛЬКО первое слово; остальные слова
    терялись, а маркеры сверх длины списка обнулялись.
