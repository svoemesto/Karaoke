# Phase 1 Data Model: Закрома — группировка альбомов

Изменений схемы БД нет. Ниже — существующие сущности, участвующие в баге, с
уточнением, какое поле является настоящим ключом идентичности альбома
внутри закромов (это и есть суть фикса — не новая сущность, а исправленный
производный ключ группировки).

## Song (существующая, `tbl_songs`, без изменений)

Поля, релевантные группировке (уже существуют):

| Поле | Тип | Значение |
|---|---|---|
| `author` (`song_author`) | String | Автор песни (свободный текст) |
| `year` (`song_year`) | Int | Год альбома песни (свободный текст) |
| `album` (`song_album`) | String | Название альбома (свободный текст) |
| `albumId` (`album_id`) | Long? | Опциональная ссылка на `Album`, проставляется `AlbumBackfill` или вручную; может быть `null` |

## Album (существующая, `tbl_albums`, без изменений)

| Поле | Тип | Значение |
|---|---|---|
| `id` | Long | PK |
| `authorId` | Long | FK на автора |
| `year` | Int | Год |
| `name` | String | Название |
| `albumType`, `sortOrder`, `description`, `shortDescription`, `warning` | — | Метаданные карточки |

Инвариант БД (уже существует, не меняется): уникальный констрейнт
`tbl_albums_author_year_name_key` на `(author_id, year, name)` — то есть
**реальная идентичность альбома — тройка (автор, год, название), а не только
название**.

## ZakromaAlbum (существующий DTO закромов, in-memory, без изменений формы)

Формируется в `Zakroma.buildFromSettings()` из группы песен одного автора.

**До фикса** — ключ группы: `album` (название). Побочный эффект: при
коллизии названий у двух альбомов разных годов создаётся ОДНА группа/карточка
на оба реальных альбома; `album.year` берётся от `settingsByAlbum.first().year`
— то есть от случайно первой в списке песни, которая может принадлежать
любому из двух исходных альбомов.

**После фикса** — ключ группы: пара **(year, album)** в пределах уже
сгруппированных по автору песен. Один `ZakromaAlbum` строго соответствует
одному (году, названию) — то есть, в типичном случае, одному реальному
альбому (за исключением уже штатно невозможного случая двух РАЗНЫХ альбомов
с одинаковыми (автор, год, название) — см. `spec.md` → «Assumptions»).

Поля `ZakromaAlbum` не меняются:

| Поле | Тип | Источник (после фикса) |
|---|---|---|
| `albumName` | String | Название из ключа группы (либо переопределено из связанной `Album.name`, если найдена по `albumId`, как и раньше) |
| `year` | Long | Год из ключа группы (детерминированно, не «первая попавшаяся» песня) |
| `picture`, `picturePreviewFileName` | String | Как раньше — по имени картинки `"$authorName - ${album.year} - $albumName"` |
| `albumSettings` | `List<ZakromaAlbumSettings>` | Песни ровно этой (год, название)-группы |
| `albumType`, `sortOrder`, `description`, `shortDescription`, `warning`, `albumTypeLabel` | — | Как раньше — из связанной `Album`, если хотя бы одна песня группы имеет `albumId` |

## State transitions

Не применимо — это read-only построение представления (закрома формируются
заново при каждом запросе из текущего состояния `tbl_songs`/`tbl_albums`),
без хранимого состояния и переходов.
