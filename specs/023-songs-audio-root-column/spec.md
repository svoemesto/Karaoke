# Feature Specification: Колонка audio_parent_id в таблице песен админки

**Feature Branch**: `[###-feature-name]`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "Админка, компонент "Песни"
Добавить в таблицу столбец audio_parent_id (заколовок стобца пусть будет "A-root"), столбец 3-й по счёту (после root).
В строке при ховере на ячейку root и A-root в тултипе должна отображаться информация о песне с эти id (Автор, год, альбом, название).
Так же это поле надо добавить в фильтр."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Отображение колонки A-root (Priority: P1)

Администратор открывает таблицу "Песни" в админке и видит колонку "A-root" третьей по счёту (после колонки "root"). В колонке отображается значение `audio_parent_id` для каждой песни.

**Why this priority**: Это основная функциональность фичи — предоставить администратору быстрый доступ к связанному идентификатору песни-источника аудио.

**Independent Test**: Открыть таблицу "Песни", убедиться, что колонка "A-root" присутствует на третьей позиции и содержит корректные значения.

**Acceptance Scenarios**:

1. **Given** таблица "Песни" открыта, **When** администратор смотрит на заголовки столбцов, **Then** "A-root" находится сразу после столбца "root" и отображается в строке заголовков.
2. **Given** в базе есть песни с заполненным `audio_parent_id`, **When** таблица загружена, **Then** значения `audio_parent_id` видны в ячейках колонки "A-root".
3. **Given** в базе есть песни с пустым `audio_parent_id`, **When** таблица загружена, **Then** ячейка "A-root" отображается пустой или специальным символом-заглушкой (например, "—").

---

### User Story 2 - Тултип с информацией о песне при наведении (Priority: P1)

Администратор наводит курсор на ячейку "root" или "A-root". В тултипе отображаются автор, год, альбом и название песни, соответствующей идентификатору в ячейке.

**Why this priority**: Тултип избавляет от необходимости открывать другую страницу, чтобы понять, на какую песню ссылается идентификатор.

**Independent Test**: Навести курсор на ячейку "root" и "A-root" и проверить содержимое тултипа.

**Acceptance Scenarios**:

1. **Given** в ячейке "root" указан id существующей песни, **When** администратор наводит на ячейку курсор, **Then** через короткую задержку появляется тултип с автором, годом, альбомом и названием этой песни.
2. **Given** в ячейке "A-root" указан id существующей песни, **When** администратор наводит на ячейку курсор, **Then** тултип содержит автор, год, альбом и название песни с данным `audio_parent_id`.
3. **Given** в ячейке нет значения или указан несуществующий id, **When** администратор наводит на ячейку курсор, **Then** тултип не появляется или показывает сообщение "Не найдено" / "—".

---

### User Story 3 - Фильтр по audio_parent_id (Priority: P2)

Администратор может фильтровать таблицу "Песни" по значению `audio_parent_id`, используя стандартный фильтр таблицы.

**Why this priority**: Фильтр позволяет быстро находить группы песен, связанных с одним аудио-источником.

**Independent Test**: Ввести значение `audio_parent_id` в фильтр и убедиться, что таблица показывает только строки с совпадающим значением.

**Acceptance Scenarios**:

1. **Given** в фильтре таблицы есть поле "A-root" / "audio_parent_id", **When** администратор вводит конкретный id, **Then** таблица отображает только песни с таким `audio_parent_id`.
2. **Given** фильтр по "A-root" применён, **When** администратор очищает поле фильтра, **Then** таблица возвращается к отображению всех песен с учётом остальных фильтров.
3. **Given** администратор вводит несуществующий id в фильтр, **When** фильтр применён, **Then** таблица показывает пустой результат с понятным сообщением.

---

### Edge Cases

- Что происходит, если `audio_parent_id` ссылается на удалённую или несуществующую песню?
- Как ведёт себя тултип при быстром перемещении курсора между ячейками?
- Что отображается в колонке "A-root", если песня не имеет связанного аудио-источника?
- Корректно ли работает фильтр при вводе частичного совпадения или только полного id?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В таблице "Песни" админки MUST отображаться колонка "A-root", показывающая значение поля `audio_parent_id`.
- **FR-002**: Колонка "A-root" MUST быть расположена третьей по порядку сразу после колонки "root".
- **FR-003**: При наведении курсора на ячейку колонки "root" или "A-root" MUST появляться тултип с информацией о песне, на которую указывает id в ячейке: автор, год, альбом, название.
- **FR-004**: Если песня по id в ячейке не найдена, тултип SHOULD показывать понятное сообщение об отсутствии данных или не отображаться.
- **FR-005**: Поле `audio_parent_id` MUST быть доступно в фильтре таблицы "Песни" под названием "A-root" или аналогичным.
- **FR-006**: Фильтр по "A-root" MUST поддерживать точное совпадение по значению `audio_parent_id`.
- **FR-007**: Очистка фильтра по "A-root" MUST возвращать таблицу к состоянию без данного фильтра.

### Key Entities *(include if feature involves data)*

- **Песня (Song)**: Сущность с атрибутами `id`, `root` (id родительской песни), `audio_parent_id` (id аудио-источника), автор, год, альбом, название.
- **Таблица песен админки (SongsTable)**: Визуальный компонент, отображающий список песен с колонками, включая "root" и "A-root", и предоставляющий фильтры.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Администратор видит колонку "A-root" в таблице "Песни" на третьей позиции в 100% случаях открытия компонента.
- **SC-002**: Тултип с автором, годом, альбомом и названием появляется при наведении на ячейки "root" и "A-root" для существующих id не позднее чем через 500 мс.
- **SC-003**: Фильтр по "A-root" позволяет находить песни по точному `audio_parent_id` с первой попытки в 95% случаев.
- **SC-004**: Отсутствие значения `audio_parent_id` корректно отображается в таблице и не приводит к ошибкам при наведении или фильтрации.

## Assumptions

- Поле `audio_parent_id` уже существует в базе данных и API, доступном таблице "Песни".
- Таблица "Песни" уже имеет колонку "root" и стандартный механизм фильтрации.
- Данные песни (автор, год, альбом, название) доступны по id через тот же источник данных, что и таблица.
- Стиль тултипа соответствует существующему дизайну админки (Bootstrap-vue-next / Bootstrap 5).
- Ввод в фильтр по "A-root" — строковый или числовой id; частичный поиск не требуется.
