# Feature Specification: Редактор видит все песни в закромах и поиске на karaoke-public независимо от статуса

**Feature Branch**: `017-editor-status-bypass`

**Created**: 2026-07-28

**Status**: Draft

**Input**: User description: "В karaoke-public в закромах и в поиске отображаются только песни со статусом >=3, так же количество песен автора в подписи плашки закромов считается так же, а авторы у которые нет таких песен не отображаются. Это абсолютно корректное поведение. Теперь из него надо сделать одно исключение - если текущий пользователь является "редактором", то для него правило "статус >=3" не действует - он видит все песни вне зависимости от статуса."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Редактор просматривает закрома автора со всеми песнями (Priority: P1)

Пользователь публичного сайта, вошедший в систему под учётной записью с ролью
«редактор», открывает закрома автора. В отличие от обычного посетителя, он
должен видеть все песни этого автора независимо от статуса готовности —
включая те, что ещё в производстве (статус < 3), — чтобы иметь возможность
отслеживать и контролировать процесс их подготовки прямо на публичном сайте.

**Why this priority**: Это основной сценарий фичи — без него исключение для
редактора не работает вовсе, и вся ценность запроса не реализована.

**Independent Test**: Войти на публичный сайт под учётной записью с ролью
«редактор», открыть закрома автора, у которого есть песни как со статусом
>= 3, так и со статусом < 3, и убедиться, что видны все песни автора, включая
недоготовые.

**Acceptance Scenarios**:

1. **Given** редактор авторизован на публичном сайте, у автора есть альбом с
   5 песнями (3 со статусом >= 3, 2 со статусом < 3), **When** редактор
   открывает закрома этого автора, **Then** в альбоме отображаются все 5
   песен.
2. **Given** у автора все песни имеют статус < 3, **When** редактор (в
   отличие от обычного посетителя) открывает закрома, **Then** автор
   отображается в списке со всеми своими песнями, а не скрывается.
3. **Given** редактор авторизован, **When** он открывает виртуальную плашку
   «Отдельные песни разных авторов» (спецзаказные авторы), **Then** в ней
   тоже показаны все песни независимо от статуса.

---

### User Story 2 - Редактор ищет песни любого статуса (Priority: P1)

Редактор использует публичный поиск по названию, автору, альбому или тексту
песни. В отличие от обычного посетителя, результаты поиска должны включать
песни любого статуса готовности, а не только готовые (статус >= 3).

**Why this priority**: Поиск — второй ключевой публичный сценарий
обнаружения контента (наравне с закромами), без которого редактор не сможет
быстро найти конкретную недоготовую песню через тот же интерфейс, что
использует обычный посетитель.

**Independent Test**: Войти под учётной записью с ролью «редактор», найти
через поиск песню со статусом < 3, убедиться, что она присутствует в
результатах — в отличие от поведения для незалогиненного посетителя.

**Acceptance Scenarios**:

1. **Given** есть песня со статусом < 3, **When** редактор ищет её по
   названию, **Then** песня появляется в результатах поиска.
2. **Given** есть две песни с одинаковым текстом, одна со статусом >= 3,
   другая со статусом < 3, **When** редактор ищет по этому тексту, **Then**
   в выдаче присутствуют обе песни.

---

### User Story 3 - Подпись количества песен автора соответствует тому, что видит редактор (Priority: P2)

Подпись плашки закромов автора показывает количество его песен. Для
обычного посетителя это количество считается только по песням со статусом
>= 3 (существующее поведение). Для редактора, который видит все песни
автора, эта подпись должна отражать полное количество песен автора
независимо от статуса, чтобы число в подписи не расходилось с тем, что
редактор реально видит, открыв закрома.

**Why this priority**: Ниже первых двух сценариев, потому что это не
отдельная точка входа к контенту, а согласованность отображаемого числа с
уже работающим (по US1) списком песен — расхождение вводит в заблуждение,
но не блокирует основную функциональность.

**Independent Test**: Войти под учётной записью с ролью «редактор», найти
автора с песнями разных статусов, сравнить число в подписи плашки закромов
с фактическим количеством песен, видимых при открытии закромов этого
автора — числа должны совпадать.

**Acceptance Scenarios**:

1. **Given** у автора 5 песен (3 со статусом >= 3, 2 со статусом < 3),
   **When** редактор просматривает список авторов/плашек закромов, **Then**
   подпись показывает 5 песен (а не 3).
2. **Given** тот же автор, **When** обычный (не редактор) посетитель
   просматривает тот же список, **Then** подпись по-прежнему показывает 3
   песни — поведение для не-редакторов не меняется.

---

### Edge Cases

- Незалогиненный посетитель и залогиненный обычный (не-редактор)
  пользователь — поведение не меняется: продолжают видеть только песни со
  статусом >= 3, как и авторов/подписи, посчитанные по этому же правилу
  (specs/013-song-status-filter).
- У автора нет ни одной песни ни при каком статусе — автор не отображается ни
  для редактора, ни для обычного пользователя (это уже не имеет отношения к
  статусу).
- Редактор открывает закрома автора, у которого есть только песни со
  статусом < 3 (для обычного посетителя такой автор вообще не отображался
  бы) — редактор всё равно видит автора и все его песни.
- Смена статуса песни (в любую сторону) должна немедленно отражаться в том,
  что видит редактор — какой бы статус ни принимала песня, она остаётся
  видимой редактору.
- Единичная страница конкретной песни по прямой ссылке, сам плеер и
  готовность плеера к воспроизведению — вне рамок этой фичи (см.
  Assumptions), как и в specs/013-song-status-filter.
- Потеря сессии/токена авторизации во время просмотра — редактор, переставший
  быть аутентифицированным как редактор, должен получать то же представление
  (только статус >= 3), что и обычный посетитель, при следующем
  обращении к странице/поиску.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST определять, что текущий пользователь публичного
  сайта аутентифицирован и имеет роль «редактор», перед применением правил
  видимости песен в закромах и поиске.
- **FR-002**: Для пользователя с ролью «редактор» просмотр закромов автора
  (включая виртуальную плашку «Отдельные песни разных авторов») MUST
  показывать все песни автора независимо от статуса готовности.
- **FR-003**: Для пользователя с ролью «редактор» публичный поиск песен (по
  названию, автору, альбому, тексту) MUST возвращать песни независимо от
  статуса готовности.
- **FR-004**: Для пользователя с ролью «редактор» автор/альбом, у которого
  есть хотя бы одна песня любого статуса, MUST отображаться в закромах —
  правило «скрывать автора без песен со статусом >= 3» (specs/013) на
  редактора не распространяется.
- **FR-005**: Подпись количества песен автора в плашке закромов, показываемая
  пользователю с ролью «редактор», MUST считать все песни автора независимо
  от статуса — то же множество песен, которое редактор видит, открыв
  закрома этого автора.
- **FR-006**: Для всех пользователей без роли «редактор» (анонимных и
  обычных зарегистрированных) поведение фильтрации закромов, поиска и
  подписи количества песен MUST остаться неизменным — только статус >= 3
  (specs/013-song-status-filter).
- **FR-007**: Изменение статуса песни MUST немедленно отражаться в том, что
  видит редактор — при следующем обращении к странице/поиску видимость
  песни соответствует её текущему статусу (песня видна редактору при любом
  статусе).
- **FR-008**: Роль «редактор» для целей этой фичи MUST определяться тем же
  признаком учётной записи пользователя, которым эта роль уже определена в
  системе — без введения нового отдельного понятия «редактор».
- **FR-009**: Данная фича относится только к публичной части сайта
  (karaoke-public); видимость песен в административной панели (webvue3) не
  затрагивается и продолжает показывать все статусы всем, кто туда имеет
  доступ, как и раньше.

### Key Entities

- **Song (песня)**: единица контента с полем статуса готовности; для
  обычных пользователей видимы только статусы >= 3, для редактора видимы
  все статусы (см. specs/013-song-status-filter).
- **Закрома автора**: публичная витрина, группирующая песни автора по
  альбомам; для редактора отображает полный набор песен автора, для прочих
  — только готовые.
- **Пользователь публичного сайта с ролью «редактор»**: аутентифицированная
  учётная запись сайта, для которой правило «статус >= 3» не применяется при
  просмотре закромов и поиска.
- **Результаты поиска**: список песен, отобранных по совпадению с поисковым
  запросом; для редактора не ограничен статусом готовности.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% песен автора (включая статусы < 3) отображаются в
  закромах при просмотре пользователем с ролью «редактор».
- **SC-002**: 100% песен, соответствующих поисковому запросу (включая
  статусы < 3), присутствуют в выдаче публичного поиска для пользователя с
  ролью «редактор».
- **SC-003**: Число в подписи количества песен автора, видимое редактору,
  совпадает с фактическим числом песен, отображаемых при открытии закромов
  этого автора тем же редактором, в 100% случаев.
- **SC-004**: Поведение для анонимных и обычных (не-редактор)
  пользователей не меняется — 100% ранее скрытых от них песен со статусом
  < 3 остаются скрытыми.

## Assumptions

- Роль «редактор» — это уже существующий в системе признак учётной записи
  пользователя сайта (используется, в частности, для доступа к разделу
  редакторских задач на публичном сайте), а не новая сущность, которую нужно
  вводить в рамках этой фичи.
- Определение аутентифицированного пользователя на публичных страницах
  закромов и поиска использует тот же механизм входа/токена, который уже
  применяется на других страницах публичного сайта, требующих знания
  личности пользователя.
- Единичная страница конкретной песни по прямой ссылке, сам плеер и
  механизм готовности плеера — отдельная, уже существующая логика; в рамках
  этой фичи не меняется (как и в specs/013-song-status-filter).
- Порог «статус >= 3» для не-редакторов остаётся тем же, что определён и
  используется в specs/013-song-status-filter — эта фича не переопределяет
  его, а добавляет единственное исключение для роли «редактор».
- Административная панель (webvue3) не входит в объём этой фичи — она уже
  показывает все статусы всем пользователям, имеющим к ней доступ, независимо
  от роли «редактор» на публичном сайте.
