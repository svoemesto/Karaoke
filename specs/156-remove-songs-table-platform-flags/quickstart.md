# Quickstart: Удаление 18 столбцов-флагов из таблицы «Песни»

**Created**: 2026-08-06
**Feature**: [spec.md](./spec.md)

Этот документ — пошаговое руководство по ручной проверке фичи. Запускается разработчиком после применения правок в feature-ветке `156-remove-songs-table-platform-flags`.

## Предусловия

- Node.js 22 (LTS), npm 10+
- Запущенные контейнеры `karaoke-web` и `webvue3` (через `bash do.sh start` из `deploy/`)
- Локально наполненная БД (несколько песен с разными флагами публикации)
- Браузер (Chrome/Firefox/Safari актуальной версии) с devtools

## Подготовка

```bash
# 1. Переключиться на feature-ветку
cd /home/nsa/Karaoke
git checkout 156-remove-songs-table-platform-flags

# 2. Собрать webvue3
cd webvue3
npm install           # если node_modules отсутствуют
npm run build

# 3. Перезапустить контейнер webvue3 (если dev-server не используется)
cd ../deploy
bash do.sh start      # или restart_webvue3 / build_start_webvue3

# 4. Открыть в браузере
open http://localhost:5173/songs   # или 8889 / 8890 — зависит от конфигурации
```

## Шаги проверки

### Шаг 1 — Визуальный осмотр шапки таблицы

1. Открыть `http://localhost:5173/songs`.
2. Навести курсор на шапку таблицы (`<thead>`).
3. **Ожидаемый результат**: видны 18 столбцов в следующем порядке:
   - ID, Композиция, Исполнитель, Год, Альбом, №, Дата, Время, Tags, Status, V, BOO, Редактор, ▶ (player), ▶ (playerDemo), DE, TG, FR
4. **Стоп-сигнал**: если видны столбцы с заголовками SP/VG/ZL/ZK/ZC/ZM/VL/VK/VC/VM/TL/TK/TC/TM/ML/MK/MC/MM — правка не применена или сборка не обновлена.

### Шаг 2 — Проверка через DOM-инспектор

1. Включить devtools (F12), перейти на вкладку **Elements**.
2. Найти элемент `<thead>` (или `tr` внутри него).
3. Подсчитать число дочерних `<th>` элементов.
4. **Ожидаемый результат**: ровно 18 `<th>`.
5. **Стоп-сигнал**: больше или меньше 18 — проверить, что все 18 объектов из `fields[]` удалены (а не, например, 17).

### Шаг 3 — Проверка ширины таблицы

1. В devtools выделить элемент `<thead>`.
2. Запустить в консоли:
   ```js
   document.querySelector('thead').getBoundingClientRect().width
   ```
3. **Ожидаемый результат**: значение **меньше** того, что было до правки на ≈ 360px (18 × 20px). Конкретное число зависит от разрешения и наличия горизонтального скролла.
4. **Стоп-сигнал**: ширина не изменилась — правка не применена.

### Шаг 6 — Регресс-проверка (раздел «Публикации»)

1. Открыть `http://localhost:5173/publications`.
2. Убедиться, что таблица публикаций отрисовывается без ошибок в консоли.
3. Кликнуть по строке публикации — должны работать кнопки/действия, использующие `processColorSponsr/Vk` и `play*` методы.
4. **Стоп-сигнал**: ошибки в консоли, кнопки воспроизведения не работают — регрессия.

### Шаг 7 — Регресс-проверка (редактор песни)

1. Открыть `http://localhost:5173/songs/:id/edit` для любой песни.
2. Убедиться, что кнопки PLAY LYRICS / PLAY KARAOKE / PLAY CHORDS / PLAY TABS / PLAY DEMO работают.
3. **Стоп-сигнал**: ошибки в консоли при клике по кнопкам — регрессия.

## Если что-то пошло не так

1. **Шаг 1-2 (столбцы видны)**: проверить, что сборка `webvue3` действительно перезапущена; проверить `git diff` в feature-ветке — все ли 18 объектов удалены.
2. **Шаг 3 (ширина не уменьшилась)**: возможно, есть горизонтальный скролл и контейнер ограничен по ширине; измерять ширину `<thead>`, а не родительского контейнера.
3. **Шаг 4 (мёртвый код)**: проверить, что удалены и `<template #cell>` шаблоны, и объекты в `fields[]`, и CSS-стили, и методы (если применимо).
4. **Шаг 5 (сборка падает)**: частая причина — забыли удалить ссылку на удалённый CSS-класс где-то ещё; запустить `npm run lint` для деталей.
5. **Шаг 6-7 (регресс)**: проверить, что `SongsTable.vue` не использовался как источник методов для других компонентов через цепочку импортов.
6. **Шаг 8 (документация)**: проверить, что PR содержит коммит с правкой `docs/features/songs-table.md`.
