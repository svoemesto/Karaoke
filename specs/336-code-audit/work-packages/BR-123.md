# [#336] S1: 25 обработчиков подтверждения собирают `customConfirmParams.body` интерполяцией `this.song… (BR-123)

Задача: устранение дефекта **BR-123** (S1) из полного аудита кода (#336).

## Что не так

25 обработчиков подтверждения собирают `customConfirmParams.body` интерполяцией `this.song.songName` в HTML-строку с `<strong>`, а `CustomConfirm.vue` рендерит `params.body` через `v-html`. Имя песни хранится в БД как есть (`SongUpdateMapper` кладёт строку в `song.fields[NAME]` без экранирования) и приходит в карточку из `/api/song`; `<img src=x onerror=…>` в имени выполняется в DOM админки при клике на любую из этих кнопок (удаление, «Создать караоке», картинки, DEMUCS, symlinks, «Скопировать поля…»). Это не self-XSS «по определению»: имя пишут не только эта форма (`Poi.kt`, two-DB sync, второй админ/вкладка), а API бэкенда закрыт только для `/api/private/**`, всё остальное — `permitAll` без CSRF (`config/SecurityConfig.kt:40–46`), т.е. из сессии админа исполнение даёт доступ к `POST /api/song/delete`, запуску процессов и т.п.

## Доказательство

«body: `Удалить песню <strong>«${this.song.songName}»</strong>?`,» (`SongEdit.vue:5037`, SHA `1977838a`); «body: `Скопировать поля из другой песни для песни <strong>«${this.song.songName}»</strong>?`,» (`:4133`); sink — «`<div :style="styleHeader" v-html="params.header" />` / `<div :style="styleBody" v-html="params.body" />`» (`Common/CustomConfirm.vue:5–6`, тот же SHA). Запись без экранирования: «`val field = fieldLookup[key]` / `song.fields[field] = value`» (`SongUpdateMapper.kt:305–306`).

## Путь достижимости

имя попадает в БД из формы/`POST /api/song/update` (`SongUpdateMapper.kt:93–94`), импорта xlsx (`Poi.kt:124`) или sync (`Song.kt:8182`) → карточка: `POST /api/song` → `store.getCurrentSong` → клик «Удалить песню» (шаблон `:2530`) → `deleteSong()` (`:5034`) → `body` (`:5037`) → `isCustomConfirmVisible = true` → `<custom-confirm :params>` (`:5–9`) → `v-html="params.body"` (`CustomConfirm.vue:6`) → `innerHTML` → `onerror/onload` в origin админки. Зеркала: `:4133, 4163, 4174, 4185, 4196, 4207, 4218, 4229, 4240, 4252, 4264, 4275, 4286, 4298, 4310, 4322, 4709, 4777, 4801, 4837, 4870, 4894, 4918, 4993, 5037` (все — `body` с `${this.song.songName}`), плюс `header` (`:4321`) — тоже `v-html`, но со статичным `${version}`.

## Предлагаемая поправка

не собирать HTML из имени — передавать имя отдельным текстовым VNode/слотом либо экранировать (`escapeHtml(songName)`) при формировании `body`; в `CustomConfirm` оставить `v-html` только для статичной разметки (или заменить на слот/`v-text`), а `header/body` из данных рендерить текстом.
