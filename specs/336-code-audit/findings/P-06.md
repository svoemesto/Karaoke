### P-06-01: karaoke-app/src/main/kotlin/com/svoemesto/karaokeapp/SyncAudioDescendants.kt:168–192 — LEAK (S2)

- Что не так: воркер синхронизации аудио-потомков создаётся как одноразовый `thread {}` и берёт JDBC-соединение `WORKING_DATABASE` через `getConnection()`, но никогда его не освобождает: `closeThreadConnection()` в файле отсутствует. По контракту `KaraokeConnection` (`KDoc :85–98`) такое соединение «держится открытым вечно», потому что поток больше никогда не вызовет `getConnection()`, чтобы переиспользовать его или обнаружить невалидным. Каждый запуск воркера = одно физическое соединение Postgres, которое не закрывается никем.
- Доказательство:
  «`thread(name = "sync-audio-descendants") {` / `    try {` / `        drainQueue()`» (SyncAudioDescendants.kt:173–175, SHA 1977838a);
  «`val connection = database.getConnection() ?: return result`» (там же:333);
  в `finally` (`:178–189`) только снимается флаг `workerRunning`, закрытия нет. Для сравнения — единственное место в `karaoke-app`, где контракт соблюдён: `KaraokeProcessWorker.kt:484` (`karaokeProcess.database.closeThreadConnection()`).
- Путь: редактор `webvue3` сохраняет песню → `Song.saveToDb` (`model/Song.kt:5665`, `:5859`) → `SyncAudioDescendants.onSongSaved` (`:141`) → `enqueue` (`:161`) → `startWorkerIfNeeded` (`:168`, под `lock` проверяет `workerRunning`) → новый `thread` (`:173`) → `syncOneParent` (`:256`) → `loadChildIds` (`:328`) → `WORKING_DATABASE.getConnection()` (`KaraokeConnection.kt:54`) → `DriverManager.getConnection` (`:66`) → `loadById` детей тем же соединением; поток завершается, соединение остаётся открытым. При активном редактировании (каждое сохранение контента, когда предыдущий проход уже закончился) — один новый поток и одно новое соединение на сохранение; `pgjdbc` не имеет надёжного финализатора, соединение живёт до перезапуска `karaoke-app` или до `pg_terminate_backend`. Дефолтный `max_connections=100` делится с `karaoke-web`; ~100 сохранений контента за сессию редактора исчерпывают пул — `getConnection()` начинает возвращать `null` («Невозможно установить соединение…»), отказывают и очередь, и админка.
