## Назначение

Краткий runbook для админа: как вручную провалидировать, что новая кнопка «Поиск родителя» работает end-to-end (фронт + бэкенд + БД + SSE).

---

## Предусловия

- Ветка `283-admin-find-parent` в git.
- Контейнер `karaoke-app` запущен с собранным jar из этой ветки (`./gradlew :karaoke-app:bootJar` на `nsa-i9`/`nsa`; см. AGENTS.md, машинно-специфичное исключение).
- Контейнер `karaoke-web` собран и работает (фронт `webvue3`).
- В БД `WORKING_DATABASE` есть хотя бы один автор с ≥1 песней, у которой `root_id = 0`.
- Открыта главная страница админки: `http://localhost:8897/#/`.

## Сценарий 1 — Базовая функциональность (одиночный автор, `crossAuthor=false`)

### Подготовка

1. В БД найти автора с непустым набором песен с `root_id = 0`:
   ```sql
   SELECT song_author, COUNT(*) AS cnt
   FROM tbl_songs
   WHERE root_id = 0
   GROUP BY song_author
   ORDER BY cnt DESC
   LIMIT 5;
   ```
2. Запомнить имя автора (например, `"Автор Для Теста"`).

### Действия

1. Открыть главную страницу админки.
2. В поле «Автор» ввести имя (например, `"Автор Для Теста"`).
3. **Проверить**: кнопка «Поиск родителя» **доступна** и расположена **непосредственно над** кнопкой «Автопривязать оригинал по аудио (статус 1 → 2)».
4. Кликнуть «Поиск родителя».
5. **Проверить**: открылась модалка с заголовком «Подтвердите действие», телом, описывающим операцию, и переключателем `Искать среди песен других авторов:` в положении **FALSE** (по умолчанию).
6. **Проверить**: кнопки «Да» / «Нет».
7. Не меняя переключатель, кликнуть «Да».
8. **Проверить**: модалка закрылась, появился info-тост «Операция запущена в фоне. Итог придёт уведомлением по завершении».

### Ожидаемые результаты

1. В консоли `karaoke-app` (`docker logs -f karaoke-app`) идут строки вида:
   ```
   Поиск родителя (автор «Автор Для Теста»): найдено песен: N
     [родитель 1/N] … — привязан родитель [..]
     [родитель 2/N] … — родитель не найден
     …
   Поиск родителя: завершено. Обработано N, родитель назначен M (найдено, но пропущено из-за текста: K)
   ```
2. В ленте SSE-уведомлений приходит:
   - `head`: «Поиск родителя (автор «Автор Для Теста»)»
   - `body`: «Обработано N, родитель назначен M (найдено, но пропущено из-за текста: K)»
   - `type`: «info»
3. В БД у части песен автора `root_id` обновился с `0` на `id` другой песни **того же автора**:
   ```sql
   SELECT id, song_name, song_author, root_id
   FROM tbl_songs
   WHERE song_author = 'Автор Для Теста' AND root_id <> 0
   ORDER BY id;
   ```
4. В логах **нет** вызовов `autoAssignOriginalByWaveform` / `findAudioParentByWaveform` (аудио-фаза отключена).

## Сценарий 2 — `crossAuthor=true` (поиск среди других авторов)

### Подготовка

Та же, что в Сценарии 1, плюс: убедиться, что у другой песни **другого** автора есть ровно такое же нормализованное название (`normalizeSongNameForSearch(song_name)` совпадает).

### Действия

1. Ввести того же автора.
2. Кликнуть «Поиск родителя».
3. В модалке переключатель `Искать среди песен других авторов:` перевести в **TRUE**.
4. Кликнуть «Да».

### Ожидаемые результаты

1. В логах — `crossAuthor=true` (можно увидеть по тому, что для одной из песен автора был выбран кандидат с `song_author <> 'Автор Для Теста'`).
2. Проверка в БД:
   ```sql
   SELECT s.id, s.song_name, s.song_author AS child_author, p.song_author AS parent_author
   FROM tbl_songs s
   JOIN tbl_songs p ON s.root_id = p.id
   WHERE s.song_author = 'Автор Для Теста' AND p.song_author <> 'Автор Для Теста';
   ```
   Должны появиться строки (или быть пусто, если у других авторов нет подходящего названия — это тоже валидный результат).

## Сценарий 8 — Песня с уже проверенным текстом пропускается

### Подготовка

Создать тестовую песню автора с `source_text IS NOT NULL`, `id_status >= 2`, `root_id = 0`, и при этом в БД должна быть **другая** песня того же автора с **точно** таким же нормализованным названием (т.е. кандидат существует).

### Действия

1. Запустить сценарий 1.

### Ожидаемые результаты

1. В логах для этой песни:
   ```
   [родитель i/N] … — родитель найден (id=…), но текст уже проверен (id_status=…) — пропущено
   ```
2. В SSE-сводке счётчик `найдено, но пропущено из-за текста` инкрементируется на 1.
3. `root_id` этой песни остаётся `0`.

## Сценарий 9 (новый, добавлен 2026-08-31) — Родитель без текста находится

### Подготовка

Создать ситуацию:
- Песня A (`song_author='Иванов'`, `song_name='Тест'`, `source_text=''`, `root_id=любой`) — «сирота»-родитель того же автора без текста.
- Песня B (`song_author='Иванов'`, `song_name='Тест'`, `source_text=''`, `root_id=0`, `id_status=0`) — кавер, обрабатываем.
- Песня C (`song_author='Петров'`, `song_name='Тест'`, `source_text='<полный текст>'`, `root_id=любой`) — другой оригинал с тем же нормализованным названием, у которого **есть** текст.

### Действия

1. Запустить сценарий 1 (`crossAuthor=false`).

### Ожидаемые результаты

1. Песня B получает `root_id = A.id` (Иванов, без текста), **а не** C.id (Петров, с текстом) — потому что:
   - `crossAuthor=false` → поиск только среди того же автора;
   - наличие `source_text` у кандидата **не** влияет на выбор (с 2026-08-31).
2. В логах:
   ```
   [родитель i/N] … — привязан родитель [<id A> …]
   ```
3. `root_id` песни B становится `A.id`.

Это **главный** сценарий, демонстрирующий замечание пользователя от 2026-08-31: «родитель должен искаться среди всех песен автора, независимо от наличия текста».

Подготовка для всех сценариев ниже:
- В БД должен быть автор с ≥1 песней, у которой `root_id <> 0` И `audio_parent_id = 0` И есть хотя бы одна другая песня в её семье (`findFamilySongIds != пусто`).

## Сценарий A1 — Базовая функциональность аудио-кнопки

### Подготовка

Подобрать автора и убедиться по SQL:
```sql
SELECT id, song_author, song_name, root_id, audio_parent_id
FROM tbl_songs
WHERE LOWER(song_author) = LOWER('Иванов')
  AND root_id <> 0
  AND audio_parent_id = 0
ORDER BY id;
```
Если строк нет — операция отработает вхолостую (нулевой выборке).

### Действия

1. Открыть главную страницу админки.
2. В поле «Автор» ввести имя.
3. **Проверить**: кнопка «Найти аудио-родителя» доступна и расположена **между** «Поиск родителя» и «Автопривязать оригинал по аудио (статус 1 → 2)».
4. Кликнуть «Найти аудио-родителя».
5. **Проверить**: модалка с заголовком «Подтвердите действие» и описанием операции; кнопки «Да»/«Нет»; **нет** дополнительных полей.
6. Кликнуть «Да».
7. **Проверить**: info-тост «Операция запущена в фоне».

### Ожидаемые результаты

1. В консоли `karaoke-app`:
   ```
   Поиск аудио-родителя (автор «Иванов»): найдено песен в семье без audio_parent_id: N
     [аудио-родитель 1/N] … — <reason>
     …
   Поиск аудио-родителя (автор «Иванов»): завершено. Обработано N, аудио-родитель назначен M, пропущено K
   ```
2. SSE-уведомление:
   - `head`: «Поиск аудио-родителя (автор «Иванов»)»
   - `body`: «Обработано N, аудио-родитель назначен M, пропущено K»
   - `type`: «info»
3. В БД у части песен автора `audio_parent_id <> 0` (где нашёлся кандидат ≥ 95%), `audio_similarity_percent`/`audio_delta_ms` заполнены.

## Сценарий A2 — Не меняет текст/маркеры/статус

### Действия

1. До запуска — сохранить `recordhash` песен автора, которые будут обработаны:
   ```sql
   SELECT id, recordhash FROM tbl_songs WHERE id IN (<ids>);
   ```
2. Запустить «Найти аудио-родителя» (Сценарий A1).
3. После завершения — снова выгрузить `recordhash` тех же песен.

### Ожидаемые результаты

1. У песен, где `audio_parent_id` стал ненулевым, **изменились** только поля аудио (`audio_parent_id`, `audio_similarity_percent`, `audio_delta_ms`, `audio_compare_history`) — и соответствующие им компоненты `recordhash`.
2. Поля `source_text`, `source_markers`, `id_status`, `root_id`, `result_text`, `formatted_text_*` — **не изменились** (в отличие от `autoAssignOriginalAll`, которая применяет выбор).
3. `recordhash` для неизменённых полей — **совпадает** до и после (если БД-движок умеет частичный дифф; иначе — проверить по `updated_at` и сравнить значения полей вручную).

## Сценарий A3 — Идемпотентность по `audio_parent_id` (повторный запуск пропускает обработанные)

### Действия

1. Запустить Сценарий A1, дождаться SSE-уведомления.
2. Запомнить число «Обработано N» из первой сводки.
3. Снова кликнуть «Найти аудио-родителя» → «Да».

### Ожидаемые результаты

1. В консоли — `найдено песен в семье без audio_parent_id: 0` (или меньше, чем в первом запуске — если не для всех песен нашёлся кандидат).
2. SSE-сводка: «Обработано 0 (или M < N первого запуска), аудио-родитель назначен 0, пропущено 0».
3. В логах **нет** новых вызовов `WaveformCompare.compareWaveforms(song=<id с audio_parent_id>…)` (проверяется по логам контейнера `karaoke-app`).
4. `audio_parent_id` песен, обработанных в первом запуске, остаётся прежним.
