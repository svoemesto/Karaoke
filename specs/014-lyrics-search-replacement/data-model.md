# Data Model: замена поискового бэкенда для текстов песен

Постоянных сущностей БД задача не вводит и не меняет (см. `spec.md` → Key
Entities). Ниже — только временные (in-memory) модели интеграционного слоя,
существующие исключительно на время одного HTTP-запроса к новому поисковому
бэкенду и не персистируемые напрямую.

## LyricsSearchResponse (замена сегодняшнего `SearchResponse` в `llm/Tools.kt`)

Разбор JSON-ответа нового self-hosted бэкенда (4get, см. `research.md`).

| Поле      | Тип                       | Описание                                             |
|-----------|---------------------------|-------------------------------------------------------|
| `results` | `List<LyricsSearchResult>`| Список найденных веб-результатов, `emptyList()` по умолчанию |

## LyricsSearchResult (замена сегодняшнего `SearchResult` в `llm/Tools.kt`)

| Поле      | Тип      | Описание                                                        |
|-----------|----------|------------------------------------------------------------------|
| `url`     | `String` | URL страницы-кандидата — единственное поле, используемое дальше по конвейеру |
| `title`   | `String` | Заголовок результата — сегодня не используется вызывающим кодом, сохраняется для отладки/логов |
| `content` | `String` | Сниппет — сегодня не используется вызывающим кодом |

**Валидация/правила**:
- Пустой/blank `url` — результат отбрасывается перед возвратом (не должен попасть
  в итоговый `List<String>`), как и сегодня неявно (SearXNG почти всегда отдаёт
  непустой `url`, но защититься от пустых значений — оборонительная мера).
- Порядок результатов сохраняется как получен от бэкенда (ранжирование — забота
  поискового бэкенда, не интеграционного слоя).
- Дедупликация URL не требуется на этом уровне — сегодняшний код её тоже не
  делает; поведение не меняется (FR-004: интерфейс и семантика вызова неизменны).

## Существующие сущности, которые НЕ меняются

- `SearchAsync` (`model/SearchAsync` — не показан в этом плане, не читался
  повторно) и `SearchResult` (`karaoke-app/.../model/SearchResult.kt`, БД-сущность
  `tbl_search_results`) — модели, в которые сохраняется результат поиска текста
  песни (`getSearXNGSearch` в `UtilsAI.kt`). Их структура и хранимые поля не
  меняются: новый бэкенд лишь меняет **источник** списка URL, попадающего в
  `SearchResult.url`/`SearchResult.text` тем же путём, что и сегодня.
