## Сверки

Спорное и подтверждения существующих записей; severity не присваивается.

1. **Подтверждение BR-115 (chmod world-writable), другое семейство.** В аудированном диапазоне
   `runCommand(listOf("chmod", …))` вызывается 11 раз: `Utils.kt:1719, 1727, 1747, 1932, 1938`
   (`777` на каталоги), `:1989, 2022` (`666` на файлы дайджестов), `:2616` (`777` на каталог) и
   `:2619, 2629, 2632` (`666` на файлы текста/описания песни). Корень тот же, что в BR-115
   (`UtilsPictures.kt:564–566`), но файл другой — отдельной записи не создаю; при желании BR-115
   расширяется списком `locations`.
2. **BR-183 (XML escaping) не дублирую.** `searchSongText` (P-07-08) — иной корень: разметка
   попадает в *данные* (`source_text`), а не в XML при сборке. Экранирование в `MltNode` этот дефект
   не лечит: теги станут литеральными символами в кадре.
3. **`syncRemotePicturesInStorage` (717–824) удаляет объект в REMOTE до загрузки нового (781–793 →
   796–821):** при сбое upload объект потерян в удалённом хранилище. Функция помечена
   `@Suppress("unused")` и вызовов в репозитории не имеет — по рубрике § 2 (мёртвый код без
   достижимого пути) записью не считаю. Если функция включается вручную из REPL/скрипта — это
   кандидат в S2 DATA.
4. **`uploadPicturesToStorage` (825–858):** `picture.storageFileExists()` → загрузка; тоже
   `@Suppress("unused")`, вызовов нет. Не запись.
5. **`convertMarkersToSubtitles` (2723–2812):** вызовов в репозитории нет. Внутри два краевых места —
   `subText[0]` при пустом `comment` (`:2776`) и `textToAnalize!!` (`:2745`); недостижимы, поэтому не
   запись. При появлении вызова — S3 ERR.
6. **`copyIfNeed` (1735–1751):** копирование выполняется, только если файла нет **или** различается
   длина (`fileFrom.length() != fileTo.length()`); файл того же размера с другим содержимым не
   перезаписывается, и в store-каталоге остаётся старая версия. Считаю это осознанным компромиссом
   (720p-артефакт меняется вместе с размером), поэтому без severity. Вопрос: полагаться ли на длину
   или сравнивать `lastModified`/хэш?
7. **`generateChordLayout` (2363–2572):** два краевых места без доказанной достижимости.
   (а) `chordNameAndFret[1].toInt()` (`:2369`) бросает `NumberFormatException` на формате `"Am|"`;
   (б) `while (fingerboards.isEmpty()) { nextFret += 1; … }` (`:2389–2392`) не имеет верхней границы —
   если `getFingerboard` не найдёт аппликатуру ни на одном ладу, поток крутится вечно. Формат с `|`
   в текущем коде формируется не из пользовательского ввода (`Song.kt:4260` собирает имя аккорда без
   `|`), поэтому записью не считаю. Вопрос владельцу: бывает ли `chord.chord` с `|` из старых данных
