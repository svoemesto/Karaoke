**Feature Branch**: `301-search-text-extract-btn`

**Created**: 2026-09-03

**Status**: Draft

**Input**: User description: "Админка, SubsEdit.vue, модалка «Поиск текста в интернете». Кнопка «Получить текст по ссылке» должна быть ПОД кнопкой «Открыть на сайте» (в том же диве, одно под другой). После нажатия на эту кнопку когда/если удалось получить текст — он должен появляться в поле текста, а пункт в списке ссылок становиться активным (не серым). **Note**: модалка реализована в `webvue3/src/components/Songs/edit/SearchText.vue` (не в `SubsEdit.vue`, как ошибочно указано в OP#51 — SubsEdit содержит лишь `<search-text>` импорт и `doSearchText` action для её открытия).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Расположение кнопки «Получить текст по ссылке» под кнопкой «Открыть на сайте» (Priority: P1)

Администратор открывает модалку «Поиск текста в интернете» из `SubsEdit.vue`. В правом столбце модалки видит **две кнопки, расположенные вертикально друг под другом**:

1. Верхняя: «Открыть на сайте» (открывает выбранную ссылку в новой вкладке).
2. Нижняя: «Получить текст по ссылке» (запускает извлечение текста по выбранной ссылке; показывается, только если выбран «серый» результат без `text`).

**Why this priority**: это видимое (визуальное) требование из баг-репорта; администратор сразу понимает, какая кнопка за что отвечает, не путает порядок.

**Independent Test**: открыть модалку, выбрать результат без текста → кнопка «Получить текст по ссылке» видна непосредственно под кнопкой «Открыть на сайте», в одном контейнере, без смещения влево/вправо или появления на новой строке.

**Acceptance Scenarios**:

1. **Given** модалка открыта, выбран результат без `text`, **When** администратор смотрит на правый столбец, **Then** обе кнопки видны: верхняя «Открыть на сайте», нижняя — «Получить текст по ссылке», обе одинаковой ширины, столбиком.
2. **Given** ни один результат не выбран, **When** администратор смотрит на правый столбец, **Then** видна только кнопка «Открыть на сайте»; кнопка «Получить текст по ссылке» скрыта (или disabled).
3. **Given** выбран результат с уже полученным `text`, **When** администратор смотрит на правый столбец, **Then** кнопка «Получить текст по ссылке» скрыта (т.к. `canExtractLyrics === false`).

### User Story 2 — Полученный текст сразу появляется в поле без закрытия модалки (Priority: P1)

Администратор выбирает «серый» результат в списке ссылок (где `text === ''`). Нажимает «Получить текст по ссылке». Backend извлекает текст, возвращает обновлённый объект с заполненным `text`. **Без закрытия модалки** администратор сразу видит:

- В textarea справа — полученный текст.
- В списке ссылок слева — выбранный пункт **перестаёт быть серым** (становится белым/активным).

**Why this priority**: основная жалоба из баг-репорта — «приходится закрывать модалку и открывать заново, чтобы увидеть изменения». Это прямой блокер UX.

**Independent Test**: выбрать серый результат → нажать «Получить текст по ссылке» → дождаться ответа → textarea справа содержит полученный текст → соответствующий пункт в списке слева **не серый**.

**Acceptance Scenarios**:

1. **Given** выбран серый результат (text пуст), **When** администратор нажимает «Получить текст по ссылке» и backend возвращает `updated.text !== ''`, **Then** textarea справа немедленно отображает полученный текст (без переоткрытия модалки); соответствующий пункт в списке слева перестаёт быть серым.
2. **Given** выбран серый результат, **When** администратор нажимает «Получить текст по ссылке» и backend возвращает `updated.text === ''` с `updated.lastError !== ''`, **Then** показывается `window.alert` с сообщением об ошибке (как сейчас); textarea и список остаются в прежнем состоянии (серый результат).
3. **Given** кнопка «Получить текст по ссылке» нажата (идёт запрос), **When** администратор смотрит на UI, **Then** кнопка disabled и показывает «Получаю текст...»; повторное нажатие невозможно.

---

### Edge Cases

- Что если `extractLyricsBySearchResultId` бросает исключение (сетевая ошибка)? Должен сработать `catch` (line 253-255 в `SearchText.vue`) — `window.alert` с сообщением, `isExtractingLyrics = false`. После этого UI возвращается в исходное состояние (textarea не пустая, если была не пустая; серый результат остаётся серым).
- Что если результат с серой подсветкой выбран, нажата кнопка, и в момент ожидания ответа пользователь выбирает **другой** результат? После прихода ответа должен обновиться тот результат, по которому шёл запрос (по `searchResultId` из `dispatch`), а не текущий выбранный. Иначе пользователь увидит «прыжок» UI.
- Что если `updated.text === ''` И `updated.lastError === ''` (бэкенд вернул пустой результат без ошибки)? Кнопка остаётся видимой (`canExtractLyrics === true`), пользователь может повторить попытку. UX — «ничего не изменилось, попробуйте другую ссылку».
- Что если в момент ожидания ответа пользователь закрывает модалку? Запрос может прийти уже после закрытия → `this.currentResult = undefined` (line 303/319), присвоение в `searchResultsList[idx]` всё равно отработает (Vue не падает), но `currentResult` останется undefined → при следующем открытии модалки `currentSearchAsync` подгрузится, но если в `data` уже закешировано — может быть несогласованность. **Mitigation**: при закрытии (`closeSearchText`) сбрасывать `searchResultsList` в `[]` (уже есть в `closeSearchText`? — TBD в plan-фазе).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Кнопка «Получить текст по ссылке» MUST быть визуально расположена **под** кнопкой «Открыть на сайте» в одном контейнере, столбиком (одна под другой), без горизонтального размещения.
- **FR-002**: После успешного `extractLyricsBySearchResultId` (когда `updated.text !== ''`), textarea справа MUST немедленно отображать полученный текст — без закрытия и переоткрытия модалки.
- **FR-003**: После успешного `extractLyricsBySearchResultId`, соответствующий пункт в списке ссылок (`SearchTextResultsTable.vue`) MUST изменить цвет фона с серого (`gray`) на активный (`white`), в реальном времени, без переоткрытия модалки.
- **FR-004**: В момент выполнения запроса (`isExtractingLyrics === true`) кнопка MUST быть `disabled`, и её текст MUST показывать «Получаю текст...» (как сейчас). Повторные клики игнорируются.
- **FR-005**: Если backend возвращает `updated.text === ''` с `updated.lastError !== ''`, MUST показываться `window.alert` с сообщением об ошибке (как сейчас). UI возвращается в исходное состояние.
- **FR-006**: При успешном обновлении, `currentResult` MUST указывать на **обновлённый** объект (а не на старый), чтобы `resultText` computed показывал новый текст.
- **FR-007**: При успешном обновлении, элемент в `searchResultsList[idx]` MUST быть реактивно заменён новым объектом (через `Vue.set` / `this.$set`), чтобы `SearchTextResultsTable.vue` (prop `searchResultsList`) перерендерил строку с новым цветом фона.
- **FR-008**: Кнопка «Получить текст по ссылке» MUST скрываться (`v-if` или `disabled`), когда `canExtractLyrics === false` (т.е. выбран результат с уже полученным `text`). Текущая логика — оставить, проверить что при обновлении `text` она корректно скрывается.

### Key Entities *(include if feature involves data)*

- **SearchResult** (результат поиска): объект с полями `id`, `url`, `text` (извлечённый текст), `lastError`. Ключевые атрибуты для бага: `text` (пустой → серый, заполненный → белый), `lastError`.
- **SearchResultsList** (список результатов): массив `SearchResult` в `data()` компонента `SearchText.vue`. Передаётся как prop в `SearchTextResultsTable.vue`.
- **CurrentResult** (текущий выбранный): `searchResultsList[currentIdx]`, в `data()` `SearchText.vue`. Используется для `resultText` computed, `openResultLink`, `extractLyricsFromSelectedResult`.
- **CanExtractLyrics** (computed): `true`, если `currentResult` существует И `currentResult.text === '' || null`. Управляет видимостью кнопки.
- **IsExtractingLyrics** (data, boolean): флаг «идёт HTTP-запрос». Управляет disabled-состоянием кнопки.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% ручных проверок на dev-машине подтверждают, что после успешного нажатия «Получить текст по ссылке»:
  - textarea справа содержит полученный текст;
  - соответствующий пункт в списке слева перестал быть серым;
  - модалка остаётся открытой на всём протяжении.
- **SC-002**: 100% ручных проверок подтверждают, что кнопки «Открыть на сайте» и «Получить текст по ссылке» (когда обе доступны) визуально расположены столбиком в одном контейнере, одинаковой ширины, без смещений.
- **SC-003**: 0 регрессий в существующем поведении:
  - Disabled-состояние кнопки во время запроса (FR-004) — работает как раньше.
  - `window.alert` при ошибке (FR-005) — работает как раньше.
  - Кнопка скрывается при `canExtractLyrics === false` (FR-008) — работает как раньше.
- **SC-004**: Тест race-condition: если администратор выбирает другой результат во время запроса, после прихода ответа обновляется **тот** результат, по которому шёл запрос (по `searchResultId`), а не текущий выбранный.

## Assumptions

- **Баг-1 (textarea не обновляется)**: подтверждённая гипотеза — `<textarea class="result-text" v-text="resultText" />` в `SearchText.vue:36`. В Vue2 `v-text` устанавливает `textContent`, но `<textarea>` хранит значение в `value`, не в `textContent`. Это известный footgun Vue2. **Фикс**: использовать `v-model="resultText"` (с правкой `resultText` → data prop + setter), либо прямую привязку `:value="resultText"`, либо ref + watch. Конкретное решение — в plan-фазе через чтение кода.
- **Баг-2 (пункт не перестаёт быть серым)**: подтверждённая гипотеза — `this.$set(this.searchResultsList, idx, updated)` уже делается (line 246), но либо prop `searchResultsList` не реактивно пробрасывает изменения в дочерний `SearchTextResultsTable`, либо `currentId` в дочернем компоненте не обновляется. **Фикс**: проверить, что prop-массив обновляется (Vue2 должен реагировать на `$set`), при необходимости — `v-if="searchAsyncId"` с key или явный re-mount. Конкретное решение — в plan-фазе.
- **Текущая логика `extractLyricsFromSelectedResult` (lines 236-258) сохраняется**: dispatch `extractLyricsBySearchResultId`, обработка `updated`, обновление массива через `$set`, обработка ошибок через `try/catch`. Фикс не должен менять backend-контракт (OP#51 — чисто UI/UX).
- **CSS-фикс для расположения кнопок**: текущие `.group-button` имеют `width: 500px` (line 504), что делает их не inline. Если `.st-body-column-2` имеет `display: block` (по умолчанию), они **уже** идут столбиком. Но в задаче сказано «должна быть ПОД», значит текущий рендер визуально не устраивает (возможно, `display: flex` без `flex-direction: column`). Конкретное CSS-решение — в plan-фазе.
- **Задача не затрагивает backend** (`karaoke-app`/`karaoke-web`). Фикс целиком на клиенте (`webvue3/src/components/Songs/edit/SearchText.vue` + возможно `SearchTextResultsTable.vue`).
- **Задача не затрагивает `SubsEdit.vue`**: несмотря на название в OP#51, модалка реализована в `SearchText.vue`. `SubsEdit.vue` лишь импортирует `<search-text>` и открывает/закрывает его через `isSearchTextVisible`. Если в plan-фазе выяснится, что нужно поправить и `SubsEdit.vue` (например, сброс состояния при закрытии), это будет отражено.
- **Per-feature документ** (`docs/features/search-text-extract-btn.md`) создаётся в plan-фазе согласно Constitution FR-009.

## Открытые вопросы

После предварительного код-ревью потенциальные вопросы, которые могут потребовать уточнения в plan-фазе:

- Как именно Vue2 реагирует на `$set` для элемента массива, переданного как prop? Достаточно ли для ре-рендера `SearchTextResultsTable`?
- Что должна делать кнопка после успешного извлечения: скрываться (`v-if`) или оставаться видимой, но disabled? Текущая логика — скрывается через `v-if`. Проверить, что это UX-корректно.
- При закрытии модалки во время выполнения запроса — нужно ли отменять запрос (AbortController)? Текущая логика не отменяет. **Если упадёт с ошибкой после закрытия — будет `window.alert` после закрытия, что плохо**. Это отдельный риск; решается в plan-фазе.

Эти вопросы — не блокеры для спецификации; они разрешаются при чтении кода и тестировании.
