## 1. Препятствия

| Что | Нужно |
|---|---|
| Флаг фичи | `songDeleteEnabled=true` в файле свойств `/sm-karaoke/system/Karaoke.properties` (либо через `/api/properties/setproperty`); по умолчанию `false` |
| Миграции | `58_news_song_id_on_delete_set_null.sql`, `59_song_name_history.sql`, `60_song_cleanup_journal.sql` — применены на LOCAL и PROD |
| Тестовая песня | запись в LOCAL `tbl_songs` с полным набором артефактов: файлы в корне папки альбома и в `hdemucs_mmi/`, `done_files/`, `done_chords/`, `sheetsage/`, `symlink_mp4/`; mp3-стемы в обоих MinIO |
| Соседняя песня | запись в том же альбоме с похожим именем (проверка «чужого не удаляем») |
| Доступ к admin-машине | `docker logs -f karaoke-app`, `/sm-karaoke` на диске |


### Проверка состояния БД (LOCAL и SERVER)

SERVER-БД доступна с 2026-11-12 (починка туннеля и allow-list, KARAOKE-407
закрыта) — проверять нужно **обе** базы: FR-001 требует удаления из рабочей и
из серверной базы, FR-045 — честного ответа при недоступности серверной.

```bash
# LOCAL (admin-машина)
psql -d karaoke -c "SELECT id, song_name FROM tbl_songs WHERE id = <ID>;"
psql -d karaoke -c "SELECT id, song_id FROM tbl_news WHERE song_id = <ID>;"
psql -d karaoke -c "SELECT count(*) FROM tbl_song_assignment_drafts d
                     LEFT JOIN tbl_song_assignments a ON a.id = d.assignment_id
                    WHERE a.id IS NULL;"
psql -d karaoke -c "SELECT run_id, kind, result, reason, path_or_key
                     FROM tbl_song_cleanup_entries WHERE run_id = <RUN_ID>
                     ORDER BY id;"

# SERVER (прод-БД; доступ — прямое соединение Connection.remote(), порт 5433)
psql -h 188.127.240.124 -p 5433 -U postgres -d karaoke \
  -c "SELECT id, song_name FROM tbl_songs WHERE id = <ID>;"

  -c "SELECT id, song_id FROM tbl_news WHERE song_id = <ID>;"

  -c "SELECT id FROM tbl_songs_sync WHERE id = <ID>;"
```

## 3. Сценарии приёмки по требованиям

### US1 / FR-001…FR-009 — администратор удаляет песню

| # | Шаг | Ожидание | Требование |
|---|---|---|---|
| 1.1 | Открыть карточку песни, нажать «Удалить песню» | В окне подтверждения видны: число файлов, объём в МБ, число объектов в каждом хранилище, отдельная строка про альбом | FR-023, FR-024, FR-025 |
| 1.2 | Подтвердить | Ответ `status = deleted`; карточка закрывается; песня пропала из списка | FR-001, FR-003 |
| 1.3 | Проверить БД **в обеих базах** | В LOCAL и в SERVER: в `tbl_songs` строки нет; в `tbl_news` строка есть, но `song_id IS NULL`; в `tbl_song_authors` строки нет (CASCADE); в SERVER удалена и строка `tbl_songs_sync` | FR-001, FR-002, FR-009, FR-045 |
| 1.4 | Проверить `tbl_song_assignments`, `tbl_song_assignment_drafts`, `tbl_site_playlist_items`, `tbl_song_share_links` | Связанных строк нет | FR-005 |
| 1.5 | Проверить `tbl_listening_history`, `tbl_search_results`, `tbl_search_async` | Связанных строк нет | FR-006 |
| 1.6 | Проверить `tbl_events` | Строк с `song_id = <ID>` нет; строки с `song_id = 0` (без привязки) **на месте** | FR-007 |
| 1.7 | Проверить потомков (`audio_parent_id`) | У потомков `audio_parent_id IS NULL`, сами потомки на месте | FR-008 |
| 1.8 | Дождаться фоновой уборки | На диске не осталось файлов песни; в обоих MinIO не осталось её объектов | FR-010, FR-013, SC-001 |
| 1.9 | Проверить обложки | Обложка альбома и картинка автора на месте (если альбом не удалён) | FR-014 |
| 1.10 | Проверить битые симлинки | Симлинки на удалённые цели удалены | FR-015 |
| 1.11 | Проверить неопознанный файл | Файл на месте, в журнале `result = KEPT`, `reason = not_recognized` | FR-016 |
| 1.12 | Проверить соседнюю песню с похожим именем | Её файлы и объекты на месте | FR-011, FR-046, SC-008 |
| 1.13 | Открыть журнал уборки | По каждому удалённому объекту видны путь/ключ, размер, результат, дата, инициатор, id прогона | FR-035, SC-009 |

### US2 / FR-018…FR-022 — каскад на альбом

| # | Шаг | Ожидание | Требование |
|---|---|---|---|
| 2.1 | Удалить последнюю песню альбома (в папке только её файлы) | Запись `tbl_albums` удалена; запись `tbl_pictures` альбома удалена; обложка и превью альбома удалены в обоих MinIO; папка альбома удалена | FR-018, FR-019, FR-020 |
| 2.2 | Удалить последнюю песню альбома-«близнеца» (в папке лежат файлы живых песен) | Запись альбома удалена; **папка осталась**, её содержимое цело | FR-021, FR-022 |
| 2.3 | Удалить не последнюю песню альбома | Альбом остался целиком: запись, картинка, папка | FR-018 |
| 2.4 | Проверить папку автора | Папка автора не удалена | Out of scope карты |

### US3 / FR-029…FR-038 — фоновая уборка, повторы, честный остаток

| # | Шаг | Ожидание | Требование |
|---|---|---|---|
| 3.1 | Удалить песню и следить за очередью | Задание типа `SONG_DELETE_CLEANUP` в lane `-1`; интерфейс не блокируется | FR-029 |
| 3.2 | Перезапустить `karaoke-app` в середине уборки | После рестарта задание вернулось в `WAITING` и уборка продолжилась | FR-030 |
| 3.3 | Сделать хранилище недоступным на середине | Повторы с нарастающими паузами (до 5 попыток), затем остаток в журнале; статус прогона `PARTIAL`; в админке видны остаток и кнопка «добрать» | FR-032, FR-033, FR-036 |

| 3.5 | Проверить порядок шагов в журнале | Записи идут: диск → хранилища → альбом → папка альбома | FR-031 |
| 3.6 | Проверить кеш хранилища после удаления объектов | `tbl_storage_metadata_cache` приведён в соответствие (объекта нет) | FR-037 |
| 3.7 | Проверить `songs_history.txt`, `audit_log`, старые записи кеша | Не изменены | FR-038 |

### US4 / FR-039…FR-043 — разовая уборка

## 4. Краевые случаи (13 edge cases спеки)

| # | Сценарий | Ожидание | Требование |
|---|---|---|---|
| E-01 | Над песней идёт фоновая обработка | Удаление отклонено, `409 process_running`, понятное сообщение | FR-004 |
| E-02 | Песня уже удалена, повторный вызов | `200 status = already_deleted`, не ошибка | FR-002 |
| E-03 | Песня-родитель с живыми потомками | Удаление разрешено; в подтверждении видно число потомков; у потомков `audio_parent_id` обнулён | FR-008, FR-026 |
| E-04 | Объект есть только в одном хранилище | Удаление по каждому хранилищу отдельно; отсутствие в другом — не ошибка | FR-013, edge case спеки |
| E-05 | Объект под старым именем песни | Удалён вместе с песней (через `tbl_song_name_history`) | FR-013 |
| E-06 | В папке альбома файл, похожий на артефакт удалённой песни, но совпадающий с именем живой | Не удалён | FR-011 |
| E-07 | Файл не опознан ни по одному правилу | Остался на месте, в журнале «оставлено» | FR-016 |
| E-08 | Хранилище недоступно в середине уборки | Повторы с нарастающими паузами, затем остаток в журнале | FR-032, FR-033 |
| E-09 | Файл занят другим процессом | Удаление не выполнено, причина в журнале (`FAILED`, `reason = file_busy`) | edge case спеки |
| E-10 | Новости песни в ленте | Новость осталась, привязка обнулена | FR-009 |
| E-11 | Публичная страница удалённой песни | Отвечает как раньше (пустой ответ) — поведение публичной части не менялось | FR-044, SC-010 |
| E-12 | Уже выданные ссылки на песню | Сервер отзывает их сам (строки `tbl_song_share_links` удалены) | edge case спеки |
| E-13 | Альбом-«близнец» | Запись-сирота удалена, папка осталась (в ней файлы живых песен) | FR-022 |

|---|---|---|
| SC-001 | Обход диска + листинг обоих MinIO после уборки: ни одного артефакта песни (включая старые имена) | 1.8, 3.5 |

| SC-009 | Поиск по журналу по `run_id`; проверка, что журнал на диске переживает рестарт приложения | 1.13, 3.2 |
| SC-010 | Сравнение публичного поведения до/после: ни одно публичное наблюдаемое поведение не изменилось | E-11 |

## 6. Проверка обратной совместимости миграций

| Сценарий | Ожидание |
|---|---|
| Старый код (без фичи) при новой схеме | `DELETE FROM tbl_songs` для песни с новостью проходит; новость остаётся с `song_id IS NULL`; метка `tbl_song_news_announced` удаляется каскадом |
| Новый код при старой схеме (FK `NO ACTION`) | Эндпоинт возвращает `500 db_error` с текстом FK-ошибки; песня остаётся в базе; **ложного успеха нет** |
| Откат флага `songDeleteEnabled=false` | Эндпоинты фичи отвечают `503 song_delete_disabled`; старый `POST /api/song/delete` — по решению лида: либо отключается целиком, либо возвращает явную ошибку (не «пустой 200») |
| Старый вызывающий `Song.deleteFromDb` | Сигнатура изменилась — 4 вызывающих (`Utils.kt`, `ApiController.kt`, `MainController.kt`, `SyncTarget.kt`) обновлены в том же PR |
