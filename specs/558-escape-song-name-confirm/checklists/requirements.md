## Notes

- Охват: **43 места** сборки текста подтверждения из пользовательских данных в **8 семействах** значений + 1 sink (`CustomConfirm.vue:5–6`). Инвентарь получен полным перебором всех блоков `customConfirmParams` в `webvue3` (75 точек интерполяции: 43 с пользовательскими данными, 32 без них). Номера строк сверены с текущим `master` (`e8170e06`) — совпадают со снимком аудита `1977838a`.
- Спецификация описывает **наблюдаемое** последствие дефекта: «одна кнопка в карточке песни исполняет чужой код в сессии администратора» → «имя показано как текст, ничего не выполняется». Механизм экранирования оставлен открытым (варианты a/b/c в разделе «Решения, требующие владельца»), потому что он определяет, вернётся ли дефект в новом месте.
- Ключевые решения, ожидающие владельца: (1) глубина защиты — рекомендуется гибрид «экранирование при сборке + безопасный режим по умолчанию в общем компоненте»; (2) проверка формата e-mail при публичной регистрации — рекомендуется вынести в отдельную задачу.
- Тяжесть дефекта в спецификации обоснована фактами: административные API не требуют проверки прав, поэтому исполнение кода в сессии администратора даёт доступ к удалению песен и запуску процессов.
