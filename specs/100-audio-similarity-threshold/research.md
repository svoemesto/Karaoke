# Research: Повышение порога аудио-похожести и демотация статуса при импорте из папки

**Branch**: `100-audio-similarity-threshold` | **Date**: 2026-07-31

> Все NEEDS CLARIFICATION разрешены на стадии `/speckit.clarify` (см. `spec.md` → `## Clarifications`). 
> Данный документ фиксирует технические решения, подтверждённые чтением кода, и их обоснование.

## R1. Порог `AUDIO_PARENT_THRESHOLD`: единая константа для трёх путей

**Decision**: Изменить значение константы `AUDIO_PARENT_THRESHOLD` в `Utils.kt:4612` с `85` на `95`. Не вводить отдельных порогов per-путь.

**Rationale**: Константа определена один раз и используется в `findAudioParentByWaveform` (`Utils.kt:4677`: `best.similarityPercent < AUDIO_PARENT_THRESHOLD`). Эту функцию вызывают все три пути:
1. Импорт из папки — `ApiController.kt:5271` (`doCreateFromFolder`).
2. Пакетная `customFunction` — `Utils.kt:189`.
3. Ручной `/song/findaudioparent` — `ApiController.kt:763`.

Одна правка покрывает все три. Сравнение строгое `<`, поэтому `95` принимается включительно (`>= 95`), что соответствует FR-002 (включительность) и сохраняет прежнюю семантику (`< 85` → reject, `>= 85` → accept).

**Alternatives considered**:
- *Per-путь пороги* (разные константы для импорта/customFunction/findaudioparent) — отвергнуты: пользователь явно сказал «повысить порог похожести аудио с 85 до 95» без оговорок; раздробленность нарушит консистентность и усложнит поддержку. Подтверждено в Clarification (вариант C выбран, но он касался `autoassignoriginalall`, не этих трёх путей — для них консистентность безусловно).
- *Параметризовать все три пути* — отвергнуто: `findAudioParentByWaveform` не имеет параметра `threshold` (в отличие от `autoAssignOriginalByWaveform`); добавление параметра + прокидывание его через эндпоинты — избыточный scope при явной просьбе «повысить порог».

## R2. Дефолт `autoAssignOriginalByWaveform` / `/songs/autoassignoriginalall`: 85 → 95, параметр остаётся

**Decision**: Поднять дефолт параметра `threshold: Int = 85` → `95` в двух местах:
- `Utils.kt:4536` — `fun autoAssignOriginalByWaveform(..., threshold: Int = 85)`.
- `ApiController.kt:4878` — `@RequestParam(required = false) threshold: Int = 85`.

Параметр остаётся параметризованным: куратор MAY передать `?threshold=<N>` для иного значения.

**Rationale**: Решение C из Clarification. `autoassignoriginalall` — другой механизм (работает по песням статуса 1 с `root_id<>0`, переводит в статус 2, не 6, не вызывается при импорте из папки). Демотация статуса 6→5 к нему НЕ применяется (он не использует `applyAudioParentMarkers`). Повышение дефолта порога — для консистентности «строгий критерий аудио-сходства во всех механизмах».

**Alternatives considered**:
- *Вариант A* (только `AUDIO_PARENT_THRESHOLD`, `autoassignoriginalall` оставить на 85) — отвергнут пользователем в Clarification.
- *Вариант B* (оба порога hard-85→95, убрать параметризацию `autoassignoriginalall`) — отвергнут: ломает существующий workflow куратора, который может намеренно гонять `autoassignoriginalall` с пониженным порогом для exploratory-привязки; параметризация — explicit opt-in.

## R3. Демотация статуса 6 → 5 в `applyAudioParentMarkers`

**Decision**: В `Utils.kt:4406` заменить `settings.fields[SongField.ID_STATUS] = "6"` на `"5"`. Функция `applyAudioParentMarkers` — единственное место, где аудио-родитель выставляет статус 6; иных правок статуса не требуется.

**Rationale**: Пользователь явно: «если для песни найден аудио-родитель и она переводилась в статус 6, то теперь переводить её в статус 5». Статус 5 = «маркеры проверены» (specs/022-song-status-lifecycle), предфинальная ручная вычитка перед публикацией (статус 6 = READY). Копирование текста/маркеров из готового (≥6) аудио-родителя по акустической сверке ≥95% — не гарантия идеального таймлайна, поэтому куратор должен подтвердить результат. Копирование и сдвиг `shiftMarkersAndFixEnd` сохраняются.

**Blast radius** (подтверждено `codegraph_explore` + grep): `applyAudioParentMarkers` имеет ровно одного caller'а — `ApiController.kt:5286` (`doCreateFromFolder`). Иные выставления статуса 6 (ручное кураторское продвижение в `SongEditorController`, `Song.kt:5014` переход через `idStatus >= 6`-порог при публикации, и т.д.) к аудио-родителю не относятся и NOT затрагиваются (FR-008).

**Alternatives considered**:
- *Статус 2 (TEXT_CHECK)* вместо 5 — отвергнут: 2 = «текст проверен (орфография)», а у нас уже скопированы и текст, и маркеры; 2 означало бы потерю прогресса (маркеры уже есть, но статус говорит «только текст»). 5 = «маркеры проверены» — ближайший осмысленный шаг перед финалом.
- *Не менять статус, оставить 6* — отвергнут: это и есть исходная жалоба пользователя.
- *Оставить копирование, но статус НЕ повышать (оставить 1 от обычного родителя)* — отвергнут: текст/маркеры уже скопированы, статус 1 = «текст найден» лгал бы о состоянии.

## R4. KDoc и человекочитаемые строки: обновить упоминания «85%» и «статус 6»

**Decision**: Обновить KDoc-комментарии и интерполированные `reason`-строки, упоминающие устаревшие значения. Конкретные точки (по grep `85\s*%|idStatus.*6`):

| Файл:строка | Что меняется |
|---|---|
| `Utils.kt:4384-4394` (KDoc `applyAudioParentMarkers`) | «статус выставляется в 6 (READY)» → «в 5 (маркеры проверены)»; обоснование «копирование уже полностью проверенного контента … осознанный обход промежуточных ручных проверок» переформулировать под 5 (теперь это НЕ обход, а осознанная остановка на предфинальной вычитке). |
| `Utils.kt:4520-4530` (KDoc `autoAssignOriginalByWaveform`) | «Порог по умолчанию — 85 %» → «95 %». |
| `Utils.kt:4611` (KDoc `AUDIO_PARENT_THRESHOLD`) | «Порог схожести (%), начиная с которого …» — значение 85 уже в коде константы; KDoc ссылается на `findAudioParentByWaveform`, текст «85%» убрать/обновить. |
| `Utils.kt:4635` (KDoc `findAudioParentByWaveform`) | «Порог отбора - AUDIO_PARENT_THRESHOLD (85%).» → «(95%).» |
| `ApiController.kt:752-754` (комментарий `findAudioParent`) | «порог 85%, см. AUDIO_PARENT_THRESHOLD» → «95%». |
| `ApiController.kt:5266-5269` (комментарий в `doCreateFromFolder`) | «Если найден и уже полностью "готов" (idStatus >= 6) - его маркеры точнее/полнее, применяем их со сдвигом и переводим песню в статус 6» → «…в статус 5 (предфинальная вычитка)». |
| `ApiController.kt:4868-4873` (KDoc `autoAssignOriginalAll`) | «порог threshold%» — значение не зашито в текст, но дефолт `@RequestParam ... = 85` меняется на 95 (см. R2); KDoc при необходимости уточнить «по умолчанию 95%». |

**Человекочитаемые `reason`** в `findAudioParentByWaveform` (`Utils.kt:4688`, `Utils.kt:4725`) и `autoAssignOriginalByWaveform` (`Utils.kt:4569`) уже интерполируют порог из `AUDIO_PARENT_THRESHOLD` / `threshold` (`"$AUDIO_PARENT_THRESHOLD%"`, `"$threshold%"`) — хардкода «85» в строках нет, после правки констант/дефолтов текст автоматически станет «95%». Проверяется ревью.

**Rationale**: FR-006 конституции (KDoc + `@see`) + FR-007 (CI ktlint/KDoc-coverage). Устаревший «85%»/«статус 6» в KDoc = ложная документация для следующего разработчика + потенциальный fail KDoc-coverage, если парсер сочтёт комментарий несоответствующим коду.

**Alternatives considered**:
- *Не трогать KDoc* — отвергнуто: violates FR-006, вводит в заблуждение.
- *Полный рефакторинг KDoc аудио-родителя* — отвергнут как out-of-scope; обновляются только точки, прямо упоминающие 85%/6.

## R5. Миграция БД и пересчёт уже назначенных аудио-родителей — НЕ требуется

**Decision**: Не выполнять миграцию; не пересчитывать `audio_parent_id`/`audio_similarity_percent` для уже привязанных песен.

**Rationale**: Значение порога живёт в коде (`AUDIO_PARENT_THRESHOLD`), не в схеме. Уже назначенные аудио-родители имеют `audio_similarity_percent` в диапазоне 85–100 (по старому порогу); некоторые из них формально ниже нового порога 95, но их `audio_parent_id` остаётся в силе — исторический факт сверки на момент импорта. Принудительный пересчёт потребовал бы `customFunction` по всей БД (тяжёлая акустическая сверка, минуты-часы на 18k+ песен) — это отдельная ручная операция куратора, в scope данной фичи не входит (Assumptions spec.md).

**Alternatives considered**:
- *Сбросить `audio_parent_id` для песен с `audio_similarity_percent` < 95* — отвергнуто: ломает уже работающие связи, потенциально скрывает валидные родительские пары (85–94% могли быть корректны для конкретного аудио). Тихий data-loss без запроса пользователя.
- *Фоновый пересчёт всех аудио-родителей при старте приложения* — отвергнут: тяжёлая операция без явного запроса, violates «не удивлять пользователя».

## R6. Влияние на фронт (`webvue3`, `karaoke-public`) — нет

**Decision**: Фронт не трогается.

**Rationale**: 
- Поле статуса в `SongEdit.vue` уже отображает 0–6 с названиями (specs/022-song-status-lifecycle, User Story 2). Статус 5 — валидное значение, UI его уже показывает корректно.
- `audio_similarity_percent` и `audio_parent_id` отображаются как есть (число/ссылка); смена порога не меняет формат.
- `/songs/autoassignoriginalall` вызывается из админки с явным `?threshold=` только если куратор решил его переопределить; дефолт 95 подхватится автоматически.

**Alternatives considered**: нет — фронт уже готов.

## R7. Проверка (testing) — ручная, через `quickstart.md`

**Decision**: Проверка через ручные сценарии в `quickstart.md`: (а) импорт папки с песней, у которой есть готовый (≥6) аудио-родитель с ≥95% → статус 5; (б) импорт с кандидатом 90% → аудио-родитель не назначается; (в) вызов `/songs/autoassignoriginalall` без `?threshold=` → дефолт 95; (г) grep логов/SSE на «95%» и отсутствие «85%».

**Rationale**: Конституция: «Тесты: в CI нет … проверка делается пользователем вручную или в production-like окружении». CI проверяет только ktlint/KDoc-coverage/ESLint (FR-007).

**Alternatives considered**:
- *Написать автотест* — отвергнут: существующие тесты `karaoke-app/src/test` интеграционные, `@Disabled`, требуют сеть/браузер/credentials; новый автотест для этой фичи требовал бы мок `WaveformCompare` + БД, что несоразмерно объёму изменения (3 правки констант).
