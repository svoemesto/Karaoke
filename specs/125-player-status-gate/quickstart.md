# Quickstart: проверка доступности плеера при статусе ≥4

Ручная проверка в браузере (в CI для `webvue3` тестов нет, см.
`.specify/memory/constitution.md`, раздел «Рабочий процесс» → «Тесты»).

## Prerequisites

- Локальный стек поднят (`webvue3` admin SPA доступен, backend отвечает).
- Доступ к таблице «Песни» в админке.
- Хотя бы по одной песне на статусах 3, 4 и 6 (или возможность быстро
  переключить статус конкретной песни через SongEdit → группа кнопок статуса).

## Steps

1. Открыть админку → раздел «Песни» (`SongsTable.vue`).
2. Найти/подготовить песню со статусом **3** (TEXT_WORDS_VERIFIED).
   - **Expected**: иконка плеера в строке — серая, неактивная (disabled),
     title при наведении — «Плеер недоступен (статус < 4)».
3. Найти/подготовить песню со статусом **4** (MARKERS_CREATED).
   - **Expected**: иконка плеера — зелёная активная (кликабельная).
   - Кликнуть по иконке → открывается `/player/{id}` в новой вкладке,
     плеер загружается и воспроизводит песню.
4. Найти/подготовить песню со статусом **6** (READY).
   - **Expected**: иконка плеера активна, как и раньше (регрессий нет).
5. На той же странице проверить колонку DEMO-плеера (`playerDemo`) для песни
   со статусом 4-5.
   - **Expected**: иконка DEMO-плеера остаётся неактивной (порог `>= 6` не
     менялся) — регрессия здесь означала бы, что изменение задело не тот
     компонент.
6. Открыть карточку редактирования песни (SongEdit) для песни любого статуса
   (включая 0).
   - **Expected**: кнопка «▶ Открыть плеер» в шапке карточки по-прежнему
     кликабельна независимо от статуса — поведение не изменилось.

## Validates

- FR-001, FR-002, FR-003, FR-004, FR-005 (spec.md)
- SC-001, SC-002 (spec.md)
