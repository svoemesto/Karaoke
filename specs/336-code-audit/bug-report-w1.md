## S1 — критично

### BR-011. Публичный `POST /changerecords` исполняет присланный SQL
`karaoke-web/.../controllers/MainController.kt:303–366` (SEC). Endpoint не защищён ни `SecurityConfig`, ни `SiteAuthInterceptor`; единственная проверка — расшифровка фиксированной строки. При незаданном `CRYPTO_AES_KEY` используется захардкоженный legacy-ключ из репозитория (в `deploy/` переменная не задаётся). Таблицы, `SET`-текст и `WHERE id` приходят из запроса. Nginx `location /changerecords` публичен. Итог: анонимный канал выполнения произвольного SQL. Требуется проверка env контейнера — `эмпирика: требует согласия`.

### BR-019. Публичная запись настроек и утечка серверного ключа капчи
`karaoke-web/.../controllers/PublicSettingsWebController.kt:50–53, 140–158` (SEC). Весь `/api/properties/**` анонимен: `GET /digest` и `/getproperty` отдают `tbl_public_settings` вместе с `yandexSmartCaptchaServerKey`, `POST /setproperty` пишет любой ключ в прод-БД (kill-switch, ключи капчи). Публичный периметр, обход не нужен.

### BR-018. Обход оплаты «скрытым жестом» в плеере
`karaoke-web/.../controllers/PublicPlayerController.kt:99–106` (SEC). Три анонимных `POST /api/public/events` (`clickToLink/songMeta/key/shiftKey`) возвращают в `meta` полный токен плеера (TTL 30 мин, `clientId` произвольный); `authorized()` принимает его как достаточное основание, `stemResponse` отдаёт полный стем. Воспроизводится без оплаты, премиума и эфира. Если жест задуман как owner-only — всё равно нельзя минтить полный токен анониму.

## S2 — серьёзно (13)

- **BR-001** — VK ID OAuth: оба endpoint'а анонимны, токен произвольного VK-пользователя уходит на admin-API по plain HTTP; при сетевой достижимости с прода — S1.
- **BR-002** — тело ответа VK с `access_token` пишется в INFO-лог.
- **BR-003** — rate-limit берёт первый `X-Forwarded-For`, nginx дописывает реальный IP в конец → обход лимита; зеркало — IP-allowlist debug-endpoint'а.
- **BR-004** — singleton `RateLimitInterceptor` дважды мутируется: оба endpoint'а живут с одним именем и лимитом, bucket'ы не разделены.
- **BR-005** — `TYPE_NTH_FREE` считает ordinal как `countPaid+1` без блокировки: залп на границе акции даёт K бесплатных подписок.
- **BR-006** — `EventsBuffer` закрывает ThreadLocal-соединение → новый физический коннект на каждое событие.
- **BR-012** — sync-батч `/changerecords` без транзакции: частичное применение.
- **BR-013** — `GET /api/public/song/{id}` без `onlyPublishedFor`/SKIP: аноним получает полный текст неопубликованной песни.
- **BR-014** — checkout удаляет корзину до создания платежа: при отказе — пустая корзина и висящие PENDING; идемпотентности нет.
- **BR-015** — публичные `/news?size=` и stream-metrics без ограничения размера: один запрос раздувает память/БД.
- **BR-020** — вебхук ставит PAID до fulfillment вне транзакции: ретрай теряет оплаченный период, параллельные ретраи продлевают дважды.
- **BR-021** — повторный `create` подписки переиспользует заказ только при `pending`: после `succeeded`/`null` создаётся второй платёж.
- **BR-023** — редактор игнорирует `null` от `createDbInstance` и отвечает 200: конкурентное сохранение теряет правку.
