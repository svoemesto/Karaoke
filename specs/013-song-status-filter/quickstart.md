# Quickstart: проверка фильтра статуса на публичных поверхностях

Проверка делается вручную (в CI автотестов на этот слой нет, см.
`plan.md` → Technical Context → Testing). Использовать локальный
sandbox-стек (`deploy/do.sh`, все сервисы уже подняты — см. память проекта
`project_local_docker_setup`), не прод.

## Предусловия

- Локальный стек поднят: `db`, `karaoke-web`, `webvue3`, `karaoke-public`.
- В БД есть (или создан вручную через админку) хотя бы один автор с двумя
  песнями: одна с `id_status < 3`, другая с `id_status >= 3`.

## Сценарий 1 — закрома автора (публичный сайт)

1. Открыть `karaoke-public` → страница автора (закрома), для автора из
   предусловий.
2. **Ожидаемо**: видна только песня со статусом >= 3; песня со статусом < 3
   отсутствует в альбоме.
3. Если у автора после фильтрации не осталось ни одной песни с статусом >=
   3 — автор не должен отображаться в общем списке закромов вовсе.

## Сценарий 2 — спецзаказная плашка

1. Убедиться, что хотя бы один спецзаказной автор (`is_special_order=true`)
   имеет песню со статусом < 3.
2. Открыть плашку «Отдельные песни разных авторов».
3. **Ожидаемо**: песня со статусом < 3 не отображается, остальные (>= 3) —
   отображаются как раньше.

## Сценарий 3 — поиск

1. В поиске на `karaoke-public` ввести название/автора/фрагмент текста,
   совпадающий с песней, у которой `id_status < 3`.
2. **Ожидаемо**: песня не появляется в выдаче.
3. Повторить запрос для песни с `id_status >= 3` с тем же критерием —
   песня появляется.

## Сценарий 4 — legacy Thymeleaf-страницы `karaoke-web`

1. Открыть `GET /zakroma?author=<автор из предусловий>` напрямую (минуя
   `karaoke-public`).
2. Открыть `GET /filter?songName=<название песни со статусом < 3>`.
3. **Ожидаемо**: то же поведение, что в сценариях 1 и 3 — песня со
   статусом < 3 не видна.

## Сценарий 5 — regression guard: админка не пострадала

1. Открыть `webvue3` → таблица песен (или карточку автора/альбома) для
   автора из предусловий.
2. **Ожидаемо**: обе песни (со статусом < 3 и >= 3) видны и редактируемы,
   как раньше.
3. Если в `karaoke-app` доступен собственный (admin-only,
   `MainController.zakroma` из `karaoke-app`) `/zakroma` — тоже должен
   показывать обе песни без фильтрации.

## Сценарий 6 — смена статуса "в реальном времени"

1. Взять песню со статусом < 3 из предусловий, в админке поднять её
   `id_status` до 3 или выше.
2. Повторно открыть закрома/выполнить тот же поиск (без пересборки/рестарта
   сервисов).
3. **Ожидаемо**: песня сразу появляется в результатах — без
   дополнительного кеша/задержки (листинг не кешируется, в отличие от
   `/api/public/stats`, который обновляется раз в час).

## Критерий готовности

Все 6 сценариев проходят так, как описано выше → фича соответствует SC-001…
SC-004 `spec.md`.
