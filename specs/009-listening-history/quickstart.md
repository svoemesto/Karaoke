# Quickstart: Валидация «Истории прослушиваний» (QW-13)

**Branch**: `009-listening-history` | **Phase**: 1 | **Date**: 2026-07-25

## Предусловия

- `karaoke-app`/`karaoke-web`/`karaoke-public` собраны и запущены локально.
- Тестовый зарегистрированный пользователь с доступом к `/song?id=...` (для
  генерации событий прослушивания).

## 0. Миграция и recordhash (research.md Decision 2-3, Constitution Principle II/III)

- Применить `deploy/karaoke-db/27_listening_history.sql` вручную на LOCAL и
  на PROD (как все миграции этого проекта — `AGENTS.md`).
- Проверить, что `tbl_listening_history` появилась с триггерами
  `update_recordhash_listening_history_trigger` и
  `update_last_updated_listening_history_trigger`.
- В `webvue3` → «Синхронизация» новая сущность «История прослушиваний»
  появляется в списке автоматически (подхватывается `SyncRegistry.all`, без
  правок в `webvue3`) — все 8 флагов синхронизации по умолчанию выключены.

## 1. Появление записи в истории (FR-001, FR-002, US1, SC-001)

- Залогиниться, открыть 2-3 разные песни, дать плееру стартовать
  воспроизведение (событие `play` уходит на `trackPlay()` → апсерт в
  `tbl_listening_history`, **дополнительно** к обычной записи в `tbl_events`).
- Открыть раздел «История» (`/account/history`) — все прослушанные песни
  видны, отсортированы по `last_played_at` от самой недавней к более старой.
- Прослушать одну и ту же песню повторно — в истории не появляется вторая
  строка, `play_count` увеличивается, `last_played_at` обновляется (запись
  «поднимается» наверх списка).

## 2. Клик по записи (FR-003, Acceptance Scenario US1.3)

- Клик по записи в списке → переход на `/song?id=<songId>` этой песни.

## 3. Пустая история (FR-006, US2)

- Новый пользователь без прослушиваний открывает «Историю» → видит сообщение
  «Вы пока ничего не слушали» + CTA в каталог, не пустой список.

## 4. Недоступность анониму (FR-005, US3)

- Разлогиниться, открыть `/account/history` напрямую → `LoginRequired` (кнопки
  «Войти»/«Регистрация»), не ошибка и не пустая история.

## 5. Лимит записей (FR-004)

- Прослушать >100 разных песен (или проверить в коде лимит запроса) —
  список не растёт бесконечно, ограничен разумным числом.

## 6. Изоляция данных между пользователями (contracts/history-api.md)

- Пользователь A слушает песню X, пользователь B — не видит её в своей
  «Истории» (SQL-фильтр по `site_user_id`, не должен утекать между
  аккаунтами).

## 7. Ссылка из личного кабинета (FR-007)

- `/account` → карточка «📜 История прослушиваний» (или похожая иконка) ведёт
  на `/account/history`.

## 8. Производительность (SC-004)

- Открытие раздела с ~50-100 записями — без ощутимой задержки (один
  индексируемый по `site_user_id` запрос с `LIMIT`, без N+1).
