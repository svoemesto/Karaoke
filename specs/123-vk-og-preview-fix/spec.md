# Spec 123: Премиум-публикация ВК — превью через `attachments=photo`

## Проблема

03.08.2026 обнаружено: при автоматической публикации через бота (`POST /method/wall.post`) ВК **не формирует превью с обложкой** для постов про премиум-выпуски, несмотря на то что:

- nginx правильно проксирует User-Agent VK-парсера (`vkShare`, `vkim`, `VKBot`, `Mail\.RU_Bot`, `VKShareBot`) на endpoint `PublicOgSongController.kt` через `rewrite` в `location /song`.
- Endpoint `/api/public/og/song` возвращает HTML в трёх вариантах:
  1. Полный OG (`<meta property="og:image">` + `<meta property="og:title">` и т.д.).
  2. «Голый» с `<title>` + видимым `<img>` (старый формат, который работал **до 02.08.2026** для ручной публикации).
  3. «Голый» с `<title>` + видимым `<img>` + размер PNG 537×240 (после отката от 1200×630 JPEG).
- Endpoint `/api/public/song-vk-image/{id}` возвращает PNG 537×240 (54 КБ).
- При **ручной** публикации через UI VK превью появляется (подтверждено пользователем).

При **бот-публикации** (`/method/wall.post`) — сниппет НЕ создаётся в обоих вариантах HTML.

## Гипотезы (03.08.2026)

1. **Кэш VK** — VK кэширует URL и при бот-публикации не делает ре-парсинг. Если ранее URL был обработан без `og:image` — сниппет «залип» в пустом виде.
2. **User-Agent VK при бот-публикации** — VK при вызове `/method/wall.post` НЕ делает парсинг сам, а полагается на закэшированный snippet.
3. **Нестандартный User-Agent** — VK использует User-Agent, который не входит в наш regex (`vksharedatacrawler`, `VKSharedCrawler`, `VkCrawler`, `OkHttp`).
4. **Open Graph мета-теги не работают на VK.ru** — VK использует свою разметку (`<title>` + видимый `<img>`), но при бот-публикации это не работает по другим причинам.

## Решение

**Прикреплять обложку через VK API `attachments=photo<owner>_<id>`** — это **самое надёжное** решение, потому что:
- VK **не делает парсинг URL** для прикреплённых фото — берёт их прямо из API-параметра.
- Это работает **одинаково** для бот-публикации и ручной.
- Photo ID можно получить, загрузив картинку через `photos.getWallUploadServer` + `photos.saveWallPhoto` (но это требует прав `photos`, которые НЕ доступны с community-token).

### Альтернативы

**A. Получить user-token через Standalone-приложение** — но мы уже обнаружили, что VK с 2019 года блокирует OAuth для новых приложений (`Security Error` при попытке Authorization Code Flow без модерации).

**B. Использовать существующее `wall.post` с дополнительным параметром** — VK имеет параметры `attachments`, но только для прикреплённых `photo/video/audio/doc/poll`, не для URL. URL обрабатывается отдельно и зависит от парсинга.

**C. Использовать Open Graph с другого домена** — некоторые платформы (Twitter, Facebook) лучше работают с определёнными доменами. Но для VK это не должно влиять.

**D. Включить модерацию VK** — подать заявку через `https://oauth.vk.ru/` → «Модерация». Занимает 1-2 недели, не гарантирует одобрения.

### Что **точно** работает сейчас

| Способ | Работает? | Замечание |
|---|---|---|
| `wall.post` с текстом + URL (`vk.ru/song?id=NNN`) | ✅ Текст публикуется | ❌ Превью нет |
| `wall.post` с attachments `=video<owner>_<id>` | ❌ Требует user-token с правом `video` | (заблокировано политикой VK) |
| `wall.post` с attachments `=photo<owner>_<id>` | ❌ Требует user-token с правом `photos` | (заблокировано политикой VK) |
| Open Graph на сайте через nginx `rewrite` | ❌ Прекрасно работает для ручной публикации, но не для бот-публикации | |
| `wall.repost` через другие группы | ❓ Возможно, VK делает повторный парсинг при репосте | Стоит попробовать |

### Выбранный подход

**Получить user-token с правом `photos` через модерированное Standalone-приложение VK**, и тогда:
- Загружать обложку альбома через `photos.getWallUploadServer` + `photos.saveWallPhoto`.
- Прикреплять через `attachments=photo<owner>_<id>` при `wall.post`.
- VK сразу вставит превью-картинку (без парсинга URL).

### План реализации (TBD)

1. **Запросить модерацию VK** для Standalone-приложения (через `https://oauth.vk.ru/`):
   - Заявка от владельца группы `svoemestokaraoke` (лично).
   - С описанием: «Бот автоматической публикации премиум-выпусков песен на стене сообщества с обложкой альбома».
   - Модерация занимает 1-2 недели.

2. **После одобрения модерации**:
   - Получить user-token через Implicit Flow (`oauth.vk.ru/authorize?...&scope=photos,wall,video,offline`).
   - Сохранить в `Karaoke.properties` (новое свойство `vkUserAccessToken`).
   - Реализовать в `VkAutoPublishService`:
     - Перед `wall.post`: загрузить обложку альбома через `photos.getWallUploadServer` + `photos.saveWallPhoto`.
     - Прикрепить через `attachments=photo<owner>_<id>`.

3. **Если модерация отклонена**:
   - Вариант fallback: использовать `wall.repost` через публичные группы, которые ВК кэширует по-другому.
   - Вариант: прикреплять обложку как **документ** через `docs.getWallUploadServer` + `docs.save` (если у community-token есть права `docs`).
   - Вариант: попробовать опубликовать пост через `wall.edit` после `wall.post` — это **триггерит** повторный парсинг VK.
