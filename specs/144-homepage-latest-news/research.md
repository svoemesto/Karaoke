# Research: 144-homepage-latest-news

**Дата**: 2026-08-05
**Спека**: [spec.md](./spec.md)
**План**: [plan.md](./plan.md)

## Контекст

Фича — компактный блок «последние 5 новостей» на главной странице сайта (SPA `karaoke-public` + legacy Thymeleaf `karaoke-web/main.html`). Никаких новых полей/таблиц/миграций; никаких новых эндпоинтов. Все архитектурные решения зафиксированы на этапе спеки и этапе `/speckit.clarify`.

Все 8 принципов конституции пройдены, открытых `NEEDS CLARIFICATION` нет.

---

## Решения

### 1. Контракт эндпоинта — переиспользовать существующий `GET /api/public/news?page=0&size=5`

**Decision**: блок на главной использует существующий эндпоинт `GET /api/public/news?page=0&size=5` (без нового кода на бэкенде). Никаких новых контроллеров, никакого нового SQL.

**Rationale**:
- `News.loadPublished` уже реализует нужный фильтр/сортировку (`publish_at IS NOT NULL AND publish_at <= now()`, `ORDER BY publish_at DESC, id DESC`, `LIMIT 5`) — это «лёгкий путь» в существующем коде, проверенный на проде.
- `LIMIT 5` + индекс по `publish_at` (или деградированный seq-scan с ранним выходом) на объёме 19000+ записей даёт <300 мс (SC-002 спеки) — без нового кода.
- Один код-путь: блок на главной + пагинация ленты `/news` используют один и тот же метод бэкенда — нет риска дрейфа (разные определения «опубликованности» в разных местах).
- Не плодим эндпоинтов, не плодим DTO, не плодим тестов.

**Alternatives considered**:
- **Новый `GET /api/public/news/latest`** с фиксированным размером 5 — отвергнут: добавляет новый код без функционального выигрыша (существующий эндпоинт уже умеет `size=5`), плодит почву для дрейфа (например, в будущем кто-то изменит фильтр в `loadPublished`, а `latest` забудет синхронизировать).
- **Server-Sent Events** для автообновления блока без перезагрузки — отвергнут: добавляет сложности, не описано в спеке (FR-002 явно говорит «при следующем открытии/перезагрузке»), и решает несуществующую проблему (частота появления новостей — несколько в день, не реалтайм).

**Ссылка**: `karaoke-web/src/main/kotlin/com/svoemesto/karaokeweb/controllers/PublicNewsController.kt:30` — уже реализован, переиспользуется.

### 2. Фильтрация строк без `link`/`title` — на фронте

**Decision**: фронт (Vue computed для SPA, th:if для Thymeleaf) отбрасывает новости с пустым `link` или пустым/пробельным `title`. Бэкенд НЕ фильтрует (мы переиспользуем существующий эндпоинт, поведение которого уже зафиксировано).

**Rationale**:
- Требование FR-006 спеки: «правило «только осмысленные строки»».
- Фильтрация на фронте даёт мгновенный отклик при изменении правила (без миграции/перезапуска бэкенда).
- В текущей базе доля таких новостей ≈ 0 (авто-новости всегда имеют `link = "/song?id={id}"` и `title` = сформированный заголовок; ручные новости в `webvue3/NewsTable` админки требуют заполнения `title` и `link` для публикации), но правило нужно зафиксировать на случай ручного кривого ввода.

**Alternatives considered**:
- **Фильтрация на бэкенде (новый SQL в `News.loadPublished`)** — отвергнут: меняет контракт существующего эндпоинта, ломает пагинацию ленты `/news` (где сейчас такие новости видны с disabled-ссылкой или не показываются вообще — нужно отдельно проверять поведение существующего фронта ленты новостей).
- **Disabled-ссылка** — отвергнут на этапе спеки (FR-006 явно фиксирует «не показывать»).

### 3. Тихaя деградация при ошибке запроса

**Decision**: SPA-блок не рендерится при любой ошибке/таймауте/невалидном JSON; legacy Thymeleaf рендерит страницу со статусом 200 и блоком в эквиваленте пустого состояния.

**Rationale**:
- FR-013 + SC-007 спеки (выбор A из Clarifications).
- Текущий `HomeView.vue:44-62` уже использует `v-if="!isLoading"` + обработку ошибок через `try/catch` в `loadStats()` — паттерн «v-if есть данные — показываем, нет — не показываем» уже есть в кодовой базе. Применяем тот же подход к блоку новостей.
- Блокировать рендер всей главной (`v-if` на корневом `<div class="km-home">`) ради новостей — неприемлемо (остальная главная не зависит от новостей).

**Alternatives considered**:
- **Видимый фолбэк «Не удалось загрузить новости»** — отвергнут как худший UX.
- **Retry** — не описан в спеке, добавляет сложности.
- **Спиннер/лоадер** — отвергнут на этапе спеки.

### 4. Формат даты — нативный `Intl.DateTimeFormat`

**Decision**: `new Intl.DateTimeFormat('ru-RU', { day: '2-digit', month: '2-digit', year: 'numeric', hour: '2-digit', minute: '2-digit' }).format(new Date(publishAt))`. Для Thymeleaf — `#{formats.formatDate(...)}` через стандартный Spring + ICU Locale (или статический форматтер на стороне контроллера, передающий уже отформатированную строку).

**Rationale**:
- Никаких новых зависимостей (Vue 3 / Spring Boot 3 уже включают нужные runtime'ы).
- `Intl.DateTimeFormat('ru-RU', ...)` даёт `dd.MM.yyyy HH:mm` без библиотек вроде `date-fns` (см. Assumptions спеки).
- Thymeleaf через Spring Thymeleaf + ICU Locale даёт ту же локализацию без кастомных JavaScript.

**Alternatives considered**:
- **`date-fns` или `moment`** — отвергнуты: новая зависимость ради одного формата даты — overkill.
- **`dayjs`** — отвергнут по той же причине; +24 KB на главную только ради даты.

### 5. Размещение блока — между статистикой и навигационными карточками

**Decision**: блок вставляется в `<main class="km-main">` `HomeView.vue` после блока `.km-stats` (`.km-stats-4`) и перед `.km-nav-cards` (HomeView.vue:43-97). Аналогично в `main.html` между секцией счётчиков и секцией ссылок.

**Rationale**:
- Логическая группировка: «что на сайте нового» → «куда пойти дальше».
- Блок не закрывает собой критичный first-paint (логотип и статистика — выше), не толкает навигацию за пределы видимой части (на десктопе 1920×1080 блок из 5 строк ≈ 250-300 px, помещается без агрессивного скролла — SC-001 спеки).

**Alternatives considered**:
- **Блок после соцсетей** — отвергнут: уезжает за первый экран, теряет смысл «новостного сигнала».
- **Блок перед статистикой** — отвергнут: статистика — это якорь доверия, должна быть в первом экране без скролла; новости вторичны.

### 6. Адаптивная вёрстка

**Decision**: блок наследует существующие медиа-запросы `HomeView.vue` (`.km-stats-4 { grid-template-columns: repeat(2, 1fr) }` на `@media (max-width: 700px)`). Для мобильных — таблица превращается в стек (одна строка на новость: дата сверху, заголовок+ссылка снизу) или используется тот же `<table>` с `table-layout: fixed` и явными `width` (паттерн из AGENTS.md).

**Rationale**:
- Существующая вёрстка главной уже адаптивна; новый блок не должен её ломать (FR-010 спеки).
- Паттерн «таблица с `table-layout: fixed` и явной `width`» — уже принят в проекте (см. AGENTS.md).

### 7. Трекинг кликов (visitor→registration воронка)

**Decision**: трекинг кликов по строкам блока — через существующий `trackLinkToSong(songId)` (см. `services/tracking` в `karaoke-public`). Для новостей без `song_id` (только ручные) — `trackLinkToSong` не вызывается; вместо этого используется существующий `trackUi('click', 'homeNews:{id}')`.

**Rationale**:
- Существующий механизм уже поддерживает трекинг кликов на песни (см. `useEngagementTracking` + `tracking.js`).
- Не добавляем новых эндпоинтов трекинга — переиспользуем.

**Alternatives considered**:
- **Новый тип события `homeNewsClick`** — отвергнут: `trackUi('click', 'homeNews:{id}')` уже достаточен; не плодим типов.

## Альтернативы, рассмотренные и отвергнутые (сводно)

| Альтернатива | Отвергнута потому что |
|---|---|
| Новый эндпоинт `GET /api/public/news/latest` | Не даёт выигрыша vs. переиспользование; плодит почву для дрейфа |
| SSE для автообновления блока | Сложность не описана в спеке; не решает реальной проблемы (частота новостей — несколько в день) |
| Disabled-ссылка для новостей без `link` | Худший UX (мёртвый кликабельный элемент) — FR-006 |
| Видимый фолбэк «Не удалось загрузить» | Худший UX; выбор A из Clarifications |
| Фильтрация без `link`/`title` на бэкенде | Меняет контракт существующего эндпоинта, ломает ленту `/news` |
| Спиннер при загрузке | Худший UX (если бэкенд лежит, спиннер висит) — FR-013 |
| Блок после соцсетей | Уезжает за первый экран |
| `date-fns` / `moment` / `dayjs` | Overkill ради одного формата; нативный `Intl.DateTimeFormat` достаточен |
| Новый тип события `homeNewsClick` | `trackUi('click', 'homeNews:{id}')` достаточен |
