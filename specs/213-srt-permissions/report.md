# Отчёт: #213 — chmod 666 на пути из данных песни

**PR:** #616, ветка `525-fix-srt-file-permissions`.

## Что было

`File("${song.rootFolder}/${song.fileName}.voice${voice+1}.srt").writeText(strText)`
и следом `runCommand(listOf("chmod", "666", pathToFile))` — два сайта в
`ApiController` (строки 3339 и 3397).

## Три проблемы

1. **Мировое право на запись** — писать может только приложение (контейнер под
   root, он же единственный писатель).
2. **Внешний процесс** ради одной операции.
3. **Отказ ломал сохранение** — на первом сайте `chmod` вне `try/catch` и уже
   после `setSourceMarkers()`, то есть запрос отдавал ошибку при применённых
   правках.

## Что сделано

`setSongFilePermissions()` — права 644 через `Files.setPosixFilePermissions`,
в процессе JVM, без подпроцесса. Ошибка логируется, сохранение не прерывается.

## Гипотеза не подтвердилась

Риск «путь выводится из данных, можно выйти из каталога» **не подтвердился**:
`song.fileName` санитизируется при импорте и переименовании через
`sanitizeSongFileName()`, которая убирает `/` и `\` (FR-001, тикет #53).

## Проверка

`SetSongFilePermissionsTest` 3/3, `compileKotlin` и `ktlintCheck` зелёные.

## Осталось

`chmod 666` встречается в проекте **89 раз**. Закрыты только два сайта из
тикета; остальные затрагивают рендеринг (Kdenlive, ffmpeg читают эти файлы) и
требуют отдельной проверки.
