# [#336] S1: проверка капчи **fail-open**: при пустом серверном ключе `validate()` возвращает `true` —… (BR-518)

Задача: устранение дефекта **BR-518** (S1) из полного аудита кода (#336).

## Что не так

** проверка капчи **fail-open**: при пустом серверном ключе `validate()` возвращает `true` — регистрация проходит без капчи. Ключ берётся не из конфигурации, а из таблицы `tbl_public_settings` (`CaptchaConfigService.getServerKey`, кэш 5 минут), а запись в эту таблицу **публична** (BR-019: `POST /api/properties/setproperty` не требует аутентификации). То есть внешний анонимный запрос может обнулить `yandexSmartCaptchaServerKey`, и в течение TTL кеша (5 минут) капча на `POST /api/public/auth/register` перестаёт проверяться — массовая регистрация аккаунтов становится возможна без капчи, а остальные средства защиты трафика (sampling/dedup) остаются единственными.

## Доказательство

**
  ```
  val serverKey = captchaConfigService.getServerKey()
  if (serverKey.isBlank()) {
      println("Yandex SmartCaptcha: серверный ключ не настроен, проверка пропущена")
      return true
  }
  ```
  (`karaoke-web/src/main/kotlin/com/svoemesto/karaokeweb/services/YandexCaptchaValidationService.kt:31–35`, SHA `1977838a`). Источник ключа: `CaptchaConfigService.fetchValue("yandexSmartCaptchaServerKey")` → `SELECT value FROM tbl_public_settings WHERE key = ?` (`services/CaptchaConfigService.kt:35–48`, TTL кеша 5 мин — `:31`). Публичная запись: `PublicSettingsWebController.setProperty` (BR-019, `PublicSettingsWebController.kt:50–54`). Потребитель: `PublicAuthController.register` → `if (!yandexCaptchaValidationService.validate(captchaToken ?: "", request.remoteAddr))` (`controllers/PublicAuthController.kt:47`) — при `validate == true` регистрация разрешена.

## Путь достижимости

** аноним → `POST /api/properties/setproperty?key=yandexSmartCaptchaServerKey&stringValue=` (BR-019, без аутентификации) → `UPDATE tbl_public_settings` → в течение ≤5 минут `CaptchaConfigService` отдаёт пустой ключ → `YandexCaptchaValidationService.validate` → `serverKey.isBlank()` → `return true` → `POST /api/public/auth/register` без капчи → массовые аккаунты (и, через них, обход лимитов, привязанных к аккаунту/реферальной программы).

## Предлагаемая поправка

** при пустом/неconfigured серверном ключе **не пропускать** проверку, а отклонять регистрацию (или явно отключать endpoint регистрации флагом, а не «пустой ключ = пропустить»); ключ капчи держать в env/конфигурации, а не в публично редактируемой таблице; в `setProperty` запретить запись ключей из allowlist'а секретов.
