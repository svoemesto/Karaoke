# Quickstart: проверка пагинации новостей

Предпосылка: локальный стенд (`karaoke-db`, `karaoke-app`, `karaoke-web`,
`webvue3`, `karaoke-public`) поднят через `deploy/do.sh`. Для реалистичной
проверки нужен объём данных, сопоставимый с прод-инцидентом (19000+ строк в
`tbl_news`) — см. сценарий 0.

## Сценарий 0: подготовка объёма данных (один раз)

Локальный `tbl_news`, скорее всего, пуст/мал — нужно сгенерировать
сопоставимый объём тестовых строк (source='auto', не влияет на
production-логику specs/089, т.к. это отдельная локальная БД):

```sql
INSERT INTO tbl_news (title, body, category, publish_at, created_at, source)
SELECT
  'Тестовая новость ' || g,
  'Тело тестовой новости ' || g,
  'air',
  now() - (g || ' minutes')::interval,
  now(),
  'auto'
FROM generate_series(1, 19000) AS g;
```

Проверить: `SELECT COUNT(*) FROM tbl_news;` — должно быть ~19000+.

## Сценарий 1: публичная лента грузит только первую порцию

1. Открыть `/news` на публичном сайте.
2. Открыть DevTools → Network — убедиться, что запрос к
   `/api/public/news` возвращает **не весь список**, а объект
   `{items, total, hasMore}` с `items.length` равным настроенному размеру
   страницы (не 19000+).
3. Страница отрисовывается быстро (см. SC-001 spec.md), видна кнопка
   «Показать ещё» (`hasMore: true`).

## Сценарий 2: «Показать ещё» дозагружает без дублей/пропусков

1. Запомнить `id` последней показанной карточки.
2. Нажать «Показать ещё».
3. Убедиться, что новая порция продолжает список сразу после запомненного
   `id` (по хронологии), без повторов уже показанных карточек и без
   пропущенных.
4. Повторить до `hasMore: false` — кнопка исчезает/дизейблится, `total`
   совпадает с фактическим числом показанных карточек.

## Сценарий 3: админка — переход по страницам в любом порядке

1. Открыть раздел «Новости» в webvue3, целевая БД — «Локальная».
2. Убедиться, что таблица показывает одну страницу (размер — см.
   research.md п.2), а `<b-pagination>` показывает корректное общее число
   страниц (из `total`, не из длины полученного списка).
3. Перейти сразу на страницу в середине диапазона (не по порядку) — таблица
   должна показать соответствующие строки без ошибки.
4. Вернуться на страницу 1.

## Сценарий 4: создание/удаление новости не ломает пагинацию

1. На странице 1 создать новую новость (без даты публикации — черновик).
2. Убедиться, что после перезагрузки списка `total` увеличился на 1, и
   новая новость видна (на первой странице — если сортировка `id DESC`,
   новая запись имеет наибольший `id`).
3. Удалить эту новость — `total` уменьшается обратно, дублей/битых страниц
   нет.

## Сценарий 5: смена целевой БД сбрасывает пагинацию

1. Находясь на странице 3+ списка «Локальная», переключить селектор на
   «Сервер».
2. Убедиться, что список и пагинация сбрасываются на страницу 1 для новой
   целевой БД (FR-007 spec.md), а не остаются «на странице 3» с чужими
   (или пустыми, если на сервере меньше данных) данными.

## Очистка после проверки

```sql
DELETE FROM tbl_news WHERE title LIKE 'Тестовая новость %';
```
