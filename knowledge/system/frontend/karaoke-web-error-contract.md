# Component: karaoke-web-error-contract (контракт ошибок и отказов karaoke-web)

> **Домен**: system (cross-cutting)
> **Компонента**: контракт ошибок `karaoke-web` (бэкенд публичного сайта и его
> Thymeleaf-шаблоны), зафиксированный аудитом #336 (волна E, пакет `PKG-S3-29` —
> OpenProject #401).

## Назначение

`karaoke-web` — приложение, которое отдаёт публичный сайт и его API. Аудит #336
(волна E, `PKG-S3-29`) нашёл в нём 17 записей **одного класса**: приложение не
различало «не знаю» и «знаю, что плохо».

- отказ «вы не редактор» уезжал в **500** (собственное исключение без
  `@ResponseStatus` и без обработчика), хотя в коде обещан 403;
- страница ошибки OG отдавалась с **HTTP 200** — для краулера это «страница
  существует»;
- «песня не найдена» была **500** (SpEL по `null` в шаблоне), а не 404;
- внутренняя ошибка **кешировалась** на 15 секунд — хотя комментарий в коде
  говорил обратное;
- «капча не пройдена» и «сервис проверки капчи недоступен» имели **один** код
  отказа (`captcha`) и один статус (400);
- `runCatching { file.delete() }` **проглатывал** неудачное удаление — чистка
  temp-директории могла молча перестать работать.

Правило в основе: **отказ должен быть отличим от успеха, а «я не знаю» — от
«я знаю, что сломалось»**.

## Интерфейсы и Контракты

### 1. Отказы контроллеров

| Ситуация | Статус | Тело |
|---|---|---|
| Нет прав (не редактор) | 403 | `{"errorCode":"share.notEditor"}` |
| Внутренняя ошибка share-ссылок | 500 | `{"errorCode":"share.internal"}` |
| Отказ от задания в неразрешённом статусе | 409 | `{"error":"not_refusable","status":…,"use":"recall"\|"delete"}` |
| OG: нет/некорректный id | 400 | HTML-страница ошибки, `Cache-Control: noindex, nofollow` |
| OG: песня не найдена | 404 | то же |
| Песня (`/song`) не найдена | 404 | страница «Песня не найдена» |

Собственное исключение контроллера **не** превращается в правильный статус
само: нужен `@ResponseStatus` **или** `@RestControllerAdvice` (у
`SiteShareLinksController` — advice, ограниченный `assignableTypes`, чтобы не
перехватывать чужие исключения).

### 2. Кеш ответов

`PollingCache.getOrCompute(key, ttl) { … }` кеширует **любой** ответ, если не
задан предикат `shouldCache`. Для heartbeat'а share-ссылки:

```kotlin
shouldCache = { it.statusCode.is2xxSuccessful || it.statusCode.value() == 410 }
```

Ошибки в кеш не попадают: иначе после падения БД клиент получал залипший 500
ещё 15 секунд после восстановления.

### 3. Капча: разные отказы — разные коды

| Исход | Код | HTTP | Смысл |
|---|---|---|---|
| `PASSED` | — | — | проверка пройдена |
| `FAILED` | `captcha` | 400 | пользователь не прошёл капчу (его вина) |
| `NOT_CONFIGURED` | `captcha_not_configured` | 400 | серверный ключ не задан (наша вина) |
| `UNAVAILABLE` | `captcha_unavailable` | **503** | внешний сервис недоступен (его вина) |

До BR-522 коды `FAILED` и `UNAVAILABLE` совпадали (`captcha`) — посетителю
говорили «вы не робот», когда капча была просто недоступна.

### 4. SQL: значения — только параметрами

`EventsBuffer.buildInsert()` собирает INSERT из имён колонок и плейсхолдеров
`?`; значения биндятся `setString`/`setLong`/`setInt`/`setBoolean`. Имена колонок
проверяются на `[a-z_]+`.

Санитайзер имён файлов (`rightFileName()`) **не применяется** к значениям: он
портит данные (`https://…` → `https-//…`, `AC/DC` → `AC_DC`), а безопасность
обеспечивал побочным эффектом подстановки кавычки.

### 5. Транзакции

Операция «отозвать старое + создать новое» (share-ссылка) выполняется в одной
транзакции: `autoCommit=false` → `commit()` / `rollback()`, режим соединения
восстанавливается в `finally` (соединение thread-local и переиспользуется
следующим запросом потока). Образец — `revokeLinkById`.

### 6. Шаблоны

- **Thymeleaf**: отсутствие атрибута модели = `null` в SpEL. Любой шаблон,
  работающий с объектом, обязан иметь ветку «объекта нет»
  (`th:if="${x != null}"` / `th:unless="${x != null}"`).
- **DOM**: `document.getElementById(...)` может вернуть `null` — и одна такая
  строка **прерывает весь** `$(function(){…})`, вместе с обработчиками других
  элементов. Элемента, которого нет, удаляют из кода.
- **Параметры URL**: `encodeURIComponent`, а не ручное экранирование одного
  символа.
- **Вставка разметки**: серверная строка разбирается на клиенте через
  `DOMParser` с allow-list тегов и CSS-свойств; пользовательский текст
  вставляется только текстовым узлом (`createTextNode`). Носитель разметки —
  инертный `<textarea>` (RCDATA).

### 7. Публичный периметр: `/api/` — публично

Прод-nginx маршрутизирует `/api/` на `karaoke-web`
(`deploy/prod-single-host/80to8897`) → любой endpoint под `/api/` в этом
приложении доступен всем на `sm-karaoke.ru`. Статистика и выгрузки — только
**вне** `/api/` (например `/statbysong-export`, рядом со страницей
`/statbysong`, которую на проде отдаёт SPA).

### 8. Метрики

Значение поля метрики должно соответствовать своему названию: `pgMaxConnections`
— реальный `SHOW max_connections` (`-1` = «не удалось прочитать»),
`currentTomcatMaxThreads` — `ThreadPoolExecutor.maximumPoolSize` коннектора
Tomcat (не `ThreadMXBean.peakThreadCount` — это пик потоков всей JVM).
