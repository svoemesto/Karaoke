# Research: Строка «Временная ссылка» в таблице FREE vs PREMIUM (169)

**Branch**: `169-share-link-in-premium-compare` | **Phase**: 0 | **Date**: 2026-08-11

> Построчная верификация с кодом — аналогично `005-free-vs-premium/research.md`
> Decision 1. Подтверждаем, что share-link (а) существует, (б) премиум-only,
> (в) имеет конкретные лимиты — и решаем, какие числа попадают в UI.

---

## Decision 1: «Временная ссылка» — премиум-only (FREE ❌, PREMIUM ✅)

**Decision**: в таблице сравнения FREE vs PREMIUM строка «Временная ссылка на
песню» имеет значение FREE ❌ и PREMIUM ✅.

**Rationale и свидетельства**:

1. **UI-уровень.** `karaoke-public/src/components/ShareLinkModal.vue:294-297` —
   при попытке создать ссылку без премиума модалка показывает явное сообщение:

   ```js
   if (status === 403 && code === 'share.notOwner')
     errorMessage.value = 'Только премиум-пользователи могут создавать ссылки'
   ```

2. **Backend-уровень.** `karaoke-web/.../services/SongShareLinkService.kt:198` —
   `class NotOwner : ShareException(ShareErrorCode.NOT_OWNER, 403)` выбрасывается
   в `tryClaim` / `createLink`, когда владелец не премиум. Контроллер
   `PublicShareController` маппит 403 в JSON для фронта.

3. **Архитектурно** функция live в проде с 2026-08-10 (см.
   `docs/features/guest-share-link.md:7-12`):
   > «Позволяет **премиум-пользователю** karaoke-public создать временную ссылку
   > на одну песню и переслать её кому угодно.»

4. **Аналогия** с уже существующими строками таблицы FREE vs PREMIUM (см.
   `PremiumView.vue:204-220`): **все 4 строки** с `free: false` → это
   премиум-only фичи («Полный доступ к плееру», «Непрерывное воспроизведение»,
   «Смена скорости/тональности», «Создание минусовок», «Чат с автором»).
   Share-link попадает в ту же категорию — явно только для премиума.

**Alternatives considered**:
- **«✅ в обеих колонках»** — отклонено: FREE-пользователь **не может** создать
  ссылку, это противоречит `403 share.notOwner`.
- **«Грейс-период для FREE»** — отклонено: такой модели нет в коде; владелец
  теряет премиум → ссылка отзывается автоматически (см.
  `docs/features/guest-share-link.md:74-78`, sweeper отзывает с
  `revoke_reason='premium_lost'`).

## Decision 2: Конкретика по TTL/устройствам — НЕ в ярлыке строки, ДА в премиум-блоке

**Decision**: ярлык строки `feature: 'Временная ссылка на песню'` содержит
только название фичи. PREMIUM-колонка в таблице показывает только ✅ (как
большинство существующих 8 из 11 строк). Точные сроки/лимиты выносятся в блок
«Что вы получили» (для премиум-пользователей) — там это фраза с указанием
TTL и количества устройств.

**Rationale**:

1. **Консистентность с большинством строк** в существующей таблице
   (`PremiumView.vue:204-220`):
   - 8 из 11 строк (онлайн-плеер/поиск/демо-фрагменты/полный доступ/
     непрерывное/смена скорости/смена тональности/минусовки/чат) —
     **только boolean** (✅/❌), без чисел в ячейках.
   - Только 2 строки («Избранное», «Свои плейлисты») — содержат числа
     («до 100/500», «1/до 50»). Обе описывают **количественные лимиты
     конкретного размера коллекции** — там число **и есть** суть фичи.
   - Share-link — **не** про количество чего-то; ключевая характеристика —
     «можно/нельзя». Число 1 ч/24 ч/7 д **выбирается пользователем при
     создании**, а не фиксированное — указывать одно значение в ярлыке
     некорректно (3 разных TTL).

2. **Числа в премиум-блоке «Что вы получили»** — там фраза, и читатель уже
   премиум, ему интересны детали («как именно работает фича, за которую он
   платит»). Здесь уместно указать **полный диапазон** и лимит устройств.

3. **Следование 005-free-vs-premium/research.md Decision 2**: «числа
   hardcoded, не через API» — точные лимиты на момент кода фронта равны
   настройкам бэкенда. Если лимиты изменятся, обновляется и эта таблица
   (см. комментарий в `PremiumView.vue:197-203`).

**Свидетельства** — точные значения из кода:

| Параметр | Значение | Источник |
|---|---|---|
| TTL (min) | 1 час (3600 сек) | `useShareLink.js:8` — `value: 3600, label: '1 час'` |
| TTL (mid) | 24 часа (86400 сек) | `useShareLink.js:9` — `value: 86400, label: '24 часа'` |
| TTL (max) | 7 дней (604800 сек) | `useShareLink.js:10` — `value: 604800, label: '7 дней'` |
| Concurrent sessions | ≤ 2 устройств | `WebShareProperties.kt:32` — `maxConcurrentSessions: Long = 2` |
| Max active links per user | 5 | `WebShareProperties.kt:20` — `maxActivePerUser: Long = 5` (для владельца, **не для гостя**) |
| Max generations per day | 30 | (премиум-владелец) |
| Max reissues per song per hour | 3 | (премиум-владелец) |
| Lease TTL | 90 сек (playback-сессия) | внутренняя механика, в UI не выносится |

Полная спецификация — `docs/features/guest-share-link.md:131-153`.

**Alternatives considered**:
- **«В ярлыке строки сразу TTL/устройства» (варианты B/C/D из FR-004 spec)** —
  отклонено: неконсистентно с 8 из 11 строк + у share-link 3 разных TTL на
  выбор (не один фиксированный).
- **«Числа через API бэкенда»** — отклонено: `005/FR-011` явно требует
  hardcoded в исходниках; рассинхрон между UI и backend-копией допустим,
  отслеживается через ручную правку при изменении лимитов (как и для
  `Избранное` 100/500).

## Decision 3: Заголовок строки — «Временная ссылка на песню»

**Decision**: `feature: 'Временная ссылка на песю'` (вопрос Q1 из spec).

**Rationale**:

1. **Консистентность с `ShareLinkModal.vue:6`**:
   > `<h2>Временный доступ к песне</h2>`

   Разница только в форме слова («доступ» vs «ссылка»). «Временная ссылка»
   точнее: фича реализована **через ссылку**, а не «доступ к фиче».

2. **Двусмысленность избегается.** «Временная ссылка» без контекста — может
   быть email-токен, magic link, временный пароль. «На песню» уточняет, что
   ссылка даёт доступ к конкретной песне.

3. **Постановка задачи.** Пользователь ввёл «Временная ссылка» — это
   ключевая фраза, которую он хочет видеть. Добавляем «на песню» для
   ясности.

**Alternatives considered**:
- **«Временная ссылка»** (короче) — допустимо, но допускает двусмысленность.
- **«Гостевой доступ к песне»** (как в `docs/features/guest-share-link.md:1`)
  — отклонено: менее точно (механизм — ссылка, не «вход как гость»).

## Decision 4: Точная формулировка для премиум-блока «Что вы получили»

**Decision**: добавить в конец существующей фразы: «+ создание временной
ссылки на песню (1 ч / 24 ч / 7 д, до 2 устройств одновременно)».

**Rationale**:

1. **Минимальная правка.** Существующая фраза (см. `PremiumView.vue:60-61`)
   уже перечисляет все фичи — добавляем одну в том же стиле.

2. **Конкретика для премиум-юзера** — он уже заплатил, хочет знать детали:
   сколько ссылок можно создать, на какой срок, сколько устройств
   одновременно. Ярлык строки в сравнительной таблице этой конкретики не
   даёт (см. Decision 2), но фраза «Что вы получили» — это подходящее место.

3. **Конкретные числа подтверждены** в Decision 2 (таблица).

**Alternatives considered**:
- **Переписать фразу целиком** (Q3 spec) — отклонено: больше diff, сложнее
  review, нет выгоды для пользователя.
- **Сделать отдельный под-список фич «Что вы получили»** — отклонено:
  overengineering для одной строки.

## Decision 5: Никаких новых миграций, эндпоинтов, модулей

**Decision**: фича — фронтенд-only правка в `karaoke-public/src/views/PremiumView.vue`
(массив `COMPARISON_ROWS` + одна фраза). НЕ затрагивает:

- базу данных (`tbl_song_share_links`, `tbl_song_share_sessions` — уже есть,
  см. `deploy/karaoke-db/38_song_share_links.sql`);
- backend endpoints (`/api/public/share/*` — уже реализованы, см.
  `docs/features/guest-share-link.md:225-273`);
- admin SPA (`webvue3`) — share-link управляется через
  `UserShareLinksModal.vue` (есть);
- дизайн (CSS-переменные `--km-*`, иконка 👑 — уже используются);
- трекинг (`tbl_events` уже пишется по CTA, см. US3 исходной таблицы);
- shаре-инфру (TTL/secret/lease/sweeper — уже реализованы в
  `SongShareLinkService.kt`, не пересекаются с этой таблицей).

**Rationale**: фича — это **пользовательский интерфейс**, не новый функционал.
Главное — **упоминание** уже работающей премиум-фичи в сравнительной
таблице. Это консистентно с подходом `005-free-vs-premium` (тоже была
только UI-правка + eventual миграция контента в массиве).

**Alternatives considered**:
- **«Завести отдельный компонент ShareLinkSummary.vue»** — отклонено:
  overengineering для 1 строки в 1 массиве.
- **«Вынести список фичей в БД / API»** — отклонено: `005/FR-011` явно
  требует hardcoded в исходниках; в рамках 169 не пересматриваем.
