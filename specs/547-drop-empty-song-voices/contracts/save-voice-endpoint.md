# Контракт: `POST /api/song/savesourcetextmarkers`

**Спека**: [../spec.md](../spec.md) (FR-002, FR-003, FR-010, FR-011, FR-012)
**Research**: [../research.md](../research.md) (R4, R5)
**Владелец эндпоинта**: `karaoke-app/.../controllers/ApiController.kt` (`saveSourceTextAndMarkers`)

Эндпоинт — точка сохранения голоса из редактора разметки админки
(`webvue3/.../Songs/edit/SubsEdit.vue` → store `saveSourceTextAndMarkers`).

## 1. Запрос

`POST /api/song/savesourcetextmarkers`
`Content-Type: application/x-www-form-urlencoded`

| Параметр | Тип | Обязателен | Смысл |
|---|---|---|---|
| `id` | long | да | id песни |
| `voice` | int | да | индекс голоса (с нуля) |
| `sourceText` | string | да | текст голоса (может быть пустым) |
| `sourceMarkers` | string (JSON) | да | массив `SourceMarker` |
| `indexTabsVariant` | int | да | вариант строя (сохраняется как раньше) |

## 2. Успешный ответ (`200`)

```json
{ "ok": true, "voice": 1, "countVoices": 2 }
```

| Поле | Смысл |
|---|---|
| `ok` | `true`, если данные применены |
| `voice` | индекс, под которым сохранённый голос находится **после** нормализации; `-1`, если голос удалён как пустой (US1) |
| `countVoices` | число голосов песни после сохранения |

Изменение относительно текущего контракта: раньше отдавался `true` (голое
boolean-тело). Единственный потребитель — `webvue3` store (research R5), он
обновляется в этой же спеке.

## 3. Ошибки

| Код | Тело | Когда | Поведение клиента |
|---|---|---|---|
| `200` | `{"ok": false, "error": "song_not_found"}` | песни с таким `id` нет | показать сообщение об ошибке сохранения |
| `200` | `{"ok": false, "error": "bad_markers"}` | `sourceMarkers` не разбирается как JSON-массив маркеров (FR-012) | показать сообщение, правки не потеряны (остаются в редакторе) |
| `200` | `{"ok": false, "error": "bad_voice"}` | `voice < 0` или `voice > countVoices` | показать сообщение |

Существующее поведение «поймать ошибку разбора и продолжить с `emptyList()`»
устраняется: битые маркеры больше не записываются (FR-012 — не терять данные).

## 4. Побочные эффекты (контракт сохранения)

1. Применяется нормализация голосов (FR-001): пустые голоса, кроме первого, удаляются.
2. Текст и маркеры голоса записываются **одной** операцией сохранения (research R4),
   поэтому промежуточного состояния «голос без текста» не существует.
3. При фактическом удалении пересчитываются `result_text` и `formatted_text_*` (FR-008).
4. Факт удаления фиксируется в логе приложения (песня, удалённые индексы) — без
   пользовательского уведомления.
5. `voice = -1` означает: редактор должен переключиться на последний оставшийся голос
   (`countVoices - 1`), иначе следующее сохранение создаст новый голос (FR-010).

## 5. Примеры

| Сценарий | Запрос | Ответ |
|---|---|---|
| Сохранение непустого второго голоса | `voice=1`, маркеры `[...]`, текст `"Привет"` | `{"ok":true,"voice":1,"countVoices":2}` |
| Сохранение пустого второго голоса (US1) | `voice=1`, `sourceMarkers=[]`, `sourceText=""` | `{"ok":true,"voice":-1,"countVoices":1}` |
| Пустой средний голос при трёх (US3) | `voice=1`, пусто | `{"ok":true,"voice":-1,"countVoices":2}`, третий голос стал индексом 1 |
| Правка третьего голоса при пустом втором (US4) | `voice=2`, маркеры `[...]`, текст `"B"` | `{"ok":true,"voice":1,"countVoices":2}` |
| Битые маркеры | `sourceMarkers="not json"` | `{"ok":false,"error":"bad_markers"}`, в БД ничего не изменилось |

## 6. Совместимость

- `POST /api/song/savesourcemarkers`, `POST /api/song/savesourcetext` — контракт
  (boolean) не меняется; нормализация применяется через `saveToDb` (research R1).
- Легаси `MainController` (`/song/{id}/{voice}/savesourcemarkers`) — контракт
  (Thymeleaf-вью `text`) не меняется.
- `POST /api/song/update` — контракт `SongUpdateResultDto` не меняется; нормализация
  применяется как побочный эффект сохранения (FR-002).
