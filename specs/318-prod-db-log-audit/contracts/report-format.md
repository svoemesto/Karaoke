# Contract: Report Format (`report.md`)

**Spec**: [../spec.md](../spec.md) FR-003 | **Data**: [../data-model.md](../data-model.md) | **Date**: 2026-09-08

> Контракт структуры финального отчёта `specs/318-prod-db-log-audit/report.md`.
> Любое отклонение от разделов считается нарушением SC-001 и FR-003.

---

## Общие правила

1. **Язык**: русский (соответствует AGENTS.md «АБСОЛЮТНОЕ ПРАВИЛО: язык общения»).
2. **Кодировка**: UTF-8, line endings LF.
3. **Размер**: ≤ 500 строк (если больше — топ-N по severity, не всё подряд).
4. **Timestamp'ы**: только из данных (`actual_window_start` / `actual_window_end`),
   не из `$(date)`. Иначе ломается SC-002 (воспроизводимость).
5. **Примеры логов** в отчёте — **санитизированные** (без паролей, хэшей,
   email, имён). Если в ERROR'е был пароль — заменяется на `[REDACTED:password]`.

---

## Структура (9 обязательных разделов)

### Раздел 1 — Header (≤ 8 строк)

```markdown
# Audit Report: karaoke-db (неделя 2026-09-01 … 2026-09-08)

**Spec**: specs/318-prod-db-log-audit | **OpenProject**: #66
**Метод сбора**: ssh root@188.119.64.111 + `docker logs --since=168h`
**Log driver**: <json-file | journald | syslog | none>
**Вердикт**: <оставлять | отключать>
```

### Раздел 2 — Резюме (TL;DR, 3–5 строк)

Три пункта: что доминирует в логах (1 категория + её доля), сколько реальных
ERROR'ов, рекомендация (одно предложение).

### Раздел 3 — Топ-10 категорий (таблица)

```markdown
| # | Категория | Линий | Доля | Уникальных сообщений | Пример |
|---|-----------|-------|------|----------------------|--------|
| 1 | auto_explain | 1100000 | 89.1 % | 5 | `LOG: duration: 12.34 ms statement: SELECT …` |
| 2 | log_min_duration_statement | 100000 | 8.1 % | 234 | `LOG: duration: 8.45 ms statement: …` |
| 3 | __other__ | 32333 | 2.6 % | 156 | `LOG: database system is ready to accept connections` |
| … |
| 10 | __unclassified__ | 200 | 0.02 % | 89 | `HikariPool-1 - Starting...` |
```

**Если `__unclassified__` > 5 %** — после таблицы варнинг-блок:
> ⚠️ **Ручной разбор требуется**: `__unclassified__` = X %. Это значит,
> что правила категоризации не покрывают значимую часть логов. Список
> уникальных `__unclassified__` сообщений — в `data/unclassified-samples.txt`.

### Раздел 4 — Реальные инциденты (топ-10)

Группировка ERROR/FATAL/PANIC по `raw_message` (одинаковый текст → одна
строка), сортировка по частоте. Если < 10 уникальных — показать все.

```markdown
| # | Уровень | Кол-во | Первый / последний | Текст (1 строка) |
|---|---------|--------|--------------------|------------------|
| 1 | ERROR | 145 | 2026-09-01 … 2026-09-08 | `duplicate key violates unique constraint "karaoke_vote_pkey"` |
```

Под таблицей — **обязательно** явная оценка:
> **Оценка серьёзности инцидентов**: [критично | умеренно | штатно].
> Все X уникальных сообщений — [описание, например: «известный шум из-за
> частого INSERT-а конфликтующих голосов; новых паттернов не обнаружено»].

### Раздел 5 — Метрики нагрузки (таблица + 2–3 абзаца)

```markdown
| Метрика | Значение |
|---------|----------|
| Окно (запрошенное) | 168 ч (2026-09-01 … 2026-09-08) |
| Окно (фактическое) | <actual_window_start> … <actual_window_end> |
| Log driver | <type> |
| Предупреждение об обрезке | <текст, если есть> |
| Всего строк | 1 234 567 |
| Всего байт | 28.9 MB |
| Байт/день (медиана) | 4.0 MB |
| Байт/день (максимум) | 5.0 MB |
| ERROR'ов | 234 (0.019 %) |
| Уникальных категорий | 7 из 10 заявленных |
```

Абзацы — интерпретация: «X МБ/день — это нормально для прода (Y МБ/день
baseline)» ИЛИ «X МБ/день в 10× больше baseline → логирование действительно
шумное и скорее всего мешает».

### Раздел 6 — Вердикт (один из двух вариантов)

#### 6a. `decision == отключать`

```markdown
## Вердикт: ОТКЛЮЧАТЬ

**Обоснование**:
1. Категория `auto_explain` занимает X % логов (доминирует абсолютно).
2. Реальных ERROR'ов < 0.1 % — диагностическая ценность verbose-логов
   низкая.
3. Размер лог-файла X МБ/день — кандидат на снижение в 5–10× после отключения.

**Конкретные изменения**: см. [disable-config.md](disable-config.md).
**Ожидаемый эффект**: размер лога уменьшится на ≥ Y %, ERROR'ы продолжат
писаться (smoke-проверка в Stage 6 acceptance scenario US2/3).
```

#### 6b. `decision == оставлять`

```markdown
## Вердикт: ОСТАВЛЯТЬ

**Обоснование**:
1. Категория X доминирует, но **соответствует активной диагностике** тикета
   Y (или события Z).
2. ERROR'ов > N % — есть реальная ценность в подробных логах.

**Критерии отключения в будущем**:
- **Триггер**: [например: «когда закроется OpenProject #Y» / «когда нагрузка
  на CPU упадёт ниже Z %» / «через 30 дней — повторный аудит»].
- **Ответственный за повторный аудит**: <имя>.
- **Дата следующего аудита**: 2026-10-08.
```

### Раздел 7 — Воспроизводимость

```markdown
## Воспроизводимость

- **md5 отчёта**: `<md5sum report.md>`
- **md5 logs.jsonl**: `<md5sum data/logs.jsonl>`
- **Повторный запуск анализа**: `bash scripts/02-parse-and-categorize.sh &&
  bash scripts/03-generate-report.sh` (после `bash scripts/01-fetch-logs.sh`)
- **Sanitization**: данные в `data/` санитизированы скриптом
  `scripts/04-sanitize-for-commit.sh`; raw.log **не коммитится** в git
  (см. FR-007).
```

### Раздел 8 — Known limitations (если есть)

Только если есть реальные ограничения (truncation, unclassified, etc.):

```markdown
## Known limitations

- Log driver `json-file` ограничен ~30 MB ring-buffer → доступны не 168 ч,
  а только последние ~6 ч (N строк, M МБ).
- Категория `__unclassified__` составила 0.02 % (ниже порога 5 %, но в неё
  попали все HikariCP-сообщения — известный non-Postgres stdout).
```

## Чек-лист соответствия (для SC-001)

Перед публикацией `report.md` пройти по списку — каждый пункт **MUST**:

- [ ] Все 9 разделов присутствуют (Header, Резюме, Топ-10, Инциденты, Метрики, Вердикт, Воспроизводимость, Limitations, Артефакты).
- [ ] Вердикт — одно из двух слов: `ОТКЛЮЧАТЬ` или `ОСТАВЛЯТЬ` (заглавные).
- [ ] Если «ОТКЛЮЧАТЬ» — есть ссылка на `disable-config.md`.
- [ ] Если «ОСТАВЛЯТЬ» — есть блок «Критерии отключения в будущем» с конкретным триггером.
- [ ] Все timestamp'ы взяты из данных, не из `$(date)`.
- [ ] `md5sum report.md` записан в Раздел 7.
- [ ] Размер отчёта ≤ 500 строк.
- [ ] Никаких `password=`, `Bearer `, `pat_*`, postgres://user:pass@ в тексте.
