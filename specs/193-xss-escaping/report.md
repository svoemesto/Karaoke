# Отчёт: #193 — v-html на пользовательском тексте

**PR:** #613, ветка `522-escape-user-html`.

## Что было

Текст песни конкатенировался в HTML-строки в четырёх форматтерах, которые
рендерятся через `v-html`. Функций экранирования в компоненте не было.

## Что экранировано

- `getFormattedText`: комментарий и текст слогов.
- `getFormattedNotes` / `getFormattedChords`: `txtHtml`, `chordHtml` (`marker.chord`),
  `noteHtml` (`marker.note`).
- `getTail`: `textCurr`, `textNext`, `textEnd`.

Экранируется HTML-форма, не исходные значения: `chord` и `note` нужны для
сравнений в логике.

## Проверка

Контейнер пересобран из старого кода:

| | старый | новый |
|---|---|---|
| сырой `<img` в HTML | **true** | false |
| экранированный `&lt;img` | нет | есть |
| элементов `<img>` в блоках `v-html` | **2** | 0 |

Полный набор e2e: 18/18.

## Честно о том, что НЕ доказано

Выполнение вредоносного скрипта end-to-end НЕ воспроизведено: на старом коде
сырой `<img>` попадал в DOM, но `onerror` не срабатывал — разбивка текста песни на
слоги разрывает тег. Утверждение «скрипт не выполнился» было пустым в обе стороны
и убрано из теста.

Доказуемо и исправлено то, что сырой HTML пользовательского текста попадал в DOM
через v-html. Эксплуатируемость целиком (с сохранением на бэкенде и отдачей) —
вопрос тикета #198.

## Три ловушки в тесте, пойманные прогоном

1. Тест проходил вхолостую: векор подставлялся в `sourceMarkers[i].label`, но
   `sourceMarkers` пересобирается из `sourceText` и значение затиралось.
2. Утверждение про запуск скрипта проходило и на уязвимом коде — убрано.
3. `npm run build` не пересобирает Docker-образ; e2e идёт против контейнера.
