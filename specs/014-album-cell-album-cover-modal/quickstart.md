## Что проверяем (end-to-end)

После реализации фичи администратор из раздела `/Albums` может менять обложку альбома
без перехода в `/Songs` или `/Pictures` — кликом по preview-обложке или по названию альбома.

## Предусловия

- Локальный Docker-стек поднят (`bash deploy/do.sh start` или эквивалент; см. `AGENTS.md`).
- Контейнер `karaoke-app` собран с новым кодом (см. `bash deploy/do.sh build_app` — **выполняет только пользователь**, не агент).
- В БД есть хотя бы один альбом с `songsCount > 0` (например, любой из существующих — 5k+ альбомов в проде).
- Открыт браузер, залогинен в `webvue3` (admin SPA, `permitAll()`, реальная авторизация не требуется).

## Сценарий 1: клик по preview обложки → поиск в интернете → сохранение

**Шаги:**

1. Открыть `/Albums`.
2. Нажать кнопку-фильтр (иконка внизу слева) → задать простой фильтр (например, `Songs count >= 1`) → «Применить».
3. Дождаться загрузки таблицы.
4. **Кликнуть по preview обложки** в колонке `(альбом)` любого альбома с `songsCount > 0`.

   **Ожидаемо:** открывается модалка «Обложка альбома» (та же, что в `SongEdit.vue`), с текущей обложкой (или плейсхолдером «Картинки альбома пока нет») и шагом `view`.

5. Ввести произвольный поисковый запрос (например, `<Автор> <Альбом> обложка`) → «Найти в интернете».

   **Ожидаемо:** модалка переходит на шаг `results`, отображается сетка кандидатов (или сообщение «Ничего не найдено»).

6. Кликнуть по одному из кандидатов → откроется шаг `cropping` с квадратным кроппером.
7. Нажать «Сохранить».

   **Ожидаемо:** модалка закрывается, превью в строке таблицы обновляется (через `loadOneRecord(albumId)`) на новую картинку.

8. **Проверить** на диске: в папке альбома (`<rootFolder одной из песен>/LogoAlbum.png`) лежит новая обложка.
9. **Проверить** в БД: запись `Pictures` с `name = <song.pictureNameAlbum>` обновилась (или создалась, если не было).

## Сценарий 2: клик по preview → загрузка с диска → сохранение

**Шаги:**

1. Повторить шаги 1-4 из сценария 1.
2. В модалке нажать «Загрузить с диска» → выбрать любой PNG/JPEG из файловой системы (например, скриншот).

   **Ожидаемо:** открывается `FileExplorerModal` (тот же, что в `SongEdit.vue`); после выбора файла — шаг `cropping`.

3. Нажать «Сохранить».

   **Ожидаемо:** модалка закрывается, превью обновлено. (Аналогично шагу 7-9 сценария 1.)

## Сценарий 3: клик по названию альбома

**Шаги:**

1. Повторить шаги 1-2 из сценария 1.
2. **Кликнуть по ячейке с названием альбома** в колонке `Название`.

   **Ожидаемо:** открывается **та же** модалка «Обложка альбома» (НЕ `CustomConfirm` с полями year/name/albumType).

3. Закрыть модалку кнопкой «Закрыть» (без сохранения).

   **Ожидаемо:** модалка закрывается, превью в таблице не меняется.

## Сценарий 4: альбом без песен (songsCount = 0)

**Шаги:**

1. Через прямой SQL или admin-сценарий создать/найти альбом с `songsCount = 0` (например, новый альбом, только что созданный через «+» в `AlbumsTable`).
2. Применить фильтр, чтобы этот альбом попал в таблицу.
3. Навести курсор на preview `(альбом)` и на ячейку `Название`.

   **Ожидаемо:** tooltip показывает «У альбома нет песен — обложка недоступна», курсор НЕ меняется на pointer, hover-стиль кликабельности не применяется.

4. Попробовать кликнуть.

   **Ожидаемо:** ничего не происходит (модалка не открывается).

## Сценарий 5: проверка восстановления `currentSongId` (SC-004)

**Предусловие:** админ до этого работал в `/Songs` и `currentSongId` была установлена на какую-то песню (например, открыл `SongEdit` песни ID=42).

**Шаги:**

1. Перейти в `/Albums`, применить фильтр.
2. Кликнуть по preview `(альбом)` любого альбома.
3. В модалке нажать «Закрыть» (без сохранения).
4. Вернуться в `/Songs`.

   **Ожидаемо:** `SongEdit` (если был открыт) или список песен в том же состоянии, что и до ухода в `/Albums`. В частности, `currentSongId = 42` (восстановлена из `prevCurrentSongId`).

## Сценарий 6: проверка не-Pic редактирования атрибутов

**Шаги:**

1. В `/Albums` применить фильтр.
2. Кликнуть по ячейке `ID` (столбец `id`).

   **Ожидаемо:** открывается `CustomConfirm` «Изменение альбома» (как было до фичи) — фича **не сломала** существующее поведение.

3. Кликнуть по ячейке `Автор` (столбец `authorId`).

   **Ожидаемо:** открывается тот же `CustomConfirm` (как было).

## Сценарий 7: проверка backend-эндпоинта напрямую (smoke test)

```bash
# Из контейнера karaoke-app (или с host, если есть curl + куки):
curl -X POST 'http://localhost:8080/api/albums/firstsongid?albumId=1'
# Ожидаемо: <число> (id первой песни альбома с id=1), либо 0, если песен нет
```

**Ожидаемо:** HTTP 200, тело — `Long` (id песни) или `0`.

## Что должно остаться как было (regression)

- `SongsTable.vue` — клик по preview обложки/авторского превью в колонках по-прежнему открывает `PictureEditModal`.
- `SongEdit.vue` — кнопка «Изменить обложку альбома» по-прежнему открывает `AlbumCoverModal` с тем же поведением.
- `AlbumsTable.vue` — клик по ячейке `albumType` (inline-select) по-прежнему меняет тип альбома без открытия модалки.
- `AlbumsTable.vue` — кнопка «+» по-прежнему создаёт новый альбом через `CustomConfirm`.
- `AlbumsTable.vue` — клик по ячейке `ID`/`Автор`/`Год`/`Название`/`Порядок` в режиме «songsCount = 0» (если бы такая ячейка была кликабельной для changeValue) — фича **не** должна ломать существующий флоу `changeValue()`. Проверить, что `changeValue()` всё ещё работает на ячейках `id`/`authorId`/`year`/`sortOrder` (только `name` теперь переключается на новый хендлер — это by design).
- Пагинация и фильтр альбомов — переживают F5 и переход в другой раздел (Vuex `albumsTableCurrentPage`, `albumsFilter*` — без изменений).

## Известные ограничения

- Если у альбома ВСЕ песни имеют `firstSongInAlbum = FALSE` И `MIN(id)`-fallback вернёт какую-то «не главную» песню — модалка откроется по ней. Это безопасное поведение (любая песня альбома — корректный контекст для `LogoAlbum.png`).
- Edge case «у альбома появилась первая песня прямо во время открытия модалки» (race condition) не покрыт — UI-блокировка клика при `songsCount === 0` + backend-возврат `0` для таких случаев считаются достаточными.
- Тесты в CI не добавляются (см. `AGENTS.md` и `constitution.md` — в проекте нет unit-тестов; проверка делается пользователем вручную по сценариям 1-7).

## Деплой

- **Локально (admin-машина):** пользователь пересобирает `karaoke-app` (`bash deploy/do.sh build_app`) и `webvue3` (через `bash deploy/do.sh build_start_web`).
- **Прод:** `deploy_web.sh` (только пользователь) — обновляет `karaoke-web` (где живёт SPA-сборка) и `karaoke-app` (где новый endpoint).
- **Проверка после деплоя (см. `AGENTS.md` «Деплой»):** в логах push нет `EOF`/`400 Bad request`; `Status: Downloaded newer image`; реальное env внутри контейнера содержит `WORKING_DATABASE=...` (через `docker exec karaoke-web env | grep WORKING_DATABASE`).
