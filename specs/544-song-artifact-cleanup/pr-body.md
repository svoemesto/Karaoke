## Что это

Исполнение решений wayfinder-карты **#306** «Избавление от лишних файлов на диске»:
автоуборка артефактов песни. OpenProject-задача: **#321**. Спека — `specs/544-song-artifact-cleanup/spec.md`.

Диски admin-машины держат 2,4 ТБ артефактов песни, из них ≈650 ГБ — заведомо лишние:
демо-ролики (177 ГБ), локальные копии mp3-стемов (445 ГБ), мёртвые sidecar-файлы,
субтитры, проекты замороженного melt. Ничего из этого сегодня не удаляется ни на одном шаге.

## Что сделано

- **US1**: демо-ролик удаляется в конце шага публикации (`PremiumAutoPublishScheduler.closeIfBothChannelsDone`) — и при успехе, и при провале; публикационные картинки — только при успехе обеих площадок.
- **US2**: у типов `MP3_*` снята локация `LOCAL_FILESYSTEM` (модель ожидаемых файлов), локальная копия mp3 удаляется только после подтверждённого наличия объекта **в обоих** MinIO (fail-closed).
- **US3**: перестали создаваться `.song`/`.settings`, `.srt`/`.srt.backup`, `.kdenlive`/`.run`; признак `hasChords` считается по маркерам в БД (чтение `.srt` вырезано).
- **US4**: разовая чистка истории — реестр классов, сухой прогон с отпечатком, утверждение, удаление с журналом; защищённые классы (исходники, flac-стемы) отклоняются API всегда.
- **US5**: покрытие проверки здоровья для каталогов `symlink_*`, гигиена мусора, приведение Knowledge к факту (melt → MinIO больше не описан как реальный путь рендера).

Уборка **выключена по умолчанию** (`cleanupEnabled=false`) и имеет режим сухого прогона (`cleanupDryRun=true`) — без явного включения поведение системы не меняется.
