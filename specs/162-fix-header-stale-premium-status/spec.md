# Feature Specification: Устаревший премиум-статус в шапке сайта после окончания подписки

**Feature Branch**: `162-fix-header-stale-premium-status`

**Created**: 2026-08-09

**Status**: Draft

**Input**: User description: "Баг в другом: если у пользователя закончилась подписка (он раньше был премиум, а теперь не премиум) то в шапке сайта он отображается как премиум (пока не обновит страницу или не перелогинится)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Статус в шапке сайта перестаёт быть премиум сразу после окончания подписки (Priority: P1)

Пользователь ранее был премиум-подписчиком. Его подписка закончилась (истёк срок, отменена, не продлена). Несмотря на это, шапка сайта (виджет авторизации — значок 🪙 «Премиум-подписчик» рядом с именем) продолжает показывать его как премиум-пользователя. Это вводит пользователя в заблуждение относительно его текущего статуса и может создавать ложные ожидания доступа к премиум-контенту.

**Why this priority**: Единственная зафиксированная проблема в этом баг-репорте — напрямую влияет на доверие пользователя к своему статусу подписки и потенциально на восприятие сервиса как ненадёжного (обещает то, чего уже нет).

**Independent Test**: Можно проверить самостоятельно: взять аккаунт с premium-подпиской, дождаться/спровоцировать её окончание на сервере, затем — не выходя из системы и не обновляя страницу — понаблюдать за шапкой сайта: значок премиума должен пропасть сам, без ручных действий пользователя.

**Acceptance Scenarios**:

1. **Given** пользователь залогинен и его подписка только что закончилась на сервере, **When** он продолжает находиться на сайте без перезагрузки страницы и без повторного входа, **Then** шапка сайта в разумный срок перестаёт показывать значок премиума.
2. **Given** та же ситуация (подписка истекла), **When** пользователь обновляет страницу или заходит на любую другую страницу сайта, **Then** шапка сразу показывает актуальный (непремиум) статус.
3. **Given** та же ситуация, **When** пользователь выходит из аккаунта и заходит заново, **Then** шапка показывает актуальный (непремиум) статус.
4. **Given** пользователь, у которого подписка активна и не менялась, **When** он просто пользуется сайтом, **Then** шапка стабильно показывает премиум-статус без ложных сбросов (защита от регрессии в обратную сторону).
5. **Given** пользователь, чья подписка была только что оформлена/продлена (был непремиум, стал премиум), **When** он продолжает находиться на сайте, **Then** шапка отражает новый премиум-статус без обязательной перезагрузки страницы (симметричный случай к User Story 1, тот же механизм актуальности статуса).

---

### Edge Cases

- Пользователь держит открытыми несколько вкладок сайта одновременно — во всех вкладках статус должен рано или поздно синхронизироваться с реальным.
- Подписка заканчивается ровно в момент активного использования сайта (например, пользователь слушает премиум-песню) — устаревший статус в шапке не должен создавать иллюзию, что доступ к контенту тоже сохранён (доступ к контенту уже проверяется отдельно и live — см. `docs/architecture-notes.md`/специфику плеера; это баг именно про отображение в шапке).
- Долгая неактивная вкладка (открыта много часов без действий) — при возврате к ней статус должен быть актуализирован, а не оставаться замороженным с момента открытия.
- Пользователь на медленном соединении/офлайн на короткое время — временная невозможность проверить статус не должна приводить к ошибочному показу премиума взамен ошибки.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Отображаемый в шапке сайта премиум-статус ДОЛЖЕН отражать актуальное (текущее, серверное) состояние подписки пользователя, а не состояние на момент последнего входа в систему.
- **FR-002**: Система ДОЛЖНА обновлять премиум-статус в шапке автоматически в течение сессии пользователя, без обязательного требования вручную перезагрузить страницу.
- **FR-003**: Система ДОЛЖНА корректно обновлять статус в шапке при обычной перезагрузке страницы и при повторном входе в систему (эти пути уже должны работать и не должны сломаться при исправлении).
- **FR-004**: Изменение статуса ДОЛЖНО работать симметрично в обе стороны — как снятие премиум-значка при окончании подписки, так и его появление при оформлении/продлении, без обязательной перезагрузки страницы.
- **FR-005**: Временная недоступность проверки статуса (сетевая ошибка, задержка) НЕ ДОЛЖНА приводить к ошибочному показу премиум-статуса, которого на самом деле нет.

### Key Entities *(include if feature involves data)*

- **Пользователь сайта (SiteUser)**: учётная запись с текущим премиум-статусом (действующая подписка или её отсутствие).
- **Сессия пользователя в браузере**: состояние авторизации на клиенте, включающее локально закэшированные данные о пользователе, которые отображаются в шапке.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После окончания подписки шапка сайта перестаёт показывать премиум-статус в течение одной сессии пользователя, без ручной перезагрузки страницы, для 100% случаев в проверке.
- **SC-002**: Ни один пользователь с действительно активной подпиской не видит ложного снятия премиум-статуса в шапке (0 регрессий при проверке до/после).
- **SC-003**: После выпуска исправления не поступает новых обращений в поддержку по теме «в шапке сайта до сих пор показывается премиум, хотя подписка закончилась».

## Assumptions

- «Шапка сайта» — это виджет статуса авторизации, отображаемый на каждой странице публичного сайта (значок 🪙 рядом с именем пользователя при premium-статусе).
- Речь идёт именно об отображении статуса в интерфейсе, а не о реальном доступе к премиум-контенту — доступ к воспроизведению уже проверяется отдельно, в реальном времени, на сервере при каждом запросе к плееру (независимый механизм, не предмет этого бага).
- «Разумный срок» автоматического обновления статуса в течение сессии — не мгновенно посекундно, а в пределах обычных пользовательских действий на сайте (переход между страницами, минуты, а не часы); точный интервал — предмет решения на этапе планирования, не бизнес-требование.
- Исправление не меняет саму бизнес-логику определения премиум-статуса (какие подписки считаются активными) — только своевременность его отображения в интерфейсе.
- Кейс "несколько открытых вкладок" — синхронизация статуса между вкладками допустима с той же задержкой, что и обновление в рамках одной вкладки; мгновенная кросс-вкладочная синхронизация не требуется.
