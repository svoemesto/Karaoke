## Вопросы владельцу (правку спеки не вносил)

1. **H3 — порядок «прод, затем PR» или «PR, затем прод»?** Edge case «CI не прошёл / PR не
   создан → на прод не выкладывается, правка считается неприменённой» противоречит Д-1,
   FR-014 и US4. Сейчас реализовано по Д-1: сначала прод, затем PR; неудачный CI catch-up PR
   не откатывает прод, а уведомляет владельца.
2. **H2 — атомарная замена вместо сохранения inode?** Для `/etc/nginx/nginx.conf` на проде
   bind-mount'а нет (требование FR-007 об inode — из практики контейнерных конфигов), поэтому
   атомарный rename удовлетворил бы и FR-007 по смыслу, и edge case. Сейчас — буква FR-007
   (`cat` + проверка sha256). Нужно ли разрешение на rename?
3. **M3 — что считать «ожидаемым» конфигом** при обнаружении расхождения прод↔репозиторий:
   отказываться от правки (как читает edge case) или фиксировать дрейф, сообщать владельцу и
   править (как сейчас)?
