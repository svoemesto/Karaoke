# Quickstart: Валидация админ-таблиц «Подписки», «История прослушиваний», «Временные ссылки»

**Feature**: 171-admin-subscriptions-history
**Date**: 2026-08-11
**Status**: Phase 1 — quickstart

> Это **руководство по валидации** end-to-end. Не содержит кода реализации — только проверочные сценарии, которые подтверждают, что фича работает после раскатки.

## Prerequisites

1. **Backend** (`karaoke-app`, `karaoke-web`) собран и запущен — `bash deploy/do.sh build_app_web && bash deploy/do.sh start_karaoke-web`.
2. **Frontend** (`webvue3`) собран и доступен — `bash deploy/do.sh build_webvue3 && bash deploy/do.sh restart_webvue3`.
3. **PostgreSQL**: обе БД (LOCAL и REMOTE) содержат записи во всех трёх таблицах:
   - `tbl_subscriptions` — минимум 100 строк.
   - `tbl_listening_history` — минимум 1000 строк.
   - `tbl_song_share_links` — минимум 50 строк (включая несколько активных).
4. **Браузер**: открыть `http://localhost:8897/` (или адрес webvue3).

## Сценарий 1: Подписки (`/subscriptions`)

### 1.1. Открытие таблицы

**Шаги:**
1. Открыть `http://localhost:8897/subscriptions` (или кликнуть «Подписки» в левом меню).
2. Дождаться загрузки.

**Ожидаемый результат:**
- Видна таблица с 25 строками (по умолчанию).
- Столбцы: дата создания, пользователь (id + email), scope (Сайт/Песня), название (тариф/песня), сумма, базовая цена + скидка, статус, автопродление, дата оплаты, номер заказа.
- Сортировка — по `created_at DESC` (самые новые сверху).
- Пагинация внизу — `Page 1 of N`.
- Toolbar — переключатель target «Local/Remote», кнопка «Фильтр».

### 1.2. Фильтр «scope=PAID, status=SONG»

**Шаги:**
1. Кликнуть «Фильтр».
2. В модалке выбрать scope=SONG.
3. Кликнуть «Применить».

**Ожидаемый результат:**
- Таблица перезагрузилась, видны только подписки `scope=SONG`.
- Footer «Показано X из Y» обновился.
- Модалка закрылась.

### 1.3. Переключение target Local ↔ Remote

**Шаги:**
1. В toolbar переключить target на «Remote».
2. Дождаться.

**Ожидаемый результат:**
- Таблица перезагрузилась, данные соответствуют REMOTE-БД (могут быть другие подписки).
- Фильтр `scope=SONG` сохранился.

### 1.4. Drill-down к пользователю

**Шаги:**
1. Кликнуть по email пользователя в любой строке.

**Ожидаемый результат:**
- Открылась страница `/siteusers` с фокусом на этом пользователе (карточка редактирования) — НЕ новая вкладка.

### 1.5. Пагинация

**Шаги:**
1. Перейти на страницу 3.
2. Перейти на `/songs`.
3. Вернуться на `/subscriptions`.

**Ожидаемый результат:**
- Таблица открылась на странице 3 с тем же фильтром.

## Сценарий 2: История прослушиваний (`/listeninghistory`)

### 2.1. Открытие таблицы

**Шаги:**
1. Открыть `http://localhost:8897/listeninghistory`.
2. Дождаться загрузки.

**Ожидаемый результат:**
- Видна таблица с 500 строками (по умолчанию).
- Столбцы: дата последнего прослушивания, пользователь, песня (id + название), исполнитель, альбом, счётчик прослушиваний.
- Сортировка по `last_played_at DESC`.
- Footer «Показано 500 из N» (N — totalCount).

### 2.2. SKIP-фильтр (негативный тест)

**Шаги:**
1. В БД пометить песню с id=98765 тегом `SKIP` (если ещё не помечена):
   ```sql
   UPDATE tbl_songs SET tags = 'SKIP' WHERE id = 98765;
   ```
2. В таблице истории — применить фильтр `userId` (того пользователя, который слушал эту песню).
3. Убедиться, что песня с id=98765 НЕ появляется.

**Ожидаемый результат:**
- Песня 98765 не в списке (SKIP-фильтр на чтении).
- Если других прослушиваний нет — таблица показывает «Истории прослушиваний нет».

### 2.3. Drill-down к песне

**Шаги:**
1. Кликнуть по названию песни в любой строке.

**Ожидаемый результат:**
- Открылась страница `/songs?focus=ID` (карточка песни в редакторе).

### 2.4. Фильтр по диапазону дат

**Шаги:**
1. Кликнуть «Фильтр».
2. Указать `lastPlayedFrom = 2026-08-01T00:00:00Z`, `lastPlayedTo = 2026-08-10T23:59:59Z`.
3. Применить.

**Ожидаемый результат:**
- Видны только прослушивания за этот диапазон.

## Сценарий 3: Временные ссылки (`/sharelinks`)

### 3.1. Открытие таблицы

**Шаги:**
1. Открыть `http://localhost:8897/sharelinks`.
2. Дождаться загрузки.

**Ожидаемый результат:**
- Видна таблица с 25 строками.
- Столбцы: дата создания, владелец, песня, дата истечения, статус, причина отзыва (если есть), наличие активной сессии (бейдж), secret.
- Сортировка по `created_at DESC`.

### 3.2. Бейдж «есть активная сессия»

**Шаги:**
1. Найти строку с активной ссылкой (active=true).
2. Если в БД нет активной сессии — открыть ссылку в анонимном браузере (через `https://sm-karaoke.ru/share/{id}/{secret}`).
3. Вернуться в админку, обновить (F5).

**Ожидаемый результат:**
- В строке виден бейдж «Идёт сессия» (или аналогичный).

### 3.3. Действие «Отозвать»

**Шаги:**
1. В toolbar убедиться, что target = Local (чтобы случайно не отозвать прод-ссылку).
2. Найти строку с `active=true` (например, id=777).
3. Кликнуть кнопку «Отозвать» в строке.
4. В модалке подтверждения ввести причину (опционально) и подтвердить.

**Ожидаемый результат:**
- Модалка закрылась.
- Строка обновилась in-place: `active=false`, `revokedAt=now()`, `revokeReason='admin'`.
- Кнопка «Отозвать» пропала (или стала disabled).
- Тост «Ссылка отозвана».
- **Без перезагрузки страницы**.

### 3.4. Проверка через прямой SQL

**Шаги:**
1. После шага 3.3:
   ```sql
   SELECT id, active, revoked_at, revoke_reason FROM tbl_song_share_links WHERE id = 777;
   ```

**Ожидаемый результат:**
```
id | active | revoked_at                | revoke_reason
---|--------|---------------------------|---------------
777 | f      | 2026-08-11 12:34:56+00   | admin
```

### 3.5. Фильтр «только активные»

**Шаги:**
1. Кликнуть «Фильтр».
2. Чекбокс «только активные» — поставить галочку.
3. Применить.

**Ожидаемый результат:**
- Видны только строки с `active=true AND expires_at > now()`.

### 3.6. Drill-down к владельцу / песне

**Шаги:**
1. Кликнуть по email владельца — открылась `/siteusers` с фокусом.
2. Кликнуть по названию песни — открылся `/songs?focus=ID`.

## Сценарий 4: Негативные кейсы

### 4.1. Пустой результат

**Шаги:**
1. В каждой из трёх таблиц применить фильтр, который точно ничего не вернёт (например, `userId=999999999`).

**Ожидаемый результат:**
- Таблица показывает заглушку («Подписок нет», «Истории прослушиваний нет», «Временных ссылок нет»).

### 4.2. Сетевая ошибка

**Шаги:**
1. Остановить backend (`bash deploy/do.sh stop_karaoke-web`).
2. В админке перейти на `/subscriptions`.

**Ожидаемый результат:**
- Тост «Нет связи с сервером».
- Таблица показывает предыдущие данные (если были) или заглушку + кнопку «Повторить».

### 4.3. Невалидный target

**Шаги:**
1. В browser DevTools → Network — перехватить запрос `/api/subscriptions/digest`, изменить `target=invalid`.

**Ожидаемый результат:**
- Бэкенд возвращает `400 invalidTarget`.
- Тост «Некорректный target».
