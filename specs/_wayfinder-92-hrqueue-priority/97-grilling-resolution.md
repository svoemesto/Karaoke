# #97 Resolution — Семантика приоритезации hrQueue

> **Resolution**: 2026-09-14T17:45Z, после grilling-сессии.
> **Метод**: скилл `grilling` (HITL, 2 раунда по 4 и 2 вопроса).

## Ответы владельца (зафиксированные как правила)

### Q1. Что «всплывает» при возврате на страницу?

**Ответ**: Только текущая страница. Все её оставшиеся задания поднимаются наверх
очереди (включая вытесненные вниз последующими страницами).

**Правило**: при `currentPage` watcher — НЕ `hrQueue = []` (текущее поведение).
Нужно:
- Удалить задания **других** страниц.
- Поднять задания **текущей** страницы наверх очереди (если они там были).

### Q2. Какие данные хранить в элементе очереди?

**Ответ**: `(songId, pageId, filterHash)`. Позволяет:
- Сортировать по приоритету (страница).
- Не запрашивать повторно для того же фильтра (если фильтр не изменился).
- Отслеживать TTL в будущем (если понадобится).

### Q3. Edge cases при изменении фильтра

**Ответ** (custom):
> Если для песни есть задания — они должны оставаться. Просто они будут вытеснены
> в конец и обработаются в последнюю очередь. Зато в следующий раз при обращении
> к этой песне кеш обращений к хранилищам уже будет заполнен.

**Правило**: при смене фильтра НЕ удалять задания. Они остаются, но сдвигаются в конец.

### Q4. Что показывать в бейдже счётчика?

**Ответ**: Всего задач в очереди. (Не только для текущей страницы.)

**Правило**: бейдж показывает `hrQueue.length` — общее число, включая все страницы.

### Q5. TTL для заданий не-текущей страницы?

**Ответ**: Без TTL. Задания живут пока в hrQueue.

**Правило**: удалять задания из очереди только при: (a) успешном fetch,
(b) явном `hrQueue = []` (например, при unmount компонента), (c) смене фильтра
согласно Q3.

### Q6. Polling vs SSE для обновления бейджа?

**Ответ**: SSE (как `countWaiting` в `ProcessWorker.vue`).

**Правило**: НЕ делать polling. Расширить существующий SSE-payload (см. resolution #95):
- Добавить `cacheFiller` блок с `pendingTotal` в существующий `/api/health/cacheStats`
  response (см. #95).
- Добавить SSE-событие `CACHE_FILLER_STATS` (или расширить существующий SSE-канал).
- Бейдж обновляется по SSE.
