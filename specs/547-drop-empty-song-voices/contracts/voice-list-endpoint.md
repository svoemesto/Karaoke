# Контракт: чтение голосов и количества голосов

**Спека**: [../spec.md](../spec.md) (FR-007, FR-010)
**Дата**: 2026-10-20

Форма ответов **не меняется** — меняется только значение числа голосов: после
нормализации оно равно числу реальных голосов (пустые, кроме первого, отсутствуют).

## 1. `POST /api/song/voices` — список голосов для редактора разметки

Владелец: `karaoke-app/.../controllers/ApiController.kt` (`getSongVoices`).

```json
{
  "voices": [
    { "voice": 0, "text": "…", "markers": [ … ], "syllables": [ … ] },
    { "voice": 1, "text": "…", "markers": [ … ], "syllables": [ … ] }
  ]
}
```

- `voices.length` = число голосов песни (после нормализации — без пустых, кроме первого).
- Порядок — по возрастанию `voice` (0..N-1).
- Клиент (`SubsEdit.vue`) строит из этого списка пункты «Голос 1..N» и «Добавить».
- Псевдо-голоса «Добавить» в ответе нет: он добавляется на клиенте.

## 2. `countVoices` в DTO песни

| Место | Поле | Значение |
|---|---|---|
| `SongDTO` (админка) | `countVoices` | число голосов = `sourceMarkersList.size` после нормализации |
| `SongDTOdigest` (дайджест) | `countVoices` | то же |
| Фильтр списка песен | `filterCountVoices` → `filter_count_voices` | сравнивается с числом реальных голосов |

Требование FR-007: после сохранения эти значения совпадают с числом голосов в
`/api/song/voices` и с числом реальных голосов в JSON-колонках.

## 3. Что НЕ меняется

- `POST /api/song` (карточка песни), `POST /api/songs` (список) — форма DTO прежняя.
- Публичные DTO (`SongPublicDto`) — `countVoices` не отдаётся/не меняется по смыслу.
- Рендер-конвейер (`getVoices`) продолжает считать **непустые** голоса; после
  нормализации позиционное индексирование перестаёт «съедать» реальные голоса
  (US3, acceptance 2).

## 4. Проверка контракта

| Проверка | Ожидание |
|---|---|
| `/api/song/voices` для 15696 после сохранения | `voices.length == 1`, маркеры первого = 621 |
| `SongDTO.countVoices` для 15696 после сохранения | `1` |
| Фильтр «Количество голосов» = 1 | песня 15696 попадает в выборку |
