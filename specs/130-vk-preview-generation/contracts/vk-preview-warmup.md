# Contract: VK preview warmup

## Назначение

Контракт описывает существующий HTTP-эндпоинт, который `karaoke-app` использует как синхронный prewarm перед созданием новой публикации во ВКонтакте. Новый внешний VK API-контракт не вводится.

## Запрос

```http
GET {vkPreviewWarmupUrl}{songId}
```

Пример значения `vkPreviewWarmupUrl`:

```text
https://sm-karaoke.ru/api/public/song-vk-image/
```

Требования к запросу:

- `songId` — положительное целое число;
- метод только `GET`, а не `HEAD`, потому что генерация запускается чтением тела;
- автоматическое следование HTTP-редиректам запрещено;
- запрос должен иметь отдельные connect/read timeout из настроек prewarm;
- запрос не содержит VK-токены и секреты.

## Успешный ответ

```http
HTTP/1.1 200 OK
Content-Type: image/png

<ненулевое тело PNG>
```

Ответ считается успешным, если одновременно выполнены условия:

1. HTTP-код равен `200`.
2. Тело непустое.
3. `Content-Type` обозначает PNG или тело успешно декодируется как PNG.
4. Тело не является HTML-страницей или текстом ошибки.

Успешный ответ означает, что `karaoke-web` завершил генерацию и запись кэш-файла до отправки ответа. После этого разрешается перейти к существующей последовательности VK-публикации.

## Неуспешные ответы

| Ответ/событие | Результат prewarm | Дальнейшее действие |
|---|---|---|
| `3xx` | `FAILED` | Не считать fallback-логотип готовым превью; `wall.post` не вызывать |
| `4xx` | `FAILED` | Сохранить причину и завершить попытку без поста |
| `5xx` | `FAILED` после допустимых retry | Сохранить причину; следующий запуск может повторить операцию |
| Тайм-аут/сетевая ошибка | `FAILED` после допустимых retry | Сохранить причину; VK-публикацию не начинать |
| `200` с пустым телом | `FAILED` | VK-публикацию не начинать |
| `200` с неверным MIME/повреждённым PNG | `FAILED` | VK-публикацию не начинать |

Ошибка публикации VK после успешного prewarm должна сохраняться отдельно как ошибка VK API, а не как ошибка preview warmup.

## Обязательный порядок операций

### Публикация без видео

```text
проверки песни и idempotency
  → render шаблона
  → prewarm GET изображения
  → PUBLISHING
  → существующий wall.post с текстом/ссылкой
  → сохранение существующего post id
```

### Публикация с видео

```text
проверки песни и idempotency
  → готовый demo-MP4
  → prewarm GET изображения
  → существующий video.save/upload/wall.post flow
  → сохранение существующего post id
```

Prewarm не меняет текст, ссылку, тип публикации, параметры видео или формат `attachments`.

## Контракт кэша веба

- Ключ: `/tmp/vk_<songId>.png` в контейнере `karaoke-web`.
- При наличии корректного файла веб возвращает его без повторной генерации.
- При отсутствии исходного album/author изображения веб не должен выдавать редирект как успешную готовность превью песни.
- Новое содержимое записывается во временный файл и атомарно заменяет целевой кэш-файл.
- Перезапуск веба может удалить эфемерный кэш; это штатно компенсируется следующим prewarm.

## Наблюдаемость

Минимальная запись результата содержит:

- id песни;
- `SUCCESS`/`FAILED`;
- HTTP-код или класс сетевой ошибки;
- количество попыток;
- длительность;
- размер ответа при успехе.

Секреты, access token и полное тело ответа в логи не записываются.
