# Data Model: 561 — Приватный бакет `stemjobs` и закрытый канал отдачи стемов (BR-258)

Схема БД **не меняется**: `tbl_stem_jobs` не участвует в двуx-БД синхронизации и остаётся
целиком на прод-БД (см. `StemJob.kt`). Ниже — сущности доступа к приватным объектам и
правила их валидации.

## Сущности

### Приватный объект премиум-задания (StemJobResultObject)

| Поле | Тип | Описание |
|---|---|---|
| `bucket` | строка (константа) | `stemjobs` — приватный бакет, bucket policy пустая |
| `key` | строка | `<jobId>/<stem>.<ext>` внутри бакета `stemjobs` |
| `stem` | перечисление | `accompaniment` / `vocals` / `drums` / `bass` / `other` / `original` |
| `ext` | строка | `mp3` для стемов; для `original` — расширение исходной загрузки из `StemJob.originalExt` |
| `sizeBytes` | Long | Размер объекта (для `Content-Length` и журнала) |

Правила валидации:
- `stem` обязан входить в набор стемов режима задания (`StemJobMode.stemNames(mode)`) либо
  быть `original`; иначе — отказ **404** без раскрытия факта существования объекта;
- `ext` обязан входить в `StemJob.ALLOWED_EXTENSIONS` (для `original`) или быть `mp3`
  (для стемов);
- имя файла не содержит `/`, `..` и других разделителей пути — иначе отказ **400**;
- ключ объекта в бакете — **только** `stemjobs/<jobId>/...`; префикс `stemjobs/` внутри
  публичного бакета `karaoke` — устаревшая раскладка, из которой объекты вычищаются.

### Legacy-объект (StemJobLegacyObject)

| Поле | Тип | Описание |
|---|---|---|
| `bucket` | строка (константа) | `karaoke` — публичный бакет (legacy-раскладка до правки) |
| `key` | строка | `stemjobs/<jobId>/<stem>.<ext>` |

Правила валидации:
- существует только для объектов, созданных **до** правки; новые объекты сюда не пишутся;
- удаляются той же уборкой, что и новые (FR-008) — иначе они остались бы анонимно
  читаемыми в публичном бакете до конца своей TTL.

### Каталог результатов на `karaoke-web` (StemJobResultFiles)

| Поле | Тип | Описание |
|---|---|---|
| `root` | путь | `stemjobs.result-dir` (env `STEMJOBS_RESULT_DIR`); по умолчанию `${stemjobs.temp-dir}/results` |
| `jobDir` | путь | `<root>/<jobId>` — каталог одного задания |
| `file` | путь | `<jobDir>/<stem>.<ext>` — рабочая копия приватного объекта |

Правила валидации:
- каталог не публикуется nginx'ом и не отдаётся анонимно — доступ только через
  `PublicStemJobController.download` с проверкой владельца/статуса/TTL;
- срок жизни копии — TTL задания (24 ч) + запас; чистка — `StemJobTempCleanupScheduler`
  и явный `purge` от `karaoke-app`;
- копия — **не** источник истины: источник истины — объект приватного бакета.

### Внутренний секрет канала (StemJobsInternalSecret)

| Поле | Тип | Описание |
|---|---|---|
| `value` | строка | Значение, одинаковое на отправителе и получателе |
| `configured` | булево | Признак, что значение задано и непустое |

Правила валидации:
- значение **не** хранится в репозитории и не попадает в сборку: `karaoke-web` —
  env `STEMJOBS_INTERNAL_SECRET`; `karaoke-app` — свойство `stemJobsInternalSecret`
  в `Karaoke.properties`;
- пустое значение = «секрет не настроен» → доступ закрыт **всегда** (fail-safe): сравнение
  выполняется только при непустом настроенном значении, поэтому «пустой секрет + пустой
  заголовок» канал **не** открывает;
- значение не попадает в журналы и не возвращается в ответе.

### Политика публичности бакета (BucketPolicyState)

| Поле | Тип | Описание |
|---|---|---|
| `bucket` | строка | Имя бакета (`stemjobs` / `karaoke`) |
| `policy` | перечисление | `private` (пустая bucket policy) / `public` (`s3:GetObject` на весь бакет) |

Правила валидации:
- `stemjobs` → **private** всегда; применяется программно при старте `karaoke-app`
  (FR-006), а не вручную в консоли MinIO;
- `karaoke` → **public** (публичная часть сайта раздаётся анонимно, FR-002); действующая
  политика при этом **не меняется** — `setBucketPublic` записывает ровно ту же, что и сейчас.

## Отношения

- Один `StemJob` → от 1 (`original`) до 6 (`original` + 5 стемов) `StemJobResultObject`.
- `StemJobResultObject` имеет **две** репрезентации: объект в приватном бакете
  (источник истины) и рабочая копия в каталоге результатов `karaoke-web` (выдаётся
  владельцу). Обе живут не дольше TTL задания.
- `StemJobLegacyObject` связан с `StemJob` тем же идентификатором; существует только для
  заданий, созданных до правки.
- Внутренний секрет — один на пару «`karaoke-app` ↔ `karaoke-web`»; значения совпадают с
  уже работающим каналом `/raw` и `/ack`.

## Изменения схемы

Отсутствуют: миграции БД не требуются (Constitution II, FR-008 — TTL/уборка сохраняются,
транзакционность применения SQL — вне задачи, BR-012).
