# `.scratch/karaoke/` — рабочий слой процесса «wayfinder → исполнение»

Каталог — рабочий слой командного процесса: карты решений (wayfinding) и
локальные issue-задачи исполнения. Живые инструкции процесса —
`~/.dsh/romario-team/` (`wayfinding-operations.md`, `subagents.md`,
`issue-tracker.md`); SSoT-репозиторий команды — `agents-team-srv`.

Это НЕ замена трекеру проекта: OpenProject (`tools/tracker.sh`) продолжает
работать по своим правилам (`AGENTS.md` § «OpenProject Workflow»), а
`.scratch/` — слой процесса команды (решения и локальные issue).

## Раскладка

- Карта решений усилия: `.scratch/karaoke/wayfinding/<усилие>/map.md`
- Тикеты-решения усилия: `.scratch/karaoke/wayfinding/<усилие>/issues/NN-<slug>.md`
- Issue-задачи исполнения: `.scratch/karaoke/issues/issues_NNNN.md`
  (создаются только для «больших» работ)

## Процесс (коротко)

1. Большая туманная задача → **wayfinder**: карта решений, по одному тикету за
   сессию (скилл включается вручную).
2. Карта закрыта → лид классифицирует остаток работы (большая/маленькая),
   **решает владелец**.
3. **Маленькая** — лид делает сам; спека не нужна.
4. **Большая** — issue-задача здесь → `speckit-specify` → спека уходит владельцу
   → **СТОП** → по слову владельца долгоживущий субагент ведёт
   `speckit-plan → speckit-tasks → speckit-analyze → speckit-implement`,
   лид ревьюит каждый шаг по фактам с диска.
5. Спека — контракт: правки FR/SC — только словом владельца.

Формат тикетов и операции (claim / frontier / туман / вне скоупа) — в
`~/.dsh/romario-team/wayfinding-operations.md`; классификация задач, запуск
долгоживущего субагента, ревью лида и закрытый список докладов владельцу — в
`~/.dsh/romario-team/subagents.md`.
