# Research: «5 причин зарегистрироваться» на главной (QW-2)

**Branch**: `004-reasons-to-register` | **Phase**: 0 | **Date**: 2026-07-25

## Decision 1: Нет дизайна «classic/modern» — только одна `HomeView.vue`

**Decision**: FR-006/FR-009 из `spec.md` («Dual classic/modern — обе версии,
`views/classic/`, `views/modern/`») трактуются как устаревшая формулировка;
блок реализуется один раз в едином `karaoke-public/src/views/HomeView.vue`.

**Rationale**: проверено чтением исходников — `karaoke-public/src/views/`
не содержит директорий `classic/`/`modern/` (`find` не находит ничего).
`localStorage.km-design` (упомянутый в JSDoc-комментарии самой `HomeView.vue`,
строка 124) нигде не читается ни в одном файле проекта (`grep -rn "km-design"`
— только этот один комментарий). Единственный реальный переключатель —
`useDesign()` (`composables/useDesign.js`), который управляет **light/dark
темой** (`data-theme` атрибут), а не «classic vs modern» layout'ом. Тот же
вывод уже был сделан в `specs/003-about-page/research.md` про `AboutView.vue`
— это системная, не-точечная неточность в старых спеках/комментариях.

**Alternatives considered**: создать `views/classic/HomeView.vue` +
`views/modern/HomeView.vue`, как буквально написано в FR-009 — отклонено:
создало бы несуществующую архитектуру ради соответствия устаревшему тексту
спеки, увеличило бы объём работы в 2 раза без реальной необходимости (сайт
уже давно работает с одной `HomeView.vue`).

## Decision 2: Пункт 5 «Скидка -10%» заменён на «Бесплатно — без карты»

**Decision** (согласовано с пользователем 2026-07-25): вместо «🏷️ Скидка -10%
— На первую премиум-подписку при регистрации» — «🆓 Бесплатно — без карты» /
«Регистрация бесплатна, банковская карта не нужна».

**Rationale**: в коде есть механизм скидки для новых пользователей
(`PromoRule.TYPE_NEW_USER_PERCENT`, обрабатывается в
`karaoke-web/.../PriceService.kt`), но это **настраиваемая администратором
запись** в `tbl_promo_rules` (`deploy/karaoke-db/15_monetization.sql`), не
гарантированно активная прямо сейчас. Публичного REST-эндпоинта для проверки
«есть ли сейчас активное `NEW_USER_PERCENT`-правило» нет
(`grep -rn "promo" .../controllers/*.kt` не находит `@GetMapping` с `api/public`).
Показывать пользователю конкретное число «-10%» без проверки реальной
активности акции — риск рекламировать то, чего может не быть (см. открытый
вопрос №3 в исходном `spec.md`, который сам явно предупреждает об этом же).
«Бесплатно — без карты» — факт, истинный всегда, ничего проверять не нужно.

**Alternatives considered**:
- Оставить «-10%» как в исходной спеке — отклонено пользователем явно.
- Смягчить формулировку до «Скидка на первую подписку» без цифры — тоже
  отклонено пользователем: всё ещё подразумевает существование активной акции,
  за которую сложно ручаться.
- Добавить backend-эндпоинт `GET /api/public/promo/active` для динамической
  проверки — отклонено: расширяет скоуп фичи (новый backend-код) ради одной
  строки текста в блоке из 5 карточек; если понадобится показывать реальные
  промо-акции на сайте — это отдельная фича (в духе QW-4/QW-8 из
  `growth.md`), не часть QW-2.

## Decision 3: Место вставки — между `.km-desc` и `.km-nav-cards`

**Decision**: новая секция вставляется в `HomeView.vue` сразу после блока
`<p class="km-desc">` (описание коллекции) и перед `<div class="km-nav-cards">`
(навигационные карточки).

**Rationale**: совпадает с рекомендацией самой spec.md (открытый вопрос №4:
«рекомендую под счётчиками, перед навигационными карточками»). Логика чтения
страницы: логотип → статистика → короткое описание → «зачем регистрироваться»
→ куда идти дальше (каталог/поиск/премиум/о проекте). Блок «причин» —
естественный мостик между «что это» (счётчики+описание) и «куда идти»
(нав-карточки).

**Alternatives considered**: над счётчиками (сразу под hero) — отклонено,
статистика — первое, что должно убедить в масштабе коллекции, ценностное
предложение регистрации логичнее после того, как посетитель уже впечатлился
цифрами.

## Decision 4: Реализация без нового компонента

**Decision**: блок — это разметка + небольшой JS прямо в `HomeView.vue`
(hardcoded массив 5 карточек в `data()`, computed `showReasonsBlock` на
`!isLoggedIn`), без выделения в отдельный `.vue`-компонент.

**Rationale**: контент статический, используется только в одном месте
(в отличие от `SocialLinks.vue`/`ShareButton.vue` из `003-about-page`,
которые переиспользуются в нескольких местах или инкапсулируют нетривиальную
логику). Выделение в отдельный компонент ради единственного места
использования — не оправданная абстракция (см. правило проекта «не вводить
абстракции сверх необходимого»).

**Alternatives considered**: `ReasonsBlock.vue` как отдельный компонент —
отклонено по вышеуказанной причине; можно выделить позже, если блок
понадобится на других страницах (например, `AboutView.vue`) — не в скоупе
этой фичи.
