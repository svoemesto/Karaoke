# Feature Specification: Новости — пагинация над таблицей, не больше 35 строк на страницу

**Feature Branch**: `093-news-pagination-top-35`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "Админка, компонент «Новости». Пагинация должна быть над таблицей, а не под ней. На каждой странице должно быть не больше 35 строк."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Администратор листает новости с пагинацией над таблицей (Priority: P1)

Администратор открывает раздел «Новости» в админке (`webvue3`) и видит таблицу со списком новостей. Элемент управления пагинацией (кнопки/ссылки перехода между страницами, индикатор текущей страницы и общего количества страниц/записей) расположен **над** таблицей, а не под ней. На каждой странице — не больше 35 строк. Поведение «создание / редактирование / удаление / переключение LOCAL↔REMOTE / переход на конкретную страницу» остаётся таким же, как сегодня.

**Why this priority**: Текущая компоновка заставляет администратора скроллить вниз страницы к подвалу таблицы, чтобы переключиться на следующую страницу, что неудобно при большом объёме (19000+ строк) и особенно при работе в верхней части таблицы (создание новой записи, просмотр последних новостей). Элементы пагинации над таблицей — стандартный UX-паттерн для админских таблиц; ограничение размера страницы 35 строками укладывает порцию в один экран ноутбука и снижает нагрузку на рендер DOM (19000 строк были бы избыточны, а лишние страницы по 50 строк — компромисс, который администратор явно пересматривает сейчас).

**Independent Test**: Открыть раздел «Новости» в админке `webvue3` на стенде с >=100 новостями в `tbl_news` (на проде таких 19000+) — переключатель страниц виден до прокрутки (в верхней части блока таблицы); при количестве строк >35 элемент пагинации показывает более одной страницы; при количестве строк <=35 элемент пагинации либо скрыт, либо показывает единственную страницу; размер каждой страницы (число строк таблицы) — не более 35.

**Acceptance Scenarios**:

1. **Given** в `tbl_news` есть >=36 новостей и администратор открывает раздел «Новости», **When** он смотрит на верхнюю часть блока таблицы (без прокрутки страницы вниз), **Then** он видит элемент управления пагинацией, позволяющий перейти на следующую/предыдущую/конкретную страницу и показывающий текущую страницу и общее число страниц/записей.
2. **Given** администратор находится на странице N, **When** он переключается на страницу N+1 или вводит конкретный номер страницы, **Then** таблица перерисовывается и показывает следующий набор строк без дублей/пропусков, и элемент пагинации остаётся в верхней части блока таблицы (не уезжает вниз).
3. **Given** в `tbl_news` есть >=36 новостей, **When** открывается страница раздела, **Then** в верхнем элементе пагинации суммарное число страниц соответствует размеру страницы 35 (т.е. `ceil(totalCount / 35)` страниц), и каждая страница отображает не более 35 строк таблицы.
4. **Given** в `tbl_news` <=35 новостей, **When** открывается раздел, **Then** таблица показывает все новости, и элемент пагинации либо скрыт, либо показывает единственную страницу без лишних/недоступных элементов перехода.
5. **Given** администратор создаёт/редактирует/удаляет новость или переключает целевую БД (LOCAL/REMOTE), **When** список перезагружается, **Then** размер страницы остаётся 35, элемент пагинации остаётся над таблицей, и состояние «текущая страница» ведёт себя так же, как сегодня (сброс на первую страницу при смене целевой БД, перезапрос на бэкенд при смене номера страницы).

---

### Edge Cases

- Что если 0 новостей? Элемент пагинации скрывается (как и сейчас — пустая таблица + сообщение «Пока новостей нет» или эквивалент), таблица не рендерит 35 пустых строк.
- Что если общее число новостей не делится на 35 нацело (например, 73 строки)? Последняя страница содержит остаток (8 строк), и пагинация корректно отражает число страниц (3). Никаких лишних пустых строк-заглушек в последней странице.
- Что если администратор вручную подставляет номер страницы больше существующего (например, через состояние стора)? Бэкенд возвращает пустой список и `totalCount`, фронт показывает пустую таблицу без падения; элемент пагинации остаётся видимым и отражает фактическое число страниц.
- Что с мобильной/узкой вёрсткой (узкий экран)? Положение пагинации «над таблицей» сохраняется; если элемент пагинации не помещается в одну строку — он переносится (поведение `<b-pagination size="sm" align="center">` по умолчанию), а не «уезжает» вниз под таблицу.
- Что с уже реализованной пагинацией из `specs/090-news-pagination`? Никаких изменений в серверной части (Kotlin-контроллер, SQL `LIMIT/OFFSET`/`COUNT`, публичный `karaoke-public`) — фича правит только UI админки `webvue3` и значение `perPage` в её Vuex-сторе.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В компоненте «Новости» админки (`webvue3/src/components/News/NewsTable.vue`) элемент управления пагинацией MUST располагаться над таблицей `<b-table>`, а не под ней.
- **FR-002**: Размер страницы (число строк таблицы на одну порцию) MUST быть не больше 35. Конкретное значение по умолчанию — 35.
- **FR-003**: Поведение перехода между страницами, перезапроса бэкенда, переключения целевой БД (LOCAL/REMOTE), создания/редактирования/удаления новости MUST остаться таким же, как после реализации `specs/090-news-pagination` (без регрессии).
- **FR-004**: Значение `perPage` MUST быть единым для всех страниц в рамках одной сессии администратора в админке (то есть настраивается как дефолт в сторе, а не как `v-model` для пользователя).
- **FR-005**: Суммарное число страниц в элементе пагинации MUST соответствовать размеру страницы 35 (т.е. `ceil(totalCount / 35)`).
- **FR-006**: При отсутствии новостей (0 строк) элемент пагинации MUST быть скрыт или не показывать лишних/недоступных элементов перехода (эквивалентно текущему поведению `<b-pagination>` при `total-rows=0`).
- **FR-007**: Серверная часть (Kotlin-контроллер `NewsController`, модель `News`, публичный `PublicNewsController`, `karaoke-public`) MUST остаться без изменений — фича правит только UI админки `webvue3` и значение `perPage` в её Vuex-сторе.

### Key Entities

- **Новость (News)**: уже существующая сущность, без структурных изменений в этой фиче. Меняются только: положение элемента пагинации в UI и значение `perPage` в Vuex-сторе `webvue3/src/components/News/store.js`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В разделе «Новости» админки `webvue3` элемент пагинации виден в верхней части блока таблицы (выше первой строки таблицы) без необходимости прокрутки страницы вниз, при объёме `tbl_news` >=36 строк.
- **SC-002**: При объёме `tbl_news` = 100 строк суммарное число страниц в элементе пагинации равно 3 (100 / 35 = 2.86 → 3 страницы), и каждая страница содержит не более 35 строк таблицы.
- **SC-003**: При объёме `tbl_news` = 0 строк элемент пагинации скрыт (или не показывает лишних элементов), таблица не содержит 35 пустых строк.
- **SC-004**: Создание, редактирование, удаление новости и переключение целевой БД (LOCAL ↔ REMOTE) продолжают работать без регрессий; размер страницы остаётся 35; элемент пагинации остаётся над таблицей после каждой такой операции.

## Assumptions

- Под «не больше 35 строк» понимается ровно 35 как значение по умолчанию (наибольшее допустимое значение; не делаем UI-селектор «10/20/35/50» в рамках этой фичи, если администратор не запросит явно).
- Положение «над таблицей» означает непосредственно перед первым рядом таблицы внутри блока `.news-table-body` (или в непосредственной близости от него) — конкретная DOM-структура/обёртка решается на этапе реализации, спецификация фиксирует только относительное положение «выше, а не ниже».
- Существующая пагинация (`specs/090-news-pagination`) реализована на сервере и в публичной части — эта фича не дублирует и не пересобирает её, а только правит UI админки и значение `perPage`. Бэкенд-параметр `pageSize` (или эквивалент) уже принимает нужное значение через Vuex-стор.
- Администратор использует десктопный/ноутбучный экран; специальная мобильная вёрстка (например, дублирование пагинации сверху и снизу для длинных таблиц) не входит в объём этой фичи, если администратор не запросит явно.
