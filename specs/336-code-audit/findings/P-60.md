## Сверки

1. **BR-195 / P-20 — кеш Stats без параметров.** `StatsController.respondCached` строит ключ `StatsCacheKey(endpoint, emptyMap())` (`StatsController.kt:78`) — без `target`, `days`, `mode`. Поэтому после переключения «БД» (local/remote) или периода в `StatsView` компоненты этой порции (`KpiCards`, `MonetizationPanel`, `GeoReferrers`, `TimeSeriesChart`, `DetailBreakdown`) до 60 с показывают цифры другого источника; фронтенд добавляет свой 60-секундный TTL (`Stats/store.js:107–110, 236`, `StatsView` `lastLoadedAt`). Новый BR не завожу — корень уже в `BR-195`; здесь только поверхности отображения. Отдельно: подписи компонентов не показывают, к какой БД/периоду относятся цифры, поэтому «чужие» данные выглядят текущими.
2. **`setWebvueProp` на каждое нажатие клавиши — `Songs/filter/store.js:203–325`.** Каждая мутация фильтра пишет `POST /api/setwebvueprop` (`lib/utils.js:57–66`) — тот же механизм, что `BR-366` (P-51-04, Albums) и P-52 «Сверки» 4/6; в этой порции добавляются: 28 последовательных `getWebvueProp` + 28 POST при открытии модалки (`SongsFilterModal.vue:752–837`), 28 повторных POST в `ok()` (`:846–893`) и ещё 26 POST в `onRowClicked` + 28 в `ok()` на клик по строке истории. Дублировать записью не стал; если лид считает паттерн дефектом — это ещё одна локация (файловое семейство `Songs/filter`).
3. **`window.open(this.resultLink, '_blank')` без `noopener` — `SearchText.vue:206`.** Ссылка приходит из результатов поиска (внешние сайты). Обратная tabnabbing-поверхность, но доказанного пути «атакующий контролирует URL результата» нет; ровно та же картина уже зафиксирована в P-28 «Сверки» 5 и P-52 «Сверки» 7. Severity не ставлю; при правке — `window.open(url, '_blank', 'noopener,noreferrer')` и проверка схемы http(s).
4. **`this.close` без вызова — `SearchText.vue:275`.** В `doSearchTextForSong` стоит `this.close` (ссылка на метод, не вызов): после подтверждения первого поиска модалка не закрывается и продолжает показывать «Асинхронный поиск еще не готов, попробуйте позже» (`:62`), хотя поиск уже запущен. Влияние только на UX (пользователь закрывает вручную), данных не касается — по §2 рубрики в находки не включаю. Автор: nsa, 2026-04-08, `1d7de1d0` (`git blame --ignore-rev 4cd50b9f`).
5. **`navigator.clipboard.writeText` без `catch`/fallback — `SearchText.vue:221–223`, `WhisperDebugModal.vue:112–114`.** Вне secure context (админка открыта по `http://<ip>:7906`, а не `localhost`) или при отказе в разрешении промис отклоняется, копирование не происходит, ошибки пользователь не видит; в `SearchText.copyAndClose` модалка при этом закрывается — текст теряется. Для штатного `localhost:7906` (secure context) путь не доказан, поэтому без severity.
6. **`SongEventsModal` показывает `events` без сверки с `song.songId`.** При отказе `/api/stats/song-events` store сохраняет события предыдущей песни (`Stats/store.js:513–525`, `catch` только `console.log`), а `StatsView.openSong` (`:927–938`) не очищает `songEvents` перед загрузкой — модалка отрисует старые события под новым названием. Корень — в store/StatsView (порции P-64/P-67), здесь не дублирую.
7. **Гонка гидратации фильтров.** `beforeMount` (`SongsFilterModal.vue:752–837`) выполняет 28 последовательных `await getWebvueProp` уже после первого рендера: ввод пользователя в поле, которое гидратируется позже, будет перезаписан серверным значением. Окно — сумма RTT; тот же вопрос уже поднят в P-52 «Сверки» 4 (guard «не сохранять, пока состояние не гидратировано»), отдельной записи не завожу.
8. **`v-text` в `<textarea>` — `WhisperDebugModal.vue:15, 23, 31`.** В проекте зафиксировано, что `v-text` не задаёт `.value` textarea (`SearchText.vue:36–43`, OP#51). Здесь текстарии монтируются только после `isLoading=false`, когда данные уже присвоены, и после этого не обновляются, поэтому достижимого «пустого» отображения не нашёл; если модалку начнут обновлять на лету — заменить на `:value`.
9. **`cap` в `SongEventsModal` не используется** (`SongEventsModal.vue:115`; родитель передаёт `songEventsPageSize`, `StatsView.vue:328`) — мёртвый проп без риска (§2).
10. **Drill-down `DetailBreakdown` ограничен `limit 60` бэкенда.** `/api/stats/by-detail` возвращает только топ-60 комбинаций (`StatBySong.kt:1114`), поэтому клик по типу, чьи строки не попали в топ, даёт «Нет данных» при непустом by-type. Корень — бэкенд (P-11/P-20), не дублирую.
