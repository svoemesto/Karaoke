# Component: song-artifact-ownership

> **Домен**: [catalog](../domain.md)
> **Компонент**: правило владения артефактом песни — строгое (для удаления песни)
> и нормализованное (для разовой уборки). Единый модуль для обеих операций.

## Ответственность | Responsibility

Компонент отвечает на вопрос **«чей этот файл / этот объект хранилища?»** — и
отвечает на него **одним кодом** для всех операций, которые что-то удаляют.

Правило реализовано в одном месте:
`karaoke-app/src/main/kotlin/com/svoemesto/karaokeapp/services/songdeletion/SongArtifactOwnership.kt`.

Правило совпадает с правилом переименования артефактов
([complete-song-rename](../../../product/features/complete-song-rename.md),
`SongArtifactRenamer.isArtifactContinuation`): если правила разойдутся, песня,
чьи файлы удалены, при следующем переименовании получит «сиротские» файлы.

## Интерфейсы и Контракты | Interfaces and Contracts

### Строгое правило (удаление песни)

`isOwnArtifact(songFileName, candidateName)`:

| Условие | Результат |
| --- | --- |
| имя начинается с имени файла песни **с точным регистром** | обязательное |
| остаток имени — продолжение артефакта: пусто, `.расширение`, `-суффикс`, ` [метка]` | обязательное |

Строгость значит: `песня.mp3` при песне `Песня`, `Пёсня.mp3`, `«Песня».mp3`,
`Песня 01.mp3` (при песне `Песня`) — **чужие** файлы. Near-match по нормализации
никогда не признаётся своим.

### Нормализованное правило (разовая уборка)

`normalizeForMatch(name)` приводит имя к сравнимому виду: регистр, `ё`/`е`,
тип кавычек, ведущие нули в числах (`01` → `1`), лишние пробелы.

`isNearMatchOfLiveSong(liveNormalizedNames, candidateName)` отвечает на обратный
вопрос — «не принадлежит ли это живой песне?» — и используется разовой уборкой,
чтобы **исключить** объект из перечня кандидатов на удаление.

### Правило для объектов хранилища

`isOwnStorageKey(author, year, album, songFileName, key)`:

- ключ начинается с `$автор/$год - $альбом/`;
- остаток — имя песни + продолжение артефакта;
- второй рубеж: ключ общей обложки альбома/автора не проходит.

Обложка альбома и картинка автора начинаются с другого префикса, поэтому
отсекаются структурно, а не «списком исключений».

## Логика и Алгоритмы | Logic and Algorithms

### Обход папки песни

`collectOwnArtifacts(rootFolder, songFileName)` обходит корень папки альбома и
подкаталоги артефактов: `hdemucs_mmi`, `done_files`, `done_chords`, `sheetsage`
и все каталоги `symlink_*` — и возвращает только файлы песни.

`collectFilesToDelete(...)` возвращает то, что будет удалено: те же файлы, но
**без живых симлинков** (битый симлинк удаляется, живой — остаётся).

### Где применяется

| Операция | Правило | Последствие |
| --- | --- | --- |
| Удаление песни | строгое | чужая песня с похожим именем не удаляется никогда |
| Предпросмотр удаления | строгое (тот же код) | показанные числа совпадают с фактом (расхождение 0) |
| Разовая уборка | нормализованное | объект живой песни исключается из кандидатов |

## Инварианты | Invariants

1. Обе операции владения реализованы **одним модулем** — второй копии правил
   быть не может (иначе предпросмотр разойдётся с уборкой, а разовая уборка
   однажды снесёт чужую песню).
2. Строгое правило **никогда** не опирается на нормализацию.
3. Вердикты реестра уборки (`PROTECTED`/`KEEP`,
   [dictionaries](dictionaries.md)) при удалении песни **не применяются**:
   удаляются в том числе исходники и файлы проектов рендера.
4. Общие обложки альбома и автора не удаляются с песнёй.

## Зависимости | Dependencies

- [catalog](../domain.md) — владелец правила; компонента работает с сущностями
  `Song`, `Album`, `Picture`.

- [health](../../health/domain.md) — модель «файл песни × локация», на которую
  опирается обход папки.
- `SongArtifactRenamer` (`karaoke-app/.../model/SongArtifactRenamer.kt`) — правило
  продолжения артефакта, общее с переименованием.
- `StorageCacheReset` (`karaoke-app/.../StorageCacheReset.kt`) — формулы имён
  файлов песни в хранилище.

## Ловушки | Pitfalls

- **Папка альбома общая для всех песен альбома.** «Удалить файлы песни» — это
  удаление по префиксу имени, а не удаление папки.
- **Переименование песни не переносит ключи в хранилища.** Старые ключи
  остаются; из-за этого у каждой песни должна быть история прежних имён
  (`tbl_song_name_history`), иначе её объекты под старыми именами не удалятся.
- **Near-match ≠ свой.** Совпадение по нормализации — это повод НЕ удалять
  объект, а не повод удалить.
