## Что осталось (не делалось намеренно)

1. **Перезагрузка страницы** владельцем — без неё браузер работает на старом
   бандле: `shell.overlay` ещё не содержит `forgejo-ci-toasts`.
2. **Живой toast** — нужен прогон, который завершится при открытой странице;
   текущий #33 терминален и по гейту FR-013 уведомления не даёт.
3. **Снятие/возврат плагина** (T045) — делает лид через `plugin_manager`.
4. **Подтверждение владельцем** панели (SC-006).
5. **Трекер**: `add-comment KARAOKE-305` → `mark-review` — после приёмки (T042).
6. **Уборка** временного `GIT_ASKPASS` (T043).

## Отклонения и честные находки

1. **`output.schema` ≠ `state.schema`.** Активация падала на подмножестве JSON
   Schema: харнесс не принимает `$schema`/`$id`/`format`/`minLength`/`minimum`/
   `maxItems` и массивы в `type`, а `enum` запрещён рядом с `oneOf`. Введён
   `lib/output.schema.json` — проекция; `enum` ошибки выражен ветвями `oneOf`
   (строка с `enum` + `null`). Полный контракт остался контрактом для маршрута,
   клиента и спеки.
2. **Дефект `trustedTasks`.** Устаревшие `running`-задачи завершённого прогона
   (19 из 25 у #33) поднимали `runner.state` до `running`: панель показывала
   работающий CI при упавшем прогоне. Исправлено гейтом по последнему прогону,
   покрыто регрессом и зеркальным тестом.
3. **Коммит `76c8b16` ушёл с падающим тестом** — не был проверен код выхода
   `node --test`. Исправлено в `e6d5e20`; с этого момента каждый доклад и коммит
   сопровождается строкой `node --test → exit=…`.
4. **`actions/tasks` врёт у завершённого прогона** (держит `running`) и не умеет
   фильтровать по прогону: строка «сейчас бегут» живёт только при активном
   последнем прогоне и скрывается, если сам эндпоинт отказал.
5. **Пурж истории в Forgejo** (4 прогона → 1 за 40 минут) потребовал кольцевого
   буфера в памяти; после перезапуска DSH история пустеет — записано в README.

## Известные ограничения (перенесены в README плагина)

- история прогонов живёт в памяти процесса; после перезапуска DSH пуста;
- разбивки «прогон → джобы» нет; строка очереди — только последний активный
  прогон и только пока `actions/tasks` отвечает;
- ручной запуск workflow и джоб-логи недоступны — плагин только читает;
- если Forgejo не отдал `created`/`updated`, подставляется время наблюдения;
- частота обновления панели — 15 с (чтение кеша), `pollMs` управляет опросом
  Forgejo.
