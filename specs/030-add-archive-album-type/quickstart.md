# Quickstart: Добавить тип альбома «Архивные записи»

**Phase 1 output for**: `030-add-archive-album-type`
**Date**: 2026-07-29
**Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Data Model**: [data-model.md](./data-model.md) | **API**: [contracts/api.md](./contracts/api.md)

## Цель

Ручная end-to-end проверка фичи в 6 сценариях. Все сценарии
выполняются на admin-машине после деплоя. Полное прохождение — ~20 минут.

## Prerequisites

- ADMIN-машина с `karaoke-app` (запущен), `karaoke-web` (запущен),
  `webvue3` (запущен).
- Доступ к LOCAL-БД (psql / pgAdmin / DBeaver).
- Браузер: открыт `http://localhost:8080/admin` (или порт `webvue3`).
- Браузер: открыт `http://localhost:8081` (или порт `karaoke-public`).
- Рекомендуется: открыть `https://svoemesto.ru` (прод) в соседней
  вкладке для сравнения с эталоном.

## Setup

```bash
# 1. Подтянуть изменения (если ещё не сделано)
cd ~/Karaoke
git pull

# 2. Пересобрать бэкенд
cd deploy && bash do.sh build_app

# 3. Перезапустить karaoke-web
cd deploy && bash do.sh build_start_web

# 4. Пересобрать webvue3
cd webvue3 && npm run build
# Или через Docker: cd deploy && bash do.sh build_start_public

# 5. Проверить, что все контейнеры поднялись
docker ps | grep -E "karaoke-app|karaoke-web|webvue3"
```

## Сценарии

### Сценарий 1: В админке доступен тип «Архивные» (FR-004, FR-001)

**Цель**: убедиться, что после релиза в webvue3 появилась опция
«Архивные» в выпадающем списке типа альбома.

**Шаги**:
1. Открыть `http://localhost:8080/admin` → раздел «Альбомы».
2. Двойной клик по любому альбому (например, id=1).
3. В открывшейся форме найти поле «Тип альбома» (inline-`<select>`
   в ячейке таблицы или в модалке редактирования).
4. Раскрыть выпадающий список.

**Ожидаемый результат**:
- В списке 6 опций: «Студийный», «Сингл», «Концертный», «Сборник»,
  «Бутлег», **«Архивный»** (новое).
- По умолчанию для нового альбома — «Студийный» (как и было).

**Проверка SC-003**: выбрать «Архивный», нажать «Сохранить»,
переоткрыть альбом — в списке снова «Архивный».

### Сценарий 2: В SQL сохранено `album_type = 'archive'` (SC-003)

**Цель**: убедиться, что новое значение корректно пишется в БД.

**Шаги**:
1. В сценарии 1 сохранить альбом с типом «Архивный».
2. Открыть psql:
   ```bash
   psql -h localhost -U karaoke -d karaoke
   ```
3. Выполнить:
   ```sql
   SELECT id, name, year, album_type
   FROM tbl_albums
   WHERE album_type = 'archive';
   ```

**Ожидаемый результат**: ≥1 строки (только что сохранённый альбом).

**Дополнительно** (sync):
```sql
-- Проверить, что recordhash одинаковый на LOCAL и SERVER (если есть):
SELECT id, recordhash FROM tbl_albums WHERE id = <сохранённый id>;
-- Повторить на SERVER-БД; результат должен совпадать.
```

### Сценарий 3: Фильтр в админке работает (FR-003, SC-002)

**Цель**: убедиться, что в модалке фильтра таблицы «Альбомы»
появилась опция «Архивные» и она фильтрует корректно.

**Шаги**:
1. В `webvue3` → раздел «Альбомы» → кнопка «Фильтр».
2. В модалке фильтра в поле «Тип альбома» выбрать «Архивный».
3. Нажать «Применить».

**Ожидаемый результат**:
- Таблица показывает только альбомы с `album_type = 'archive'`.
- Счётчик у кнопки фильтра = количество альбомов этого типа в БД.
- Снять выбор — таблица возвращается к полному списку.

**Проверка SC-002**:
```sql
-- Сравнить с БД:
SELECT COUNT(*) FROM tbl_albums WHERE album_type = 'archive';
-- Должно совпадать с количеством строк в таблице после фильтра.
```

### Сценарий 4: На Закромах (karaoke-public) появился раздел «Архивные записи» (FR-005, SC-001)

**Цель**: убедиться, что публичный фронт отображает новый раздел.

**Шаги**:
1. Выбрать исполнителя, у которого **есть** хотя бы 1 альбом с
   `album_type = 'archive'` (например, id=1, который только что
   сохранили).
2. Открыть `http://localhost:8081/zakroma/<author_id>` (или
   эквивалентный URL).
3. Прокрутить страницу вниз.

**Ожидаемый результат**:
- Внизу страницы виден заголовок **«Архивные записи»** (после
  «Бутлеги»).
- Под заголовком — 1 альбом (тот, что проставили в сценарии 1).
- Альбом помечен каноническим лейблом «Исторические/архивные
  записи» (из DTO `albumTypeLabel`).

**Проверка SC-001**: альбом с `album_type = 'archive'` НЕ
отображается в разделах «Студийные», «Синглы», «Концертные»,
«Сборники» или «Бутлеги» (только в «Архивные записи»).

**Контр-сценарий**:
1. Выбрать исполнителя, у которого НЕТ альбомов с
   `album_type = 'archive'`.
2. Открыть его Закрома.

**Ожидаемый результат**: раздел «Архивные записи» НЕ отображается
(пустые разделы скрыты).

### Сценарий 5: Backward compat — старые/невалидные значения (SC-005, FR-006)

**Цель**: убедиться, что фича не ломает обратную совместимость.

**Шаги**:
1. В psql выполнить:
   ```sql
   -- Запись с пустым album_type (старая запись до введения типов):
   SELECT id, name, album_type
   FROM tbl_albums
   WHERE album_type IS NULL OR album_type = ''
   LIMIT 5;
   ```
2. Открыть Закрома для автора одной из таких записей.
3. Также проверить нестандартное значение:
   ```sql
   -- Записать вручную нестандартное значение:
   UPDATE tbl_albums
   SET album_type = 'unknown_type_for_test'
   WHERE id = <some_other_id>;
   -- Открыть Закрома — альбом должен попасть в «Студийные альбомы»
   -- (default), не упасть с ошибкой.
   -- Затем вернуть:
   UPDATE tbl_albums SET album_type = 'studio' WHERE id = <some_other_id>;
   ```

**Ожидаемый результат**:
- Альбомы с `album_type = ''` или `NULL` отображаются в
  «Студийные альбомы» (default).
- Альбомы с `album_type = 'unknown_xxx'` отображаются в
  «Студийные альбомы» (default через `fromDb()`).
- Нет 500-ошибок, нет падений.

**Проверка FR-006**: `AlbumType.fromDb(null)` возвращает `STUDIO`,
`fromDb("archive")` возвращает `ARCHIVE`. Можно проверить через
Kotlin REPL или тестовый endpoint, но проще — по поведению UI
(см. сценарий 4).

---

### Сценарий 6: Sync LOCAL↔SERVER (SC-004, FR-008)

**Цель**: убедиться, что запись с `album_type = 'archive'`
синхронизируется между LOCAL и SERVER без ошибок.

**Шаги**:
1. На LOCAL-админке создать новый альбом с типом «Архивный» (или
   проставить существующему).
2. В webvue3 → раздел «Sync» → «Альбомы» → «Push» (или
   эквивалентный one-click flow).
3. Дождаться окончания.
4. На SERVER-БД выполнить:
   ```sql
   SELECT id, name, album_type
   FROM tbl_albums
   WHERE album_type = 'archive';
   ```

**Ожидаемый результат**:
- В SERVER-БД видна запись с `album_type = 'archive'`.
- В логах sync НЕТ ошибок, связанных с album_type.
- recordhash на LOCAL и SERVER одинаковый (проверить через
  `tbl_albums.recordhash`).

**Проверка FR-008**: `recordhash`-функция работает без изменений
(строки хешируются посимвольно, без whitelist значений).

## Регрессии

После прохождения всех 6 сценариев убедиться, что **не сломано**:

- [ ] Альбомы с `album_type = 'studio'` отображаются в
      «Студийные альбомы» на Закромах.
- [ ] Альбомы с `album_type = 'single'` отображаются в «Синглы».
- [ ] Альбомы с `album_type = 'live'` отображаются в
      «Концертные альбомы».
- [ ] Альбомы с `album_type = 'compilation'` отображаются в
      «Сборники».
- [ ] Альбомы с `album_type = 'bootleg'` отображаются в
      «Бутлеги».
- [ ] Фильтр по каждому из 5 старых типов работает.
- [ ] Сохранение альбома с каждым из 5 старых типов работает.
- [ ] Счётчики на главной странице (`/stats`) не изменились
      (или изменились ожидаемо — добавлением архивных).
