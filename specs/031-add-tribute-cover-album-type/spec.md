# Feature Specification: Добавить тип альбома «Трибьют/Кавер»

**Feature Branch**: `[081-add-tribute-cover-album-type]`

**Created**: 2026-07-29

**Status**: Draft

**Input**: User description: "Ещё один тип альбома - Трибьют/Кавер"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Админ может назначить альбому тип «Трибьют/Кавер» (Priority: P1)

Администратор каталога (в webvue3, раздел «Альбомы» → двойной клик по альбому →
редактирование типа альбома) хочет отметить конкретный альбом как
«Трибьют/Кавер», чтобы посетители видели его в одноимённом разделе на
Закромах, а не в «Сборниках» или «Бутлегах».

**Why this priority**: Без возможности присвоить тип в админке фича не
имеет никакого эффекта для пользователя — это базовая операция записи,
без которой остальные истории теряют смысл.

**Independent Test**: Открыть любой существующий альбом в админке, в
выпадающем списке типа альбома выбрать «Трибьют/Кавер», сохранить,
переоткрыть альбом — значение сохранилось. Проверяется в
`tbl_albums.album_type = 'tribute'` через SELECT.

**Acceptance Scenarios**:

1. **Given** админ открывает редактор альбома, **When** он раскрывает
   список типов альбома, **Then** в списке присутствует пункт
   «Трибьют/Кавер» (наравне со «Студийные», «Синглы», «Концертные»,
   «Сборники», «Бутлеги», «Архивные»), а значение по умолчанию для
   нового альбома по-прежнему «Студийные».
2. **Given** админ выбрал «Трибьют/Кавер» и нажал «Сохранить»,
   **When** он переоткрывает тот же альбом, **Then** в списке снова
   отображается «Трибьют/Кавер», а в БД
   `tbl_albums.album_type = 'tribute'`.
3. **Given** альбом имеет `album_type = 'tribute'`, **When** админ
   открывает список всех альбомов, **Then** в колонке «Тип» он
   отображается как «Трибьют/Кавер» (тот же лейбл, что и в фильтре/
   группировке).

---

### User Story 2 - На Закромах (karaoke-public) трибьют-альбомы появляются отдельным разделом (Priority: P2)

Посетитель сайта на странице исполнителя/Закромов видит, что альбомы
сгруппированы по типу: «Студийные альбомы», «Синглы», «Концертные
альбомы», «Сборники», «Бутлеги», «Архивные записи». С добавлением
типа «Трибьют/Кавер» внизу (после архивных) появляется новый раздел
«Трибьют/Кавер», в который попадают только альбомы с типом TRIBUTE.

**Why this priority**: Это основной «визуальный» эффект фичи для
конечного пользователя — без него трибьют/кавер-альбомы ничем не
отличались бы от остальных.

**Independent Test**: На странице Закромов исполнителя, у которого
есть хотя бы один альбом с `album_type = 'tribute'`, внизу страницы
присутствует заголовок «Трибьют/Кавер» и карточки/список альбомов
этого типа. Исполнители без трибьют/кавер-альбомов не получают
пустой раздел.

**Acceptance Scenarios**:

1. **Given** у исполнителя есть 2 студийных и 1 трибьют-альбом,
   **When** посетитель открывает страницу Закромов, **Then** альбомы
   показаны в порядке: «Студийные альбомы» → «Синглы» → «Концертные
   альбомы» → «Сборники» → «Бутлеги» → «Архивные записи» →
   «Трибьют/Кавер», и в последнем разделе — ровно 1 альбом.
2. **Given** у исполнителя нет альбомов с типом TRIBUTE, **When**
   посетитель открывает страницу Закромов, **Then** раздел
   «Трибьют/Кавер» НЕ отображается (пустые разделы скрыты).
3. **Given** в каталоге уже есть альбомы со старым (неизвестным)
   значением `album_type` (например, `NULL` или пустая строка),
   **When** посетитель открывает Закрома, **Then** такие альбомы
   по-прежнему попадают в «Студийные альбомы» (поведение
   `AlbumType.fromDb()` сохранено).

---

### User Story 3 - В админке можно отфильтровать список альбомов по типу «Трибьют/Кавер» (Priority: P3)

Администратор, работая с большим каталогом (тысячи альбомов), хочет
быстро найти все трибьют/кавер-альбомы — например, чтобы проверить их
оформление или найти ошибки классификации. Для этого в модалке фильтра
таблицы «Альбомы» (webvue3) появляется опция «Трибьют/Кавер» рядом с
уже существующими «Студийные»/«Синглы»/«Концертные»/«Сборники»/
«Бутлеги»/«Архивные».

**Why this priority**: Удобство админки, не блокирует основной flow;
можно отложить, если ресурсы ограничены.

**Independent Test**: В webvue3 → «Альбомы» → открыть модалку фильтра
→ в списке типов появилась опция «Трибьют/Кавер» → выбрать её →
таблица показывает только альбомы с `album_type = 'tribute'`. Счётчик
у кнопки фильтра совпадает с количеством таких альбомов в БД.

**Acceptance Scenarios**:

1. **Given** в БД 18 858 альбомов, из них 3 имеют
   `album_type = 'tribute'`, **When** админ открывает модалку фильтра
   и кликает «Трибьют/Кавер», **Then** таблица показывает ровно 3
   строки, а счётчик на кнопке фильтра отображает «3».
2. **Given** админ уже отфильтровал по «Трибьют/Кавер», **When** он
   снимает выбор, **Then** таблица возвращается к полному списку
   (состояние фильтра сбрасывается корректно, без артефактов).

---

### Edge Cases

- **Невалидное значение `album_type` в БД** (например, `'tributes'`,
  `NULL`, `''`, `'Tribute'` с большой буквы): `AlbumType.fromDb()`
  мапит их на `STUDIO` (текущее поведение, не ломаем обратную
  совместимость).
- **Альбом создан до фичи, `album_type = 'studio'`**: ничего не
  меняется, остаётся «Студийные» — обратной конвертации не требуется.
- **Миграция БД не требуется**: колонка `tbl_albums.album_type` уже
  `VARCHAR`, новая строка `'tribute'` принимается без `ALTER TABLE`.
- **Поле пустое в форме редактирования** (админ очистил значение):
  должно тихо подменяться на дефолт (`STUDIO`) — как уже сделано в
  `fromDb()`.
- **Sync LOCAL↔SERVER**: новый `dbValue = "tribute"` корректно
  проходит через recordhash-триггер (строка как строка, без
  хардкода списка значений). Никаких дополнительных правок в
  recordhash-функции не нужно.
- **Совпадение с тегом `SKIP`**: если у альбома в `tbl_albums.tags`
  стоит `SKIP`, на Закромах показывается заглушка «удалено по
  требованию правообладателя» — это правило применяется к
  трибьют/кавер-альбомам так же, как к остальным, отдельной логики
  не требуется.
- **Параллельная фича 030-add-archive-album-type**: фичи независимы,
  но при деплое в одной сборке обе enum-константы (ARCHIVE и
  TRIBUTE) должны быть в коде одновременно — порядок добавления в
  enum и в `ZAKROMA_GROUP_ORDER` согласован (TRIBUTE строго после
  ARCHIVE).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Backend `AlbumType` enum
  (`karaoke-app/.../model/AlbumType.kt`) MUST содержать новую
  константу `TRIBUTE` с `dbValue = "tribute"`,
  `description = "Альбом каверов/трибьютов"`,
  `groupLabel = "Трибьют/Кавер"`, `filterLabel = "Трибьют/Кавер"`.
- **FR-002**: Backend MUST добавить `TRIBUTE` в `ZAKROMA_GROUP_ORDER`
  последним элементом (после `ARCHIVE`). Итоговый порядок:
  `STUDIO → SINGLE → LIVE → COMPILATION → BOOTLEG → ARCHIVE → TRIBUTE`.
- **FR-003**: Frontend `webvue3` (фильтр таблицы «Альбомы»,
  `AlbumsFilterModal.vue` и связанный стор) MUST отображать новую
  опцию фильтра «Трибьют/Кавер» (использует `filterLabel` из
  `AlbumType`).
- **FR-004**: Frontend `webvue3` (редактор альбома,
  `AlbumEdit.vue`/форма редактирования) MUST включать «Трибьют/Кавер»
  в выпадающий список типа альбома с `value = "tribute"`.
- **FR-005**: Public frontend `karaoke-public` MUST показывать раздел
  «Трибьют/Кавер» на Закромах, в котором перечислены только альбомы
  с `albumType == TRIBUTE`. Пустые разделы не рендерятся.
- **FR-006**: Backend MUST сохранять обратную совместимость:
  `AlbumType.fromDb(null)` и `fromDb("")` возвращают `STUDIO`;
  `fromDb("tribute")` возвращает `TRIBUTE`;
  `fromDb("неизвестное значение")` возвращает `STUDIO` (а не падает).
- **FR-007**: Никаких миграций схемы БД НЕ требуется: колонка
  `tbl_albums.album_type` уже принимает произвольную `VARCHAR`-строку.
  Значение `'tribute'` становится доступным сразу после релиза без
  `ALTER TABLE`.
- **FR-008**: Должна сохраниться текущая логика sync LOCAL↔SERVER:
  добавление `TRIBUTE` НЕ требует правок в `recordhash`-функции
  (строки сравниваются посимвольно), `SyncTarget`-классах для
  `tbl_albums` или `getDiff()`/`getSqlToInsert()`.
- **FR-009**: Счётчик количества альбомов в карточке статистики
  главной страницы (`Stat.kt` / `cachedTotal`) MUST включать альбомы
  с `album_type = 'tribute'` в общее число «Песен в коллекции» /
  «Всего в БД» — то есть вести себя так же, как и для других типов,
  без отдельного исключения.
- **FR-010**: Существующие альбомы с `album_type = 'tribute'` (если
  такие окажутся в БД после ручной правки или предыдущих попыток
  добавить тип) MUST корректно подхватываться без миграции и без
  переоткрытия/пересохранения.

### Key Entities *(include if feature involves data)*

- **AlbumType** (enum, `karaoke-app/.../model/AlbumType.kt`):
  расширяется одной константой `TRIBUTE`. Семантика и подписи
  фиксируются в коде, `dbValue` = `"tribute"` (lowercase-строка, по
  конвенции `SongType` — enum-обёртка над строкой, чтобы переименование
  констант не требовало миграции).
- **Album** (`tbl_albums`): без изменений схемы и без новых полей;
  уже содержит `album_type VARCHAR` и геттер/сеттер `albumTypeEnum`.
- **AlbumsFilter state** (Vuex,
  `webvue3/.../Albums/filter/store.js`): без изменений по структуре
  (значение фильтра — строка `dbValue`, фронт подставляет лейблы из
  бэкенда). Поведение: при выборе «Трибьют/Кавер» в state
  сохраняется `"tribute"`.
- **ZakromaAlbumPublicDto** (DTO для публичного API,
  `karaoke-web/.../dto/ZakromaPublicDto.kt`): без изменений полей;
  добавляется новый ключ группировки «Трибьют/Кавер», который
  попадает в JSON-ответ `ZakromaPublicDto.albumsByType` (или
  эквивалентное поле) под этим лейблом только если есть
  соответствующие альбомы.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% альбомов в БД с
  `tbl_albums.album_type = 'tribute'` отображаются на Закромах
  (karaoke-public) в разделе «Трибьют/Кавер» и НЕ отображаются в
  разделах «Студийные», «Синглы», «Концертные», «Сборники»,
  «Бутлеги» или «Архивные записи». Проверяется SQL-выборкой по
  `tbl_albums.album_type = 'tribute'` и сравнением с публичным
  JSON-эндпоинтом.
- **SC-002**: В модалке фильтра таблицы «Альбомы» (webvue3) после
  выбора опции «Трибьют/Кавер» отображаются ровно те альбомы, у
  которых `tbl_albums.album_type = 'tribute'`, в количестве,
  совпадающем с результатом
  `SELECT COUNT(*) FROM tbl_albums WHERE album_type = 'tribute'`
  (расхождение 0).
- **SC-003**: При создании нового альбома в webvue3 и выборе типа
  «Трибьют/Кавер» после сохранения в `tbl_albums` появляется строка
  с `album_type = 'tribute'`; значение сохраняется при перезагрузке
  страницы редактирования альбома.
- **SC-004**: При ручном
  `UPDATE tbl_albums SET album_type = 'tribute'` для существующего
  альбома и перезагрузке админки/albumа на Закромах изменение видно
  сразу (без ручного рефреша кешей, кроме штатного `@Scheduled`
  или `@PostConstruct` `StatsCacheScheduler`-а).
- **SC-005**: Альбомы со старыми/нестандартными значениями
  `album_type` (например, `NULL`, `''`, недокументированные строки)
  по-прежнему отображаются в разделе «Студийные альбомы» — фича
  ничего не ломает в обратной совместимости (0 регрессий в
  существующих альбомах при `git diff` существующих строк в БД).
- **SC-006**: Никаких новых записей в `tbl_albums` или
  `tbl_albums_sync` НЕ создаётся в результате фичи (фича —
  аддитивная: добавляет значение enum'а, не миграцию). Проверяется
  сравнением `pg_dump` до/после.

## Assumptions

- **Семантика «Трибьют/Кавер»** согласована с пользователем:
  объединённый тип для cover-альбомов (альбом каверов одного
  исполнителя) и tribute-альбомов (альбом, посвящённый другому
  исполнителю, где разные артисты исполняют его песни). Slash
  трактуется как синонимы в бытовом смысле.
- **dbValue** выбран как `tribute` (lowercase, единственное число)
  по образцу уже существующих значений (`studio`, `live`,
  `compilation`, `bootleg`, `single`, `archive`).
- **Порядок в `ZAKROMA_GROUP_ORDER`** — последним (после `ARCHIVE`),
  согласовано с пользователем.
- **Никаких миграций схемы БД не требуется**: `tbl_albums.album_type`
  уже `VARCHAR`, обратная совместимость обеспечивается текущей
  логикой `AlbumType.fromDb()` (неизвестное → `STUDIO`).
- **Никаких изменений в `recordhash`-функции для `tbl_albums` не
  требуется**: строка `'tribute'` хешируется тем же алгоритмом, что
  и остальные допустимые значения, LOCAL и SERVER дадут одинаковый
  md5 для одной и той же записи.
- **Фронт получает лейблы из бэкенда** (через DTO/эндпоинт), а не
  хардкодит русские подписи — поэтому добавление TRIBUTE не требует
  изменений во всех Vue-компонентах, где перечислены типы; достаточно
  того, что бэкенд отдаёт новую константу в списке.
- **Никаких изменений в публичной бизнес-логике** (free/premium
  лимиты, доступ к стемам, статистика по типу): трибьют/кавер-альбомы
  подчиняются тем же правилам, что и остальные.
- **Никаких изменений в MLT-генераторе, рендере MP4 или очереди
  задач**: `albumType` не влияет на пайплайн обработки.
- **Картинки альбома, авторы, описание, теги** работают одинаково для
  TRIBUTE и для остальных типов — никакой новой логики.
- **Параллельная фича 030-add-archive-album-type**: фичи
  независимы. Если обе будут смёржены в одну сборку, оба типа
  (ARCHIVE и TRIBUTE) появятся одновременно — порядок в
  `ZAKROMA_GROUP_ORDER` согласован: ARCHIVE перед TRIBUTE.
