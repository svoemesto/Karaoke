## Question

На основе результатов тикетов #102 (структурное сравнение) и #103
(rule duplication map), провести **grilling-раунд с владельцем**, чтобы
зафиксировать **scope of governance rewrite** для Karaoke:

1. **Какие разделы AGENTS.md (Karaoke) удалить целиком** (вынести в
   Knowledge / ADR / удалить)? Например, раздел «Диагностика на локальной
   машине» — это runtime-директива или knowledge?
2. **Какие разделы CLAUDE.md (Karaoke) переписать** (текущий MUST-CHECKLIST
   явно дублирует MUST #0 из AGENTS.md)?
3. **Какие правила в Karaoke вообще не нужны** (сравнение с TOP покажет,
   что в TOP их нет и без них модель работает)?
4. **Какие правила в Karaoke отсутствуют по сравнению с TOP** (например,
   «Symmetric Instructions» в TOP — обязательное правило синхронизации
   файлов)?
5. **Hard-gate канонизация**: какие правила **MUST** стать hard-gate
   (с явным failure-stop) в финальной AGENTS.md?

**Формат ответа** (в resolution-комментарии тикета):

```
## Scope of rewrite

- **Удалить** (вынести в ADR / Knowledge / удалить):
  - [раздел X в AGENTS.md] — обоснование: [почему]
  - ...

- **Переписать** (изменить формулировку, не смысл):
  - [правило Y] — текущая формулировка: [...]; предлагаемая: [...]
  - ...

- **Добавить** (новые правила из TOP, отсутствующие в Karaoke):
  - [правило Z] — откуда (TOP-AGENTS.md L...): [...]; почему для Karaoke: [...]
  - ...

- **Hard-gate канонизация** (явный failure-stop):
  - [правило W] — текущий failure-stop: [.../отсутствует]; предлагаемый: [...]
  - ...
```
