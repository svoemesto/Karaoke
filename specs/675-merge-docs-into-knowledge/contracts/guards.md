# Контракт: guard'ы запрета параллельной документации

**Feature**: `675-merge-docs-into-knowledge` | **Issue**: `KARAOKE-334` | **Дата**: 2026-10-29
**Источник**: D9, D20, FR-012, FR-013, FR-015 (см. [research.md § 1](../research.md))

> Guard — автоматическая проверка, падающая при появлении запрещённого состояния.
> Контракт ниже — **интерфейс** guard'а: имя, аргументы, коды возврата, сообщения, фикстуры, места вызова.

---

## C1. Guard «каталог `docs/` в корне отсутствует»

| Поле | Значение |
|---|---|
| Скрипт | `tools/check-no-docs-dir.sh` |
| Назначение | FR-012, FR-001, SC-001, SC-005 |
| Вызов | `bash tools/check-no-docs-dir.sh [--root <dir>]` |
| `<dir>` | по умолчанию корень репозитория; нужен для прогона на фикстурах |

**Логика (порядок проверок)**

| # | Условие | Действие |
|---|---|---|
| 1 | `git -C <root> ls-files -- docs/` — не пусто | **ошибка**: перечислены отслеживаемые файлы в `docs/` |
| 2 | каталог `<root>/docs` существует на диске | **ошибка**: каталог `docs/` запрещён (даже если файлы не отслеживаются) |
| 3 | иначе | **OK**, код 0 |

**Коды возврата**

| Код | Значение |
|---|---|
| 0 | нарушений нет |
| 1 | нарушение найдено (выведено до 20 имён файлов + счётчик) |
| 2 | проверка не выполнена (нет `git`, корень не найден) — по образцу `check-feature-doc.sh` (BR-509) |

**Сообщение об ошибке (обязательный минимум)**

```
[FAIL] Каталог docs/ в корне репозитория запрещён (ADR-0011).
       knowledge/ — единственный слой проектной документации.
       Если материал нужен — перенесите его в knowledge/ (см. knowledge/README.md § «Бывшие пути»).
```

**Фикстуры** — `tools/fixtures/no-docs-dir/`

| Фикстура | Содержимое | Ожидание |
|---|---|---|
| `vulnerable/` | `docs/legacy-note.md` (файл-заглушка с пометкой «ФИКСТУРА») | guard **падает** (код 1) |
| `clean/` | пусто (только `.gitkeep`-подобный README-заглушка) | guard **проходит** (код 0) |

Образец фикстур — `tools/fixtures/marker-escape/`, `tools/fixtures/actions-pinned/`, `tools/fixtures/confirm-escape/`: замороженный снимок, который читает только guard-скрипт.

**Места вызова (все обязательны — FR-012)**

| Место | Как |
|---|---|
| `.forgejo/workflows/lint.yml` | отдельный job-шаг в джобе `docs-lint` (или рядом с `knowledge-structure`) |
| `.github/workflows/lint.yml` | **тот же** шаг (две копии workflow обязаны содержать одинаковый набор проверок) |
| `.pre-commit-config.yaml` | hook `no-docs-dir`, `files: '^(docs/.*)?$'` либо `pass_filenames: false` + `always_run` |

## C2. Проверка синхронности двух копий workflow

| Поле | Значение |
|---|---|
| Скрипт | `tools/check-ci-workflow-sync.sh` |
| Назначение | FR-013 — «две копии CI-конфигурации расходятся, контрактный тест покрывает только `.github/`» |
| Вызов | `bash tools/check-ci-workflow-sync.sh` |
| Вход | `.forgejo/workflows/lint.yml` и `.github/workflows/lint.yml` |

**Логика**

| # | Условие | Действие |
|---|---|---|
| 1 | оба файла существуют | иначе — код 2 (проверка не выполнена) |
| 2 | извлечь из каждого **набор гейтовых команд** (строки с `bash tools/`, `python3 tools/`, `npx markdownlint`, `actionlint`-подобные вызовы) | нормализация: обрезка пробелов, отбрасывание комментариев |
| 3 | наборы равны (как множества) | **OK**, код 0 |
| 4 | расхождение | **ошибка**: вывести строки, присутствующие только в одной копии, с указанием файла |

**Что НЕ сравнивается** (расхождения, не связанные с гейтами, — норма)

| Не сравнивать | Почему |
|---|---|
| `runs-on:` (разные раннеры: Forgejo ≠ GitHub) | инфраструктурное различие |
| `timeout-minutes:` | инфраструктурное различие |
| `if:` / `needs:` / порядок шагов | не влияет на набор проверок |
| комментарии | не влияют |

**Коды возврата**

| Код | Значение |
|---|---|
| 0 | копии синхронны |
| 1 | расхождение в наборе гейтовых команд |
| 2 | проверка не выполнена (файла нет) |

**Фикстуры** — `tools/fixtures/ci-workflow-sync/`

| Фикстура | Содержимое | Ожидание |
|---|---|---|
| `divergent/` | две копии workflow, в одной — лишний гейт | guard **падает** (код 1) |
| `synced/` | две идентичные (по гейтам) копии | guard **проходит** (код 0) |

**Места вызова**: оба workflow + pre-commit (дешёвая проверка, ловит рассинхрон до CI).

## C3. Guard «BR-код ↔ компонент» (соответствие реестру)

| Поле | Значение |
|---|---|
| Скрипт | `tools/check-audit-registry.py` |
| Назначение | FR-015, D9 |
| Вызов | `python3 tools/check-audit-registry.py` |
| Вход | `knowledge/**/*.md` (все, кроме самого реестра) + `knowledge/system/infra/audit-336-registry.md` |

**Логика**

| # | Условие | Действие |
|---|---|---|
| A | `BR-NNN` встречается в `knowledge/**` (кроме реестра), но отсутствует в реестре | **ошибка**: «код не зарегистрирован» |
| B | код есть в реестре, но не встречается в `knowledge/**` (кроме реестра) **и** не помечен в разделе «Коды без зеркала» | **ошибка**: «код потерян» |
| C | иначе | **OK**, код 0 |

**Коды возврата**

| Код | Значение |
|---|---|
| 0 | соответствие полное |
| 1 | нарушения (перечислены все, с файлами и строками) |
| 2 | проверка не выполнена (реестр не найден) |

**Фикстуры** — `tools/fixtures/audit-registry/`

| Фикстура | Содержимое | Ожидание |
|---|---|---|
| `orphan-code/` | компонент с `BR-999`, которого нет в реестре | guard **падает** |
| `lost-code/` | код в реестре, отсутствующий в `knowledge/` и не помеченный | guard **падает** |
| `consistent/` | код в реестре + код в компоненте + помеченный «без зеркала» | guard **проходит** |

**Места вызова**: оба workflow (джоб структуры Knowledge) + pre-commit.

## C4. Связи guard'ов с остальными проверками

| Guard | Дополняет | Не дублирует |
|---|---|---|
| C1 «нет `docs/`» | — | `check-knowledge-structure.sh` проверяет **наличие** каталогов `knowledge/`; C1 проверяет **отсутствие** `docs/` |
| C2 «синхронность workflow» | контрактный тест `PkgS335SourceContractsTest.kt` (покрывает **только** `.github/`) | C2 покрывает **обе** копии |
| C3 «BR-код ↔ компонент» | — | `lint-knowledge.py` проверяет профиль A; C3 проверяет полноту реестра |

## C5. Требования к сообщениям

1. Каждое сообщение об ошибке содержит: **что** нарушено, **где** (путь/файл), **почему** (ссылка на ADR-0011 или правило), **что делать** (целевое место).
2. Никаких секретов и содержимого окружения в выводе.
3. Коды возврата различаются (0 / 1 / 2) — по образцу `check-feature-doc.sh` (BR-509), чтобы CI мог отличить «нарушение» от «проверка не выполнена».
