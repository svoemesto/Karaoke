# Phase 1 Data Model: Устаревший премиум-статус в шапке сайта

Новых сущностей и изменений схемы БД эта фича не вводит. Ниже — существующая
модель данных, которую фича делает своевременно актуальной (без изменения её
формы).

## SiteUser / SiteUserDto (существующая сущность, без изменений полей)

Источник истины на сервере: `karaoke-app/src/main/kotlin/.../model/SiteUser.kt`
(таблица `tbl_site_users`), сериализуется в `SiteUserDto`
(`karaoke-app/.../model/SiteUserDto.kt`). Из полей DTO для этой фичи значим
один флаг:

| Поле DTO | Тип | Смысл |
|---|---|---|
| `isEffectivePremium` (Kotlin) → `effectivePremium` (JSON, из-за отбрасывания Jackson-ом префикса `is*`) | boolean | Актуальный, вычисляемый на сервере на момент запроса признак «пользователь премиум прямо сейчас» — источник истины, не кэшируется на сервере. |

Никаких новых полей не добавляется. Эндпоинт `GET /api/public/auth/me`
(`PublicAuthController.me`) уже отдаёт полный, свежий `SiteUserDto` — фикс не
меняет ни его форму, ни его backend-логику.

## Клиентское состояние сессии (`useAuth.js`, существующее, расширяется поведением)

Хранится как module-level `ref`, персистится в `localStorage`:

| Поле | Тип | Источник | Как обновляется сегодня | Как обновляется после фикса |
|---|---|---|---|---|
| `token` | string | `km_auth_token` в `localStorage` | `setSession()` (логин), `clearSession()` (логаут/401) | без изменений |
| `user` | `SiteUserDto \| null` | `km_auth_user` в `localStorage` | `setSession()` при логине; `fetchMe()` — но только из 3 конкретных view | + периодический фоновый `fetchMe()` (Decision 1-3, research.md), не меняя саму форму объекта |

**State transitions для `user.effectivePremium`** (с точки зрения того, что
видит пользователь в шапке):

```
[залогинен, premium=true] --(подписка истекает на сервере)--> [сервер: premium=false]
                                                                        │
                                             ДО фикса: шапка не знает об этом,
                                             пока не сработает fetchMe() на
                                             /account, /editor/tasks или /editor/work,
                                             либо не произойдёт relogin
                                                                        │
                                             ПОСЛЕ фикса: следующий плановый тик
                                             периодического fetchMe() (≤5 мин,
                                             Decision 2) обновляет user.value →
                                             шапка автоматически показывает
                                             актуальный статус
```

Симметрично для обратного перехода (`premium=false` → `premium=true`,
User Story 1 сценарий 5 в spec.md) — тот же механизм, без отдельной ветки
логики.

## Валидационные правила

Не меняются — `SiteUserDto.validationErrors()`/`isValid()` (email-валидация)
не относятся к premium-статусу и этой фичи не касаются.
