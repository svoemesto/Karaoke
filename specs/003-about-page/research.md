## Decision 1: Блок «Площадки» — переиспользовать `SocialLinks.vue`

**Decision**: вставить в `AboutView.vue` готовый компонент
`<SocialLinks />` (`karaoke-public/src/components/SocialLinks.vue`) без
изменений.

**Rationale**: компонент уже переиспользуется на `HomeView.vue` для точно
той же цели (иконки-ссылки на Sponsr/Dzen/VK/VK-видео/Telegram/Max),
самодостаточен (список площадок захардкожен внутри, пропсы не нужны),
уже трекает клики через `trackLinkToSocialNetwork`. Ровно совпадает с
требованием FR-002 «Блок «Площадки» (Sponsr, Dzen, VK, Max, Telegram) с
иконками».

**Alternatives considered**:
- Новый компонент специально для `/about` — отклонено: чистое дублирование
  кода без смысловой разницы (те же площадки, тот же трекинг).
- Инлайн-разметка прямо в `AboutView.vue` (как было исторически в
  `HomeView.vue` до выделения `SocialLinks.vue`) — отклонено: `SocialLinks.vue`
  уже существует именно как переиспользуемый вариант этой разметки.

## Decision 2: Кнопка «Поделиться» — новый компонент, emoji вместо новых SVG

**Decision**: новый компонент `ShareButton.vue`. Меню при клике: VK,
Telegram, WhatsApp, Odnoklassniki (через `https://vk.com/share.php`,
`https://t.me/share/url`, `https://wa.me/?text=`,
`https://connect.ok.ru/offer` — стандартные share-URL этих площадок,
открываются в новой вкладке) + кнопка «Скопировать ссылку»
(`navigator.clipboard.writeText`, с фолбэком на `document.execCommand('copy')`
для старых браузеров). Иконки — emoji (🎵→ конкретно: 🔵 VK, ✈️ Telegram,
💬 WhatsApp, 🟠 OK, 🔗 копировать), не новые SVG.

**Rationale**:
- `SvgIcon.vue` не содержит иконок WhatsApp/Odnoklassniki (`viewBoxMap`
  ограничен `sponsr/boosty/dzen/vk/tg/vkgroup/max/pl/player/premium/favorite/
  playlist`) — добавление новых SVG-ассетов увеличивает скоуп P3-задачи без
  необходимости.
- `AboutView.vue` уже использует emoji в CTA-кнопках («🎵 Послушать демо»,
  «📚 Открыть каталог», «🔖 Зарегистрироваться», «👤 В личный кабинет») —
  emoji для share-меню стилистически консистентны с уже принятым решением
  того же файла, не «новый» паттерн.
- Стандартные `share.php`/`t.me/share`/`wa.me`/`connect.ok.ru` URL не требуют
  API-ключей/SDK соцсетей — не увеличивают bundle size, не требуют новых
  зависимостей в `package.json`.

**Alternatives considered**:
- `navigator.share()` (Web Share API) — не выбран как единственный механизм:
  не поддерживается на десктопных браузерах (только мобильные Safari/Chrome
  Android), а спека явно требует «меню с 5+ соцсетями» (акцептанс-критерий
  US3), то есть явный список, а не системный шаринг-диалог. Можно добавить
  как *дополнительный* быстрый путь на мобильных (`if (navigator.share)`),
  но это не покрывает акцептанс-критерий сам по себе — MVP реализует явное
  меню.
- Библиотека для share-кнопок (`vue-social-sharing` и т.п.) — отклонено:
  новая npm-зависимость ради тривиальной функциональности (5 `window.open`
  вызовов + `clipboard.writeText`) — не соответствует constitution
  Principle I (минимизация внешних зависимостей в горячем пути) по духу,
  хотя формально Principle I про медиа-пайплайн; решение по аналогии.

## Decision 3 (ретроспектива): динамическая статистика вместо Vuex-модуля

**Decision (уже принято, задокументировано постфактум)**: `AboutView.vue`
загружает `/api/public/stats` напрямую через `apiGet` в `methods.load()`,
а не через существующий Vuex-модуль `stats` (которым пользуется `HomeView.vue`
через `mapGetters('stats', ...)`).

**Rationale** (реконструирована по коду): `AboutView.vue` уже параллелит
`/api/public/authors` + `/api/public/stats` одним `Promise.all` в `load()` —
переиспользование Vuex-модуля потребовало бы либо дублирования его
`loadStats`-логики, либо смешивания стилей загрузки (часть данных — через
Vuex actions, часть — напрямую). Учитывая, что `/about` — самостоятельная
страница без общего состояния с `HomeView`, прямой `apiGet` проще.

**Alternatives considered**: переиспользовать Vuex `stats`-модуль — не стали
менять существующий, рабочий код ради стилистического единообразия без
функциональной выгоды; выходит за рамки P1/P2/P3 задач этой фичи.
