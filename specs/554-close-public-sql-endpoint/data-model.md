# Data Model: 554 — Закрыть публичный доступ к `POST /changerecords`

Модель данных не меняется: правка касается только доступа к существующему эндпоинту.
Ниже — сущности, которые участвуют в доступе, и правила их валидации.

## Сущности

### Внутренний секрет синхронизации (SyncInternalSecret)

| Поле | Тип | Описание |
|---|---|---|
| `value` | строка | Секретное значение, одинаковое на отправителе и получателе |
| `configured` | булево | Признак, что значение задано и непустое |

Правила валидации:
- Значение **не** хранится в репозитории и не попадает в сборку: на стороне `karaoke-web` —
  переменная окружения `SYNC_INTERNAL_SECRET`, на стороне `karaoke-app` — свойство
  `syncInternalSecret` в `Karaoke.properties` (задаётся администратором).
- Пустое значение = «секрет не настроен» → доступ закрыт (fail-safe), а не открыт.
- Значение не попадает в журналы и не возвращается в ответе.

### Запрос на изменение данных (ChangeRecordsRequest)

Существующая сущность, формат не меняется (FR-011).

| Поле | Тип | Описание |
|---|---|---|
| `word` | строка | Зашифрованное кодовое слово (проверка `Crypto.decrypt`) |
| `dataCreate` / `dataUpdate` / `dataDelete` | списки SQL-действий | Набор изменений к применению |

Правила валидации (без изменений):
- Запрос принимается только при совпадении внутреннего секрета **и** сетевого разрешения источника.
- При отказе тело запроса не разбирается и не применяется.

### Запись журнала безопасности (SyncSecurityLogRecord)

| Поле | Тип | Описание |
|---|---|---|
| `occurredAt` | время | Момент отказа |
| `source` | строка | Адрес источника запроса |
| `reason` | перечисление | `missing_secret` / `invalid_secret` / `secret_not_configured` |

Правила валидации:
- Тело присланного запроса и текст ошибки БД в запись **не** попадают (FR-007).

## Отношения

- Внутренний секрет — единственный для пары «клиент синхронизации ↔ karaoke-web»; обе стороны
  используют одно и то же значение.
- Сетевой список разрешённых адресов — независим от секрета: он определяет, кто вообще может
  обратиться к маршруту, секрет определяет, кто именно является легитимным клиентом.

## Изменения схемы

Отсутствуют: миграции БД не требуются (FR-007 спеки, Constitution II).
