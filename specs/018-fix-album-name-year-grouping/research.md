# Phase 0 Research: Закрома — коллизия одноимённых альбомов разных годов

Technical Context не содержит `NEEDS CLARIFICATION` — исследование ниже
фиксирует единственное значимое техническое решение фикса и рассмотренные
альтернативы.

## Решение: ключ группировки альбомов

**Decision**: В `Zakroma.buildFromSettings()` (`karaoke-app/.../model/Zakroma.kt:126`)
заменить группировку `settingsByAuthor.groupBy { it.album }` (только по
названию) на группировку по составному ключу **(год, название альбома)** в
пределах уже сгруппированных песен одного автора. Год карточки альбома
берётся из этого ключа, а не из «первой попавшейся» песни группы.

**Rationale**:
- Реальная идентичность альбома в БД — тройка `(author_id, year, name)`:
  именно на неё завязан уникальный констрейнт `tbl_albums_author_year_name_key`
  (`Album.getAlbumByAuthorYearName`) и именно её использует идемпотентный
  бэкфилл `AlbumBackfill` (`groupBy { it.author to it.year }`, затем
  `getAlbumByAuthorYearName(authorId, year, name)`). Группировка в закромах по
  одному названию — единственное место в кодовой базе, где эта тройка
  «урезана» до одного поля, и именно это расхождение вызывает баг.
- Ключ (год, название) корректно работает независимо от того, привязана ли
  уже песня к сущности `Album` через `album_id`, — не требует завершённости
  бэкфилла (часть песен может быть ещё не забэкфиллена, но всё равно попадёт
  в правильную карточку по своим свободнотекстовым `year`/`album`).
- Изменение минимально: один `groupBy`, без переписывания остальной логики
  сборки карточки альбома (обложка/описание/тип по-прежнему подтягиваются из
  связанной `Album`, если `albumId` уже проставлен хотя бы у одной песни
  группы).

**Alternatives considered**:
1. **Группировать строго по `albumId`, с фолбэком на название для песен без
   `albumId`.** Отклонено: даёт двухуровневую, несогласованную логику —
   часть песен одного и того же реального альбома (одни уже забэкфиллены,
   другие ещё нет, если бэкфилл выполнялся частями/повторно прерывался) может
   разъехаться по разным веткам группировки. Ключ (год, название) не имеет
   этой проблемы, так как одинаков для всех песен альбома независимо от
   `albumId`.
2. **Полный переход на группировку по `albumId` для всех песен.** Отклонено
   как избыточное для этого бага: требует гарантии 100%-й привязки
   `album_id` у всех песен (сейчас это не гарантировано — `AlbumBackfill`
   идемпотентен, но нет проверки, что он был прогнан для всех данных).
   Вынесено в `spec.md` → «Assumptions» как возможное будущее улучшение,
   вне скоупа текущего фикса.
3. **Ничего не менять в группировке, только «постфактум» разделять
   результат по году после `groupBy { it.album }`.** Отклонено: это то же
   самое решение (1), но реализованное более многословно — расширение ключа
   `groupBy` сразу даёт тот же результат за один проход.

## Побочные технические вопросы

- **Обложка/описание/тип альбома** (FR-004 spec.md): уже выбираются через
  `settingsByAlbum.firstOrNull { it.albumId != null }?.albumId` **внутри**
  группы — после исправления ключа группировки эта логика автоматически
  работает корректно для каждой (год, название)-группы отдельно, изменений в
  этой части не требуется.
- **Сортировка карточек альбомов** (`ZakromaAlbum.compareTo`) — уже
  учитывает `year` как один из ключей сортировки; после фикса две карточки
  с одинаковым названием, но разными годами, будут сортироваться по году
  (и `sortOrder`/`albumType`, если он уже проставлен бэкфиллом) — изменений
  не требуется.
- **FR-009 (per-feature документ)**: `docs/features/special-orders.md`
  явно описывает `buildFromSettings()» как «группировка Автор→Альбом→Песни» —
  требует обновления в этом же PR с уточнением ключа группировки альбомов.
