## Question

Как сейчас устроен пул задач HealthReport в коде: где физически хранится
очередь (in-memory atomic-очередь / redis / БД), как новые задания
добавляются (в начало или в конец), как сейчас обрабатывается порядок
при переходе между страницами, и где именно ломается логика «всплытия»
заданий при возврате на посещённую страницу.

Дополнительно — какой API отдаёт количество оставшихся заданий (нужно для
UI-бейджа).

## Investigation scope

- `karaoke-app` (Kotlin backend) — искать классы/сервисы с префиксами
  `HealthReport`, `StorageHealth`, `StorageCache`, `Pool`, `Queue`,
  `TaskQueue`, `AsyncPool`, `ChunkExecutor`, `BatchExecutor`.
- Возможно: `karaoke-web` (Kotlin), если есть выделенный web-pool.
- Фронт: искать компонент «Песни» в админке — где сейчас инициируется
  каскад HealthReport при монтировании страницы.

## Outputs

- Имена и пути файлов, реализующих пул (с line numbers).
- Цитата реализации метода `add` / `enqueue` / `addFirst` (если есть).
- Цитата метода, отвечающего за порядок обработки чанков.
- Точное место, где сломан «всплытие» (или подтверждение, что его просто нет).
- API endpoint с количеством заданий в пуле (если есть) — путь, контракт,
  контракт.
