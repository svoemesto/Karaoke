## Сверки (баг или задумано, без severity)

1. **Самопривязка Sponsr UID даёт premium.** `POST /api/public/account/profile` принимает `sponsrUid` от самого пользователя (`PublicAccountController.kt:30–44`, поле есть в форме `karaoke-public/src/views/AccountView.vue:98`), а `SponsrSyncService.applyToUsers` выдаёт `sponsrPremiumUntil` всем сайт-пользователям, чей `sponsrUid` совпал с идентификатором активного подписчика Sponsr (`karaoke-app/.../services/SponsrSyncService.kt:153–160`). Вопрос: задумана ли привязка без подтверждения владения UID? Трактовки: (а) дефект — чужой/публичный Sponsr UID даёт платный доступ; (б) задумано — UID не секрет, пользователь вводит свой. Почему важно: это обход платного доступа (потенциально S1), но без доказательства доступности чужих UID и без явного запрета в спеке severity не ставится.

2. **IP для SmartCaptcha берётся не из `ClientIpResolver`.** `PublicAuthController.register` передаёт в `YandexCaptchaValidationService.validate` `request.remoteAddr` (`PublicAuthController.kt:47`), а за host-nginx это адрес nginx (loopback/docker-шлюз) для всех клиентов; в проекте для этого есть `ClientIpResolver.resolve(request)` (используется в `MainController`/`RateLimitInterceptor`). Вопрос: SmartCaptcha получает один и тот же IP на всех — задумано (ip необязателен) или ошибка, обесценивающая per-IP-проверку/дающая ложные отказы?

3. **`/registerevent` принимает `siteUserId` из query и пишет в чужую историю.** `MainController.doRegisterEvent(..., siteUserId: Long = 0)` берёт id из query-параметра, и при `eventType=player`/`linkType=play` вызывает `ListeningHistory.upsert(siteUserId, songId, ...)` без проверки токена (`MainController.kt:144–150, 270–272`) — IDOR в историю прослушиваний. Однако канонический prod-nginx (`deploy/prod-single-host/80to8897:110–125`) проксирует `/` в SPA `:7907`, а в karaoke-web идут только `/api/` и `/changerecords`; внешняя достижимость `/registerevent` не доказана. Вопрос: закрыть как латентный IDOR или endpoint считается внутренним и недостижимым.
