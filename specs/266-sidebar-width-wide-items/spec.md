# Feature Specification: Расширение левого меню админки webvue3 под широкие пункты и бейджи

**Feature Branch**: `266-sidebar-width-wide-items`
**Created**: 2026-08-30
**Status**: Draft
**Input**: User description: "Админка webvue3 - увеличить ширину левой меню так, чтобы выбранные широкие пункты и бейджи не "висели" в воздухе."

## Контекст

В админке `webvue3` левая колонка навигации (`.app-sidebar` в `webvue3/src/App.vue:727-735`) имеет фиксированную ширину **190px** (комментарий в коде: «Ширина подобрана так, чтобы самый длинный пункт („Пользователи сайта“) помещался в одну строку»). С момента добавления новых пунктов и бейджей длинные пункты и бейджи перестали помещаться в этой ширине и «висят в воздухе» — визуально вылезают за правую границу сайдбара и накладываются на соседнюю колонку (см. скриншот пользователя 331×1137 px, sha256:9500214023293f9a60d7d19c9b28ab5ca4ff7d9e2671f556e4b8b179bc4d544c, где бейдж «46» у «Задания редактора», «8» у «Авторы» и текст пунктов «Пользователи сайта», «Подписки», «История прослушиваний», «Временные ссылки», «Sponsr-синхронизация», «Синхронизация БД» выходят за серый фон сайдбара на белую область основного контейнера).

**Текущая вёрстка** (`.app-sidebar`, `App.vue:727-735`):

```css
.app-sidebar {
  width: 190px;
  flex-shrink: 0;
  padding: 10px;
  /* … */
}
.app-sidebar .nav-link {
  padding: 8px 12px;
  white-space: nowrap;
}
```

**Расчёт горизонтального пространства под текст**:

| Элемент | Размер |
|---------|--------|
| `.app-sidebar` общая ширина | 190px |
| `padding: 10px` слева + справа | −20px |
| `.nav-link` `padding: 8px 12px` слева + справа | −24px |
| **Доступно под текст** | **146px** |
| «Sponsr-синхронизация» (~20 символов кириллицы @ ~9px) | ~180px |
| «История прослушиваний» (~20 символов) | ~180px |
| «Пользователи сайта» + `padding 12px` | ~165px |
| «Шаблоны публикаций» (~19 символов) | ~170px |
| Бейдж `songeditor-nav-badge` рядом с «Задания редактора» | +30px (badge `min-width: 18px; padding: 0 5px`) |

Ширина 190px **не вмещает** самый длинный пункт «Sponsr-синхронизация» (≈180px текста), и при наличии бейджа суммарно нужно ≥210px на строку «Задания редактора» + «46».

**Замечание из AGENTS.md/CLAUDE.md**: правка только в `webvue3/src/App.vue` (CSS), backend не затрагивается, фича не меняет bounded context и C4-уровень, отдельный LiveDoc не требуется (изменение — косметика лейаута админки).

**Решение пользователя** (от 2026-08-30): увеличить ширину сайдбара с 190px до **240px** (компромисс: вмещает все текущие пункты + бейдж, не съедает слишком много места у основного контейнера на типичных десктопных разрешениях ≥1280px). Все остальные правки в этой спеке — производные от смены ширины.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Длинные пункты помещаются в одну строку (Priority: P1)

Все пункты левого меню админки — включая самые длинные («Sponsr-синхронизация», «История прослушиваний», «Шаблоны публикаций», «Пользователи сайта», «Синхронизация БД») — отображаются в одну строку (`white-space: nowrap`) и **полностью находятся внутри серой области сайдбара**, не вылезают на белую область основного контейнера.

**Why this priority**: Это базовая бизнес-ценность запроса («увеличить ширину левого меню, чтобы выбранные широкие пункты … не „висели“ в воздухе»). Без этого весь запрос не выполнен. Это самое маленькое из изменений, формирует основу для US2.

**Independent Test**: Открыть админку на десктопе (ширина окна ≥1280px), навести мышь на пункт «Sponsr-синхронизация» — его `getBoundingClientRect().right` ≤ `getBoundingClientRect(.app-sidebar).right` (не выходит за границу серого фона). Аналогично для «История прослушиваний», «Шаблоны публикаций», «Пользователи сайта», «Синхронизация БД», «Задания редактора» (с бейджем), «Авторы» (с бейджем), «Чат» (с бейджем).

**Acceptance Scenarios**:

1. **Given** админ открывает админку на ширине окна ≥1280px; **When** он смотрит на левое меню; **Then** ВСЕ пункты меню (включая «Sponsr-синхронизация», «История прослушиваний») помещаются в одну строку и НЕ вылезают за правую границу серой области `.app-sidebar`.
2. **Given** ширина окна = 1280px; **When** он измеряет правую границу самого длинного пункта; **Then** `getBoundingClientRect(`.app-sidebar .nav-link:last-of-type`).right` − `getBoundingClientRect(`.app-sidebar`).right` **≤ 0** (нет отрицательного зазора — пункт внутри).
3. **Given** ширина окна уменьшена до 1024px (типичный ноутбук); **When** админ просматривает меню; **Then** основной контейнер `.app-main-content` всё ещё занимает ≥700px (текущая ширина сайдбара 190px съедает ~15% от 1024px; новая 240px — ~23%, что приемлемо).
4. **Given** `white-space: nowrap` на `.app-link` сохранён (текущее поведение, см. `App.vue:749`); **When** любой пункт слишком длинный; **Then** он НЕ переносится на две строки, а полностью виден в одну (т.е. ширины сайдбара достаточно).

### User Story 2 — Бейджи не вылезают за границу сайдбара (Priority: P1)

Все три бейджа в левом меню — `authors-nav-badge` («Авторы: 8»), `chat-nav-badge` («Чат: N»), `songeditor-nav-badge` («Задания редактора: 46») — полностью видны **внутри** серой области `.app-sidebar`, не «висят в воздухе» над основным контейнером. Текст пункта + бейдж + padding умещаются в новую ширину сайдбара.

**Why this priority**: На скриншоте пользователя бейдж «46» частично вылезает на белую область — это самая заметная визуальная проблема, именно про неё фраза «не „висели“ в воздухе». Без фикса бейджей запрос нельзя считать выполненным.

**Independent Test**: Открыть админку, дождаться загрузки бейджей (счётчики `authorsWithNewAlbumCount > 0`, `chatUnreadTotal > 0`, `submittedAssignmentsCount > 0`). Проверить, что `getBoundingClientRect(.songeditor-nav-badge).right` ≤ `getBoundingClientRect(.app-sidebar).right`. Аналогично для двух других бейджей.

**Acceptance Scenarios**:

1. **Given** у автора есть новые альбомы (`authorsWithNewAlbumCount = 8`); **When** админ смотрит на пункт «Авторы»; **Then** бейдж `.authors-nav-badge` с цифрой «8» полностью внутри серой области сайдбара, `flex-justify: space-between` (`.authors-nav-link`, `App.vue:792-796`) корректно раздвигает текст и бейдж.
2. **Given** в чате есть непрочитанные сообщения (`chatUnreadTotal > 0`); **When** админ смотрит на пункт «Чат»; **Then** бейдж `.chat-nav-badge` не вылезает за границу сайдбара.
3. **Given** есть назначенные задания (`submittedAssignmentsCount = 46` — двухзначное число); **When** админ смотрит на пункт «Задания редактора»; **Then** бейдж `.songeditor-nav-badge` с «46» (ширина ≈30px) вмещается справа от текста «Задания редактора» (≈145px), итого <200px, вписывается в новую ширину сайдбара 240px.
4. **Given** все бейджи имеют `display: flex` контейнер (`.chat-nav-link`, `.songeditor-nav-link`, `.authors-nav-link` — все с `display: flex !important; justify-content: space-between`, см. `App.vue:758-807`); **When** ширина сайдбара увеличена; **Then** `justify-content: space-between` работает корректно — текст прижат влево, бейдж прижат вправо.

### User Story 3 — Сайдбар не «съедает» основной контейнер (Priority: P2)

Увеличение ширины сайдбара с 190px до 240px (т.е. **+50px**) не должно критически уменьшать рабочую область основного контейнера `.app-main-content`. На типичных десктопных разрешениях (≥1280px) у основного контейнера должно оставаться **не менее 1000px** (т.е. 1280 − 240 − небольшой padding = ≥1000).

**Why this priority**: UX-компромисс — слишком широкий сайдбар тоже плохо (мало места для таблиц и форм). Это требование ограничивает максимальную ширину сайдбара и проверяет, что мы не «перестарались».

**Independent Test**: Открыть админку на 1280×800 — `getBoundingClientRect(.app-main-content).width >= 1000`. Открыть на 1920×1080 — `>= 1650`. На 1024×768 (минимально комфортный ноутбук) — `>= 750`.

**Acceptance Scenarios**:

1. **Given** ширина окна = 1280px; **When** админ смотрит на layout; **Then** `.app-main-content` имеет ширину ≥ 1000px (текущие таблицы с 6–8 колонками помещаются без горизонтальной прокрутки).
2. **Given** ширина окна = 1024px (компактный ноутбук); **When** админ смотрит на layout; **Then** `.app-main-content` имеет ширину ≥ 750px (формы и таблицы редактора ещё помещаются).
3. **Given** ширина окна ≥ 768px; **When** админ открывает админку; **Then** сайдбар **НЕ переходит в мобильный режим** (т.е. НЕ схлопывается в hamburger / overlay). Текущая вёрстка не имеет мобильного режима — это вне scope.
4. **Given** `flex-shrink: 0` на `.app-sidebar` (`App.vue:729`); **When** окно сужается; **Then** сайдбар сохраняет свою ширину (240px), основной контейнер сжимается — layout не ломается.

---

### User Story 4 — Визуальное соответствие скриншоту пользователя (Priority: P2)

После применения правки скриншот админки на ширине окна ≥1280px **визуально совпадает** с запросом пользователя: все пункты и бейджи — внутри серой области, нет «висящих в воздухе» элементов.

**Why this priority**: Это формальный «visual regression» — после правки скриншот должен перестать показывать проблему, описанную пользователем.

**Independent Test**: Сделать скриншот админки при ширине ≥1280px и сравнить с эталонным скриншотом пользователя 331×1137 px (sha256:9500214023293f9a60d7d19c9b28ab5ca4ff7d9e2671f556e4b8b179bc4d544c) — все ранее «висящие» пункты и бейджи теперь полностью внутри серой области.

**Acceptance Scenarios**:

1. **Given** админ открывает админку; **When** он делает скриншот; **Then** на скриншоте все пункты меню и бейджи находятся **внутри** серого прямоугольника `.app-sidebar` (визуальная проверка: правый край самого длинного элемента совпадает с правым краем фона сайдбара или отступает влево от него).
2. **Given** пользователь сравнивает новый скриншот с эталонным; **When** он накладывает их; **Then** «висящих в воздухе» элементов (бейджей, выходящих за серый фон; текста пунктов, наложенного на белую область основного контейнера) больше нет.

## Edge Cases

- **Что если в будущем добавят пункт ещё длиннее** (например, «Что-то-очень-длинное-с-many-слов-в-названии»)? Default: правка рассчитана на текущий набор пунктов. Если в будущем название станет длиннее 25 символов — нужно либо сократить название, либо снова увеличить ширину. Мониторинг — code review при добавлении новых пунктов.
- **Что если бейдж станет трёхзначным** (`submittedAssignmentsCount = 100+`)? Default: `min-width: 18px; padding: 0 5px` на бейджах (`App.vue:763-806`) — бейдж растёт в ширину вместе с цифрой. Для трёхзначного числа ширина ≈36px, плюс текст «Задания редактора» (~145px), итого ~185px — всё ещё помещается в 240px (с padding ещё меньше). Edge case в рамках лимита.
- **Что если в localStorage у пользователя кастомный масштаб браузера (zoom 110–125%)?** Default: ширина сайдбара считается в `px` (фиксировано), все элементы масштабируются пропорционально — пропорции сохраняются. Возможна более плотная посадка текста, но без вылезания.
- **Что если на ширине окна <1024px** (планшет / узкий ноутбук)? Default: основной контейнер сжимается (`.app-main-content` имеет `flex: 1`, `App.vue:817-822`), но сайдбар остаётся 240px — таблицы начнут показывать горизонтальный скокролл внутри себя (`overflow: auto` на `.app-main-content`). Это приемлемо: текущая вёрстка не имеет мобильного режима, и при ширине <1024px админка и так некомфортна (поэтому в AGENTS.md `Проверка — пользователем`).
- **Что если изменение ширины сломает другие элементы** (например, фиксированные отступы в `process_worker`, `MonitorLight`, `ChatNotifyButton` в шапке)? Default: эти элементы находятся в `.app-main-content`, их ширина — `flex: 1`, они подстраиваются. Текущее изменение `width: 190px → 240px` уменьшает основной контейнер **только на 50px** — это не критично (50px помещается в любые отступы).
- **Что если пользователь предпочтёт большую или меньшую ширину** (например, 220px или 260px)? Default: 240px — компромисс, согласован с пользователем. Если позже понадобится — меняется одной строкой CSS (`width: 240px;` в `App.vue:728`). Дополнительных адаптаций не требуется (всё считается через `flex`).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В `webvue3/src/App.vue` (стилевой блок, секция `.app-sidebar`, строка 728) значение `width` MUST быть изменено с `190px` на `240px`. Комментарий «Ширина подобрана так, чтобы самый длинный пункт („Пользователи сайта“) помещался в одну строку» MUST быть обновлён до «Ширина подобрана так, чтобы все пункты меню (включая „Sponsr-синхронизация“ и „История прослушиваний“) и бейджи („Авторы“, „Чат“, „Задания редактора“) полностью помещались внутри сайдбара».
- **FR-002**: Свойство `flex-shrink: 0` на `.app-sidebar` (`App.vue:729`) MUST быть сохранено без изменений — сайдбар не должен сжиматься при уменьшении ширины окна.
- **FR-003**: Свойство `white-space: nowrap` на `.app-sidebar .nav-link` (`App.vue:749`) MUST быть сохранено без изменений — пункты меню всегда в одну строку.
- **FR-004**: `padding: 10px` на `.app-sidebar` (`App.vue:731`) и `padding: 8px 12px` на `.app-link` (`App.vue:745`) MUST быть сохранены без изменений — изменяется ТОЛЬКО ширина сайдбара.
- **FR-005**: Все три правила `.chat-nav-link` / `.songeditor-nav-link` / `.authors-nav-link` (`App.vue:758-807`) с `display: flex !important; align-items: center; justify-content: space-between` MUST быть сохранены без изменений — они и так корректно раздвигают текст и бейдж, при увеличенной ширине будет больше воздуха между ними.
- **FR-006**: Стили бейджей `.chat-nav-badge` / `.songeditor-nav-badge` / `.authors-nav-badge` (`App.vue:763-806`) — `background-color: #d02c3a; color: #fff; border-radius: 10px; min-width: 18px; height: 18px; line-height: 18px; text-align: center; font-size: 11px; padding: 0 5px;` — MUST быть сохранены без изменений.
- **FR-007**: Серверная часть (Kotlin/Spring), БД-миграции, API-эндпоинты MUST NOT быть затронуты. Правка чисто фронтенд-косметическая.
- **FR-008**: LiveDoc `livedocs/features/*` MUST NOT быть затронут (фича — косметика CSS, не меняет bounded context). Если по решению пользователя всё-таки потребуется LiveDoc — он будет в `livedocs/features/266-sidebar-width-wide-items.md` со ссылкой на `App.vue:728`.

### Key Entities *(include if feature involves data)*

- **`.app-sidebar` (CSS, `App.vue:727-735`)**: меняется ТОЛЬКО значение `width` (190px → 240px) и комментарий. Никаких других CSS-свойств не меняется.
- **`.app-main-content` (CSS, `App.vue:817-822`)**: НЕ меняется. Его ширина автоматически уменьшается на 50px за счёт `flex: 1` и `flex-shrink: 0` на сайдбаре.
- **`.nav-link`, `.chat-nav-link`, `.songeditor-nav-link`, `.authors-nav-link`, `.chat-nav-badge`, `.songeditor-nav-badge`, `.authors-nav-badge`**: НЕ меняются.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На ширине окна ≥1280px для самого длинного пункта «Sponsr-синхронизация» `getBoundingClientRect(.nav-link:contains("Sponsr-синхронизация")).right` ≤ `getBoundingClientRect(.app-sidebar).right`. Разница должна быть ≤0 (пункт внутри или точно на границе, без вылезания). Аналогично для «История прослушиваний», «Шаблоны публикаций», «Пользователи сайта», «Синхронизация БД», «Задания редактора» (с бейджем 46), «Авторы» (с бейджем 8), «Чат» (с бейджем).
- **SC-002**: На ширине окна 1280px ширина `.app-main-content` ≥ 1000px (измеряется через `getBoundingClientRect`).
- **SC-003**: На ширине окна 1024px ширина `.app-main-content` ≥ 750px (измеряется через `getBoundingClientRect`).
- **SC-004**: Сравнение скриншота «до» (эталонный sha256:9500214023293f9a60d7d19c9b28ab5ca4ff7d9e2671f556e4b8b179bc4d544c) и скриншота «после» — на скриншоте «после» нет элементов (текста пунктов или бейджей), выходящих за серую область `.app-sidebar` на белую область `.app-main-content`.
- **SC-005**: `npm run build` в `webvue3/` проходит без ошибок и предупреждений (Pass 245 предупреждает: Vite-build ≠ Docker-образ — после правки CSS ОБЯЗАТЕЛЬНО также `bash do.sh build_webvue3` для проверки Docker-multi-stage сборки, поскольку изменения в `webvue3/src/App.vue` попадают в `COPY ./webvue3/` контекст, см. AGENTS.md).
- **SC-006**: `npm run lint` и `npx prettier --check "src/**/*.{vue,js,ts,json}"` в `webvue3/` проходят без НОВЫХ нарушений (baseline OK).
- **SC-007**: `flex-shrink: 0` подтверждён в DevTools — при уменьшении ширины окна от 1920 до 1024px ширина `.app-sidebar` остаётся 240px (не сжимается).

## Assumptions

- 240px — компромиссное значение, согласованное с пользователем 2026-08-30. Достаточно для текущих 26 пунктов + 3 бейджей. Если в будущем добавится пункт длиннее 25 символов — нужно пересмотреть (это отдельная задача, вне scope).
- Текущая вёрстка `.app-sidebar` не имеет мобильного режима (нет hamburger / collapse). На ширине <1024px админка и так некомфортна — это вне scope. Если в будущем появится задача «мобильный режим» — она будет отдельной спекой.
