# Local ADR-0015: Автоматизация allow-list админ-машины — самовосстановление доступа к прод-каналу

* **Status**: Accepted
* **Date**: 2026-10-30
* **Deciders**: команда Karaoke (решения владельца от 2026-10-30, спека 677 / KARAOKE-337)

> **Note**: this is a **local** ADR — describes a specific subsystem
> convention (vs global ADR-0001..0006 which describe project-wide decisions).

## Context

Админ-машина `nsa-i9` ходит к прод-хосту `188.127.240.124` по L4-каналам
`5433` (прод-БД) и `9000` (MinIO). Доступ разрешён **только** для адресов из
allow-list в `/etc/nginx/nginx.conf` (host-nginx, блок `stream {}`, по три строки
`allow …;` + `deny all;` в каждом из двух блоков).

Разбор инцидента 2026-10-30 (коммит владельца `d60e4750`) установил **две разные
причины** «прод недоступен с админ-машины»:

1. **Пул провайдера** плавает ежемесячно: `185.26.28.109` → `83.137.50.231` →
   `185.26.28.199`.
2. **Выход включённого VPN**: с включённым VPN админ-машина ходит к проде через
   VPS `87.58.202.244`, которого в allow-list на проде **нет** (утверждение задачи
   о внесении не подтверждалось на диске).

Симптом в обоих случаях один: конвейер встаёт (синхронизация двух БД, загрузка в
MinIO), а мониторинг на той же машине поднимает **ложный** CRITICAL «Прод-сервер
недоступен» при живом проде — тот же механизм, что дал ложный CRITICAL 5+ часов
2026-10-23 (ADR `local-0014`, спека 676).

Механизма доставки `nginx.conf` из репозитория на прод **нет**: прод — не
git-чекаут, конфиги копируются вручную (`prod-config-delivery.md` §1), каталог
`/root/Karaoke/deploy/prod-single-host/` на проде пуст.

## Решения владельца (2026-10-30)

- **Д-1**: прод-хоста — **операционная истина**. Правка применяется прямо на проде
  (бэкап → проверка синтаксиса → перезагрузка → контрольная проверка → откат).
  Репозиторий догоняет через PR, который одобряет и сливает владелец: Forgejo не
  допускает одобрения автором собственного PR.
- **Д-2**: уведомления — Telegram, через существующего бота проекта; токен читается
  из окружения и не попадает в репозиторий, журнал и уведомления.
- **Д-3**: таймер каждые 10 минут; не более одной правки за 30 минут.
- **Д-4**: текущую дыру (адрес выхода VPN `87.58.202.244`) вручную **не** закрывать —
  ждём автоматизацию.

## Decision

1. **Скрипт** `deploy/admin-ip-allowlist.sh` (bash) под systemd-таймером
   `deploy/admin-ip-allowlist.timer` (`OnUnitActiveSec=10min`, Д-3). Юниты лежат в
   репозитории; **установку выполняет владелец** (как
   `deploy/heap-dump-retention.{service,timer}`).
2. **Детектор**: с админ-машины — TCP `5433`, TCP `9000` и HTTPS
   `https://sm-karaoke.ru/health` (2xx). Если HTTPS не отвечает — причина не в
   allow-list и адрес **не** добавляется (FR-002, SC-004).
3. **Адрес**: машинно, с админ-машины, из публичного HTTPS-сервиса определения
   внешнего адреса, с резервным источником (FR-003); список источников идёт
   по кругу, расхождение ответов → правка не выполняется; адрес валидируется на
   публичность (FR-004).
4. **Правка** — хирургическая: ровно одна строка `allow <ip>;` перед `deny all;` в
   каждом из двух stream-блоков (FR-006). Порядок (FR-007, FR-008, FR-009):
   перепроверка адреса → временный файл → `nginx -t -c <temp>` → бэкап →
   **подмена содержимым с сохранением inode** (`cat`, не `mv`) → проверка целостности
   записи (sha256) → `nginx -t` → `nginx -s reload` → контрольная проверка
   (TCP 5433/9000 + HTTPS). Любой сбой → восстановление из бэкапа содержимым,
   reload, уведомление владельцу.
   Перед применением выполняется проверка diff'а (FR-020): изменение должно
   состоять **только** из добавленных строк `allow`.
5. **Частота**: не более одной применённой правки за 30 минут (FR-010); состояние —
   в файле рядом с журналом, вне репозитория.
6. **Журнал**: отдельный файл + journald, формат `event:key=value` (ADR
   `local-0005`): время, адрес, причина срабатывания, результат проверки синтаксиса,
   результат контрольной проверки, действие, признак отката (FR-012).
7. **Уведомления**: Telegram-бот проекта (Д-2). Токен **не попадает в argv** —
   Bot API вызывается через `curl -K` с конфиг-файлом `600` (guard
   `tools/check-secret-in-argv.sh`, BR-551/552/605).
8. **PR**: после успешного применения — через **Forgejo API** (contents API: ветка →
   коммит → `POST /pulls`). Локальный git не используется: рабочее дерево
   админ-машины используется другими сессиями, и `git checkout` из таймера устроил бы
   гонку (прецедент Pass 379, IX.3). Состав PR — **репозиторная копия плюс только
   недостающая строка `allow`**: посторонние расхождения прод↔репозиторий в PR не
   выносятся, они фиксируются в журнале и сообщаются владельцу. Слияние — за
   владельцем (Д-1).
9. **Проверяемость**: режим `--self-test` (FR-018) — изолированный сценарий «IP
   сменился» без обращения к прод-хосту: добавление, проверка синтаксиса, откат при
   ошибке, отказ при недоступном проде, ограничение частоты, состав PR.
10. **Guard** `tools/check-allowlist-guardrails.sh` (BR-631): структура allow-list в
   репозиторной копии, уникальность и публичность адресов, заданное окно частоты,
   отсутствие секретов, период таймера. Подключён к pre-commit и к обеим копиям
   CI-workflow.

## Отклонённые альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| WireGuard-туннель вместо автоматизации (уровень 1) | владелец выбрал уровень 2: автоматизацию allow-list (Д-1…Д-4) |
| Только ручная правка по текущему адресу через PR | не закрывает «прод недоступен» без участия человека; Д-1 фиксирует автоматизацию как основной путь |
| `allow 0.0.0.0/0;` или снятие `deny all;` | снимает ограничение доступа к прод-БД и MinIO вообще (ADR `0004-karaoke-app-admin-only`) |
| Автоматическое удаление старых адресов | FR-011: адреса не удаляются никогда, удаление — только по слову владельца; в списке сохраняются все адреса, включая четыре последних |
| Правка `nginx.conf` через `sed -i` по номеру строки | номера строк нестабильны между продом и репозиторием; нужен diff и откат |
| Атомарное переименование файла (`mv`) вместо подмены содержимым | FR-007 прямо требует сохранения inode. Факт снят на проде 2026-10-30: `findmnt -T /etc/nginx/nginx.conf` → TARGET `/`, SOURCE `/dev/vda2`, ext4 — файл **не** является точкой монтирования, поэтому требование об inode ничего не защищает и пришло из практики контейнерных bind-mount'ов. Реализована буква FR-007 (`cat` + проверка sha256); в скрипт добавлена проверка `findmnt -T` с записью результата в журнал — переключение станет одной правкой в одном месте, если владелец разрешит rename |
| `access_log` в stream-блоках (FR-019) | SHOULD, а изменение прода требует согласия владельца — вне объёма (спека 677) |
| Локальный `git` из таймера для создания PR | гонка с другими сессиями в том же checkout (Pass 379 / IX.3) |

## Consequences

- Разворот внешнего адреса перестаёт означать простой конвейера и ложный CRITICAL:
  доступ восстанавливается автоматически за цикл таймера (10 минут) плюс время
  применения правки (секунды).
- Прод-конфигурация меняет автоматика, поэтому защита выстроена слоями: бэкап,
  двойная проверка синтаксиса, проверка целостности записи, контрольная проверка
  фактического ответа, откат, ограничение частоты, проверка diff'а, guard в CI.
- Репозиторий догоняет прод через PR, который одобряет владелец: автоматизация
  никогда не сливает PR сама (Д-1, Forgejo не допускает одобрения автором своего PR).
- Появился новый операционный артефакт на админ-машине (таймер) и новый формат
  журнала; оба описаны в `knowledge/guidelines/runbooks/prod-config-delivery.md` §8 и
  `knowledge/product/features/admin-ip-allowlist.md`.
