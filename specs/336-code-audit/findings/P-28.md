## Сверки (спорное, без severity)

1. **Транспорт realtime в этой сборке мёртв.** `connect()` открывает `new SockJS('/api/message')` (`songs2.html:39, 49`), но в `karaoke-app` такого эндпоинта нет: `GET :8898/api/message/info` → **404** (и `:7906/api/message/info` → 404); брокер `@EnableWebSocketMessageBroker` + `addEndpoint("/api/message").withSockJS()` есть только в `karaoke-web` (`WebSocketConfig.kt:15, 23`), а вызовов `convertAndSend` в `/api/messages/*` в репозитории нет вовсе (grep по `karaoke-app` и `karaoke-web`). То есть P-28-04 — не единственная причина: даже с исправленными именами полей сообщения некому отправлять. Вопрос лиду: считать это отдельной находкой (ERR) или добить P-28-04 формулировкой «канал не подключён»? Ответ на стороне архитектуры: возможно, страница рассчитана на другую топологию (прод-nginx), которой в этой сборке нет.
2. **Кнопка «Создать kdenlive files» вызывает удалённый эндпоинт.** `doCreateKdenliveFiles` (`songs2.html:1192–1206`) делает GET `/song/{id}/createkdenlivefiles`, а эндпоинт удалён по `specs/544-song-artifact-cleanup` FR-009: «`// specs/544-song-artifact-cleanup (FR-009): эндпоинт /song/{id}/createkdenlivefiles удалён` / `// вместе с писателем .kdenlive-файлов; вызовов во фронтендах не было.`» (`MainController.kt:1484–1485`). Вызов есть — кнопка `button_kdenlive_files` (`area_center_column.html:584`); клик даёт 404 и молча ничего не делает (P-28-05). Это «удалённая функциональность со stale-UI»: решить — убрать кнопку или вернуть эндпоинт.
3. **Мутирующие операции через GET.** `doDelete` → `GET /song/{id}/delete` (`MainController.kt:341–355`), `doSymlink`, `doSetDateTimeAuthor` (массовый пересчёт дат публикации у всех песен автора с `id` больше текущей — `Song.setPublishDateTimeToAuthor`, `Song.kt:8785–8808`), `doProcess` (`doprocess*`). В проекте GET-мутации — принятая практика (`AGENTS.md` Pass 381 документирует `GET /process/stop`), поэтому отдельной записью не завожу; но для удаления это значит, что любой GET (prefetch, сканер ссылок) удаляет песню **вместе с файлами** — `deleteFromDb` сначала удаляет файлы на диске и только потом строку (`Song.kt:6066–6085`, без транзакции). Прошу решения: считать ли это допустимым для `delete`.
4. **Копирование в буфер и secure context.** Часть обработчиков использует `navigator.clipboard.writeText` без `catch` и без fallback (:621, :643, :1101), часть — `copyToClipboard` через `document.execCommand` (:1997–2007). В не-secure контексте (страница по `http://<ip>:8898`, не localhost) `navigator.clipboard` === `undefined` → TypeError. Проверено только на localhost (secure context), поэтому не запись: зависит от того, открывают ли админку по IP.
