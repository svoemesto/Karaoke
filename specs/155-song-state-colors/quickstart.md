# Quickstart: проверка состояний и цветов песен

## Предварительные условия

- Репозиторий находится на ветке `155-song-state-colors`.
- Установлены JDK 17, Gradle wrapper и зависимости `webvue3`.
- Для автоматических unit-тестов БД, сеть и браузер не требуются.
- Для ручной проверки UI доступно локальное admin-окружение проекта.

## Автоматические проверки

Из корня репозитория:

```bash
./gradlew :karaoke-app:test --tests "com.svoemesto.karaokeapp.model.SongStateTest"
./gradlew :karaoke-app:compileKotlin
cd webvue3 && npm run lint:check && cd ..
./gradlew ktlintCheck
```

Для полного CI-предварительного прогона дополнительно выполнить:

```bash
cd karaoke-public && npm run lint:check && cd ..
./tools/check-kdoc-coverage.sh --strict
./tools/check-jsdoc-coverage.sh webvue3
./tools/check-jsdoc-coverage.sh karaoke-public
./tools/check-feature-doc.sh docs/features/song-state-colors.md
pre-commit run --all-files
```

## Матрица автоматических тестов

Тесты должны проверять как минимум:

1. `idStatus < 6` с датой, временем и `free=true` → `IN_WORK`, цвет пустой.
2. `idStatus >= 6`, `free=true`, без даты и времени → `ON_AIR`, `#33FF33`.
3. Готовая песня с эфиром сегодня в будущем → `TODAY`, `#FFFF00`.
4. Готовая песня с эфиром внутри бесплатного окна → `ON_AIR`, `#33FF33`.
5. Готовая песня с эфиром после окончания бесплатного окна → `DONE`, `#CCFFCC`.
6. Готовая песня с будущим эфиром не сегодня → `DONE`, `#CCFFCC`.
7. Готовая не бесплатная песня без даты и времени → `EXCLUSIVE`, `#99CCFF`.
8. Неполная или некорректная пара даты/времени → `EXCLUSIVE` для готовой не бесплатной песни.
9. Граница момента эфира и граница окончания окна проверяются с фиксированным значением `now`.

## Ручная проверка backend/frontend

1. Запустить admin frontend штатной командой проекта и открыть экран публикаций.
2. Проверить, что в легенде отображаются ровно пять кнопок: `DONE`, `TODAY`, `ON_AIR`, `EXCLUSIVE`, `IN_WORK`, с цветами из `contracts/song-state-color.md`.
3. Нажать каждую кнопку и убедиться, что отправляется соответствующий `param` из `contracts/publications-date-filter.md`, дата диапазона обновляется, а сетка публикаций загружается без ошибки.
4. Проверить, что старые кнопки `STATE_ALL_DONE`, `STATE_OVERDUE`, `STATE_ALL_UPLOADED`, `STATE_WO_TG`, `STATE_WO_VK`, `STATE_WO_DZEN`, `STATE_WO_VKG` и `STATUS_0..6` отсутствуют.
5. Найти одну песню каждого типа в таблице песен и сетке публикаций. Цвет имени песни должен совпадать в обоих представлениях.
6. Для песни со статусом ниже 6 проверить отсутствие специального фона, а не подстановку старого цвета стадии.
7. Изменить дату/время или `free`, обновить данные и проверить пересчёт цвета без старой категории.

## Ожидаемый результат

Все пять состояний покрыты автоматическими тестами и ручной матрицей, UI не отправляет удалённые токены, а цвет одной песни одинаков во всех административных представлениях.
