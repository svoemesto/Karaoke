# ADR-local-0010: Harbor как основной каталог образов, Zot — зеркало и локальный кэш прода

## Context & Problem | Контекст и проблема

До 2026-10-27 единственным registry был Zot на прод-хосте (`sm-karaoke.ru:5443`).
Он решал задачу доставки образов на прод, но не давал каталога с UI, RBAC,
робот-аккаунтами по проектам и разделением организаций. Для второй команды
(`dub2000`) и для роста числа проектов нужен полноценный registry-каталог,
который не лежит на прод-хосте и не смешивает права команд.

Одновременно действовал принцип: **прод не должен зависеть от чужих серверов
в момент деплоя** — образы для прода обязаны быть локально.

## Decision | Решение

1. **Основной каталог образов — Harbor** на infra-сервере (`registry.sm-karaoke.ru`,
   Harbor v2.14.6, LXD-контейнер). TLS терминирует host-nginx, данные — HDD
   `/srv/infra/registry`, БД — SSD.
2. **Проекты Harbor**: `svoemesto`, `dub2000`, `mirror`; `library` — публичный.
   Разграничение — членство в проекте и робот-аккаунты (`robot$<project>+<name>`).
3. **Zot на прод-хосте остаётся** и работает в двух ролях:
   * **живое зеркало** Harbor (репликация push, event-based);
   * **локальный источник образов для деплоя прода**.
   Он остаётся **writable**: read-only или выключение ломают обе роли.
4. **Перенос образов** — `skopeo copy --all` с сохранением digest; для образов,
   отсутствующих в Harbor, допускается отдельный тег (`0.1.0-f1466a0`) без
   перезаписи существующих.
5. **Проект `mirror` — public на чтение**: сторонние вендорные образы не секрет,
   а закрытый проект приводил к «no such manifest» у чужих учёток.

## Rationale | Обоснование

* **Оставить только Zot**: отклонено — нет UI, RBAC по проектам и роботов;
  каталог остаётся на прод-хосте.
* **Оставить только Harbor, Zot выключить**: отклонено — прод начал бы тянуть
  образы с чужого сервера, нарушая независимость деплоя; кроме того, при
  недоступности infra-сервера встал бы и деплой.
* **Pull-through cache вместо зеркала**: отклонено — не даёт гарантии, что на
  проде лежит именно запушенный образ к моменту деплоя.

## Consequences | Последствия

1. **Запрет**: не переводить Zot в read-only и не выключать, пока прод тянет
   образы из него. Это вернётся в план только при осознанном решении
   «прод тянет напрямую из Harbor».
2. **Инвариант**: каждый push в Harbor, затрагивающий прод-образы, обязан
   доехать до Zot (репликация event-based). Отставание репликации — инцидент.
3. **Инвариант**: digest'ы прод-образов в Harbor и Zot совпадают; проверка —
   сверка `Docker-Content-Digest`.
4. **Известное ограничение**: multi-arch образы, залитые через `docker push`,
   могут иметь другой digest, чем в Zot; для точного переноса использовать
   `skopeo copy --all`.
5. **Required Update**: `knowledge/system/infra/registry.md`,
   `knowledge/system/infra/harbor-registry.md`,
   `knowledge/system/infra/external-infra.md`.
