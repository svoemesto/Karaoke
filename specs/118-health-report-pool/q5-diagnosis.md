## Диагностика после скриншота владельца

Владелец обнаружил:
1. **Синий бейдж не виден** — несмотря на наличие заданий.
2. **Механизм «всплытия» не работает** — при нахождении на стр.1 обрабатываются
   песни другой страницы (видно в логах karaoke-app).

### Анализ

**SSE-событий с бекенда действительно нет** (проверено прямым подключением
к `/api/subscribe` через curl). За 10 секунд подписки — только `HEALTH_REPORTS`
и `LOG`. Ни `PROCESS_COUNT_WAITING`, ни `PROCESS_LANE_COUNT_WAITING`.

Возможные причины:
- В lane1 (HR) сейчас `0 WAITING` — все процессы в WORKING/DONE. Backend не
  шлёт `PROCESS_COUNT_WAITING` потому что общий счётчик не менялся (дедупликация).
- Это означает: **бейдж может быть корректно скрыт условием `v-if="... && poolCountWaiting > 0"`**.

**Но**: серый бейдж KaraokeProcess (`text-count-waiting`) тоже не виден
на скриншоте. У него нет условия `v-if` — он должен быть виден всегда при
`hideButton=false`. Если серый тоже не виден — значит **рендеринг бейджей
был сломан ДО моих правок** (это pre-existing проблема).

**По фиксу «всплытия» (#122)**: я ошибся в направлении. Залида:
- **«пул» в #118** — это backend-cascade (`tbl_processes` lane1), а не UI
  `hrQueue` (UI-очередь для отчётов).
- **«чанки»** — это `getProcessesToStart` SQL `ROW_NUMBER()` в backend.
- **«всплытие»** должно быть на backend: при возврате на стр.X нужно
  обновить порядок песен стр.X в `tbl_processes` lane1, чтобы они
  обрабатывались первыми.

Мой PR #492 адресовал UI-очередь `hrQueue` — это **не та проблема**.

### Что нужно сделать

   - Возможный фикс: при возврате на стр.X вызвать backend endpoint

     обновит `process_order` (или аналогичное поле) в `tbl_processes` lane1
     для процессов этих песен, чтобы они получили максимальный приоритет.
   - Это требует backend + frontend правки + нового API.

2. **#123 — диагностика бейджа**:

   - Нужны DevTools данные от владельца: `console.log(document.querySelector('.text-pool-size'))`,
     `console.log(store.state.processes.countWaitingByThreadId)`.

3. **#125 (backend `countwaiting?threadId=1`)** — проверено через curl: код в
