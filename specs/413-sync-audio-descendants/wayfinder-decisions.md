# #141 — Решения механизма «Синхронизация аудио-потомков»

> **Сессия**: 2026-09-19, wayfinder→spec (ветка `413-sync-audio-descendants`).
> **Артефакт**: [`specs/413-sync-audio-descendants/spec.md`](../specs/413-sync-audio-descendants/spec.md).

Туман рассеян wayfinder-грилем (28 узлов дерева решений). Все спорные вопросы
сняты с владельцем, назначение — спека для последующей реализации.

## Ключевые решения

### Триггер и ворота

- Ворота: синхронизация запускается, только если у **родителя статус ≥5**.
  Любые правки родителя при статусе <5 на потомках не отражаются.
- Условие запуска: content-diff (маркеры/текст/форматирование) **или** переход
  статуса `<5 → 5/6` (например, 2→5, 2→6). Переход 5→6 повторно не гоняет сверку.
- Точка перехвата: общий save-путь `Song` с гейтом по diff — иначе ~80 фоновых
  вызовов `saveToDb` (sync/autopublish/workers/HealthReport) дали бы ложные сверки.
- Для родителя типа «Песня» (`song`) маркеры обязательны; `instrumental`/`poetry` —
  пустые допустимы.
- Тип потомка ≠ тип родителя — всё равно синхронизировать.

### Что переносим

- Набор эквивалентен существующему `applyAudioParentMarkers`: sourceText, resultText,
  sourceMarkers (сдвиг на дельту + END по длительности потомка), formattedText*.
  Тональность/BPM/ссылки/картинки — не трогаем.
- Число голосов потомка приводится к числу голосов родителя (лишние обрезать,
  недостающие дополнить пустыми).
- После переноса — перегенерировать `.voice{N}.srt`.
- Обновлять `audio_similarity_percent`, `audio_delta_ms`, `audio_compare_history`.
- Статус потомка → **5** (если иной). Фильтр кандидатов: `audio_parent_id = <родитель>`,
  `status < 6`.

### Сверка и безопасность

- Перед переносом — повторная аудио-сверка; порог 95 %. Ниже порога — пропуск с логом,
  данные и статус не меняются.
- Только прямые дети (`audio_parent_id = id` родителя), без рекурсии.
- Активный `KaraokeProcess` у потомка → пропуск с логом.
- Очередь с дедупликацией по id, последовательная обработка.
- Подавление триггеров, порождённых собственной записью синхронизации (защита от каскада).
- Общий лок для авто-синхронизации и админ-функции.
- Только локальная БД, без push на прод.

### Админ-функция

- Новая кнопка на `HomeView.vue` + эндпоинт (в идеологии Custom Function): фоновый
  поток, внутри по одному, лог по каждой песне, SSE-тост со сводкой.
- Перебор: потомки `audio_parent_id <> 0` со статусом <6, группировка по родителю
  (каждый уникальный родитель — один раз).
