# Feature Specification: Шаблоны автоматических новостей сайта

**Feature Branch**: `128-news-publish-templates`

**Created**: 2026-08-03

**Status**: Draft

**Input**: User description: "Задача - в компонент админки «Шаблоны публикаций» добавить шаблоны для автоматических новостей на проде (выход «в эфир» и добавление в коллекцию). Шаблоны так же, как и для телеграма и ВК, должны поддерживать плейсхолдеры. В случае с новостями на проде шаблоны должны быть и для заголовка, и для текста новости."

## Контекст

В проекте уже существует механизм автоматических новостей сайта
(`specs/089-auto-news-song-release`, `specs/101-song-news-flag`,
`specs/092-fix-auto-news-triggers`, `specs/125-news-flags-backfix`):
`SongReleaseAnnouncementService` в двух независимых точках создаёт
записи `tbl_news` (`source="auto"`, `publish_at <= now()`), которые
появляются в публичной ленте новостей сайта:

- **«В эфире»** (`category="air"`) — плановая проверка
  `SongReleaseAnnouncementScheduler` (~раз в 5 минут, PROD): песня
  стала публично watchable (статус ≥6 + наступила дата эфира + стемы/
  обложки/маркеры готовы) впервые → создаётся новость. Заголовок и тело
  сегодня формируются хардкод-строками в Kotlin:
  `title = "Новая песня: ${author} — ${songName}${albumYearSuffix}"`,
  `body = "Песня «${songName}» (${bodyDetails}) вышла в эфир."`.
- **«В коллекции»** (`category="premium"`) — детекция перехода флага
  `Song.newsAvailableAnnounced` false→true при применении синхронизации
  на сервере (`MainController.doChangeRecords`). Заголовок и тело сегодня
  формируются хардкод-строками:
  `title = "Новая песня: ${author} — ${songName}${albumYearSuffix}"`,
  `body = "Песня «${songName}» (${bodyDetails}) появилась в коллекции."`.

Формулировки этих новостей зашиты в код и не редактируются без
перекомпиляции `karaoke-app`/`karaoke-web`. Администратор не может
поменять формулировку, добавить хештег, эмодзи или ссылку в другом
формате, не трогая код.

В админке `webvue3` уже есть компонент «Шаблоны публикаций»
(`PublishTemplatesView.vue`, роут `/publish-templates`) с двумя
платформами-вкладками — **ВКонтакте** и **Telegram** (`specs/121-vk-news-auto-publish`,
`specs/113-telegram-demo-publish`). Каждая платформа имеет шаблоны по
типам (`air`/`premium`), поддерживает плейсхолдеры в фигурных скобках
(`{author}`, `{songName}`, `{link}`, `{body}` и т.п.), подсветку
плейсхолдеров, предупреждение о несбалансированных скобках, превью на
тестовой песне и сброс к дефолту. Шаблоны хранятся в `KaraokeProperties`
(строковые ключи `vkTemplateAir`, `vkTemplatePremium`,
`telegramTemplateAir`, `telegramTemplatePremium`) и применяются без
перезапуска.

Эта спецификация описывает **третью вкладку/платформу** того же
компонента — «Новости сайта» (прода), с двумя отличиями от ВК/Telegram:

1. Шаблон состоит из **двух полей** — заголовок (`title`) и текст
   (`body`) новости, т.к. `tbl_news` имеет отдельные колонки `title` и
   `body` (а не единый caption, как у поста ВК/Telegram).
2. Триггером применения шаблона является создание auto-новости на
   проде (`SongReleaseAnnouncementService`), а не отправка во внешний
   канал. Шаблон «рендерится» в заголовок+текст записи `tbl_news` при
   её автоматическом создании — то есть прямо в момент вызова
   `News.createAutoAnnouncement`.

Два типа шаблонов соответствуют двум существующим категориям
авто-новостей: **«В эфире»** (`air`) и **«В коллекции»** (`premium`).
Для каждого типа — своя пара шаблонов `title`/`body`. Шаблоны
редактируются администратором в `webvue3` и применяются без
перезапуска `karaoke-web` (и `karaoke-app`, где работает детектор
«в коллекции» при sync).

## Clarifications

### Session 2026-08-03

- Q: Где хранить 4 строковых ключа шаблонов новостей сайта
  (`newsTemplateAirTitle/Body`, `newsTemplatePremiumTitle/Body`), учитывая
  что рендеринг шаблона происходит на проде (`karaoke-web`:
  `SongReleaseAnnouncementScheduler` для `air`,
  `MainController.doChangeRecords` для `premium`), где
  `KaraokeProperties`-файл `/sm-karaoke/system/Karaoke.properties`
  недоступен (он есть только на admin-машине); ВК/Telegram-шаблоны этому
  не подвержены, т.к. их боты запускаются на admin-машине → A:
  `tbl_public_settings` (Postgres) — единый источник истины, читается и
  с admin, и с прода через JDBC (по образцу
  `isNewsAutoPublishKillSwitchActive` в `News.kt`, `CaptchaConfigService`
  в `karaoke-web`). Запись — через существующий endpoint
  `/api/publicsettings/*` (`PublicSettingsController`/`PublicSettingsWebController`),
  чтение в точке рендера — прямым JDBC-запросом (не через
  `KaraokeProperties`). Не требует sync-механизма между файлом и БД.
- Q: Какой набор плейсхолдеров использовать для дефолтов (FR-010),
  чтобы сохранилась byte-идентичность текущим хардкод-формулировкам,
  где `albumYearSuffix` (`" (альбом «X», Y)"`) и `bodyDetails`
  (`"author, альбом «X», Y"`) — составные хелперы с условной логикой
  (пустой альбом/год → пустой суффикс/усечённый список) → Гибрид:
  `{albumYearSuffix}` и `{bodyDetails}` как цельные составные
  плейсхолдеры (инкапсулируют существующие хелперы
  `SongReleaseAnnouncementService.albumYearSuffix`/`bodyDetails`,
  byte-идентичность гарантируется вызовом тех же функций) +
  расширенный набор granular плейсхолдеров ВК/Telegram: `{author}`,
  `{songName}`, `{songNameCensored}`, `{year}`, `{album}`, `{link}`,
  `{id}`, `{newsBody}`, `{descriptionHeader}`, `{descriptionFooter}`,
  `{description}`, `{descriptionWithTimecodes}`. Дефолты используют
  составные `{albumYearSuffix}`/`{bodyDetails}` для byte-идентичности;
  администратор может использовать granularные для пользовательских
  правок. Маркер `{demoVideo}` НЕ включён (новости сайта не
  прикрепляют видео — это внешний пост VK/Telegram). Полный список
  плейсхолдеров фиксируется в `NewsTemplateService.PLACEHOLDERS` по
  образцу `VkTemplateService.PLACEHOLDERS` (с описаниями для UI).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Администратор редактирует формулировку авто-новости «в эфире» без правки кода (Priority: P1)

Администратор хочет изменить текст авто-новости о выходе песни в эфир
(добавить хештег, эмодзи, поменять порядок автора/названия, убрать
упоминание альбома) — сегодня это требует редактирования Kotlin-строк
в `SongReleaseAnnouncementService` и перевыпуска `karaoke-app`. С этой
фичей администратор открывает «Шаблоны публикаций» → вкладку «Новости
сайта», правит шаблон `title`/`body` для типа «В эфире (air)»,
сохраняет — и следующая авто-новость создаётся уже по новому шаблону,
без перекомпиляции.

**Why this priority**: Это основная ценность фичи — снять с
администратора зависимость от разработчика для правки формулировок
авто-новостей. Сегодня любое изменение формулировки — это код-правка +
релиз `karaoke-app` + синхронизация на прод, что блокирует быстрые
текстовые правки.

**Independent Test**: Открыть «Шаблоны публикаций» → «Новости сайта»,
изменить шаблон `body` для «В эфире (air)» (например, добавить эмодзи
♪ в конец). Сохранить. Дождиться (или смоделировать) выход тестовой
песни в эфир. Убедиться, что созданная auto-новость в `tbl_news` и в
публичной ленте содержит новый текст с эмодзи — без перезапуска
`karaoke-app`/`karaoke-web`.

**Acceptance Scenarios**:

1. **Given** администратор открыл «Шаблоны публикаций» → «Новости
   сайта», **When** он видит шаблон типа «В эфире (air)» с двумя полями
   (заголовок и текст) и списком доступных плейсхолдеров, **Then**
   оба поля редактируются как многострочные текстовые поля с подсветкой
   плейсхолдеров и предупреждением о несбалансированных скобках.
2. **Given** администратор отредактировал шаблон `body` типа «air» и
   сохранил, **When** `SongReleaseAnnouncementService.checkOnAirWindow`
   создаёт новую auto-новость категории `air`, **Then** `body`
   созданной записи `tbl_news` сформирован по обновлённому шаблону (без
   перезапуска `karaoke-app`/`karaoke-web`).
3. **Given** администратор отредактировал шаблон `title` типа «air» и
   сохранил, **When** создаётся новая auto-новость категории `air`,
   **Then** `title` созданной записи `tbl_news` сформирован по
   обновлённому шаблону.
4. **Given** администратор ввёл в шаблон несбалансированную скобку
   (например, `{author` без `}`), **When** он сохраняет шаблон,
   **Then** редактор показывает предупреждение, но НЕ блокирует
   сохранение — механизм применения шаблона трактует неизвестные
   плейсхолдеры как literal-текст (не заменяет, не падает).

### User Story 2 - Администратор редактирует формулировку авто-новости «в коллекции» (Priority: P1)

Администратор хочет изменить формулировку авто-новости «песня появилась
в коллекции» (категория `premium`, триггер — переход флага
`Song.newsAvailableAnnounced` false→true при sync). Например,
переформулировать с «появилась в коллекции» на «доступна
премиум-подписчикам», добавить хештег, убрать альбом. С этой фичей
администратор открывает «Шаблоны публикаций» → «Новости сайта»,
правит шаблон `title`/`body` для типа «В коллекции (premium)»,
сохраняет — и следующая auto-новость категории `premium` создаётся
по новому шаблону.

**Why this priority**: Двойник User Story 1 для второй категории
авто-новостей. Без этого шаблон «в коллекции» остался бы хардкодом,
и фича была бы неполной (только `air`).

**Independent Test**: Открыть «Шаблоны публикаций» → «Новости сайта»,
изменить шаблон `body` для «В коллекции (premium)». Сохранить.
Смоделировать переход `newsAvailableAnnounced` false→true для тестовой
песни через sync. Убедиться, что созданная auto-новость категории
`premium` в `tbl_news` содержит новый текст — без перезапуска.

**Acceptance Scenarios**:

1. **Given** администратор открыл «Шаблоны публикаций» → «Новости
   сайта», **When** он видит шаблон типа «В коллекции (premium)» с
   двумя полями (заголовок и текст), **Then** оба поля редактируются
   как многострочные текстовые поля с подсветкой плейсхолдеров.
2. **Given** администратор отредактировал шаблон `body` типа «premium»
   и сохранил, **When** `SongReleaseAnnouncementService.detectAndAnnounceAvailability`
   создаёт новую auto-новость категории `premium`, **Then** `body`
   созданной записи сформирован по обновлённому шаблону (без
   перезапуска).
3. **Given** администратор отредактировал шаблон `title` типа «premium»,
   **When** создаётся новая auto-новость категории `premium`, **Then**
   `title` созданной записи сформирован по обновлённому шаблону.

### User Story 3 - Превью шаблона новости на тестовой песне (Priority: P2)

Администратор перед сохранением шаблона хочет увидеть, как будет
выглядеть новость для конкретной песни — заголовок и текст с
подставленными значениями плейсхолдеров. Это аналог превью в ВК/
Telegram-вкладках, но возвращает два поля (`title` и `body`) вместо
одного `caption`.

**Why this priority**: Превью снижает риск сохранить шаблон с опечаткой
в плейсхолдере и увидеть ошибку только на следующей реальной
авто-новости (которую нельзя откатить без ручного удаления записи).

**Independent Test**: В редакторе шаблона новости ввести id тестовой
песни, нажать «Превью». Убедиться, что показаны подставленные
заголовок и текст. Если в шаблоне есть неизвестный плейсхолдер
(например, `{nonexistent}`) — он остаётся literal-текстом в превью.

**Acceptance Scenarios**:

1. **Given** администратор ввёл id существующей песни в поле превью
   шаблона новости, **When** он нажимает «Превью», **Then** система
   возвращает и показывает отдельно отрендеренные `title` и `body` с
   подставленными значениями плейсхолдеров для этой песни.
2. **Given** шаблон содержит неизвестный плейсхолдер `{nonexistent}`,
   **When** администратор запрашивает превью, **Then** превью
   содержит literal-текст `{nonexistent}` (не заменяется, не падает).
3. **Given** шаблон содержит несбалансированную скобку, **When**
   администратор запрашивает превью, **Then** превью отрабатывает без
   ошибки, некорректная скобка остаётся literal-текстом.

---

### User Story 4 - Сброс шаблона к дефолту (Priority: P3)

Администратор может вернуть любой из четырёх шаблонов (`air`/`premium`
× `title`/`body`) к заводскому дефолту одной кнопкой — как в ВК/
Telegram-вкладках. Дефолт соответствует текущим хардкод-формулировкам
(чтобы при первом развёртывании фичи формулировки авто-новостей не
изменились).

**Why this priority**: Дефолт — страховка от того, что администратор
сломает шаблон и не сможет вернуть «как было». Заводские дефолты
должны сохранять текущее поведение до правки.

**Independent Test**: Изменить шаблон, сохранить. Нажать «Сбросить к
дефолту». Поле вернулось к исходной формулировке. Сохранить. Убедиться,
что следующая авто-новость использует дефолтную формулировку.

**Acceptance Scenarios**:

1. **Given** администратор изменил шаблон, **When** он нажимает
   «Сбросить к дефолту», **Then** поле шаблона (title или body)
   заполняется заводским дефолтным значением (но не сохраняется
   автоматически — нужно нажать «Сохранить»).
2. **Given** заводской дефолт для `air`/`body`, **When** шаблон
   сброшен, **Then** дефолт совпадает с текущей хардкод-формулировкой
   `SongReleaseAnnouncementService` для категории `air`
   («Песня «{songName}» (...) вышла в эфир.»).
3. **Given** заводской дефолт для `premium`/`body`, **When** шаблон
   сброшен, **Then** дефолт совпадает с текущей хардкод-формулировкой
   для категории `premium` («Песня «{songName}» (...) появилась в
   коллекции.»).

### Edge Cases

- **Неизвестный плейсхолдер** (`{nonexistent}`) — остаётся literal-
  текстом, не обрезается, не вызывает ошибку (аналог ВК/Telegram-
  шаблонов, FR-023 `specs/121-vk-news-auto-publish`).
- **Несбалансированные скобки** (`{author` без `}`) — редактор
  показывает предупреждение, но НЕ блокирует сохранение; при рендере
  некорректная скобка остаётся literal-текстом.
- **Песня без альбома/года** — плейсхолдеры альбома/года должны
  корректно подставляться (пустая строка или пропущенный суффикс),
  формулировка не должна содержать пустые «альбом «»» или «()».
  Точный способ (плейсхолдер `{albumYearSuffix}` целиком vs отдельные
  `{album}`/`{year}`) — **РЕШЕНО в plan.md**: используются составные
  плейсхолдеры `{albumYearSuffix}` (суффикс « (альбом «X», Y)», пустой
  если альбом/год не заполнены) и `{bodyDetails}` (строка author, альбом
  «X», Y) — byte-идентично существующим хелперам
  `SongReleaseAnnouncementService.albumYearSuffix`/`bodyDetails`. См.
  FR-004, FR-010.
- **Шаблон `title` превышает лимит длины заголовка `tbl_news.title`**
  (`VARCHAR(500)`) — **РЕШЕНО в plan.md (FR-010a)**: усекается после
  рендера до `NEWS_TITLE_MAX_LENGTH=500` с суффиксом `…` (по образцу
  `VkTemplateService.truncate`). Превышение фиксируется признаком
  `titleTruncated=true` в ответе `POST /api/news/templates/preview`
  (contracts/api.md §3).
- **Шаблон `body` превышает лимит длины `tbl_news.body`** — `body` имеет
  тип `TEXT` (без лимита), усечение не требуется; `bodyTruncated` всегда
  `false` (contracts/api.md §3).
- **Первое включение после развёртывания** — заводские дефолты
  совпадают с текущими хардкод-формулировками, поэтому вид
  авто-новостей не меняется при выпуске фичи. Администратор может
  начать править шаблоны сразу после включения.
- **Параллельное редактирование двумя сессиями админки** — последнее
  сохранение выигрывает (как и для ВК/Telegram-шаблонов);
  отдельной блокировки не вводится.
- **Песня, у которой меняется категория уже после создания новости**
  (админ удалил auto-новость и вручную создал другую) — система не
  переоткрывает авто-новость (существующий FR-008
  `specs/089-auto-news-song-release`); шаблон применяется только в
  момент первичного создания.
- **Изменение шаблона НЕ должно затрагивать уже созданные новости** —
  новый шаблон применяется только к новым auto-новостям, существующие
  записи `tbl_news` не перезаписываются (аналог FR-010
  `specs/121-vk-news-auto-publish`).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В компоненте `webvue3` «Шаблоны публикаций»
  (`PublishTemplatesView.vue`, роут `/publish-templates`) ДОЛЖНА
  появиться третья вкладка/платформа — «Новости сайта» — наравне с
  существующими «ВКонтакте» и «Telegram». Вкладка переключается тем же
  UI-паттерном (`nav nav-tabs`), не ломая существующие вкладки.
- **FR-002**: На вкладке «Новости сайта» ДОЛЖНЫ отображаться два типа
  шаблонов — «В эфире (air)» и «В коллекции (premium)» —
  соответствующие двум категориям auto-новостей
  `SongReleaseAnnouncementService` (`category="air"` и
  `category="premium"`). Переключение между типами — тем же
  `nav nav-pills`-паттерном, что в ВК/Telegram.
- **FR-003**: Для каждого типа шаблон ДОЛЖЕН состоять из **двух
  полей** — «Заголовок» (`title`) и «Текст» (`body`), соответствующих
  колонкам `tbl_news.title` и `tbl_news.body`. Оба поля —
  многострочные текстовые редакторы с подсветкой плейсхолдеров,
  предупреждением о несбалансированных скобках и кнопкой «Сбросить к
  дефолту» (по образцу ВК/Telegram-вкладок, но применённой к обоим
  полям независимо).
- **FR-004**: Шаблоны ДОЛЖНЫ поддерживать плейсхолдеры в фигурных
  скобках (`{author}`, `{songName}`, `{link}`, и т.п.). Набор
  плейсхолдеров — объединение granular-плейсхолдеров ВК/Telegram
  (`{author}`, `{songName}`, `{songNameCensored}`, `{year}`, `{album}`,
  `{link}`, `{id}`, `{newsBody}`, `{descriptionHeader}`,
  `{descriptionFooter}`, `{description}`, `{descriptionWithTimecodes}`)
  и двух составных `{albumYearSuffix}`, `{bodyDetails}`,
  инкапсулирующих существующие хелперы
  `SongReleaseAnnouncementService.albumYearSuffix`/`bodyDetails`
  (для byte-идентичности дефолтов, см. FR-010). Маркер `{demoVideo}` НЕ
  включён (новости сайта не прикрепляют видео — это внешний пост
  VK/Telegram). Полный список с описаниями фиксируется в
  `NewsTemplateService.PLACEHOLDERS` по образцу
  `VkTemplateService.PLACEHOLDERS` и возвращается endpoint'ом списка
  шаблонов (FR-012) для UI-подсказок.
- **FR-005**: Неизвестные плейсхолдеры (`{nonexistent}`) и
  несбалансированные скобки (`{author` без `}`) ДОЛЖНЫ трактоваться
  как literal-текст — не заменяются, не вызывают ошибку применения
  шаблона (аналог FR-023 `specs/121-vk-news-auto-publish`).
- **FR-006**: При применении шаблона (создании auto-новости) система
  ДОЛЖНА подставлять значения плейсхолдеров из данных конкретной
  песни в ОБА поля (`title` и `body`) независимо. Результат
  подстановки записывается в `tbl_news.title` и `tbl_news.body` через
  существующий `News.createAutoAnnouncement` (без изменения схемы
  `tbl_news`). При рендере `body` категории `air` в
  `NewsTemplateService.render(template, song, news)` передаётся
  связанная новость `news` (источник для плейсхолдера `{newsBody}`);
  для `title` всех категорий и для `title`/`body` категории `premium`
  `news = null`.
- **FR-007**: Применение шаблона ДОЛЖНО происходить в точках создания
  auto-новостей: `SongReleaseAnnouncementService.checkOnAirWindow`
  (категория `air`) и `SongReleaseAnnouncementService.detectAndAnnounceAvailability`
  (категория `premium`). Текущие хардкод-строки в этих методах
  заменяются на рендеринг соответствующего шаблона (с плейсхолдерами).
- **FR-008**: Изменения шаблонов ДОЛЖНЫ применяться без перезапуска
  `karaoke-app` и `karaoke-web`. Четыре строковых ключа
  (`newsTemplateAirTitle`, `newsTemplateAirBody`,
  `newsTemplatePremiumTitle`, `newsTemplatePremiumBody`) хранятся в
  `tbl_public_settings` (Postgres — единый источник истины, см.
  FR-016) и читаются при каждом применении через прямой JDBC-запрос (не
  кэшируются в статическом поле). Запись — через новый endpoint
  `/api/news/templates/*` (см. FR-012), использующий UPSERT
  (`INSERT ... ON CONFLICT (key) DO UPDATE`) — существующий
  `/api/publicsettings/*` умеет только `UPDATE` и падает на первом
  сохранении отсутствующего ключа (см. `research.md` R2).
- **FR-009**: На вкладке «Новости сайта» ДОЛЖНО работать превью
  шаблона на тестовой песне — администратор вводит id песни, нажимает
  «Превью», система возвращает отрендеренные `title` и `body`
  (раздельно) с подставленными значениями. Превью не создаёт запись в
  `tbl_news`. **РЕШЕНО в plan.md**: превью запрашивается для **пары
  `title`+`body`** текущего типа (`air` или `premium`) одним запросом
  `POST /api/news/templates/preview` (см. contracts/api.md §3);
  отдельно по каждому из четырёх полей превью не вызывается.
- **FR-010**: Заводские дефолты четырёх шаблонов ДОЛЖНЫ совпадать с
  текущими хардкод-формулировками `SongReleaseAnnouncementService`
  (с подстановкой плейсхолдеров вместо `${...}`):
  - `air`/`title`: `"Новая песня: {author} — {songName}{albumYearSuffix}"`
  - `air`/`body`: `"Песня «{songName}» ({bodyDetails}) вышла в эфир."`
  - `premium`/`title`: `"Новая песня: {author} — {songName}{albumYearSuffix}"`
  - `premium`/`body`: `"Песня «{songName}» ({bodyDetails}) появилась в коллекции."`
  Составные плейсхолдеры `{albumYearSuffix}` и `{bodyDetails}` при
  рендере вызывают те же хелперы
  (`SongReleaseAnnouncementService.albumYearSuffix`/`bodyDetails`),
  что и текущий хардкод, — это гарантирует byte-идентичность
  результата (включая пустой суффикс/усечённый список при отсутствии
  альбома/года). Granular-плейсхолдеры (`{album}`, `{year}` и т.п.)
  экспонируются для пользовательских правок, но дефолты их в составных
  местах не используют.
- **FR-010a**: Поле `title` (`tbl_news.title` = `VARCHAR(500)`) ДОЛЖНО
  усекаться после рендера до `NewsTemplateService.NEWS_TITLE_MAX_LENGTH`
  (= 500) с суффиксом `…` (по образцу `VkTemplateService.truncate`).
  Поле `body` (`tbl_news.body` = `TEXT`, без лимита) усечению НЕ
  подлежит. См. Edge Cases и `contracts/api.md` §3
  (`titleTruncated` / `bodyTruncated=false`).
- **FR-011**: Изменение шаблона НЕ ДОЛЖНО затрагивать уже созданные
  записи `tbl_news` — новый шаблон применяется только к новым
  auto-новостям (аналог FR-010 `specs/121-vk-news-auto-publish`).
- **FR-012**: Шаблоны новостей сайта хранятся в `tbl_public_settings`
  (см. FR-016) и редактируются через отдельный endpoint-паттерн (НЕ
  generic Properties UI — многострочные шаблоны с плейсхолдерами
  неудобно править в однострочном поле, см. FR-024
  `specs/121-vk-news-auto-publish`). **РЕШЕНО в plan.md/research.md R3**:
  отдельный контроллер `NewsTemplateController` в `karaoke-app`
  (`@RequestMapping("/api/news/templates")`) с 4 endpoints:
  `GET /` (список всех 4 ключей + плейсхолдеры + `default` для каждого,
  query `target=local|remote`), `POST /` (UPSERT по `key`+`value`+`target`,
  валидация `key in allowedNewsTemplateKeys`), `POST /preview`
  (рендер `titleTemplate`+`bodyTemplate` на song по `id`), `GET /defaults`
  (4 заводских значения из `NewsTemplateService.DEFAULT_*`). Делегирование
  существующему `/api/publicsettings/*` НЕ применяется — он умеет только
  `UPDATE` (без UPSERT), что падает на первом сохранении отсутствующего
  ключа (см. FR-008, `research.md` R2). Все 4 endpoint принимают
  параметр `target=local|remote` (по образцу
  `PublicSettingsController.resolveDb`); `remote` пишет/читает напрямую
  prod-БД (см. FR-016, `research.md` R1). В любом случае запись идёт в
  `tbl_public_settings`, не в `KaraokeProperties`-файл. Полный контракт —
  `contracts/api.md`.
- **FR-013**: Заводские дефолты ДОЛЖНЫ быть доступны отдельным
  endpoint (`/api/news/templates/defaults`) для кнопки «Сбросить к
  дефолту» — по образцу ВК/Telegram (`/api/vk/templates/defaults`,
  `/api/telegram/templates/defaults`).
- **FR-014**: Превью ДОЛЖНО работать через отдельный endpoint
  (`/api/news/templates/preview`) — принимает значение шаблона и id
  песни, возвращает отрендеренные `title`/`body` + длины + признак
  усечения (если применимо). Не создаёт запись в БД.
- **FR-015**: Развёртывание фичи НЕ ДОЛЖНО менять вид уже
  публикуемых auto-новостей — заводские дефолты дают byte-идентичный
  текущим хардкод-формулировкам результат (FR-010), поэтому
  администратор может не трогать шаблоны сразу после релиза.
- **FR-016**: Шаблоны новостей сайта НЕ ДОЛЖНЫ зависеть от наличия
  `karaoke-app` на проде. Применение шаблона происходит на проде
  (`karaoke-web` — `SongReleaseAnnouncementScheduler`/`MainController.doChangeRecords`),
  где `KaraokeProperties`-файл `/sm-karaoke/system/Karaoke.properties`
  недоступен (он есть только на admin-машине; ВК/Telegram-шаблоны этому
  не подвержены, т.к. их боты запускаются на admin-машине). Поэтому
  хранилище шаблонов новостей сайта — `tbl_public_settings` (Postgres),
  читаемая и с admin, и с прода через прямой JDBC-запрос (по образцу
  `isNewsAutoPublishKillSwitchActive` в `News.kt`,
  `CaptchaConfigService` в `karaoke-web`). `KaraokeProperties` для этих
  ключей НЕ используется (ни для чтения, ни для записи) — это исключает
  рассинхрон между файлом и БД. Заводские дефолты (FR-010) хранятся
  в коде (`NewsTemplateService.DEFAULT_*`) и возвращаются endpoint'ом
  `/api/news/templates/defaults` (FR-013); в БД ключи отсутствуют до
  первого сохранения (пустая строка → рендер использует дефолт из кода,
  по тому же паттерну, что `VkTemplateService.templateFor`).

### Key Entities

- **NewsTemplate (Шаблон авто-новости)**: пара `title`/`body` с
  плейсхолдерами для одной категории авто-новостей (`air` или
  `premium`). Хранится в `tbl_public_settings` (Postgres, см. FR-016)
  как четыре строковых ключа: `newsTemplateAirTitle`,
  `newsTemplateAirBody`, `newsTemplatePremiumTitle`,
  `newsTemplatePremiumBody`. Применяется в момент создания auto-новости
  (`SongReleaseAnnouncementService`). Заводские дефолты — в коде
  (`NewsTemplateService.DEFAULT_*`), используются когда ключ в БД
  пуст/отсутствует (по образцу `VkTemplateService.templateFor`).
- **News (Новость)**: существующая сущность `tbl_news`
  (заголовок `title`, текст `body`, категория `category`, ссылка
  `link`, дата публикации `publish_at`, источник `source`). Фича НЕ
  меняет схему `tbl_news` — только заменяет источник значений
  `title`/`body` с хардкод-строк на рендеринг шаблона.
- **Song (Песня)**: источник данных для плейсхолдеров (автор,
  название, альбом, год, ссылка). Использует существующие поля;
  новые поля на песне не вводятся.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После выпуска фичи администратор может изменить
  формулировку авто-новости любой категории (`air` или `premium`) в
  UI «Шаблоны публикаций» без правки кода и без перезапуска
  контейнеров, и следующая созданная auto-новость будет использовать
  новую формулировку.
- **SC-002**: При первом развёртывании фичи (без правки шаблонов
  администратором) вид публикуемых auto-новостей не меняется —
  заводские дефолты дают текст, byte-идентичный текущим
  хардкод-формулировкам `SongReleaseAnnouncementService`.
- **SC-003**: Администратор может запросить превью шаблона на
  тестовой песне (обе пары полей `title`+`body`) до сохранения и до
  создания реальной auto-новости — за время ≤ 3 секунды на типичной
  песне.
- **SC-004**: Все четыре шаблона (`air`/`premium` × `title`/`body`)
  доступны для редактирования, превью и сброса к дефолту в одной
  вкладке «Новости сайта» компонента «Шаблоны публикаций» — без
  отдельных UI/экранов.
- **SC-005**: Изменение любого из четырёх шаблонов не требует
  перекомпиляции или перезапуска `karaoke-app` или `karaoke-web` —
  новый шаблон применяется при следующем создании auto-новости.

## Assumptions

- Шаблоны новостей сайта редактируются в том же компоненте
  `PublishTemplatesView.vue` и тем же UI-паттерном (вкладки платформ
  + пилюли типов + многострочный редактор с подсветкой), что и ВК/
  Telegram-шаблоны — отдельный UI не создаётся.
- Плейсхолдеры используют тот же синтаксис фигурных скобок (`{name}`),
  что в ВК/Telegram-шаблонах; механизм подстановки literal-treatment
  неизвестных — тот же.
- `tbl_news` схема не меняется — фича заменяет только источник
  значений `title`/`body` (хардкод → шаблон), а не структуру
  хранения.
- Идемпотентность auto-новостей определяется существующими механизмами
  (`News.existsAutoAnnouncement`, флаг `Song.newsAvailableAnnounced`)
  и не зависит от содержимого шаблона — замена формулировки не влияет
  на идемпотентность.
- Заводские дефолты совпадают с текущими хардкод-формулировками, чтобы
  выпуск фичи был прозрачным для пользователей сайта (вид ленты
  новостей не меняется до первой правки администратора).
- Механизм хранения шаблонов должен работать на проде, где
  `karaoke-app` не разворачивается; `KaraokeProperties`-файл
  `/sm-karaoke/system/Karaoke.properties` на проде недоступен, поэтому
  хранилище — `tbl_public_settings` (Postgres), читаемая и с admin, и с
  прода (по образцу `isNewsAutoPublishKillSwitchActive`,
  `CaptchaConfigService`). `KaraokeProperties` для этих 4 ключей НЕ
  используется (см. FR-016).
- Превью не создаёт запись в `tbl_news` — только рендерит шаблон в
  памяти и возвращает текст (аналог ВК/Telegram preview).
- Шаблоны применяются только в момент первичного создания
  auto-новости; повторное применение при изменении шаблона к уже
  существующим новостям не происходит (FR-011).
- Лимиты длины `tbl_news.title`/`tbl_news.body` (если есть) — те же,
  что для ручных новостей; усечение/валидация — по образцу
  существующего `News.createNew`.
