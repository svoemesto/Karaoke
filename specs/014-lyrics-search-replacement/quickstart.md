# Quickstart: проверка замены поискового бэкенда для текстов песен

## Предпосылки

- Локальный docker-стек поднят (`deploy/do.sh`, см. `DEVELOPMENT.md`).
- Новый self-hosted поисковый сервис (см. `research.md`/`plan.md`, кандидат —
  4get) развёрнут отдельным контейнером и доступен по адресу, заданному в
  `lyrics-search.base-url` (см. `contracts/lyrics-search-backend.md`).
- Существующий контейнер `searxng` продолжает работать без изменений (нужен для
  поиска обложек альбомов, вне рамок этой фичи).

## Сценарий 1 — базовая проверка нового бэкенда изолированно

1. Дёрнуть новый поисковый сервис напрямую (curl/браузер) с русским запросом вида
   `<автор> текст песни <название>` для песни, на которой сегодняшний SearXNG
   возвращал 0-1 ссылку.
2. Убедиться, что ответ — валидный структурированный (JSON) список результатов
   с непустыми `url`, и что их заметно больше, чем возвращал SearXNG для того же
   запроса (сравнить с логами/предыдущим прогоном на SearXNG, если есть).

## Сценарий 2 — сквозная проверка через пайплайн (User Story 1, P1)

1. Взять song-запись без `sourceText`, для которой ранее не нашлось текста через
   SearXNG (или создать тестовую).
2. Запустить шаг автопоиска текста (`getSearXNGSearch` / `LyricsFinderService`,
   см. `karaoke-app/.../UtilsAI.kt:88`) для этой песни.
3. **Ожидаемый результат**: в БД создаётся `SearchAsync` с непустым `rawData`
   (список URL), и хотя бы один `SearchResult` с непустым `text` — то есть текст
   песни найден автоматически там, где раньше это не получалось.
4. Проверить логи: при недоступности нового бэкенда (временно остановить его
   контейнер и повторить) — ошибка залогирована, `searchUrls` вернула пустой
   список, пайплайн не упал (acceptance scenario 2 из `spec.md`).

## Сценарий 3 — конфигурация без правок кода (User Story 2, P2)

1. Изменить значение `lyrics-search.base-url` (env-переменная в
   docker-compose) на адрес другого/тестового инстанса нового бэкенда.
2. Перезапустить `karaoke-app` контейнер (только с согласия пользователя — см.
   ограничения агента в `.specify/memory/constitution.md`).
3. Убедиться, что поиск текстов песен использует именно новый адрес (по логам
   запроса), без изменений в `LyricsFinderService`/`UtilsAI.kt`.

## Сценарий 4 — регрессия по обложкам альбомов (FR-007, вне рамок)

1. Запустить поиск обложки альбома (`AlbumCoverService.search`, эндпоинт
   `POST /api/song/searchalbumcover`, см. `ApiController.kt`).
2. Убедиться, что он по-прежнему использует контейнер `searxng` (не новый
   бэкенд) и работает так же, как до этой задачи — без регрессий (SC-005).

## Что НЕ входит в quickstart

- Нагрузочное тестирование нового бэкенда.
- Автоматизированный CI-тест (проект не полагается на CI-тесты для
  интеграционных сценариев такого рода, см. `constitution.md` → «Рабочий
  процесс» → «Тесты»); проверка — ручная, пользователем, как и для остальных
  фич проекта.
