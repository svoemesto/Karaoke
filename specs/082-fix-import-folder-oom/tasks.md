## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: без зависимостей — можно начинать сразу.
- **Foundational (Phase 2)**: зависит от Setup; блокирует обе user story только в части «свежести» находок `research.md` (T004 — сверка, не код-правка).
- **User Stories (Phase 3-4)**: обе зависят от завершения Foundational. Между собой независимы по файлам (US1 — `Utils.kt`/`ApiController.kt`/`MainController.kt`; US2 — `Song.kt`) и могут вестись параллельно либо последовательно в порядке приоритета (P1 → P2).
- **Polish (Phase 5)**: зависит от завершения обеих желаемых user story.

### User Story Dependencies

- **User Story 1 (P1)**: можно начинать сразу после Foundational — не зависит от US2.

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Phase 1: Setup.
2. Phase 2: Foundational (сверка находок).
3. Phase 3: User Story 1.
4. **Остановиться и проверить**: Сценарии 1-2 `quickstart.md` независимо.
5. При необходимости — уже на этом этапе можно поставить PR с MVP (устраняет главную жалобу пользователя: падение по памяти при большом количестве файлов).

### Incremental Delivery

1. Setup + Foundational → находки актуальны.
2. + User Story 1 → проверить независимо → закрывает исходную жалобу про OOM (MVP).
3. + User Story 2 → проверить независимо → корректный кортеж заданий в одном лейне.
4. Polish → пред-коммитный чек-лист, финальная регрессия, PR.

### Solo-исполнитель

US1 и US2 правят разные файлы без пересечений — реалистичный порядок для
одного исполнителя: Setup → Foundational → (US1 и US2 в любом порядке,
US1 первым как P1/MVP) → Polish.
