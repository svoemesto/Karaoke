## Что делает

Пакет закрывает 24 записи аудита #336 в модуле `tools/` — в самих guard'ах,
которыми проверяется всё остальное. Общий признак дефектов: **guard
объявлял успех там, где проверка не была выполнена**, — пустой вход, потерянный
код возврата, недостижимая ветка, неверный источник данных, умноженный
счётчик.

Темы пакета: `guard-empty-input-pass`, `guard-counter-multiplied`,
`guard-unreachable-branch`, `guard-wrong-field-source`,
`guard-discards-exit-code`, `guard-diff-context-false-positive`,
`tmp-file-predictable`.

## Зачем

- **Доверие к гейтам.** Guard, который всегда возвращает 0, хуже отсутствующего
  guard'а: он создаёт иллюзию контроля. Аудит #336 нашёл 24 таких места —
  в проверках, которыми проверяют остальное.
- **Ложные срабатывания.** `check-frontend-build.sh` блокировал корректные
  коммиты, потому что не видел `cd webvue3` из контекста diff'а; обход —
  `git commit --no-verify`, то есть гейт отключался целиком.
- **Ложные «прогоны».** `check-endpoint-field-coverage.sh` брал поддерживаемые
  поля из одного жёстко зашитого `SongUpdateMapper.kt` для **любой** пары из
  `endpoint-pairs.yml` — то есть проверял не тот эндпоинт, который заявлял.
- **Тихая потеря данных.** `tracker-implement-done.sh` публиковал в трекере
  отчёт-заглушку («замените на настоящий отчёт») и переводил задачу в
  In review — workflow OpenProject считался выполненным без отчёта.
- **Безопасность.** Промежуточные файлы в предсказуемых `/tmp` и `curl`
  с секретом в argv-adjacent коде — векторы, которые в этом пакете закрыты
  частично (см. «Инварианты»).
- **Переносимость.** `grep -cP` (PCRE) и `|| echo "000"` — расхождения с
  поведением на другой машине и на другой версии curl.

## Как работает

Каждый правленый guard получил один из двух режимов самопроверки, чтобы
дефект не мог вернуться молча:

- `--self-test` — фикстуры «до/после» на изолированных данных (временный
  каталог), без обращения к репозиторию и без сети: `check-endpoint-field-coverage.sh`,
  `check-container-restart.sh`, `check-docker-image-tags.sh`,
  `check-frontend-build.sh`, `check-enforcement.sh`, `check-spec-issue-link.py`,
  `auto-jsdoc.py`, `auto-kdoc.py`, `auto-kdoc-quality.py`,
  `tracker-bootstrap.sh`.
- самопроверка внутри скрипта (в генераторах) — проверка существования
  `@see`-целей перед записью в исходники.

Скрипты трекера (`tools/tracker-*.sh`) не имеют `--self-test`: они работают с
живым OpenProject, и их негативные сценарии проверяются воспроизводимыми
командами в отчёте пакета (`specs/402-pkg-s3-30/report.md`).

Коды возврата унифицированы: `0` — успех, `1` — нарушение/ошибка данных,
`2` — проверка не могла быть выполнена (usage error, недоступный инструмент,
неразрешённый ref). Guard, который не смог проверить, обязан вернуть
ненулевой код, а не «успех».

## Инварианты

1. **Guard не может сообщить успех, не выполнив проверку.** Пустой набор
   входных данных, отсутствующий файл, недоступный инструмент, неразрешённый
   git-ref — это ошибка (код ≥ 1), а не «нарушений нет».
2. **Код возврата внешней команды не теряется.** `curl`, `eslint`, `docker
   compose`, `docker exec`, `git log`, `npm install`, `gradlew`, `docker
   compose` — код возврата проверяется явно; пайп (`cmd | tail`) не может
   скрыть провал, если у него включён `pipefail`.
3. **Счётчик нарушений равен числу нарушений.** Проверка, не зависящая от
   контейнера/итератора, выполняется один раз на файл; счётчик не умножается
   на число элементов внешнего цикла.
4. **Источник данных — тот, который заявлен.** Список поддерживаемых полей
   берётся из контроллера пары, а не из единственного маппера на всё.
5. **Контекст diff'а не выдумывается.** Проверка multi-line правила использует
   полное содержимый файла; номера строк берутся из diff'а.
6. **Временные файлы — приватные.** `mktemp -d` + `trap`-очистка; никаких
   предсказуемых путей в `/tmp`.
7. **Правила не ломают рабочие guard'ы.** Для каждого правленого guard'а
   обязателен негативный тест: (а) на корректном дереве — PASS, (б) на
   подсовытом нарушении — FAIL с ненулевым кодом.
8. **Baseline-механика не ломается.** Ключ базы — `<путь>:sha256(содержимое
   строки)[:16]`; вставка строк выше упоминания не ломает базу.

## Известные ловушки

1. **Пайп скрывает код возврата, если не включён `pipefail`.**
   `cmd | tail -3` завершается кодом `tail` (всегда 0) — провал `cmd`
   не виден. В `tools/generate-docs.sh` это приводило к сообщению
   «✅ Готово!» при отсутствующей документации. Правило: скрипт с пайпами
   обязан иметь `set -o pipefail` **и** проверять код возврата явно.
2. **`curl -w "%{http_code}"` при ошибке соединения печатает `000` в stdout.**
   Конструкция `curl … || echo "000"` даёт `"000000"` — значение, не
   совпадающее ни с одной веткой `case`. Правило: код возврата `curl`
   проверяется отдельно, статус приводится к `"000"`.
3. **`grep -c` возвращает 1, когда совпадений нет.** Под `set -euo pipefail`
   пайп `grep … | wc -l` из-за этого убивает скрипт **без** диагностики —
   пользователь видит тихий выход вместо сообщения «нет проектов».
   Правило: `|| true` в пайпе либо `grep -c` с явной проверкой.
4. **`grep -q` в пайпе даёт SIGPIPE (код 141).** `echo "$x" | grep -q …`
   под `pipefail` может вернуть 141 (grep закрыл пайп раньше, чем echo
   дописал) — условие `if` становится ложным при успешном совпадении.
   Правило: `grep -q … <<< "$x"` (herestring) вместо пайпа.
5. **Точный матч и «неприменимое правило» исключают друг друга.**
   В `check-docker-image-tags.sh` ветка «матчер ослеп» была недостижима:
   вердикт `n/a` выдавался ровно тогда, когда имя не совпадало с `nginx`/
   `node`. Правило: самодиагностика должна быть **проверяема** фикстурой —
   если ветку нельзя достичь, фикстура её не поймает.
6. **Проверка «по контексту diff'а» без полного файла даёт ложные срабатывания.**
   `cd webvue3` в контексте diff'а — не добавленная строка; список добавленных
   строк его не содержит. Правило: контекст — полное содержимое файла,
   номера строк — из diff'а.
7. **Один источник данных на все случаи = проверка не того.**
   `SongUpdateMapper.kt` подставлялся как список поддерживаемых полей для
   любой пары `endpoint-pairs.yml`, а fallback на `@RequestParam` был
   недостижим (файл маппера существует всегда). Правило: источник данных
   выводится из объявленной в паре сущности.
8. **Предсказуемый `/tmp`-файл — общий ресурс.** `/tmp/_nocomm.txt`,
   `/tmp/eslint-current.json` и подобные можно заранее создать или
   подменить symlink'ом. Правило: `mktemp -d` + `trap`-очистка.
9. **Числовые ID сущностей в скриптах настройки.** `rules = [[1, 9], [7, 9], …]`
   в `tracker-bootstrap-board.sh` — это дефолтные ID статусов OpenProject;
   на другой инсталляции они указывают на другие статусы. Правило: резолвить
   по имени (`Status.find_by(name: …)`), отсутствующие — перечислять.
10. **Отчёт-заглушка проходит workflow.** Stub-отчёт, опубликованный
    комментарием, закрывает формальную часть «claim → report → mark-review».
    Правило: workflow-шаг не выполняется без настоящего артефакта.
11. **Регулярка без границы слова ловит чужие слова.** `оп\w*`/`op\w*`
    матчили «опубликация», «operation», «drop» — агент получал claim чужой
    задачи. Правило: короткие токены (`оп`, `op`) — только отдельное слово
    с явным разделителем; длинные (`задача`, `таск`, `task`) — с окончаниями.
12. **Значение по умолчанию, вычисленное до загрузки окружения, — мусор.**
    `ASSIGNEE="${TRACKER_AGENT_USER:-ai-agent}"` до `tracker_load_env`
    игнорировал `.env.local-tracker`. Правило: значение по умолчанию читать
    после загрузки окружения; явный флаг CLI — приоритет.
