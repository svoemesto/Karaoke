# Contract: publications-date-filter

## Endpoint

`POST /api/publications/date`

## Request

Параметр формы `param` обязан иметь одно из значений:

| Значение | Искомое состояние |
|---|---|
| `STATE_DONE` | `DONE` |
| `STATE_TODAY` | `TODAY` |
| `STATE_ON_AIR` | `ON_AIR` |
| `STATE_EXCLUSIVE` | `EXCLUSIVE` |
| `STATE_IN_WORK` | `IN_WORK` |

Клиент не отправляет старые `STATE_*` статусы площадок и `STATUS_0..6` как цветовые категории.

## Response

- Успех с найденной песней: строка с датой песни в действующем формате публикаций (`dd.MM.yy`).
- Если песня выбранного состояния отсутствует или параметр неизвестен: пустая строка.
- Endpoint не изменяет песню и не сохраняет выбранное состояние.

## Поведение

1. Backend рассчитывает состояние по правилам `data-model.md`.
2. Возвращается дата первой найденной песни выбранного состояния.
3. `STATE_TODAY` ищет именно состояние `TODAY`, а не любую песню с сегодняшней датой.
4. Для `STATE_IN_WORK` используется одна категория без отдельных кнопок для каждого `idStatus`.
5. Ответ используется frontend-экраном публикаций для выбора даты диапазона, после чего загружается обычный дайджест публикаций.

## Обратная совместимость

Старые токены не являются частью нового контракта. Их сохранение в UI или добавление скрытых алиасов считается нарушением FR-009/SC-003, поскольку оставляет удалённые статусы доступными пользователю.
