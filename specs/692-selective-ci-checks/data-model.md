# Data Model: Выборочный запуск CI-проверок по зонам интереса

**Feature**: 692-selective-ci-checks | **Дата**: 2026-11-01

Модель — файловая: единственный носитель — манифест `config/ci/checks.yml` (версия 1).
Ниже — сущности, их поля, правила валидации и переходы состояний прогона.

---

## 1. Манифест (Manifest)

Машиночитаемое описание всех проверок, их зон, режимов и групп. Единственный носитель правила
выборочного запуска (FR-006, R-48).

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `version` | int | обязательно | версия схемы; поддерживается `1`. Неизвестная версия → код `2` (FR-014) |
| `unknown_paths` | enum(`all`\|`none`) | опционально, default `all` | что делать с путём вне объединения зон (FR-004) |
| `groups` | map | опционально | именованные группы связанных проверок |
| `groups.<name>.members` | list[str] | обязательно при наличии группы | job-id членов группы |
| `checks` | list | обязательно | список проверок |

**Инварианты манифеста** (проверяет `tools/check-ci-checks-manifest.sh`):

| # | Инвариант | Нарушение |
|---|---|---|
| M-1 | `version` ∈ поддерживаемых; `unknown_paths` ∈ {`all`, `none`} | ошибка (код `1` при «известная, но неверная», `2` при «неизвестная/нечитаемая») |
| M-2 | `checks[].id` уникальны; **тотальное** соответствие job-id обеих копий workflow (1:1, без исключений) | ошибка |
| M-3 | `checks[].title` непуст | ошибка |
| M-4 | `mode: paths` ⇒ `paths` непустой, `evidence` непустой | ошибка |
| M-5 | `mode: always` ⇒ `paths` отсутствует или пуст | ошибка |
| M-6 | каждый глоб из `paths` матчит хотя бы один tracked-файл (мёртвая зона) — **только для `mode: paths`** | ошибка |
| M-7 | `cost` ∈ {`heavy`, `light`, `info`}, `gate: false` ⇒ `cost: info` | ошибка |
| M-8 | члены `groups.*.members` существуют среди `checks[].id`; проверка — максимум в одной группе | ошибка |
| M-9 | `class: infrastructure` ⇒ `mode: always`, `paths` и `evidence` пустые | ошибка |
| M-10 | `if:`-условия в двух копиях идентичны по job-id | ошибка |
| M-11 | `needs` джоба `karaoke-public-e2e` покрывает все записи с `cost: heavy` | ошибка |
| M-12 | `needs` в двух копиях идентичны по job-id (порядок выполнения одинаков) | ошибка |

## 2. Проверка (Check)

Единица CI-контура.

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `id` | str | обязательно | machine-readable ключ = job-id в workflow (1:1) |
| `class` | enum(`check`\|`infrastructure`) | опционально, default `check` | класс записи (см. ниже) |
| `title` | str | обязательно | человекочитаемое имя (сводки, отчёты) |
| `gate` | bool | опционально, default `true` | входит ли в блокирующий набор |
| `cost` | enum(`heavy`\|`light`\|`info`) | опционально, default `light` | стоимость; приоритет оптимизации и метрика |
| `mode` | enum(`paths`\|`always`) | обязательно | по зонам / всегда |
| `paths` | list[glob] | обязателен при `mode: paths` | зоны интереса |
| `evidence` | str | обязателен при `mode: paths` | доказательство зоны (файл:строка) |

**Два класса записей** (D-19). Манифест — полный реестр job-id обеих копий workflow:
**35 записей** = 31 существующий job-id + `direct-commits-guard` + `ci-checks-manifest-guard` +
`changes` + `ci-summary`. Инвариант «джоб ↔ запись» тотальный, без списков исключений.

| Класс | Состав | Зоны | Блокирует |
|---|---|---|---|
| `check` | 31 существующий job-id + `direct-commits-guard` | `mode: paths` — зона обязательна; `mode: always` — без зоны | `gate: true` (по умолчанию) |
| `infrastructure` | `changes`, `ci-summary`, `ci-checks-manifest-guard` | нет (`mode: always`) | `changes`/`ci-summary` — `gate: false`; `ci-checks-manifest-guard` — `gate: true` |

**Режимы**:
- `paths` — применимость вычисляется по зонам; проверка пропускается, если ни одна зона не
  затронута (FR-002);
- `always` — проверка не пропускается никогда (FR-008: зависит от истории git, а не от файлов).

**Стоимость** (`cost`) — не влияет на применимость; используется для метрики (SC-001…SC-003) и
для правила сериализации FR-018/FR-019: `karaoke-public-e2e` получает `needs` на все джобы с
`cost: heavy`.

## 3. Зона интереса (Zone)

Набор путей репозитория, изменение которых делает проверку применимой. Выражена глобами в
`paths`.

**Семантика глоба** (git-стиль, матчинг по всему пути):

| Глоб | Матчинг |
|---|---|
| `**` | любой набор сегментов, включая ноль |
| `*` | любой набор символов внутри одного сегмента (не `/`) |
| `karaoke-app/**` | всё внутри каталога `karaoke-app` |
| `knowledge` | каталог целиком (эквивалент `knowledge/**`) |
| `**/Dockerfile*` | любой файл с именем `Dockerfile*` в любом каталоге |
| `/*` | файлы верхнего уровня репозитория (паттерн с ведущим `/` привязан к корню) |

Правила: путь сравнивается без ведущего `./`; регистр учитывается; regex и отрицания не
поддерживаются; ведущий `/` привязывает паттерн к корню репозитория.

**Мёртвая зона** — глоб, не матчащий ни одного tracked-файла репозитория → ошибка согласованности
(FR-013). Поэтому зона проверки «на отсутствие» выражается **местом**, где запрещённый файл мог бы
появиться (`root-junk-guard` → `/*`), а не его именем: сам запрещённый путь не матчит ни одного
tracked-файла. Отсутствие ловится через `unknown_paths: all` — новый путь вне зон запускает всё.

## 4. Группа проверок (Group)

Набор связанных проверок, применяемых вместе (FR-009).

- применимость группы = применимость **любого** её члена;
- применяются **все** члены группы, если группа применима;
- пример: `ssoT` = [`ssot-impact`, `knowledge-structure`] — правка знаний обязана прийти с кодом.

Проверка входит максимум в одну группу (иначе применимость неоднозначна) — инвариант M-8.

## 5. Изменение (Change)

Набор изменённых путей, по которому вычисляется применимость.

| Источник | Как считается |
|---|---|
| CI (PR) | `git diff origin/master...HEAD --name-only` (fallback — `master`) |
| CI (push в master) | пустой список + флаг «полный набор» (`all=true`) |
| CI (расписание / ручной полный) | пустой список + `all=true` |
| Локально | то же, что CI, **плюс** рабочее дерево: staged + unstaged + untracked |

**Инварианты**:
- C-1 — переименование = удаление + создание → учитываются оба пути (union, не diff-формат);
- C-2 — пустой список изменений **не** означает «все проверки неприменимы»: при пустом списке и
  неизвестной причине запуска действует флаг полного набора; если флага нет — считается
  применимым всё (fail-closed);
- C-3 — список путей нормализуется (без `./`, без ведущих слешей).

## 6. Прогон (Run)

Один запуск CI на коммите. Состояния:

**Словарь (единственный источник терминов; отсюда ссылаются все артефакты):**

| Термин | Значение |
|---|---|
| **применимая проверка** | правка доказуемо затрагивает её зону интереса — проверка запускается |
| **неприменимая проверка** | проверка не запускалась, потому что правка доказуемо вне её зоны; это **не** «пройдена» и **не** «зелёная» |
| **не отработало** | проверка должна была выполниться (применима), но результата нет — прогон не зелёный |
| **блокирующий набор** | записи манифеста с `gate: true` — их провал блокирует слияние |

| Состояние | Смысл | Источник истины |
|---|---|---|
| применимо и зелёно | проверка выполнилась и завершилась успешно | `needs.<job>.result == 'success'` |
| применимо и красное | проверка выполнилась и упала | `needs.<job>.result` ∈ {`failure`, `error`, `cancelled`} |
| неприменимо | проверка не запускалась, правка доказуемо вне её зоны | `needs.changes.outputs.<id> == 'false'` |
| не отработало | проверка должна была выполниться, но результата нет | `needs.changes.outputs.<id> == 'true'` и результата нет |

Различение «неприменимо» и «не отработало» — FR-003; «не отработало» ≠ «зелёный» — FR-014.

## 7. Агрегированный сигнал (Summary)

Единственный результат прогона, по которому принимается решение о слиянии (FR-010). Носитель —
джоб `ci-summary` (статус-чек контекста `ci-summary`).

**Входы**: `needs.changes.outputs` (что должно было выполниться) и `needs.<job>.result` (чем
закончилось) — два независимых источника.

**Правила агрегата**:

| # | Условие | Результат агрегата |
|---|---|---|
| S-1 | джоб `changes` не `success` (манифест нечитаем / неизвестна версия / нет истории) | **падает** (fail-closed, независимо от `gate`) |
| S-2 | **блокирующая** запись (`gate: true`) применима и завершилась не `success` | **падает** |
| S-3 | **блокирующая** запись применима, а результата нет (джоб не стартовал из-за сбоя зависимости) | **падает** |
| S-4 | неприменимая проверка (по outputs `changes`) — её `skipped` ожидаем | **не влияет** |
| S-5 | расхождение: `changes` говорит «применима», результата нет | **падает** (то же, что S-3) |
| S-6 | все применимые блокирующие — `success`; неприменимые — `skipped`; неблокирующие (`gate: false`) — не влияют | **зелёный** |
| S-7 | запись `ci-summary` (агрегат сам) не оценивается — своего результата у него нет | не влияет |

**След пропуска (FR-017)**: агрегат печатает перечень неприменимых проверок с указанием зон, по
которым они не применились. Этот перечень — часть вывода агрегата (лог джоба и summary-строка).

## 8. Отношения сущностей

```text
Manifest 1 ──── * Check
Manifest 1 ──── * Group * ──── * Check        (membership через groups.<name>.members)
Check    * ──── * Zone                          (paths[])
Check    1 ──── 0..1 Group
Run      1 ──── * CheckState                   (одно состояние на проверку в прогоне)
Run      1 ──── 1 Summary
```

## 9. Отображение на файлы

| Сущность | Где живёт |
|---|---|
| Manifest, Check (в т.ч. `class: infrastructure`), Group, Zone | `config/ci/checks.yml` |
| Change (CI) | вычисляется `tools/ci-checks.py` из git |
| Change (локально) | вычисляется `tools/ci-checks.py` из git + рабочее дерева |
| CheckState | `needs.<job>.result` раннера |
| Summary | вывод джоба `ci-summary` + статус-чек контекста `ci-summary` |
