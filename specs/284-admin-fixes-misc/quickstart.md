# Quickstart — Админка: мелкие правки UI (SongEdit label, описание, пагинация истории)

**Feature**: [../spec.md](../spec.md) | **Plan**: [../plan.md](../plan.md)
**Контракт**: [./listeninghistory-pagination.md](./listeninghistory-pagination.md)

Ручная валидация по сценариям. Все действия — в UI админки `webvue3` на LOCAL-окружении
(см. AGENTS.md, раздел «Машинно-специфичные исключения»: на `nsa-i9`/`nsa` бэкенд
пересобирать можно; на других машинах — пересборка `karaoke-app` запрещена, но UI-правки
можно поднять через `deploy/do.sh build_webvue3` без перезапуска JVM).

## Сценарий 1 — Лейбл `Censored:` в карточке песни (FR-001, SC-001)

**Предусловие**: LOCAL-БД имеет хотя бы одну песню; в карточке заполнено поле
`songNameCensored` (можно оставить пустым).

1. Открыть админку `webvue3`, перейти на страницу любой песни (например, через `/songs`).
2. В первой колонке формы найти блок с полем ввода «censored название» — сразу под полем
   «Композиция:».
3. **Ожидаемый результат**: лейбл над полем ввода — **`Censored:`**, а не
   `Композиция (цензурированная):`.
4. Навести курсор на лейбл. **Ожидаемый результат**: всплывает подсказка
   «Ручное значение используется в публикациях (VK/Telegram/News) и публичном API БЕЗ
   повторной фильтрации…».
5. Ввести любое значение в поле, нажать Enter (или потерять фокус) — значение
   сохраняется в `song.songNameCensored`, кнопка undo становится активной.
6. **Ожидаемый результат**: поведение (v-model, undo, copy, paste) идентично прежнему.

## Сценарий 2 — Высота поля «Описание» (FR-004, SC-002)

**Предусловие**: открыта карточка песни (та же, что в Сценарии 1 или другая).

1. Найти блок «Описание:» в первой колонке формы.
2. **Ожидаемый результат**: визуальная высота `<textarea>` **≈ в 2 раза ниже**, чем раньше.
   До правки — `rows="4"` (4 строки), после — `rows="2"` (2 строки).
3. Открыть DevTools → Elements → найти `<textarea>` для `song.description`. Проверить
   атрибут `rows="2"`.
4. Ввести длинный текст (>2 строк). **Ожидаемый результат**: `<textarea>` показывает
   встроенную вертикальную прокрутку, текст вводится без потерь.
5. Нажать кнопку «undo» справа от поля. **Ожидаемый результат**: значение сбрасывается
   к ранее сохранённому (как и раньше).

## Сценарий 3 — Пагинация: базовый кейс (FR-005, SC-003)

**Предусловие**: LOCAL-БД содержит **> 500 строк** в `tbl_listening_history`. Если строк
меньше — сначала добавить (через публичный плеер karaoke-public или прямой INSERT).

1. Открыть DevTools → Network (включить фильтр `Listeninghistory`).
2. Открыть админку → раздел «История прослушиваний» (`/listeninghistory`, target = `Локальная`).
3. **Ожидаемый результат**: в Network виден ровно 1 запрос `POST /api/listeninghistory/digest`.
4. Дождаться загрузки. Найти пагинатор сверху (цифры страниц + стрелки). Кликнуть на
   цифру «2».
5. **Ожидаемый результат**: в Network появляется новый `POST /api/listeninghistory/digest`
   с `page=2` в form-data. Таблица обновляется строками второй страницы.

## Сценарий 4 — Пагинация: навигация (FR-005, FR-007)

**Предусловие**: сценарий 3 пройден.

1. Кликнуть на стрелку «вперёд» (`>`) — таблица переходит на страницу 3.
2. Кликнуть на «последняя» (`>>`) — таблица переходит на последнюю страницу.
3. Кликнуть на стрелку «назад» (`<`) — таблица возвращается на страницу N-1.
4. **Ожидаемый результат на каждом клике**: 1 POST-запрос с актуальным `page`, таблица
   обновляется, пагинатор показывает активную страницу.

## Сценарий 5 — F5 в той же вкладке: страница восстанавливается (FR-006 частично)

**Предусловие**: сценарий 4 пройден; сейчас выбрана страница, например, 3.

1. Нажать F5.
2. **Ожидаемый результат**:
   - Пагинатор сразу показывает страницу 3 (currentPage восстановлена из Vuex).
   - Первый запрос после F5 содержит `page=3` (а не `page=1`).
3. Таблица показывает строки страницы 3.

**NB**: эта персистенция — **in-tab** (Vuex in-memory). После закрытия вкладки страница
сбросится на 1 (см. `contracts/listeninghistory-pagination.md` § 6 — если потребуется
F5 cross-session, это отдельная подзадача на `setWebvueProp`/`hydrate`).

## Сценарий 6 — Смена target сбрасывает на 1 (FR-008)

**Предусловие**: сценарий 5 пройден; на «Сервер» тоже есть записи истории.

1. На странице с `currentPage > 1` сменить target на «Сервер».
2. **Ожидаемый результат**: `currentPage` сбрасывается на 1, грузится первая страница
   серверной истории.

## Сценарий 7 — Никогда не уходит лишний запрос при mount (FR-010, SC-003)

**Предусловие**: LOCAL-БД имеет хотя бы одну строку.

1. Открыть DevTools → Network (очистить перед заходом).
2. Открыть `/listeninghistory` первый раз после mount.
3. **Ожидаемый результат**: ровно 1 запрос `POST /api/listeninghistory/digest` (с
   `page=1`, потому что Vuex state initial = 1, и `data() { currentPage: … || 1 }`
   ставит 1 → watcher с `newPage === oldPage` НЕ диспатчит → только `mounted.reload()`
   шлёт 1 запрос).

## Сценарий 8 — Крайний случай: пустая таблица (Edge Cases)

**Предусловие**: очистить `tbl_listening_history` для target = `Локальная` (TRUNCATE)
или выбрать target, где нет строк.

1. Открыть `/listeninghistory` с пустой таблицей.
2. **Ожидаемый результат**: показывается заглушка «Истории прослушиваний нет»,
   пагинатор скрывается (т.к. `totalCount === 0` < `perPage`).

## Сценарий 9 — Регрессия: остальные поля SongEdit работают (SC-005)

**Предусловие**: открыта карточка песни.

1. Изменить поле «Композиция:» (обычное название), сохранить → значение отображается
   в шапке карточки.
2. Изменить поле «Исполнитель:» → сохраняется.
3. Изменить поле «Год:» / «Альбом:» / «Тэги:» → сохраняется.
4. Нажать «undo» на любом поле → возвращается к предыдущему.
5. **Ожидаемый результат**: ни одна из правок лейбла `Censored:` / `rows="2"` не повлияла
   на остальные поля формы.

## Сценарий 10 — Регрессия: остальные страницы админки не сломаны (SC-005)

**Предусловие**: открыта админка `webvue3`.

1. Открыть `/songs` (таблица всех песен) — пагинация и фильтры работают.
2. Открыть `/albums` — пагинация работает.
3. Открыть `/authors` — пагинация работает.
4. Открыть `/news` / `/subscriptions` / `/sharelinks` / `/processes` — пагинация работает.
5. **Ожидаемый результат**: правка в `ListeningHistoryTable.vue` не задела соседние
   таблицы (мы не трогали `<b-table>` и watcher других таблиц).
