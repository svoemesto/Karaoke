# Feature Specification: Возврат выпадающего списка свободных слотов публикации в поле «Дата» (`SongEdit.vue`)

**Feature Branch**: `268-song-edit-date-datalist`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "Админка webvue3, SongEdit.vue — при фокусе на поле «Дата» должен появляться выпадающий список дат предполагаемых публикаций — теперь вместо него список браузера с предложением заполнения поля."

## Контекст (Background)

В `webvue3/src/components/Songs/edit/SongEdit.vue` поле «Дата» (строка ~342) привязано
к HTML5 `<datalist id="list_free_time_slots">` через атрибут `list`. Согласно спеке
[`156-publish-slots-range`](../156-publish-slots-range/spec.md), этот datalist должен
показывать администратору до 13 строк формата `"dd.MM.yy HH:mm"` — по одной на каждый
целый час с 10:00 до 22:00 включительно, причём всегда строго в будущем
(относительно серверного времени).

В актуальном поведении при фокусе и начале ввода браузер (Chrome/Edge/Firefox)
**подменяет datalist собственным автокомплитеном** (история введённых значений
поля), и список предполагаемых публикаций перестаёт быть виден. Аналогично
ведёт себя поле «Время» (`<input ... list="list_hours">`), но эффект менее заметен,
т.к. значения времени короткие и совпадают с типичной браузерной историей.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Администратор видит список свободных слотов при фокусе на поле «Дата» (Priority: P1)

Администратор открывает карточку песни, у которой поле «Дата» пустое, ставит
фокус (или начинает ввод) и видит выпадающий список из 13 значений формата
`"dd.MM.yy HH:mm"` — по одному на каждый час с 10:00 до 22:00 включительно.
Все значения — строго в будущем. Это та же подсказка, которая работала
до возникновения регрессии.

**Why this priority**: Без этой подсказки администратор вынужден либо вручную
подбирать дату и время, ориентируясь на занятые слоты (которые нужно открывать
в таблице песен), либо рискует поставить публикацию на уже занятый слот.
Это прямой возврат ранее работавшего поведения.

**Independent Test**: Открыть любую песню с пустым полем «Дата», поставить фокус
и убедиться, что выпадающий список содержит варианты из 13 элементов
диапазона 10:00–22:00 и **не** содержит значений из истории браузера/поля.

**Acceptance Scenarios**:

1. **Given** поле «Дата» пусто и сервер вернул 13 свободных слотов, **When**
   администратор ставит фокус в поле, **Then** отображается выпадающий список
   с этими 13 значениями формата `dd.MM.yy HH:mm`.
2. **Given** поле «Дата» пусто, **When** администратор ставит фокус и начинает
   ввод, **Then** список остаётся видимым и фильтруется (стандартное поведение
   `<datalist>`); **And** в списке нет значений из автозаполнения браузера.
3. **Given** поле «Дата» содержит ранее введённое значение `12.08.26 14:00`,
   **When** администратор ставит фокус, **Then** подсказка datalist доступна
   по клику/стрелкам; прошлая история браузера не вытесняет datalist.
4. **Given** администратор ранее вводил в это поле произвольный текст
   (например, имя файла, скопированное по ошибке), **When** он ставит фокус,
   **Then** datalist со слотами публикации показывается первым, а не список
   «Предлагать заполнение поля» от браузера.

---

### User Story 2 — Поведение поля «Время» остаётся консистентным (Priority: P2)

Поле «Время» (`<input v-model="song.time" list="list_hours" />`) использует
тот же UX-паттерн (`<datalist>`) и страдает от того же регресса в Chrome/Edge.
Администратор ожидает, что при фокусе на «Время» показывается фиксированный
список часов из 6 значений (`11:00`..`16:00`), а не подмешанная браузерная
история.

**Why this priority**: Тот же баг, тот же класс фикса, нулевая дополнительная
стоимость — правится заодно, чтобы в следующий раз не возвращаться.

**Independent Test**: Открыть карточку любой песни, поставить фокус в поле
«Время», убедиться, что список содержит ровно 6 вариантов из `data.hours`
(`11:00`, `12:00`, `13:00`, `14:00`, `15:00`, `16:00`), без браузерного автокомплита.

**Acceptance Scenarios**:

1. **Given** поле «Время» пусто, **When** администратор ставит фокус,
   **Then** выпадающий список содержит ровно 6 значений из `data.hours`.
2. **Given** поле «Время» содержит ранее введённое значение `13:00`,
   **When** администратор ставит фокус, **Then** datalist доступен
   и не маскируется браузерным автокомплитом.

---

### Edge Cases

- **Что если значение в поле не совпадает ни с одним вариантом datalist?**
  Datalist — это подсказка, не валидатор. Свободный ввод остаётся разрешён
  (как было до регрессии); сервер сохраняет любое переданное значение,
  проходя существующую валидацию. Поведение не меняется.
- **Что если в браузере отключён JavaScript?** Атрибут `list` работает
  на чистом HTML и не зависит от JS; фикс через атрибуты `autocomplete`/
  `name` также не требует JS. Поведение должно остаться идентичным
  текущему (datalist и так подгружается через Vuex-стор; до фикса он
  тоже работал, просто маскировался браузером).
- **Что если сервер вернул пустой `freeTimeSlots` (например, ещё ни одной
  публикации в системе, либо `getFreeTimeSlots` не смог подключиться к БД)?**
  Datalist будет пустым — поведение не отличается от текущего. Администратор
  просто не увидит подсказок; ввести дату вручную по-прежнему можно.
- **Что если пользователь работает в приватном режиме браузера, где
  автокомплит отключён на уровне браузера?** Атрибут `autocomplete="off"`
  не ломает существующее поведение, datalist продолжит показываться
  (раньше он и так показывался — просто под браузерным списком).
- **Что если у пользователя включено расширение, перехватывающее
  автокомплит (например, менеджеры паролей)?** Расширения имеют приоритет
  над атрибутами страницы; это вне нашего контроля, поведение явно
  не улучшаем и не ухудшаем.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: При фокусе на пустом (или частично заполненном) поле «Дата»
  карточки `SongEdit.vue` администратор MUST видеть выпадающий список
  подсказок из `<datalist id="list_free_time_slots">`, **а не** список
  браузерного автокомплита.
- **FR-002**: Поведение `<datalist>` MUST остаться идентичным спеке
  [`156-publish-slots-range`](../156-publish-slots-range/spec.md) —
  13 значений диапазона 10:00–22:00, все строго в будущем.
- **FR-003**: Атрибут `name` у поля «Дата» MUST быть задан явно и
  уникально в пределах страницы (не пустой, не совпадает с другими
  полями формы), чтобы браузер не привязывал к нему общую историю
  автозаполнения.
- **FR-004**: Поле «Дата» MUST иметь атрибут `autocomplete="off"`,
  чтобы браузер не предлагал свою историю заполнения поверх datalist.
- **FR-005**: Аналогичный фикс (`name` + `autocomplete="off"`) MUST
  быть применён к полю «Время» (`<input ... list="list_hours" />`),
  использующему тот же паттерн `<datalist>`.
- **FR-006**: Фикс MUST быть ограничен разметкой `SongEdit.vue` —
  никаких изменений в backend, store, API, логике сохранения/валидации,
  формате хранения `song.date`.
- **FR-007**: Существующая функциональность (undo/copy/paste-кнопки,
  `v-model`, формат `dd.MM.yy HH:mm`) MUST остаться без изменений.

### Non-Functional Requirements

- **NFR-001**: Изменение MUST быть точечным: дифф только в одном
  файле `SongEdit.vue`, не более ~25 добавленных строк (включая
  комментарии).
- **NFR-002**: Существующие линтеры (ESLint + Prettier) MUST не
  получать новых нарушений после изменения.
- **NFR-003**: Сборка `npm run build` (Vite) MUST проходить без
  новых ошибок и предупреждений, связанных с данной правкой.

### Ключевые сущности (не меняются)

- **`song.date: string`** — формат `dd.MM.yy HH:mm`, берётся из `tbl_songs.publish_date`
  + `publish_time`. Поведение не меняется.
- **`song.time: string`** — формат `HH:mm`, отдельное поле в UI для удобства.
- **`freeTimeSlots: string[]`** — Vuex-геттер `getFreeTimeSlots`, формируется
  в backend `Utils.kt::getFreeTimeSlots()` (см. спеку 156).
- **`hours: string[]`** — статический массив `data.hours = ['11:00'..'16:00']`
  в `SongEdit.vue` (поле «Время»).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Администратор при фокусе на поле «Дата» карточки `SongEdit.vue`
  в браузерах Chrome 120+, Edge 120+, Firefox 120+, Safari 17+ видит выпадающий
  список из ≤13 элементов формата `dd.MM.yy HH:mm` (либо пустой, если сервер
  вернул пустой `freeTimeSlots`), **а не** собственный список автокомплита
  браузера. Проверка: ручное тестирование пользователем на dev-стенде.
- **SC-002**: Поле «Время» при фокусе показывает список из 6 элементов
  (`11:00`..`16:00`) либо не показывает ничего — браузерный автокомплит
  не появляется. Проверка: ручное тестирование.
- **SC-003**: Изменение проходит все проверки CI webvue3 (ESLint baseline,
  Prettier, Vite build) без новых нарушений. Проверка: локальный запуск
  `npm run lint && npx prettier --check && npm run build`.
- **SC-004**: Дифф PR содержит изменения только в файле
  `webvue3/src/components/Songs/edit/SongEdit.vue`, ≤25 строк добавлено.

## Out of Scope

- Изменение логики формирования списка `freeTimeSlots` на бэке
  (это часть спеки 156 — уже сделано).
- Изменение списка `hours` (поле «Время» сейчас предлагает только
  `11:00`..`16:00`, расширение этого списка — отдельная задача).
- Замена `<datalist>` на кастомный выпадающий список (например,
  на bootstrap-vue-next `BDropdown` или `<select>`). Если фикс через
  `autocomplete="off"` + `name` окажется недостаточным в Safari/других
  браузерах — это потребует отдельной спецификации с UX-проработкой.
- Любые изменения в `SubsEdit.vue`, таблице песен, публичных страницах.

## Assumptions

- Браузерный автокомплит действительно имеет приоритет над `<datalist>`
  в текущей версии Chrome/Edge/Firefox (это документированное поведение:
  если `autocomplete` не задан в `off`, браузер показывает свой
  список над/вместо datalist).
- Атрибуты `autocomplete="off"` + уникальный `name` достаточно, чтобы
  заставить современные браузеры не показывать собственную историю
  для конкретного `<input>`. Это **наиболее распространённый** и
  рекомендованный (MDN) способ; в редких браузерах (старые версии,
  экзотические) может не сработать — но эти случаи **вне** целевой
  аудитории (админка используется разработчиком в актуальных браузерах).
- Формат `song.date` (`dd.MM.yy HH:mm`) остаётся как есть, не меняется
  на `type="date"` / `type="datetime-local"` (это потребует отдельной
  UX-спецификации с миграцией данных).
- Поведение datalist при пустом `freeTimeSlots` (бэк вернул `[]`)
  остаётся «пустой выпадающий список» — это ожидаемо, не регрессия.
