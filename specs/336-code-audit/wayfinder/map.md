**Доказательность**: статика обязательна для каждой записи (`файл:строки` + цитата + объяснение); эмпирика (замер, падающий тест, Playwright, логи) — где дёшево и не требует перезапуска контейнера. На `nsa-i9` перезапуск `karaoke-app` запрещён без согласия владельца (AGENTS.md Pass 380/381); если для проверки нужен рестарт — запись помечается «эмпирика требует согласия», аудит не блокируется.

**Формат записи** — как в `/home/nsa/Documents/bugs-novikov.md`: `BR-NN: файл:строки — класс` / что не так / доказательство (цитата) / поправка / найден в (порция) / автор (git blame) / статус / проверено лидом. Нумерация сквозная, «одна причина — одна запись»; зеркала (одинаковый корень в нескольких местах) сводятся в одну запись с перечислением мест.

**Триаж**: автор по `git blame`; severity S1–S3 по прецеденту #186/#214 (S1 — публичный периметр, утечка данных, безопасность; S2 — сломанная функция или обходной путь; S3 — админский/редкий сценарий, тест); классы — из рубрики. Спорные «баг или задумано?» — в раздел «Требует решения владельца», пакетом после отчёта.

**Исполнение**: лид + 3 параллельных read-only субагента по порциям; каждый субагент не меняет код, не перезапускает контейнеры, не пишет в БД; лид проверяет каждую запись по диску и собирает отчёт.

**Артефакты**: `specs/336-code-audit/` — `rubric.md`, `inventory.md` + `coverage-ledger.csv`, `protocol.md`, `findings/<порция>.md`, `bug-report.md`; итоговый `bug-report.md` прикладывается к #336 через API OpenProject (проверено: `POST /api/v3/work_packages/336/attachments` доступен).

**Мандат владельца 2026-10-23**: «продолжай без остановки» — исполнение идёт без остановок на утверждение. Отдельная спека не выделялась: контракт исполнения — `rubric.md`, `protocol.md`, `schedule.md`, `acceptance.md`; задача-исполнитель — #336.

**Передача в исполнение**: остаток — большая работа (78 порций, 259 827 строк). Исполнение ведётся в #336 по контракту; промежуточный отчёт после волны 1, финальный — после волны 7.

**Базовая точка**: аудит ведётся от `master`; каждая порция фиксирует SHA, на котором читала код. Правки кода в ходе аудита запрещены.

**Прецеденты методики**: #186 (аудит SubsEdit.vue: статика + эмпирика + падающий тест), #214 (аудит SongEdit.vue), #83/#306 (карты декомпозиции).
