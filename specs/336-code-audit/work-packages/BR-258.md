# [#336] S1: результаты и исходники премиум-задания «Создать минусовку» кладутся в тот же бакет `karaok… (BR-258)

Задача: устранение дефекта **BR-258** (S1) из полного аудита кода (#336).

## Что не так

результаты и исходники премиум-задания «Создать минусовку» кладутся в тот же бакет `karaoke`, что и публичные картинки/mp3, а бакет открыт анонимным `s3:GetObject` на весь префикс (`arn:aws:s3:::$bucketName/*`). Прод-nginx проксирует `/minio/<bucket>/<object>` без авторизации. Значит объект `stemjobs/<id>/<stem>.mp3` и пользовательский `original.<ext>` доступны анонимным GET по угадываемому URL, хотя премиум-гейт (`PublicStemJobController` в `karaoke-web`) рассчитан на проверку подписки.

## Доказательство

«`val bucket = "karaoke"` / `SAC_APP.uploadFile(bucket, "stemjobs/${job.id}/original.${job.originalExt}", uploadFile.absolutePath)` / `stemFiles.forEach { (stem, file) -> SAC_APP.uploadFile(bucket, "stemjobs/${job.id}/$stem.mp3", file.absolutePath) }`» (StemJobProcessing.kt:193–196, SHA 1977838a);
  «`"Effect": "Allow",` / `"Principal": {"AWS": ["*"]},` / `"Action": ["s3:GetObject"],` / `"Resource": ["arn:aws:s3:::$bucketName/*"]`» (services/KaraokeStorageService.kt:584–587; тот же шаблон для remote — services/StorageApiClient.kt:454–470);
  «`location /minio/ {` … `proxy_pass http://127.0.0.1:8890/;`» (deploy/prod-single-host/80to8897:6–10) — без `auth_request`/`allow`/`deny`.

## Путь достижимости

анонимный клиент → `GET https://sm-karaoke.ru/minio/karaoke/stemjobs/<id>/acc.mp3` → nginx `/minio/` (замена префикса, без auth) → MinIO `karaoke` (публичная политика выше) → тело объекта. `id` — последовательность `tbl_stem_jobs_id_seq`, перебирается; окно доступности — до `expires_at` (`StemJob.RETENTION_HOURS`, 24 ч), после чего объект удаляется периодической уборкой. Тем же способом доступен `original.<ext>` — файл, загруженный пользователем. Публичность пути `/minio/karaoke/...` подтверждается тем, что `karaoke-web` отдаёт браузеру прямые ссылки `/minio/karaoke/<encoded>` (`PublicPlaylistController.kt:68,80`, `PublicApiController.kt:951`), а `PublicStemJobController.kt:166` сам ходит в `$minioProxyUrl/minio/karaoke/...`.

## Предлагаемая поправка

вынести объекты `stemjobs/` в отдельный приватный бакет (или приватный префикс с явным `Deny` на `stemjobs/*` в политике бакета) и отдавать их только через `PublicStemJobController` с проверкой права, либо короткоживущими presigned-ссылками; заодно пересмотреть политику «весь бакет `karaoke` анонимно читаем».

- Проверка владельцем (2026-10-24, по коду на SHA 1977838a — без обращения к прод-данным):
  - **Политика бакета — на весь бакет.** `setBucketPublic` выставляет `Principal: {"AWS": ["*"]}`, `s3:GetObject`, `arn:aws:s3:::$bucketName/*` (`KaraokeStorageService.kt:578–599`) — префикс `stemjobs/*` подпадает под то же правило, отдельного `Deny` нет.
  - **Бакет читается анонимно — это подтверждает сам продукт.** Публичные страницы отдают браузеру прямые ссылки `/minio/karaoke/<file>` (`PublicApiController.kt:951,962`, `PublicPlaylistController.kt:68,80`), а `PublicStemJobController.download` сам читает объект по публичному пути `$minioProxyUrl/minio/karaoke/<key>` **без учётных данных** (`PublicStemJobController.kt:166`) — то есть анонимная читаемость для фичи обязательна, иначе не работал бы и премиум-гейт.
  - **nginx не фильтрует.** В прод-блоке `location /minio/ { proxy_pass http://127.0.0.1:8890/; }` (`deploy/prod-single-host/80to8897:6–10`); во всём конфиге нет ни `allow`/`deny`, ни `auth_request` (grep по файлу — 0 совпадений).
  - **TTL работает, окно ограничено.** `StemJob.RETENTION_HOURS = 24`; уборка каждые 5 минут (`StemJobPollScheduler.cleanup`, `StemJobPollScheduler.kt:192–208`) → `StemJobCleanup.cleanupJob` удаляет и объекты (`SAC_APP.deleteFile(bucket, "stemjobs/${job.id}/…")`, `StemJobCleanup.kt:27–33`), и строку БД. То есть бессрочной утечки нет — но в окне 24 часов доступны все чужие задания, включая `original.<ext>` с аудиофайлом пользователя.
  - **Идентификатор перебирается.** Ключ — `stemjobs/<id>/<stem>.<ext>`, `id` — последовательный `tbl_stem_jobs_id_seq`; имена стемов фиксированы (`StemJobMode.stemNames`: `accompaniment`, `vocals`, `drums`, `bass`, `other`).
  - **Вердикт:** публичность подтверждена по коду → severity повышена S2 → **S1**, запись включается в волну A бэклога.
