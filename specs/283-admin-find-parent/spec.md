# Feature Specification: Админка webvue3 — кнопка «Поиск родителя» для автора

**Feature Branch**: `283-admin-find-parent`
**Created**: 2026-08-31
**Status**: Draft
**Input**: User description: "Админка webvue3, главная страница. Для автора нужно добавить кнопку 'Поиск родителя' (Над кнопкой 'Автопривязать оригинал по аудио...', недоступна если не выбран автор). По нажатию на неё должна открываться стандартная модалка с вопросом 'Нужно ли искать среди песен других авторов (по умолчанию - нет)' и осуществятся поиск для всех песен автора у которых rootId = 0"

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Поиск родителя для всех песен одного автора (Priority: P1)

Куратор каталога (админ) выбрал в поле «Автор» конкретного исполнителя и хочет разово прогнать поиск родителей (`root_id`) для всех его песен с `rootId = 0`, не затрагивая остальных авторов. Сейчас для этого приходится запускать глобальную «Custom Function» (которая обходит **все** песни каталога), что неудобно и долго — плюс в одной выборке оказываются разные авторы, что мешает разбору инцидентов.

После нажатия на новую кнопку «Поиск родителя» открывается стандартная модалка подтверждения с переключателем «Искать среди песен других авторов?», по умолчанию — **НЕТ** (то есть ищем только среди того же автора). После подтверждения — фоновая задача на бэкенде, итог приходит SSE-уведомлением.

**Why this priority**: это основной сценарий фичи — дать куратору точечный и безопасный (по умолчанию ограниченный «своим» автором) способ прогнать текстовый поиск родителей для одной группы песен, не трогая глобальную `Custom Function` и не получая на вход чужих песен в подбор.

**Independent Test**: выбрать автора, у которого есть 2-3 песни с `rootId = 0`, повторяющимися по названию у другого автора; запустить «Поиск родителя» с переключателем в положении «НЕТ» — проверить, что родитель подбирается только среди того же автора; затем повторить с переключателем «ДА» — проверить, что подхватываются и кандидаты других авторов.

**Acceptance Scenarios**:

1. **Given** в поле «Автор» ничего не введено (или введено пустое значение), **When** пользователь смотрит на главную страницу админки, **Then** кнопка «Поиск родителя» отображается, но **задизейблена** (как у соседней «Автопривязать оригинал по аудио…»).
2. **Given** в поле «Автор» введено имя (например, «Пупкин В.»), **When** пользователь смотрит на главную страницу, **Then** кнопка «Поиск родителя» доступна для клика и расположена **непосредственно над** кнопкой «Автопривязать оригинал по аудио (статус 1 → 2)» в том же блоке «field-and-buttons-wrapper».
3. **Given** пользователь кликнул доступную кнопку «Поиск родителя», **When** открывается модалка подтверждения, **Then** в её теле виден вопрос «Искать среди песен других авторов?» с переключателем (TRUE/FALSE), по умолчанию — **НЕТ**, и кнопки «Да»/«Нет».
4. **Given** модалка открыта, **When** пользователь подтверждает с переключателем «НЕТ», **Then** отправляется запрос на бэкенд с выбранным автором и флагом «только среди своего автора»; модалка закрывается; показывается информационный тост «Операция запущена в фоне».
5. **Given** модалка открыта, **When** пользователь подтверждает с переключателем «ДА», **Then** отправляется запрос на бэкенд с выбранным автором и флагом «разрешён поиск среди других авторов»; модалка закрывается; показывается информационный тост «Операция запущена в фоне».
6. **Given** модалка открыта, **When** пользователь нажимает «Нет», **Then** модалка закрывается, никаких запросов на бэкенд не уходит.
7. **Given** фоновая задача завершилась, **When** приходит SSE-уведомление, **Then** в нём указано: сколько песен автора с `rootId = 0` обработано, сколько из них получили родителя, сколько найдено, но пропущено (у песни уже есть проверенный текст), и итог по аудио-родителю — не выводится (т.к. аудио-фаза для этой кнопки не запускается).

### User Story 2 — Повторный запуск безопасен и идемпотентен (Priority: P2)

Если куратор случайно запустил «Поиск родителя» повторно (например, двойной клик или повторный запуск для подхвата новых песен автора), система не должна:
- дублировать обработку (назначать двух родителей);
- падать с ошибкой гонки;
- молча перетирать уже существующего валидного родителя.

**Why this priority**: фоновая операция, рассчитанная на админа с правами записи в БД — должна быть «безопасной к повтору», как и существующая `Custom Function` и `autoAssignOriginalAll`.

**Independent Test**: запустить «Поиск родителя» дважды подряд для одного автора — проверить, что второе прохождение либо отказывает («ALREADY_RUNNING»), либо повторно привязывает только те песни, у которых после первого прохода `root_id` всё ещё `0`.

**Acceptance Scenarios**:

1. **Given** фоновая задача «Поиск родителя» уже запущена, **When** админ повторно кликает кнопку, **Then** бэкенд возвращает `ALREADY_RUNNING`, фронт показывает тост-предупреждение («Уже запущено — дождитесь завершения»).
2. **Given** предыдущий запуск завершился и часть песен получила `root_id <> 0`, **When** админ снова нажимает кнопку, **Then** повторно обрабатываются только те песни, у которых `root_id = 0` на момент старта; уже привязанные не трогаются.

### User Story 3 — Поиск аудио-родителя среди претендентов в семье (Priority: P1)

После того как семья для песен автора сформирована (кнопкой «Поиск родителя» или вручную), куратор хочет подтвердить/опровергнуть аудио-схожесть внутри семьи — без полной фазы 2 `Custom Function` (которая глобальна и двухфазна) и без `autoAssignOriginalAll` (которая ещё и применяет выбор — копирует маркеры, переводит в статус 2). Новая кнопка «Найти аудио-родителя» должна выполнить **только запись `audio_parent_id`** (без изменения текста/маркеров/статуса) для всех песен автора, у которых `root_id <> 0`, по кандидатам из их семьи.

**Why this priority**: даёт куратору лёгкий способ прогнать акустическую сверку в уже сформированной семье, не рискуя перезаписать ручной текст/маркеры (как это делает `autoAssignOriginalAll`).

**Independent Test**: выбрать автора, у которого есть 3-5 песен в семье; запустить «Найти аудио-родителя»; проверить, что у части песен проставился `audio_parent_id` (если акустическое сходство ≥ 95% с кем-то в семье), а `source_text`/`source_markers`/`id_status` остались нетронутыми.

**Acceptance Scenarios**:

1. **Given** в поле «Автор» ничего не введено, **When** пользователь смотрит на главную страницу админки, **Then** кнопка «Найти аудио-родителя» отображается, но **задизейблена**.
2. **Given** в поле «Автор» введено имя, **When** пользователь смотрит на страницу, **Then** кнопка «Найти аудио-родителя» доступна для клика и расположена **непосредственно между** кнопкой «Поиск родителя» и кнопкой «Автопривязать оригинал по аудио (статус 1 → 2)».
3. **Given** пользователь кликнул доступную кнопку «Найти аудио-родителя», **When** открывается модалка, **Then** в её теле виден вопрос «Запустить поиск аудио-родителя среди всех претендентов в семье для песен автора «…» с `root_id ≠ 0`, у которых ещё не найден `audio_parent_id`?» и кнопки «Да»/«Нет».
4. **Given** модалка открыта, **When** пользователь подтверждает, **Then** отправляется POST на `/api/utils/findaudioparentforauthor?author=…`; модалка закрывается; показывается info-тост «Операция запущена в фоне».
5. **Given** фоновая задача завершилась, **When** приходит SSE-уведомление, **Then** в нём: `head = "Поиск аудио-родителя (автор «…»)"`, `body = "Обработано N, аудио-родитель назначен M, пропущено K"`, `type = "info"`.
6. **Given** задача завершилась, **When** админ проверяет БД, **Then**:
   - у части песен автора `audio_parent_id <> 0` (где нашёлся кандидат ≥ 95%);
   - `source_text`, `source_markers`, `id_status`, `root_id` этих песен **не изменились** (в отличие от `autoAssignOriginalAll`).
7. **Given** в семье нет ни одной другой песни (например, только что привязанная песня — единственная в семье), **When** обрабатывается эта песня, **Then** `findFamilySongIds` вернёт пусто → `findAudioParentByWaveform` вернёт `matched=false` с reason «Нет кандидатов в семье (root_id транзитивно)»; `audio_parent_id` остаётся `0`.
8. **Given** у песни уже есть `audio_parent_id <> 0` (т.е. `findAudioParentByWaveform` уже отработал ранее), **When** админ запускает «Найти аудио-родителя», **Then** такая песня **не попадает в выборку** (SQL-фильтр `audio_parent_id = 0`); тяжёлая `WaveformCompare.compareWaveforms` для неё повторно не вызывается; в SSE-сводке она не учитывается.

---

### Edge Cases

- **Пустой результат подбора**: ни одной песни автора с `rootId = 0` в каталоге — бэкенд отправляет SSE-уведомление «Обработано 0 песен, родитель назначен 0», фронт показывает тост с `warning`.
- **Автор не найден** (имя введено с опечаткой): SQL `LOWER(song_author) = LOWER(?)` не возвращает ни одной строки — то же поведение, что и в Edge Case «пустой результат».
- **У всех песен автора уже есть `root_id <> 0`**: то же поведение.
- **Имя автора с пробелами в начале/конце**: фронт тримит, бэкенд использует trimmed-значение (аналогично `autoAssignOriginalAll`).
- **Конкуренция с глобальной «Custom Function»**: если параллельно идёт глобальная операция, обе работают на разных «волнах» SQL-выборки — но обе пишут в `tbl_songs.root_id`; защита от race — `@Volatile` флаги `isFindParentInProgress` / `isCustomFunctionInProgress`, второй запуск возвращает `ALREADY_RUNNING`.
- **Песня с уже проверенным текстом** (`id_status >= 2` и `source_text` непуст): родитель находится, но не привязывается — пропускается с пояснением в логе и в сводке.
- **Модалка с переключателем и SSE-уведомлением приходят раньше подтверждения пользователя**: SSE-уведомление от прошлого запуска не должно «приклеиваться» к новой модалке; фича использует отдельный заголовок SSE-сообщения, чтобы пользователь мог отличить.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** Главная страница админки MUST отображать новую кнопку «Поиск родителя» в блоке «field-and-buttons-wrapper» с полем «Автор», **непосредственно над** кнопкой «Автопривязать оригинал по аудио (статус 1 → 2)» (порядок именно такой: сначала «Поиск родителя», затем «Автопривязать оригинал по аудио…»).
- **FR-002** Кнопка MUST быть задизейблена, если поле «Автор» пустое (или содержит только пробелы); в этом случае её `onClick` не срабатывает.
- **FR-003** По клику на доступную кнопку MUST открываться стандартная модалка подтверждения (`CustomConfirm`) с заголовком «Подтвердите действие», телом, описывающим суть операции (для какого автора, какие песни будут затронуты), и переключателем (boolean) «Искать среди песен других авторов?» со значением по умолчанию **FALSE** (соответствует варианту «НЕТ»).
- **FR-004** По подтверждению (клик «Да») MUST отправляться POST-запрос на бэкенд с двумя параметрами: `author` (trimmed-строка, обязательно) и `crossAuthor` (boolean; `false` — по умолчанию, `true` — если переключатель в положении «ДА»).
- **FR-005** По подтверждению MUST показываться информационный тост «Операция запущена в фоне. Итог придёт уведомлением по завершении.»; модалка закрывается.
- **FR-006** Бэкенд MUST обрабатывать только песни выбранного автора с `root_id = 0` (без фильтра по `id_status` на этапе отбора — пользователь явно сказал «для всех песен автора у которых rootId = 0»); сравнение `song_author` — регистронезависимое (`LOWER(song_author) = LOWER(?)`).
- **FR-007** Для каждой такой песни MUST применяться та же логика подбора кандидата в «родители», что и в существующей функции `findParentCandidateId` (Utils.kt, точный поиск по нормализованному названию), с двумя приоритетами: «того же автора → с наименьшим id», и с дополнительным ограничением по флагу `crossAuthor`:
  - если `crossAuthor = false` — кандидаты отбираются **только** среди песен того же автора (всех, независимо от наличия `source_text`);
  - если `crossAuthor = true` — если среди того же автора кандидатов нет, fallback на любую другую песню с минимальным `id`;
  - **наличие `source_text` у кандидата НЕ влияет на выбор родителя** (важно: родителем может быть и песня без текста — «сирота» с тем же нормализованным названием).
- **FR-008** Если у песни уже есть проверенный текст (`source_text` непусто И `id_status >= 2`) — родитель находится, но **не привязывается** (поведение как у существующей `customFunction`, фаза 1).
- **FR-009** Бэкенд MUST запускать операцию в **фоновом потоке** (паттерн `thread { … }`, как у `customFunction`/`autoAssignOriginalAll`); ответ HTTP возвращается сразу, итог приходит SSE-уведомлением с заголовком «Поиск родителя (автор …)» и телом-сводкой (обработано / назначено / найдено, но пропущено из-за текста).
- **FR-010** Бэкенд MUST иметь защиту от повторного запуска: in-memory флаг `@Volatile isFindParentInProgress` (single-instance JVM); если уже идёт — возвращает `ALREADY_RUNNING`, фронт показывает тост-предупреждение.
- **FR-011** В отличие от глобальной `customFunction`, новая операция MUST включать **только фазу 1** (текстовый поиск родителя); фаза 2 (аудио-родитель по акустическому сходству) **НЕ запускается** (по требованию пользователя — только «поиск родителя», без аудио-сверки).
- **FR-012** Новая операция должна быть **идемпотентна** относительно уже привязанных родителей: песни, у которых на момент старта `root_id <> 0`, в выборку НЕ попадают (SQL-фильтр `WHERE root_id = 0`).
- **FR-013** Логи консоли (stdout) MUST сохранять образец сообщений существующей `customFunction`: `Найдено песен: N`, `[родитель i/N] … — привязан родитель`, `… — пропущено (текст уже проверен)`, `… — родитель не найден`, финальная сводка `Обработано N, родитель назначен M (найдено, но пропущено из-за текста: K)`.
- **FR-014** Главная страница админки MUST отображать новую кнопку «Найти аудио-родителя» **между** кнопкой «Поиск родителя» (FR-001) и кнопкой «Автопривязать оригинал по аудио (статус 1 → 2)». Кнопка MUST быть задизейблена, если поле «Автор» пустое.
- **FR-015** По клику MUST открываться стандартная модалка `CustomConfirm` с заголовком «Подтвердите действие», телом-описанием (автор, критерий отбора `root_id ≠ 0`, фразы «текст/маркеры/статус не изменяются» и «операция очень тяжёлая»), без дополнительных полей. По подтверждению — POST `/api/utils/findaudioparentforauthor?author=…`.
- **FR-016** Бэкенд MUST отбирать только песни выбранного автора с `root_id <> 0` **И** `audio_parent_id = 0` (`LOWER(song_author) = LOWER(?)`); `findParentForAuthor` для текстового поиска не вызывается — только аудио-фаза. Фильтр `audio_parent_id = 0` обеспечивает идемпотентность: песни, для которых `findAudioParentByWaveform` уже отработал ранее, повторно не обрабатываются.
- **FR-017** Для каждой такой песни MUST вызываться `findAudioParentByWaveform(song, …, searchOtherAuthors = false)`. Параметр `searchOtherAuthors = false` MUST исключать `searchSongsByNormalizedName` из набора кандидатов — поиск идёт **только в семье** (`findFamilySongIds` транзитивно по `root_id`).
- **FR-018** Используется существующая логика записи `audio_parent_id`/`audio_similarity_percent`/`audio_delta_ms` через `findAudioParentByWaveform`: **без** копирования маркеров/текста/статуса, **без** перевода в статус 2, **без** записи `.srt` (в отличие от `autoAssignOriginalByWaveform`).
- **FR-019** Используется существующий порог `AUDIO_PARENT_THRESHOLD = 95%` (hardcoded в `Utils.kt:5087`); кэш `audio_compare_history` (`WaveformCompare.compareWaveforms` не вызывается повторно для уже сверенных пар) — действует автоматически.
- **FR-020** Фоновая операция (`thread { … }`), отдельный `@Volatile isFindAudioParentInProgress` (single-instance JVM); при повторном вызове во время работы — `"ALREADY_RUNNING"`, фронт показывает warning-тост. **Отдельный** от `isFindParentInProgress` флаг — аудио- и текстовая фазы могут идти параллельно.
- **FR-021** SSE-уведомление по завершении: `head = "Поиск аудио-родителя (автор «<author>»)"`, `body = "Обработано N, аудио-родитель назначен M, пропущено K"`, `type = "info"`.
- **FR-022** Логи консоли (stdout) MUST логировать прогресс по образцу `customFunction`: `Поиск аудио-родителя (автор «…»): найдено песен в семье: N`, `[аудио-родитель i/N] … — …» (reason из `AudioParentResult.reason`), финальная сводка `Обработано N, аудио-родитель назначен M, пропущено K`.

### Key Entities

- **Song** (таблица `tbl_songs`): сущность песни; ключевые атрибуты для фичи — `id`, `song_author`, `song_name`, `source_text`, `root_id`, `id_status`. Выборка — только строки с `root_id = 0` и (после фильтра по автору) `LOWER(song_author) = LOWER(?)`. Изменяемый атрибут — `root_id` (привязывается `id` родителя).
- **ParentCandidate** (in-memory, private в `Utils.kt`): кандидат в «родители» — `id`, `author`. Наличие текста (`source_text`) больше **не** хранится в этой data-class и не влияет на выбор кандидата (см. замечание пользователя 2026-08-31).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% сценариев — кнопка задизейблена при пустом авторе и доступна при непустом (проверяется за один цикл открытия/закрытия главной страницы админки).
- **SC-002**: После нажатия «Поиск родителя» с переключателем «НЕТ» (`crossAuthor=false`) **ноль** песен других авторов становятся кандидатами в родители — даже если у них точно совпадает нормализованное название (проверяется по логам `findParentCandidateId`: `pool`/`sameAuthor` после применения фильтра содержит только `sameAuthor`).
- **SC-003**: Повторный запуск во время работы MUST вернуть `ALREADY_RUNNING` в течение 1 секунды (фронт показывает warning-тост); повторный запуск после завершения MUST обработать только те песни, у которых `root_id = 0` на момент старта (SQL-фильтр).
- **SC-004**: SSE-уведомление по завершении содержит: количество обработанных песен автора, количество получивших родителя, количество найденных, но пропущенных из-за уже проверенного текста — **без** упоминания аудио-фазы.
- **SC-005**: Операция не изменяет записи песен других авторов и не запускает фазу акустической сверки (ffmpeg-декод на «семью»); в логах контейнера `karaoke-app` за время операции нет вызовов `autoAssignOriginalByWaveform`/`findAudioParentByWaveform`, инициированных этим запросом.
- **SC-006**: Кнопка «Найти аудио-родителя» обрабатывает только песни автора с `root_id <> 0` **И** `audio_parent_id = 0`. Песни, для которых `findAudioParentByWaveform` уже отработал ранее (`audio_parent_id <> 0`), НЕ попадают в выборку — повторный запуск не инициирует для них `WaveformCompare.compareWaveforms` (проверяется по логам контейнера `karaoke-app` — отсутствие новых строк `WaveformCompare.compareWaveforms(song=<id с audio_parent_id>…)`).
- **SC-007**: Кнопка «Найти аудио-родителя» НЕ изменяет `source_text`, `source_markers`, `id_status`, `root_id` обработанных песен (в отличие от `autoAssignOriginalAll`, которая применяет выбор); изменяются только `audio_parent_id`/`audio_similarity_percent`/`audio_delta_ms`/`audio_compare_history` (проверяется по `recordhash`-диффу до/после в `tbl_songs`).

## Assumptions

- **A-001**: «Стандартная модалка» в контексте главной страницы админки — это `CustomConfirm` (компонент `webvue3/src/components/Common/CustomConfirm.vue`), с булевым полем через `fldIsBoolean: true`. Именно он уже используется во всех остальных кнопках `HomeView`.
- **A-002**: «Искать среди песен других авторов» — это расширение текущей логики `findParentCandidateId`, а не новая логика с нуля. Если `crossAuthor=false`, отбираются кандидаты только среди песен того же автора (`sameAuthor` — единственный допустимый пул). Если кандидатов в `sameAuthor` нет — возвращается `null` (родитель не найден), **без** фоллбэка на других авторов.
- **A-010**: По замечанию пользователя от 2026-08-31, наличие `source_text` у кандидата больше **не** влияет на выбор родителя — ранее существовавшая приоритезация «сначала кандидаты с текстом → потом того же автора» ошибочно отсеивала «сирот»-родителей без текста. Применяется и в `customFunction` (общая функция `findParentCandidateId` теперь ищет среди всех песен автора, независимо от `source_text`). Логика применения (`applyDuplicateOriginal` если у оригинала есть текст; иначе просто `song.rootId = original.id`) остаётся без изменений.
- **A-003**: Под «аудио-родителем» (фаза 2) пользователь не подразумевает — речь только про текстового родителя по нормализованному названию (фаза 1 `customFunction`). Если в будущем понадобится аудио-фаза для автора — будет отдельная фича/кнопка.
- **A-004**: Куратор использует уже знакомый поток «выбрал автора → кликнул кнопку → подтвердил → дождался SSE-тоста». Дополнительной инструкции/хелпа в модалке не требуется — текст в `body` кратко описывает, что будет сделано.
- **A-005**: Новый эндпоинт — отдельный (`POST /api/utils/findparent` или `POST /api/songs/findparent`), а не параметризация существующего `/api/utils/customfunction` — чтобы не ломать фронт глобальной кнопки и не множить флаги внутри одной функции.
- **A-006**: Идемпотентность по `root_id` обеспечивается чисто SQL-фильтром на старте — никаких дополнительных «защёлок» в `tbl_songs` не требуется.
- **A-007**: Защита от гонок — в памяти JVM (`@Volatile`), достаточно для single-instance `karaoke-app` (см. Constitution § IV и образец `isCensoredRescanInProgress` в `Utils.kt`).
- **A-008**: Фича действует только на **LOCAL** (как и существующая `customFunction`/`autoAssignOriginalAll`) — изменения попадают на прод через обычную синхронизацию, отдельной логики прод-зеркала не требуется.
- **A-009**: Период хранения результатов и история запусков — не в скоупе фичи (в SSE-тосте достаточно сводной строки).
