# Quickstart: проверка фикса группировки одноимённых альбомов

В CI автотестов на этот сценарий нет (см. `constitution.md`), проверка —
ручная, локально на admin-машине (LOCAL БД).

## Предпосылки

- Локальный стек поднят (`deploy/do.sh`, LOCAL Postgres,
  `karaoke-app`/`karaoke-web`/`webvue3`/`karaoke-public` контейнеры).
- Доступ к LOCAL Postgres (`psql` или любой SQL-клиент).

## 1. Найти или создать тестовую коллизию

Проверить, есть ли уже в LOCAL БД автор с двумя альбомами одинакового
названия в разные годы:

```sql
SELECT song_author, song_album, song_year, count(*) AS songs
FROM tbl_songs
GROUP BY song_author, song_album, song_year
HAVING song_album <> ''
ORDER BY song_author, song_album;
```

Затем визуально проверить по выводу, есть ли для одного `song_author` +
`song_album` несколько разных `song_year`. Если готовых данных нет — можно
временно (только на LOCAL, не на проде) продублировать `song_album` у пары
песен разных лет одного автора, либо взять любого тестового автора с 1
альбомом и добавить вторую тестовую песню с тем же названием альбома, но
другим годом.

## 2. Проверка через прямой API-запрос (быстрее всего)

```bash
curl -s "http://localhost:<WEB_PORT>/api/public/zakroma?author=<ИМЯ_АВТОРА>" | jq '.[0].albums[] | {albumName, year, songs: (.albumSettings | length)}'
```

**Ожидаемый результат (после фикса)**: по одной строке на каждую реальную
(год, название)-комбинацию, сумма `songs` по всем строкам с одинаковым
`albumName` равна фактическому числу песен в БД для этого автора+альбома
(см. запрос из шага 1).

**Признак бага (до фикса)**: одна строка на дублирующееся `albumName» с
`songs`, равным сумме обоих альбомов, и `year`, равным году «первой
попавшейся» песни — второй год в выдаче отсутствует вовсе.

## 3. Проверка через UI (закрома)

1. Открыть `/zakroma?author=<ИМЯ_АВТОРА>` (admin или прод-страница) либо
   соответствующую страницу в `karaoke-public`.
2. Убедиться, что видно ДВЕ отдельные карточки альбома с одинаковым
   названием и разными годами.
3. Открыть каждую карточку и убедиться, что состав песен и (если уже
   привязан `album_id`) обложка/описание соответствуют именно этому
   (году, названию), а не перемешаны.

## 4. Регресс для авторов без коллизий

Выбрать 1-2 произвольных авторов без дублирующихся названий альбомов,
сравнить `curl`-вывод (шаг 2) до и после фикса — списки альбомов и подсчёт
песен должны совпадать побайтово (SC-003 spec.md).

## Критерий готовности

- Шаг 2/3 показывают обе карточки с корректными годами и полным (без потерь
  и задвоений) набором песен — SC-001, SC-002 spec.md выполнены.
- Шаг 4 не показывает отличий — SC-003 spec.md выполнен.
