# Feature Specification: Альбомы — клик по ячейке открывает модалку обложки альбома

**Feature Branch**: `[014-album-cell-album-cover-modal]`
**Created**: 2026-07-27
**Status**: Draft
**Input**: User description: "Админка, компонент \"Альбомы\". Клик на ячейку столбца (альбом) должен открывать такую же модалку, как открывается при клике на кнопку \"Изменить обложку альбома\" в SongEdit.vue с таким же функционалом."

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Клик по preview обложки альбома открывает модалку обложки (Priority: P1)

Администратор открывает раздел «Альбомы», применяет фильтр (или видит уже загруженные альбомы), наводит курсор на preview обложки в колонке `(альбом)` — курсор меняется, ячейка визуально подсвечивается. Клик по этой ячейке открывает модальное окно «Обложка альбома» с тем же интерфейсом и поведением, что и кнопка «Изменить обложку альбома» в `SongEdit.vue`: превью текущей обложки, поле поискового запроса, чекбокс «Не искать в Яндекс.Музыке», кнопки «Найти в интернете» / «Загрузить с диска», переход к шагу кадрирования и сохранение как `LogoAlbum.png` в папке альбома.

**Why this priority**: Это и есть суть фичи — повторить функционал SongEdit в Albums. Preview-обложка — самое логичное место для триггера, т.к. колонка буквально называется `(альбом)`.

**Independent Test**: Открыть `/Albums`, применить фильтр, навести курсор на preview в колонке `(альбом)` — должна появиться визуальная подсказка кликабельности. Кликнуть — должно открыться модальное окно «Обложка альбома» с шагами `view` / `searching` / `results` / `cropping` (как в SongEdit). Закрыть — таблица не сломана, текущая страница и фильтр сохранены.

**Acceptance Scenarios**:

1. **Given** таблица альбомов загружена (songsCount > 0), **When** администратор кликает по preview обложки в колонке `(альбом)`, **Then** открывается модалка `AlbumCoverModal` с шагом `view` и текущей обложкой (или плейсхолдером «Картинки альбома пока нет»).
2. **Given** открыта модалка обложки из `AlbumsTable`, **When** администратор вводит запрос, нажимает «Найти в интернете» и кликает по одному из кандидатов, **Then** открывается шаг `cropping`, по «Сохранить» обложка сохраняется в `LogoAlbum.png` папки альбома, модалка закрывается, превью в таблице обновляется.
3. **Given** открыта модалка обложки из `AlbumsTable`, **When** администратор нажимает «Загрузить с диска», выбирает файл и подтверждает, **Then** открывается шаг `cropping`, по «Сохранить» обложка сохраняется аналогично сценарию 2.
4. **Given** открыта модалка обложки из `AlbumsTable`, **When** администратор нажимает «Закрыть» без сохранения, **Then** модалка закрывается, обложка в таблице не меняется.

### User Story 2 — Клик по названию альбома тоже открывает модалку обложки (Priority: P2)

Администратор кликает по ячейке с названием альбома в колонке `Название` — открывается та же модалка «Обложка альбома» (а не модалка изменения атрибутов альбома, как сейчас).

**Why this priority**: Поведение «клик по preview = модалка обложки» для админки альбомов логически расширяется на название — пользователь, привыкший к интерфейсу `Pictures`/`Authors`, ожидает кликабельности ячейки с именем. Делать только preview было бы «полу-мерой». P2, потому что preview — главный кейс.

**Independent Test**: Кликнуть по ячейке `Название` любого альбома с songsCount > 0 — открывается `AlbumCoverModal` (не `CustomConfirm` редактирования).

**Acceptance Scenarios**:

1. **Given** таблица альбомов загружена (songsCount > 0), **When** администратор кликает по ячейке с названием альбома, **Then** открывается модалка `AlbumCoverModal` (а не `CustomConfirm` с полями `year`/`name`/`albumType`/…).
2. **Given** альбом с songsCount = 0, **When** администратор наводит курсор на ячейку `Название` или preview `(альбом)`, **Then** курсор не меняется на pointer (или ячейка визуально показывает, что действие недоступно), при клике ничего не происходит / показывается ненавязчивая подсказка «У альбома нет песен — обложка недоступна».

---

### User Story 3 — Корректное восстановление состояния после закрытия модалки (Priority: P3)

После открытия модалки обложки из `AlbumsTable` и её закрытия (с сохранением или без) — таблица альбомов, пагинация, фильтр и прочее состояние админки работают без сбоев. Если до открытия модалки в `SongsStore` уже была установлена `currentSongId` (например, администратор до этого работал в разделе «Песни»), то после закрытия модалки это состояние либо сохраняется, либо корректно сбрасывается — без неожиданных эффектов.

**Why this priority**: Побочный эффект — админ не должен потерять рабочий контекст. P3, потому что это «защита от граблей», а не основной сценарий.

**Independent Test**: Перейти `Песни → Альбомы` (с активной `currentSongId`), кликнуть preview `(альбом)`, сохранить новую обложку, закрыть. Вернуться в `Песни` — должна открыться та же песня, что и до перехода (или хотя бы не «случайная»).

**Acceptance Scenarios**:

1. **Given** администратор переходит в `Альбомы` с уже установленной `currentSongId` в `SongsStore`, **When** он открывает и закрывает модалку обложки альбома, **Then** после закрытия `currentSongId` восстанавливается к прежнему значению (если до открытия модалки временно подменялась на песню альбома).

---

### Edge Cases

- **Альбом без песен** (`songsCount = 0`): модалка обложки работает с `settings.pictureAlbum` через `Song.loadFromDbById`, поэтому **без хотя бы одной песни** альбом не имеет `rootFolder`/папки на диске — открывать модалку бессмысленно. Должна быть защита: ячейка не реагирует на клик, либо модалка показывает сообщение «У альбома нет песен — невозможно открыть обложку».
- **Альбом с одной песней**: основной кейс — модалка открывается по этой песне.
- **Альбом с многими песнями**: какую песню использовать как «контекст»? По умолчанию — **первую по id** (сортировка стабильна, повторяемо). Документируется в Assumptions.
- **Preview обложки ещё не загружено в MinIO**: модалка показывает плейсхолдер «Картинки альбома пока нет» (как в SongEdit) — штатное поведение.
- **Ошибка сети при сохранении**: модалка показывает сообщение «Не удалось сохранить картинку» (как в SongEdit), не закрывается.
- **Совместимость с фильтром SKIP/тегами**: фича не зависит от тегов, работает на любом альбоме в `albumsDigest` (даже если у песен альбома есть `tags = 'SKIP'` — тогда обложка всё равно доступна, но в публичном каталоге не показывается).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В `AlbumsTable.vue` клик по ячейке в колонке `(альбом)` (превью обложки) **MUST** открывать модалку `AlbumCoverModal` с тем же шаблоном, поведением, шагами и событиями (`close`, `saved`), что и в `SongEdit.vue`.
- **FR-002**: В `AlbumsTable.vue` клик по ячейке в колонке `Название` **MUST** открывать ту же модалку `AlbumCoverModal` (а не `CustomConfirm` редактирования атрибутов альбома).
- **FR-003**: Перед открытием модалки система **MUST** гарантировать наличие подходящего «контекста» — песни, от имени которой будет работать модалка (`Song.loadFromDbById` на бэке использует `settings.rootFolder`, `settings.album`, `settings.author`). Если у альбома нет песен (`songsCount === 0`) — клик **MUST** не открывать модалку, и **SHOULD** показывать ненавязчивую подсказку (title у ячейки).
- **FR-004**: Сохранение новой обложки через модалку **MUST** приводить к тому же результату, что и сохранение из `SongEdit.vue`: файл `LogoAlbum.png` в папке альбома на диске, обновление/создание записи `Pictures` с тем же `name = settings.pictureNameAlbum`, инвалидация кэша. После успешного сохранения модалка **MUST** закрываться, а превью обложки в `AlbumsTable` **MUST** обновиться (через `loadOneRecord` для этой записи, как уже делается в `doChangeValue`).
- **FR-005**: Изменение `currentSongId` в `SongsStore`, необходимое для открытия модалки, **MUST** быть либо обратимым (восстановление прежнего значения после закрытия модалки), либо документированным в Assumptions как «побочный эффект» (с сохранением обратной навигации через стек/историю).
- **FR-006**: В `AlbumsTable.vue` **SHOULD** быть визуальная подсказка кликабельности ячеек `(альбом)` и `Название` (cursor: pointer, hover-стиль), согласованная с остальными кликабельными ячейками таблицы (как у `.fld-album-name:hover`).
- **FR-007**: Модалка **MUST** корректно закрываться по крестику/«Закрыть»/клику вне области без сохранения, и `AlbumsTable` **MUST** восстанавливать работоспособность (текущая страница пагинации, фильтр, состояние таблицы) без перезагрузки.

### Key Entities *(include if feature involves data)*

- **AlbumCoverModal** (Vue-компонент): модалка поиска/загрузки/обрезки/сохранения обложки альбома. Уже существует, не изменяется.
- **Album (albumsDigest)**: запись альбома в таблице `AlbumsTable` с полями `id`, `authorId`, `authorName`, `year`, `name`, `albumType`, `songsCount`, `albumPictureId`, `albumPicturePreviewUrl`. Не имеет `rootFolder` — берётся из связанной `Song`.
- **Song**: запись песни; используется как «контекст» для модалки (через `currentSongId` в `SongsStore`). Содержит `rootFolder`, `album`, `author`, от имени которых backend читает/пишет `LogoAlbum.png`.
- **Picture (Pictures table)**: запись изображения альбома в БД + MinIO; связана с `Album` через `albumPictureId` (preview в таблице берётся из MinIO).
- **LogoAlbum.png**: файл обложки альбома, лежит в `settings.rootFolder/LogoAlbum.png`. Источник истины для `pictureAlbum` — модалка пишет сюда.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Администратор, находясь в `/Albums`, может сменить обложку любого альбома с `songsCount > 0` за ≤ 4 клика (preview → модалка → выбор кандидата/загрузка с диска → сохранить), без перехода в `/Songs` или `/Pictures`.
- **SC-002**: После сохранения новой обложки из `AlbumsTable` превью в колонке `(альбом)` обновляется без ручной перезагрузки страницы (≤ 2 секунд после закрытия модалки).
- **SC-003**: Сохранённая через `AlbumsTable` обложка идентична той, что получилась бы при сохранении через `SongEdit` той же песни того же альбома: тот же файл `LogoAlbum.png`, та же запись `Pictures` (сравнение по хэшу файла и `name = settings.pictureNameAlbum`).
- **SC-004**: 0 случаев потери рабочего контекста администратора: после открытия/закрытия модалки обложки фильтр альбомов, текущая страница пагинации и `currentSongId` (если была установлена до входа в `/Albums`) — в согласованном состоянии (см. FR-005).

## Assumptions

- Под «столбцом (альбом)» понимается колонка с заголовком `(альбом)` (preview обложки) в `AlbumsTable.vue`. Колонка `Название` делается кликабельной тоже (P2) — это однозначно и не противоречит требованию.
- Backend `/api/song/picturealbum`, `/api/song/searchalbumcover`, `/api/song/savealbumcover` привязаны к **id песни** — это **не меняется** в рамках фичи. Чтобы использовать существующую модалку as-is, перед открытием нужно установить `currentSongId = <id одной из песен альбома>`.
- Для выбора «контекстной» песни альбома используется **первая песня по `id`** (songsCount > 0). Если в будущем понадобится выбирать конкретную песню (например, с минимальным `sortOrder` или «главную») — это будет отдельная фича.
- Если в `SongsStore` уже была установлена `currentSongId` (например, администратор до этого был в `/Songs`), при открытии модалки из `/Albums` эта `currentSongId` **временно подменяется** на `currentSongId = <id песни альбома>`; после закрытия модалки — **восстанавливается** к прежнему значению. Это реализуется в `AlbumsTable.vue` (save → restore в `@close`/`@saved`).
- На уровне `data`/`AlbumCoverModal` **никаких изменений** не требуется: модалка уже умеет работать с `getCurrentSong` из store.
- Edge case «альбом без песен» обрабатывается **только на UI-уровне** (запрет клика), а не в бэкенде (бэкенд вернёт ошибку «Песня не найдена», и модалка покажет «Ничего не найдено» — но это плохой UX, поэтому блокируем раньше).
- Тесты для новой функциональности в рамках фичи **не добавляются** (см. `AGENTS.md` — «Тесты в CI нет. Существующие тесты… большинство `@Disabled`. Не полагайся на них как на проверку»). Проверка — пользователем вручную.
