# Quickstart: ручная проверка окна бесплатного доступа

Все проверки — на LOCAL-стенде (dev-pc), с прямым доступом к БД для
подготовки тестовых данных (Constitution: разрешено на `dev-pc`/`dev`).

## Подготовка

Выбрать/создать 4 тестовые готовые песни (`id_status >= 6`, оба стема +
обе картинки готовы, непустые `source_markers`) и выставить им разные
`publish_date`/`publish_time`/`free`:

| Песня | `publish_date`/`time` | `free` | Ожидаемое состояние |
|---|---|---|---|
| A | пусто | `false` | не в эфире, не всегда-бесплатна → по подписке |
| B | завтра | `false` | ещё не в эфире → «Будет в эфире с …» |
| C | 3 дня назад | `false` | в окне (< 1 месяца) → «В эфире до …» |
| D | 2 месяца назад | `false` | окно истекло → по подписке, без доп. текста |
| E | 2 месяца назад | `true` | всегда бесплатна → доступна, без доп. текста |

## 1. Доступ к плееру (`/api/public/player/{id}/access`)

Для каждой песни, под тремя ролями (аноним, обычный registered без
подписки, premium):

```bash
curl -s "http://localhost:.../api/public/player/{id}/access" | jq
```

Ожидаемо: `canWatch=true` для C, E (любая роль), для A/B/D — `canWatch=true`
только под premium ИЛИ если оформлена личная подписка на песню (проверить
отдельно через `Subscription`). Для B (не в эфире) — под всеми ролями кроме
premium/подписки `canWatch=false`, `isDemo` зависит от готовности демо-
фрагмента.

## 2. Закрома (`/zakroma`, karaoke-public)

Открыть `/zakroma` под анонимным пользователем, найти автора с песнями
A-E:
- A: без доп. текста (монетка премиум видна)
- B: «Будет в эфире с {дата}»
- C: «В эфире до {дата = момент эфира + 1 месяц}»
- D: без доп. текста (монетка видна, как A)
- E: без доп. текста, плеер доступен

Повторить под premium-пользователем — ни для одной строки нет
дополнительного текста (FR-010).

## 3. Страница песни (`/song?id=...`)

Для песни D (аирилась, окно истекло) под анонимным пользователем: карточка
ожидания с заголовком «Эта песня доступна только по подписке» (НЕ
легаси VK-видео-блок). Для песни с ещё не готовым контентом и `onAir=true`
— наоборот, должен показаться VK-видео-блок (регрессия на Decision 6).

## 4. Счётчики (`/api/public/stats`, `/`, `/about`)

```bash
curl -s "http://localhost:.../api/public/stats" | jq
```

Проверить: `freeNow` включает C и E (и все реальные аналоги в БД), НЕ
включает A/B/D. `subscriptionOnly = collection - freeNow`. Открыть `/` и
`/about` — карточки статистики показывают согласованные числа с прямым
`curl`-запросом.

## 5. Админка (`webvue3`)

- Таблица песен: колонка `EX`/фильтр «Exclusive» отсутствуют.
- Карточка редактирования песни: переключателя «Эксклюзивно на sponsr»
  нет; переключатель «Бесплатно на sponsr» переименован (текст про
  «всегда бесплатно / вечный эфир»), по-прежнему меняет `song.free`.
- Сохранить песню с `free=true` без даты эфира — убедиться, что
  `/api/public/player/{id}/access` отдаёт `canWatch=true` анониму.

## 6. Регресс: авто-новость «в эфире» (specs/089) не сломана

Взять песню, у которой скоро наступит `publish_date`/`publish_time` (или
выставить дату/время на 1-2 минуты вперёд), дождаться срабатывания —
убедиться, что новость категории `air` публикуется РОВНО ОДИН РАЗ в момент
наступления даты (не раньше, не при истечении окна месяц спустя). Это
проверяет, что `Song.isPubliclyWatchable`/`onAir` не были случайно задеты
(research.md Decision 1).

## 7. Итоговая проверка тождества (SC-003 spec.md)

```sql
SELECT
  (SELECT count(*) FROM tbl_songs WHERE <SKIP_FILTER>) AS total,
  (SELECT count(*) FROM tbl_songs WHERE <CONTENT_READY_FILTER> AND <SKIP_FILTER>) AS collection;
```

Сверить `collection == freeNow + subscriptionOnly` и
`total == collection + inWork` из ответа `/api/public/stats`.
