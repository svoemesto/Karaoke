## Сверки

Без severity; к разбору лидом/владельцем.

1. **BR-195 (P-20) со стороны фронта.** `StatsView` шлёт `target`/`days`/`mode` в каждом запросе и сбрасывает собственный TTL при смене БД (`clearActiveTabData` → `setLastLoadedAt {ts: 0}`), но бэкенд-кеш 60 с всё равно отдаёт ответ другого `target`/`days` (ключ без параметров). Фронтовая часть — не новый дефект, а подтверждение пути в BR-195; отдельной записи не создавал. Замечание: вкладка «Монетизация» (`/api/stats/monetization`) — денежные цифры другой БД в том же окне.
2. **Частичный успех и TTL.** `loadStatsBreakdown`/`loadStatsGeo` возвращают `true`, если успешен **хотя бы один** из 2–3 endpoint'ов (`store.js:435`, `:458`), а `StatsView.loadDataForActiveTab` по `true` взводит TTL на всю вкладку (`StatsView.vue:784–787`). При отказе одного endpoint'а его блок (например, `channels`) не перезагружается 60 с и показывает прежние/пустые данные. Спека 478 FR-004 говорит «TTL только при успехе» — считать ли частичный успех успехом (задумано) или это дефект? Нужен вердикт.
3. **Валидация цены тарифа.** UI не мешает ввести отрицательную цену при редактировании (`min="0"` — только атрибут HTML, `isChanged`/`save` не проверяют), `TariffsController.update` (вне порции) значение не валидирует. Вопрос: вести это как дефект в порции `karaoke-app` controllers (деньги, прод-БД) или считать административной ошибкой ввода?
4. **Размер drill-down.** `loadStatsSongEvents` по умолчанию просит `pageSize=2000` (`store.js:513`), а `/api/stats/song-events` передаёт `pageSize` в SQL без клампа. Ограничение лимита на бэкенде уже описано в P-20-02 (BR-196) — не дублирую; здесь только фиксирую, каким объёмом фронт пользуется штатно.
5. **Лишний I/O при смене периода.** `onDaysChange` (`StatsView.vue:855–877`) всегда шлёт `summary`+`timeseries`+`breakdown` (5 запросов) при активной вкладке KPI/Динамика/Разбивки и взводит TTL только для активной вкладки, поэтому при переходе на соседнюю вкладку те же данные запрашиваются повторно. Не дефект по рубрике (нет неверного результата), но избыточная нагрузка на 11-endpoint-дашборд.
