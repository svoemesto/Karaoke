# Feature Specification: Исправление автоподстановки найденного текста песни

**Feature Branch**: `[020-fix-search-lyrics-autofill]`

**Created**: 2026-07-28

**Status**: Draft

**Input**: User description: "Как то странно работает функционал \"Найти тексты для всех песен\". Результаты поиска не всегда сохраняются в таблицах tbl_search_async и tbl_search_results, а если есть найденный текст, при пустом тексте песни не происходит подставление найденного текста в текст песни. Возможно это из-за того, что в поле source_text может быть как пустое значение, так и [\"\"]. В обеих случаях это значит \"текста ещё нет\". (Уточнение автора в ходе диалога: претензия про ненадёжное сохранение в tbl_search_async/tbl_search_results снята — это нормальное поведение, когда поиск ничего не находит. Актуальная и подтверждённая проблема — только неподстановка найденного текста. Найденное значение должно подставляться в текст песни, если текущий текст песни — `''` либо `'[\"\"]'`.)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Автоподстановка найденного текста независимо от способа хранения "пустого" текста (Priority: P1)

Редактор запускает поиск текста песни в интернете (для одной песни или пакетно — «Найти тексты для всех песен») для песни, у которой текста ещё нет. Поиск находит непустой текст-кандидат. Система должна автоматически подставить найденный текст в поле текста песни — независимо от того, хранится ли текущее "отсутствие текста" как пустая строка (`''`) или как значение-заглушка (`'[""]'`).

**Why this priority**: Это основная цель бага — сейчас при значении-заглушке `'[""]'` подстановка молча не происходит, и редактору приходится вручную копировать найденный текст, хотя система формально считает, что делает это автоматически. Это касается всех движков поиска (YANDEX_SYNC, YANDEX_ASYNC, SEARXNG, FOURGET), которые формируют результат.

**Independent Test**: Взять песню с текстом `'[""]'`, запустить поиск текста любым движком так, чтобы поиск нашёл непустой текст-кандидат; убедиться, что текст песни заполнился найденным текстом, а статус песни продвинулся так же, как если бы текущий текст был пустой строкой `''`.

**Acceptance Scenarios**:

1. **Given** текст песни — пустая строка `''` и статус песни "новая" (текста ещё нет), **When** поиск текста находит непустой текст-кандидат, **Then** найденный текст подставляется в текст песни (текущее поведение сохраняется).
2. **Given** текст песни — значение-заглушка `'[""]'` и статус песни "новая" (текста ещё нет), **When** поиск текста находит непустой текст-кандидат, **Then** найденный текст подставляется в текст песни точно так же, как в сценарии 1.
3. **Given** текст песни уже содержит реальный (непустой и не равный `''`/`'[""]'`) текст, **When** поиск текста находит какой-либо текст-кандидат, **Then** существующий текст песни не перезаписывается автоматически.
4. **Given** пакетный запуск «Найти тексты для всех песен» на нескольких песнях, часть из которых имеет `''`, а часть — `'[""]'`, **When** поиск по каждой из них находит непустой текст-кандидат, **Then** для всех таких песен, независимо от формы "пустого" значения, найденный текст подставляется одинаково.

---

### Edge Cases

- Что происходит, если поиск не находит ни одного непустого текста-кандидата (обычная ситуация, не баг)? Текст песни остаётся как был («текста ещё нет»), подстановки не происходит.
- Что происходит, если текущий текст песни — не `''` и не `'[""]'`, а, например, пробелы или другое "пустое на вид" значение? Такие значения не входят в подтверждённое определение "текста ещё нет" для этой фичи и не рассматриваются — поведение для них не меняется.
- Что происходит, если поиск запущен через движок YANDEX_SYNC, у которого результат приходит синхронно? Автоподстановка должна сработать так же надёжно, как и для остальных движков — факт использования конкретного движка не должен влиять на то, сработает ли подстановка при найденном тексте.
- Что происходит с результатами поиска, если ни один текст-кандидат не найден (это НЕ входит в объём этой фичи — является ожидаемым поведением, а не дефектом)?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА использовать единое, одинаковое во всех местах определение "у песни ещё нет текста", включающее оба подтверждённых представления: пустая строка `''` и значение-заглушка `'[""]'`.
- **FR-002**: При завершении поиска текста песни (для любого из поддерживаемых движков поиска) система ДОЛЖНА автоматически подставлять первый найденный непустой текст-кандидат в текст песни, если у песни "ещё нет текста" согласно определению из FR-001.
- **FR-003**: Автоподстановка ДОЛЖНА срабатывать одинаково независимо от того, какой из поддерживаемых движков поиска использовался (синхронный и асинхронный запросы, а также инструменты веб-поиска).
- **FR-004**: Система НЕ ДОЛЖНА автоматически перезаписывать текст песни, если у песни уже есть текст, не подпадающий под определение "ещё нет текста" из FR-001.
- **FR-005**: Поведение пакетного запуска «Найти тексты для всех песен» для каждой отдельной песни в отношении автоподстановки ДОЛЖНО быть идентично поведению поиска текста для одной песни.

### Key Entities *(include if data involved)*

- **Песня (Song)**: содержит текст песни (source text) и статус готовности текста; "текста ещё нет" определяется как текст, равный `''` либо `'[""]'`.
- **Результат поиска (найденный текст-кандидат)**: текст, извлечённый по одной из найденных поиском ссылок; может быть пустым (тогда не используется для подстановки) или непустым (тогда — кандидат на подстановку).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для 100% песен, у которых текст равен `''` или `'[""]'` и поиск нашёл непустой текст-кандидат, текст песни автоматически заполняется найденным текстом — без ручного вмешательства редактора.
- **SC-002**: Результат автоподстановки (заполнится текст или нет) не зависит от того, какое из двух подтверждённых "пустых" представлений было у песни до поиска, и не зависит от выбранного движка поиска.
- **SC-003**: Ни одна песня с уже существующим (не "пустым" согласно FR-001) текстом не получает автоматическую перезапись текста в результате поиска.

## Assumptions

- "Текста ещё нет" в рамках этой фичи означает ровно два подтверждённых автором представления: пустая строка `''` и значение-заглушка `'[""]'`. Другие потенциально "пустые" представления (например, пробелы, JSON-массив с несколькими пустыми элементами для многоголосых песен) не входят в объём этой фичи, если не будут отдельно подтверждены.
- Ретроактивная переобработка уже сохранённых ранее результатов поиска (для песен, где подстановка в прошлом не сработала из-за этого дефекта) не входит в объём — редактор может воспользоваться существующей функцией «переискать» для конкретной песни при необходимости.
- Опрос/сохранение сырых результатов поиска в таблицах результатов поиска (tbl_search_async/tbl_search_results) работает штатно и не является предметом этой фичи — единственный подтверждённый дефект находится в шаге подстановки найденного текста в текст песни.
