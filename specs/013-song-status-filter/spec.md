# Feature Specification: Показ на проде только песен со статусом готовности >= 3

**Feature Branch**: `013-song-status-filter`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "На проде (в закромах, в поиске) отображать только песни со статусом >=3"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Посетитель просматривает закрома автора (Priority: P1)

Посетитель публичного сайта открывает закрома автора (страницу со списком его
альбомов и песен). Он должен видеть только те песни, которые действительно
готовы к прослушиванию (статус готовности >= 3), и не должен видеть песни,
которые ещё находятся в производстве (транскрибируются, размечаются,
рендерятся и т.п.).

**Why this priority**: Это основной сценарий обнаружения контента на сайте —
показ незавершённых песен вводит посетителя в заблуждение (пустые/битые
ссылки, отсутствующий плеер, недоделанный текст) и подрывает доверие к
продукту.

**Independent Test**: Найти автора, у которого есть песни со статусом < 3 и
песни со статусом >= 3, открыть его закрома на проде и убедиться, что в
списке присутствуют только песни со статусом >= 3, а остальные не показаны
(и не оставляют «дыр»/пустых карточек).

**Acceptance Scenarios**:

1. **Given** у автора есть альбом с 5 песнями, из которых 3 имеют статус >= 3,
   а 2 — статус < 3, **When** посетитель открывает закрома этого автора,
   **Then** в альбоме отображаются только 3 готовые песни.
2. **Given** у автора все песни имеют статус < 3, **When** посетитель
   открывает закрома, **Then** автор не отображается в списке (или
   отображается без единой песни/альбома — без пустых карточек).
3. **Given** виртуальная плашка «Отдельные песни разных авторов»
   (спецзаказные авторы), **When** посетитель открывает её, **Then** в ней
   тоже показаны только песни со статусом >= 3.

---

### User Story 2 - Посетитель ищет песню через поиск (Priority: P1)

Посетитель использует поиск по названию, автору, альбому или тексту песни.
Результаты поиска должны содержать только песни со статусом готовности >= 3.

**Why this priority**: Поиск — второй по значимости способ найти песню на
сайте; та же проблема доверия и битого опыта, что и в закромах, поэтому
приоритет такой же высокий.

**Independent Test**: Выполнить поиск по названию/автору, среди результатов
которого есть песни со статусом < 3, и убедиться, что такие песни не попадают
в выдачу.

**Acceptance Scenarios**:

1. **Given** есть песня с названием, совпадающим с поисковым запросом, и
   статусом < 3, **When** посетитель выполняет поиск по этому названию,
   **Then** песня не появляется в результатах.
2. **Given** есть две песни с одинаковым текстом в тексте песни, одна со
   статусом >= 3, другая со статусом < 3, **When** посетитель ищет по этому
   тексту, **Then** в выдаче присутствует только песня со статусом >= 3.

---

### User Story 3 - Редактор продолжает видеть все песни в админке (Priority: P2)

Редактор/администратор в админ-панели должен по-прежнему видеть песни всех
статусов (включая ещё не готовые), чтобы отслеживать их производство и
управлять ими. Новый фильтр не должен затронуть admin-интерфейс.

**Why this priority**: Ниже, чем видимость на проде, потому что это не новая
функциональность, а условие «не сломать» существующий рабочий процесс
редактора — но без этого фикс на проде рискует случайно задеть админку и
заблокировать работу редакторов.

**Independent Test**: Открыть в админке (webvue3) список песен автора, у
которого есть песни со статусом < 3, и убедиться, что они по-прежнему видны и
редактируемы.

**Acceptance Scenarios**:

1. **Given** песня со статусом < 3, **When** редактор открывает её карточку в
   админке, **Then** песня видна и доступна для редактирования как раньше.

---

### Edge Cases

- Что происходит, если у автора/альбома после фильтрации не остаётся ни одной
  песни: автор/альбом не должен отображаться в закромах пустой карточкой.
- Смена статуса песни с < 3 на >= 3 (например, песня наконец готова) должна
  сделать её видимой в закромах и поиске без дополнительных действий со
  стороны пользователя (при следующем открытии страницы/повторном поиске).
- Обратная смена статуса (например, откат готовой песни на доработку) должна
  немедленно скрыть её из закромов и поиска.
- Спецзаказная плашка «Отдельные песни разных авторов» — фильтр применяется к
  ней так же, как к обычным закромам автора.
- Единичная страница конкретной песни по прямой ссылке (не через закрома и не
  через поиск) — вне рамок этой фичи (см. Assumptions).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Публичный просмотр закромов автора MUST показывать только песни
  со статусом готовности >= 3.
- **FR-002**: Публичная плашка «Отдельные песни разных авторов» (спецзаказные
  авторы) MUST показывать только песни со статусом готовности >= 3.
- **FR-003**: Публичный поиск песен (по названию, автору, альбому, тексту)
  MUST возвращать только песни со статусом готовности >= 3.
- **FR-004**: Если после применения фильтра у автора или альбома не остаётся
  ни одной песни, такой автор/альбом MUST NOT отображаться в результатах
  закромов (без пустых карточек-заглушек).
- **FR-005**: Изменение статуса песни MUST отражаться в закромах и поиске без
  дополнительного вмешательства — при следующем обращении к странице/поиску
  видимость песни должна соответствовать её текущему статусу.
- **FR-006**: Admin-интерфейс (управление песнями в админ-панели) MUST
  продолжать показывать песни всех статусов — данный фильтр НЕ распространяется
  на административные списки/поиск в админке.
- **FR-007**: Порог фильтрации ("статус >= 3") MUST соответствовать уже
  используемому на сайте определению «песня в коллекции» (то же значение
  статуса, что используется для публичных счётчиков количества песен), чтобы
  публичные списки и публичные счётчики оставались согласованными друг с
  другом.

### Key Entities

- **Song (песня)**: единица контента с полем статуса готовности (числовое
  значение производственного пайплайна); значения >= 3 означают, что песня
  прошла стадии, необходимые для показа посетителю сайта (доступна для
  прослушивания/просмотра), значения < 3 — песня ещё в производстве.
- **Закрома автора**: публичная витрина, группирующая песни автора по
  альбомам для просмотра/прослушивания.
- **Результаты поиска**: список песен, отобранных по совпадению с поисковым
  запросом (название/автор/альбом/текст), показываемый посетителю сайта.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% песен, отображаемых в публичных закромах (включая
  спецзаказную плашку), имеют статус готовности >= 3.
- **SC-002**: 100% песен в выдаче публичного поиска имеют статус готовности
  >= 3.
- **SC-003**: Публично видимое количество песен в закромах/поиске
  согласовано с уже существующим публичным счётчиком «песен в коллекции»
  (не превышает его и не противоречит ему).
- **SC-004**: Видимость и редактируемость песен любого статуса в
  админ-панели не меняется — 100% ранее видимых редактору песен остаются
  видимыми после внедрения фильтра.

## Assumptions

- Порог «статус >= 3» — это то же самое значение, что уже применяется на
  бэкенде для публичного счётчика «песен в коллекции» (используется для
  главной страницы сайта); переиспользуем это же определение для
  согласованности, а не вводим новый отдельный порог.
- «Закрома» и «поиск» в этой фиче — это публичные страницы/API, которыми
  сегодня пользуются посетители сайта (просмотр автора по альбомам,
  спецзаказная плашка, поиск по названию/автору/альбому/тексту). Если на
  проде существуют устаревшие/неиспользуемые дублирующие страницы с тем же
  назначением, их тоже нужно привести в соответствие для согласованности
  опыта — но это не самостоятельный отдельный сценарий, а следствие того же
  правила.
- Индивидуальная страница конкретной песни по прямой ссылке, сам плеер и
  механизм готовности плеера (кто и когда может проигрывать конкретную песню)
  — отдельная, уже существующая логика; в рамках этой фичи не меняется.
- Админ-панель (интерфейс редактора/администратора) должна продолжать
  показывать песни всех статусов без исключений — фильтр статуса >= 3
  затрагивает только то, что видят посетители сайта.
