# Quickstart: Ручная проверка бейджа «новые альбомы»

**Feature**: 176-authors-new-albums-badge
**Date**: 2026-08-12
**Spec**: [spec.md](./spec.md)
**Contract**: [contracts/api-authors-withnewalbumcount.md](./contracts/api-authors-withnewalbumcount.md)

## Сценарии проверки

Каждый сценарий привязан к одному или нескольким Success Criteria из спеки. Проверка ручная — в CI автотестов нет (см. AGENTS.md «Тесты»).

## Предусловия

1. Локальный стек запущен (`bash deploy/do.sh start` или эквивалент):
   - `karaoke-db` (Postgres)
   - `karaoke-app` (бэкенд с endpoint)
   - `webvue3` (админка с бейджем)
2. Админка `webvue3` доступна (по умолчанию `http://localhost:8080/` или настроенный URL).
3. Открыть DevTools (F12) → вкладки `Console` и `Network` (для отслеживания polling-запросов).

## Сценарий 1 — Бейдж появляется при наличии новых альбомов (SC-001, SC-005)

**Цель**: Проверить, что бейдж отображается при наличии ≥ 1 автора с `haveNewAlbum = true` и визуально идентичен бейджам «Чат» / «Задания редактора».

**Шаги**:
1. Создать/выбрать в БД автора с условием `haveNewAlbum = true`:
   ```sql
   -- Убедиться, что есть хотя бы один такой автор:
   SELECT COUNT(*) FROM tbl_authors
   WHERE watched = true
     AND (ym_id <> '' OR vk_id <> '')
     AND (last_album_ym <> last_album_processed
          OR last_album_vk <> last_album_processed);
   -- Если 0 — обновить существующего автора:
   UPDATE tbl_authors
   SET watched = true,
       last_album_ym = 'Тест 2026-08',
       last_album_processed = ''
   WHERE id = 1;  -- или любой существующий
   ```
2. Открыть админку `http://localhost:8080/` (или F5, если уже открыта).
3. На левом сайдбаре найти пункт «Авторы».
4. **Ожидается**: справа от надписи «Авторы» появился красный бейдж с числом ≥ 1.
5. Сравнить визуально с бейджами «Чат» и «Задания редактора» (если у них тоже есть значения):
   - Цвет фона — одинаковый красный (`#d02c3a`).
   - Белый текст, одинаковый шрифт.
   - Скруглённые углы, одинаковый размер.

**Чек-лист проверки**:
- [ ] Бейдж виден в течение ≤ 20 секунд после открытия админки.
- [ ] В DevTools → Elements виден `<span class="authors-nav-badge">{{число}}</span>`.
- [ ] В DevTools → Styles для `.authors-nav-badge`: `background-color: #d02c3a` (или эквивалентно).
- [ ] Визуально совпадает с `.chat-nav-badge` / `.songeditor-nav-badge`.

## Сценарий 2 — Бейдж скрыт при count = 0 (SC-002)

**Цель**: Проверить, что при отсутствии авторов с новыми альбомами бейдж не отображается (нет «0» в бейдже).

**Шаги**:
1. Обнулить условие:
   ```sql
   -- Самый простой способ: всем watched авторам проставить last_album_processed = last_album_ym.
   UPDATE tbl_authors
   SET last_album_processed = last_album_ym
   WHERE watched = true AND last_album_ym <> '';
   UPDATE tbl_authors
   SET last_album_processed = last_album_vk
   WHERE watched = true AND last_album_vk <> '';
   ```
2. Подождать ≤ 20 секунд (один polling tick).
3. **Ожидается**: бейдж на пункте «Авторы» исчез.
4. В DevTools → Elements: `<span class="authors-nav-badge">` отсутствует (или скрыт через `v-if`).

**Чек-лист проверки**:
- [ ] Бейдж пропал за ≤ 20 секунд.
- [ ] Пункт меню «Авторы» не сместился (без «пустого места» от бейджа).

## Сценарий 3 — Polling обновляет значение без F5 (SC-003, SC-006)

**Цель**: Проверить, что счётчик обновляется автоматически по polling-у, без ручной перезагрузки страницы.

**Шаги**:
1. Открыть DevTools → Network, отфильтровать `withnewalbumcount`.
2. Убедиться, что запрос `POST /api/authors/withnewalbumcount` приходит каждые 20 секунд.
3. Не закрывая админку, изменить число «новых» авторов в БД:
   ```sql
   -- Увеличить на 1 (если был 0):
   UPDATE tbl_authors
   SET last_album_ym = 'Новый ' || now()::text,
       last_album_processed = ''
   WHERE id = (SELECT id FROM tbl_authors WHERE watched = true LIMIT 1);
   ```
4. Подождать один polling tick (≤ 20 сек).
5. **Ожидается**: бейдж обновился до нового числа без действий пользователя.

**Чек-лист проверки**:
- [ ] В Network видны запросы каждые ~20 сек.
- [ ] Бейдж обновился в течение ≤ 20 сек после изменения БД.

## Сценарий 4 — Resilience к ошибкам сети/БД (FR-010)

**Цель**: При падении запроса за счётчиком предыдущее значение бейджа сохраняется.

**Шаги**:
1. Открыть админку, дождаться появления бейджа с числом N > 0.
2. В DevTools → Network → Throttling выставить «Offline» (или заблокировать `POST /api/authors/withnewalbumcount`).
3. Подождать 1-2 polling tick-а (40 сек).
4. В DevTools → Console: видны сообщения об ошибках (как у других бейджей).
5. **Ожидается**: бейдж продолжает показывать N, не сбрасывается в 0.
6. Восстановить сеть (Throttling → No throttling).
7. Подождать 1 polling tick.
8. **Ожидается**: бейдж обновился до актуального значения.

**Чек-лист проверки**:
- [ ] Бейдж не пропал и не показал `0` во время offline.
- [ ] После восстановления сети бейдж вернулся к актуальному значению.

## Сценарий 5 — Визуальная консистентность (SC-005)

**Цель**: Бейдж «Авторы» идентичен бейджам «Чат» / «Задания редактора» по стилю.

**Шаги**:
1. Создать условия для отображения всех трёх бейджей одновременно:
   - Чат: новое сообщение от пользователя сайта.
   - Задания редактора: песня в статусе SUBMITTED.
   - Авторы: ≥ 1 автор с `haveNewAlbum = true`.
2. Открыть DevTools → Elements, найти все три бейджа.
3. В DevTools → Computed сравнить стили:
   - `background-color` → `#d02c3a` у всех.
   - `border-radius` → `10px` у всех.
   - `min-width` → `18px` у всех.
   - `height` → `18px` у всех.
   - `font-size` → `11px` у всех.
   - `color` → `#fff` (или `rgb(255, 255, 255)`) у всех.

**Чек-лист проверки**:
- [ ] Все три бейджа имеют идентичные визуальные параметры.

## Сценарий 6 — Отсутствие утечек таймеров (SC-006)

**Цель**: Проверить, что `setInterval` корректно очищается при размонтировании (нет накопления таймеров при HMR).

**Шаги**:
1. Открыть админку.
2. В DevTools → Performance Monitor (или Sources → Snippets):
   ```js
   setInterval(() => {}, 1000);  // пример создания таймера
   // Проверить window.setInterval.toString() — оригинал или обёртка
   ```
3. Несколько раз перезагрузить админку (F5) — 5-10 раз.
4. Открыть Chrome DevTools → Memory → Performance: таймеры не должны накапливаться (в норме — ровно 1 `loadAuthorsWithNewAlbumCount` polling таймер на вкладку).
5. Закрыть вкладку. **Ожидается**: `beforeUnmount` сработал, таймер очищен (нет warning в Console).

**Чек-лист проверки**:
- [ ] Нет накопления polling-таймеров при многократных перезагрузках.
- [ ] Нет ошибок «memory leak» / «setInterval still running» в Console при закрытии вкладки.

## Сценарий 7 — Сайдбар не ломается (SC-007)

**Цель**: При большом числе (3+ цифры) бейдж не ломает верстку сайдбара.

**Шаги**:
1. Создать большое число авторов с `haveNewAlbum = true` (например, 250):
   ```sql
   UPDATE tbl_authors
   SET watched = true,
       last_album_ym = 'Тест 2026',
       last_album_processed = ''
   WHERE id <= 250;
   ```
2. Открыть админку.
3. **Ожидается**: бейдж показывает «250», пункт «Авторы» остаётся в одну строку, без переноса.
4. Сравнить с пунктами «Чат» / «Задания редактора» — те тоже не должны ломаться.

**Чек-лист проверки**:
- [ ] Сайдбар не «прыгает», пункт «Авторы» в одну строку.
- [ ] Высота строки такая же, как у соседних пунктов без бейджа.

2. Открыть админку.
3. Должен появиться бейдж «5».
4. Кликнуть на пункт «Авторы» — открывается список.
5. В фильтре AuthorsFilterModal выбрать «Новый альбом» = «Да».
6. В списке — ровно 5 авторов (или больше, если в БД есть ещё).
7. Закрыть вкладку, вернуться в БД, проставить всем `last_album_processed = last_album_ym` — «обработали».
8. Вернуться в админку, F5. Бейдж скрыт.

Если все 7 сценариев + smoke прошли — фича работает.
