## Phase 3: User Story 1 - Прод недоступен с админ-машины после смены адреса (Priority: P1) 🎯 MVP

**Цель**: система сама обнаруживает, что прод-канал закрыт из-за адреса, определяет текущий
внешний адрес, добавляет его в allow-list и подтверждает восстановление доступа.

**Критерий независимой проверки**: подменить адрес в тестовой среде (посторонний адрес в
allow-list отсутствует) → дождаться срабатывания детектора → адрес добавлен, проверка синтаксиса
прошла, контрольная проверка доступа успешна, запись появилась в журнале.

## Implementation Strategy

### MVP First (User Story 1 Only)

T001–T021 дают работающий детектор с самовосстановлением доступа и изолированный тест
сценария «адрес сменился». Без US2/US3/US4 правка не безопасна для прода, поэтому **перед первым
применением на проде обязательны US3** (T028–T034), а перед merges — US2 и US4.

### Delivery Order

1. **MVP (US1 + Foundational)** — T001–T021: обнаружение, определение адреса, правка, контроль,
   self-test.
2. **Безопасность (US3)** — T028–T034: diff-проверка, откат, частота, self-test отката.
3. **Наблюдаемость (US2)** — T022–T027: журнал и уведомления.
4. **Синхронизация канона (US4)** — T035–T040: PR через API.
5. **Защита и знания (Polish)** — T041–T056: guard, ADR, per-feature, runbook, реестры, отчёт.

### Notes по рискам реализации

- **FR-019** (access-журнал stream-блоков) — **вне объёма**: включение `access_log` в
  stream-блоках меняет прод и требует согласия владельца; задач по нему нет намеренно.
- **FR-011** (адреса из allow-list не удаляются) — соблюдается конструктивно: скрипт умеет
  только вставлять строку, механизма удаления в нём нет; список хранит все адреса, включая
  четыре последних (требование «не менее четырёх последних адресов»).
- **FR-015** (не менять ничего, кроме файла allow-list и его бэкапа) — временный файл на проде
  создаётся на время операции и убирается в любом случае, включая аварийный выход.

- **Прод не трогать на этапе разработки**: все проверки — на self-test и `--diagnose`
  (только чтение с прода).
- **Токены — только из окружения**, никогда в argv и никогда в репозиторий.
- **Рабочее дерево `/home/nsa/Karaoke` не используется автоматизацией** — PR собирается через
  Forgejo API (FR-014, R12).
- **Коммит — только по слову владельца**: до разрешения все артефакты живут в рабочем дереве.
