Инструмент разовый, терпит, но лимита нет.
4. **Хрупкость `manifest.py` к типам.** `load_manifest` перехватывает только `(json.JSONDecodeError, KeyError, TypeError)` (manifest.py:64) и не проверяет типы `timeMs`/`durationMs`: нечисловой `timeMs` дойдёт до `chunking.py` (`times_ms[idx] - times_ms[...]`) и уронит многочасовой прогон необработанным `TypeError`. Манифест пишет karaoke-app (`Long`), поэтому путь требует посторонней правки файла — скорее сверка, чем дефект.
5. **Имя временного файла в `serve.py` берётся из клиента.** `suffix = Path(file.filename or "audio").suffix or ".flac"` (serve.py:68) — суффикс попадает в имя `NamedTemporaryFile`. Проверено: `PurePath.suffix` не может содержать разделителя пути (компонент имени уже разобран), поэтому обхода каталога/инъекции в имя файла нет; фиксирую, чтобы вопрос не переоткрывался.
6. **Периметр `alignmentServiceUrl` — LAN без аутентификации.** Сервис `serve.py` не имеет ни авторизации, ни rate-limit; `alignmentServiceUrl` задаётся в свойствах админки и по умолчанию указывает на `http://<admin-host>:8017/align`. Если этот адрес когда-либо окажется достижим из публичной сети (а `karaoke-app` в `SecurityConfig.kt:42–45` аутентифицирует только `/api/private/**`, то есть `/api/songeditor/edit/forcedAlignMarkers` открыт для любого, кто видит `:8898`), P-69-01 и P-69-02 поднимаются до S1. Вопрос владельцу: изоляция админской машины по сети — принятая граница доверия (ADR-0004) или нужен shared-secret/IP-allowlist на стороне `serve.py`?
7. **Одновременное удержание двух моделей в памяти.** `_model_cache` (align.py:66) намеренно держит baseline **и** дообученную модель одновременно (докстринг 60–65), а `serve.py` может переключаться на каждом запросе; при `ALIGN_MODEL_PATH` это 2×~1.2 ГБ весов в одном процессе. Документировано как замысел, но при ограниченной RAM админской машины (модель занимает и VRAM) риск OOM не оценён — вопрос к владельцу: нужен ли выгрузка неиспользуемой модели.
8. **Отсутствие retry-политики у клиента.** `AlignmentServiceClient.align` при любой ошибке возвращает `null` (AlignmentServiceClient.kt:79–81) → контроллер отдаёт «alignment_service_unavailable» (`SongEditorController.kt:1027`) без повторов. Это уже зафиксировано в `knowledge/domains/integration/components/alignment-ml.md` § «Known gaps» («Что делать при ошибке align — retry policy»), поэтому отдельной записи не завожу; отмечено для полноты картины по порции.
