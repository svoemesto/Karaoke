# Feature Specification: Улучшение блоков «Текст пользователя», «Разметка» и «Маркеры» в модалке проверки задания

**Feature Branch**: `263-editor-task-review-modal`
**Created**: 2026-08-30
**Status**: Draft
**Input**: User description: "Админка webvue3, компонент «Задания редактора», модалка проверки задания. Блок «Текст пользователя» — выравнивание текста по левому краю. Рядом с блоком «Текст пользователя» добавить блок «Разметка» в который выводить текст в такой же формате, как он выводится в онлайн-редакторе. Для обоих текстовых блоков добавить размер шрифта так же, как в онлайн-редакторе. Блок «Маркеры» сделать одной строкой."

## Контекст

В админке `webvue3` в разделе «Задания редактора» (компонент `SongEditorTable.vue`) для ревью каждого задания открывается модалка `ReviewModal.vue` (см. `webvue3/src/components/SongEditor/ReviewModal.vue:1`). Текущая модалка содержит три информационных блока в сетке `.se-cols`:

1. **«Текст пользователя»** (`.se-text`, `ReviewModal.vue:73`) — голый `<pre>` с текстом из `draftSourceTexts[currentVoiceIdx]`. Без выравнивания (использует дефолт `<pre>` — обычно left, но это не зафиксировано стилем), без явного размера шрифта под редактор (сейчас 0.82rem — произвольно выбрано).
2. **«Маркеры: N»** (`.se-marker-summary`, `ReviewModal.vue:76-83`) — четыре строки-счётчика (Слоги / Концы строк / Новые строки / END), расположенные вертикальным flex-списком.
3. **Отсутствует блок «Разметка»** — то, что админ видит в онлайн-редакторе (`SongKaraokeEditorView.vue:281-319`) в правой колонке: HTML-представление текста с подсветкой текущего слога и цветовым кодированием групп голоса (`GROUP|0..3`), сгенерированное функцией `formatText(markers, curMarkerIndex)` из `karaoke-public/src/composables/useKaraokeEditor.js:447`.

Онлайн-редактор разметки (в karaoke-public и в admin-режиме `SongKaraokeEditorModal`) уже задаёт **стандартный формат отображения** для текста и разметки:

| Блок | Шрифт по умолчанию | Источник |
|------|-------------------|----------|
| «Текст песни» (`<textarea>`) | `textFontSize = 16px` (настраивается слайдером 6–36) | `useKaraokeEditor.js:29` + `SongKaraokeEditorView.vue:287` |
| «Разметка» (`<div class="ske-preview">` с `v-html`) | `previewFontSize = 18px` (настраивается слайдером 6–36) | `useKaraokeEditor.js:30` + `SongKaraokeEditorView.vue:310` |

CSS разметки (цвет групп, текущий слог, комментарии) определён в `.ske-preview :deep(.ske-fx-…)` блоках (`SongKaraokeEditorView.vue:1850-1872`). Аналогичный набор для karaoke-public — `.ke-preview :deep(.ke-fx-…)` (`EditorWorkView.vue:1861-1888`). Поскольку `formatText` генерирует HTML с классами **`ke-fx-*`** (хардкод в `useKaraokeEditor.js:448-454`), а стили в webvue3 определены для `ske-fx-*`, в admin-редакторе (`SongKaraokeEditorView`) цвета групп на самом деле не подсвечиваются — это известная деталь реализации. По решению пользователя от 2026-08-30 для блока «Разметка» в `ReviewModal` применяется та же палитра, что в karaoke-public (`.ke-fx-*` на чёрном фоне) — без переименования классов и без адаптации под светлый фон. Внутри `.se-markup` будет чёрный фон `#000`, что визуально отделит «Разметку» от остальной светлой модалки и обеспечит пиксель-в-пиксель идентичность с правой колонкой онлайн-редактора в `EditorWorkView.vue`. Размер шрифта — `previewFontSize` (18px по умолчанию, настраивается в редакторе).

Цель — привести модалку ревью к тому же визуальному стандарту, что и онлайн-редактор, чтобы админу не приходилось переключаться между двумя представлениями текста и разметки при оценке работы редактора.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Текст пользователя выравнивается по левому краю (Priority: P1)

Администратор открывает задание в `ReviewModal`. Блок «Текст пользователя» отображается с явным выравниванием по левому краю (`text-align: left`), независимо от того, в каком контексте модалка открыта (light/dark theme, на разных контейнерах, при разной ширине окна).

**Why this priority**: Это базовое визуальное требование, без которого текст в текущей реализации может «прыгать» (поскольку `<pre>` в Bootstrap-окружении иногда наследует `text-align: center` от родительских flex/grid-контейнеров). Это самое простое из изменений, формирует основу для US2.

**Independent Test**: Открыть задание с длинным текстом — текст прижат к левому краю контейнера `.se-text`. Поменять ширину модалки (ресайз окна) — выравнивание не меняется.

**Acceptance Scenarios**:
1. **Given** админ открывает задание с непустым `currentSourceText`; **When** модалка отрисовалась; **Then** текст в `.se-text` выровнен по левому краю (`text-align: left` вычисленно через `getComputedStyle`).
2. **Given** текст содержит смешанные кириллицу/латиниць/переводы строк; **When** админ просматривает блок; **Then** строки идут друг под другом без сдвига вправо.
3. **Given** `currentSourceText` пуст; **When** блок отображается; **Then** показан плейсхолдер `(пусто)` также по левому краю.

### User Story 2 — Добавлен блок «Разметка» в формате онлайн-редактора (Priority: P1)

Рядом с блоком «Текст пользователя» (в той же сетке `.se-cols`, либо в новой трёхколоночной сетке) появляется блок с заголовком «Разметка», в котором текст отображается в **том же формате, что и в правой колонке онлайн-редактора**: HTML с подсветкой групп голоса (GROUP|0..3), текущего слога и комментариев (COMMENT|…), сгенерированный той же функцией `formatText(markers, curMarkerIndex)` из `useKaraokeEditor.js`.

**Why this priority**: Это основная бизнес-ценность фичи — дать админу визуальное представление разметки прямо в модалке ревью, без необходимости открывать полный редактор (`SongKaraokeEditorModal`) только чтобы посмотреть, что наразмечал редактор.

**Independent Test**: Открыть задание с разметкой (`parsedMarkers.length > 0`) — в модалке виден блок «Разметка» с цветными группами голосов на чёрном фоне. Сравнить визуально с правой колонкой `EditorWorkView.vue` (karaoke-public) — порядок строк, цветовая схема и текущий слог совпадают пиксель-в-пиксель (одна и та же палитра `.ke-fx-*`). Сравнение с `SongKaraokeEditorView.vue` (webvue3 admin-редактор) ожидаемо покажет **отличия** в цветах групп, т.к. там определены `ske-fx-*` стили, которые НЕ совпадают с `ke-fx-*` (известная деталь, см. контекст выше).

**Acceptance Scenarios**:
1. **Given** задание с непустым `parsedMarkers` (`markerCount > 0`); **When** админ открывает модалку; **Then** блок «Разметка» содержит отрендеренный HTML: слоги разделены пробелами, переводы строки — через `<br>`, группы — цветные `<span class="ke-fx-groupN">` (`GROUP|0` — белый, `GROUP|1` — жёлтый italic, `GROUP|2` — голубой, `GROUP|3` — зелёный italic, согласно палитре karaoke-public на чёрном фоне).
2. **Given** в `parsedMarkers` есть маркер с `markertype === 'setting'` и `label === 'COMMENT|…'`; **When** блок отрисован; **Then** комментарий виден курсивом, отделён `<br>` от следующей строки текста.
3. **Given** `parsedMarkers` пуст (`markerCount === 0`); **When** админ открывает модалку; **Then** блок «Разметка» показывает плейсхолдер `(пусто)`.
4. **Given** у задания `voiceCount > 1`; **When** админ переключает голос (`.se-voice-tabs`); **Then** блок «Разметка» обновляется для нового голоса (reactive computed `parsedMarkupHtml` пересчитывается при `currentVoiceIdx`).
5. **Given** блок «Разметка» отрисован; **When** админ сравнивает его с тем же заданием, открытым в `SongKaraokeEditorModal` или `EditorWorkView.vue` (karaoke-public); **Then** количество `<br>` совпадает; порядок span-ов с текстом слогов совпадает; цвета групп слогов идентичны (та же палитра `.ke-fx-*` на чёрном фоне, тот же CSS класс `ke-fx-group0..3`); единственное допустимое отличие — размер шрифта (настраивается отдельно, по умолчанию 18px).

### User Story 3 — Размер шрифта в обоих текстовых блоках как в онлайн-редакторе (Priority: P1)

Размер шрифта в блоках «Текст пользователя» и «Разметка» соответствует размеру шрифта, заданному в онлайн-редакторе для соответствующих блоков:

- **«Текст пользователя»** → `textFontSize` (по умолчанию 16px, диапазон 6–36px).
- **«Разметка»** → `previewFontSize` (по умолчанию 18px, диапазон 6–36px).

Значения по умолчанию берутся из `EDITOR_DEFAULTS` (`useKaraokeEditor.js:28-36`) и применяются, если админ не менял настройки редактора в localStorage. Текущий размер шрифта фиксируется как дефолт в `ReviewModal` (без слайдера в самой модалке — `textFontSize`/`previewFontSize` настраиваются только в редакторе; см. Out of Scope).

**Why this priority**: Соответствие размеров шрифта — половина задачи «как в онлайн-редакторе». Без этого разница в `font-size: 0.82rem` (текущее) и `16px` (онлайн-редактор) делает визуальное сравнение в голове у админа бессмысленным.

**Independent Test**: Открыть одно и то же задание в `ReviewModal` и в `SongKaraokeEditorModal`. `getComputedStyle('.se-text').fontSize` в модалке ревью равен `getComputedStyle('.ske-textarea').fontSize` в редакторе (или его инхериту, если textarea наследует от родителя). Аналогично для блока «Разметка».

**Acceptance Scenarios**:
1. **Given** у админа в localStorage нет кастомных настроек редактора (или они = дефолт); **When** он открывает модалку ревью; **Then** `.se-text` имеет `font-size: 16px`, а блок «Разметка» — `font-size: 18px`.
2. **Given** у админа в localStorage `karaoke-editor-settings.textFontSize = 24`; **When** он открывает модалку; **Then** `.se-text` имеет `font-size: 24px`.
3. **Given** `previewFontSize` в localStorage = 30; **When** модалка открыта; **Then** блок «Разметка» имеет `font-size: 30px`.
4. **Given** значения выходят за допустимый диапазон (например, `textFontSize: 100` — повреждённый localStorage); **When** `loadEditorSettings()` отрабатывает; **Then** clamp в `loadEditorSettings` (`useKaraokeEditor.js:43`) ограничивает значение до `[6, 36]`, и `font-size` в модалке не превышает `36px`.

### User Story 4 — Блок «Маркеры» в одну строку (Priority: P1)

Блок «Маркеры» (`se-marker-summary`) вместо вертикального flex-списка из четырёх строк отображается в одну строку. Счётчики «Слоги», «Концы строк», «Новые строки», «END: есть/нет» идут друг за другом горизонтально через разделитель (например, ` · ` или `|`), при необходимости переносятся на следующую строку при нехватке места (`flex-wrap: wrap`).

**Why this priority**: В текущей реализации блок «Маркеры» занимает ~4 строки по высоте и «раздувает» модалку. С однострочным вариантом вся сетка `.se-cols` (3 колонки: Текст / Разметка / Маркеры) помещается компактно, и админу нужно меньше скроллить. Это чисто визуальное требование, самое маленькое из четырёх, но формально явно запрошено.

**Independent Test**: Открыть модалку с `markerCount > 0` — блок «Маркеры» занимает ровно одну строку при ширине окна ≥768px. При ширине <500px — допускается перенос на 2 строки (`flex-wrap: wrap`).

**Acceptance Scenarios**:
1. **Given** модалка открыта на десктопе (ширина ≥768px); **When** админ смотрит на блок «Маркеры»; **Then** четыре счётчика идут в одну строку, разделённые ` · ` (или вертикальной чертой `|`).
2. **Given** модалка открыта на узком экране (ширина <500px); **When** счётчики не помещаются; **Then** они переносятся (`flex-wrap: wrap`), но заголовок «Маркеры: N» остаётся на своей строке.
3. **Given** в `parsedMarkers` есть END-маркер; **When** блок отрисован; **Then** счётчик `END` показывает `есть`; если END нет — `нет`. Это поведение сохраняется без изменений (логика `markerStats` не меняется).
4. **Given** `parsedMarkers` пуст; **When** блок отрисован; **Then** счётчики показывают `0 / 0 / 0 / нет` (как сейчас), но в одну строку.

### Edge Cases

- **Что если `parsedMarkers` пуст и `currentSourceText` тоже пуст?** Default: оба блока показывают плейсхолдер `(пусто)`. Никаких ошибок, layout не ломается.
- **Что если в `parsedMarkers` есть маркеры `markertype === 'endofsyllable'` (тип есть в `MARKER_COLOR_*`, но не в `formatText`)?** Default: `formatText` их просто игнорирует (не имеет case в switch — `useKaraokeEditor.js:460-489`). В блоке «Разметка» они будут невидимы (как и в самом редакторе). Это совпадает с поведением онлайн-редактора и не требует доработки.
- **Что если в `parsedMarkers` есть маркер `markertype === 'setting'` с `label` отличным от `GROUP|0..3` и не начинающимся с `COMMENT|`?** Default: `formatText` его игнорирует (case `'setting'` имеет только две ветки). Это совпадает с поведением онлайн-редактора.
- **Что если `voiceCount > 1` и пользователь переключает голос?** Default: computed `currentSourceText`, `parsedMarkers` и `parsedMarkupHtml` реактивно пересчитываются на новый `currentVoiceIdx`. Все три блока обновляются синхронно (это уже работает для двух из них).
- **Что если localStorage недоступен (приватный режим / квота)?** Default: `loadEditorSettings()` тихо возвращает дефолты (`useKaraokeEditor.js:53-56`). В модалке применяются `16px / 18px` — без падений.
- **Что если `formatText` импортируется в webvue3 (а не в karaoke-public)?** Default: `formatText` определён в `karaoke-public/src/composables/useKaraokeEditor.js:447`. Для использования в `webvue3` нужно скопировать/переиспользовать функцию (например, через общий пакет или прямой импорт из `karaoke-public/src/composables/useKaraokeEditor.js` — это уже работает в `SongKaraokeEditorView.vue:335`). Существующая зависимость не нарушается.
- **Что если пользователь задал font-size > 36px через повреждённый localStorage?** Default: clamp в `loadEditorSettings` (`useKaraokeEditor.js:43`) ограничивает `[6, 36]`. Лишние значения игнорируются.
- **Что если палитра `ke-fx-*` (белое/жёлтое/голубое/зелёное на чёрном фоне) выбивается из светлого дизайна модалки?** Default: НЕ выбивается — это согласованное решение пользователя (см. Clarifications, Q1 → 2026-08-30). Чёрный фон `.se-markup` визуально отделяет «Разметку» от остальных блоков модалки как «плеер-зона» (по аналогии с iframe-плеером, который тоже имеет чёрный фон, см. `.se-player-wrap` в `ReviewModal.vue:465-470`). Это упрощает реализацию (никаких адаптаций CSS, прямое переиспользование `.ke-preview`-стилей из `EditorWorkView.vue:1845-1888`) и обеспечивает визуальную идентичность с онлайн-редактором.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В `webvue3/src/components/SongEditor/ReviewModal.vue` блок «Текст пользователя» (`.se-text`) MUST иметь явный `text-align: left` (выравнивание по левому краю), зафиксированный в стилях компонента. Текущее поведение (наследуемое от `<pre>` и родителя) MUST быть заменено на явное правило.
- **FR-002**: В `ReviewModal.vue` MUST быть добавлен новый блок `<div class="se-col se-col-markup">` с заголовком «Разметка» рядом с блоком «Текст пользователя» в сетке `.se-cols`. Контент блока — HTML, сгенерированный функцией `formatText(markers, curMarkerIndex)` из `karaoke-public/src/composables/useKaraokeEditor.js` (уже используется в `SongKaraokeEditorView.vue:515`), обёрнутый в `<div class="se-markup" v-html="parsedMarkupHtml">`.
- **FR-003**: В `ReviewModal.vue` MUST быть добавлен computed `parsedMarkupHtml`, возвращающий `formatText(this.parsedMarkers, this.curMarkerIndexInMarkup)`. По умолчанию `curMarkerIndexInMarkup === -1` (никакой слог не подсвечивается как «текущий», т.к. в модалке ревью плеер не запущен — это отличается от онлайн-редактора, где `curMarkerIndex` динамически зависит от `currentTime`).
- **FR-004**: В `ReviewModal.vue` блок `.se-text` MUST использовать `font-size`, равный `textFontSize` из `EDITOR_DEFAULTS` (по умолчанию 16px, диапазон 6–36px). Значение берётся через `loadEditorSettings()` (`useKaraokeEditor.js:38`) на этапе `mounted()` (однократно при открытии модалки) и хранится в `data().textFontSize` / `data().previewFontSize`. **Без live-watcher'а на localStorage** — смена настройки в редакторе не подхватывается в открытой модалке (достаточно переоткрыть).
- **FR-005**: В `ReviewModal.vue` блок «Разметка» (`.se-markup`) MUST использовать `font-size`, равный `previewFontSize` из `EDITOR_DEFAULTS` (по умолчанию 18px, диапазон 6–36px). Загрузка и применение аналогично FR-004.
- **FR-013** (Pass 247, 2026-08-30): В `ReviewModal.vue` MUST быть добавлены два слайдера (`<input type="range" min="6" max="36" step="1">`) с `v-model.number` на `textFontSize` / `previewFontSize` — по одному рядом с блоками «Текст пользователя» и «Разметка» (аналог `SongKaraokeEditorView.vue:287-289, 309-312`). Подпись «Шрифт Npx» показывает текущее значение. Watcher'ы `textFontSize(v)` и `previewFontSize(v)` MUST вызывать `saveEditorSettings({ textFontSize: v })` / `saveEditorSettings({ previewFontSize: v })` (try/catch для приватного режима / квоты). Слайдеры дают админу возможность менять шрифт прямо в модалке, без открытия редактора.
- **FR-006**: Стили блока «Разметка» в `ReviewModal.vue` MUST использовать **ту же палитру, что в karaoke-public** (`.ke-preview :deep(.ke-fx-…)` из `EditorWorkView.vue:1861-1888`): чёрный фон `#000`, белый/жёлтый/голубой/зелёный цвета групп слогов, красный жирный для текущего слога (не используется в модалке — см. FR-003), охра-курсив для `COMMENT|…`. Классы внутри HTML — `ke-fx-cur`, `ke-fx-group0..3`, `ke-fx-comment` (без переименования в `se-fx-*`), поскольку `formatText` уже генерирует именно их. Никаких новых CSS-правил для этих классов в `ReviewModal.vue` НЕ требуется — стили наследуются глобально, либо (при `:scoped`) определяются через `:deep(.ke-fx-…)`.
- **FR-007**: В `ReviewModal.vue` блок «Маркеры» (`.se-marker-summary`) MUST быть переформатирован из вертикального flex-списка в горизонтальную компоновку (`flex-direction: row; flex-wrap: wrap;`), счётчики разделяются ` · `. Приватный режим / квота — без падений (дефолты применяются автоматически внутри `loadEditorSettings`).
- **FR-011**: Существующая логика блока «Маркеры» (computed `markerStats`, метод `statusLabel`) НЕ изменяется — переформатируется ТОЛЬКО CSS-разметка (`.se-marker-summary`), не computed.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: При открытии модалки ревью с дефолтным localStorage `getComputedStyle('.se-text').fontSize === '16px'` и `getComputedStyle('.se-markup').fontSize === '18px'` (или эквивалент через DOM-замер). При кастомных значениях `textFontSize=24` / `previewFontSize=30` в localStorage — `getComputedStyle` возвращает `'24px'` и `'30px'` соответственно.
- **SC-002**: Визуально блок «Разметка» в `ReviewModal` идентичен правой колонке `EditorWorkView.vue` в karaoke-public (та же палитра, тот же чёрный фон, те же CSS-классы `ke-fx-*`). Контраст текст/фон ≥ WCAG AA для всех 4 групп + текущий слог + комментарий (поскольку палитра уже валидирована в karaoke-public, дополнительная проверка не требуется — достаточно визуальной сверки при code review).
- **SC-003**: При `voiceCount > 1` переключение голоса через `.se-voice-tabs` обновляет блок «Разметка» за <50мс (один синхронный tick реактивности Vue, без дополнительных запросов к бэкенду).
- **SC-004**: При ширине окна 1280px три блока (Текст / Разметка / Маркеры) помещаются в одну строку; при ширине 800px — Текст + Разметка в одной строке, Маркеры внизу; при ширине 500px — все три блока вертикально.
- **SC-005**: Блок «Маркеры» занимает ОДНУ строку при ширине модалки ≥768px (визуальная проверка: `getBoundingClientRect().height` счётчиков < 1.5× высоты одной строки текста).
- **SC-006**: В блоке «Разметка» для задания с `parsedMarkers.length > 0` присутствуют как минимум: (а) `<span class="ke-fx-groupN">` с текстом слога, (б) `<br>` для перевода строки между `endofline`/`newline`-маркерами, (в) `<span class="ke-fx-comment">` для каждого `COMMENT|…` маркера. Количество `<br>` совпадает с количеством `endofline + newline` маркеров в `parsedMarkers` (плюс один завершающий, если есть `COMMENT|…` после слога — соответствует поведению `formatText`).
- **SC-007**: Изменение шрифта в редакторе (`SongKaraokeEditorView`, слайдер «Шрифт 16px») сохраняется в localStorage и при следующем открытии модалки ревью блок «Текст пользователя» отображается тем же размером (проверка через open editor → change slider → close → open ReviewModal → font-size совпадает).

Если админ хочет изменить размер — он открывает редактор, меняет там, закрывает, возвращается в модалку.
