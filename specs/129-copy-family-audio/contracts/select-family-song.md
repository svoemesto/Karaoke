# Контракт выбора похожей версии песни

**Feature**: `129-copy-family-audio`
**Основной интерфейс**: `POST /api/song/selectfamilysong`

## Назначение

Контракт применяет выбранную строку из «Похожие версии песни» к текущей песне. Он сохраняет существующее копирование family-данных и добавляет согласованный набор аудиополей.

## UI event contract

Компонент `FamilySongsModal` emits event `select` только для строки, у которой `current === false`.

```text
select({
  id: Long,
  deltaMs: Long | null,
  audioSimilarityPercent: Int | null
})
```

Правила формирования:

| Состояние `compareResults[id]` | `deltaMs` | `audioSimilarityPercent` |
|---|---:|---:|
| `status === 'done'` | результат сверки, включая 0 и отрицательные значения | результат сверки, включая 0 |
| `idle`, `loading`, `error` или отсутствует | `null` | `null` |
| `song.current === true` | событие не emit-ится | событие не emit-ится |

`audioSimilarityPercent` нельзя проверять через truthiness: `0` при `status === 'done'` является валидным результатом.

## HTTP request

Формат: существующий `application/x-www-form-urlencoded` запрос через `promisedXMLHttpRequest`.

Обязательные параметры:

| Параметр | Тип | Описание |
|---|---:|---|
| `id` | Long | ID текущей песни из состояния редактора |
| `idAnother` | Long | ID выбранной строки-кандидата |

Опциональные параметры:

| Параметр | Тип | Когда передаётся |
|---|---:|---|
| `deltaMs` | Long | Только при `status === 'done'`; используется для сдвига маркеров и `audioDeltaMs` |
| `audioSimilarityPercent` | Int | Только при `status === 'done'`; значение 0 передаётся явно |

### Смысл комбинаций параметров

| `deltaMs` | `audioSimilarityPercent` | Результат |
|---|---|---|
| отсутствует | отсутствует | Выбор без сверки; сохраняется `audioParentId=idAnother`, метрики `0/0` |
| присутствует | присутствует | Сохраняются переданные процент и signed-сдвиг |
| присутствует | отсутствует | Невалидная частичная пара; запрос отклоняется без изменения песни |
| отсутствует | присутствует | Невалидная частичная пара; запрос отклоняется без изменения песни |

Сервер всегда вычисляет `audioParentId` из загруженного кандидата `idAnother`; отдельный клиентский параметр для него запрещён.

## HTTP response: success

Статус: успешный ответ существующего endpoint.

```json
{
  "rootId": 123,
  "idStatus": 1,
  "audioParentId": 456,
  "audioSimilarityPercent": 93,
  "audioDeltaMs": 120
}
```

Поля `audioParentId`, `audioSimilarityPercent` и `audioDeltaMs` — значения после нормализации и сохранения, а не эхо неподтверждённого запроса.

Существующие поля ответа:

- `rootId` — фактически установленный `rootId` кандидата или его обычного корня;
- `idStatus` — текущий статус после действующего условного правила `0 → 1`.

## HTTP response: validation/error

При следующих условиях сервер не должен применять выбор:

- `id == idAnother`;
- текущая песня или кандидат не найдены;
- процент вне диапазона `0..100`;
- передана только одна метрика из пары `deltaMs`/`audioSimilarityPercent`;
- после сохранения перечитывание не подтверждает ожидаемые три аудиополя.

Для такой ситуации клиент получает rejected HTTP response без success DTO. Frontend оставляет модалку открытой, не обновляет текущие аудиополя частично и показывает toast с возможностью повторить выбор.

До записи сервер валидирует входные данные. Все изменения одного успешного выбора выполняются до одного `Song.saveToDb()`; после него сервер проверяет сохранённые аудиозначения.

## Обратная совместимость

- Запрос без двух новых аудиометрик остаётся допустимым и означает ручной выбор без сверки (`0/0`).
- `autoAssignOriginalByWaveform` не вызывает этот HTTP endpoint и не получает новых аудиополей: его вызов `applyFamilySongSelection` сохраняет прежнее поведение.
- `SongDTO`, `SongDTOdigest`, `/api/song/update` и `/api/song/findaudioparent` не меняют формат.

## Frontend application contract

После успешного ответа `SongEdit`:

1. устанавливает `rootId` и `idStatus` из ответа;
2. устанавливает все три аудиополя из ответа одновременно;
3. синхронизирует snapshot этих полей как сохранённых;
4. закрывает модалку и сбрасывает состояние in-flight.

При ошибке:

1. не присваивает новые значения текущей песне;
2. не синхронизирует snapshot;
3. оставляет модалку открытой;
4. показывает понятное сообщение и разрешает повторный выбор.

## Инварианты контракта

- Три аудиополя всегда описывают одну выбранную строку.
- Signed `audioDeltaMs` не инвертируется и не преобразуется через `abs`.
- Нулевой результат успешной сверки передаётся и сохраняется как значение, а не отбрасывается.
- Выбор текущей строки не изменяет ни один из трёх полей.
- Контракт не создаёт новую запись и не требует миграции.
