# Contract: CLI автоматизации allow-list (`deploy/admin-ip-allowlist.sh`)

> Phase 1 output. Контракт внешнего интерфейса скрипта: режимы, флаги, коды возврата,
> переменные окружения. Реализация обязана соответствовать этому описанию.

## 1. Назначение

Скрипт выполняет один цикл самовосстановления: определяет, доступен ли прод-канал с
админ-машины, и — если недоступность вызвана allow-list — добавляет текущий внешний адрес
в allow-list на прод-хосте (FR-001…FR-020).

## 2. Режимы

| Режим | Флаг | Поведение | Прод трогается |
|---|---|---|---|
| Основной | (по умолчанию) | Полный цикл: пробы → решение → правка (если нужна) → журнал → уведомление → PR | Да, только при выполнении правки |
| Диагностика | `--diagnose` | Печатает состояние: результаты проб, текущий внешний адрес, текущий allow-list на прод-хосте, план изменения. **Ничего не меняет** (FR-017) | Только чтение |
| Самопроверка | `--self-test` | Изолированный сценарий без обращения к прод-хосту: подстановка постороннего адреса → добавление → проверка синтаксиса → откат при ошибке (FR-018) | Нет |
| Справка | `--help` | usage, список переменных окружения, коды возврата | Нет |

## 3. Коды возврата

| Код | Значение |
|---|---|
| 0 | Цикл завершён штатно: правка не требовалась, либо применена и подтверждена контрольной проверкой, либо отказ по правилам (см. журнал) |
| 1 | Ошибка применения: синтаксис не прошёл, контроль не прошёл (выполнен откат), прод недоступен по ssh, файлы недоступны |
| 2 | Ошибка использования (неизвестный флаг, отсутствующая обязательная переменная окружения) |
| 3 | Отказ по правилам: прод недоступен целиком (FR-002), источники адреса недоступны или расходятся, адрес невалиден, частота превышена |

Код 3 — не ошибка, а штатное решение «не вмешиваться»; в журнале фиксируется причина.

| Переменная | По умолчанию | Назначение |

| `ALLOWLIST_PROD_PORTS` | `5433 9000` | Прод-каналы, проверяемые по TCP |

| `ALLOWLIST_IP_TIMEOUT` | `8` | Таймаут запроса к источнику, с |
| `ALLOWLIST_PROBE_TIMEOUT` | `5` | Таймаут TCP-пробы, с |

попадают в argv (токен Telegram — через `curl -K` с конфиг-файлом `600`) и не попадают в
журнал (FR-016).

## 5. Поведение по шагам (основной режим)

1. **Пробы** (FR-001): TCP `5433`, TCP `9000`, HTTPS `health` (код 2xx).
2. **Решение о причине** (FR-002): HTTPS недоступен → код 3, уведомление, прод не трогаем.
   HTTPS доступен, каналы недоступны → причина в allow-list, продолжаем.
3. **Определение адреса** (FR-003): источники по очереди; расхождение ответов → код 3.
4. **Валидация адреса** (FR-004): невалиден → код 3.
5. **Проверка присутствия** (FR-005): адрес уже в allow-list → действий нет (код 0), запись
   в журнал «правок не требуется».
6. **Ограничение частоты** (FR-010): с последней применённой правки прошло меньше окна →
   код 3, запись в журнал, уведомление.
7. **Правка** (FR-006…FR-009, FR-020): см. [allow-list-surgery.md](allow-list-surgery.md) —
   включая перепроверку адреса перед применением, проверку целостности записи (sha256),
   информационную сверку с репозиторной копией (дрейф фиксируется и сообщается, правку не
   блокирует) и уборку временного файла.
8. **Журнал** (FR-012) и **уведомление** (FR-013) — по каждому шагу.
9. **PR** (FR-014): только после успешного применения и успешного контроля. Содержимое PR —
   **репозиторная копия плюс только недостающая строка `allow <ip>;`**; посторонние
   расхождения прод↔репозиторий в PR не выносятся (в журнал и владельцу).

## 6. Формат вывода

Каждая строка вывода — `event:key=value` (конвенция ADR `local-0005`), события:
`probe`, `decision`, `address`, `edit`, `syntax`, `reload`, `control`, `rollback`, `notify`,
`pr`, `skip`. Те же строки пишутся в файл журнала и в journald.
