# 318 — Audit инцидентов прод-БД за последнюю неделю (LiveDoc)

> Drill-down — [specs/318-prod-db-log-audit/spec.md](../../specs/318-prod-db-log-audit/spec.md).
> Контекст задачи — OpenProject #66 «Проверка инцидентов на проде за последнюю неделю».
> Карта источников логов Karaoke — [docs/ops/log-correlation.md](../../docs/ops/log-correlation.md).

## Что делает

Аналитическая задача (не код-фича): владелец/on-call хочет понять, что
происходит в логах контейнера `karaoke-db` за последние 7×24 часа, и на
основании этого принять одно из двух решений:

- **Оставить** verbose-логирование (если оно всё ещё нужно для on-call
  или в нём видны реальные инциденты);
- **Отключить** verbose-логирование (если цель диагностики достигнута
  и/или логирование создаёт избыточную нагрузку).

Это **задача P1 по OpenProject**; результат — воспроизводимый отчёт
`specs/318-prod-db-log-audit/report.md` с категоризацией, метриками
нагрузки и явным вердиктом.

## User Stories (краткий список)

- **US1 (P1)** — Аналитический отчёт по инцидентам недели: владелец
  получает сводный отчёт с топ-10 категориями сообщений, списком
  реальных инцидентов (ERROR/FATAL/PANIC) и метриками нагрузки
  (размер лог-файла, средний/максимальный размер сообщения, объём
  за сутки). Отчёт воспроизводим (±1 %).
- **US2 (P2)** — Отключение verbose-логирования: если вердикт
  «отключать», изменение применяется штатным способом (env /
  docker-compose / SQL) **без пересборки образов** и **только по
  прямому запросу владельца** (Constitution п.2 «Деплой — только по
  согласию»).
- **US3 (P3)** — Решение «оставлять» с фиксацией порога: если вердикт
  «оставлять», в отчёте есть раздел «Критерии отключения в будущем»
  с конкретным триггером (дата / событие / метрика) и владельцем
  решения.

## Functional Requirements (указатель)

- **FR-001** — Воспроизводимый скрипт сбора логов `karaoke-db` за
  последние 7×24 часа (`data/raw.log`), SSH-доступ к прод-серверу
  `188.119.64.111` через `~/.ssh/id_rsa`.
- **FR-002** — Категоризация по regex-списку в `data/categories.json`,
  минимум 6 категорий: `pg_stat_statements`/`auto_explain`,
  `statement_timeout`/`lock_timeout`, `checkpoint`/`wal`,
  `connection`/`authentication`, `__errors__`, `__other__` (плюс
  `__unclassified__` если > 5 % сообщений не распознано).
- **FR-003** — Структура отчёта: топ-10 категорий, список инцидентов,
  метрики нагрузки, раздел «Вердикт» (`оставлять`/`отключать`),
  обоснование; если `отключать` — список конкретных настроек/файлов.
- **FR-004** — Если вердикт `отключать`: применять изменение
  **только по прямому запросу владельца**; аналитик **не запускает**
  `deploy_*.sh` и **не редактирует файлы на сервере** без подтверждения.
- **FR-005** — Контрольный замер через 24 ч после отключения:
  размер лога, число строк, доля ERROR — для подтверждения, что
  verbose-часть отключена и прод не пострадал.
- **FR-006** — Все артефакты в `specs/318-prod-db-log-audit/`,
  коммитятся в feature-ветку `318-prod-db-log-audit`.
- **FR-007** — Никаких секретов (`deploy/.env`, ключи, токены) в
  коммите; pre-commit `git ls-files | grep -iE 'env|key|pem'` пуст.

## Edge Cases

- **> 30 % сообщений уровня ERROR/FATAL** → отчёт выделяет их в раздел
  «Реальные инциденты» и рекомендует **не отключать** до разбора.
- **> 5 % сообщений не распознано** → категория `__unclassified__`
  с пометкой «ручной разбор требуется».
- **Лог < 100 МБ или < 1 000 строк** → отчёт явно говорит «данных
  недостаточно», а не делает вид, что проанализировал.
- **Контейнер `karaoke-db` недоступен** → задача **блокируется** до
  восстановления доступа; аналитик фиксирует причину и останавливается.
- **Расхождение LOCAL ↔ SERVER** (verbose-логирование включено только
  на одной стороне) → отчёт подсвечивает — возможно, на проде забыли
  отключить после локальной диагностики.

## Код

Эта задача **не вносит изменений в код Karaoke** — только в
операционную конфигурацию (env / docker-compose / SQL) контейнера
`karaoke-db` на прод-сервере (если вердикт «отключать»). Артефакты:

- Скрипт сбора логов: `specs/318-prod-db-log-audit/data/raw.log` (создаётся аналитиком).
- Конфиг категоризации: `specs/318-prod-db-log-audit/data/categories.json`.
- Структурированные данные: `specs/318-prod-db-log-audit/data/logs.jsonl`.
- Отчёт: `specs/318-prod-db-log-audit/report.md` — **главный артефакт**.
