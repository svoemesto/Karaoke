# Quickstart: проверка видимости для редактора на karaoke-public

Ручная проверка (в CI автотестов на этот путь нет — см. Constitution Check
в `plan.md`). Выполняется на локальном docker-стенде (`deploy/do.sh`).

## Предпосылки

1. Локальный стенд поднят: `karaoke-web`, `karaoke-public`, БД с данными.
2. В БД есть тестовый автор с песнями и `id_status >= 3`, и `id_status < 3`
   (например через `webvue3` временно понизить статус одной песни, или
   найти уже существующего автора в разработке).
3. Есть учётная запись сайта (`tbl_site_users`) с `is_editor = true` и её
   Bearer-токен (получить логином через `/api/public/auth/login` или
   выставить `is_editor=true` вручную в `webvue3 → SiteUsers` для тестового
   пользователя и залогиниться под ним на `karaoke-public`).

## Сценарий 1 — закрома автора (US1, FR-002/FR-004)

```bash
# без токена (как обычный посетитель) — только id_status >= 3
curl -s "http://localhost:<PORT>/api/public/zakroma?author=<AUTHOR>" | jq '.[0].albums[].albumSettings[].songName'

# с токеном редактора — все статусы
curl -s -H "Authorization: Bearer <EDITOR_TOKEN>" \
  "http://localhost:<PORT>/api/public/zakroma?author=<AUTHOR>" | jq '.[0].albums[].albumSettings[].songName'
```

**Ожидание**: второй вызов возвращает как минимум на 1+ песню больше первого
(включая ту, у которой `id_status < 3`).

Автор, у которого ВСЕ песни `id_status < 3` (для обычного посетителя вообще
не должен встретиться в `/api/public/authors-tiles`) — при явном запросе
`?author=<такой автор>` с токеном редактора MUST вернуть непустой список
альбомов; без токена — пустой список.

## Сценарий 2 — поиск (US2, FR-003)

```bash
curl -s "http://localhost:<PORT>/api/public/songs?songName=<НАЗВАНИЕ НЕГОТОВОЙ ПЕСНИ>" | jq length
# ожидание: 0

curl -s -H "Authorization: Bearer <EDITOR_TOKEN>" \
  "http://localhost:<PORT>/api/public/songs?songName=<НАЗВАНИЕ НЕГОТОВОЙ ПЕСНИ>" | jq length
# ожидание: >= 1
```

## Сценарий 3 — подпись количества песен (US3, FR-005, SC-003)

```bash
curl -s "http://localhost:<PORT>/api/public/authors-tiles?scope=all" \
  | jq '.[] | select(.author=="<AUTHOR>") | .songCount'
# ожидание: количество песен со статусом >= 3

curl -s -H "Authorization: Bearer <EDITOR_TOKEN>" \
  "http://localhost:<PORT>/api/public/authors-tiles?scope=all" \
  | jq '.[] | select(.author=="<AUTHOR>") | .songCount'
# ожидание: полное количество песен автора (>= первого значения)
```

Сверить второе число с фактическим количеством песен, полученным в Сценарии
1 (с токеном редактора) для того же автора — числа должны совпадать (SC-003).

## Сценарий 4 — регресс для не-редакторов (SC-004, FR-006)

Повторить Сценарии 1-3 под токеном обычного (не-`isEditor`) залогиненного
пользователя сайта. Ожидание: результаты идентичны анонимному запросу без
токена (числа/списки не отличаются от значений «без токена» выше).

## Сценарий 5 — в браузере (полный UI-путь)

1. Открыть `karaoke-public` в браузере, залогиниться под учётной записью
   редактора (`is_editor=true`).
2. Перейти в «Закрома», открыть автора с песнями разных статусов —
   убедиться, что видны все песни (включая недоготовые, если UI как-то их
   помечает/не ломается на отсутствующих данных плеера/текста).
3. Выполнить поиск по названию недоготовой песни — убедиться, что она
   находится.
4. Разлогиниться (или открыть те же страницы в приватном окне без токена) —
   убедиться, что недоготовые песни и авторы без готовых песен снова не
   видны.

## Не входит в проверку

- Плеер и его готовность к воспроизведению конкретной недоготовой песни —
  вне рамок этой фичи (см. Assumptions в spec.md); если UI при клике на
  недоготовую песню ведёт себя не так, как для готовой — это ожидаемо и не
  относится к этой фиче.
