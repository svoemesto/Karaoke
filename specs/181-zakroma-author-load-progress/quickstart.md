# Quickstart: 181-zakroma-author-load-progress — ручные сценарии проверки

**Branch**: `181-zakroma-author-load-progress` | **Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)

Это ручные сценарии, которые нужно выполнить **после** merge в master,
чтобы убедиться, что фича работает end-to-end. Запускаются на проде
(`https://sm-karaoke.ru/zakroma`) — **именно там**, потому что localhost
через vite proxy не воспроизводит nginx-буферизацию.

> **ВАЖНО:** сценарии проверяют **real-time прогресс через NDJSON-стрим**.
> Если на проде nginx-конфиг не обновлён (commit #4 не применён через
> `tools/deploy-nginx-stream.sh`), эти сценарии **не пройдут** — будет
> видно «зависший» спиннер без прогресса (nginx буферизует ответ).

## Предусловия

- [ ] `git checkout master` + `git pull --rebase` — все коммиты #1-#6 применены.
- [ ] Backend (`karaoke-web`) пересобран и запущен
  (`bash deploy/do.sh build_start_web` от пользователя).
- [ ] Nginx конфиг обновлён (`bash tools/deploy-nginx-stream.sh`).
- [ ] `nginx -t && systemctl reload nginx` выполнен без ошибок.
- [ ] DevTools открыт: Network tab → фильтр `Fetch/XHR` → включить
  «Preserve log» (чтобы видеть chunked-ответы).

## Сценарий 1 — real-time прогресс на большом авторе (P1)

**Цель:** убедиться, что счётчик «Получено X из N» растёт в реальном
времени по мере прихода чанков с сервера.

1. Открыть `https://sm-karaoke.ru/zakroma` в Chrome.
2. Выбрать автора с ≥ 200 песен (например, **«Агата Кристи»** —
   на главной странице Закромов обычно в топе). После выбора увидеть
   сетку тайлов, кликнуть по тайлу.
3. В DevTools Network найти запрос `/api/public/zakroma/stream?author=...`:
   - Status: 200.
   - Transfer-Encoding: chunked.
   - Content-Type: application/x-ndjson.
   - Response — несколько чанков (не один большой).
4. В UI наблюдать:
   - **Сразу после клика** (до прихода первого чанка) — `<div>` с
     надписью «Загрузка...» появляется синхронно (FR-001, ≤ 50 мс).
   - **Через ~200-500 мс** появляется «Загружаем N песен автора Агата
     Кристи… 0%» (где N — число с тайла, например «230»).
   - **По мере прихода song-сообщений** — процент и число «получено X
     из N» обновляются в реальном времени (не синтетический таймер).
   - **В конце** — UI показывает таблицу с альбомами/песнями,
     индикатор скрывается через ~300 мс.

**Ожидаемый результат:**
- SC-001 ✅: очистка в течение 50 мс.
- SC-002 ✅: TTFB первого чанка ≤ 500 мс.
- SC-005 ✅: старый `/api/public/zakroma` без `stream=true` тоже
  продолжает работать (проверить, переключившись на любого автора
  на старой версии фронта или через curl).

**Провал если:**
- Индикатор показывает статичный «Загрузка...» без чисел.
- Network показывает один большой chunked-ответ (а не несколько
  по 1-5 КБ) — значит nginx буферизует, нужен recheck
  `80to8897`.
- Приходит ошибка 500 — проверить логи karaoke-web.

## Сценарий 2 — отмена через кнопку «Отмена» (P1)

**Цель:** убедиться, что `AbortController` корректно отменяет
fetch и UI возвращается к сетке тайлов.

1. Открыть `/zakroma`, выбрать автора (например, «Митяев» — есть
   в базе, средний размер каталога).
2. Сразу после клика (когда виден прогресс, например 15%) — кликнуть
   **«Отмена»** рядом с прогрессометром.
3. В DevTools Network — статус запроса `/zakroma/stream` должен
   измениться на **`(canceled)`**.
4. В UI — сетка тайлов авторов появится снова, выбранный автор
   сброшен, прогрессометр скрыт.

**Ожидаемый результат:**
- FR-FE-006 ✅: `AbortController.abort()` отменяет fetch.
- SC-007 ✅: возврат к сетке ≤ 100 мс.

**Провал если:**
- Network показывает «200» (запрос НЕ отменён).
- UI зависает / показывает ошибку.

## Сценарий 3 — повторный клик по тому же автору в течение 30 секунд (P1)

**Цель:** убедиться, что no-op защита работает.

1. Открыть `/zakroma`, выбрать автора, дождаться полной загрузки.
2. Сразу после загрузки — кликнуть по тому же тайлу ещё раз.
3. В DevTools Network — НЕ должно быть нового запроса
   `/zakroma/stream` для этого автора.
4. В UI — состояние не меняется (таблица остаётся, прогрессометр
   не появляется).

**Ожидаемый результат:**
- FR-FE-009 ✅: no-op, если < 30 с с последней успешной загрузки.

## Сценарий 4 — force refresh через > 30 секунд (P1)

**Цель:** убедиться, что после 30 секунд повторный клик запускает
новый fetch.

1. Выполнить сценарий 1 (выбрать автора, дождаться загрузки).
2. Подождать **31 секунду** (можно просто посмотреть в DevTools
   Console на timestamp).
3. Кликнуть по тому же тайлу ещё раз.
4. В DevTools Network — новый запрос `/zakroma/stream`, прогрессометр
   появляется заново (с 0% → 100%), таблица перерисовывается.

**Ожидаемый результат:**
- FR-FE-009 ✅: force refresh, если > 30 с.

## Сценарий 5 — обработка ошибки сети (P1)

**Цель:** убедиться, что UI не зависает при таймауте/5xx.

1. Открыть DevTools Network → включить **«Offline»** (или `cmd+shift+R`
   потом выключить интернет).
2. Открыть `/zakroma`, выбрать автора.
3. В UI — после клика появится «попытка загрузки», через ~10-30 секунд
   (таймаут fetch) — сообщение «Не удалось загрузить» + кнопка
   «Повторить».
4. Кликнуть «Повторить» — новый fetch начнётся.
5. Включить сеть обратно, повторный запрос завершится успешно, UI
   покажет таблицу.

**Ожидаемый результат:**
- FR-FE-001 ✅: catch error → сообщение + Retry, не «вечный» индикатор.
- SC-003 ✅: 0 случаев «зависшего спиннера».

**Провал если:**
- UI остаётся в состоянии «Загрузка...» навсегда.

## Сценарий 6 — обратная совместимость старого endpoint (FR-BE-007, SC-005)

**Цель:** убедиться, что `GET /api/public/zakroma` (без `stream`)
продолжает работать для других потребителей.

```bash
# Через curl или в браузере:
curl -s 'https://sm-karaoke.ru/api/public/zakroma?author=Агата%20Кристи' \
  | head -c 1000
```
или в DevTools Console:
```js
fetch('/api/public/zakroma?author=' + encodeURIComponent('Агата Кристи'))
  .then(r => r.json())
  .then(d => console.log('count:', d.length, 'first:', d[0]?.author))
```

**Ожидаемый результат:**
- Старый endpoint возвращает **JSON-массив** (не NDJSON, не chunked).
- Длина массива = числу песен автора (то же `expectedCount`).
- Никаких изменений в формате по сравнению с мастер-версией.

**Провал если:**
- Endpoint возвращает 404, 500 или другое поведение.

## Сценарий 7 — обратная совместимость для редактора (FR-BE-007 + specs/013)

**Цель:** убедиться, что для залогиненного редактора `>=6` фильтр
снимается (видит все статусы).

1. Залогиниться как редактор в `https://sm-karaoke.ru`.
2. Открыть `/zakroma`, выбрать автора.
3. Проверить, что `expectedCount` в `meta`-сообщении соответствует
   общему числу песен автора (включая `idStatus < 6`), а не только
   опубликованные.

**Ожидаемый результат:**
- FR-BE-007 ✅: `onlyPublished = onlyPublishedFor(request)` — для
  редактора `false`, все песни видны.

## Сценарий 8 — мобильный (≤ 400px) (из спеки Assumptions)

**Цель:** убедиться, что прогрессометр корректно отображается на
узких экранах.

1. Открыть DevTools → Toggle device toolbar → iPhone SE (375×667).
2. Перейти на `/zakroma`, выбрать автора.
3. Прогрессометр должен растягиваться на всю ширину контента,
   не вылезать за края, текст «Загружаем N песен… 56%» — переносится
   по словам если не влезает.

**Ожидаемый результат:**
- Никаких горизонтальных scrollbar'ов.
- Текст читаем (font-size ≥ 14px).

## Сценарий 9 — тёмная тема (FR-FE-005 + спека Edge Cases)

**Цель:** убедиться, что прогрессометр использует CSS-переменные
`--km-*`.

1. Открыть `/zakroma`, переключить тему на «Тёмная» (🌙 в шапке).
2. Выбрать автора, наблюдать прогрессометр.
3. Цвет полосы прогресса и текста должны соответствовать тёмной
   палитре (как и остальной UI).

**Провал если:**
- Прогрессометр «выпадает» в светлые цвета.

## Сценарий 10 — A11y (FR-FE-011, screen reader)

**Цель:** убедиться, что screen reader корректно озвучивает прогресс.

1. Открыть DevTools → вкладка «Accessibility» (или включить
   NVDA/VoiceOver).
2. Открыть `/zakroma`, выбрать автора.
3. Screen reader должен:
   - При появлении прогрессометра — сказать «progress bar, N percent».
   - При обновлении процента — НЕ спамить каждым чанком (throttle
     через rAF).

**Провал если:**
- Screen reader читает КАЖДЫЙ чанк как отдельное обновление
  (50 раз в секунду).
