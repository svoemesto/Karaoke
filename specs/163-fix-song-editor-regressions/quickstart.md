# Quickstart: проверка фикса регрессий редакторов текста песни

**Спека**: [spec.md](./spec.md) | **Research**: [research.md](./research.md) | **Data model**:
[data-model.md](./data-model.md) | **Инвариант**:
[contracts/sync-idempotency-invariant.md](./contracts/sync-idempotency-invariant.md)

Backend не меняется — все проверки ниже про `webvue3` (админка).

## Предпосылки

- Локальный стек `webvue3` запущен в dev-режиме (`npm run dev` в `webvue3/`) поверх работающего
  `karaoke-app` (см. `deploy/do.sh`, project docs `DEVELOPMENT.md`).
- Тестовые данные: минимум одна песня с несколькими строками `~Куплет~`/`~Припев~`/`~comment:...~`
  и заметным числом слоговых маркеров (для проверки P2 — желательно 20+ маркеров/несколько
  спецтегов, чтобы разница в 10% была измеримой); минимум одна песня без единого спецтега (для
  проверки отсутствия регрессии, FR-008).

## Проверка 1 — идемпотентность `syncMarkersFromSpecTags` (без браузера, быстрый чек)

Быстрее всего ловится тем же способом, каким была подтверждена диагностика (research.md §2):
вызвать функцию напрямую из Node на реальном тексте со спецтегами.

1. Взять `sourceText` реальной песни со спецтегами и произвольный стартовый `markers`-массив
   (можно получить из `markersFromServer(...)` на уже сохранённых данных песни, либо построить
   вручную по формату `data-model.md`).
2. Вызвать `syncMarkersFromSpecTags(markers, sourceText)` **три раза подряд** на одном и том же
   `markers`/`sourceText`, фиксируя `markers.length` после каждого вызова.
3. **Ожидаемый результат после фикса**: длина после 1-го вызова может вырасти (реальная вставка
   отсутствующих тег-маркеров); после 2-го и 3-го — **не меняется** (см. инвариант в
   `contracts/sync-idempotency-invariant.md`).
4. Повторить тот же чек для `syncMarkersFromSpecTags` в `SubsEdit.vue` (структурно идентичная
   копия) — регрессионная проверка, не обязательный фикс, но обязательный тест.

## Проверка 2 — облегчённый редактор сохраняет правки (US1, P1)

1. Открыть песню (или задание) в облегчённом редакторе (модалка `SongKaraokeEditorModal.vue`).
2. Ввести/изменить текст, НЕ содержащий спецтегов; дождаться `«Сохранено ✓»`.
3. Закрыть редактор, открыть заново (или обновить страницу) — убедиться, что текст/маркеры
   отражают правку. *(Регрессионный чек — уже работало до фичи, должно продолжать работать.)*
4. Повторить шаги 1-3 на песне со строками `~Куплет~`/`~Припев~`/`~comment:...~`, добавляя/меняя
   текст **рядом** со спецтегами и **сами** спецтеги. После нескольких десятков нажатий клавиш
   (имитируя обычный набор текста) — дождаться `«Сохранено ✓»`, переоткрыть.
5. **Ожидаемый результат после фикса**: текст и маркеры при переоткрытии соответствуют
   последнему состоянию; список маркеров НЕ содержит подозрительно много повторяющихся
   `GROUP|N`/`COMMENT|...` записей на одной и той же смысловой позиции (см. SC-001).

## Проверка 3 — явная ошибка сохранения не маскируется под успех (US1, сценарии 3-4)

1. В открытом облегчённом редакторе отключить сеть (или временно остановить `karaoke-app`).
2. Изменить текст, дождаться попытки автосохранения.
3. **Ожидаемый результат**: индикатор показывает `«Ошибка сохранения»`, НЕ `«Сохранено ✓»`.
4. Попытаться закрыть редактор (кнопка «×» или «Отмена»).
5. **Ожидаемый результат (FR-004)**: закрытие блокируется явным предупреждением; пользователь
   может либо подтвердить закрытие с потерей правок, либо дождаться восстановления сети и
   успешного сохранения.
6. Восстановить сеть/`karaoke-app`, повторно нажать «Сохранить» (или дождаться следующего
   автосохранения) — индикатор должен перейти в `«Сохранено ✓»`.

## Проверка 4 — SubsEdit не тормозит и не «слипается» в нуле (US2, P2)

1. Открыть в SubsEdit песню без спецтегов (контрольная группа) — засечь время от клика до
   готовности редактора к работе (визуально: маркеры на местах, вейвформа кликабельна).
2. Открыть в SubsEdit песню сопоставимого размера **со** спецтегами (20+ маркеров, несколько
   `~Куплет~`/`~Припев~`) — засечь то же самое время.
3. **Ожидаемый результат (SC-003)**: время из шага 2 превышает время из шага 1 не более чем на
   10%.
4. Во время загрузки и сразу после неё — визуально проверить вейвформу: маркеры сразу на своих
   позициях, БЕЗ красной полосы/скопления в нулевой позиции (ни мгновенного, ни постоянного).
5. Отредактировать текст песни со спецтегами (добавить строку, изменить слог рядом со спецтегом) —
   убедиться, что повторной вспышки в нуле не происходит.
6. Повторить шаги 1-5 на песне без спецтегов — поведение должно быть идентично состоянию ДО этой
   фичи (FR-008, отсутствие новой регрессии).
