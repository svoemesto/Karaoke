# Quickstart: проверка фикса «импорт из папки не падает по памяти»

**Feature**: [spec.md](./spec.md) | **Contract**: [contracts/create-from-folder.md](./contracts/create-from-folder.md)

Для `Utils.getListFiles` добавляется узкий unit-тест (см. `plan.md`,
`Testing`) — прогоняется как обычно (`./gradlew karaoke-app:test`). Для
остальной части (устойчивость к OOM на реальном большом дереве, корректность
кортежа заданий в очереди) автотестов нет — проверка вручную на `dev-pc`/`dev`
(см. допуски в «Ограничения и доступы агента» `constitution.md`: на этой
машине разрешено пересобирать/перезапускать `karaoke-app` и работать с
локальной БД без отдельного согласия пользователя).

## Предусловия

- Локальный стек поднят (`db`, `karaoke-app`, `webvue3`).
- После правок в `karaoke-app/src/main/kotlin/...` — пересобрать и
  перезапустить **только** модуль `app` (scoped-команды):

```bash
cd deploy
bash do.sh build_app
bash do.sh start_app
```

- Открыть админку `webvue3` → главная страница (поле «путь к папке» +
  кнопка «Добавить файлы из папки») и раздел «Процессы».

## Сценарий 1 — большая/глубоко вложенная папка не роняет приложение (US1, FR-001/FR-002/FR-003)

1. Подготовить на admin-машине тестовую папку с несколькими тысячами
   файлов (можно смешать: часть — валидные по шаблону имени flac/mp3/m4a
   внутри подпапок вида `<год> - <альбом>/`, часть — файлы других типов и
   имён, часть — глубоко вложенные подпапки без валидных файлов), например
   скриптом-генератором временных файлов.
2. В `webvue3` указать путь к этой папке и нажать «Добавить файлы из
   папки», подтвердить диалог.
3. **Ожидаемый результат**: запрос успешно завершается (нет разрыва
   соединения/500-й ошибки), в логе `karaoke-app` нет ошибки нехватки
   памяти (`OutOfMemoryError`/`Java Heap Space`), контейнер `karaoke-app`
   не перезапускается сам по себе. Приходит SSE-уведомление «Добавление
   файлов из папки» с итоговым числом добавленных (и пропущенных, см.
   Сценарий 2) файлов.
4. Повторить с ещё большей папкой (на порядок больше файлов), убедиться,
   что поведение то же (нет деградации, специфичной для конкретного
   объёма).

## Сценарий 2 — некорректные файлы не прерывают импорт (US1, FR-005/SC-004)

1. В тестовую папку из Сценария 1 включить файлы с заведомо некорректным
   именем (не по шаблону `YYYY (NN) [Автор] - Песня.flac`) и файлы
   неподдерживаемых расширений.
2. Запустить импорт той же папки.
3. **Ожидаемый результат**: операция не прерывается из-за этих файлов;
   итоговое SSE-уведомление показывает и число добавленных, и число
   пропущенных файлов (не только «добавлено», как раньше).

## Сценарий 3 — кортеж заданий формируется в одном лейне для каждой новой песни (US2, FR-006/FR-007/FR-008)

1. В отдельную папку положить 1-2 валидных по имени аудиофайла (реальных,
   небольших — чтобы демукс отработал за разумное время) и импортировать
   её.
2. В разделе «Процессы» отфильтровать по `settings_id` новой песни.
3. **Ожидаемый результат**: сразу после импорта видны задания
   `KEY_BPM_FROM_FILE` (`thread_id=2`, `THREAD_LANE_STEM_JOBS`) и `DEMUCS2`
   (`thread_id=1`, `THREAD_LANE_HEALTH_REPORT`) — это **разные** лейны, и
   так и должно быть: `KEY_BPM_FROM_FILE` — независимое задание, не входит
   в кортеж и не должно с ним конкурировать за слот; кортеж начинается с
   `DEMUCS2`.
4. Дождаться завершения `DEMUCS2`. **Ожидаемый результат**: автоматически (без
   ручных действий) появляются `FF_MP3_ACCOMPANIMENT` и `FF_MP3_VOCAL`, тоже
   в `thread_id=1`.
5. Дождаться их завершения. **Ожидаемый результат**: автоматически
   появляются `UPLOAD_TO_LOCAL_STORE` (для музыки и для голоса), затем после
   их завершения — `UPLOAD_TO_REMOTE_STORE` (для музыки и для голоса), всё
   в том же `thread_id=1`. Ни на одном шаге не появляется дублирующее
   задание того же типа для той же песни.

## Сценарий 4 — массовый импорт: кортежи разных песен не мешают друг другу (US2, FR-008)

1. Импортировать папку с 10+ валидными новыми песнями одновременно.
2. **Ожидаемый результат**: для каждой песни независимо разворачивается
   свой кортеж заданий (Сценарий 3), без потерянных шагов; задания разных
   песен корректно чередуются в общей последовательности лейна
   `THREAD_LANE_HEALTH_REPORT` (лейн один на все песни — это ожидаемо и не
   является багом, FR-008 требует лишь отсутствия блокировки/потери шагов
   между песнями, не параллельного исполнения).
