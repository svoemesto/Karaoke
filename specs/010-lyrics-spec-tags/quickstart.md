# Quickstart: проверка спецтегов в тексте песни

Проверка после реализации (`/speckit-implement`). Не заменяет unit-тесты (`SpecTagsTest.kt`) — это сценарии сквозной проверки в реальном окружении, которые пользователь (не агент, см. `constitution.md` про недоверие к интеграционным тестам) должен прогнать перед тем, как считать фичу готовой.

## Предпосылки

- Локальный стек поднят (`deploy/do.sh`, см. `DEVELOPMENT.md`), доступен `webvue3` (admin UI) и `karaoke-app`.
- Есть тестовая песня с загруженным аудио и введённым текстом (или можно создать новую тестовую песню специально для проверки).
- Форс-алаймент сервис (`AlignmentServiceClient`) доступен (как и для обычной работы "Точные маркеры" сегодня).

**Примечание к сценариям B/C/C2/F**: тег можно вписать в текст вручную ИЛИ вставить кнопкой на панели над текстовым полем (см. FR-011) — обе реализации ДОЛЖНЫ давать идентичный результат, кнопка не более чем печатает тот же синтаксис в позицию курсора.

## Сценарий A — Backward compatibility (регресс)

1. Взять уже существующую размеченную песню (без каких-либо спецтегов в тексте).
2. Запустить "Точные маркеры" в SubsEdit — сохранить список маркеров (экспорт/копия JSON через `/api/song/voicesourcemarkers`).
3. После деплоя фичи повторить п.2 на том же тексте/аудио.
4. **Ожидаемый результат**: список маркеров идентичен (см. FR-004/FR-010, SC-001) — количество, типы, `time`, `label` совпадают в пределах точности форс-алаймента (детерминированного при одинаковом входе).

## Сценарий B — `~newline~` эквивалентен пустой строке

1. Взять текст песни, скопировать в двух вариантах: (a) с обычной пустой строкой между двумя блоками, (b) та же пустая строка заменена на строку, содержащую только `~newline~`.
2. Прогнать оба варианта через "Точные маркеры" (на одном и том же аудио).
3. **Ожидаемый результат**: идентичный список маркеров в обоих случаях — маркер `NEWLINE` в той же позиции (см. User Story 1, SC-002).

## Сценарий C — `~group:N~` и `~comment:текст~`

1. В тексте тестовой песни перед куплетом вставить строку `~group:1~`, перед бриджем — `~comment:вступление гитары~`.
2. Прогнать "Точные маркеры".
3. **Ожидаемый результат**: в разметке в соответствующих позициях появляются маркер группы №1 (`SETTING`, `label="GROUP|1"`) и маркер комментария (`SETTING`, `label="COMMENT|вступление гитары"`) — видно как флажки в SubsEdit при выбранных фильтрах отображения маркеров (см. User Story 2).
4. Некорректный вариант: заменить `~group:1~` на `~group:abc~`, повторить прогон — маркер группы не должен появиться, остальная разметка не должна нарушиться, процесс не должен завершиться с ошибкой (Edge Case, FR-008).

## Сценарий C2 — Алиасы групп (`Куплет`/`Припев`/`Бридж`/`Приговор`)

1. Взять текст песни в двух вариантах: (a) перед куплетом строка `~group:0~`, (b) та же строка заменена на `~Куплет~`.
2. Прогнать оба варианта через "Точные маркеры" на одном аудио.
3. **Ожидаемый результат**: идентичный маркер группы №0 в обоих случаях (User Story 2, сценарий 4).
4. В одном тексте использовать одновременно `~group:1~` в одном месте и `~Припев~` в другом (разные позиции, оба обозначают ту же группу-припев) — оба должны дать маркер группы №1 в своих позициях, без ошибок.
5. Проверить регистронезависимость: `~куплет~`, `~Куплет~`, `~КУПЛЕТ~` — все три дают тот же результат, что `~group:0~`.
6. Проверить, что `~Куплет:2~` (алиас со значением) не распознаётся — строка обрабатывается как нераспознанный тег (Edge Case).
7. Убедиться, что для `group:4` алиаса нет — только числовая форма `~group:4~` даёт маркер, человекочитаемого синонима не предусмотрено в v1.

## Сценарий D — Автодобавление при ручном редактировании (без повторного форс-алаймента)

1. Взять уже размеченную песню (маркеры расставлены, "Точные маркеры" не перезапускается).
2. В текстовом поле лирики в SubsEdit добавить `~newline~` на отдельной строке в месте, где сегодня маркера новой строки нет.
3. Вызвать сохранение/пересчёт маркеров в редакторе (без нажатия кнопки "Точные маркеры").
4. **Ожидаемый результат**: в списке маркеров появляется новый маркер `NEWLINE` в соответствующей позиции, остальные существующие маркеры не изменились по времени/составу (User Story 3, сценарий 1).
5. Повторить пересчёт ещё раз без изменения текста.
6. **Ожидаемый результат**: маркер не дублируется (User Story 3, сценарий 2; SC-003).

## Сценарий E — Существующий маркер без тега не удаляется

1. В размеченной песне вручную (клавишей/панелью в SubsEdit) поставить маркер новой строки в месте, где в тексте нет `~newline~` (обычный сегодняшний способ).
2. Отредактировать текст в другом месте песни (не трогая эту позицию), вызвать пересчёт/сохранение.
3. **Ожидаемый результат**: ранее поставленный вручную маркер остаётся на месте без изменений (FR-005).

## Смежная проверка — подсчёт слогов не сломан (реальный воспроизведённый баг, исправлен)

Это не гипотетический edge case — пользователь реально получил ошибку "Число слогов в тексте не совпало с результатами выравнивания (внутренняя ошибка)" на тексте со спецтегами, хотя без тегов тот же текст размечался нормально. Причина была в четвёртом независимом месте — `alignment-ml/syllables.py` (форс-алаймент сервис, физически отдельный Python-процесс за кнопкой "Точные маркеры"), которое не знало про спецтеги и считало тег-строку словом.

1. На песне с `~group:1~`/`~comment:...~`/`~newline~` вперемешку с обычным текстом убедиться, что "Точные маркеры" **не** возвращает ошибку несовпадения количества слогов (см. `buildMarkersFromSyllableTimes` — возвращает `null` при несовпадении, что в UI видно как эта ошибка).
2. Если ошибка появилась снова — проверить первым делом `alignment-ml/syllables.py` (`_strip_spec_tags`/`split_text_into_words`), а не только Kotlin/Vue-стороны — расхождение чаще всего именно там (см. `research.md` §9).

## Сценарий F — Краудсорсинг-редактор (`karaoke-public`) не ломается на тегах

Третья независимая реализация контракта (см. `contracts/tag-registry.md`) — легко забыть при проверке, если тестировать только `webvue3`.

1. У песни, чей официальный текст уже содержит спецтеги (например `~Куплет~`/`~newline~`), создать/открыть назначение (song assignment) волонтёру и открыть его в `EditorWorkView.vue` (`karaoke-public`).
2. **Ожидаемый результат**: текст задания отображается, слоги разбиты корректно (тег не превратился в фиктивный "слог"), маркер по тегу уже стоит на своём месте (аналог Сценария D, но при первой же загрузке задания — `loadTask()` вызывает `syncMarkersFromSpecTags` сразу после `relabelSyllables`).
3. Добавить в текст задания `~group:2~` в новом месте (или его алиас `~Бридж~`) и убедиться, что после ввода (`onTextInput`) соответствующий маркер добавляется без ручной расстановки клавишами.
4. Убедиться, что маркер, расставленный волонтёром вручную без тега, не исчезает и не сдвигается при последующей правке текста в другом месте задания (аналог Сценария E).

## Готовность

Все сценарии A–F проходят → фича готова к финализации и коммиту. Если сценарий A не проходит — это блокер (нарушение обратной совместимости), реализация не может считаться завершённой независимо от того, что остальные сценарии работают.
