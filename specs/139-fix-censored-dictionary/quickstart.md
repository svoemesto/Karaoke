# Quickstart: проверка исправления цензурирования {songNameCensored}

В проекте нет надёжного CI-прогона тестов (см. Constitution, «Рабочий процесс») — проверка ручная.
Ниже — сценарии, доказывающие, что фикс закрывает исходную жалобу («на серверной части
{songNameCensored} не отрабатывает, как будто там нет словаря») и не ломает существующий путь
(Telegram/ВК с admin-машины).

## Предпосылки

- Слово в словаре «Censored» с корректной разметкой, например `тест[о]вое` (используйте
  безопасное тестовое слово, не реальный мат, чтобы не засорять прод при проверке).
- Доступ к `karaoke-db` (LOCAL) и, если проверяется прод-путь, к SERVER БД.

## Сценарий 1 — Функция censored() принимает чужой database (unit-уровень, после фикса)

```kotlin
// Проверка вручную, например через /api/dictionaries/test (см. contracts/dictionary-test-endpoint.md)
// или временный main()-сниппет на admin-машине:
val webLikeConnection = Connection.remote() // имитирует «чужой» database, переданный вызывающей стороной
val result = "тестовое слово тестовое".censored(database = webLikeConnection)
// Ожидается: слово заменено на маскированную форму — т.е. database реально влияет на результат,
// а не игнорируется в пользу глобала.
```

**Ожидаемый результат до фикса**: параметра `database` у `censored()` не существует (не
компилируется) — сигнатура зафиксирована в `data-model.md`.
**Ожидаемый результат после фикса**: вызов компилируется, и явно переданный `database` реально
используется (можно проверить, подставив заведомо нерабочее соединение — результат должен НЕ
цензурировать, доказывая, что параметр не игнорируется).

## Сценарий 2 — Новый admin-эндпоинт проверки словаря (FR-003, User Story 2)

```bash
curl -s -X POST 'http://localhost:<admin-app-port>/api/dictionaries/test' \
  --data-urlencode 'dictName=Censored' \
  --data-urlencode 'text=Название с тестовое словом'
```

**Ожидаемый результат**: JSON с `"changed": true` и `"result"`, содержащим маскированную форму —
за одно действие, без реальной публикации песни (SC-003).

## Сценарий 3 — Реальный путь «новость на сайте» (воспроизведение исходного бага + проверка фикса)

1. На SERVER БД (или в тестовом окружении, эмулирующем `karaoke-web`) убедиться, что тестовое слово
   присутствует в `tbl_dictionaries` (`dict_name='Censored'`).
2. Подготовить тестовую песню с датой/временем эфира в ближайшем прошлом (в окне
   `ON_AIR_WINDOW_LOOKBACK_MINUTES`, `SongReleaseAnnouncementService.kt`) и названием, содержащим
   тестовое слово.
3. Дождаться тика `SongReleaseAnnouncementScheduler` (`@Scheduled(fixedDelay = 5 * 60_000L)`) на
   прод-сервере, либо (если доступно) вызвать `checkOnAirWindow` вручную в тестовом контексте с
   `database = com.svoemesto.karaokeweb.WORKING_DATABASE`.
4. Проверить `tbl_news.title`/`body` созданной записи.

**Ожидаемый результат до фикса**: тестовое слово в `title`/`body` НЕ замаскировано (воспроизводит
исходную жалобу).
**Ожидаемый результат после фикса**: тестовое слово замаскировано — идентично тому, что вернул бы
`/api/dictionaries/test` с тем же входом (SC-001).

## Сценарий 4 — Наблюдаемость сбоя чтения словаря (FR-002, SC-002)

1. Временно сделать `database`, передаваемый в `censored()`, нерабочим (например, заведомо неверный
   URL/порт — только в тестовом окружении, не на проде).
2. Вызвать путь, использующий `{songNameCensored}` (сценарий 1 или 2).
3. Проверить `docker logs karaoke-web` (или соответствующий вывод) на наличие лога об ошибке чтения
   словаря, отличимого от обычного «слов не найдено».

**Ожидаемый результат**: сбой виден в логах — не тихая деградация до пустого списка.

## Сценарий 5 — Регресс: Telegram/ВК с admin-машины продолжают работать (не сломано фиксом)

1. На admin-машине (где реально развёрнут `karaoke-app`) опубликовать тестовую песню с тем же
   тестовым словом через существующий VK/Telegram auto-publish путь (или
   `/api/vk/templates/preview`-аналог, если есть).
2. Убедиться, что слово по-прежнему маскируется — дефолтный параметр `database = WORKING_DATABASE`
   в изменённых функциях не поменял поведение для уже работавшего пути (Constraints, plan.md).

## Сценарий 6 — Подсказка формата словаря (FR-004, User Story 3)

1. В `webvue3` → Словари → выбрать словарь «Censored» → начать вводить новое значение без `[`/`]`.
2. Убедиться, что видна подсказка/предупреждение об ожидаемом формате перед сохранением.
