## Что проверял

Утверждения находки P-77-04:

1. `curl -w "%{http_code}"` при ошибке соединения печатает `000` в stdout **и** возвращает ненулевой
   код ⇒ конструкция `|| echo "000"` дописывает второе `000` ⇒ `http_status="000000"`.
2. Ветка `000)` не срабатывает, срабатывает `*)` ⇒ «неожиданный HTTP статус 000000» и код возврата
   **5** вместо документированного **2** («трекер недоступен»).
3. В аудит-лог при этом пишется `http_status=0` (jq приводит «000000» к 0), а не признак сбоя.

## Как проверял (команды)

Поведение `curl` при недоступном сервере:

```bash
curl -sS -o /dev/null -w "%{http_code}" --max-time 3 --config /dev/null "http://127.0.0.1:9/nope"
# вывод: 000 ; код возврата curl: 7
```

Код в текущем `master`:

```bash
sed -n '240,320p' tools/tracker-lib.sh
```

## Вывод

**Не воспроизводится.** Ключевой сдвиг: `|| echo "000"` из выражения **убран** — вместо него
код возврата `curl` фиксируется в отдельную переменную, а значение `http_status` нормализуется
после вызова:

```bash
        # При недоступном сервере статус всегда приводим к "000".
        if [ "${curl_rc}" -ne 0 ] || ! [[ "${http_status}" =~ ^[0-9]{3}$ ]]; then
            http_status="000"
        fi
```

Проверено:
- при недоступном сервере `curl` печатает `000` и возвращает 7 ⇒ `curl_rc != 0` ⇒ `http_status`
  приводится к `"000"` — ровно три символа, а не `"000000"`;
- защита дублирует и вторую проверку `! [[ "${http_status}" =~ ^[0-9]{3}$ ]]` — если `curl`
  напечатает что-то не-трёхзначное, статус всё равно станет `"000"`;
- ветка `000)` в `case "$http_status"` **достижима** и возвращает документированный код **2**:
  ```bash
              000)
                  tracker_log_audit "$cmd_name" "${method} ${endpoint}" "000" "$duration_ms" "Connection failed" "$retry_count"
                  echo "${C_RED}ERROR${C_RESET}: Plane недоступен по ${PLANE_URL}, проверьте сеть/URL (PLANE_URL)" >&2
                  return 2
                  ;;
  ```
- в аудит-лог уходит `"000"` (строка-строка, не число), поэтому jq не приводит его к `0` —
  признак сбоя сохраняется в логе.

Пункт 3 находки закрыт тем же изменением: `tracker_log_audit` получает literal `"000"`.
