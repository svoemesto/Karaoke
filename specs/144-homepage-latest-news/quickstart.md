## Цель

Этот документ — **руководство по ручной валидации** фичи end-to-end на dev/staging/prod. Никаких автоматизированных тестов в проекте нет (см. AGENTS.md — тесты в CI не запускаются, существующие интеграционные тесты `@Disabled`), поэтому проверка делается пользователем вручную через браузер и инструменты БД.

---

## Предусловия

1. Окружение Karaoke (admin + web + public) развёрнуто и работает (см. `docs/onboarding.md`, `docs/deployment.md`).
2. В БД `tbl_news` есть **хотя бы 5 опубликованных** новостей (`publish_at IS NOT NULL AND publish_at <= now()`). На проде сейчас ≈19000+ записей.
3. Браузер с DevTools (для проверки сетевых запросов и HTML).
4. Доступ к БД (psql или pgAdmin) для SQL-проверок.

---

## Сценарий 1: Базовый happy-path (≥5 опубликованных новостей)

**Что проверяем**: блок виден на обеих главных, 5 строк, корректные данные.

### Шаги

1. Открыть SPA-главную: `https://<host>/` (через nginx `80to8897` или прямой порт `karaoke-public`).
2. Открыть legacy Thymeleaf-главную: `https://<host>/` (через nginx `80to8897`).
3. В DevTools → Network найти запрос `GET /api/public/news?page=0&size=5` (только на SPA-главной).

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| Блок виден без агрессивного скролла | SC-001 спеки |
| В блоке ровно 5 строк | FR-002, FR-005 |
| Первая строка — самая свежая по `publish_at` | FR-009 |
| Колонка «Дата/время» отформатирована как `dd.MM.yyyy HH:mm` | FR-007 |
| Колонка «Заголовок» содержит `News.title` | FR-002 |
| Колонка «Ссылка» кликабельна, ведёт на `News.link` | FR-003 (SC-003) |
| Legacy Thymeleaf показывает те же 5 строк (порядок и содержимое) | FR-003, SC-004 |

### SQL-проверка источника

```sql
-- Должно вернуть ровно те же 5 записей, что показывает блок
SELECT id, title, link, publish_at, source
FROM tbl_news
WHERE publish_at IS NOT NULL AND publish_at <= now()
ORDER BY publish_at DESC, id DESC
LIMIT 5;
```

## Сценарий 2: Менее 5 опубликованных новостей

**Что проверяем**: блок деградирует корректно (показывает 1-4 строки или 0 строк + скрывается/надпись).

### Шаги

1. На стенде (не на проде!) удалить 4 из 5 самых свежих новостей через `webvue3` или прямым SQL:
   ```sql
   -- Сохранить одну самую свежую для проверки
   DELETE FROM tbl_news WHERE id IN (
     SELECT id FROM tbl_news
     WHERE publish_at IS NOT NULL AND publish_at <= now()
     ORDER BY publish_at DESC, id DESC
     OFFSET 1 LIMIT 4
   );
   ```
2. Открыть SPA-главную и legacy Thymeleaf-главную.

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| В блоке 1 строка (или блок скрыт, если удалить все) | FR-005, SC-005 |
| Никаких пустых строк-заглушек | FR-005 |
| Вёрстка не сломана (нет пустых `<tr>` с `&nbsp;`) | FR-010 |
| После восстановления данных блок снова показывает 5 строк | идемпотентность |

### Cleanup

```sql
-- Восстановить удалённые строки через Sync (или восстановить бэкап БД)
-- Здесь опускаем — на dev-окружении это OK сделать через пересоздание
-- стенда
```

## Сценарий 3: 0 опубликованных новостей

**Что проверяем**: блок полностью скрывается (или показывает надпись «Пока новостей нет»), без битой вёрстки.

### Шаги

1. На стенде удалить все новости с `publish_at <= now()` (например, через временный SQL-фильтр):
   ```sql
   -- ВНИМАНИЕ: только на dev/staging!
   UPDATE tbl_news SET publish_at = publish_at + INTERVAL '100 years';
   ```
2. Открыть SPA-главную и legacy Thymeleaf-главную.

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| Блок не виден (или показывает надпись «Пока новостей нет») | FR-005, SC-005 |
| Вёрстка остальной страницы не сломана | FR-010 |
| HTTP 200 OK для обеих главных (не 500) | SC-007 |

### Cleanup

```sql
UPDATE tbl_news SET publish_at = publish_at - INTERVAL '100 years';
```

## Сценарий 4: Тихaя деградация при сбое бэкенда

**Что проверяем**: блок не рендерится при недоступности/ошибке бэкенда, остальная главная работает.

### Шаги

1. На стенде остановить контейнер `karaoke-web`:
   ```bash
   cd deploy && bash do.sh stop_web
   ```
2. Открыть SPA-главную (`karaoke-public` продолжает работать — nginx/static).

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| Блок новостей отсутствует на SPA-главной | FR-013, SC-007 |
| Никакого спиннера / «Загрузка новостей...» / сообщения об ошибке | FR-013 |
| Остальная главная (логотип, статистика, навигация, соцсети) показывается как обычно | FR-013 |
| В DevTools → Console нет необработанных JS-исключений, которые ломают остальную страницу | FR-013 |
| После восстановления `karaoke-web` блок снова появляется при следующей загрузке | FR-013 |

### Cleanup

```bash
cd deploy && bash do.sh start_web
```

## Сценарий 5: Проверка фильтра (нет `link` или пустой `title`)

**Что проверяем**: строки с пустым `link` или пустым `title` не попадают в блок.

### Шаги

1. Создать через админку `webvue3` новость с заполненным `title`, но **пустым `link`**.
2. Создать новость с **пустым `title`** (только пробелы).
3. Опубликовать обе (`publish_at = now()`).
4. Открыть SPA-главную и legacy Thymeleaf-главную.

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| Обе «кривые» новости НЕ отображаются в блоке | FR-006 |
| Блок показывает другие новости (до 5 штук) | FR-006 |
| Никакого `<a href="">` или `disabled`-ссылки | FR-006 |

### Cleanup

```sql
-- Найти и удалить «кривые» новости через админку или SQL
DELETE FROM tbl_news WHERE title IS NULL OR trim(title) = '' OR link IS NULL OR trim(link) = '';
```

## Сценарий 6: Проверка трекинга клика

**Что проверяем**: клики по строкам пишутся в `tbl_events`.

### Шаги

1. Открыть SPA-главную.
2. Кликнуть по строке новости, у которой `link = /song?id={id}` (авто-новость).
3. Кликнуть по строке новости с произвольным внешним `link` (ручная новость).
4. Проверить `tbl_events`:
   ```sql
   SELECT event_type, link_type, link_name, created_at
   FROM tbl_events
   WHERE created_at > now() - INTERVAL '5 minutes'
   ORDER BY created_at DESC
   LIMIT 10;
   ```

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| Для авто-новости — событие `clickToLink` / `linkToSong` с `link_name = <songId>` | существующий трекинг |
| Для ручной новости — событие `ui` / `click` с деталью `homeNews:<id>` | существующий трекинг |
| Никаких JS-исключений | FR-013 |

## Сценарий 7: Адаптивная вёрстка

**Что проверяем**: блок корректно отображается на десктопе, планшете, мобильном.

### Шаги

1. Открыть SPA-главную в DevTools → Device Toolbar.
2. Проверить на трёх пресетах:
   - Desktop: 1920×1080 — блок виден без скролла.
   - Tablet: 768×1024 — блок виден, читаем, не ломает сетку.
   - Mobile: 375×667 — блок виден, читаем (вертикальный стек или горизонтальная прокрутка таблицы).

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| На десктопе блок помещается в первый экран | SC-001 |
| На планшете/мобильном блок не вылезает за границы viewport | FR-010 |
| Текст читаем (нет обрезанных колонок) | FR-007 |
| Существующие блоки (статистика, навигация, соцсети) не сломаны | FR-010 |

2. Запустить «Синхронизацию в 1 клик» (см. `docs/features/dual-db-sync.md`).
3. На проде открыть SPA-главную.

### Ожидаемый результат

| Проверка | Критерий |
|---|---|
| Sync завершается без ошибок (нет `sync_news_*` нарушений) | FR-008 |
| Новость появилась на проде в блоке главной | FR-006/US-2 |

## Метрики (для продакшена)

- **Просмотры блока** — через трекинг SPA (см. `useEngagementTracking('home')`, уже подключён в `HomeView.vue:175`).
- **Клики по строкам** — через `tbl_events` (см. Сценарий 6).
- **Время ответа эндпоинта** — SC-002 (<300 мс на 19000+ записей). Замер через nginx-логи или APM.
- **Conversion (visitor→registration)** — после включения блока отслеживать воронку через существующий механизм `tbl_events` (см. `docs/strategy/growth.md`).
