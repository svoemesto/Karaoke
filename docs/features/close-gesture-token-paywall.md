# Close gesture token paywall (закрытие обхода оплаты по «скрытому жесту»)

> **Status**: active
> **Feature Key**: close-gesture-token-paywall
> **Last Updated**: 2026-10-24
> **Spec**: [specs/557-close-gesture-token-paywall/spec.md](../../specs/557-close-gesture-token-paywall/spec.md) (OpenProject #358, аудит BR-018)
> Per-feature документ по [Constitution VI FR-009](../../.specify/memory/constitution.md).

## Что делает

Закрывает обход оплаты на публичном периметре: полный доступ к стемам и разметке больше
**нельзя получить по «скрытому жесту»**, а право на полный доступ проверяется **в момент
отдачи байт**, а не по факту владения ранее выданным токеном.

Два рубежа:

1. **Выдача.** Публичный эндпоинт событий `POST /api/public/events` больше не возвращает
   значение доступа: в ответе поле `meta` остаётся, но всегда `null`. Распознавание «жеста»
   (три клика с зажатой клавишей по полю метаданных песни) удалено из сервиса токенов.
2. **Отдача.** Файловые эндпоинты плеера (`fileminus.mp3`, `filevoice.mp3`, `filebass.mp3`,
   `filedrums.mp3`, `playerdata`, `playerfile`) спрашивают правило доступа
   (`PlayerAccessService.evaluate`) и отдают полные байты только при действующем праве.

Правило доступа — единое для всех точек выдачи:

| Основание | Проверка в момент запроса |
|---|---|
| Песня публично доступна (всегда бесплатно / эфир в окне бесплатного доступа) | `Song.isFreelyAvailableNow` |
| Действующий премиум | живая загрузка `SiteUser` → `isEffectivePremium` |
| Бессрочная подписка на эту песню | `Subscription.isSubscribedToSong` |
| Гостевая сессия по публичной share-ссылке | `SongShareLinkService.validateShareSession` |
| Предпросмотр неодобренной разметки по **своему** заданию редактора | живая проверка владения `SongAssignment` |

Если ни одного основания нет — посетитель получает демо-фрагмент (обрезанный на сервере) либо
404 (если не предъявил ни токена, ни сессии). Полный файл и полная разметка не покидают сервер
ни при каких условиях.

## Зачем

Аудит кода #336 (карточка P-36-01, реестр BR-018) зафиксировал обход оплаты **S1**:
«скрытый жест» минтился публичным `POST /api/public/events` без аутентификации и без проверки
права на песню, а выданный токен принимался достаточным основанием для отдачи полных mp3-стемов
и полной разметки любой песни. Итог — анонимный посетитель получал платный контент бесплатно
(три анонимных запроса), а «секретность» жеста была лишь обфускацией: параметры рассылки были
видны в публичном JavaScript сайта.

Ключевая особенность дефекта: токен жеста и легитимный токен **структурно неразличимы** (один
сервис, TTL 30 минут, различие только у демо-токена). Поэтому «просто убрать выдачу токена»
было недостаточно — право всё равно проверяется в момент отдачи байт.

Решение владельца (2026-10-24): вариант А — скрытый жест перестаёт быть основанием доступа;
срок жизни токена (30 минут) не меняется.

## Как работает

### Роли и сущности

- **Токен доступа к плееру** — короткоживущее (не более 30 минут) подтверждение, что доступ к
  конкретной песне однажды был разрешён. **Не является правом на платный контент.** Хранится
  только в памяти процесса (`PlayerGestureUnlockService`), в БД не пишется.
- **Право на прослушивание** — совокупность пяти условий из таблицы выше; определяется по
  правилам [song-air-access.md](song-air-access.md).
- **Демо-фрагмент** — ограниченный по времени фрагмент аудио с ограниченной разметкой,
  обрезается на сервере.

### Поток выдачи токена

`GET /api/public/player/{id}/access` — единственная точка выдачи токена для обычного посетителя
(плюс `PublicSongEditorController` — токен задания редактора). Токен несёт **id пользователя**,
чьё право было проверено: аудио-эндпоинты плеера не получают заголовок `Authorization` (плеер
грузит стемы через `fetch(url)` без заголовков), поэтому сервер берёт пользователя из токена и
**перечитывает** его премиум/подписку из БД в момент запроса.

### Поток отдачи байт

```
GET /api/public/player/{id}/fileminus.mp3?token=…&session=…
  ├─ песня не найдена                    → 404
  ├─ решение PlayerAccessService.evaluate:
  │    ├─ Full  → полные байты
  │    ├─ Demo  → байты, обрезанные Mp3Trimmer по диапазону фрагмента
  │    └─ None  → 404
  └─ отказ (нет доступа / полный токен без права) → запись в журнал `infra.player.access`
```

`playerdata` устроен так же: при решении `Demo` маркеры обрезаются до диапазона и
перебазируются (время вычитается), в ответе `isDemo=true` + `demoFadeInSeconds`.

`playerfile` (выгрузка пакета `.smkaraoke`) отдаётся только при **полном** доступе и **живом
премиуме**; гость по share-ссылке — 403 (пакета в демо-режиме не существует).

### Журнал

Категория `infra.player.access`:

| Сообщение | Уровень | Когда |
|---|---|---|
| `player:access:denied` | WARN | доступа нет вовсе либо «полный» токен без действующего права (сигнал обхода оплаты) |
| `player:access:demo` | INFO | штатный демо-режим: полный доступ не предоставлен, выдан фрагмент |

В записи есть `songId=` и `reason=`; **сам токен и содержимое аудио не пишутся**.

### Фронтенд (karaoke-public)

- `services/tracking.js` — `trackMetaClick` стал fire-and-forget (ответ эндпоинта событий
  больше ничего не сообщает). Состав трекинг-события не изменился: обычный клик-трекинг по
  метаданным песни работает как раньше.
- `views/SongView.vue` — `onMetaClick` больше не открывает плеер по ответу на трекинг.
  Легитимный путь получения токена (`usePlayerAccess` → `/access`) не тронут.

## Инварианты

- **MUST**: выдача полного аудио и полной разметки опирается на действующее право, проверенное **в момент запроса**, а не только на факт владения ранее выданным токеном (FR-002).
- **MUST**: полный доступ — только при одном из пяти оснований: публичность песни / живой премиум / живая подписка на песню / гостевая share-сессия / владение заданием редактора (FR-003, FR-009).
- **MUST**: отсутствие действующего права исключает выдачу полного аудио и полной разметки, даже если токен ещё не истёк (FR-004).
- **MUST**: полный файл и полная разметка не покидают сервер ни при каких условиях, включая неразбираемый поток mp3 (FR-005).
- **MUST**: доступ к одной песне не открывает доступ к другой (FR-006).
- **MUST**: `POST /api/public/events` не содержит значений, пригодных как ключ доступа к платному контенту; обычный клик-трекинг при этом работает (FR-007).
- **MUST**: гость по share-ссылке смотрит плеер, но не выгружает пакет файлов; выгрузка — только при действующем премиуме (FR-008).
- **MUST**: срок жизни токена — не более 30 минут и не увеличивается (FR-013).
- **MUST**: каждый отказ в выдаче полного аудио попадает в журнал с временем, id песни и причиной; токен и аудио в журнал не попадают (FR-012).
- **MUST**: правка не меняет схему БД и не требует миграции данных (FR-015).
- **MUST**: посетитель без полного доступа получает демо-фрагмент, а не ошибку; публичные страницы не ломаются (FR-010).

## Известные ловушки

- **Токен — не право**: любая правка, которая смотрит только `validateToken(token, id)`, снова открывает обход. Правило живёт в `PlayerAccessService` — правки идут туда.
- **Аудио-эндпоинты не получают `Authorization`**: премиум/подписку нельзя проверять по заголовку — только по id пользователя из токена (`PlayerRightsProvider`).
- **Демо-обрезка fail-closed**: `Mp3Trimmer.trimToRange` при неразбираемом потоке возвращает пустой массив, а не исходные байты. «Лучше тишина, чем полная песня».
- **Токены живут в памяти процесса**: ранее выданные (в т.ч. по жесту) токены переживут развёртывание максимум 30 минут. Развёртывание `karaoke-web` на бою должно сопровождаться перезапуском контейнера — решение владельца.
- **Публичный эндпоинт событий не ограничен по частоте**: защита от флуда — отдельная задача (вне объёма спеки 557).
- **Имя `PlayerGestureUnlockService` историческое**: жеста в классе больше нет; переименование — отдельная правка.
- **Демо-режим в плейлистах не предусмотрен**: `playerLauncher.fetchPlayerToken` намеренно строгий (`canWatch===true`) — демо-фрагмент не подставляется в очередь плейлиста.
