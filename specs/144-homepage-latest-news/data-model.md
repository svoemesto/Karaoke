## TL;DR

Фича **не вводит** новых сущностей, таблиц, колонок или индексов. Используется существующая модель `News` (`tbl_news`) только для **чтения** через уже существующий метод `News.loadPublished` и эндпоинт `GET /api/public/news?page=0&size=5`.

Этот документ фиксирует контракт «как блок на главной читает данные», а не новую схему БД.

---

## Существующая сущность (переиспользуемая, read-only)

### `News` (`tbl_news`)

Источник: `karaoke-app/src/main/kotlin/com/svoemesto/karaokeapp/model/News.kt`.

| Поле | Тип | Nullable | Используется блоком |
|---|---|---|---|
| `id` | `Long` | no | нет (в UI не выводится, но нужен как ключ Vue `:key`) |
| `title` | `String` | no (DB NOT NULL) | **да** — текст строки в колонке «Заголовок» |
| `body` | `String` | no | нет |
| `category` | `String` | no | нет (но сохраняется в DTO для возможных будущих фич) |
| `link` | `String` | **yes** (DB NULLable) | **да** — `href` ссылки в колонке «Ссылка»; **строка отбрасывается**, если `null`/`""` |
| `publish_at` | `Timestamp` | **yes** | **да** — дата/время в колонке «Дата/время» |
| `created_at` | `Timestamp` | yes | нет (для UI берётся `publish_at`) |
| `song_id` | `Long` | yes | используется только для трекинга (`trackLinkToSong(songId)`) |
| `source` | `String` (`"manual"` / `"auto"`) | no | нет (UI не различает auto/manual) |

**Правила фильтрации на фронте** (FR-006 спеки):
- Строка **не попадает в блок**, если `link` пустое (`null`/`""`).
- Строка **не попадает в блок**, если `title` пустое (`""`) или состоит из пробелов (`trim().isEmpty()`).
- Эти правила применяются на фронте (Vue computed для SPA; `th:if` для Thymeleaf), не на бэкенде — чтобы не менять контракт существующего эндпоинта и не ломать ленту `/news`.

**Правила сортировки**: на бэкенде (см. `News.loadPublished`, `News.kt:212`) — `ORDER BY publish_at DESC, id DESC`. Фронт сортировку не переопределяет.

## Связи между сущностями

Нет новых связей. Блок «последние 5 новостей» — чисто презентационная агрегация над существующей `News`.

| Откуда | Связь | Куда |
|---|---|---|
| `News.link` (строка) | URL перехода | `SongView` (`/song?id={id}` для авто-новостей) или внешний URL |
| `News.song_id` (Long, nullable) | FK → `tbl_settings.id` (опосредованно, через существующий контракт авто-публикации) | только для трекинга клика |

## Жизненный цикл / состояния

Не применимо — фича read-only. Состояние новости (`publish_at <= now()` vs `publish_at > now()` vs `publish_at IS NULL`) определяется на бэкенде фильтром в `News.loadPublished` и не меняется в рамках этой фичи.

## Объём данных

- На проде ≈19000+ записей в `tbl_news` (см. `specs/089-auto-news-song-release`).
- Блок всегда читает 5 строк (через `LIMIT 5` на бэкенде).
- Размер полезной нагрузки JSON — ≤5 записей × ~200-400 байт = ≤2 KB; пренебрежимо.

---

## Что НЕ меняется (контракт «не трогать»)

- `tbl_news` — ни схемы, ни индексов, ни триггеров.
- `News.loadPublished` — без изменений.
- `NewsDto` — без изменений (уже содержит все нужные поля: `id`, `title`, `link`, `publishAt`, `category`, `source`).
- `SyncRegistry.all` (sync-цель `news`) — без изменений.
- Существующий эндпоинт `GET /api/public/news` (с пагинацией) — без изменений (мы просто передаём ему `size=5`).
- Существующий эндпоинт `GET /api/public/news/since` (бейдж непрочитанных) — без изменений.

## Валидация (на фронте, без бэкенд-валидации)

| Условие | Действие |
|---|---|
| `item.title.trim() === ""` | строка отбрасывается |
| `!item.link` (пустая строка / undefined) | строка отбрасывается |
| HTTP 200, `items.length > 0`, все строки прошли фильтр | блок рендерится |
| HTTP 200, `items.length === 0` (или все отброшены фильтром) | блок не рендерится (тихая деградация) |
| HTTP 5xx, таймаут, невалидный JSON, сетевой отказ | блок не рендерится (FR-013 — тихая деградация) |
