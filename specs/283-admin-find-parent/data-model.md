# Data Model: 283-admin-find-parent

**Branch**: `283-admin-find-parent`
**Date**: 2026-08-31
**Spec**: `../spec.md`

## Назначение

Зафиксировать изменения в data-модели для фичи «Поиск родителя для одного автора». Новых таблиц/колонок не появляется; меняется только **поведение выборки и подбора кандидатов** на основе уже существующих полей.

---

## Затронутая сущность: `Song` (таблица `tbl_songs`)

Существующая сущность. Изменений схемы **нет** — фича работает поверх уже существующих колонок.

### Используемые поля (read-only на старте, write только для `root_id`)

| Поле            | Тип          | Назначение в фиче                                                  |
|-----------------|--------------|--------------------------------------------------------------------|
| `id`            | `Long` (PK)  | Идентификатор песни; первичный ключ выборки.                       |
| `song_author`   | `String?`    | Фильтр выборки (`LOWER(song_author) = LOWER(?)`).                  |
| `song_name`     | `String?`    | Используется `findParentCandidateId` для нормализации и сравнения. |
| `source_text`   | `String?`    | Если непуст и `id_status >= 2` — родитель находится, но не применяется (FR-008). |
| `id_status`     | `Int`        | Используется в условии `id_status >= 2` для пропуска (FR-008).    |
| `root_id`       | `Long`       | Фильтр выборки `root_id = 0`; единственное поле, которое фича пишет. |

### Используемые поля НЕ меняются

| Поле            | Почему не трогаем                                  |
|-----------------|----------------------------------------------------|
| `audio_root_id` | Фаза 2 (аудио-родитель) **отключена** по FR-011.   |
| `song_album`    | Не участвует в подборе родителя.                   |
| `song_year`     | Не участвует в подборе родителя.                   |

## In-memory сущность: `ParentCandidate` (расширение существующей)

В `Utils.kt` объявлен (обновлено 2026-08-31):

```kotlin
private data class ParentCandidate(
    val id: Long,
    val author: String,
)
```

Поле `hasText` **удалено** — больше не хранится и не влияет на выбор кандидата (см. R-002 в `research.md`).

### Изменения для фичи

Изменяется логика выбора финального пула в `findParentCandidateId` (см. R-002 в `research.md`):

| `crossAuthor` | Поведение                                                                                |
|---------------|-------------------------------------------------------------------------------------------|
| `true`        | `sameAuthor.ifEmpty { candidates }` (фоллбэк на других авторов, **без** фильтра по тексту). |
| `false`       | Только `sameAuthor` (тоже без фильтра по тексту). Если пусто — возвращается `null`.      |

`candidates` — все песни с тем же нормализованным названием, **включая песни без `source_text`**.

## HTTP-контракт (резюме; полный — в `contracts/`)

### Endpoint

`POST /api/utils/findparentforauthor`

### Query / form params

| Параметр      | Тип        | Обязательность | Описание                                              |
|---------------|------------|----------------|-------------------------------------------------------|
| `author`      | `String`   | required       | Имя автора; trimmed; case-insensitive сравнение в SQL. |
| `crossAuthor` | `Boolean`  | optional, default `false` | Если `true` — разрешён подбор среди других авторов. |

### Response

| HTTP | Тело ответа | Условие                                              |
|------|-------------|------------------------------------------------------|
| 200  | `"OK"`      | Запущено в фоне.                                     |
| 200  | `"ALREADY_RUNNING"` | Уже идёт предыдущий запуск (фронт показывает warning-тост). |

### SSE-уведомление (по завершении)

`head = "Поиск родителя (автор «<author>»)"`
`body = "Обработано N, родитель назначен M (найдено, но пропущено из-за текста: K)"`
`type = "info"`

Детали — в `contracts/`.

## Валидации

| Условие                                                          | Реакция                                                                                  |
|------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| `author` пустой или только пробелы                              | Запрос не должен уйти с фронта (`disabled` на кнопке); если пришёл на бэк — `400 Bad Request` (защита на стороне контроллера). |
| `author` не найден в `tbl_songs`                                | `ids.size == 0` → SSE-уведомление «Обработано 0, родитель назначен 0», warning-тост.   |
| У всех песен автора уже `root_id <> 0`                          | То же поведение, что выше.                                                              |
| `crossAuthor=false` + есть кандидаты только у других авторов     | `findParentCandidateId` возвращает `null` для каждой песни → SSE «родитель назначен 0», без падений. |

## Состояние и переходы

Состояние песни не меняется (статусы жизненного цикла — за рамками фичи). Единственная мутация — `root_id: 0 → <id другой песни>` для песен автора, прошедших подбор.

```
              ┌──────────────────────┐
              │ root_id = 0          │
              │ song_author = ?      │
              │ (отобрана на старте) │
              └──────────┬───────────┘
                         │
                findParentCandidateId
                         │
            ┌────────────┼─────────────┐
            │            │             │
         null      same author    found but
       (не нашли)   with text      has verified
            │            │             text (id_status ≥ 2)
            ▼            ▼             ▼
   пропуск + лог   root_id :=     пропуск + лог
                  candidateId     (parentSkippedHasText++)
                  + saveToDb()
```
