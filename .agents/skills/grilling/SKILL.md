# Grilling

## Overview

Relentless-интервью владельца до общего понимания. Каждое решение — это
узел дерева дизайна, от которого зависят другие узлы. Сессия закончена,
когда **фронтир пуст**: все ветви дерева посещены, ничего не осталось
молчаливо предположенным.

## Core Pattern: Design Tree + Rounds + Frontier

### Design Tree

Каждое решение ветвится в дочерние, которые от него зависят. Цель —
пройти всё дерево, не пытаясь сразу прыгнуть к листьям.

### Frontier

**Фронтир** — все решения, чьи prerequisites уже решены и которые можно
спросить **сейчас**, не угадывая ответов на ещё-открытые вопросы.

В каждом раунде — задавать **весь фронтир** одним списком. Нельзя:

- смешивать открытые и закрытые вопросы в одном раунде;
- спрашивать вопрос, чей ответ зависит от ещё-открытого вопроса (это вопрос
  следующего раунда).

### Round Format

Каждый вопрос — пронумерован, с заголовком, телом и **рекомендованным
ответом**:

```
❓ **Q1** — **<заголовок>**: <тело вопроса, может быть несколько
параграфов; варианты выбора, если есть>

➡️ <рекомендованный ответ>

---

❓ **Q2** — **<заголовок>**: ...

➡️ <рекомендованный ответ>
```

После каждого ответа пользователя — пересчитать фронтир и задать следующий
раунд.

## Rules

1. **Факты — твоя работа, не пользователя.** Если фронтир-вопрос требует
   факта из окружения (файлы, инструменты, код, OpenProject) — запусти
   субагента или прочитай сам. Не спрашивай у пользователя то, что можешь
   узнать сам.
2. **Решения — пользователя.** Каждое решение — к нему, ждать ответа.
3. **Не блокируйся на исследовании.** Если запущен субагент по факту —
   фронтир-вопрос, который от него зависит, ждёт. Остальные вопросы
   фронтира задавай сейчас.
4. **Один вопрос за раз — антипаттерн.** Спрашивать по одному — медленно и
   теряет дерево. Фронтир за один раунд.
5. **Рекомендация обязательна.** Каждый вопрос — с `➡️ <твоя
   рекомендация>`. Пользователь может отклонить, но должен видеть, что
   ты **уже подумал**.
6. **Сессия окончена, когда фронтир пуст.** Не действуй, пока пользователь
   не подтвердит: «общее понимание достигнуто».

## Когда применять

- Сложный архитектурный выбор (новая фича с trade-off, рефакторинг,
  миграция).
- Решения, которые потом превратятся в спеку / план.
- Любой разговор, где владелец говорит «давай разберёмся» / «подумаем» /
  «grill me» / «спроси меня жёстко».

## Когда НЕ применять

- Один простой вопрос с очевидным ответом.
- Задача, которая уже в спеке — открытые вопросы должны были быть закрыты
  на `speckit-clarify`.
- Когда владелец явно сказал «не спрашивай, делай».

## Инструменты Karaoke

- **`ask_user_question`** — основной инструмент для раунда. Один вызов =
  несколько вопросов с вариантами. Использовать с `multi_select: false`
  для бинарных выборов.
- **`subagent`** (фоновый) — для фактов: чтение файлов, grep по коду,
  запросы к OpenProject. Не блокирует раунд — задай фронтир без
  зависимого вопроса, обнови его когда субагент вернётся.
- **`codegraph_explore`** / **`grep`** — для кода Karaoke.
  **Только после** Knowledge-first MUST #0 ([`AGENTS.md`](../../../AGENTS.md)).

## Common Mistakes

| Red Flag | Reality |
|----------|---------|
| «Спрошу один вопрос за раз» | Антипаттерн. Фронтир за раунд. |
| «Вопросы без рекомендации» | Всегда давай `➡️`. Ты думаешь, не пользователь. |
| «Спрошу у пользователя что есть в `tools/`» | Это твоя работа — прочитай. |
| «Буду ждать субагента и не задам другие вопросы» | Фронтир можно частично пройти. |
| «Действую после раунда 1» | Сессия закончена, когда **фронтир пуст**, не когда тебе покажется достаточным. |

## Karaoke-специфика

- **Knowledge-first MUST #0** ([`AGENTS.md` MUST #0](../../../AGENTS.md))
  обязателен ДО grilling — без него ты не знаешь, какие решения уже
  приняты в ADR / конституции.
- **Конституция** ([`.specify/memory/constitution.md`](../../../.specify/memory/constitution.md))
  — последняя инстанция для governance-вопросов: grilling не должен
  приводить к решениям, противоречащим MUST/SHOULD, без отдельного
  `speckit-constitution` шага.
- **OpenProject** — если grilling приходит к решению «создать новую
  фичу», финальный артефакт = OpenProject issue + спека. Не заканчивай
  grilling без оглашения «создаю issue #N, иду в `speckit-specify`».
