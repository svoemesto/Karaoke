# Feature Specification: Импорт из папки — родители только у того же автора + автообложка альбома

**Feature Branch**: `238-import-folder-author-album-cover`
**Created**: 2026-08-25
**Status**: Draft
**Input**: Описание пользователя: "Задача - модифицировать процедуру добавления файлов из папки на главной странице админки webvue3. Нужно сделать два изменения. Первое - при поиске "родителей" для новой песни не искать в песнях других авторов, только того же самого автора. Второе - при создании альбома проверять, есть ли в папке графический файл (jpg, png и т.п.). Если графический файл есть и он один - то использовать его в качестве исходника для картинки альбома: обрезать до формата сторон 1:1 по короткой стороне, смасштабировать до 400*400 пикселей, сохранить с именем LogoAlbum.png, создать превью, загрузить в локальное и удалённое хранилище - в общем все необходимые действия чтобы у альбома была картинка."

## Clarifications

### Session 2026-08-25

- Q: Если импортируемая папка имеет подпапки (например, `2024 - Альбом/CD1/`, `2024 - Альбом/CD2/`) и песни лежат внутри них, в каком каталоге искать графический файл-обложку и куда сохранять `LogoAlbum.png`? → A: B — искать в каждой `rootFolder` файла (`Album/CD1/` отдельно от `Album/CD2/`), `LogoAlbum.png` сохранять туда же — каждый диск может иметь свою обложку.
- Q: Должна ли новая логика применяться и в legacy-эндпоинте `MainController.doCreateFromFolder` (`/utils/createfromfolder` через шаблон `main.html`), который ходит через те же общие функции `Song.createFromPath` / `Album.findOrCreateForSongImport`? → A: A — применять в обоих эндпоинтах без исключений; изменения в общих функциях автоматически покрывают и admin UI (`ApiController.doCreateFromFolder`), и legacy (`MainController.doCreateFromFolder`).
- Q: Если в `rootFolder` уже лежит `LogoAlbum.png` (или `LogoAlbum.preview.png`) **и одновременно** ровно один «настоящий» графический файл (например, `cover.jpg`), как должен работать подсчёт кандидатов на автообложку? → A: B — `LogoAlbum.png` и `LogoAlbum.preview.png` считаются обычными графическими файлами; если в `rootFolder` лежат `LogoAlbum.png` + `cover.jpg`, это «два файла» — автообложка не создаётся.

## Пользовательские сценарии и тестирование *(обязательные)*

### Пользовательская история 1 — Поиск «родителя» ограничен только тем же автором (Приоритет: P1)

Оператор импортирует из папки пачку новых песен. Для каждой вновь созданной песни система пытается автоматически привязать её к существующему «родителю» (исходной/оригинальной записи с тем же названием без учёта содержимого в скобках), чтобы переиспользовать уже готовый текст и маркеры разметки. При поиске «родителя» система должна рассматривать **только** песни того же автора, что и импортируемая — поиск среди песен **других** авторов не выполняется.

Если у того же автора запись с подходящим названием не найдена — никакая другая песня «родителем» не назначается; дальнейшие шаги (фоновый поиск текста через SearXNG и т. п.) выполняются как обычно.

**Почему этот приоритет**: Сегодня поиск «родителя» сначала перебирает песни того же автора, а при ненахождении — **расширяется на всех авторов**. Это приводит к ложным привязкам (например, одинаковые по названию песни у разных исполнителей получают чужой текст и чужие маркеры), что портит качество базы и приводит к ручной перепроверке оператором. Ограничение поиска «только у того же автора» — это устранение ложных срабатываний и упрощение операторской работы.

**Независимый тест**: Подготовить две одинаково названные песни (например, «Звезда») у разных авторов, при этом у одной из них есть полностью готовый текст и маркеры. Импортировать папку с новой песней «Звезда» для второго автора. Убедиться, что система **не** привязала к ней текст/маркеры от первого автора (никаких `sourceText`/`resultText`/`sourceMarkers` от чужого автора, `root_id` остаётся 0 или равен id только этой же песни). Затем импортировать папку с такой же песней у того же автора, у которого уже есть оригинал — убедиться, что привязка **происходит** (как раньше для случая «того же автора»).

**Сценарии приёмки**:

1. **Дано** в базе есть песня «Звезда» (с готовым текстом и маркерами) у автора A, **Когда** импортируется папка с новой песней «Звезда» для автора B, **Тогда** новая песня автора B **не** получает `sourceText`/`resultText`/`sourceMarkers`/`root_id` от песни автора A.
2. **Дано** в базе есть песня «Звезда» у автора A (с готовым текстом и маркерами), **Когда** импортируется папка с новой песней «Звезда» для автора A, **Тогда** новая песня получает те же `sourceText`/`resultText`/`sourceMarkers`, что и существующая, и `root_id` указывает на существующую (текущее поведение для случая «того же автора» сохраняется).
3. **Дано** в базе нет ни одной песни с подходящим названием ни у того же, ни у других авторов, **Когда** импортируется папка с новой песней, **Тогда** поведение системы не отличается от текущего: «родитель» не найден, запускается фоновый поиск текста (как и сейчас при ненахождении).
4. **Дано** у того же автора есть несколько песен с подходящим названием (например, две песни «Звезда» с разными регистрами/скобками), **Когда** импортируется новая песня, **Тогда** правило выбора «оригинала» (например, по наименьшему `id` или иному стабильному критерию) остаётся тем же, что и сейчас; меняется только область поиска.

### Пользовательская история 2 — Автообложка альбома из графического файла в папке (Приоритет: P1)

Оператор импортирует папку вида `YYYY - Название альбома`, внутри которой лежат файлы песен по шаблону `YYYY (NN) [Автор] - Песня.flac` **и** ровно один графический файл (`jpg`, `jpeg`, `png`, `webp`, `bmp`, `tiff` — без учёта регистра расширения). Если в процессе импорта система создаёт **новый** альбом (то есть альбома с таким сочетанием автор/год/название в базе ещё не было), то найденный графический файл должен автоматически стать обложкой альбома: быть обрезан до квадратного формата 1:1 по короткой стороне, смасштабирован до 400×400 пикселей, сохранён как `LogoAlbum.png` в папке альбома, с созданием превью (`LogoAlbum.preview.png`) и загрузкой в локальное и удалённое хранилище — так, чтобы у альбома появилась рабочая картинка без ручных действий оператора.

Если графического файла в папке нет, или таких файлов больше одного, автообложка не создаётся (поведение как сейчас), а оператор при необходимости может добавить обложку вручную позже (как раньше).

**Почему этот приоритет**: На практике многие релизы приходят к оператору в виде папки с треками и одной JPG/PNG обложкой от правообладателя. Без автоматического использования этого файла оператор вынужден вручную через модалку выбирать/кадрировать картинку для **каждого** нового альбома — это трудоёмко и часто пропускается, из-за чего у альбомов остаются плейсхолдеры «Нет изображения». Автоматизация на пути импорта из папки покрывает этот сценарий «по умолчанию» без дополнительных кнопок.

**Независимый тест**: Подготовить папку `YYYY - Тестовый альбом`, положить в неё несколько файлов песен по требуемому шаблону и **ровно один** графический файл (например, `cover.jpg` произвольного размера и соотношения сторон). Запустить «Добавить файлы из папки». После завершения операции проверить, что:
- В папке появился файл `LogoAlbum.png` (400×400, квадратный, PNG).
- В папке появился файл превью обложки.
- У альбома в базе отображается обложка (через интерфейс админки или таблицу `tbl_pictures`).
- Картинка доступна по тому же URL-формату, что и обложки, добавленные вручную через модалку.

**Сценарии приёмки**:

1. **Дано** в импортируемой папке лежит ровно один графический файл (`jpg`/`jpeg`/`png`/`webp`/`bmp`/`tiff`, регистр расширения не важен), **Когда** в процессе импорта создаётся **новый** альбом, **Тогда** в папке альбома появляется `LogoAlbum.png` — квадратное изображение 400×400 пикселей, обрезанное по короткой стороне исходника, сохранённое в формате PNG.
2. **Дано** обложка создана автоматически, **Когда** операция импорта завершается, **Тогда** у альбома есть превью (`LogoAlbum.preview.png` или эквивалент), а сама обложка загружена и доступна в локальном и удалённом хранилище так же, как обложки, добавленные вручную через интерфейс.
3. **Дано** в импортируемой папке **нет** графических файлов, **Когда** создаётся новый альбом, **Тогда** никакая автообложка не создаётся; альбом создаётся без картинки (как сейчас).
4. **Дано** в импортируемой папке **несколько** графических файлов (2 и более), **Когда** создаётся новый альбом, **Тогда** никакая автообложка не создаётся автоматически (оператор при необходимости выбирает обложку вручную через существующую модалку).
5. **Дано** альбом с таким сочетанием автор/год/название **уже существует** в базе (то есть при импорте альбом не создаётся, а переиспользуется), **Когда** обрабатывается новая песня этой папки, **Тогда** существующая обложка альбома (если есть) **не** заменяется автоматически — никаких «перезатираний» уже существующих обложек, иначе это разрушит ручной выбор для уже оформленных альбомов.
6. **Дано** в папке лежит графический файл, но альбом **уже существует**, **Когда** обрабатываются песни этой папки, **Тогда** поведение системы для существующего альбома не отличается от текущего (никаких побочных эффектов от лежащего рядом графического файла).

## Граничные случаи

- Имя файла графической обложки может быть любым (например, `cover.jpg`, `front.png`, `обложка.jpeg`, `Front (1).webp`) — учитывается только расширение, без привязки к конкретному имени файла.
- Источник может быть в любом формате из поддерживаемых (`jpg`, `jpeg`, `png`, `webp`, `bmp`, `tiff`); другие форматы (например, `gif`, `svg`, `heic`) — **не** считаются кандидатами на автообложку.
- Скрытые файлы и файлы, начинающиеся с точки (например, `.DS_Store`, `._cover.jpg`), — не учитываются как кандидаты.
- Источник может быть уже квадратным и любого размера — на выходе всё равно 400×400 PNG (квадрат из квадрата, но согласованного размера).
- Источник с прозрачностью (PNG с альфа-каналом) — сохраняется как PNG; после обрезки до квадрата прозрачные области по короткой стороне исчезают (кадрирование по короткой стороне).
- Источник нечитаем/повреждён — операция импорта **не** падает; для этой папки автообложка просто не создаётся, импорт остальных песен продолжается.
- В импортируемой папке на момент обработки уже лежит `LogoAlbum.png` (например, от предыдущего импорта или ручной правки) **и одновременно** рядом лежит «настоящий» графический файл-источник (например, `cover.jpg`): `LogoAlbum.png` и `LogoAlbum.preview.png` считаются обычными графическими файлами, поэтому в `rootFolder` оказывается **минимум два** кандидата — автообложка не создаётся (FR-008, см. Clarifications Q3).
- Песни одного альбома лежат в подпапках дисков (`Album/CD1/`, `Album/CD2/`) — графический файл ищется в каждой `rootFolder` отдельно (см. Clarifications Q1); если в `CD1/` есть ровно один графический файл, автообложка создаётся в `CD1/LogoAlbum.png`, в `CD2/` — отдельно по своим правилам.
- Поиск «родителя» у того же автора с учётом регистра и скобок должен остаться консистентным с текущим (например, regex `\([^)]*\)` для исключения скобок, регистронезависимое сравнение названия) — меняется только область поиска.

## Требования *(обязательные)*

### Функциональные требования

- **FR-001**: При импорте новой песни из папки система ДОЛЖНА искать «родителя» (исходную песню с тем же названием без учёта содержимого в скобках) **только** среди песен того же автора, что и импортируемая; поиск среди песен других авторов НЕ ДОЛЖЕН выполняться.
- **FR-002**: Если у того же автора запись-«родитель» не найдена, система НЕ ДОЛЖНА пытаться назначить «родителем» песню другого автора; запись остаётся без `root_id` (как и сейчас при ненахождении «родителя» вообще), после чего отрабатывает существующая фоновая логика поиска текста.
- **FR-003**: Правила выбора «родителя» среди песен того же автора (например, приоритет по `id`, требования к непустому `sourceText`, регистронезависимое сравнение названия с исключением содержимого в скобках) ДОЛЖНЫ быть сохранены без изменений — меняется только область поиска.
- **FR-004**: Существующая ручная кнопка «Найти и обработать дубликаты песен автора» (и связанная с ней серверная логика) НЕ ДОЛЖНА быть затронута этой доработкой.
- **FR-005**: В процессе импорта папки, при создании **нового** альбома, система ДОЛЖНА проверить `rootFolder` каждого файла песни (parent-каталог файла) на наличие графических файлов (`jpg`, `jpeg`, `png`, `webp`, `bmp`, `tiff`, без учёта регистра расширения, без учёта имён, исключая скрытые файлы). `LogoAlbum.png` и `LogoAlbum.preview.png` считаются обычными графическими файлами и НЕ исключаются из подсчёта (см. Clarifications Q3). Поиск идёт **в каждой `rootFolder` независимо** — даже если у альбома несколько дисков в подпапках (`Album/CD1/`, `Album/CD2/`), графика ищется в каждой подпапке диска отдельно.
- **FR-006**: Если в `rootFolder` найден **ровно один** графический файл, система ДОЛЖНА использовать его в качестве исходника для автообложки альбома: обрезать изображение до квадратного формата 1:1 по короткой стороне, смасштабировать до 400×400 пикселей и сохранить как `LogoAlbum.png` **в той же `rootFolder`**, где был найден исходник.
- **FR-007**: Созданная автообложка ДОЛЖНА сопровождаться превью (`LogoAlbum.preview.png` или эквивалент), и обе версии ДОЛЖНЫ быть загружены в локальное и удалённое хранилище тем же способом, что и обложки, добавленные вручную через интерфейс — так, чтобы у альбома появилась рабочая картинка, видимая в админке и публичной части.
- **FR-008**: Если в папке графических файлов **нет** или их **больше одного**, система НЕ ДОЛЖНА создавать автообложку; альбом создаётся без картинки (текущее поведение сохраняется).
- **FR-009**: Автообложка создаётся ТОЛЬКО для **вновь создаваемых** альбомов; для **уже существующих** альбомов (когда при импорте переиспользуется ранее созданный альбом) никаких автоматических замен/пересоздания обложки выполняться НЕ ДОЛЖНО.
- **FR-010**: Если исходный графический файл нечитаем или повреждён, автообложка для этой папки НЕ ДОЛЖНА создаваться, а импорт остальных песен папки ДОЛЖЕН продолжаться без ошибок.
- **FR-011**: Логика автообложки применяется в пути импорта из папки через общие функции `Song.createFromPath` / `Album.findOrCreateForSongImport` и покрывает оба эндпоинта импорта — admin UI `ApiController.doCreateFromFolder` (`/api/utils/createfromfolder`, главная страница админки «Добавить файлы из папки») и legacy `MainController.doCreateFromFolder` (`/utils/createfromfolder`, шаблон `main.html`); существующий механизм ручного сохранения обложки через модалку (фронт-энд + соответствующий серверный эндпоинт) НЕ ДОЛЖЕН быть затронут этой фичей.
- **FR-012**: Доработка НЕ ДОЛЖНА менять внешний интерфейс админки: ни подтверждающий диалог, ни текст кнопки, ни поведение модалок. Изменения прозрачны для оператора — картинка просто появляется у нового альбома.

### Ключевые сущности

- **Песня**: запись, создаваемая при импорте из папки; получает «родителя» (если найден в рамках того же автора) и идентификатор альбома.
- **«Родитель» песни**: существующая в базе песня с тем же автором и подходящим названием (без учёта содержимого в скобках), у которой непустой `sourceText`; используется как источник `sourceText`/`resultText`/`sourceMarkers` для новой песни, `root_id` указывает на неё.
- **Альбом**: сущность, идентифицируемая сочетанием «автор + год + название»; при импорте может создаваться заново или переиспользоваться.
- **Папка альбома**: каталог на диске вида `YYYY - Название альбома` (соглашение об именовании папок), в котором лежат файлы песен этой папки и потенциально графический файл-обложка.
- **`LogoAlbum.png`**: файл обложки альбома 400×400, PNG, лежит в `rootFolder` файлов песен (для плоского альбома совпадает с папкой альбома; для много-дискового — в `rootFolder` каждого диска, см. Clarifications Q1).
- **Превью обложки**: уменьшенная версия `LogoAlbum.png` для быстрого отображения в таблицах/карточках.
- **Локальное хранилище картинок**: локальная файловая система (наследует существующую логику хранения `Pictures`).
- **Удалённое хранилище картинок**: MinIO (наследует существующую логику загрузки `Pictures`).

## Критерии успеха *(обязательные)*

### Измеримые результаты

- **SC-001**: При импорте папки с новой песней, для которой в базе есть одноимённая песня **другого** автора с готовым текстом, новая песня **не** получает чужих `sourceText`/`resultText`/`sourceMarkers`/`root_id` (в 100% случаев такого сценария).
- **SC-002**: При импорте папки с новой песней, для которой у того же автора есть одноимённая запись с готовым текстом, новая песня получает те же `sourceText`/`resultText`/`sourceMarkers` и `root_id` указывает на существующую (текущее поведение сохраняется в 100% случаев).
- **SC-003**: При импорте папки, где создаётся **новый** альбом и в `rootFolder` (parent-каталоге файлов песен) лежит ровно один графический файл, после завершения импорта:
  - в этой `rootFolder` существует файл `LogoAlbum.png` размером 400×400 пикселей, формат PNG;
  - существует файл превью обложки;
  - в таблице `tbl_pictures` (или эквивалентной сущности хранения) есть запись с тем же содержимым, что и `LogoAlbum.png`, доступная по тому же URL-формату, что и ручные обложки;
  - обложка доступна и в локальном, и в удалённом хранилище (MinIO).
- **SC-004**: Если в импортируемой папке нет графических файлов или их несколько, автообложка **не** создаётся, импорт остальных песен завершается успешно без ошибок (в 100% таких случаев).
- **SC-005**: Если альбом уже существует в базе, лежащий рядом графический файл **не** приводит к автоматической замене/пересозданию его обложки (в 100% таких случаев).
- **SC-006**: Внешний интерфейс админки (тексты кнопок/диалогов, состав модалок) остаётся без изменений — `git diff` по `webvue3/src/views/HomeView.vue`, `webvue3/src/components/Albums/**` показывает только правки бэкенда, без изменения UI-текстов.
- **SC-007**: Существующая ручная кнопка «Найти и обработать дубликаты песен автора» и связанная серверная логика продолжают работать как раньше (никаких побочных эффектов от изменения `findDuplicateOriginal()`).

## Допущения

- **A-001**: Под «графическим файлом» понимается файл с расширением `jpg`, `jpeg`, `png`, `webp`, `bmp` или `tiff` (без учёта регистра); остальные расширения (включая `gif`, `svg`, `heic`, `psd`) не считаются кандидатами на автообложку. `LogoAlbum.png` и `LogoAlbum.preview.png` считаются обычными графическими файлами и НЕ исключаются из подсчёта (см. Clarifications Q3).
- **A-002**: Под «`rootFolder` файла» понимается parent-каталог файла песни при импорте из папки (для плоского альбома совпадает с папкой альбома; для много-дискового — это `Album/CD1/`, `Album/CD2/` и т. п.); графический файл-исходник ищется именно в этой `rootFolder`, и `LogoAlbum.png` сохраняется туда же — каждый диск может иметь свою обложку (см. Clarifications Q1).
- **A-003**: Под «ровно один графический файл» понимается ровно один файл с подходящим расширением после фильтрации скрытых файлов; нулевое или большее число файлов означает «автообложка не создаётся».
- **A-004**: Существующая серверная функция кадрирования/масштабирования изображения до квадрата 400×400 (используемая ручным путём сохранения обложки через модалку) переиспользуется без изменений — только вызывается автоматически при соблюдении условий.
- **A-005**: Существующая серверная логика записи `Pictures` (создание/обновление записи, загрузка в локальное и удалённое хранилище) переиспользуется без изменений — автообложка проходит тот же путь, что и ручная обложка.
- **A-006**: «Тот же автор» при поиске «родителя» определяется по полю автора песни (включая потенциальные нечёткие сравнения, если они есть сейчас) — правила сравнения авторов не меняются, меняется только множество кандидатов.
- **A-007**: Изменение затрагивает только путь импорта из папки (главная страница админки `/api/utils/createfromfolder` через `ApiController.doCreateFromFolder` И legacy-эндпоинт `/utils/createfromfolder` через `MainController.doCreateFromFolder`) — оба идут через общие функции `Song.createFromPath` / `Album.findOrCreateForSongImport`, изменения делаются в этих общих функциях и автоматически покрывают оба пути (см. Clarifications Q2); другие пути создания/обновления песен и альбомов (например, ручное создание через форму редактора) остаются без изменений.
- **A-008**: Файлы, начинающиеся с точки (`.DS_Store`, `._cover.jpg` и т. п.), считаются скрытыми и не учитываются как кандидаты на автообложку.
