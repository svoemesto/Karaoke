# Quickstart: проверка расширенного диапазона свободных слотов публикации

Ручная проверка (в CI автотестов для этого пути нет, см. `plan.md` → Technical
Context → Testing). Выполняется на dev-машине с локально поднятым стеком
(`karaoke-app` + `webvue3` + локальная БД).

## Предпосылки

- Локальный стек поднят (`karaoke-app`, `webvue3`, локальная PostgreSQL) — см.
  `DEVELOPMENT.md` / `deploy/do.sh`.
- Есть доступ к локальной БД (psql/DBeaver/аналог) для подготовки тестовых данных
  в `tbl_songs.publish_date`/`publish_time`.

## Сценарий 1 — расширенный диапазон часов (User Story 1, FR-001, FR-003, SC-001)

1. Открыть админку (`webvue3`), перейти в любую карточку песни (`SongEdit`).
2. Очистить поле «Дата публикации», кликнуть в него (фокус).
3. **Ожидаемо**: список подсказок содержит ровно 13 вариантов — по одному на
   каждый час с 10:00 до 22:00 включительно, в том числе часы, которых раньше не
   было (10:00, 18:00, 19:00, 20:00, 21:00, 22:00).
4. Если в БД нет ни одной записи с `publish_time = '20:00'` — убедиться, что
   вариант для 20:00 всё равно присутствует в списке (не пропущен).

## Сценарий 2 — гарантия «только будущее», кейс из описания задачи (User Story 2, FR-004, SC-002)

1. В БД найти/создать запись `tbl_songs` с `publish_time = '10:00'` и
   `publish_date`, равной дате месяц назад от текущего дня (формат `DD.MM.YY`).
2. Убедиться, что для часа `10:00` в БД нет других, более поздних дат.
3. Установить/дождаться, чтобы текущее время на сервере было позже 10:00 (например,
   ~12:00).
4. Открыть `SongEdit`, очистить поле «Дата публикации», поставить фокус.
5. **Ожидаемо**: вариант для 10:00 в списке — это **завтрашняя** дата в 10:00 (не
   «месяц назад + 1 день», и не сегодняшняя дата).

## Сценарий 3 — час ещё не наступил сегодня (edge case из spec.md, User Story 2 сценарий 2)

1. В БД найти/создать запись с `publish_time = '15:00'` и `publish_date` = вчера.
2. Текущее время на сервере — до 15:00 сегодня (например, 10:00).
3. Открыть `SongEdit`, очистить «Дата публикации», фокус.
4. **Ожидаемо**: вариант для 15:00 — **сегодняшняя** дата.

## Сценарий 4 — общая проверка отсутствия дат в прошлом (SC-002, все 13 слотов)

1. Открыть `SongEdit` для любой песни, очистить «Дата публикации», фокус.
2. Для каждого из 13 предложенных вариантов вручную сверить: дата+время строго
   позже текущего момента (по времени сервера/системных часов machine, где крутится
   `karaoke-app`).
3. **Ожидаемо**: ни один из 13 вариантов не оказывается в прошлом или равным
   текущему моменту.

## Прямая проверка эндпоинта (опционально, без UI)

```bash
curl -s -X POST http://localhost:<PORT>/api/getfreetimeslots | jq
```

(порт — локальный порт `karaoke-app`, см. `deploy/do.env`/`docker-compose.yml`).

**Ожидаемо**: JSON-массив из ровно 13 строк формата `dd.MM.yy HH:mm`, часы —
`10:00`, `11:00`, …, `22:00` по порядку, все даты строго в будущем — см.
`contracts/getfreetimeslots.md`.
