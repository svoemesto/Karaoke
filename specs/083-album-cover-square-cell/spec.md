# Спецификация фичи: Альбомы — квадратная ячейка обложки альбома

**Feature Branch**: `[083-album-cover-square-cell]`
**Created**: 2026-07-29
**Status**: Draft
**Input**: Описание пользователя: "В админке в компоненте \"Альбомы\" в таблице надо ширину колонки с картинкой альбома сделать такой же как высота строк (ячейка должна быть квадратной)"

## Пользовательские сценарии и тестирование *(обязательно)*

### Пользовательская история 1 — Ячейка с обложкой альбома квадратная (Приоритет: P1)

Администратор открывает раздел «Альбомы», применяет фильтр и видит таблицу со списком альбомов. В колонке `(альбом)` каждая ячейка визуально представляет собой квадрат: ширина ячейки равна её высоте, изображение обложки (или плейсхолдер «Нет изображения») вписано в этот квадрат без искажений пропорций. Колонка с обложкой автора `(автор)` сохраняет текущее поведение.

**Почему этот приоритет**: Это и есть суть запроса — единообразный квадратный вид ячейки обложки альбома. Без квадрата картинки разного соотношения сторон визуально «прыгают» по ширине, таблица выглядит неаккуратно.

**Независимый тест**: Открыть `/Albums`, применить фильтр с альбомами, имеющими обложки. Измерить визуально ширину и высоту ячейки в колонке `(альбом)` — они должны совпадать. Изображение вписано без обрезки (вписывается пропорционально) и не вылезает за границы ячейки.

**Сценарии приёмки**:

1. **Дано** таблица альбомов загружена, **Когда** администратор смотрит на колонку `(альбом)`, **Тогда** каждая ячейка имеет одинаковые ширину и высоту (квадрат), а обложка отображается внутри без искажений.
2. **Дано** у альбома нет изображения (отображается плейсхолдер «Нет изображения»), **Когда** администратор смотрит на ячейку `(альбом)`, **Тогда** плейсхолдер занимает всю площадь квадрата, ячейка остаётся квадратной.
3. **Дано** у альбома обложка с неквадратным соотношением сторон (например, 400×300), **Когда** администратор смотрит на ячейку `(альбом)`, **Тогда** изображение вписано в квадрат без обрезки, по бокам или сверху/снизу — пустое пространство.
4. **Дано** администратор меняет размер окна браузера / увеличивает/уменьшает масштаб, **Когда** таблица перестраивается, **Тогда** ячейка `(альбом)` остаётся квадратной, ширина по-прежнему равна высоте.

---

### Пользовательская история 2 — Квадрат применяется только к колонке `(альбом)`, не к `(автор)` (Приоритет: P2)

Администратор видит, что квадратной сделана только ячейка с обложкой альбома. Колонка с обложкой автора `(автор)` сохраняет прежнее поведение (прямоугольная, ширина как у ячейки обложки альбома или как было раньше — допустимо не трогать).

**Почему этот приоритет**: Запрос пользователя касается только колонки `(альбом)`. Колонка `(автор)` либо уже подходит по дизайну, либо не входит в scope этого изменения. Менять её без явного запроса — лишний риск.

**Независимый тест**: Открыть `/Albums` с альбомами, имеющими обложки. Сравнить визуально ячейки колонок `(автор)` и `(альбом)` — допустимо, что `(автор)` останется прямоугольной (если так было).

**Сценарии приёмки**:

1. **Дано** таблица альбомов загружена, **Когда** администратор смотрит на колонки `(автор)` и `(альбом)`, **Тогда** квадратной является только ячейка `(альбом)`, ячейка `(автор)` сохраняет прежний вид.
2. **Дано** запрос пользователя, **Когда** ревью изменений, **Тогда** правки внесены только в `webvue3/src/components/Albums/AlbumsTable.vue` (стили и/или ширина колонки), никаких изменений в `AuthorsTable.vue`, `SongsTable.vue` или публичной части.

## Требования *(обязательно)*

### Функциональные требования

- **FR-001**: Колонка `(альбом)` в `AlbumsTable.vue` ДОЛЖНА иметь фиксированную ширину, равную высоте строки таблицы (квадратная ячейка).
- **FR-002**: Ячейка `(альбом)` ДОЛЖНА содержать обложку альбома либо плейсхолдер «Нет изображения» без искажений пропорций (пропорциональное вписывание или эквивалент).
- **FR-003**: Ширина колонки `(альбом)` ДОЛЖНА быть задана явно (например, в `albumDigestFields` через `style` поля `albumPicture`), а не наследоваться от содержимого.
- **FR-004**: Правки ДОЛЖНЫ быть ограничены компонентом `AlbumsTable.vue` (и, при необходимости, связанными CSS-правилами в этом же файле) — никаких изменений в `AuthorsTable.vue`, публичной части `karaoke-public` или бэкенде.
- **FR-005**: Высота строки таблицы (определяемая самой высокой ячейкой в строке) ДОЛЖНА оставаться стабильной — изменение ширины колонки `(альбом)` не должно уменьшать/увеличивать высоту остальных строк.

### Ключевые сущности

- **Ячейка `(альбом)`**: визуальная ячейка в колонке `albumPicture` таблицы `AlbumsTable.vue`. Содержит либо изображение с `albumPicturePreviewUrl`, либо блок-плейсхолдер «Нет изображения».
- **Поле `albumPicture`**: элемент массива `albumDigestFields` с ключом `albumPicture`, чей `style` задаёт ширину колонки через `minWidth`/`maxWidth`/`width`.

## Критерии успеха *(обязательно)*

### Измеримые результаты

- **SC-001**: Визуально ширина и высота ячейки `(альбом)` совпадают (квадрат) на стандартном разрешении админки (≥ 1280×800).
- **SC-002**: Обложка альбома отображается внутри квадрата без обрезки и без искажений пропорций при любом соотношении сторон исходного изображения.
- **SC-003**: Плейсхолдер «Нет изображения» занимает всю площадь квадрата, ячейка остаётся квадратной.
- **SC-004**: Изменения касаются только `AlbumsTable.vue`; `git diff` показывает правки только в `webvue3/src/components/Albums/AlbumsTable.vue` (или связанных CSS внутри него).

## Допущения

- **A-001**: Текущая высота строки таблицы в `AlbumsTable.vue` определяется ячейкой `.fld-picture-preview` (сейчас `height: 54px`). Квадрат = ширина ячейки, равная этой высоте (т.е. `54px`).
- **A-002**: Колонка `(автор)` не входит в scope этого изменения — её вид не меняется.
- **A-003**: Существующая логика клика по ячейке `(альбом)` (открытие `AlbumCoverModal`, см. `specs/014-album-cell-album-cover-modal`) сохраняется без изменений.
- **A-004**: Существующая логика плейсхолдера «Нет изображения» (`.no-image-placeholder`) сохраняется; меняется только размер/площадь ячейки.
- **A-005**: Используется фиксированная ширина колонки (через `style` в `albumDigestFields` для `albumPicture`), а не `min-width`/`max-width` с большим разбросом — иначе ширина может «плавать» в зависимости от содержимого и не быть квадратом стабильно.
