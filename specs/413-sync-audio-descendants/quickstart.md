# Quickstart: 413 — Синхронизация аудио-потомков

**Дата**: 2026-09-19
**Спека**: [spec.md](spec.md)
**Цель**: end-to-end валидация механизма после реализации.

## Prerequisites

1. Локальное окружение Karaoke запущено; `karaoke-app` собран на текущей ветке.
2. PostgreSQL LOCAL доступен.
3. Подготовлены данные:
   - **родитель** `P` со статусом ≥5 и непустыми маркерами;
   - **потомок** `C1` со статусом <6 и `audio_parent_id = P`;
   - **потомок** `C2` со статусом 6 (`audio_parent_id = P`);
   - **родитель** `P2` со статусом <5 и потомком `C3` (`audio_parent_id = P2`);
   - пара с аудио-схожестью <95 % (для негативного сценария), если воспроизводимо.

Проверить данные:

```sql
SELECT id, song_author, song_name, id_status, audio_parent_id, song_type
FROM tbl_songs
WHERE id IN (P, C1, C2, P2, C3);
```

## Сценарий 1 — Авто-синхронизация при правке родителя (US1)

1. Убедиться: `P.id_status >= 5`.
2. Изменить маркеры `P` в редакторе (admin) и сохранить.
3. Дождаться завершения фонового прохода (лог `[sync-audio]`).
4. Проверить:

```sql
SELECT id, id_status, audio_similarity_percent, audio_delta_ms
FROM tbl_songs WHERE id = C1;
```

**Ожидается**:
- `C1.source_text/result_text/source_markers/formatted_text_*` = контент `P`
  (маркеры сдвинуты на `audio_delta_ms`);
- `C1.id_status = 5`;
- `AUDIO_SIMILARITY_PERCENT`/`AUDIO_DELTA_MS` обновлены свежей сверкой;
- рядом с песней появились перегенерированные `.voice1.srt` и т.д.

## Сценарий 2 — Ворота по статусу родителя (US1, FR-002)

1. Изменить маркеры `P2` (статус <5), сохранить.
2. Убедиться: в логе **нет** строк `[sync-audio]` для `P2`; `C3` не изменился.

## Сценарий 3 — Переход статуса (2→5 / 2→6)

1. У `P` (или другого родителя, у которого есть потомок) выставить статус сразу 5
   из более низкого (например 2→5).
2. **Ожидается**: запуск синхронизации, потомок обновлён.

## Сценарий 4 — Переход 5→6 не запускает повтор

1. У родителя, уже синхронизировавшего потomka при 5, выставить 6.
2. **Ожидается**: `[sync-audio]` для него не появляется.

## Сценарий 5 — Потомок со статусом 6 не трогается (FR-006)

1. После сценария 1 `C2` (статус 6) не изменился.

## Сценарий 6 — Активный процесс (FR-008)

1. Поставить у `C1` активный `KaraokeProcess` (WAITING/WORKING).
2. Изменить родителя.
3. **Ожидается**: `[sync-audio] … child=C1 — skipped: active_process`.

## Сценарий 7 — Массовая админ-функция (US2)

1. Открыть главную страницу админки (`webvue3`).
2. Нажать «Синхронизировать аудио-потомков (Custom Function)» → подтвердить.
3. **Ожидается**: сразу ответ; в логе — строки по каждой паре; по завершении —
   SSE-тост со сводкой.
4. Повторный клик во время прохода → `"ALREADY_RUNNING"`.

## Сценарий 8 — Нет каскада и ложных запусков (US3)

1. Синхронизировать `C1` (записав потomka) — убедиться, что его собственные
   потомки (если есть) не были затронуты; повторных `[sync-audio]` нет.
2. Фоновое сохранение песни без правки контента (например, sync/worker) не
   порождает `[sync-audio]`.
