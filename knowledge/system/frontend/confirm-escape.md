# Экранирование текста подтверждений админки (`CustomConfirm`)

> **Домен**: system (frontend)
> **Компоненты**: `webvue3/src/components/Common/CustomConfirm.vue` (общий
> компонент подтверждения), `webvue3/src/utils/escapeHtml.js` (экранирование),
> `tools/check-confirm-escape.py` (проверка), `config/frontend/confirm-safe-expressions.txt`
> (список безопасных выражений).
> **Спека**: `specs/558-escape-song-name-confirm/spec.md` (контракт),
> `specs/562-impl-xss-escape/` (реализация). **OpenProject**: #360, аудит #336,
> дефект **BR-123** (S1).

## Назначение

Админское подтверждение — единая точка, через которую проходят все
административные подтверждения: удаление песни, создание караоке, DEMUCS,
SHEETSAGE, картинок и текстов, бан пользователя сайта, удаление картинки,
запуск двуx-БД синхронизации, работа со словарём, Smart Copy. Текст подтверждения
собирается вызывающим кодом и может содержать **пользовательские данные**:
имя песни, имя автора, e-mail публично зарегистрированного пользователя сайта,
имя картинки, выделенный фрагмент текста песни, текст ошибки синхронизации,
параметры Smart Copy.

До правки спеки #558 текст выводился через `v-html` **всегда**, а имя песни
подставлялось в разметку как есть: имя с `<img src=x onerror=…>` выполнялось как
код в сессии администратора — в origin админки, откуда доступны все
административные действия без дополнительного подтверждения.

## Два рубежа

### 1. Текстовый режим по умолчанию (компонент)

```html
<div :style="styleHeader" v-if="params.allowHtml" v-html="params.header" />
<div :style="styleHeader" v-else v-text="params.header" />
<div :style="styleBody" v-if="params.allowHtml" v-html="params.body" />
<div :style="styleBody" v-else v-text="params.body" />
```

`v-text` пишет через `textContent`: разметка в значении не создаёт элементов и
не выполняет сценариев. Сырая разметка принимается **только** при явном
`params.allowHtml === true`. Структура DOM и стили не меняются — оформление
подтверждения сохраняется.

Инвариант: **`allowHtml: true` объявлен тогда и только тогда, когда в `header`
или `body` есть статичная разметка** (`<strong>`, `<br>`, `<hr>`). Блоки с
чистым текстом остаются в текстовом режиме.

### 2. Экранирование на входе (вызывающий код)

Пользовательское значение оборачивается в `escapeHtml(...)` **в момент входа в
HTML-буфер**, а не «на выходе»:

```js
body: `Удалить песню <strong>«${escapeHtml(this.song.songName)}»</strong>?`
```

Это то же правило проекта, что и для полей `formattedText*`
(см. `song-public-dto.md`): экранировать готовую HTML-строку целиком нельзя —
сломается статичная разметка.

## Инварианты

- **Экранирование ровно один раз.** Компонент на выходе не экранирует ничего.
  Иначе `&` превратится в `&amp;` на экране.
- **В текстовом режиме экранирование не применяется.** `v-text` показывает
  строку как есть; экранированное значение отобразилось бы как `&amp;`.
- **Данные не меняются.** Правка носит характер отображения: значения в базе
  остаются прежними, включая уже испорченные (с разметкой).
- **Формат подтверждения прежний.** Заголовки, кнопки, таймауты, действия по
  кнопке «Да» не изменились.
- **Публичный периметр не затронут.** `karaoke-public` использует `v-html` только
  к серверно-экранированным `formattedText*`; в Thymeleaf-шаблонах нет ни одного
  `th:utext`.

## Проверка (`tools/check-confirm-escape.py`)

| Правило | Что проверяет |
| --- | --- |
| **R1** | общий компонент не принимает сырую разметку по умолчанию (есть `v-text`, а `v-html` — только под `params.allowHtml`) |
| **R2** | `allowHtml: true` ⇔ в `header`/`body` есть статичная разметка |
| **R3** | в блоке с разметкой каждое пользовательское значение обёрнуто в `escapeHtml(...)` |

Проверка разбирает **все** блоки `customConfirmParams` в `webvue3` (137 блоков
в 18 файлах) и умеет разворачивать промежуточные локальные переменные
(`scope` в `HomeView.vue`, `body` в `SmartCopyModal.vue`, `lines` в
`SyncTable.vue`) — иначе user-данные, спрятанные в промежуточной переменной,
были бы не найдены.

Выражения, которые пользовательскими данными **не** являются (счётчики,
идентификаторы, значения из закрытых перечислений, справочные подписи),
перечислены явно в `config/frontend/confirm-safe-expressions.txt` с причиной
по каждой строке. Всё, чего в списке нет, считается пользовательскими данными:
deny-by-default важен — он ловит новые источники, а не только регрессию
перечисленных.

Проверка подключена в `.pre-commit-config.yaml` (хук `confirm-escape-guard`) и
`.github/workflows/lint.yml` (job `confirm-escape-guard`). Собственный
«до/после»-тест guard'а — `tools/check-confirm-escape-fixtures.sh`: на
уязвимом снимке кода guard обязан упасть, на исправленном — пройти (FR-014
спеки #558).

## Регресс-контроль (прецедент спеки #215)

`webvue3/src/utils/__tests__/escapeHtml.test.js` (запуск: `cd webvue3 && npm run
test:unit`):

- для значения **без спецсимволов** результат экранирования побайтово совпадает
  с исходным значением (baseline совпадает);
- значение с `&` даёт ровно одну `&amp;` — двойного экранирования нет;
- `null`/`undefined` дают пустую строку.

## Ловушки

- **Экранировать готовую HTML-строку** — сломает статичную разметку.
- **Экранировать в текстовом режиме** — покажет `&amp;` буквально.
- **Значение в промежуточной переменной** — экранировать надо там, где значение
  **входит** в HTML-буфер, а не где объявлено.
- **Правило `vue/no-v-html` выключено** (решение владельца, FR-015 спеки #558):
  возврат правила — отдельная задача (14 мест в проекте, часть требует
  перехода на санитайзер, а не на простой запрет). Защиту обеспечивает проверка
  `tools/check-confirm-escape.py`, а не линтер.
- **Смежный незакрытый дефект**: BR-312 — метки маркеров редактора
  (`ReviewModal.vue:98`, `SongKaraokeEditorView.vue:317`, `karaoke-public`).
  Другой корень, отдельная задача.
