# Feature Specification: Временные ссылки в синхронизации БД

**Feature Branch**: `172-db-sync-temporary-links`
**Created**: 2026-08-12
**Status**: Draft
**Input**: User description: "Добавить \"Временные ссылки\" в механизм синхронизации БД в один клик. По умолчанию направление - с сервера на локал."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Синхронизация временных ссылок с сервера (Priority: P1)

Администратор запускает синхронизацию БД в один клик и переносит записи о временных ссылках с сервера на локальную БД, не выбирая направление вручную.

**Why this priority**: Это основной заявленный сценарий и безопасный для рабочего процесса вариант по умолчанию.

**Independent Test**: Создать отличающуюся запись временной ссылки на сервере, запустить синхронизацию с настройками по умолчанию и убедиться, что локальная БД содержит ожидаемую запись.

**Acceptance Scenarios**:

1. **Given** на сервере есть новая или изменённая временная ссылка, **When** администратор запускает синхронизацию в один клик без изменения направления, **Then** ссылка переносится на локал.
2. **Given** временная ссылка удалена на сервере, **When** выполняется синхронизация по умолчанию, **Then** соответствующее удаление отражается на локали согласно действующим правилам синхронизации.
3. **Given** временные ссылки одинаковы на обеих сторонах, **When** запускается синхронизация, **Then** изменений не создаётся и операция завершается успешно.

---

### User Story 2 - Выбор обратного направления (Priority: P2)

Администратор выбирает направление с локали на сервер и запускает синхронизацию временных ссылок для обслуживания специального сценария восстановления или публикации данных.

**Why this priority**: Обратная синхронизация нужна для полноты управления, но не должна быть направлением по умолчанию.

**Independent Test**: Изменить запись на локали, явно выбрать направление локал → сервер и проверить результат на сервере.

**Acceptance Scenarios**:

1. **Given** администратор явно выбрал направление локал → сервер и на локали есть новая временная ссылка, **When** запускается синхронизация, **Then** запись появляется на сервере.
2. **Given** направление не выбрано, **When** администратор открывает форму синхронизации, **Then** отображается сервер как источник и локал как получатель.

### Edge Cases

- При отсутствии соединения с одной из БД операция завершается с понятным сообщением, а частично обработанные изменения не выдаются за успешно завершённые.
- При конфликтующих изменениях администратор получает сведения о конфликте и может выбрать разрешённое направлением действие; данные не перезаписываются скрыто.
- Истёкшие или отозванные временные ссылки синхронизируются как обычные записи со своим текущим состоянием.
- Повторный запуск после успешной синхронизации не создаёт дубликатов.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST включать сущность «Временные ссылки» в список сущностей механизма синхронизации БД в один клик.
- **FR-002**: Система MUST поддерживать перенос новых, изменённых и удалённых временных ссылок между серверной и локальной БД.
- **FR-003**: Система MUST устанавливать направление сервер → локал как направление по умолчанию для временных ссылок.
- **FR-004**: Пользователь MUST иметь возможность явно выбрать направление локал → сервер до запуска синхронизации.
- **FR-005**: Система MUST применять к временным ссылкам те же проверки доступа к операции и подтверждение опасных действий, что и к другим сущностям синхронизации.
- **FR-006**: Система MUST показывать временные ссылки и их изменения в сводке операции до и после выполнения синхронизации.
- **FR-007**: Система MUST сообщать об ошибке соединения, конфликте или неуспешной обработке временной ссылки отдельно от успешных изменений.
- **FR-008**: Система MUST обеспечивать идемпотентность повторного запуска синхронизации.
- **FR-009**: Система MUST сохранять неизменными значения идентификаторов, владельцев, срока действия и секретов временных ссылок при переносе.

### Key Entities

- **Временная ссылка**: ограниченная по времени ссылка на доступный ресурс; включает идентификатор, владельца, целевой ресурс, срок действия, статус отзыва и секретную часть.
- **Операция синхронизации**: запуск переноса выбранных сущностей между серверной и локальной БД с направлением, результатом и перечнем изменений.
- **Конфликт синхронизации**: ситуация, когда одна временная ссылка имеет несовместимые изменения на обеих сторонах и требует явного разрешения.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Администратор может включить временные ссылки в синхронизацию и запустить перенос сервер → локал не более чем за 3 действия после открытия экрана синхронизации.
- **SC-002**: Не менее 99% синхронизаций без конфликтов завершаются с одинаковым набором временных ссылок на источнике и получателе.
- **SC-003**: Повторный запуск неизменившейся синхронизации не создаёт дубликатов и не изменяет существующие временные ссылки.
- **SC-004**: В 100% неуспешных операций администратор видит, что именно не перенесено и почему.
- **SC-005**: Явно выбранное направление локал → сервер работает не хуже направления по умолчанию для новых, изменённых и удалённых временных ссылок.

## Assumptions

- «Временные ссылки» уже имеют определённую сущность и хранилище, а задача добавляет их в существующий механизм синхронизации, а не создаёт новый тип ссылки.
- Направление задаётся на уровне операции синхронизации и может быть переопределено администратором перед запуском.
- Существующие политики авторизации, подтверждения и обработки конфликтов применяются без изменения.
- Секретные значения временных ссылок не отображаются в сводках и журналах; сохраняется только возможность корректного использования ссылки.
- Синхронизация выполняется для текущих записей; создание отдельного архива истёкших ссылок не входит в объём первой версии.
