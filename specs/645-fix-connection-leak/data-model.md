# Data Model: Устранение утечки соединений с БД (BR-627)

**Дата**: 2026-10-26 | **Спека**: [spec.md](spec.md) | **План**: [plan.md](plan.md)

## Сущности

Спека не вводит новых доменных сущностей и не меняет схему БД (FR-011: миграция
данных не требуется). Ниже — сущности **проверки** (то, что описывает
`OneShotThreadWiringTest` и детектор `RawThreadDbGuard`).

### `DbSourceFile` — файл прикладного кода, обращающийся к БД

| Поле | Тип | Описание |
|---|---|---|
| `path` | `String` | путь относительно корня репозитория, POSIX-разделители |
| `dbMarkers` | `List<String>` | какие маркеры обращения к БД сработали (для диагностики) |
| `rawThreads` | `List<RawThreadHit>` | найденные сырые фоновые потоки |

Правило отбора: файл считается обращающимся к БД, если **код** (без
комментариев — `//`, `/* … */`, KDoc) содержит хотя бы один маркер из
[research.md D-3](research.md#d-3-проверка-обнаруживает-файлы-обращающиеся-к-бд-динамически).

### `RawThreadHit` — найденный сырой фоновый поток

| Поле | Тип | Описание |
|---|---|---|
| `line` | `Int` | номер строки (1-based) в исходном файле |
| `kind` | `ThreadKind` | `KOTLIN_THREAD` (нижний регистр `thread`) или `JAVA_THREAD_SAM` (`Thread { … }`) |
| `snippet` | `String` | строка-источник (для сообщения об ошибке) |

### `ThreadKind`

| Значение | Что означает | Нарушение в DB-файле? |
|---|---|---|
| `KOTLIN_THREAD` | `kotlin.concurrent.thread` (`thread {`, `thread(`, `kotlin.concurrent.thread {`) | **да** (FR-002) |
| `JAVA_THREAD_SAM` | `java.lang.Thread { … }` — SAM-конструктор | **да**, кроме JVM shutdown hook (`addShutdownHook(Thread { … })`) |
| — | `Thread(…)` с non-SAM-аргументами (фабрика потока пула, consumer-поток) | нет |
| — | `Thread { … }` в файле **без** обращений к БД | нет (US2, сценарий 2) |

### `ScanResult` — результат обхода

| Поле | Тип | Описание |
|---|---|---|
| `dbFiles` | `List<DbSourceFile>` | все файлы прикладного кода, обращающиеся к БД |
| `violations` | `List<Violation>` | файлы с сырыми фоновыми потоками |

### `Violation`

| Поле | Тип | Описание |
|---|---|---|
| `path` | `String` | путь к файлу |
| `line` | `Int` | номер строки |
| `kind` | `ThreadKind` | тип нарушения |
| `snippet` | `String` | строка-источник |

## Инварианты проверки

1. **Покрытие (FR-003, SC-003)**: обходятся **все** `.kt` в
   `karaoke-app/src/main/kotlin` и `karaoke-web/src/main/kotlin` — не
   фиксированный перечень.
2. **Различение (FR-004)**: нарушение фиксируется только в файле, который
   обращается к БД; сырой поток в файле без обращений к БД нарушением не
   считается.
3. **Точность указания (US2, сценарий 1)**: сообщение об ошибке содержит путь
   файла и номер строки.
4. **Комментарии не считаются кодом**: `thread {` в KDoc/обычном комментарии
   не является нарушением (в коде есть такие места — например,
   `KaraokeConnection.kt:202`).
5. **Канонический механизм исключён**: `services/OneShotThread.kt` — файл,
   в котором `Thread(` — это и есть реализация канонического способа; он не
   является нарушением (конструкция `Thread(`, а не SAM `Thread {`).
6. **Негативная фикстура (FR-006)**: проверка обязана **падать** на копии
   реального DB-файла с внедрённым сырым `thread {`, и её сообщение должно
   указывать этот файл и строку.

## Инварианты кода (после фикса)

7. **Единственный способ запуска одноразового фонового потока** —
   `startOneShotThread(database, name) { … }` (+ `alsoClose` для второго
   экземпляра БД) (FR-001).
8. **Соединение одноразового потока закрывается детерминированно** — при
   успехе и при исключении (FR-005).
9. **Соединение переиспользуемого потока не закрывается** — контракт ADR
   local-0009 не меняется (проверяется существующими тестами
   `ChatControllerThreadLocalTest` и `EventsBufferThreadLocalTest`).
10. **Публичные HTTP-контракты и схема БД не меняются** (FR-011).

## Состояния фонового потока

```
запуск (startOneShotThread)
   │
   ├─ тело успешно ───────────────► finally: onFinally() → closeThreadConnection(database) → alsoClose[*] → поток умер
   ├─ тело бросило исключение ────► finally: onFinally() → closeThreadConnection(database) → alsoClose[*] → поток умер (исключение — в stderr потока)
   └─ getConnection() не удался ───► finally: closeThreadConnection() — закрывать нечего (no-op), ошибок в логах нет
```

Последний пункт — edge case спеки («фоновая операция падает **до** получения
соединения — закрывать нечего, проверка обязана это различать и не считать
ошибкой»): `KaraokeConnection.closeThreadConnection()` при
`threadLocalConnection.get() == null` выходит сразу, ничего не логируя.
