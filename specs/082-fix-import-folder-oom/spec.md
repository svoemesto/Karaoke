# Feature Specification: Устойчивый импорт файлов из папки без падения по памяти

**Feature Branch**: `082-fix-import-folder-oom`

**Created**: 2026-07-29

**Status**: Draft

**Input**: User description: "При нажатии "Добавить файлы из папки" если в папке (и подпапках много файлов) то в логе появляется ошибка про Java Heap Out Of Space или что-то в этом роде про нехватку памяти. Надо чтобы функционал работал не падая при большом количестве обрабатываемых файлов. Так же нужно проверить, что при добавлении новой песни правильно формируется кортеж заданий в рамках одного лейна: демукс - создание мп3 музыки и голоса - загрузка мп3 музыки и голоса в локальное и удалённое хранилище"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Импорт большой папки не приводит к падению по памяти (Priority: P1)

Оператор указывает путь к папке (в которой, включая вложенные подпапки, может
находиться очень много аудиофайлов) и нажимает «Добавить файлы из папки».
Операция должна успешно завершиться и добавить подходящие файлы как новые
песни, не приводя к падению приложения по нехватке памяти (Java Heap Out Of
Memory), независимо от того, сколько файлов и подпапок обрабатывается.

**Why this priority**: Это блокирующий баг — сейчас массовый импорт из
большой папки завершается падением по памяти, и оператор не может добавить
песни таким способом вообще. Это основной сценарий использования кнопки, без
него функционал бесполезен для больших партий.

**Independent Test**: Подготовить папку с вложенными подпапками, суммарно
содержащую значительно больше файлов, чем обычно (порядок величины, ранее
вызывавший падение), нажать «Добавить файлы из папки» и подтвердить импорт;
убедиться, что операция завершается без падения приложения и без ошибки
нехватки памяти в логе, а подходящие файлы добавлены как песни.

**Acceptance Scenarios**:

1. **Given** папка (с вложенными подпапками) содержит очень большое
   количество аудиофайлов, **When** оператор нажимает «Добавить файлы из
   папки» и подтверждает операцию, **Then** приложение не падает и в логе не
   появляется ошибка нехватки памяти (Out Of Memory), а операция доходит до
   конца.
2. **Given** импорт большой папки выполняется, **When** операция долго
   обрабатывает файлы, **Then** оператор видит по завершении итоговый
   результат (сколько записей добавлено), как и при импорте небольшой папки.
3. **Given** папка содержит как подходящие файлы, так и файлы, которые не
   могут быть распознаны/обработаны (например, некорректный формат имени),
   **When** выполняется массовый импорт, **Then** такие файлы не прерывают
   всю операцию и не вызывают роста потребления памяти, пропорционального
   общему числу файлов в папке.

---

### User Story 2 - Корректный кортеж заданий для каждой новой песни (Priority: P2)

Для каждой новой песни, добавленной из папки, система должна автоматически
поставить в очередь и довести до конца полный набор заданий одного лейна:
разделение аудио на музыку и голос (демукс) → создание mp3 музыки и mp3
голоса → загрузка mp3 музыки и голоса в локальное хранилище → загрузка mp3
музыки и голоса в удалённое хранилище — без ручного вмешательства оператора
и без потерянных или задвоенных шагов, в том числе при массовом добавлении
многих песен одновременно.

**Why this priority**: Даже если падение по памяти устранено, польза от
импорта нулевая, если добавленные песни не доводятся автоматически до
готового состояния (со стемами и файлами в обоих хранилищах) — оператору
придётся вручную выяснять и достраивать недостающие задания для каждой
песни. Приоритет ниже P1, так как это не блокирует саму операцию импорта, но
без этого её результат неполноценен.

**Independent Test**: Добавить через «Добавить файлы из папки» одну или
несколько новых песен и проследить в очереди заданий, что для каждой из них
без ручных действий оператора (кроме ожидания выполнения) последовательно
создаются и выполняются: демукс → создание mp3 музыки и голоса → загрузка
mp3 музыки и голоса в локальное хранилище → загрузка mp3 музыки и голоса в
удалённое хранилище.

**Acceptance Scenarios**:

1. **Given** для новой песни, добавленной из папки, поставлено и успешно
   завершилось задание демукса, **When** оператор ничего не делает,
   **Then** система автоматически ставит в очередь создание mp3 музыки и mp3
   голоса для этой песни.
2. **Given** mp3 музыки и mp3 голоса для песни созданы, **When** эти задания
   завершаются, **Then** система автоматически ставит в очередь загрузку
   соответствующих файлов сначала в локальное, а затем в удалённое
   хранилище.
3. **Given** из одной папки одновременно добавлено много новых песен,
   **When** задания каждой песни по цепочке завершаются, **Then** кортеж
   заданий формируется полностью и независимо для каждой песни — без
   потерянных шагов, задвоенных заданий и без задержек, вызванных обработкой
   других песен в этой же партии.
4. **Given** среди новых песен из папки есть дубликат уже существующей
   записи (родительское аудио уже прошло часть цепочки ранее), **When**
   кортеж заданий формируется для этой песни, **Then** система не создаёт
   повторно задания для шагов, которые уже были выполнены для родительского
   аудио.

---

### Edge Cases

- Что происходит, если папка (с учётом подпапок) не содержит ни одного
  подходящего аудиофайла? Операция должна корректно завершиться с нулевым
  результатом, без ошибок.
- Что происходит, если путь к папке некорректен или недоступен? Оператор
  должен получить понятное сообщение об ошибке, а не падение приложения.
- Что происходит, если среди файлов встречаются неподдерживаемые форматы или
  файлы с некорректным именем (не по ожидаемому шаблону)? Такие файлы должны
  пропускаться, не влияя на обработку остальных и не накапливаясь в памяти.
- Что происходит, если задание демукса для одной из песен партии завершается
  с ошибкой? Дальнейшие шаги кортежа для этой конкретной песни не должны
  выполняться до устранения проблемы, но это не должно останавливать
  обработку остальных песен партии или других лейнов очереди.
- Что происходит при очень глубокой вложенности подпапок (много уровней
  каталогов)? Обработка не должна зависеть от глубины дерева сильнее, чем от
  общего количества файлов в нём.
- Что происходит, если один и тот же файл фактически соответствует уже
  существующей песне (полный дубликат)? Он не должен порождать повторный
  полный кортеж заданий с нуля.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА обрабатывать содержимое папки (включая
  вложенные подпапки) без одновременной загрузки в память полного списка
  путей и связанных с ними данных для произвольно большого количества
  файлов.
- **FR-002**: Система ДОЛЖНА корректно освобождать системные ресурсы,
  используемые при обходе дерева папки (открытые дескрипторы и т. п.),
  независимо от того, успешно завершился обход или с ошибкой.
- **FR-003**: Операция «Добавить файлы из папки» НЕ ДОЛЖНА приводить к
  падению приложения (включая ошибку нехватки памяти) независимо от
  количества файлов и глубины вложенности подпапок в исходной папке.
- **FR-004**: Система ДОЛЖНА ограничивать количество одновременно
  выполняемых тяжёлых сопутствующих операций на файл/песню при массовом
  импорте (например, автоматический поиск текста песни во внешних
  источниках, поиск дублирующего аудио-«родителя»), не запуская их для всех
  новых песен партии параллельно без ограничения.
- **FR-005**: Если часть файлов папки не может быть обработана (некорректное
  имя, ошибка распознавания/конвертации и т. п.), система ДОЛЖНА продолжать
  обработку остальных файлов и сообщить оператору итоговый результат
  (сколько добавлено, сколько пропущено), не прерывая операцию целиком.
- **FR-006**: Для каждой новой песни, добавленной из папки, система ДОЛЖНА
  автоматически, без ручных действий оператора, поставить в очередь и
  довести до выполнения полный кортеж заданий одного лейна: демукс (разбивка
  на музыку и голос) → создание mp3 музыки и mp3 голоса → загрузка mp3
  музыки и голоса в локальное хранилище → загрузка mp3 музыки и голоса в
  удалённое хранилище.
- **FR-007**: Формирование кортежа заданий для новой песни ДОЛЖНО учитывать
  уже выполненные ранее шаги (например, для песен с уже готовым
  родительским аудио) и не создавать избыточные повторные задания на тех же
  файлах.
- **FR-008**: Формирование и выполнение кортежа заданий для одной песни НЕ
  ДОЛЖНО задерживаться или блокироваться из-за одновременного массового
  добавления множества других песен в той же партии — каждая песня
  доводится до полного набора нужных заданий независимо от остальных.
- **FR-009**: Оператор ДОЛЖЕН иметь возможность убедиться через
  существующие средства (очередь заданий/статус песни), что после массового
  импорта для каждой добавленной песни кортеж заданий сформирован полностью,
  без необходимости вручную анализировать базу данных.

### Key Entities *(include if feature involves data)*

- **Песня**: запись, создаваемая при импорте на основе распознанных из имени
  файла данных (год, номер, автор, название); отправная точка для
  формирования кортежа заданий.
- **Задание**: единица работы в очереди обработки с типом (демукс, создание
  mp3, загрузка в хранилище и т. д.) и принадлежностью к определённому
  лейну; для новой песни создаётся последовательность связанных заданий.
- **Кортеж заданий лейна**: упорядоченный набор заданий одного лейна для
  одной песни — демукс → mp3 музыки и голоса → загрузка в локальное
  хранилище → загрузка в удалённое хранилище.
- **Папка импорта**: исходный каталог (с произвольным количеством вложенных
  подпапок), который сканируется на предмет поддерживаемых аудиофайлов.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Импорт папки с несколькими тысячами аудиофайлов (включая
  вложенные подпапки) завершается без падения приложения и без ошибки
  нехватки памяти.
- **SC-002**: Потребление оперативной памяти сервером обработки во время
  импорта папки остаётся ограниченным и не растёт пропорционально общему
  числу файлов в папке.
- **SC-003**: Для 100% новых песен, успешно добавленных при импорте из
  папки, в течение обычного времени обработки без ручного вмешательства
  выполняется полный кортеж заданий лейна: демукс → mp3 музыки и голоса →
  загрузка в локальное хранилище → загрузка в удалённое хранилище.
- **SC-004**: После завершения массового импорта оператор получает итоговый
  результат: сколько файлов обработано успешно и сколько пропущено.
- **SC-005**: Массовый импорт большой папки не увеличивает время отклика
  остальной части приложения (интерфейс, другие лейны очереди) сверх
  обычного.

## Assumptions

- Поддерживаемые для импорта форматы файлов (аудио) остаются теми же, что и
  в текущей реализации; изменение набора поддерживаемых форматов вне
  области этой доработки.
- «Большое количество файлов» — порядок величины (тысячи и более файлов в
  папке с подпапками), при котором сейчас воспроизводится падение по
  памяти; точный числовой порог не является жёстким контрактом, а
  ориентиром для тестирования устойчивости.
- Сопутствующая логика при добавлении песни (поиск дубликатов, поиск
  аудио-«родителя», автоматический поиск текста песни) сохраняется по сути;
  доработка ограничивает её одновременный/неконтролируемый запуск для всей
  партии файлов, а не убирает её.
- Кортеж заданий (демукс → mp3 → загрузка локально → загрузка удалённо) уже
  частично реализован через существующий механизм пошагового построения
  очереди по мере готовности предыдущих шагов; задача этой доработки —
  проверить и обеспечить его корректность и устойчивость при массовом
  импорте, а не спроектировать заново.
- Изменение текста подтверждающего диалога или внешнего вида кнопки
  «Добавить файлы из папки» не требуется — фокус доработки на устойчивости
  обработки и корректности постановки заданий.
