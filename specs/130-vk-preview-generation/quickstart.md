# Quickstart: проверка превью ВК

## Цель

Проверить, что картинка песни генерируется и записывается на стороне `karaoke-web` до создания VK-поста, а при ошибке прогрева пост не создаётся.

## Предварительные условия

- Рабочее окружение с запущенными `karaoke-app` и `karaoke-web`.
- Тестовая песня имеет готовый публичный контент и положительный `<SONG_ID>`.
- Для песни не заполнен `idVk`; для PREMIUM не установлен флаг уже отправленной premium-публикации.
- Настроены существующие VK-параметры (`vkGroupId`, `vkAccessToken`) и включён нужный сценарий публикации.
- `vkPreviewWarmupEnabled=true`, а `vkPreviewWarmupUrl` указывает на публичный `song-vk-image` endpoint.
- Проверка выполняется на тестовой песне, чтобы не создавать лишний пост в рабочей группе.

## Сценарий 1: проверить отдельный прогрев

Не вызывайте этот шаг перед сценарием 2 на той же песне, если требуется проверить именно холодный кэш. Используйте новую тестовую песню или очистите кэш на стороне `karaoke-web` способом, доступным владельцу окружения.

```bash
time curl -sS \
  -D /tmp/vk-preview-headers.txt \
  -o /tmp/vk-preview.png \
  "https://sm-karaoke.ru/api/public/song-vk-image/<SONG_ID>"

file /tmp/vk-preview.png
```

Ожидаемый результат:

- HTTP `200`, без промежуточного `3xx`;
- `Content-Type: image/png`;
- `file` распознаёт корректное PNG-изображение;
- размер результата не нулевой.

## Сценарий 2: опубликовать песню с автоматическим прогревом

Для ручного AIR-сценария:

```bash
curl -sS -X POST \
  "http://localhost:8898/api/song/publishToVkNow" \
  -d "id=<SONG_ID>&type=air"
```

Для ручного PREMIUM-сценария:

```bash
curl -sS -X POST \
  "http://localhost:8898/api/song/publishPremiumVk" \
  -d "id=<SONG_ID>"
```

Ожидаемый результат:

1. В логах `karaoke-app` сначала появляется успешный `preview prewarm`, затем вызов VK-публикации.
2. Ответ операции содержит `PUBLISHED` только после успешного создания поста.
3. В группе ВКонтакте появляется один пост с исходными текстом и ссылкой.
4. В посте отображается превью песни.
5. В момент первого обращения к картинке VK получает готовый PNG; повторная генерация на этом обращении не происходит.

Проверка журнала без вывода секретов:

```bash
docker logs karaoke-app 2>&1 | grep -E "VkAutoPublish|preview prewarm|wallPost"
```

## Сценарий 3: проверить идемпотентность

Повторите ту же команду публикации для песни с уже заполненным `idVk`:

```bash
curl -sS -X POST \
  "http://localhost:8898/api/song/publishToVkNow" \
  -d "id=<SONG_ID>&type=air"
```

Ожидаемый результат: новый пост не создаётся, prewarm не запускается, возвращается существующее состояние `PUBLISHED` и прежний идентификатор поста.

## Сценарий 4: проверить отказ при ошибке прогрева

В отдельном тестовом окружении временно задайте через Properties UI некорректный `vkPreviewWarmupUrl`, например `http://127.0.0.1:1/api/public/song-vk-image/`, затем повторите публикацию песни с пустым `idVk`.

Ожидаемый результат:

- операция завершается состоянием `SEND_FAILED`;
- `vkAutoPublishLastError` начинается с `preview prewarm failed:`;
- новый вызов `wall.post` не выполняется;
- `idVk` остаётся пустым;
- после восстановления URL повторный запуск использует готовое изображение или создаёт его заново и публикует пост.

После проверки обязательно восстановите рабочее значение `vkPreviewWarmupUrl`.

## Сценарий 5: отделить ошибку VK от ошибки изображения

На тестовой песне оставьте рабочий prewarm, но используйте тестовую конфигурацию с заведомо невалидными правами VK. Запустите публикацию и проверьте:

- журнал содержит успешный prewarm;
- ошибка операции относится к VK API и не начинается с `preview prewarm failed:`;
- `idVk` не записывается;
- повторный запуск после восстановления VK не требует обязательной повторной генерации картинки.

## Контрольная серия

Для проверки критерия успеха проведите не менее 20 новых публикаций на песнях с корректными исходными изображениями. Для каждой зафиксируйте:

- время и результат prewarm;
- HTTP-код и MIME-тип ответа картинки;
- результат создания поста;
- наличие превью в группе ВКонтакте;
- отсутствие дубликатов.

Если prewarm успешен, но превью отсутствует во всех или большинстве постов, гипотеза о задержке генерации не подтверждается. В этом случае результат следует рассматривать отдельно от реализации загрузки изображения через VK API, описанной в `specs/123-vk-og-preview-fix`.

## Автоматические проверки после реализации

```bash
./gradlew :karaoke-app:test
./gradlew :karaoke-app:compileKotlin :karaoke-web:compileKotlin
./gradlew ktlintCheck
bash tools/check-feature-doc.sh docs/features/*.md
```

Существующие интеграционные тесты проекта не заменяют ручную проверку живого VK-поста: они требуют сети, браузера или credentials и не являются CI-гарантией.
