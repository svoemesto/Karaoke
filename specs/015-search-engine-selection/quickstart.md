# Quickstart: проверка выбора поискового движка

## Предпосылки

- Локальный стек поднят, включая `searxng` и `fourget` (см.
  `specs/014-lyrics-search-replacement/quickstart.md`).
- В UI «Свойства» (webvue3) видны новые записи `lyricsSearchEngine` и
  `albumCoverSearchEngine` (после реализации FR-001/FR-002).

## Сценарий 1 — движок по умолчанию для текста песни (US1)

1. В «Свойства» выставить `lyricsSearchEngine = SEARXNG`.
2. Взять песню без сохранённых результатов поиска текста, открыть окно
   поиска текста из SubsEdit → запустить обычный (первый) поиск.
3. **Ожидаемо**: в логах `karaoke-app` виден запрос именно к `searxng`
   (`/search?...`), НЕ к `fourget`.
4. Повторить с `lyricsSearchEngine = FOURGET` на другой песне без
   результатов — убедиться, что запрос идёт к `fourget`.

## Сценарий 2 — движок по умолчанию для обложек альбомов (US1)

1. В «Свойства» выставить `albumCoverSearchEngine = FOURGET`.
2. Запустить поиск обложки альбома для песни/автора.
3. **Ожидаемо**: запрос обложки идёт к `fourget` (`/api/v1/images?...`), не к
   `searxng`.
4. В настройках виден список ровно из 2 опций (без Яндекс-вариантов) — если
   UI-конфигурация свойства ограничивает список опций.

## Сценарий 3 — «Искать заново» с выбором движка (US2)

1. Взять песню, у которой уже есть сохранённые (в т.ч. пустые/неудачные)
   результаты поиска текста.
2. Открыть окно результатов поиска из SubsEdit, нажать «Искать заново».
3. Подтвердить, выбрав в диалоге другой движок (например, `YANDEX_ASYNC`).
4. **Ожидаемо**: старые `SearchResult`/`SearchAsync` для этой песни удалены
   (проверить в БД или по обновлённому списку в окне), новые получены
   выбранным движком.
5. Повторить, нажав «Отмена» в диалоге — убедиться, что старые результаты
   НЕ удалены и новый поиск не запущен.

## Сценарий 4 — «Удалить результаты поиска» (US3)

1. Для песни с сохранёнными результатами нажать «Удалить результаты
   поиска», подтвердить.
2. **Ожидаемо**: результаты исчезли из окна и из БД, новый поиск НЕ был
   запущен автоматически.
3. Повторить, нажав «Отмена» — результаты остаются нетронутыми.

## Сценарий 5 — смена настройки не трогает старые результаты (Edge Case)

1. Найти текст песни А движком `FOURGET` (результаты сохранены).
2. Сменить `lyricsSearchEngine` на `SEARXNG` в настройках.
3. Открыть окно результатов поиска для песни А (без «Искать заново»).
4. **Ожидаемо**: старые результаты песни А (найденные `FOURGET`) остаются
   как есть — смена дефолта не изменила и не удалила их (SC-005/FR-010).

## Сценарий 6 — автоматическая очистка при достижении статуса готовности (US4)

1. Взять песню со статусом <3 и сохранёнными результатами поиска текста.
2. Перевести статус песни в ≥3 (обычным путём, например через редактор).
3. **Ожидаемо**: результаты поиска для этой песни исчезли (проверить в БД или
   через `getSearchAsyncList`/`getSearchResultsList`).

## Сценарий 7 — массовая очистка для уже готовых песен (US4)

1. Убедиться, что есть хотя бы одна песня со статусом ≥3 с сохранёнными
   (оставшимися с «до этой задачи») результатами поиска, и хотя бы одна песня
   со статусом <3 с результатами поиска (контрольная — НЕ должна быть
   затронута).
2. На главной странице администратора нажать «Удалить результаты поиска
   готовых песен», подтвердить.
3. **Ожидаемо**: по завершении — тост с количеством обработанных песен;
   результаты поиска песен со статусом ≥3 удалены; результаты контрольной
   песни (статус <3) остались нетронутыми.

## Что НЕ входит в quickstart

- Нагрузочное/конкурентное тестирование одновременных повторных поисков.
- Точный формат ответа `fourget /api/v1/images` — сверяется отдельно curl'ом
  на этапе реализации (см. `research.md`, Вопрос 3, "Note for implementation").
