# Quickstart: проверка автопубликации новостей во ВКонтакте

**Feature**: `121-vk-news-auto-publish`
**Date**: 2026-08-01
**Spec**: [spec.md](./spec.md) | [research.md](./research.md) |
[contracts](./contracts/vk-api-contract.md) | [data-model](./data-model.md)

> Ручная end-to-end проверка фичи на admin-машине. Все действия — на
> admin-машине в `karaoke-app` (на проде бот не разворачивается, см.
> `constitution.md` и `plan.md` Technical Context).

## Предварительные требования

1. **Admin-машина** с работающим `karaoke-app` (локальная БД, MinIO,
   `Karaoke.properties`).
2. **Группа ВКонтакте** (тестовая или реальная):
   - Публичная группа (`vk.ru/<group_short_name>`).
   - В настройках: «Управление → Работа с API → Ключи доступа →
     Создать новый ключ» с правами `wall`, `video`, `photos`.
   - Скопировать Community access token.
3. **Полностью готовая тестовая песня** (статус 6, стемы/обложки/маркеры
   на месте) с пустым `idVk` в `tbl_songs`.
4. **Опубликовано новости категории `air`** для тестовой песни:
   - Либо дождаться авто-новости (`SongReleaseAnnouncementService` после
     sync, см. `specs/089-auto-news-song-release`).
   - Либо вручную создать новость через `webvue3`: категория `air`,
     `link = /song?id=<songId>`, `publishAt` в прошлом или «сейчас».

## Настройка конфигурации (через Properties UI в `webvue3`)

1. Открыть `webvue3` → раздел «Properties» (или прямой доступ к
   `Karaoke.properties`).
2. Установить новые ключи (см. `research.md` §10):
   - `vkAutoPublishEnabled = true`
   - `vkGroupId = <ID группы без минуса>` (например, `123456`)
   - `vkAccessToken = <Community access token>`
   - `vkApiVersion = 5.199` (или актуальная стабильная)
   - `vkProxyUrl` — если admin-машина за firewall (по образцу
     `telegramProxyUrl`); иначе пусто.
   - `vkAutoPublishMaxVideoSizeMb = 50` (или больше, если нужно)
   - `vkAutoPublishRateLimitPerHour = 3`
3. Перезапустить `karaoke-app` (только пользователь — см. AGENTS.md
   «Ограничения агента»; на `dev-pc`/`dev` — агент может).

## Сценарий 1: Автопубликация по расписанию (FR-001, основной flow)

**Цель**: Проверить, что опубликованная на сайте новость `air` для песни
с пустым `idVk` автоматически превращается в пост в группе ВКонтакте.

**Шаги**:

1. Убедиться, что у тестовой песни `Song.idVk` пуст (через `webvue3`
   карточку песни или SQL: `SELECT id_vk FROM tbl_songs WHERE id = <songId>`).
2. Убедиться, что в `tbl_news` есть опубликованная новость `air` для
   этой песни:
   ```sql
   SELECT id, title, category, publish_at, song_id
   FROM tbl_news
   WHERE category = 'air' AND song_id = <songId>
     AND publish_at <= now();
   ```
3. Дождаться очередного тика `VkAutoPublishScheduler` (каждые 60 сек,
   `@Scheduled(fixedDelay = 60_000L)`).
4. **Ожидаемый результат**:
   - В группе ВКонтакте появляется пост с текстом новости и прикреплённым
     демо-MP4 видео.
   - В `tbl_songs.id_vk` для тестовой песни появляется значение
     `-<groupId>_<postId>`.
   - В логах `karaoke-app`: `VkAutoPublishService: song id=<songId> → PUBLISHED (post_id=...)`.

**Проверка**:
```sql
SELECT id_vk FROM tbl_songs WHERE id = <songId>;
-- ожидается: -<groupId>_<postId>, не пусто
```

## Сценарий 2: Идемпотентность — повторный тик не дублирует (FR-007, FR-008)

**Цель**: Проверить, что после успешной публикации повторные тики не
создают второго поста в группе.

**Шаги**:

1. Выполнить сценарий 1 — пост появился, `idVk` заполнен.
2. Перезапустить `karaoke-app` (или просто подождать 2-3 тика ~3 минуты).
3. **Ожидаемый результат**:
   - В группе ВКонтакте **не** появляется второго поста по той же песне.
   - В логах: `VkAutoPublishService: song id=<songId> idVk not empty, skip (FR-008)`.
   - `Song.idVk` остаётся прежним (не перезаписывается).

## Сценарий 3: Ручная очистка и переопубликование (User Story 3, FR-014)

**Цель**: Проверить, что администратор может очистить `idVk` и
переопубликовать песню (если пост ВК удалён вручную).

**Шаги**:

1. Выполнить сценарий 1 — `idVk` заполнен.
2. Вручную удалить пост в группе ВКонтакте (через интерфейс ВК).
3. В `webvue3` открыть карточку тестовой песни, очистить поле `idVk`
   (существующий UI редактирования полей песни), сохранить.
4. Дождаться следующего тика `VkAutoPublishScheduler` (60 сек) ИЛИ
   нажать кнопку «Опубликовать во ВКонтакте сейчас» (FR-016, если
   реализована).
5. **Ожидаемый результат**:
   - В группе ВКонтакте снова появляется пост с текстом и демо-MP4.
   - `Song.idVk` снова заполняется новым `post_id`.

## Сценарий 4: Кнопка «Опубликовать во ВКонтакте сейчас» (FR-016)

**Цель**: Проверить принудительный запуск публикации, минуя ожидание тика.

**Шаги**:

1. Подготовить тестовую песню с пустым `idVk` и опубликованной новостью `air`.
2. В `webvue3` открыть карточку песни.
3. Нажать кнопку «Опубликовать во ВКонтакте сейчас» (новый элемент UI).
4. **Ожидаемый результат**:
   - Запрос `POST /api/song/publishToVkNow?id=<songId>` (см.
     `contracts/vk-api-contract.md` §6).
   - В группе ВК появляется пост с демо-MP4.
   - `Song.idVk` заполняется.
   - Кнопка становится disabled (т.к. `idVk` теперь не пуст).

## Сценарий 5: Песня не готова — публикация откладывается (FR-022)

**Цель**: Проверить, что бот не публикует демо-MP4 для неготовой песни.

**Шаги**:

1. Подготовить тестовую песню со статусом < 6 (или без стемов/обложки).
2. Убедиться, что есть опубликованная новость `air` для этой песни
   (можно создать вручную).
3. Убедиться, что `Song.idVk` пуст.
4. Дождаться 2-3 тиков `VkAutoPublishScheduler` (~3 минуты).
5. **Ожидаемый результат**:
   - В группе ВК **не** появляется поста.
   - `Song.idVk` остаётся пуст.
   - В логах: `VkAutoPublishService: song id=<songId> not content-ready, skip (FR-022)`.
6. Доведите песню до полной готовности (статус 6, стемы, обложки).
7. Дождаться следующего тика.
8. **Ожидаемый результат**: пост появляется, `idVk` заполняется.

## Сценарий 6: Снимок-бэклог — исторические песни не постятся (FR-012)

**Цель**: Проверить, что при первом включении бота песни с уже
заполненным `idVk` (исторические) не получают повторных постов.

**Шаги**:

1. Найти песню с уже заполненным `Song.idVk` (историческая ручная
   публикация):
   ```sql
   SELECT id, id_vk FROM tbl_songs WHERE id_vk IS NOT NULL AND id_vk != '' LIMIT 5;
   ```
2. Убедиться, что для одной из таких песен есть опубликованная новость
   `air` (создать вручную при необходимости).
3. Включить бота (`vkAutoPublishEnabled = true`) и дождаться тика.
4. **Ожидаемый результат**:
   - В группе ВК **не** появляется нового поста для этой песни (FR-008 —
     `idVk` уже заполнен, бот пропускает).
   - `Song.idVk` не меняется.

## Сценарий 7: Ручная `air`-новость без song_id (FR-021, редкий случай)

**Цель**: Проверить, что ручная новость `air` без привязки к песне
публикуется без видео (только текст), и идемпотентность работает
через `News.playerReadinessFlags`.

**Шаги**:

1. В `webvue3` создать новость:
   - Категория: `air`.
   - `link`: пусто или произвольная строка (не `/song?id=...`).
   - `publishAt`: сейчас.
   - (Не задаётся `song_id` — через `NewsController.create` нет такого
     параметра; `song_id` заполняется только в `News.createAutoAnnouncement`.)
2. Дождаться тика.
3. **Ожидаемый результат**:
   - В группе ВК появляется пост с текстом новости, **без видео** (FR-021).
   - В `News.playerReadinessFlags` появляется ключ
     `vkAutoPublishState=published` (FR-004a).
4. Дождаться ещё одного тика.
5. **Ожидаемый результат**: повторного поста **нет** (идемпотентность
   через `player_readiness_flags`, FR-004a).

## Сценарий 8: Премиум-публикация вручную (FR-026, User Story 5)

**Цель**: Проверить, что кнопка «Опубликовать во ВК (premium)»
формирует пост по премиум-шаблону и заполняет `idVk`.

**Шаги**:

1. Подготовить песню со статусом 6 (премиум-готова) с пустым `idVk`.
2. Настроить `vkTemplatePremium` (отличный от `vkTemplateAir`):
   через редактор шаблонов (Сценарий 9) или Properties UI.
3. В `webvue3` открыть карточку песни, нажать «Опубликовать во ВК
   (premium)».
4. **Ожидаемый результат**:
   - Запрос `POST /api/song/publishToVkNow?id=<songId>&type=premium`
     (см. контракты §6).
   - В группе ВК появляется пост по `vkTemplatePremium` (отличается от
     `air`-шаблона — например, без хештега «в эфире», с «премиум»).
   - `Song.idVk` заполняется.
   - Обе кнопки (`air` и `premium`) становятся disabled (FR-016, общая
     идемпотентность).
5. Очистить `idVk`, нажать «Опубликовать во ВК (air)» — пост по
   `air`-шаблону. Убедиться, что шаблоны различаются.

## Сценарий 9: Редактор шаблонов ВК (FR-025, User Story 6)

**Цель**: Проверить, что редактор шаблонов показывает/правит шаблоны
без перезапуска `karaoke-app`.

**Шаги**:

1. В `webvue3` открыть раздел редактора шаблонов ВК (новый компонент
   `VkTemplatesEditor.vue` — точная навигация зависит от webvue3
   layout: раздел «Шаблоны ВК» в меню или через настройки).
2. `GET /api/vk/templates` (см. контракты) — получить текущие шаблоны
   `air` и `premium` + список плейсхолдеров.
3. Изменить `vkTemplateAir`: добавить хештег `#test` или
   переформулировать подпись.
4. Сохранить → `POST /api/vk/templates?key=vkTemplateAir&value=...`.
5. Создать/дождаться `air`-новость для тестовой песни с пустым `idVk`,
   дождаться публикации.
6. **Ожидаемый результат**: пост в ВК содержит обновлённый текст по
   новому шаблону (без перезапуска `karaoke-app`, FR-015).
7. Ввести несбалансированную скобку `{author` (без `}`), сохранить.
8. **Ожидаемый результат**: редактор показывает предупреждение, но
   сохранение проходит. При публикации текст содержит `{author` как
   literal (FR-023).

## Очистка после тестов

1. Удалить тестовые посты из группы ВК (вручную).
2. Очистить `idVk` у тестовых песен (через `webvue3` или SQL).
3. Удалить тестовые новости (через `webvue3` → Новости → удалить).
4. (Опц.) выключить бота: `vkAutoPublishEnabled = false`.
5. (Опц.) восстановить дефолтные шаблоны (`vkTemplateAir`,
   `vkTemplatePremium` очистить — бот использует хардкод-дефолты, см.
   research.md §6).
